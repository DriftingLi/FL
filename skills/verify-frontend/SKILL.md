# verify-frontend

`verify-project` 通过后执行本 Skill，对前端页面做肉眼级验收。以下检查每项都要给出明确通过/失败结论。

## 前置条件

- frontend 开发服务器已启动（`npm run dev`），或已构建并可通过 HTTP 访问
- 有浏览器自动化工具可用（Playwright / agent-browser-cli 等）
- 桌面视口宽度 ≥ 1024px，移动端视口宽度 375px

## 步骤 1：页面加载检查

- 打开页面，等待网络空闲（`networkidle`）或指定超时（建议 10 秒）
- 截图保存
- 判断：页面标题是否正确、是否有全屏空白/白屏、是否有资源 404

失败条件：白屏、标题错误、关键 JS/CSS 资源 404。

## 步骤 2：核心交互检查

对每个核心交互路径执行操作并验证结果：

- 导航链接/路由跳转：点击后 URL 是否正确变化、内容区是否更新
- 表单提交：填写必填项，提交后是否有成功反馈
- 按钮点击：每个主要按钮至少点击一次，确认有响应
- 数据展示：列表/图表/表格是否正常渲染，无明显缺失

每项操作后截图记录。任何交互无响应或报错即失败。

## 步骤 3：375px 移动端适配检查

- 将视口设为 375×812（iPhone X 比例）
- 刷新页面，等待加载完成
- 截图保存
- 逐项检查：
  - 文字是否可读，没有被裁切或溢出
  - 按钮是否可点击，没有被遮挡
  - 横向是否出现滚动条（不应出现）
  - 导航/菜单是否适配小屏
  - 表单输入框是否正常显示

任何一项明显错位、裁切、遮挡即失败。

## 步骤 4：浏览器控制台检查

- 打开浏览器开发者工具 Console
- 清空日志
- 刷新页面，等待加载完成
- 读取 Console 中的错误和警告

判断标准：

- **错误（Error）**：不允许有任何 Error 级别日志，出现即失败
- **警告（Warning）**：记录但不阻塞，在报告中列出
- **忽略项**：已知第三方库的无关警告（如 analytics、telemetry），如确认为无害可在报告中注明忽略理由

## 步骤 5：视觉错位检查

- 恢复桌面视口（≥1024px）
- 截图全页
- 逐项检查：
  - 页面布局是否对齐，无明显错位
  - 弹窗/抽屉/下拉菜单是否完整显示，没有被裁切
  - 滚动条是否正常，内容是否可滚动到底部
  - 图片/图标是否正常加载，没有破图
  - 元素之间是否有异常重叠或遮挡

任何明显视觉问题即失败。

## 汇报格式

```
✅ verify-frontend 通过
  页面加载: 通过（截图: /tmp/verify-xxx.png）
  核心交互: 通过（X/X 项）
  375px 适配: 通过
  控制台: 无 Error，X 个 Warning（列表）
  视觉检查: 通过
```

或失败时：

```
❌ verify-frontend 失败
  步骤: [步骤名称]
  问题描述: [具体描述]
  截图: /tmp/verify-xxx.png
  修复建议: [根据问题类型给出修复方向]
```

## 注意事项

- 本 Skill 只覆盖能明确判断对错的检查项；动画效果、配色美观、交互手感等主观判断不属于本 Skill 范围。
- 截图文件写入 `/tmp/` 或项目内的临时目录，不要将 base64 内嵌到对话中。
- 如果浏览器自动化工具不可用，跳过本 Skill，在报告中注明原因，改为人工验收。
