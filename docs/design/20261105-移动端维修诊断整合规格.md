# 第一部分 · 规格

## Problem Statement

师傅在手机上问一句「中力 E41 怎么修」，现在只能对着一个空白输入框打字。

他不能按品牌/车型点选——不知道对方知识库里管那个型号叫什么，只能靠自己猜；他不能把车间里那块控制面板拍下来直接问，只能费力描述「第三排第二个灯闪红」；答案回来以后看不到手册里那张图，只看到「诊断配图」四个字；他也不知道这一轮系统到底查了什么、等了多久。

这不是「功能还没做」的形态，而是**刚被摘掉一半**的形态：上游换了服务，旧的筛选面板与其数据源一起退役，页面上留下一个纯文字输入框。网页版那边已经补齐并上线，手机上是半成品——同一个学员换个屏幕就从「能用」跌回「凑合」。

## Solution

把手机上的「智能维修诊断」专项页补成一个能真正干活的闭环：

按品牌 → 系统/型号 → 故障现象点选，系统自动拼成一句完整的问题让他确认或改写；输入故障码时当场告诉他认不认识；能拍照或从相册选图（最多三张）随问题一起发出去，只发图不写字也行；回答回来时带上「这轮用了哪些能力」的徽章和耗时；追问接得上上文；取不到数据、服务挂了、登录过期，都有明确而可行动的交代。

登录、权限、积分仍走 FL 自己的那一套，不嵌任何第三方界面，**不引入 web-view**。

## User Stories

1. 作为学员，我希望进入诊断页时先按品牌挑，以便不用背下知识库里那些型号名。
2. 作为学员，我希望选完品牌后看到第二层是「系统」还是「型号」，以便不用猜下一步该选什么。
3. 作为学员，我希望在林德那种八十多个型号的列表里能搜索，以便不用一直往下滑。
4. 作为学员，我希望选完现象后看到系统替我拼好的那句话，以便既能直接发、也能先改两个字。
5. 作为学员，我希望随时可以跳过点选直接打字，以便向导不成为束缚。
6. 作为第一次进来的学员，我希望看到几个常见问题，以便点一下就知道能问什么。
7. 作为点到一半放弃的学员，我希望下次进来是干净的空态，以便不被半截状态困住。
8. 作为带新人的维修主管，我希望新人能照着这套点选走一遍，以便他描述不清时也有个抓手。
9. 作为学员，我希望敲下「E01」时立刻知道系统认不认识这个码，以便不用发出去才发现问错了。
10. 作为学员，我希望敲错格式（少横杠、把 O 打成 0）时系统不报错、只是不提示，以便不被自己的一时手误打断。
11. 作为学员，我希望系统认出故障码时给我一个可点的追问，以便一次识别直接变成一次诊断。
12. 作为学员，我希望在车间拍一张控制面板照片就发出去，以便不用把症状翻译成文字。
13. 作为学员，我希望一次能带最多三张图（正面、侧面、铭牌），以便覆盖判断需要的角度。
14. 作为学员，我希望选错的图能删掉再重选，以便不会把错图发出去。
15. 作为学员，我希望只发图不写字也能诊断，以便手上全是油、腾不出手打字时也能问。
16. 作为学员，我希望上传时看到进度，以便知道是在传而不是卡死。
17. 作为学员，我希望超过三张时立刻被拦住并说清上限，以便不会发出后才发现少了两张。
18. 作为学员，我希望自己发出的图出现在对话里，以便确认发对了。
19. 作为学员，我希望过两天回看这个会话时图还在，以便复盘当时现场是什么样。
20. 作为学员，我希望追问「那第一步先量什么」时回答能接上上文，以便不用把整段背景重讲一遍。
21. 作为学员，我希望等待时能看到已经等了多少秒，以便判断还要不要继续等。
22. 作为学员，我希望回答超过半分钟时等待态不会自己消失，以便不会对着一个「已完成」的空白气泡发呆。
23. 作为学员，我希望连着点两次发送时被温和告知当前还在回复，以便不会重复问同一个问题。
24. 作为学员，我希望答得不对时能一键重问，以便不用重新打字。
25. 作为学员，我希望看到这轮用了哪些能力（识别故障码、检索知识库一类），以便知道系统是真查了还是随口答。
26. 作为学员，我希望看到这轮耗时，以便判断这种问法值不值得再问一次。
27. 作为学员，我希望过几天回看历史会话时徽章和耗时还在，以便对比同一故障前后两次的结论。
28. 作为学员，我希望回答里的标题、列表、代码块排得整齐，以便在手机上能读。
29. 作为学员，我希望诊断服务挂掉时看到一句人话，以便不用面对一个 HTTP 码。
30. 作为学员，我希望引导数据取不到时看到的是留白，而不是一排点了就报错的按钮。
31. 作为学员，我希望网络超时时被告知稍后重试，而不是对着空白等。
32. 作为学员，我希望登录过期时被送回登录页且只提示一次，以便不被重复弹窗打断。
33. 作为未登录用户，我希望在进诊断页那一刻就被要求登录，以便不会白问一轮才发现没登录。
34. 作为学员，我希望限免期内不用担心扣积分，以便放心多问几轮。
35. 作为维护者，我希望上游换域名或换 Key 时学员侧只看到「诊断服务暂时不可用」，以便内部拓扑不外泄。
36. 作为维护者，我希望改组句模板时两端的守护同时提醒我，以便网页版和手机版不会各说各话。
37. 作为维护者，我希望后来者加图片能力时只能走统一选图入口，以便不会冒出第四条上传路径。
38. 作为维护者，我希望诊断能力进入发版冒烟清单，以便真机上的关键操作不会因为「测试全绿」而被跳过。

## Implementation Decisions

**通道与边界**

1. 复用既有的第二个模型适配器与单轨上游通道；模型端口、功能注册表、计量闸门三层不动。上游换服务是「换实现」，不是「加一条通道」。
2. 会话仍归 FL：上游是无状态单轮，多轮由后端把最近几轮折叠进本轮正文。因此**不引入 `conv_id`、不建会话映射表、不为学员在上游注册账号**——「FL 是唯一账号主体、唯一会话真相源」两条边界不变。
3. 手机端只认 FL 自己的网关合同（六事件流 + 统一信封），完全不感知上游协议；**API Key 与 base64 永不下发到客户端**，图片在客户端只以「站内附件 URL」的形式出现。
4. 已知缺口本轮不修：对话端点仍允许匿名访问。收紧会跨到 Web 侧，且当前限免，收益低于改动面，单独立票。

**引导面**

5. 品牌/车型不做结构化请求字段：上游本轮只有正文一个文本通道，字段送了也没人读。改为前端纯函数组句——**组句是前端职责，不是后端职责**，后续若上游恢复结构化字段，只换这一层。
6. 组句模板两端同源：手机版与网页版共用同一套语义，由跨栈守护比对模板字面量，禁止各写一份。
7. 第二层形态由品牌数据里的 `picker` 决定（型号档 / 系统档），其余与空值一律按系统档渲染。引入第三个取值时按系统档处理，并记为待观测项。
8. 引导数据取四个只读端点 + 一次健康探测；**健康探测失败时整块留白**，不留「点得动、点了必失败」的死入口。
9. 空态欢迎区 = 品牌快选 + 常见问题；诉求卡只出现在品牌根层，不搬到欢迎区。

**故障码体检**

10. 输入防抖后就近查询故障码体检端点；本轮只消费「已知」态的一行提示与一个可点追问，其余状态不渲染（把四态的界面强度留到有真实语料后再定）。

**图片**

11. 图片走「选图 → 压缩 → 逐张上传换站内 URL → 随消息发送」四步；不新增上传端点、不引入 base64 客户端直传。
12. 单轮上限三张、单张五兆，与上游闸门同值；**客户端先拦**并给可读提示，不把拒绝留给服务端。
13. 允许「有图无字」发送：文本为空但有图时不早退，由后端补一句默认话术。
14. 压缩能力在目标端不确定时**降级为原样上传**，靠服务端的三道闸兜底；不因为压缩不可用就挡掉发送。

**结果与等待**

15. 正文权威性：上游的最终全文是权威，流式增量只为观感。客户端实现为「最终全文到达则替换、缺席则保留累积」的向前兼容形态——这条有前车之鉴：网页侧曾因「只归一了返回值、没归一用户看到的那份」导致图片请求真的打到第三方主机。
16. 徽章与耗时随最终事件下发并落库，历史回放同源；轨迹类数据永不展示、也不落库。
17. 等待与超时：诊断通道超时与后端一致（五秒级→三百秒级，取后端值），等待态显示已用秒数；取消原先固定三十秒的强制复位，改为「请求结束时清除」。代价是慢回答会让学员等更久，收益是不会把还在跑的回答判死。

**页面形态**

18. 不新增页面：引导面是半屏面板。因此不触发应用打包面门，也不新增会话分区。
19. 会话分区沿用既有不变式「按功能键真分区，且有键者必须有列该区的界面」，诊断页右上角抽屉即该界面。
20. 配图本轮不在手机端渲染：正文里的图片语法降级成文字说明，手机端不向第三方主机发任何请求。**这是有意的能力扣减**（学员看到「诊断配图」四字而非图），二期再做。

**推翻的既有裁定（各需一份 ADR）**

21. 解除「专项页不含用户上传图片」——原裁定的理由是「图片能力根本不存在，专业版锁着一个空壳按钮」，并写明「图片能力落地后再并入」；现链路已就绪，属该条设定的落地点。同批把守护断言由否定式改为肯定式，**不得先放宽后补 ADR**。
22. 不执行「删除多轮折叠」——该要求的前提是「前端已组句历史」，但前端传的是完整消息数组、不自行拼历史；删掉即追问失忆。

**计费**

23. 诊断功能沿用限免声明：不扣积分、不发用量事件、界面不显示扣分；因此本轮不做「积分不足 → 去任务中心」的入口。**结束限免的那张票必须同批补这个入口**，否则学员会撞上一个无法行动的错误。

## Testing Decisions

**什么叫好测试**：只测外部行为——给定输入，产出什么；不测实现细节（内部函数名、字段顺序、调用次数）。纯函数要**真执行**后断言产物，而不是读源码文本比对字面量；仓规已明确「接线守护不构成 ③ 门证据」，所以「字面量还在」永远不能当作「逻辑还对」。

**唯一主 seam**：手机端的 `.uts` 纯函数行为测试层（既有 harness，先例是回答渲染层的行为测试）。所有新逻辑下沉为纯函数后在这一个 seam 上覆盖：

- 组句：同一组（品牌/型号/现象）→ 同一句话；缺项时的降级形态。
- 四步状态机：`picker` 判档、步骤推进与回退、预选兑现、空态与「点选到一半退出」的清理。
- 图片名额：三张上限的入队与拒绝、超限不落队、删除后名额归还。
- 最终事件归一：全文到达 → 替换累积；全文缺席 → 保留累积；徽章/耗时映射；轨迹字段被丢弃。
- 留白判定：健康探测失败 ⇒ 引导面整块不渲染。

**既有 seam 继续各守其位**（不新增）：

- 接线守护（读源码文本）：只锁接线——诊断页必须开启图片按钮、不得直接调用选图 API（必须经统一入口）、上限常量与服务端同值。放宽时必须同批改为肯定断言。
- 后端契约桩：补两条——图片以站内 URL 进、以 dataURL 出且超三张被截断；纯图轮次补话术。用既有的目录桩那套，不开新桩。

**端到端**：因为上游契约原文不在仓内，**一次真实联调是唯一的端到端证据**（故障码命中 + 一轮带图 + 一轮纯文字追问）。此后每轮的判据是：手机端行为测试 + 小程序构建门 + 真机那八条人工打勾。

**明确不测**：不写针对上游返回形状的快照（形状在对方手里、必然过期）；不为 UI 组件补快照测试（第二部分的 `file:line` 会先过期）。

## Out of Scope

- 手机端配图渲染、逐字流式（需另开分块通道）、导出、报修/转人工、VIN 识别、多图历史高级预览、会话重命名、完整历史分页。
- `web-view` 路线及其域名/备案/证书——整条路线被否，备案依赖随之消失。
- 计费口径变更（仍限免）、新功能键、会话映射表、上游服务账号。
- 对话端点的匿名访问收紧。
- 上游服务端改造；第三方前端那五十余个功能函数的复刻。
- 生产切流与旧服务退役的运维动作（另票）。

## Further Notes

1. **上游 v1 已物理删除、无回滚通道**（旧机已停机、开机自启已置零）。这意味着「端到端真验过」是硬门槛而不是可选项：没有退路。
2. **上线前置两件，不在本规格代码范围**：生产侧两个密钥未配置、上游仍是明文 http。前者不配则诊断取数恒失败，后者让密钥明文过公网——都属「必须解决但不由本期代码解决」。
3. **两份同号 ADR 的处置**：canonical 是「诊断回答配图的白名单代理与降级」那份（已入库）；另一份「替换为 v0.1 平台与会话保真」是**未提交草稿**，其 `conv_id`/服务账号路线从未落地且与现行实现冲突 ⇒ 删除，或改写为「未采纳方案」附注并不得占用 0091 号。
4. **本轮的三处如实扣减**（不可在验收时声称等价）：手机端看不到手册配图；拿不到结构化来源清单；林德的命中率不可能等于对方（对方靠维修手册语料特征词表，我们拿不到那份数据面）。
5. **证据缺口**：上游契约原文不在仓内（被忽略的本地参考目录）、本地工作树落后远端一个提交、生产是否已切流无仓内证据、小程序端压缩能力未验、微信后台域名白名单与证书到期日是后台读数。逐条与 `file:line` 判据见第二部分。
6. **发布形态**：票面正文＝本规格的**第一部分**（用户故事 + 决策 + 测试决策 + 范围 + 本注）；含 `file:line` 的判据附录**不进票面**，实施会话按需回查本文件第二部分。标签取移动端变体 `ready-for-mobile-agent`。

## 0. 为什么这份规格存在

三件外在事实决定了本规格的形状，先钉死，免得后来者重新勘察：

1. **上游不是同一套服务的新版本，而是架构级重写。** v1 交付包（`/assistant/api/chat`、`/assistant/api/chat/with-image`，阻塞 JSON）已物理删除、无开关、无回滚通道（lxc101 于 2026-11-04 14:44 停机、`onboot` 置 0）。现行唯一上游是 v2 的 `POST /api/v2/chat`（SSE、`X-API-Key`）。
2. **`web-view` 路线整体被否。** 因此「买域名＋1~3 周备案＋配证书」这条**不构成本期外部依赖**：移动端只跟 `https://api.gdyidao.cn/api` 说话，该域名的备案与证书是既有资产。
3. **两份 ADR-0091 不是重号债。** canonical 是 `docs/adr/ADR-0091-诊断回答配图的白名单代理与降级.md`（已入库）；`docs/adr/ADR-0091-外部诊断助手替换为v0.1平台与会话保真.md` 是 **untracked 草稿**（`git status` = `??`），其「FL 持服务账号 + `assistant_conv_map(conv_id)` 会话保真」从未落地，且与现行「静态 `X-API-Key` + 单轮无状态」直接冲突 ⇒ 按 §10.3 处置，**不得作为判据引用**。

## 2. 最终架构

```
学员端（uni-app x → mp-weixin / app-android）
  │  HTTPS 仅 https://api.gdyidao.cn/api     ← 唯一出网面，无第二个域名
  │  JWT（FL 登录 / Cap(ai_assistant.use) / 积分）
  ▼
FL 后端（唯一账号主体、唯一会话真相源）
  ├─ POST /api/ai-assistant/chat            SSE 六事件
  │    └─ meteredAIModel（限免期直通）
  │         └─ diagnosisAdapter ──POST {DIAGNOSIS_ASSISTANT_URL}/api/v2/chat (X-API-Key, SSE)
  ├─ GET  /api/ai-assistant/diagnosis/{intents,systems,faults,code-hint,health}
  │         └─ GET {base}/api/v2/{intents,systems,faults,code_hint}；health 走无鉴权 /api/health
  ├─ GET  /api/ai-assistant/diagnosis/ossimg/*   ← 配图唯一出口（白名单五道闸）
  ├─ POST /api/ai-assistant/upload-image         ← 图片唯一入站
  └─ ai_chat_sessions / ai_chat_messages（feature_key 分区，meta 列）
        ▲
        └── 外部 v2（ECS）：RAG + 维修手册 + 故障码知识库 = 唯一知识面
```

四条不变式（实施中不得违反）：

1. **移动端永不直连外部方、永不见 `X-API-Key`、永不见 base64**；图片只以站内 URL 形式进 `messages[].images`。
2. **`conv_id` 不存在**：v2 单轮无状态，会话由 FL 的 `session_id` + `foldHistoryIntoQuery` 承担。
3. **`done.answer` 是权威全文**；`delta` 仅为观感。移动端当前用累积 delta（与整包接收等价），实现须写成「`done` 若带 `content` 则替换累积」的**向前兼容**形态 —— #2293 合入后自动受益。⚠️ 这条在 Web 侧曾以「浏览器真向第三方主机发了请求」的形式炸过（#2293），移动端虽不发图请求，但同一类「用户看到的那份正文由谁产出」的问题必须显式处理。
4. **配图只有一条出口**（本站代理），不开放第三方外链放行。

## 3. 功能范围（A 的口径）

### 3.1 进（本期）

1. **引导面**：半屏 sheet 四步 —— 品牌（`intents.brands`，含 `picker`）→ 第二层（**两档都走 `systems?brand=`**：中力 14 个系统带 icon、林德 87 个型号无 icon 且可搜索；`picker` 只决定搜索框与第三层标题，**不决定端点**）→ 现象（`faults?brand=&second=<第二层 id>`）→ 组句预览并发送。`faults?brand=` **不带 `second`** 是品牌根层诉求/故障项，只用于「品牌根层诉求卡」，不是型号列表（#2310 订正）。**分支口径 1:1 复刻 Web 已落地实现**（`frontend/src/pages/ai-assistant/FeatureChatPage.vue` + `frontend/src/utils/diagnosisCompose.ts`），本规格不复述其细节 —— 抄一遍就是一处漂移源。
2. **空态欢迎区**：品牌快选横滑 + `intents.faq` 列表（点击填入输入框）。
3. **故障码体检**：输入框 250ms 防抖调 `code-hint?q=`，仅消费 `status==='known'` 的 `message` 一行 + 「按提示追问」；其余态不渲染（记录为后续）。
4. **随问图片 ≤3 张**：相册/拍照 → 压缩 → 逐张 `POST /upload-image` → 缩略图预览/删除 → 随消息发送 → 气泡缩略图 → 历史回显。
5. **纯图片轮次**：允许「有图无字」发送（当前 `sendInput` 的 `text.length==0` 早退必须放宽），由后端补话术「请根据现场图片进行分析」（`diagnosis_adapter.go:529-532` 已实现）。
6. **回答增强**：徽章行（`meta.badges`）+ 耗时脚注（`meta.elapsed`），历史回放同源（`AIChatMessageDTO.meta`）。
7. **等待态**：诊断页超时改 300s 与后端 `aiStreamTimeout` 对齐；等待期显示已用秒数；`useAiChat.uts:217-222` 的 30s 强制复位改为**请求结束时清除**。
8. **失败与空态**：`health` 一次探测，失败则引导面**整块留白**（不留「点得动、点了就 502」的死入口，先例 2244 决策①）；错误沿用既有 `[错误：…]` + toast。

### 3.2 不进（A 的取舍，须产品认账）

- **不做移动端配图渲染**：学员看到的是「诊断配图」四字，不是图。
- **不做逐字流式**：整包到达，无 `status` 实时价值。
- **不做结构化来源清单**：v2 的 `done` **不回 `sources`**，`ctx` 容器恒空（`diagnosis_adapter.go:38-39`）⇒ 移动端「资料来源」在诊断下实际不可得（组件保留、不回退）。**这是「保留维修手册/参考资料」这条要求在移动端的真实扣减**；二期靠配图渲染把「手册图」补回来。

### 3.3 已定、不再讨论

`fault_diagnosis` 沿用 `freePreview` 限免（不扣积分、不发 `usage`、不显示扣分）；不新增功能键；不引入 `conv_id` 或服务账号；不动 `pages.json`（**无新页面 ⇒ 不触发 ④a/④b 打包门**）。

### 3.4 主动推翻的既有裁定（两条）

| 裁定 | 出处 | 本期处理 |
|---|---|---|
| 「专项页不含用户上传图片」 | 移动端 ADR-0009 修订② + 守护 `utils/aiFeatureEntryWiringContract.test.js:420-422` | **推翻**。ADR-0009 原文的理由是「图片能力根本不存在（专业版锁着一个空壳按钮）」，并写明「图片能力落地后再并入」；现链路上传/闸门/话术全部就绪，属该条设定的「落地后」。写移动端 ADR-0054 并同步放宽守护 |

## 6. 接口契约

### 6.1 三组契约的差异（定案）

| 契约 | 定位 | 状态 |
|---|---|---|
| `/assistant/api/chat`、`/assistant/api/chat/with-image` | v1 交付包（lxc101）：阻塞 JSON，带图为**独立端点** | **已物理删除**，无开关、无回滚通道 |
| `/api/chat`（`X-Session-Token`、`conv_id` 必填、配套 `/api/login`、`/api/conversations`） | 外部 v0.1 平台；交付包与方案 B 文档描述的正是这套 | **未采用**。ADR-0091 拒绝「小程序直连 + 第二套登录」；其 `conv_id` 会话保真与本仓「FL 是唯一会话真相源」冲突 |
| `POST /api/v2/chat`（`{content, images[]}`，SSE，`X-API-Key`） | FL 后端 → 外部 v2 | **唯一在用**。图片不是独立端点，是 **dataURL 数组**；`/api/v2/chat/complete` 存在但未使用 |

对外（移动端可见）的契约只有下面两张表。

### 6.2 移动端 → FL

| 端点 | 鉴权 | 关键字段 |
|---|---|---|
| `POST /api/ai-assistant/chat` | OptionalAuth（JWT 可选） | 请求 `{session_id, messages:[{role,content,images[]}], feature_key}`；响应 SSE：`message{content}` / `status{text}` / `sources{sources}` / `usage` / `error{message}` / `done{meta\|content?}` |
| `GET /api/ai-assistant/diagnosis/intents` | OptionalAuth | `{brands:[{id,name,tagline,icon,cls,picker}], faq:[{q,a}]}`，`max-age=300` |
| `GET …/diagnosis/systems?brand=` | OptionalAuth | `{items:[{id,name,icon?}]}`；缺 `brand` → 400 |
| `GET …/diagnosis/faults?brand=&second=` | OptionalAuth | `{items:[…]}`；**不带 `second` 是根层**，带 `second` 是另一份列表（比对选错层会误判） |
| `GET …/diagnosis/code-hint?q=` | OptionalAuth | `{status,message,fix,samples[]}`；无缓存 |
| `GET …/diagnosis/health` | OptionalAuth | `{ok, app_configured}`；**永远 200** |
| `GET …/diagnosis/ossimg/*filepath` | OptionalAuth | 裸图片字节（**非信封**），`max-age=86400` |
| `POST /api/ai-assistant/upload-image` | OptionalAuth | multipart 字段 `file` → `{url}`（**仅本站前缀可用**） |
| `GET/POST /ai-assistant/sessions`、`GET /sessions/{id}/messages`、`DELETE` | JWT + `Cap(ai_assistant.use)` | 消息 DTO 含 `images / sources / meta` |

### 6.3 出站口径（移动端必须照做，不是自由发挥）

- 集合恒非 null（`brands/faq/items/samples` 空即空数组，后端已归一）。
- 错误映射：429 透传；其余一律 502 固定文案「诊断服务暂时不可用」，**上游原文不外发**（ADR-0064 决策 9）⇒ 移动端只展示 `message`，不要自己拼状态码。
- `health.ok=false` 时**连已拿到的字典一起丢掉**。
- `picker==='model'` 才是型号档；其余与 `null` 一律系统档。引入第三个值时按系统档处理（已知未定项）。

### 7.2 必须新增的守护（都会红在真问题上的那种）

1. 专项页正向断言（§5.2 末行）—— 反向断言已存在，**放宽必须同批改成正向**，否则等于删守护。
2. `diagnosisCompose` 与 `frontend/src/utils/diagnosisCompose.ts` 模板字面量一致（跨栈防漂移）。
3. 图片上限常量 == 3（与后端 `diagnosisMaxImages` 同值），并锁「前端先拦，不靠后端拒绝」。
4. 纯图轮次可发送（`sendInput` 的 `text.length==0` 早退必须在 `images.length>0` 时放行）。
5. `done.content` 优先、缺席回退累积（两条路径各一例，防止 #2293 合入后正文被丢）。
6. `health.ok=false` ⇒ 引导面整块不渲染。

### 7.3 真人验收（真机 + mp-weixin，一条条打勾）

1. 进诊断页：欢迎区出品牌卡与 FAQ；`health` 失败时整块留白、无死按钮。
2. 四步向导：中力走「系统」档、林德走「型号」档（含搜索），组句后正文可编辑再发。
3. 故障码：输入「E01」出命中提示；输入乱码不出提示、不报错。
4. **有图无字**：拍一张发出去，8~15s 内出完整回答（不是空白、不是 `[错误：…]`）。
5. 超 3 张：第 4 张被拦并给可读提示；单张 >5MB 被后端拒并显示「图片单张不能超过 5MB」。
6. 长回答：超过 30s 时等待态仍在、计时在走（不再 30s 消失）。
7. 连续追问：第二轮能接上上文，不同学员互不串线。
8. 重进页面/切走再回来：会话在抽屉里，历史消息的附图与徽章/耗时能回显。

### 7.4 真实联调（一次，会消耗对方额度）

`code-hint` 命中 + 一轮带图对话 + 一轮纯文字追问，三条读数全绿才算通；失败按 runbook 的错误分层定位，**不要**在联调中改白名单常量。
