## 结论先行

**维护者拍板：不立。** 不挂 CI 必检、不挂 pre-commit 拦提交、不改 ruleset、不改 `.github/scripts/lib/gate-validator.mjs`。

`npm run audit:spacing -- --all` 保持为**提交前自检命令**：读数可以写进 PR 正文，但**不参与判绿红**，与 `npm run test:impact` 同形（同批已写进根 `AGENTS.md`「命令速查」的移动端条目）。

## 1. 三条理由

1. **方向相反**：这个仓在持续减门——② 于 2026-11-05 整体退役（#2320）、①b 整体退役（#2103）、`pr-evidence` 自认荣誉制、ruleset 必检只剩 `ci-summary`。新增一道必检要动 ruleset，且每个 PR 都要付一次成本。
2. **判据是判断类**：间距的「违规」与「有意」边界靠白名单 + 原型实测锁值（见 `scripts/spacing-whitelist.json` 每条 `reason`），机检只能保证「改了没登记」，保证不了「这个值对不对」；硬判据会迫使每处原型锁值都去争一条白名单，等于把判断挪进脚本，造第二份口径。
3. **成本持续、收益一次性**：漂移是低频事件（本轮 5 轮收敛后一次归零），而门是每 PR 的固定税；白名单本身还会随页面改版增长，那时误红要人工解释。

## 2. 现测读数（2026-11-20，master `b23b6ce5`）

- `npm run audit:spacing -- --all` ⇒ `扫描 121 个 .uvue：WARN 0 / INFO 0 / SKIP 152`。
- 白名单 19 条（8 个整页前缀 + 11 个选择器），逐条带 `reason`；新增条目按文件头 `$comment` 的约定在 PR 里说明来路。
- 现有守护面不缺：`utils/modulesDeclarationContract.test.js` 仍有 600 行预算；本轮唯一的红是他人未提交的 `utils/touchTargetContract.test.js` D 条（要求一个不存在的组件），与本裁定无关。

## 3. 明确不做

- 不新增 CI 门、不改 ruleset、不给 `audit:spacing` 加 `--strict` 的必检调用点。
- 不把白名单做成「豁免标记 + 判红」的第二套机制（那是判据 C 那类，见 `docs/design/20261107-兜底边口径机检判据边界裁定.md`）。
- 不把间距阈值写进任何测试断言或文档常量（页面锁值以原型实测为准，会随改版漂）。

## 4. 复议条件（不执行）

若将来复议，形态必须满足三条：① **非必检**（独立 job 或 `continue-on-error`，只提示不判红，先例同 `lint-issue-references` 在预检里的用法）；② 先取得真实 PR 上的误报率证据（白名单外的 WARN 是否真违规），再谈升必检；③ 先落新裁定替换本文，不复用本结论。
