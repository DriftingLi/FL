# 第一部分 · 规格

## Problem Statement

讲师今天只有一把钥匙。后端能力表里 `tutor` 角色绑死 5 个能力键，任何讲师账号拿到的都是同一份；超管无法给「只做题库的讲师」和「只写课程的讲师」分配不同权限——想让某人少看一个菜单，唯一的办法是删账号（[#2584](https://github.com/DriftingLi/FL/issues/2584) charting 取证）。

这把钥匙还太粗。`tutor.access` 一个键同时开了讲师工作区的入口、课程/章节的读、章节的写、附件的增删、文件库的 11 个端点。想要「能看不能改」的讲师，或者「能管自己文件但不动课程」的讲师，今天做不到（#2590 取证①②）。

更根本的是数据级没有边界。章节正文、章节附件、题目——只要你是讲师，就能改任何人的：

- 讲师 A 能改讲师 B 的章节正文、删 B 的附件（`model/training.go:151-153` 的注释就明写了「讲师之间无内容隔离」）；
- 讲师 A 能改、删、提审讲师 B 创建的题目（题目的 `created_by` 字段一直存在，但三条写路径都不校验它）。

对照之下，同一个人写的文件库（#2494）**有**严格归属隔离——同一个身份在两个面上一紧一松，这个不一致本身就是缺陷信号（#2587/#2586 取证）。

## Solution

三步，一步一个独立 PR：

1. **拆粗键（阶段一）**：`tutor.access` 收缩为「工作区入口 + 课程/章节读」；新增 `course.author`（章节写、附件增删、提审、图文插图上传）与 `tutorfile.manage`（文件库全部端点）。静态能力表让讲师默认三键全拿，**上线当天讲师行为逐字不变**——这一步不收紧任何人的权限，只把「能力的名字」放到位，让后两步有地方挂。
2. **数据级隔离（阶段二）**：两套彼此独立的域层谓词。课程侧引入**课程级认领制**（多讲师可共认一门课，认领了才能写）；题库侧按 `created_by` **个人隔离**（读全量、写隔离）。两套谓词不交叉：认领课程与能否改某道题无关。
3. **授权链动态化（阶段三）**：完整复刻 admin 的角色链（#1618/ADR-0074）——`tutor` 从静态角色翻为动态角色，能力由 `tutor_role` + 角色能力表回答，超管按账号挂角色；配套前端从「静态能力表」切到「运行时能力集」（与 admin 同一条管线）。

## User Stories

1. 作为超级管理员，我希望给某位讲师只挂「题库讲师」角色，以便他不必看到课程和文件库菜单。
2. 作为超级管理员，我希望给某位讲师挂「只读讲师」角色，以便他能查阅内容但不能改动。
3. 作为超级管理员，我希望新建讲师默认没有任何权限、由我显式授权，以便新账号不会默认获得全部能力。
4. 作为超级管理员，我希望讲师角色的能力在「角色权限」页里逐项勾选，以便不必改代码就能调整可达面。
5. 作为超级管理员，我希望受保护的全权讲师角色不可被改能力或删除，以便永远存在一个能救场的角色。
6. 作为讲师，我希望只看到我有权限的菜单项，以便不被点进去才 403 的项干扰。
7. 作为讲师，我希望能认领一门无人负责的课程，以便开始编写它的章节。
8. 作为讲师，我希望能和另一位讲师共认同一门课，以便分工写不同章节。
9. 作为讲师，我希望能在「我的课程」列表上直接看到哪些课我已认领，以便知道哪些能改。
10. 作为讲师，我希望认领后能看到同课的其他讲师，以便知道谁在和我一起编。
11. 作为讲师，我希望能退出认领，以便交接给其他人。
12. 作为讲师，我希望退出认领后我写过的章节仍归属我，以便历史记录不被抹掉。
13. 作为讲师，我希望未认领课程时写按钮被禁用并给出「先认领」的明确提示，以便不白点。
14. 作为讲师，我希望只被允许改自己创建的题目，以便我的题库不被别人误改。
15. 作为讲师，我希望仍能看到全部题目（含他人的草稿与待审），以便参考和学习。
16. 作为讲师，我希望列表能筛「我创建的」，以便快速找到自己的题。
17. 作为讲师，我希望列表有一列显示创建者，以便知道某道题是谁的。
18. 作为管理员，我希望能给某位讲师代分配课程、也能移除，以便在讲师离职或分工调整时兜底。
19. 作为管理员，我希望自己改任何题目、任何章节都直接生效并不受认领约束，以便不被讲师规则卡住。
20. 作为讲师，我希望被拒时看到明确原因（「请先认领本课程」/「只能编辑自己创建的题目」），以便立刻知道该怎么办。
21. 作为讲师，如果我的账号还没被授权，我希望登录后看到一句「还没有讲师权限，请联系管理员」，而不是一片空白。

## Implementation Decisions

### 阶段一 · 拆粗键（P1）

- **A1 键形与归属**：`tutor.access` 收缩为「讲师工作区入口 + 课程/章节**读**」；新增 `course.author`（章节写/附件上传删除/提审/Vditor 传图）与 `tutorfile.manage`（文件库全部端点）。两个新键**只绑讲师角色**，不授给管理员、不进超管的能力全集——与现状逐字一致（管理员今天也打不进讲师面端点，编辑课程走管理端 `course.manage`），也符合既有裁定「不把不属于超管的身份授给它」。
- **A2 后端路由划分**：讲师域读三端点留 `tutor.access`；写六端点挂 `course.author`；文件库**九端点**挂 `tutorfile.manage`，其章节侧换挂（`POST /api/tutor/chapter/:chapter_id/files/swap`）例外挂 `course.author`——它改的是章节的附件挂接并把章节打回草稿，键跟着它改变的资源走（#2595 实施裁定）。组级守卫拆成「读组 + 写组」，不再一键盖全。
- **A3 前端页键映射**：仪表盘/我的课程/章节管理页保持 `tutor.access`（读面）；章节编辑页改挂 `course.author`；文件库页改挂 `tutorfile.manage`。章节管理页内的上传/删除按钮对只读讲师**由后端 403 兜底**，本阶段不新增页内逐能力分流（现状无此机制，新增一项要动所有讲师页）。
- **A4 标签页键错位顺带修**：讲师端「标签管理」页的能力声明从 `question.author` 改为 `catalog.author`，与后端标签接口的守卫对齐——修的是前端声明与后端守卫**早已不一致**的既有缺陷。
- **A5 配套生成面**：能力表新增两键后，前端能力类型文件与能力词表（穷尽 Record）必须同步再生成/补词条，否者类型检查红。管理端角色配置页无需专门改动：没有对应侧栏页的能力键会自动归入「动作」分组。**注意这句只对已在可授权集合里的键成立**——可授权集合是各角色能力的并集，只绑讲师、不授超管的键（本阶段两键）永远不会进那个并集，故也不会出现在超管勾选面（#2595 实施裁定：A1 优先，不为此改动管理端）。
- **A6 零行为变化**：静态表讲师默认三键全拿，故上线当天任何讲师的可达面与今天逐字相同。**本阶段不做任何收紧**。
- **A7 PR 边界**：一个 PR。含路由挂键、静态表、前端页配置、生成链、锁定测试更新。

### 阶段二 · 数据级隔离（P0）

#### 块 B · 课程认领（tutor 域）

- **B1 认领实体**：课程级认领关系 `(tutor_id, course_id, source, created_at)`，`(tutor_id, course_id)` 唯一；`source ∈ {self, admin}` 记分配来源供审计。多讲师可共认同一门课（多对多，不是归属）。
- **B2 编辑权谓词**：讲师域新增具名谓词「要求课程认领」，入参为当前讲师与目标章节，内部由章节查课程再查认领行。**五条写路径统一前置**：更新章节、上传章节附件、删除章节附件、批量删除章节附件、提交章节审核。管理员不经讲师面端点（阶段一已定新键不授管理员），故不需要旁路分支——这是数据级不变式由域具名谓词单点表达，而非能力表能表达的东西。
- **B3 端点与能力键**：讲师自助认领 `POST /api/tutor/course/:id/claim`、退出 `DELETE /api/tutor/course/:id/claim`，均挂 `course.author`；管理员代分配/移除挂在讲师账号管理组（`tutor.manage`）。
- **B4 读面不受认领限制**：课程与章节的读对任何有 `tutor.access` 的讲师开放。理由与题库「读全量、写隔离」同：认领是编辑权的边界，不是可见性的边界。
- **B5 重复认领档位**：本人已认领再认领返回 **409「已认领」**，不新增行（并发兜底）；不做静默幂等 200——前端要能把「你已经在里面了」和「刚成功」分开显示。
- **B6 退出/移除不回溯**：退出或移除只断**今后**的编辑权。章节的作者归属字段保留（既有裁定：归属是「作者」而非「最后编辑者」）、在审快照照常走完审核（审核权在管理员）。最后一名认领者退出后课程回到「无主」状态，对全体讲师开放认领。
- **B7 存量回填**：迁移内以「章节作者归属非空的课程」为其归属讲师回填认领行（来源记 `self`，历史归属视同自助认领），幂等可重跑。无主课程不回填、保持开放认领。

#### 块 C · 题库写隔离（questionbank 域）

- **C1 谓词形态**：题库域新增具名谓词「要求题目归属」，入参为题行、当前操作者 id 与类型；管理员直通，其余要求 `created_by == 操作者`。三条写路径（更新、提交审核、删除）在载入题行之后统一调用。
- **C2 NULL 题处置**：`created_by` 为空的存量题**仅管理员可写**，讲师一律拒。空值比例待生产库现测（本机无数据库连接，契约测试会干净 skip），不阻塞规则成立——规则本身与比例无关。
- **C3 错误档位**：非本人题写操作回 **403**「只能编辑自己创建的题目」。不用 404 伪装：编辑面本来就全量可读，题目的存在性不是秘密，404 在这里没有信息保护收益。
- **C4 读面不变**：题库编辑面分流（作者/审核者看全量含草稿与待审，学员走题库池）逐字不动。
- **C5 前端顺带补**：题库管理页加「我创建的」筛选开关（默认关）与「创建者」列。题目 DTO 早已带 `created_by` / `created_by_type`，前端只加展示与筛选轴，不改接口形状。

#### 块 D · 认领入口前端形态

- **D1 认领状态数据源**：讲师课程列表 DTO 扩两个字段 `claimed_by_me`（布尔）与 `claim_count`（整数），由一次联表聚合算出，不逐行查。另加「课程认领讲师列表」读端点，供章节页展示共认者与管理端分配面板复用。
- **D2 课程卡片交互**：课程卡片操作区加认领态——未认领显示「认领课程」按钮（点击即认领，成功后乐观更新）；已认领显示「已认领」标签并保留原「管理章节」按钮；他人已认领显示「N 位讲师在编」中性标识且**仍可认领**（共认已定）。退出入口不放卡片（低频动作，放章节管理页）。
- **D3 章节页认领态**：章节管理页顶部加认领条——已认领显示共认讲师名单 + 「退出认领」按钮（确认框写明不回溯：「退出后你不能再编辑本课程；已写章节的归属与在审内容不受影响」）；未认领时**写操作按钮全部禁用**并显示提示条「认领本课程后才能编辑章节」（带认领按钮）。章节编辑页由直达链接进入未认领课程时同降级：提示条 + 保存/提交禁用（后端 403 兜底仍在）。
- **D4 管理端分配入口**：讲师管理页的讲师行加「分配课程」动作（抽屉：课程多选 + 已分配标识，调管理端分配/移除端点）。「给谁分配课程」是讲师管理动作，落在讲师管理页而不是课程页。移除确认文案同不回溯口径。
- **D5 错误提示口径**：统一动作级 toast，不做页级错误页——未认领写→「请先认领本课程」；题库非本人→「只能编辑自己创建的题目」；重复认领→「你已认领本课程」；认领成功→「已认领，可以开始编辑章节」。
- **D6 D 块所属阶段**：D 块**随阶段二一起发布**（认领机制没有入口就等于没有机制）。D1 的 DTO 扩展与 D2/D3/D4 的 UI 在同一个 PR 内完成。

### 阶段三 · 授权链动态化（P2）

#### 块 E · 后端授权链

- **E1 实体与迁移**：`tutor_role`（角色）+ `tutor_role_capability`（角色能力）+ 讲师行挂 `role_id`（可空）。**一条迁移内**完成建表、seed 四模板、存量讲师全部挂到全权角色——避免出现「表建好了但没人有角色」的全员 fail-closed 中间态（admin 迁移的同姿势）。
- **E2 fail-closed 语义**：`role_id` 为 NULL ＝ 未授权，取不到任何能力。**新建讲师默认 NULL**，由管理员显式挂角色。
- **E3 resolver 形态**：并列新包（复制 `admincap` 姿势，只依赖 model/authz/gorm 以避开 import 环），走 `tutor.role_id → tutor_role → 能力`；进程内缓存 **TTL 40s**，与 admin 同口径；`granted=false` 也缓存，**故障不入缓存**（否则一次抖动会让该讲师在 TTL 内持续被判无权限）。
- **E4 中间件分派**：既有的动态角色能力解析源接口加**并列方法**（讲师能力集），守卫的判定逻辑按角色分派：admin 走既有解析源、tutor 走新解析源。**不泛化单方法**——泛化会波及既有测试 stub 与估值模块的注入面，收益不抵风险。
- **E5 dynamicRoles 翻转**：动态角色集合从 `{admin}` 翻为 `{admin, tutor}`。翻转后静态能力表对讲师 `fail closed`（该角色的静态行清空），能力只由数据层回答。静态角色（学员/招聘者）不受影响。
- **E6 四模板能力集**（阶段一之后的讲师侧共 7 键）：

  | 角色 | 能力集 | 说明 |
  | --- | --- | --- |
  | 全权讲师（protected） | 7 键全量 | **由代码回答、不落行**，能力词表仍只有能力表一个事实源 |
  | 题库讲师 | `tutor.access` + `question.author` + `catalog.author` + `notification.use` | 4 键；保留入口键才能登录进工作区 |
  | 课程讲师 | `tutor.access` + `course.author` + `tutorfile.manage` + `notification.use` | 4 键 |
  | 只读讲师 | `tutor.access` + `notification.use` | 2 键；**不给** `catalog.author`——标签接口的 CRUD 一体、无只读键，标签页守卫自然拦住 |

  `contribution.review`（投稿审核）**仅全权持有**，模板不授：讲师端投稿审核 UI 是二期独立工作。不新造 `catalog.read` 之类的只读键。
- **E7 角色管理端点**：讲师角色 CRUD + 讲师挂角色端点，挂 `tutor.manage`。护栏对齐管理端先例：protected 角色不可改能力、不可删除（409）；不可摘掉自己正在挂的角色（防自锁）。
- **E8 缓存时效**：角色变更最多延迟 40s 生效（与 admin 同口径）；讲师禁用/重置口令已即时吊销全部会话（既有行为），角色变更**不做**即时失效——一致性优先于实时性，与 admin 先例一致。

#### 块 F · 前端运行时能力

- **F1 能力集接口**：并列独立端点 `GET /api/tutor/me/capabilities`，响应形状与 admin 的同名端点一致（`{capabilities, granted}`）。**只挂登录守卫、不挂能力键**——未授权讲师也要能取到空集，否则会撞出 403 而无法显示「还没有权限」页。不扩展 `/auth/me`：资料面与权限装载有各自的状态机（尤其「装载失败」要能与「资料没补齐」区分），混在一起会把两个承诺搅成一句话。
- **F2 装载管线**：前端登录态 store 的能力装载按角色分派（admin→管理端端点、tutor→讲师端端点），其余复用既有状态机：失败落空集且**不保留上一份**（否则刚被收回权限的人还能看到菜单）、换账号作废在途装载、装载必然落定（ready/failed）。
- **F3 codegen 边界**：生成物的动态角色集合加 `tutor`，静态表的讲师行渲染为空（与 admin 同姿势）。学员/招聘者的静态表保留不动。`hasCapability('tutor', …)` 恒 false 是 fail closed；消费面已全部走运行时判定入口。
- **F4 守卫与侧栏零新机制**：动态角色集合翻转后，讲师自动走既有的「守卫发现角色是动态的 → 先补拉能力集 → 用运行时集合判定」管线；侧栏过滤同源。子域边界（导师专属子域）按角色判定，与能力集正交，不受影响。
- **F5 未授权讲师落点**：新建讲师端「无权限」页，复刻管理端同名页的**两态**——空集＝「当前账号还没有讲师权限，请联系管理员在讲师角色里授权」；装载失败＝「权限加载失败」并给重试按钮。该页不声明能力位（否则自锁）；侧栏空、顶栏给出身份与退出。**不复用**管理端同页（会把「联系超级管理员/角色权限/管理员管理」的管理端指引印给讲师）。
- **F6 落点挑选**：新增讲师侧落点函数，按讲师侧栏的 nav order 取第一个「当前能力集持有其能力位」的页；空集→F5 页。因仪表盘挂 `tutor.access`，任何已授权讲师的落点恒为仪表盘。

### 各端需求面（概要，实施票再细化）

- **Web 讲师端**：阶段一改页键；阶段二加认领交互（课程卡片、章节页认领条、退出确认）与题库筛选/创建者列；阶段三切运行时能力集 + 无权限页。
- **Web 管理端**：阶段二加讲师行「分配课程」；阶段三加讲师角色 CRUD 与挂角色 UI（角色权限页与讲师管理页）。
- **后端**：三阶段各自的键、谓词、实体、迁移与分派。
- **移动端**：本规格射程外；移动端若读讲师面接口，阶段一后仍由静态三键全拿保证可达（移动端不走动态能力集）。

## Testing Decisions

- **阶段一（键与声明，最高层 seam＝路由守卫 + 生成物）**
  - 能力集合断言：讲师静态集合包含三键、管理员集合不含两新键。
  - 生成物字节锁：前端能力类型文件与能力表渲染结果全等（既有锁，扩展新增键）。
  - 路由守卫存在性：讲师域写组与文件库组各自挂了正确的键（既有蓝图级守护测试扩展）。
  - 行为不变断言：讲师对全部讲师面端点可达性逐字不变（用能力表驱动，断言「三键全拿 ⇒ 全端点可达」）。
- **阶段二（数据级谓词，seam＝service 层公开方法）**
  - 认领谓词：未认领讲师调五条写路径全拒；认领后放行；退出后再拒；退出后章节作者字段仍在。
  - 共认：两位讲师共认同课，各自可写；重复认领返回 409。
  - 存量回填：迁移后有作者归属的课程生成认领行、无主课程无认领行；迁移幂等重跑不重复。
  - 题目归属：他人题目更新/提交/删除三路径全 403；管理员直通；`created_by` 为 NULL 时讲师拒、管理员通。
  - 契约测试沿既有纪律（随机 schema、按 `current_schema()` 收窄的 PG 契约用例）；本机无数据库连接时会干净 skip，**首跑在 CI**。
- **阶段三（授权链，seam＝resolver + 中间件 + 端点）**
  - 模板能力集：四模板各自的能力集合与预期全等；protected 角色由代码回答、无数据行。
  - fail closed：`role_id` 为 NULL 的讲师取到空集且 `granted=false`；解析故障时守卫渲染 500 而不是 403（故障不得伪装成权限问题）。
  - 缓存语义：TTL 内不重复查库；`granted=false` 命中缓存；故障不入缓存。
  - 前端：能力集装载失败落空集且不保留旧份；动态角色判定不回落静态表；未授权讲村落 F5 页。
- **不新增守护/机检**：判断类问题不接确定性检查（既有编码标准约定）。

## Out of Scope

- **讲师审核权**：`question.review` / `chapter.review` 保持管理员独占。「先审后发」是内容安全底线，放开讲师审核等于自审自批。
- **投稿审核的讲师端 UI**：`contribution.review` 讲师端界面属二期独立工作；本规格只在第四模板里保留全权讲师的该能力位。
- **移动端（training-app）**：本规格只覆盖 Web 前端与后端。移动端不走动态能力集，靠静态三键全拿保证可达。
- **讲师侧多角色**：一位讲师一个角色（`role_id` 单值），不做多角色合并。
- **能力变更的即时推送**：角色变更靠 TTL 自然生效，不做 WebSocket/SSE 推送。
- **各端实施代码**：本规格只定语义，实施票由 `/to-tickets` 切。

## Further Notes

- 图 [#2584](https://github.com/DriftingLi/FL/issues/2584) 的 Decisions so far 是决策索引：每条决策的完整论证在对应票的 resolution comment 里，本规格不复述论证、只固化结论。
- **三阶段严格按「阶段一 → 阶段二 → 阶段三」发布**（对应票面上的 P1→P0→P2 序号）。阶段一必须先落：阶段二/三都依赖新键存在。阶段二与阶段三彼此独立，但阶段三的模板能力集按阶段一之后的 7 键定义，若阶段二先行完成则能力键不变、无冲突。
- 阶段二的两套谓词**互不引用**：认领状态不影响题目归属判定，题目归属不影响课程认领。这条是本规格里最容易在实施时被「顺手统一」掉的地方，别统一。
- 表名、枚举值、接口路径的确切拼写属实施细节，由实施票定；但「能力键名恰一个点」「protected 角色能力由代码回答不落行」「未授权＝空集且 fail closed」三条是硬约束。
