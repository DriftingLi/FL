## 0. 口径

| 项 | 定义 |
| --- | --- |
| 扫描面 | `frontend/src/**/*.vue`，排除 `__tests__`，共 **172** 个 |
| 裸用 | 标签出现在 `components/ui/**` **之外** 的 `<template>` 里（封装层自己要渲染 `el-*`，不算裸用） |
| scoped 取值 | `<style scoped>`（含 `@media` 内）的声明；非 scoped 的单独标注 |
| 容器 vs 部件 | 选择器里带 `card/panel/tile` **且不以** `title/header/body/footer/list/item/...` **收尾**的才算容器（`.card-title`、`.stat-cards` 栅格、`.notification-panel` 内块都不算） |
| 渲染实测 | CDP `getComputedStyle` 在真实页面上量，不用源码推断 |

## 4. 切换面：三个组件是三种意图，但错位了 4 处

`el-tabs` / `UiSegmentTabs` / `UiUnderlineTabs` 不是「三种重复」，而是**三种意图**；错位的是「参数选择」有 2 处用了全宽 tab 条、「面板切换」有 2 处用了胶囊：

| 意图 | 判据（三轴里的哪一轴把它们分开） | 落点 | 形态 |
| --- | --- | --- | --- |
| **参数选择** | 目标=换一组筛选条件或一个会被保存的取值；后果=重新查询/写入设置；半径=当前列表或字段 | `UiSegmentTabs` **18** 处 / 14 文件；`el-tabs` 2 处（`ProfileReview` 待审核/已通过/已拒绝、`ForumManage` 全部/讨论/问答/经验） | **胶囊 vs 全宽 tab 条** ← 错位2处 |
| **视图切换** | 目标=换呈现方式（编写/预览）；后果=不改数据；半径=当前输入区 | `UiUnderlineTabs` 2 处（`ForumMarkdownInput`、`MarkdownEditor`） | 下划线 |
| **面板切换** | 目标=换一整块工作区；后果=整块替换、可能丢未保存编辑；**半径=整个内容区** | `el-tabs` 4 处（`ContributionManage`、`ForumManage` 外层、`ValuationConfigManage`、`TutorChapterEdit`）；`UiSegmentTabs` **2 处**（`FaqManage` 分类/条目、`Materials` 课程资料/学员投稿） | **全宽 tab 条 vs 胶囊** ← 错位2处 |

截图：`05-switch-params-light.png`（/admin/faq 的胶囊）vs `06-switch-panel-light.png`（/admin/valuation-config 的 `el-tabs type="border-card"`）。

**为什么「参数选择」不能再拆成「数据档/视图档」两套说法**：18 处参数选择里 **16 处是列表筛选**（最新/最热、已解决/未解决、全部/我的、类型、时间范围、图文/视频/文档…），只有 2 处是「会被保存的表单取值」（论坛正文格式）。原 `ui-conventions` 把胶囊说成「数据档 = 会被保存的选择」，与它 16/18 的落点对不上 —— 本次按实际落点改写（见 ui-conventions 的「参数选择」行）。

### 7.4 描边：只有一档

`1px solid var(--color-border-light)`（= `border-line`），13 处容器显式写、其余由 `UiCard` 提供。
例外 1 处：`.result-card` 用 `--color-border`（= `line-strong`）—— 它是作答页里的「结果卡」，比题面卡更实；迁移票复核后要么改回 `line`，要么留成登记例外。

## 8. 顺带查出的缺陷（已另开票）

全站**没有配置 Element Plus 的 locale**（`grep -r "zh-cn\|zhCn" frontend/src` 零命中），所以 EP 内置文案一律英文，而 `useConfirm` 是因为自己写死了中文才没露出来：

| 位置 | 现在渲染 | 契约 |
| --- | --- | --- |
| `UiPagination` 的 total（34 处，`showTotal` 默认开） | `Total 26` | `UiPagination.vue:20` 的注释写着「共 X 条」 |
| `el-popconfirm` 按钮（5 处） | `Yes` / `No` | `ui-conventions`「中文优先」 |

截图：`07-pagination-total-en-light.png`、`08-confirm-inline-yesno-light.png`。

这不是形态问题，是**同一意图的两套形态各自带了一套语言**：模态确认有中文默认值（`useConfirm` 的 `BASE`），行内确认没有。修法（`ConfigProvider` + `zhCn`，或给 `el-popconfirm` 传中文按钮文案）不在本票射程。
