## 1. 问题陈述（用户原话改写）

微信小程序每个页面右上角都有一个**原生胶囊按钮**（"···" 菜单与关闭/返回首页按钮的组合），它由微信客户端绘制，位置固定、悬浮在页面内容之上，开发者**不可移除、不可遮挡、不可自定义内容**（§3.1、§3.2）。当页面设置 `navigationStyle: "custom"` 后，微信只移除原生导航栏，**胶囊仍然保留**（§3.1）。

用户反馈的冲突形态：页面在胶囊区域（右上角）或紧挨其下方放置了自己的功能按钮/操作区（如「取消」「保存」「发帖」「⋯」菜单、图标按钮组、计时器），导致：

1. **视觉重叠/紧贴**：自放按钮与胶囊并排挤在一行，间距不足或直接落进胶囊矩形；
2. **交互冲突**：点自放按钮时可能误触胶囊（或反之），微信设计指南明确要求「若开发者在附近放置可交互元素，要特别注意交互事件是否会冲突」（§3.2）；
3. **观感差**：自绘头部与原生胶囊风格不统一，页面显得「没设计过顶部」。

## 3. 官方口径（逐条带 URL；抓取日 2026-10-23）

### 3.1 胶囊在 `navigationStyle: custom` 下仍保留

- **微信官方·页面配置**：`navigationStyle` 可选 `default` / `custom`，`custom` = **「自定义导航栏，只保留右上角胶囊按钮。」**（iOS/Android 微信 7.0.0+，Windows/Mac 基础库 ≥ v3.6.1）
  来源：https://developers.weixin.qq.com/miniprogram/dev/reference/configuration/page.html
- **uni-app 官方·API 文档**（uni-app x 亦按此语义）：「在小程序平台，如果原生导航栏被隐藏，**仍然在右上角会有一个悬浮按钮**，微信下也称为胶囊按钮。」
  来源：https://uniapp.dcloud.net.cn/api/ui/menuButton.html
- **uni-app x 官方·pages.json**：`navigationStyle` 「仅支持 default/custom」，「custom即取消默认的原生导航栏」；custom 时「系统状态栏背景色恒为透明」；（旁证：支付宝小程序 custom 不生效）。
  来源：https://doc.dcloud.net.cn/uni-app-x/collocation/pagesjson.html

### 3.2 胶囊的机器行为与设计要求（官方设计指南）

微信官方设计指南「2.1 导航明确，来去自如」（https://developers.weixin.qq.com/miniprogram/design/）原文要点：

1. 小程序**所有页面**（含内嵌网页和插件），微信都会「在其右上角放置小程序官方控件」；
2. 「开发者**不可对其内容自定义**，但可选择深浅两种基本配色以适应页面设计风格」——即只能配深浅色，不能动位置/形状/功能；
3. 「官方菜单位于界面**固定位置**，开发者设计界面时**需预留该区域空间**。若开发者在附近放置可交互元素，**要特别注意交互事件是否会冲突**。」——这是对用户所提冲突的官方直接回应；
4. 导航建议：「建议所有的次级页面左上角提供返回上一级页面操作」「保持不同页面间导航一致，指向清晰，有路可退」；自有导航「样式与微信小程序官方控件样式保持一定差异，以便区分」。

（设计指南未给出「页面级操作按钮必须放哪」的硬性规定，只有「标签分页栏可固定在页面顶部或底部」等间接建议——本条为**未规定**的明确说明，非缺漏。）

### 3.3 `getMenuButtonBoundingClientRect()` 的准确口径

- **微信官方 API**（https://developers.weixin.qq.com/miniprogram/dev/api/ui/menuButtonBoundingClientRect 的稳定路径为 `/dev/api/ui/menu/wx.getMenuButtonBoundingClientRect.html`）：基础库 **2.1.0** 起支持；「获取菜单按钮（右上角胶囊按钮）的布局位置信息。坐标信息以屏幕左上角为原点。」返回 `width / height / top / right / bottom / left`，**单位均为 px**（逻辑像素）。页面正文经 webReader 抓取核验（页面为 JS 渲染，WebFetch 只能取到目录）。
  来源：https://developers.weixin.qq.com/miniprogram/dev/api/ui/menu/wx.getMenuButtonBoundingClientRect.html
- **uni-app 官方 API**（跨端封装，uni-app x 同名同义）：返回值字段/单位与微信一致（六字段均 number、单位 px）；平台差异——微信/支付宝/百度/抖音/飞书/QQ 等小程序 **√**，**App 与 H5 ✗**（调用报 not implemented；支付宝行为有差异）。
  来源：https://uniapp.dcloud.net.cn/api/ui/menuButton.html
- **典型用法（官方示例）**：与 `uni.getWindowInfo()` / `getSystemInfo` 联动——取 `statusBarHeight` 做状态栏占位、取胶囊 `top/height` 对齐导航条、取胶囊 `left/right/width` 让右侧操作区左移（见 §3.4 两条官方示例）。

### 3.4 官方自定义导航栏适配示例（两个一手范例）

1. **uni-app x 官方 `uni-nav-bar`**（uni-ui x，https://doc.dcloud.net.cn/uni-app-x/component/uni-ui-x/uni-nav-bar.html）：
   - 使用前提：pages.json 设 `"navigationStyle": "custom"`；组件「自动适配顶部安全区，用 padding-top 让出顶部状态栏的高度」；高度 44px（不含状态栏）；left/mid/right 三区；
   - **胶囊避让官方示例**（`#ifdef MP-WEIXIN` 内，onMounted 执行）：
     ```js
     const menuButtonInfo = uni.getMenuButtonBoundingClientRect()
     const windowInfo = uni.getWindowInfo()
     // 预留胶囊按钮宽度和右侧间距，让右侧插槽显示在胶囊按钮左边（文档原注释）
     rightMargin.value = windowInfo.windowWidth - menuButtonInfo.right + menuButtonInfo.width
     ```
     模板对 `<template #right>` 外层 view 施加 `transform: translateX(-rightMargin + 'px')`。
2. **微信官方 WeUI `navigation-bar`**（wechat-miniprogram/weui-miniprogram，`gh api` 读源码一手核验）：
   - 组件文档：「当页面配置 navigationStyle 设置为 custom 的时候可以使用此组件替代原生导航栏」，back 左 / title 中 / right slot 右（https://github.com/wechat-miniprogram/weui-miniprogram/blob/master/docs/navigation.md）；
   - 源码 `src/components/navigation-bar/navigation-bar.ts:56-67`（`gh api repos/wechat-miniprogram/weui-miniprogram/contents/...` 实读）：`attached()` 中 `const rect = wx.getMenuButtonBoundingClientRect?.()` + `getSystemInfo` 取 `statusBarHeight` 与 `menuButtonWidth: rect?.width`，右侧按胶囊宽度让位（less 中 `.weui-navigation-bar__right` 以 menuButtonWidth 预留——宽度让位型，与本仓「左边界钉位型」同族）。

### 3.5 uni-app x 编译到 mp-weixin 的支持结论

- `pages.json` 的 `navigationStyle`（default/custom）在 uni-app x 对微信小程序目标**支持**（§3.1 第三条，兼容性表格覆盖微信小程序列）；
- `uni.getMenuButtonBoundingClientRect()` 编译到 mp-weixin 即映射微信同名 API（uni-app x 文档无独立 API 页，语义随 uni-app 侧；本仓 `utils/system.uts:68` 的调用经 #1602 四门验证在小程序端可用——仓内一手证据，非官方文档断言）；
- uni-app x 侧 CSS 不支持 `env(safe-area-inset-*)` / `var()`（ADR-0035:107，`docs/agents/uvue-css.md`），安全区只能 JS 动态取——本仓因此走 `useSafeArea()` 测量层路线，与官方 uni-nav-bar 的 JS 计算路线一致。

## 4. 缺陷清单（按页面；均只陈述，不动代码）

### 4.1 高：`pages/search/search` ——「取消」按钮无胶囊避让（N06 自绘页空档）

- 事实链：`search.uvue:4` 状态栏占位（仅 `statusBarHeight`，不含胶囊垂直带）→ `:6-15` 自绘 `search-header`（`:420-425`：`padding: 16rpx 24rpx`，背景主色）→ 输入框 `flex:1` + 行末**「取消」文字按钮**（`:11`；样式 `:461-466`：`padding: 24rpx 8rpx 24rpx 24rpx`，右 padding 含在 header 的 24rpx 内）。
- **无任何胶囊矩形测量**：N06 页不受 `app-nav-bar` 的 `rightSlotStyle` 保护；`safeAreaContract` 只管组件、`batch6UiContract:130-140` 只管状态栏占位——顶部右端是**机检空档**。
- 几何推断（**推断**，需真机取证）：以 375pt 宽机型为典型，胶囊 left ≈ 281pt（右边带 ≈ 94pt ≈ 188rpx）；「取消」按钮右缘距屏右缘仅 24rpx（12pt）——**深入胶囊水平带约 80pt**。垂直向：胶囊 bottom ≈ statusBar + 32pt，而 search-header 内容带 ≈ statusBar + 8pt ~ 52pt——**两带重叠**。即取消按钮与胶囊同时满足水平重叠 + 垂直重叠，只是按钮整体在胶囊左侧、以紧贴/部分重叠形态并存（精确重叠量依机型胶囊实测矩形）。
- 交互冲突：取消按钮命中区（padding 上下各 12pt）与胶囊左缘间隙不足，误触风险即微信设计指南 §3.2-3 所指情形。

### 4.2 中（需真机几何复验）：右槽内容宽于可用槽宽的三类页

机制背景：`app-nav-bar` 的右槽是**定宽容器**（`width = 750 − capsuleLeft`，rpx）+ `justify-content: flex-end`、无 overflow 裁切声明（`app-nav-bar.uvue:13-21`、`:181-187`）。内容超宽时溢出方向向右——**顶进「胶囊左边线 − 24rpx」的间隙带乃至胶囊矩形**；ui-spec §5.1 的纪律「放不下 = 页面把次要动作移出页头」是**靠页面自觉**，机检测不到。

典型机型换算（**推断**）：375pt 屏、胶囊 left ≈ 281pt ⇒ 可用槽宽 = 750 − 562 ≈ 188rpx，再扣 24rpx 间隙 ⇒ **内容可用 ≈ 164rpx**。

| 页面 | 内容估算 | 结论 |
| --- | --- | --- |
| `dashboard.uvue:96`（`['🔍','🔔','🛒']`） | 3 ×（44rpx 图标 + `padding: 0 12rpx`×2 = 24rpx） ≈ **204rpx** | 超 ≈40rpx，溢出推断成立；且 ADR-0035:26 记载 #1602 之前 dashboard 就是「右仅 32rpx 却放 3 图标」的老冲突点——图标数未减，靠的是槽宽扩大 |
| `forum.uvue:6-18`（✉️ 64rpx + 徽标 + 发帖 pill 120rpx） | ≈ **184-200rpx** | 临界超出；ADR-0035:26 记载「发帖按钮落在胶囊区」是 #1602 修复对象，修复方式是搬进右槽，未减宽度 |
| `practice-do.uvue:5-7` / `mock-exam.uvue:6`（计时 + 进度动态文字） | "⏱ 88:88"（≈150rpx）+ "50/50"（≈100rpx）+ `ml-24` | 两段合计最长 ≈270rpx 明显超宽（practice-do）；mock-exam 单段 ≈150rpx 临界 |

（以上三行全部是**静态代码 + 典型机型几何的推断**；真机取证判据沿 ADR-0035:120 口径：`uiautomator dump` bounds 对比胶囊矩形。）

### 4.3 低（记录在案，不必动）

- **N06 三页顶部内容与胶囊垂直带重叠**（`index` / `login` / `profile-setup`）：状态栏占位只垫 `statusBarHeight`，胶囊垂直带（状态栏下 ~0-32pt）内是页面首屏内容——内容居中、无右侧交互元素，无交互冲突；观感上「欢迎页」标签/logo 与胶囊同高并存，属可接受的低风险。
- **旧基础库回退失去避让**：`utils/system.uts:69` `rect == null`（基础库 < 2.1.0）⇒ `capsuleLeft = 0` ⇒ 右槽不限宽。微信 2.1.0 发布于 2018 年，现网占比可忽略（推断）。
- **register / forgot-password**：原生导航，胶囊由微信置于原生导航栏同一行，页面内容从导航栏下方开始——无冲突（微信原生行为，非本仓实现）。
- **jobs/job-list**：tab 行右端头像（:6 注释、:274-279）在 88rpx 页头之下，垂直带已过胶囊底缘——特意设计，判低。

### 4.4 死件待清理

`components/common/platform-nav-bar.uvue`（`padding-right: 80rpx` 写死，:95-100）与 `page-container.uvue`（`padding-right: 10rpx`，:75-80）：0 引用 + git 未跟踪；ADR-0035:69 判「直接删除」未执行。留着会被误当「已有避让组件」复用（`platform-nav-bar.uvue:2` 注释自称「解决小程序右上角遮挡问题」，实际是魔数让位——恰是 ui-spec §5.1 明令禁止的 `80rpx` 魔数形态）。

## 5. 业界常见解法盘点 + 对本仓各缺陷页的适配建议（只建议、不动代码）

按业界与官方实践归为五类；前三类有一手官方出处，后两类标注社区来源。

**S1. 自定义导航按胶囊矩形留白（官方主路线，本仓已实现于页头件）**
右缘钉在 `capsuleLeft − 间隙`（本仓 `app-nav-bar` 型）或按胶囊宽度整体右移（uni-nav-bar `translateX` 型、WeUI `menuButtonWidth` 型）。对本仓：**机制无需改**；缺口不在算法而在覆盖面——search 页未受保护（见 S1 对 search 的适配）。
- `search` 适配：自绘搜索头保留 N06 形态亦可，但「取消」按钮行必须引入胶囊测量——两个具体选项：① 搜索头行给右端预留 `useSafeArea().capsuleLeft`（取消按钮右缘 ≤ 胶囊左边线 − 24rpx，与页头件同间隙值）；② 仿 job-list 的下沉思路，取消动作并入输入框（清空 ✕ 已有，`search.uvue:9-11`）或左缘返回位，右端不放可点元素。

**S2. 胶囊高度对齐（垂直向适配）**
导航内容高度取胶囊 `height`、导航条顶取胶囊 `top`（WeUI / Taro-navigation-bar 的通用公式；社区教程如腾讯云《微信小程序自定义导航栏》https://cloud.tencent.com/developer/article/2433795，**非直接来源**）。本仓页头件固定 88rpx 正文高 + `statusBarHeight` 占位，与胶囊（高 ≈32pt）不同高——因为本仓右槽已让位，无并排冲突，不必改；若未来做「页头即胶囊同高」的极简形态可引用此公式。

**S3. 右侧操作区让位 / 次要动作移出页头（官方纪律，本仓 ui-spec §5.1 已明文）**
「放不下 = 移出页头（不隐藏、不换行、不压缩）」。对临界页的具体建议：
- `dashboard`：3 图标收敛为 2（如 🔍 并入 🔔 页或下沉到功能区宫格——`dashboard-menu-grid` 已有入口网格形态）；或右槽改「⋯」单钮弹出面板（与胶囊语义区隔需拉开样式差异，微信设计指南 §3.2-4 建议与官方控件保持差异）。
- `forum`：发帖 pill 下沉——页内已有「点击即进发布」的搜索栏（`forum.uvue:20-24`），发帖动作可并入该栏右端（在胶囊下方、无冲突）；✉️ 保留右槽单图标。
- `practice-do` / `mock-exam`：计时与进度合并单段（"⏱12:34 · 3/50"）或计时下沉到答题卡/底部操作条（页内已有底部 `.submit-bar` 形态，`practice-do` 的 bottom-placeholder :280 可挂）。

**S4. 操作下沉到内容区/底栏（页面级重排）**
适合「页头本来就不该放操作」的页（编辑保存类）。`resume-edit`（保存）、`custom-models`（＋添加）、`notebook`（新建）当前单钮在槽宽内、判低，可不动；若未来加动作，底栏优先（forum-detail 的回复面板、practice-do 的交卷条已是本仓先例）。

**S5. WeUI 模式（back 左 / title 中 / right 留胶囊宽）**
官方组件库的标准三段式。本仓 `app-nav-bar` 同构（leftIcon/title/right 槽），差异只在 WeUI 用胶囊**宽度**让位、本仓用胶囊**左边界**钉位——后者对「胶囊左侧间隙随机型变化」更稳健，不必迁移。

## 6. 结论与建议的后续动作

**结论**：本仓对胶囊冲突**已有全站约定与实现**（ADR-0035 → #1602/#1608/#1609：唯一测量层 `useSafeArea` + 唯一页头件 `app-nav-bar` 右槽让位 + 契约机检），与微信官方设计指南、uni-app x 官方 uni-nav-bar、WeUI 官方 navigation-bar 的路线一致。现存问题不在方法论，在**三个执行缺口**：N06 自绘页（search）未受避让保护、部分右槽内容宽于可用槽宽（几何无验证）、死件未删。

**值得开票的页面/事项清单**（按优先级；均建议先真机几何取证再动手，判据沿 ADR-0035:120）：

1. **search 页取消按钮胶囊避让**（高，新缺陷）：N06 自绘页顶部右端首个实锤；顺手可补一条机检——「N06 页顶部行内右端可点元素右缘不得越过 capsuleLeft − 间隙」（结构断言可先做，几何留真机）。
2. **dashboard / forum 右槽超宽复验与收敛**（中）：先取证（大概率超宽 20-40rpx），再按 S3 收敛图标/下沉动作。
3. **practice-do / mock-exam 计时文字复验**（中偏低）：合并单段或下沉。
4. **死件删除**（低，ADR-0035:69 已有决策待执行）：删 `components/common/` 两件（连带其自称「解决遮挡」的误导性注释消失）。
5. **可选题**：给 `useSafeArea` 的 `rect == null` 分支加显式降级日志（当前静默失去避让，排查成本高）。

**不建议开票**：N06 三页观感（低风险）、register/forgot-password（原生导航无冲突）、job-list（已特意设计避让）、页头件算法重写（无缺陷，且 D++ 机检锁住了坐标系修正成果）。
