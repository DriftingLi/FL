# 内容精选正文排版使用说明

> 面向内容编辑者（管理端「内容精选 → 新建/编辑」与讲师端「章节编辑」）。
> 判据来源见 `docs/adr/ADR-0046-内容渲染口径.md`；本文只讲**怎么用**、以及**各端看到什么**。

## 0. 一句话总览

正文有两种形态，二选一：

| 形态 | 什么时候用 | 读者端 |
| --- | --- | --- |
| **Markdown 正文**（默认） | 自己写、要反复改内容 | Web 学员端 + 门户 + 移动端（移动端降级） |
| **导入 Word 文档** | 已有排版好的 .docx，要原样呈现 | Web 学员端 + 门户（移动端提示去网页看） |

写 Markdown 时，工具栏多了十个按钮可以调**排版与表格结构**：四个表格按钮（增删行列）+ 六个排版按钮（居中 / 左对齐 / 图片居中 / 文字颜色 / 字号）。

| 按钮组 | 出现条件 | 说明 |
| --- | --- | --- |
| 四个表格按钮 | 只在 Markdown 编辑模式（IR） | 源码模式没有表格 DOM，命令无处落脚，故不挂 |
| 六个排版按钮 | 编辑器开了 `content-styles`（讲师端章节、管理端内容精选都是） | 写进正文的是内嵌 HTML，见下节 |

---

## 1. 排版按钮怎么用

六个按钮都在工具栏中段（`链接 / 表格 / 代码` 与四个表格按钮之后、`撤销` 之前）：

| 按钮 | 图标 | 怎么用 |
| --- | --- | --- |
| 文本居中 | 三条居中的横线 | 选中文字 → 点按钮 |
| 左对齐 | 三条左对齐的横线 | 选中文字 → 点按钮 |
| 图片居中 | 方框里一座山 | 选中整段图片语法 `![说明](地址)` → 点按钮 |
| 文字颜色 | 实心圆点（子菜单是「色点 + 颜色名」五档） | 选中文字 → 点按钮 → 选颜色 |
| 字号 | 大写 A 加升降号（子菜单是「图标 + 档位名」四档） | 选中文字 → 点按钮 → 选档位 |

**没选中文字就点**：文本居中 / 左对齐 / 颜色 / 字号会插入「在此输入文字」并自动选中，直接打字覆盖即可。**图片居中不会插占位文字**——它必须选中一张真的图片，否则只弹提示、正文一个字都不动。

**想改回来**：再点一次同一个按钮会去掉这层样式（只认「选区就是完整的一层外壳」这一种情况）。

**怎么知道哪个按钮是哪个**：鼠标停在按钮上会浮出名字与快捷键（例如「粗体 \<Ctrl+B\>」「文本居中」）。气泡显示在按钮**下方**——这是刻意的，上方会被编辑器上边界裁掉。

**几层样式能叠加**：先居中、再上色、再放大，三层嵌套都生效；再点居中会撤掉居中那一层、颜色和字号保留。

### 按钮做了什么（写进正文的到底是什么）

按下按钮后，正文里会出现一段内嵌 HTML，例如：

```html
<div align="center">这段文字居中</div>
<div align="center"><img src="地址" alt="说明"></div>
<span style="color:#DC2626">这段是红字</span>
<span style="font-size:var(--text-xl, 1.25rem);">这段是大号字</span>
```

- **对齐用块级 `div`**：编辑器（Vditor）只把**块级** HTML 渲染成预览，行内的 `span` 一律显示成灰色源码标签，作者点完看不出任何变化。用块级标签才有「所见即所得」。
- **图片居中会顺手把 `![说明](地址)` 转成 `<img>`**：块级容器内部**不再解析 Markdown**，不转的话读者看到的是字面量 `![说明](地址)`。代价是图片段里不能再夹加粗等行内语法（本来也不该有）。
- **颜色是写死的色值**：读者端（门户 / 移动端）没有本站的 CSS 变量，写 `var(--color-danger)` 在那边只会退成浏览器默认色。
- **字号带 `var(--text-*, 兜底)`**：本站自己渲染时跟着 UI 字号阶梯走，门户那边没有这些变量就落到 rem 兜底——两边都是设计想要的字号。

### 编辑态看到的和读者看到的不一样，正常

在编辑器里，这些样式**不一定当场生效**：

- 居中（文字 / 图片）：能看到居中效果（有渲染预览）。
- 颜色 / 字号：显示成灰色源码标签，不上色、不放大。

**想看真实效果，点「发布端预览」。** 那是读者实际会看到的排版。

## 2. Markdown 表格

直接用 GFM 语法，`链接` 按钮右边的表格按钮会插入骨架：

```markdown
| 故障码 | 含义 | 处理 |
| --- | :---: | ---: |
| E01 | 电池欠压 | 充电 |
```

**对齐写法**：`---` 左对齐（默认）、`:---:` 居中、`---:` 右对齐。

### 增删行列：四个表格按钮

表格光标停在**任何一个格子**里，工具栏「表格」按钮右边有四个按钮：

| 按钮 | 作用 |
| --- | --- |
| 下方插入一行 | 在当前行下方加一行空行（列数与当前行相同，对齐方式沿用） |
| 右侧插入一列 | 在当前列右侧加一列空格（表头那行补的是表头格） |
| 删除当前行 | 删掉光标所在的那一行 |
| 删除当前列 | 删掉光标所在的那一列 |

三件要知道的：

1. **光标必须先在格子里**。光标在表格外面点这四个按钮，只会弹一句「请先把光标放进表格的某个格子里」，不会改动正文。
2. **表头行不能删**。表头是表格的骨架，删了整张表就不是表格了。要减列请用「删除当前列」。
3. **最后一列不能删**（只剩一列的表没有意义）。真要整张表删掉，请选中整张表格按 Delete。

> 为什么不用快捷键：Vditor 自带的 `Ctrl+=` / `Ctrl+-` 那套在 Windows 上是浏览器缩放键，会先被浏览器吃掉。

**各端渲染**（2026-11 起）：

| 端 | 表格 |
| --- | --- |
| Web 学员端 | ✅ 真表格 |
| 门户（www） | ✅ 真表格 |
| 移动端 App | ⚠️ 降级为源码文本 |

移动端的降级是技术限制（uni-app x 手写解析器没有 DOM），编辑器会在正文里有越界语法时给出黄色提示，**提示不阻断保存**。

## 3. 导入 Word 文档

正文形态切到「导入 Word 文档」后：

1. 点「选择 .docx 文件」上传（**单文件 ≤ 50MB，仅支持 `.docx`**；老的 `.doc` 请先用 Word 另存为 `.docx`）。
2. 上传完成后显示文件名，可「移除」或「重新上传」。
3. **点「发布端预览」看一眼**：预览里就是读者看到的样子（Word 原样排版），不用先保存再去看。
4. 保存 / 发布。

### 要知道的三件事

1. **导入后正文不再是 Markdown**。文章以「原始文件 + 类型标记」存储，读者端按 Word 原样渲染。**要改内容只能改 Word 后重新上传**——这时编辑器里已经没有正文可编辑了。
2. **排版保真度约等于 Word 自己**：页眉页脚、多级列表、合并单元格、字体字号都会还原。但它不是 Word 的逐像素复刻，极复杂的图文混排（浮动文字框、艺术字）可能走样。
3. **移动端看不到 Word 正文**：App 没有浏览器内核，会显示「请在网页端查看完整排版」。**要求移动端读者也能读全的内容，请用 Markdown 正文。**

### 什么时候该选哪个

| 情况 | 建议 |
| --- | --- |
| 后续还要改错别字 / 补一段 | Markdown |
| 移动端读者必须能读全文 | Markdown |
| 已有排版精美的 Word（招标文件、正式通知） | 导入 Word |
| 内容一次成型，之后不动 | 导入 Word |

## 4. 发布前自检清单

- [ ] 点过「发布端预览」，排版与预期一致
- [ ] 正文里的图片能显示（图片走本站上传，外部链接的图读者端可能加载不出）
- [ ] 有公式时看过黄色提示（移动端不渲染公式）
- [ ] 导入了 Word 的话，确认读者主要用电脑访问
- [ ] 摘要、封面、分类都填了（这三个决定列表页卡片长什么样）

## 5. 常见问题

**Q：点了居中没有反应？**
A：先确认选中了文字（光标折叠在某个位置不算选中）。居中现在会当场显示效果——如果没变，多半是没选中。

**Q：图片居中点了以后，预览里图片还是靠左？**
A：要选中**整张图片**（点击图片让它被选中即可）。如果选区里没有图片，按钮只会弹一句提示、不动正文——那种情况请用「文本居中」。

**Q：图片居中会不会把图片弄丢？**
A：2026-11 有一版会（选中图片后点它，图片被占位文字覆盖）。现已修好：选区里没有图片时按钮直接拒绝执行，不会写任何东西。

**Q：能不能给一段文字同时设颜色和字号？**
A：可以，依次点即可，两层会叠加。要撤掉某一层就再点一次那个按钮。

**Q：Word 上传失败？**
A：检查三件：是不是 `.docx`（不是 `.doc`）；是不是超过 50MB；网络是否正常。

**Q：Word 文章想加一个段落怎么办？**
A：在 Word 里改完，回来「重新上传」覆盖。编辑器里没有 Word 正文的可编辑副本。

**Q：我在正文里手写了 `<div>`，为什么不生效？**
A：块级 HTML 会关掉内部的 Markdown 解析，且各端支持不一致。**排版请用工具栏按钮**，不要手写 HTML。

**Q：表格按钮点了没反应？**
A：先看光标在不在表格里——这是最常见的。其次看提示语具体说了什么：命中表头会说「表头行不能删除」，只剩一列会说「这是最后一列了」。这两种是按设计拒绝的，不是故障。

**Q：全屏编辑后点了退出按钮没反应？**
A：这是 2026-11 修掉的问题（全屏编辑器的层级低于顶部导航栏，退出按钮被盖住、点不到）。如果还遇到，请刷新页面重进——大概率是旧的页面缓存。
