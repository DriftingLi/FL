# 微信门②截图采集方案调研（2026-10-25）

先给结论：

- **现状一句话**：② 的截图采集 = `miniprogram-automator` 的 `miniProgram.screenshot({path})` 落盘 PNG，采完之后**机器只验「存在性」**（≥1 张、PNG 魔数、IHDR 宽高可读），**内容判定为零**（是不是目标页、渲染了业务内容没有、是不是白屏/401 Toast——全靠人看或一次性 spike 工具）。「人看的证据」与「机器判定的输入」混在同一份 PNG 上，但两者各自只吃到了对方能力的一小半。
- **怪点 top3**：① 前置链约 10 步、截图是末梢——链上任一环节（就绪/注入/冷启动）抖动都以「截图超时/缺失」结账（#1157、#1690 run5、#1817）；② 机器判定面与证据面脱节——`#1845` 实证路由判据可通过而截图实拍「登录已过期」Toast，PNG 内容无任何机检兜底；③ 元素断言被 ADR-0008 整体禁用（`element-api-unusable`，2026-09-18），但那条 verdict 测于「就绪闸门早跑窗口」被订正的同一周（#1157）、且现行 IDE 2.02.2608070 上**无复测记录**——最成熟的替代路线（官方 `page.$`/`text`/`waitFor` 断言）处于「被禁、未证伪到底」状态。
- **推荐一句话**：**主案 = 截图证据形态不动（人证 + 存在性机检），判定面做一次「元素断言复活裁决」：对真就绪会话 × IDE 2.02 重跑 `mp-weixin-element-probe.mjs`，可用则给探针加 2–3 个锚点元素断言（`page.waitFor` + `page.$().text()`）机检「页面真的渲染了」，不可用则退而只做 `page.waitFor` 替代定长 `settleMs` 的微调。** golden-image 像素 diff 不进 ②（0043 决策 5 已把像素比对留给发版冒烟；跨天阈值失准与模拟器分辨率漂移两坑仓内均已实测，见 §2.5/§2.4）。

### 1.2 截图采完拿来干什么（判定面）

机器判定只吃 PNG 的三样东西（`mp-weixin-probe.mjs:167-177` + `pngInfo :112-126`）：

1. **`isPng`**：头 8 字节魔数 `89504e470d0a1a0a`；
2. **IHDR 宽高**（只读前 24 字节，不验 IDAT 完整性——截断的 PNG 也能过这一关）;
3. **张数**：可验证子集要求「至少 1 张当前页截图」（`currentPageScreenshot`）；导航可用时另有 `screenshotsProduced`（每页一张）。该断言 false ⇒ failures ⇒ **exit 1 门未过**（`mp-weixin-check.ps1:176-178`）。

除此之外 PNG 内容**零机检**。其余断言（connected / pageStack 非空 / 入口页在栈 / console error=0 / exception=0）全部与像素无关。门报红路径：截图缺失/非法 ⇒ `exit 1`（门未过）；截不到图的会话层原因（连不上/空栈/就绪超时）⇒ `exit 2` env-blocked；两者在探针与门计划里有明确的 `connectError.kind` 与 exit2 归属表（`mp-weixin-probe.mjs:225-235`、`mp-weixin-check.ps1:604-610`）。

**两套截图体系澄清（本调研任务最容易混的点）**：仓库里与「截图判定」相关的机制分三处，归属完全不同——

| 体系 | 采集方式 | 判定 | 归属 |
| --- | --- | --- | --- |
| ② 微信门 | automator `mp.screenshot({path})` | 仅存在性（§1.2） | 本调研对象 |
| ①真机 `dev:finish` 步骤 6/7 | adb `exec-out screencap -p`（有界单次调用 #1560/#1562） | **像素 diff + 阈值**（`lib/png-diff.mjs:135` 默认 0.5%）+ 四态判定表（`lib/screenshot-gate.ps1:14-26`：首跑自动建基线 / 无变化绿 / 有变化红 / `-UpdateBaseline` 刷新） | ①真机侧，**不在 ②** |
| #1650/#1671 一次性取证 | automator 连拍 + `png-lum-profile.mjs` / `png-crop.mjs` | 亮度剖面启发式（§2.5） | throwaway spike，非门 |

### 1.3 依赖环境与硬编码/平台耦合面

- **无 headless，永远本机**：官方 CLI/automator 文档均无 headless 模式（§3.2）；托管 runner 两轮实验证伪（HBuilderX 回 `Please Login in!`、DevTools `islogin` 因 UserData 未初始化 ENOENT，`mobile-gates.yml:8-13`）。
- **登录态**：`cli.bat islogin` 前提，过期需人补扫码（`mp-weixin-check.ps1:165-167`）。
- **端口**：默认 9420（`:255`）；被占自动向后换（`Get-FreeAutoPort :833`，坑位 6a）；监听面绑通配地址、局域网可达，CLI 无参数可收窄（`:146-149` 照实记）。

- **storage 落盘确认读 IDE 私有目录**：flushConfirm 轮询 `WeappStorage/storage_*.json`，非默认安装面退 45s 盲等（`mp-weixin-auth.mjs:157-182`）——无官方承诺的观测面。

## 2. 「怪在哪」清单

**怪 1：前置链约 10 步，截图是末梢，一损俱损。**
截图调用只占单页 4s，但它站在 publish→close→open→auto→port→ready→auth-inject（含 45–90s 落盘确认）→换页冷启动之后；链上任何一环的时序病都以「截图超时/缺失」结账。血账链：#883（pageStack 空全误导弹错）→ #1157（就绪闸门早跑 17s ⇒ captureScreenshot 恒超时，门在健康机器上判不过）→ #1690 run5（冷启动后渲染服务未热 ⇒ screenshot 撞 15s 应答超时，为此加了 2 次重试）→ #1817（游客页被注 auth ⇒ 页面自跳 ⇒ 截图撞超时）。每一条的根因都不在截图本身，但每一条的**表象**都是截图失败。
证据：`mp-weixin-probe.mjs:302-304`（重试注释引 #1690 run5）、ADR-0008:26（#1157 订正全文）、`20261023-省略微信门调研.md` §7.1 Run2（login 截图炸 ⇒ 门 exit 1）。

**怪 2：机器判定面与证据面混同——「截到了」≠「截的是这个页」≠「页面渲染了业务内容」。**
现有断言只证第一层；第二层靠冷启动落地页判据（`pageStack[0] == 目标路由`）**间接**代理；第三层完全没有机检。#1845 实证了第三层缺口：storage 旧过期 token 复活、路由停在目标页 ⇒ 路由判据独自放行、截图实拍「登录已过期」Toast——处置是 #1863 的「auth 注入失败 ⇒ 该页 SKIP」条款，属于**用注入侧状态反推画面内容**，不是对画面本身的判定。`miss-` 前缀约定（`mp-weixin-probe.mjs:300`）也只是命名纪律，门脚本不校验「入库图文件名与达成页集合一致」。
证据：`mp-weixin-check.ps1:2077-2089`（#1863 条款注释）、#1845 / #1863 票面、ADR-0040:19（决策 3 自认「② 兜不住视觉回归」）。

**怪 3：像素启发式只活在 throwaway spike 里，救过真 bug 但没有沉淀。**
#1650/#1671 是本仓唯一一次对 ② 截图做像素级判定：`png-lum-profile.mjs`（自写零依赖 PNG 解码 + 逐行亮度剖面）的判据为——实心白面板行 = 行均值 >228 且标准差 <14（`png-lum-profile.mjs:79-83`）；遮罩分类 = darkFrac>0.6 ⇒ DARK / 非面板行中位亮度 <195 ⇒ SHALLOW / 否则 NONE（`:117`）；位置分类 = panelTop<25% 屏高 ⇒ TOP / >60% ⇒ BOTTOM（`:118`）；三态猜测 full/drawer/anchor 由两者组合（`:119`）；状态栏 0–14 行跳过。`png-crop.mjs` 按行区间裁片供人目检（`png-crop.mjs:1-5`）。这套启发式在 #1650 的 12 帧上判出 `12/12 mask=NONE、darkFrac≤0.03` ⇒ 坐实「fixed 全屏遮罩一帧不绘制」——**这正是元素断言结构性测不出的失效**（组件在元素树里、attached 已走、事件链全通，只是画布上没有）。#1671 据此 4 行修复并用同口径反转验证（面板 7–8% → 40% 屏高、顶部 40% 黑遮罩实证绘制）。
代价与局限：判据魔法数（228/14/0.6/195）均为该案手标、无守护测试、头注自 throwaway；亮度剖面认不出「那段是不是 tab bar」，还得靠裁片人眼定案（`png-crop.mjs:2-4` 自述）。两文件现仍在 `scripts/` 顶层，容易被误当常规工具复用。
证据：`png-lum-profile.mjs:1-7`、`:79-119`；#1650 / #1671 票面。

**怪 4：元素断言被整体禁用，但禁令的证据基础有两个缺口。**
2026-09-18 spike（PR #1136）用 `mp-weixin-element-probe.mjs` 裁决：`page.$('view')`（页面无关判据）8s 超时、不存在 class 同样超时、`page.data()` 超时 ⇒ `verdict=element-api-unusable`，守护 C3 随之禁探针用元素级 API（ADR-0008:24、`mp-weixin-check.ps1:27-28`、GATE_PLAN `:600`）。两个缺口：**(a)** 同周 #1157 订正证明当时「app 级通 / 页面级全挂」的分界线是就绪闸门早跑 ≈17s 的产物——元素探针虽以 pageStack 非空为前置，但「pageStack 应答」与「页面/元素树可服务」之间没有再验证过等价性；**(b)** 现行 IDE 已升 2.02.2608070（坑位 6b 处置），`element-api-unusable` 的测量全在 2.01.2510290 上，**仓内无任何 2.02 复测记录**（grep `element-api-unusable` 仅 ADR-0008:24 与 0020:101 两处转述）。也就是：这条禁令当下可能仍是 对的，但它是**一次未在当前环境复核的测量**在挡住一条官方主推路径。
证据：ADR-0008:21-28、PR #1136 正文实测表、`mp-weixin-element-probe.mjs:209-235`（判据预登记 + 已知必败对照项 design）。

**怪 5：像素 diff 的全套件仓内已有，但其两个前提在 ② 场景下都被实测打掉。**
`dev:finish` 步骤 7（①真机侧）已有成熟件：`png-diff.mjs` 逐像素比 + 默认 0.5% 阈值 + 容差/忽略行参数、`screenshot-gate.ps1` 四态判定、首跑自动建基线（ADR-0008:30-37，#1139/#1158 两轮修）。但移到 ② 的两个前提不成立：**(a) 阈值不可移植**——0.5% 是同帧标定（#1027），跨天基线把零改动树读出 0.919%（`dev-loop.md:352` 血账，0043 决策 5 明文「比对阈值不许直接移植」）；**(b) 分辨率自由度**——② 截图随模拟器窗口漂移（§1.3，461×997 vs 696×1507），基线要么钉死窗口尺寸/DPR（官方无 API），要么每轮重标定。而 0043 的口径已把像素比对定位在**发版冒烟的分级人看**里（决策 5），PR 粒度明确「视觉回归无人验」是接受的风险（`:33`）。
证据：`20261024-ADR0043落地差距与验收门修改清单.md` §1 条 10、ADR-0043:21/:33、`png-diff.mjs:185-190`（0.5% 理由注释）。

**怪 6：逐页截图依赖「改产物 app.json 冷启动」的重机制，是导航 API 恒败的代偿。**
`mp.reLaunch`/`mp.navigateTo` 在 automator 0.12.1 上两版 IDE 恒报 `Uncaught [object Object]`（已对完全就绪会话复测排除偶然，ADR-0008:293）⇒ 每页截图 = 换 dist `app.json` 首项 + 整段 close→open→auto→ready 重跑（§1.1 步 6）。这条链自带三类脆弱点且都有血账：入口漂移自愈（#1690 run14：上次强杀遗留换页 ⇒ 孤儿页被当入口静默取证）、`Get-Prop` 读 `[ordered]` 计划键静默返 null（guest 相判据恒空，#1817 复测才照出）、用毕还原依赖 finally（ADR-0038 决策 2）。uni-app x 官方文档确认的 automator 已知坑（跨组件选择、父子选择器、分包页 reLaunch 需 waitFor ≥7s，§3.4）本仓一条都躲不开，且实际比官方坑更深一层（连 reLaunch 都用不了）。
证据：`mp-weixin-check.ps1:1977-1999`（入口漂移自愈）、`20261023-省略微信门调研.md` §7.2 第三条缺陷。

**怪 7：截图入库链是「失败不阻断」的旁路，产物可靠性靠自觉。**
入库（§1.1 步 9）任何一步失败只 warning、不影响门结论（`mp-weixin-check.ps1:2323-2330`）——这是刻意设计（不让入库拖死门），代价是「门绿 + 证据图没了」可静默发生；历史上它已断过两次：#1209（StrictMode 下空 shots 取 `.Sum` 抛异常，把 sha 绑定评论整步打断）、#1695（入库提交只 commit 不 push，评论里 `- commit:` sha 在 GitHub 404）。② 的 sha 绑定评论校验的是结构不是真伪（ADR-0008:148-163「只校结构、不校真伪」），CI 侧管家也不执行真门（`mobile-gates.yml:8-13`）⇒ 截图从产生到被人看到之间没有一条强制通路。
证据：`mp-weixin-check.ps1:1508-1516`（#1209 注释）、`:1602-1613`（#1695 push 纪律）、ADR-0008:184。

**怪 8：等待策略是定长 sleep，不是条件等待。**
探针在导航后按 `settleMs / routes.length` 定长等待（`mp-weixin-probe.mjs:392`）、直达模式收尾 settle 2s（`:333`）、截图重试间隔 3s（`:320`）——全部是拍脑袋常数，不是「等页面稳定」的判据。官方 `page.waitFor`（选择器/时长/断言函数三态，§3.1）就是为这个准备的，仓内只用了它的时长形态都不用（直接 sleep）。mp-web-polyfill 同类案例更粗糙（固定睡 4s/1.5s，`20261024-验收门成本fix调研.md` §1.1 明言「本仓勿学」的是它，但本仓自己的等待也同族）。
证据：`mp-weixin-probe.mjs:51`（settleMs 默认 2000）、`:320`/:333/:392。

**怪 9：PNG 完整性只验 24 字节。**
`pngInfo` 读前 24 字节验魔数 + IHDR 宽高（`mp-weixin-probe.mjs:112-126`），IDAT 截断/损坏不验。低危（落盘由 automator 完成、截断概率低），但「机器判定的输入」这一层确实只到此为止。

## 3. 官方能力核验（一手出处，逐条复核）

### 3.1 `miniProgram.screenshot` 全貌

- 签名 `miniProgram.screenshot(options?: Object): Promise<string | void>`；原文：**「对当前页面截图，目前只有开发者工具模拟器支持，客户端无法使用」**；**「如果不传 options，该方法返回图片数据的 base64 编码」**，传 `path` 则落盘不返回内容（https://developers.weixin.qq.com/miniprogram/dev/devtools/auto/miniprogram.html ）。仓内注释「不返回内容 ⇒ 只能看文件」（`mp-weixin-probe.mjs:8`）与官方一致——**base64 形态官方是支持的**，本仓没走它是为了直接落盘 + IHDR 自证。
- **没有 page 级 / element 级截图**：Page API（page.$/$$/waitFor/data/setData/size/scrollTop/callMethod）与 Element API（$/text/attribute/property/wxml/tap/size/offset/…）方法全集里均无 screenshot（https://developers.weixin.qq.com/miniprogram/dev/devtools/auto/page.html 、…/auto/element.html ）。
- **格式只有 PNG**：文档无其他格式参数（未找到即如实记）。
- Element 级几何信息可用 `element.size()` / `element.offset()`（Element API 文档），可作「元素可见/在视口内」的代偿判定。

### 3.2 CLI 能力边界

- **没有 `cli screenshot` 命令**（命令索引全集中不存在）；截图能力只在 automator API（https://developers.weixin.qq.com/miniprogram/dev/devtools/cli.html ）。
- `cli auto --project <root> --auto-port 9420` 官方在列（示例端口即 9420）；`--trust-project` 不在文档参数表中（仓内实际在用，`cli auto -h` 亦未列 `--auto-port`——ADR-0008:27 已照实记「传与不传差异未单独隔离」）。
- `cli islogin` 官方在列（「是否登录工具」）；`cli open --pure-simulator`（「纯模拟器模式」）在列——20261024 调研 §5 已把它列为「对 ② 会话面的适用性未实测」候选，本调研维持该结论。
- **无 headless**：automator 文档 launch 需启动 GUI 工具（cliPath 默认仅 Mac/Win 两处、无 Linux）；文档无任何 headless 字样（https://developers.weixin.qq.com/miniprogram/dev/devtools/auto/automator.html ）。

### 3.3 已知限制与时机

- **真机不可 screenshot**：官方明文 screenshot 仅模拟器；真机自动化通道（`miniProgram.remote()`）**需人扫码**、文档未列 screenshot 在真机的可用性（https://developers.weixin.qq.com/miniprogram/dev/devtools/auto/remote.html ）⇒ 「② 截图」与「真机画面」结构性不等价（与 0008 非等价声明同向）。
- **Skyline 渲染引擎**：skyline 下截图走 `<snapshot>` 组件 + `takeSnapshot` 接口，是**页面内代码方案**而非 automator 通道（https://developers.weixin.qq.com/miniprogram/dev/component/snapshot.html ）；automator `screenshot` 对 skyline 页面的行为官方 automator 文档未提（弱证据：官方未承诺兼容）。本仓 uni-app x 编译产物当前走 webview 渲染，skyline 未启用（仓内 `manifest.json` 无 skyline 配置——未逐字核验，推断）。
- **时机/竞态**：官方推荐的等待手段是 `page.waitFor`（选择器/时长/函数三态）与 `miniProgram.pageScrollTo` 等 page 级 API；FAQ 页只有 4 条（系统组件不可操作 / 脚本不退出 / 多账号 / getTicket），**没有** screenshot 时机、连接超时、pageStack 的条目（https://developers.weixin.qq.com/miniprogram/dev/devtools/auto/faq.html ）。就绪时序（SDKVersion 与 pageStack 里程碑相隔 20–30s）官方无任何记载——那是本仓 #1157 用裸 ws 帧实测出来的私有知识。
- **窗口尺寸/DPR 对截图分辨率的影响**：官方文档无此参数、无说明。仓内两次实测尺寸不同（461×997 / 696×1507）支持「随模拟器窗口走」的推断——**弱证据/推断**，无官方出处。

### 3.4 uni-app x（uvue → mp-weixin）在 automator 里的选择器形态

- DCloud 官方（uni-app x 自动化测试，mp-weixin 节点）：**「微信小程序 element 不能跨组件选择元素，首先要先获取当前组件，再继续查找」**（`page.$('.test')` 取不到组件内元素，须先 `page.$('uni-tag')` 再链式 `$()`）；**「微信小程序暂不支持父子选择器」**；分包页 reLaunch 后需 `page.waitFor(7000)` 才能正确取 page 对象（https://doc.dcloud.net.cn/uni-app-x/worktile/auto/quick-start.html ）。`element.text()` 返回字符串、`attribute` 恒字符串（含 class/id）、`property` 读组件属性（微信 automator Element API 同源）。
- 官方没有「uvue 自定义组件编译到 mp-weixin 后选择器形态」的专门说明——上述限制即官方口径的全部；本仓 element 探针的靶点用的就是类选择器 `.app-title`（`mp-weixin-element-probe.mjs:62-64`），与官方「类选择器可用但须先取到所在组件」的口径相容（弱证据：本仓 login 页锚点是否在自定义组件内未核验）。

### 3.5 业界同类实践（面向「验收门自动判定」）

- **元素断言替代像素判定是主流**：微信官方自动化快速开始与 uni-automator 的示例判定形态就是「导航 + `page.$` + `text`/`attribute` 断言」（§3.1/§3.4 引文）；全 GitHub `miniprogram-automator path:.github/workflows` 仅 2 命中、uni-automator 0 命中，主流 uni-app 组件库 CI 无一跑开发者工具 e2e（`20261023-省略微信门调研.md` §4.6 一手清点）——**「截图作人证、判定走元素/协议」是惯例，像素 diff 在小程序自动化里无一手案例**（检索未找到，证据等级弱）。
- **golden-image 工具本身成熟**：jest-image-snapshot（pixelmatch 内核，https://github.com/americanexpress/jest-image-snapshot ）是 web 生态标准件，接 buffer 即用；但其稳定性配方（mock 时间/数据、定视口）恰好对应本仓 ② 缺的自由度（时钟、模拟器窗口）。仓内 `png-diff.mjs` 是等价的零依赖自研件（①侧在用）。**「pixel diff 用在每 PR 门」在小程序场景无公开先例**；仓内跨天阈值失准实测（§2.5）是比任何外部案例更硬的反证。
- 官方运行时验证通道是云测 Minium（Python，每周免费 150 分钟）——姊妹篇已定位为「发版前选项」而非每 PR 门（`20261023-省略微信门调研.md` §4.3/§6.4），本调研不重复。

## 5. 最终推荐

**主案：维持 A 的证据形态（截图=人证+存在性机检，不引入像素 diff），把判定面升级的事交给一次低成本裁决——对「真就绪会话 × IDE 2.02.2608070」重跑 `scripts/mp-weixin-element-probe.mjs`，按结果二选一：**

- **B 路线（裁决可用）**：给直达探针加**可选**的锚点元素断言（每页 1–2 个稳定锚点，如 login 页 `.app-title` 文本比对），断言带 8s 步超时（沿用 element-probe 的「挂起与报错分得开」设计），失败进 failures ⇒ 门红。截图保持现职责（人证 + 存在性），**不**承担判定。这一步直接补掉 #1845 型「路由过而画面错」的机检空档，且把 ② 从「console 无报错门」升格为「渲染内容门」——0043 决策 3 说 ② 是「唯一运行时反馈通道」，这条升级让该定位更名副其实。
- **A+ 路线（裁决不可用，即复现 element-api-unusable）**：如实把复测记录写回 ADR-0008（含 2.02 版本号与原始错误串），禁令转为「双版本实测钉死」；微调包只做 E 的低风险项——把探针里三处定长 sleep 换成 `page.waitFor`（时长形态也先实测可用性，不可用则维持现状并在 ADR 记「waitFor 亦不可用」），其余不动。

**为什么这个性价比最高**：

1. **成本锚定在一次会话级实验**：element-probe 是现成工具（含已知必败对照项、判据预登记、版本记录字段，`mp-weixin-element-probe.mjs:209-235`），就绪闸门 `--require-stack` 已把 #1157 那个「早跑窗口」实验条件修掉——今天重跑的实验质量比 2026-09-18 那次更高，而它直接决定要不要改造探针，避免在「禁令可能基于失真测量」的状态下持续放弃官方主推路径。
2. **绕开了像素路线的全部实测大坑**：分辨率漂移无官方参数可钉（§2.4）、阈值跨天失准仓内自证（§2.5）、0043 已把像素判定划给发版冒烟——golden-image 在 ② 的性价比是四个方案里最差的，且 #1671 案例恰好说明像素启发式的正确用法是「人已怀疑渲染坏了」的定向取证，不是每 PR 全页跑。
3. **渐进路径与守护体系兼容**：C3 守护（探针不得用元素级 API）与 E 系守护是文本/行为锁，裁决可用后改判据是**有据可依的改锁**（ADR-0008 先例：2026-09-18 修订就是同一条禁令的立锁过程）；裁决不可用则锁照旧，零改动面。
4. **失败模式可控**：锚点断言挂起只会让该页记失败（带步超时），不会复现 #883 那类「静默挂 15s 拖死整门」——探针现架构里 failures/env/assertions 三分与诚实降级条款（#1863）都在位。

**执行序（供排期，本调研不动码）**：① 裁决实验（一次跑，读数回写 ADR-0008）；② 若可用：探针 `--assert-selector/--assert-text` 参数 + GATE_PLAN `directPages` 增锚点声明 + C3/E 系守护连动 + 单独 PR（工具链改动按 DoD 单独验证）；③ 若不可用：仅 ADR 记录 + （可选）waitFor 微调实验。两条路都不触碰 0043 决策 3 的口径。

## 6. 未集成的缺口 / 待实测（别当已证）

- ~~**element API 在 IDE 2.02.2608070 上的可用性：无实测记录**~~ **已于同日 spike 裁决（票 #1917）：页面级元素断言可用**——`page.$('.app-title')` 8ms 解析、`element.text()` 精确匹配期望文本，对照项可信 ⇒ 2026-09-18 的 `element-api-unusable` 系就绪闸门早跑窗口的产物；verdict = `class-selector-usable-tap-flow-unproven`（点击流未证实系靶点 v-if 未渲染，非 API 失败）。读数已写回 ADR-0008（2026-10-25 修订条）。B 路线解锁：探针锚点断言走 `page.$` + `element.text()`。
- ~~**`page.waitFor` 在本仓直达模式（connect + currentPage 路径）下的可用性**~~ **同日实测：两形态分家**——时长形态可用（3000ms → 3013ms 返回）；**选择器形态挂起**（`.app-title` 8s 超时，#883 同族）。条件等待不能依赖 `waitFor(选择器)`；怪 8 的「定长 sleep 换条件等待」在 ② 的可行形态是**轮询 `page.$`**（可用原语），不是 `waitFor(选择器)`。
- **screenshot 分辨率与模拟器窗口的因果**：两例尺寸不同的观测支持推断，未做控制变量实验；若未来做像素基线，先补这个实验。
- **`--pure-simulator` 对 ② 会话面的适用性**：20261024 调研 §5 已列，本轮未新增证据。
- **skyline 下 automator screenshot 行为**：官方未提；本仓未启用 skyline，暂无暴露面（推断）。
- **锚点元素的跨组件可达性**：uni-app x 官方「不能跨组件选择」的限制意味着锚点必须选在页面级或按「先取组件再链式查」写——每个锚点落地前要单验（#1650 的探针证明该页事件链可达，元素查询是另一条通道，未等价验证）。
