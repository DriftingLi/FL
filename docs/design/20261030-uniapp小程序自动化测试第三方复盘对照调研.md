## 2. 特别核查：这条路到不到得了 uni-app x（一手原话）

- `…/worktile/auto/quick-start.html`：「**插件支持在HBuilderX内对 uni-app(x)普通项目 、 CLI项目 进行自动化测试。**」「如下所示，是一个**标准的uni-app x项目**测试工程目录介绍。」（示例树是 `App.uvue` / `main.uts` / `index.test.js`）
- `…/auto/hbuilderx-cli-uniapp-test.html`：「插件市场 HBuilderX uni-app自动化测试 插件 4.1.0版本起，支持被HBuilderX CLI调用了。支持在命令行运行 **uni-app (x)** 自动化测试到 Web、微信小程序、Android、iOS 和 Harmony。」「特别注意事项：运行HBuilderX cli uniapp.test 前，请先确保…插件可以在HBuilderX内正常使用。」
- `…/worktile/`（工程化总览，上次更新 2026/1/8）：「**uni-app x不支持cli创建项目，但HBuilderX创建的项目，可以调用HBuilderX的cli来通过命令行打包。**」
- **复核结论**：`docs/design/20261023-省略微信门验证影响与同类实践调研.md`:117 那句「CLI 工程自动化教程仅适用 uni-app vue-cli 工程——**uni-app x 项目用不了纯 CLI 路**」**只对「CLI 工程（vue-cli 创建项目）」这一路成立**；HBuilderX cli + 插件那一路官方明写覆盖 uni-app(x)。**措辞需收窄，结论不变**——本仓不引入的理由从来不是「不支持」，而是能力空洞（`20261026` 结论 3：api.md 里 uni-app x 列一排 `x`）、版本握手、单实例排队、以及 2026-09-19 已实测清退。

## 3. 本仓真正缺的那一格（只有一格，且是可选微改）

`-Doctor` 的**静态半区（L1–L4）无法单独跑**：想拿到「配置＋路径＋产物」的结论，必须一并付 L5–L7（`close→open→auto→就绪闸门`，实测约 77 秒）且 L2 已在动 `cli.bat islogin`。文章的 C7 价值**只在成本分层**这一点上，本仓覆盖面比它宽（7 层 vs 8 项静态）、判据比它硬（实测列出套件 vs 文件存在）。
- **落点**：`scripts/mp-weixin-check.ps1` 参数区（:331 同族开关）加 `-StaticOnly`，切点在 :1196 的 `if ($Doctor)` 静态块与 `Start-GateStage -Name 'automation'` 之间；入口 `npm run build:mp-weixin-precheck`；配一条接线守护（与 `utils/mpWeixinGate*` 同族）。
- **成本**：30–60 分钟（含守护与 ADR-0008 一行登记）。**收益低**：② 已有指纹短路（:1171-1172）与 ADR-0047 取锁前无变更预检，本改只省「诊断环境」那一次的机时，不改门语义。
- 文章的「`env.js` 字段完整性静态检查」这一档本仓**没有也不需要**——本仓不装 `env.js`（ADR-0020 已清退），它是「已裁决不做」路线的伴生需求。

## 4. 一手核实产出的三条修正（值得动手，但都不动门）

1. **`deprecated` 的归属：既有裁决**不用改**，但多了一条前瞻事实**（本条由主控复核后订正，原稿指错了目标行）。npm 实况＝`@dcloudio/uni-automator` 1529 个版本、latest `2.0.2-5030320261023001`、`modified` 2026-10-29（**仍在活跃发版**），`deprecated` 只命中**单个版本 `2.0.0 => "error version"`**。复核仓内三处措辞：ADR-0020:27 与 ADR-0008:31 **都已写成 `@dcloudio/uni-automator@2.0.0`**（版本限定，与 npm 实况一致 ⇒ 本次一手核实是**印证**它们，不是纠正）；唯一措辞含糊的是 `docs/design/20261026-…:119` 的「npm 上**该包**已带 deprecated」（上文有 `@2.0.0` 兜着，读法可两解）。**真正新增的是反面事实**：包本体 2026-10-29 还在发版 ⇒ 「官方已弃坑 uni-automator」这个读法**不成立**，ADR-0044 附录 A 第 2 项（版本握手能否解开）将来重估时，对面是一个仍在维护的包、且存在与 HBuilderX 树内 `3.0.0-*` 配对的 `2.0.2-*` 版本线，不是一条死路。成本：给 20261026:119 补一个版本限定（半行），**不重开裁决**（清退的另两条理由＝配置承诺不存在能力、半死配置必然失败，都不依赖 deprecated）。
2. **官方 `uni-test` 包装层 fail-open**（`bin/uni-test.js:82` 命中插件缺失后 `process.exit(0)`）＝本仓「退出码恒 0、判成败只解析 stdout」血账（`hx-run.ps1`:41 / ADR-0020:100）的**新增实例**。价值：将来任何重启评估必须把它列进判据（现成 ADR-0020 附 C 第 4 条已覆盖该语义，**无需新增机制**，建议登记一条出处）。
3. **版本握手纸面可能绕开（待实测）**：走插件路时运行时由插件自带（`20261029` 取证：`hbuilderx-for-uniapp-test/src/environment/package.json` 内含 jest-image-snapshot 6.1.0），不解析项目本地那份 ⇒ ADR-0020 附 B 的「精确相等」失败点**可能**不适用。这正是 ADR-0044 附录 A 第 2 项，**仍挂起、未实测**，不得据本条改任何门行为。

## 6. Q1-Q7 结论与证据等级

- **Q1** `hbuilderx-cli` 现状：latest **1.2.0**（2025-12-29），4 个版本、`modified` 2026-09-18、**0 个 deprecated、dependencies 为空**；bin 四个（`uni-test`/`hbuilderx`/`uni-launch`/`uni-logcat`）；`uni-test` 就是 spawn `cli.exe uniapp.test` 的薄包装 ⇒ **两套入口一套实现**，与 `20261029`:114 本机取证互相印证。README 门槛：`uni-test` 需 HX 4.87+。**一手**。
- **Q2 支持 uni-app x**：**是**（§2 三处原话，一手）；本仓 20261023:117 措辞待收窄。
- **Q3 版本握手**：npm 实况一手（§4 第 1 条）；「插件路绕开握手」**推断，待实测**（ADR-0044 附录 A 第 2 项挂起中）。
- **Q4 EINVAL 归属**：Node 当前 API 文档**不含 EINVAL 字样**（一手，反证），真源＝CVE-2024-27980 加固 ⇒ 本仓 ADR-0008:31 已实测并纠正归因。文章的「Node 对 .cmd/.bat 敏感」属**二手转述**。
- **Q5 中文路径**：**一手来源未取得**；本仓解法（`-LiteralPath` + 候选数组 + 双名匹配 + profile 枚举）判为更强，作者的 Unicode 转义不需要采纳。
- **Q6 预检差哪一格**：差 §3 那一格（成本分层），**覆盖与判据都不差**。
- **Q7 是否等于重开 0020**：**是**（一手：ADR-0020:36 逐字点名 `cli.exe uniapp.test`）。前置条件＝另立 ADR supersede 0020 + 附 C 三条现测 + 判成败只解析 stdout。
