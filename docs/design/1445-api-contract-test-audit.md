## 4. 与 ADR-0070 决策 8 的关系（关键一条）

决策 8 的原话是「契约测试留在装配根（`internal/api`）」，理由是 `router_test_helper_test.go:47-52` 明文反对**另起测试装配链** —— 「装配链分叉 = 测试装配与生产装配各测各的」。

但 B 桶这 31 个用例**今天就已经在分叉**：它们自己 `gin.New()`（或自建 group）、自己 `forum.RegisterRoutes(...)`，只挂被测域那几条路由，本来就不在测生产装配链。⇒

1. 它们**不是**决策 8 要保护的装配面证据（那 58 个 A 桶才是），所以下沉不破坏决策 8 的初衷；
2. 下沉后「域级行为证据」与实现同目录，正是 ADR-0070 决策 1/3「测试与测试对象同居」的取向；
3. 真正要守的只剩一句：**下沉后仍必须走 HTTP**（`httptest` + `ServeHTTP` 或等效的域路由装配），不许改成直调 service —— 否则契约价值就丢了。

## 7. 局限

1. 分桶是**机械判据**（见 §1），它回答「能不能不靠 `NewRouter`」，**不回答**「该沉到哪个包最合理」—— `job_card_contract_test.go`（域=resume 却校验职位卡片）这类跨域味道重的用例需要人读一遍再定目标包。
2. `*_face_ledger_test.go`（3 个）与 `*_lock_test.go`（6 个）按规则一律留；个别账本理论上有「域内那一半」，但拆账本会引入「一条事实两个举证地」，与 nullability 锁的「一条事实一个证据」相冲，故不建议拆。
3. 行数是文件总行数（含 fixture 与注释），不等于搬迁成本；B2 的真实成本主要在 §5 第 1 条那份域内夹具。
4. 「自建引擎 = 否」的 B1/B2 用例仍会挂域路由（只是引擎来自 `httptest.NewServer` 之类的宿主），故「是否自建引擎」只作参考，不作判据。
