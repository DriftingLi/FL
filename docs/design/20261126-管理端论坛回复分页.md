# 管理端论坛删除回复后的分页恢复

2026-11-26 已确认并实施。范围为 Web 管理端论坛详情抽屉。

后端按回复子树执行级联删除并更新总数。改动前，管理页只从缓存移除选中的回复并将总数减一。删除也会改变后续页的偏移量。例如管理员已经加载三页，在第二页删除一条带子回复的回复，部分后续回复会前移。继续使用旧页码续读可能漏项。

## 已确认行为

- 删除成功后，使受影响帖子的已加载分页和在途响应失效，并重新请求该帖首页。抽屉继续展示该帖，回复列表从首页恢复。其他帖的缓存继续有效。
- 首页恢复失败时，抽屉展示该帖的加载错误。重试从首页发起，成功后从新首页继续续页。
- 回复、总数和页数采用服务端返回值。沿用 [ADR-0042](../adr/ADR-0042-回复列表分页与置顶后端化.md) 的后端分页和采纳回复置顶规则。

重取首页只需一次请求，代价是管理员需要重新加载后续页，才能回到原来的审核位置。按帖加载、续页、重试和失效归入同一个回复分页模块，让抽屉和删除动作共享该帖的加载状态。

## 验收场景

| 场景 | 可观察结果 |
| --- | --- |
| 已加载三页，在第二页删除带子回复的回复 | 重取该帖首页。被删除的回复及子回复消失，总数与服务端一致。 |
| 删除前发出的续页响应晚于删除成功返回 | 旧响应无法回填已失效的分页。 |
| 删除成功后首页请求失败 | 该帖显示错误。重试请求首页，成功后可以正常续页。 |
| 重新加载至删除位置附近 | 分页以服务端的新顺序为准，无漏项。 |
| 在帖子甲删除回复后打开已缓存的帖子乙 | 帖子乙仍使用自己的分页状态。 |

分页状态集中在 [回复分页模块](../../frontend/src/pages/admin/useForumReplyPages.ts)，由 [Web 管理端论坛页](../../frontend/src/pages/admin/ForumManage.vue) 使用。验证从抽屉的实际操作入口断言列表、总数和重试行为。[管理端论坛测试](../../frontend/src/pages/admin/__tests__/ForumManageContent.spec.ts)
