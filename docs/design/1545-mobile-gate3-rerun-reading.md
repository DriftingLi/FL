## 1. 四个源各自的判据，以及它们各自漏什么

### 1.1 S1 会话转录

判据是**结果文本**而不是命令形态：一次 `Bash` 调用的 `tool_result` 里能解析出 `Test Suites: …` 与 `Time: …`。窗内 jest 相关调用共 **700 条**（v4 台账：单套件③ 298 · 无汇总行 287 · 全量③ 111 · 收窄③ 4），全量档 111 次。

两类数字不能混：

- **111 次内部**有两种「绕路进上下文」：5 次命令带落盘重定向（`… 2>&1 | Out-File "$log"`），9 次由宿主后台的 `.output` 文件解析出汇总（`src=bg:*`）。它们的汇总行**最终仍进了上下文**，只是路径不同。后台那一类有个口径细节必须写下来：`resultChars` 记的是 jest 输出部分，**不含宿主包装那一行**（票 1532 实测块长 1227，首行 `1113 C:\Users\ZHENG\AppData\Local\Temp\qoder-cli\D--FL\98e35be1-…\tasks\b2j5dnsu9.output` 占 114 字符，1227 − 114 = 1113 与台账逐位相符）。

## 10. 不可约的局限（写在读数旁边，不写在脚注）

1. **mtime 间隔 ≠ 纯机器时间**（AC④ 点名要声明的这条）。S2 的时间面是文件 mtime：它是「命令下发 + 门跑完 + 落盘」之后的一个点，不含 `npm ci`，且**同一文件被覆写时只留最后一次**。§4 的「相邻全量 mtime 间隔」因此**不能**读成「两次门之间跑了多久」。
2. **jest `Time:` ≠ 端到端墙钟**。它是套件计时之和；`npm run test:unit` 的启动、模块装载、`-i` 排队不在其中。窗内 CI 侧的对照给出了这个差有多大：S4 真跑 229 次里，job 墙钟 31,703.0 s 而「单元测试」这一步净 27,049.0 s ⇒ 差 4,654 s 全在 checkout/setup-node/npm ci/收尾。**本件的 8.77 h 是 `Time:` 口径**，不是「门占了几小时」。
3. **JSONL 的 `ts` 对落盘跑是命令下发时刻**（§2 的票 1472 例已核）。所以 P2 的时间窗取 `+30 s .. +1800 s` 而非对称窗——这个上下界是拍出来的，改它就可能改变 P1/P2 的分配（但改不动并集下界，因为并集按文件计数）。
4. **归因只覆盖 111/147**。仅落盘的 36 次（9,277.1 s）没有「为什么」。
5. **`eCode/eDoc/eOther/gOps` 只在同一 JSONL 文件内计数**。跨会话（A 会话改码、B 会话跑门）会漏 ⇒ C4 的 75 是下界、C2 的 26 是**上界偏乐观**。`gOps` 更弱：它把只读 `git status/log` 也算成动作，窗内 111 次里 68 次 `gOps > 0`，所以 C2b 那一档**不承重**，本件不用它单独论证任何结论。
6. **本件未做「#1526 合并前/后」的时间切分**（§7 留的口子）。`4e9098ae` 在窗内，若要判 C1 是否已被它压住，得把 9 次 C1 按 ts 与 `4e9098ae` 的合并时刻切两栏——本件没做，标为**未验**。
7. **复算脚本在 gitignored 的 `.scratch/research/1545-*.mjs`**（`.gitignore:81`）。树没了就没了。所以 §11 把判据写到**可重写**的程度，而不只是指路；#1546 若要「落地后再测一次并与本件对照」，要么照 §11 重写，要么另票把这批脚本入库。
