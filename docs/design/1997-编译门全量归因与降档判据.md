## 一、结论

945 s 里 **71.9% 是「59 页 android class 编译」**，其中真正的杠杆是**整模块 kotlinc（445.9 s）** 与 **dex 化（229.0 s）**——
两者都是**全模块**活动，与「你改了哪一页」无关。所以省时的正确做法不是把准备段做快，而是**决定要不要 clean**。

## 五、这次归因推翻了什么

- **不是 HBuilderX 冷启贵**：0.5%（主程序当时已在跑，`HX_BUSY wait=0 result=free`）。
- **不是打包贵**：④a 根本不打包。
- **不是「改哪页影响编译时间」**：贵的是全模块 kotlinc + dex 化。
- **开关是 `--cleanCache true`**：丢掉 `class/` ⇒ 1515 个 class 必须整编；热缓存实测 257 s ⇒ 全量贵 ≈3.7 倍。
