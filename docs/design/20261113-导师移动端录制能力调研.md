# 导师移动端录制能力调研（一手资料）

> 只查事实，不给决策结论。凡未标注来源的都是算术推导，已写清假设；查不到官方口径的写「未找到官方口径」。
> 面向的工程：`training-app/叉车维修培训学员端跨端应用/`（uni-app x，发布面 App-Android / App-iOS / 微信小程序）。
> 参照的既有约束：单文件上限 2GB、分片 5–8 MiB、服务端 Go 60s 读超时。

## ③ uni-app x 录制 API 面（官方原文）

**`uni.chooseVideo`** [4]：兼容 Web 4.0 / 微信小程序 4.41 / 支付宝 5.31 / Android 4.18 / iOS 4.18 / HarmonyOS 4.61（数字为 HBuilderX 版本）。

- `maxDuration`：原文「拍摄视频最长拍摄时间，单位秒。**最长支持 60 秒**」。
- `sourceType` 默认 `['album','camera']`；`camera` 合法值 `front`/`back`。
- `compressed`：默认 `true`，「是否压缩所选的视频源文件」，并标注 **已废弃，仅为了向下兼容保留**；`albumMode` 同样已废弃。
- 返回 `tempFilePath / duration / size / height / width`。

**`uni.chooseMedia`** [5]：兼容 **Web = `x`（不支持）** / 微信 4.41 / 支付宝 5.31 / Android 4.51 / iOS 4.51 / HarmonyOS 4.61。

- `maxDuration` 默认 `10`，原文「时间范围为 **3s 至 30s** 之间」。
- `mediaType` 默认 `['image','video']`；`count` 默认 9。
- Tips：Android 端「拍照的 maxDuration 和 camera 属性在部分手机上不生效」；App 端选完媒体「**默认没有压缩**」，需自行 `uni.compressVideo`。

**`uni.getRecorderManager`** [12]：**只做音频**。`start.duration` 默认 60000ms，「微信小程序最大值 600000（10 分钟)，App 平台没有最大值限制」；format 合法值 aac/mp3/pcm/wav/m4a。→ 不能用来录像。

**`uni.createCameraContext` + `camera` 组件** [2][3]：App 端唯一可指定录制时长的官方录像路径。

- 兼容 Android 4.61 / iOS 4.61（HarmonyOS x；Web 与小程序未列）。
- `startRecord(options)`：`timeout` 默认 **30**，「录制时长上限，单位为秒」；`selfieMirror` 默认 true；`timeoutCallback`「超过录制时长上限时会结束录像并触发此回调，录像异常退出时也会触发此回调」。
- `stopRecord(options)`：`compressed` 默认 false，「压缩效果同 chooseVideo」；返回 `tempVideoPath`（原文「视频将以 **mp4** 格式存放到 uni-media 目录下文件系统」）与 `tempThumbPath`（jpg）。
- 错误码 `2003009`「app进入后台，摄像头终止」、`2003101` 视频压缩失败。
- `camera` 组件属性只有 `resolution: low/medium/high`、`flash`、`device-position`、`mode: normal/scanCode` 等；事件 `@stop`「摄像头在非正常终止时触发，如退出后台等情况」。

**上传与文件**：

- `uni.uploadFile` [13]：参数仅 `filePath/files/name/formData/header/timeout`，`timeout` 默认 **120000 ms**；返回 `UploadTask`（`abort`、`onProgressUpdate`）。**全文无「后台/锁屏」字样**；无 chunk/range 参数。
- `uni.request` [11]：`timeout` 默认 **60000 ms**；`data` 在 app-android 4.51+ / app-ios 4.61+ 支持 `ArrayBuffer`。
- `getFileSystemManager` [10]：原文「读取文件 API 受具体设备内存大小限制……请避免一次性读取大文件的情况(**建议文件大小不要超过 16M**)」；`read(option)` 支持 `fd` + `offset` + `length` + `position`，即**按位置分片读**（Android 4.31 / iOS 4.61）。
- `plus.*` / `weex.*` [9]：原文「**uni-app x 中不再支持 plus 和 weex 的 API。**」→ 旧 uni-app 的后台/原生能力在 uni-app x 里没有等价物。
- `getBackgroundTaskManager`：`/uni-app-x/api/get-background-task-manager.html` 返回 404，**未找到官方口径**。

## ④ 编码与格式可控性

- 官方 API 层面**没有任何编码器参数**：可选控制量只有 `resolution(low/medium/high)`、`compressed(bool)`、`timeout`，「压缩效果同 chooseVideo」但**未写压缩后的编码/分辨率/码率** [2][3][4]。
- 手机系统相机侧的默认值由 OS/厂商决定，调用方拿到的只是 `tempFilePath` [4]。
- iOS 默认录 **HEVC**：Apple 原文「iOS 11 和 macOS High Sierra 引入了 HEIF/HEVC」「HEVC 提供比 H.264 更好的压缩」；可在「设置 > 相机 > 格式 > 兼容性最佳」改回「JPEG 或 H.264」，并明确说旧格式「**更广泛地被其他设备和操作系统兼容**」[14]。
- HEVC 播放兼容面（caniuse）：iOS Safari 11+ 全支持；桌面 Chrome 只有带硬件解码的设备才 `a`（部分支持），Windows 需装 HEVC 扩展；Android Chrome 同样只有硬件支持设备可用 [15]。→ **HEVC 在 Web 侧不是安全默认值**。
- H.264 播放兼容面：iOS Safari 3.2+、Chrome 4+ 全支持 [16]。
- Android 官方支持矩阵：H.264 AVC Baseline/Main、H.265 HEVC **Android 5.0+（MP4）**、VP8 4.3+、VP9、AV1 14+ [17]；**未找到**「各厂商默认编码选择」的官方口径。
- 即：**在 uni-app x 现有 API 内不能指定编码/码率/帧率**，要可控只能走 UTS 原生或浏览器 `MediaRecorder`。

## ⑤ 分段录制

- 官方 API 单段上限：`chooseVideo` **60s**、`chooseMedia` **30s（uni 文档）/ 60s（微信文档）**、`camera.startRecord` **默认 30s 且未写最大值** [4][5][2]。
- **没有** pause/resume 的官方录像接口（`getRecorderManager` 的 pause/resume 只对音频，且 Android 需 7.0+）[12]。
- 官方路径的「一节课拆成多段」只有一种：**反复 `startRecord`/`stopRecord`，每段各自落一个 mp4 文件**；App 端 `timeout` 可调大到覆盖单段时长，但「最大值」文档未写，属**未实测项**。
- iOS 原生层（UTS/AVFoundation）有硬上限参数：`AVCaptureFileOutput.maxRecordedDuration`「specifies a **hard limit** on the duration…default value … indicates **no limit**」[18] → 原生路径可单段录完整节课。

## ⑥ 微信小程序端

- 录制：`wx.chooseMedia`（基础库 2.10.0+）`maxDuration` 默认 10，原文「时间范围为 **3s 至 60s** 之间。**不限制相册**」；count 2.25.0 后最多 20 [6]。
  - ⚠️ 与 uni-app x 文档写的「3s 至 30s」**不一致**，两端都要按「以实际端为准」处理。
- `wx.chooseVideo` **自基础库 2.21.0 起停止维护**，官方要求改用 `chooseMedia` [19]。
- 上传：`wx.uploadFile` 文档**未写文件大小上限**（参数只有 url/filePath/name/header/formData/timeout 等）[20]；网络默认超时 **60s**，`wx.request/uploadFile/downloadFile` 最大并发 **10** [7]。
- 后台上传：**不可能**。原文「小程序进入后台运行后，如果 **5s** 内网络请求没有结束，会回调错误信息 `fail interrupted`」[7]；「进入后台状态一段时间后（目前是 **5 秒**），微信会停止小程序 JS 线程的执行……进入挂起状态」「挂起后…（目前是 **30 分钟**）都未再次进入前台，小程序会被销毁」[8]。
- 事实结论：小程序端**单段最长 60s→需多段**，且**上传必须在页面前台完成**；长视频「录完就走」在小程序端不成立。

## ⑦ 移动浏览器端（Web）

- `getUserMedia`：**仅安全上下文（HTTPS/localhost）**；不安全上下文里 `navigator.mediaDevices` 直接 undefined [21]。caniuse：Safari 11+ / iOS Safari 11+ 支持；备注「**iOS 14.3 之前 WKWebView/UIWebView 拿不到视频输入设备**」「**不支持独立运行的 PWA（装到主屏）**」[22]。
- `MediaRecorder`：MDN 标注 Baseline「自 2021 年 4 月起跨浏览器可用」[23]；caniuse 首个支持版本 Safari **14.1**、iOS Safari **14.5–14.8** [24]。
- 编码/容器：`MediaRecorder` 构造可传 mimeType 与码率，但**能否用取决于实现**，必须 `MediaRecorder.isTypeSupported()` 运行时探测；MDN 示例的候选含 `video/webm;codecs=vp8|h264`、`video/mp4;codecs=avc1…|hvc1…`、`av01…` [25]。
- 分片：`start(timeslice)` 每 N 毫秒吐一个 Blob，`requestData()` 可强制切块 [23][26] → **Web 端是唯一能「边录边切」的端**。
- 后台：页面进 `hidden` 后可能被冻结/丢弃；原文「Modern browsers today will sometimes **suspend pages or discard them entirely**」「frozen 状态下浏览器暂停任务队列执行，**JS 定时器与 fetch 回调不跑**」[27]。**未找到 Apple 对 Safari 锁屏后继续录制/上传的官方口径**。
- 时长/内存：MDN 与 Chrome 文档**均未写**录制时长或内存上限；数据以 Blob 交付页面，落盘/上传由页面自理 [23][26]。

## ⑧ UTS 插件与原生路径

- UTS 插件定义（官方）：原文「uts 插件，指利用 uts 语法，**操作原生的 API（包括手机 os 的 api 或三方 sdk）**，并封装成一个 uni_modules 插件」；UTS 编译目标 Android=Kotlin、iOS=Swift、HarmonyOS=ArkTS；uni-app x 自 **HBuilderX 3.9+** 支持 [28]。
- 打包约束：Android 原生配置「**均需提交云端打包才能生效，真机运行时需使用自定义基座**」；且「目前仅支持通过 HBuilderX 创建和使用 UTS 插件，**不支持通过 cli 的方式使用 UTS 插件**」[28]（与仓内 `npm run build:*` 脚本链相关）。
- 插件市场实测检索（2026-11-13）[29]：
  - `id=29489`「自定义相机、水印相机」UTS 插件，声明支持 **uni-app x 标准模式 + 蒸汽模式**，版本 2.2.25，更新 **2026-11-11**，`uni_modules`，收费（可试用）。
  - `id=30503`「无预览拍照录像相机」uni-app x 标准模式插件，Android，版本 1.0.0，更新 **2026-11-03**。
  - `id=27874`「Android 原生自定义相机拍照 录像 UTS 插件」，uni-app x (5.07)，版本 1.0.0，更新 **2026-05-04**。
  - `id=28232`「iOS 视频录制插件」；`id=5258 / 11236` 短视频录制（标「时长自定义」）——均为三方插件。
- **未找到 DCloud 官方（非三方）的录像 UTS 插件**；也未检索到「后台上传」类 UTS 插件。以上为插件市场检索结果，**许可/价格/售后未逐条核实**（标注：未核实）。
- 原生可行性（官方口径支撑）：UTS 可调 OS API，故 CameraX（Android）/ AVFoundation（iOS）路线在文档层面成立；iOS 侧 `maxRecordedDuration` 可设硬上限 [18]，Android 侧有前台服务类型 `camera` + `dataSync`（见⑩）。

## ⑨ 体积数字账（假设 + 算法）

**码率基准**（YouTube 官方推荐上传码率，SDR / 标准帧率 24–30）[30]：720p **5 Mbps**、1080p **8 Mbps**、1080p60 **12 Mbps**；容器 MP4、视频编码 H.264。

算法：`每分钟 MB = 码率(Mbps) × 60 ÷ 8`；`时长(min) = 2048 MB ÷ 每分钟 MB`。

| 档位 | 码率假设 | MB/分钟 | 30 分钟体积 | 2GB(2048MB) 可录 |
| --- | --- | --- | --- | --- |
| 720p30 H.264 | 5 Mbps（低档 2.5） | **37.5**（18.75） | **1.10 GB**（0.55） | **54.6 分钟**（109） |
| 1080p30 H.264 | 8 Mbps | **60** | **1.76 GB** | **34.1 分钟** |
| 1080p60 H.264 | 12 Mbps | 90 | 2.64 GB（**超 2GB**） | 22.8 分钟 |
| 1080p30 HEVC | 4 Mbps（按「省 50%」假设） | 30 | 0.88 GB | 68.3 分钟 |
| 720p30 HEVC | 2.5 Mbps（同上假设） | 18.75 | 0.55 GB | 109 分钟 |

- HEVC「同画质省约 50% 码率」是**假设**（Apple 只说「better compression」，未给百分比）[14]；真实手机默认码率（iPhone 1080p30 HEVC、各 Android 厂商）**未取到官方数字**，属未实测项。
- 结论性数字：**30 分钟 1080p30 H.264 ≈ 1.76 GB，正好顶到 2 GB 上限**；1080p60 会超。
- 上行耗时（1 GB = 8192 Mbit，理论值、不含 TCP/协议开销，实际约 +10–20%）：

| 上行 | 1 GB | 1.76 GB（30 分钟 1080p30） |
| --- | --- | --- |
| 1 Mbps | **136.5 分钟** | 240 分钟 |
| 5 Mbps | **27.3 分钟** | 48 分钟 |
| 20 Mbps | **6.8 分钟** | 12 分钟 |

- 分片与 60s 读超时的算术卡点：8 MiB = 67.1 Mbit → **1 Mbps 需 67 s（> 60s 超时）**、2 Mbps 需 33.6s、5 Mbps 需 13.4s；5 MiB 在 1 Mbps 需 **41.9 s**；同段 1800 MB 体积按 8 MiB/片 = **225 片**、5 MiB/片 = **360 片**。

## ⑩ 权限与后台上传的系统约束

- **Android 前台服务**（后台上传的官方载体）：必须显示状态栏通知；`dataSync` 类型需 `FOREGROUND_SERVICE_DATA_SYNC`；`camera` 类型需 `FOREGROUND_SERVICE_CAMERA` + `CAMERA` 运行时权限，「**cannot create a camera foreground service while your app is in the background**」[31]。
- **Android 时长限制**：`dataSync`/`mediaProcessing` 前台服务「**6 小时 / 24 小时**」，超时系统调 `Service.onTimeout`，不自行 `stopSelf` 会抛 `RemoteServiceException`；该 6 小时为**同类型全 App 共享**，App 回前台会重置计时 [32]。
- **iOS 后台上传**：`URLSession` 原文「upload tasks … **support background uploads while the app isn't running**」；`URLSessionConfiguration` 有 `backgroundSessionConfiguration`、`isDiscretionary`（系统决定调度时机）、`sessionSendsLaunchEvents`（传输完成后把 App 拉起/恢复）[33][34]。上传任务以**文件**提交（`uploadTask(with:fromFile:)`）[35]。
- **iOS 录制**：DCloud 已把「app 进入后台，摄像头终止」写成错误码 2003009 [2]；**未找到** Apple 允许 App 在后台继续摄像的官方口径。
- **权限**：`camera` 组件与 `startRecord` 需要相机（+ 录音）权限，微信侧需在 `app.json` 声明；本轮**未逐端核实权限声明清单**（标注：未核实）。
