## 0. 置顶结论（最重要的那条先说）

**uni-app x 的 App 端「支持」微信登录，而且不是「需自行集成原生 SDK」那条路。** DCloud 已把微信 Open SDK 做成内置模块 `uni-oauth`（含微信 provider 实现），从 **HBuilderX 5.08** 起 `uni.login({provider:'weixin'})` 在 App-Android / App-iOS 可用。

- 一手依据①（API 文档开头原话）：「Android、iOS平台从 HBuilderX5.08 版本开始支持微信登录」
  https://doc.dcloud.net.cn/uni-app-x/api/sign-in.html
- 一手依据②（内置模块表）：「uni-oauth 三方登录模块（HBuilderX5.08+）包括API：uni.login … 此模块仅包含基础登录模块，需手动配置需要使用登录方式」
  https://doc.dcloud.net.cn/uni-app-x/collocation/manifest-modules.html
- 一手依据③（模块配置页原话）：「微信登录 使用 "微信 Open SDK for Android" 实现，使用前需到微信开放平台创建移动应用并在开发配置中正确配置 Android应用 的包名和签名。」
  https://doc.dcloud.net.cn/uni-app-x/collocation/manifest-android.html （章节 `uni-oauth（登录） → 微信登录`）
  iOS 同理：「使用 "微信 Open SDK for iOS" 实现，使用前需到微信开放平台创建移动应用并在开发配置中正确配置 iOS应用 的 Bundle ID 和 Universal Links。」
  https://doc.dcloud.net.cn/uni-app-x/collocation/manifest-ios.html

**卡点不在框架，在微信侧前置条件**：移动应用 AppID/AppSecret 未注册 ⇒ 无法通过微信的「AppID + 包名 + 签名（Android）/ Bundle ID + Universal Links（iOS）」一致性校验，真链路一步都跑不通；这一步是**外部审核流程（1-7 个工作日）＋主体资质**，不是代码能绕的。

- 一手依据：「在进行微信 OAuth2.0 授权登录接入之前，在微信开放平台注册开发者账号，并拥有一个已审核通过的移动应用，并获得相应的 AppID 和 AppSecret，申请微信登录且通过审核后，可开始接入流程。」
  https://developers.weixin.qq.com/doc/oplatform/Mobile_App/WeChat_Login/Development_Guide.html
- 一手依据（审核时长/信息项）：「预计会在 1-7 个工作日内完成审核」
  https://developers.weixin.qq.com/doc/oplatform/Mobile_App/guideline/create.html
- 一手依据（框架侧错误码即校验点）：`1310500 未找到微信 APPID`、`1310501 APPID、appIdentifier、bundleId不匹配`、`1310502 微信可能未安装`、`1310512 iOS 没有配置对应的URL Scheme`、`1310513 iOS 没有配置对应的Universal Link`
  https://doc.dcloud.net.cn/uni-app-x/api/sign-in.html （LoginFail.errCode 表）

## 1. uni-app x 的 App 端到底支不支持微信登录？

### 1.1 支持，且 `provider` 取值含微信

| 事实 | 一手来源 | 引文要点 |

### 1.2 官方要求的配置面（x 版）

1. **模块声明（provider 机制不参与摇树，必须手写）**
   「摇树不支持 provider 机制，…登录 uni-oauth 和 分享 uni-share 模块需要手动配置使用 Provider 依赖的三方SDK模块。」
   https://doc.dcloud.net.cn/uni-app-x/collocation/manifest-modules.html
2. **manifest.json 节点（官方文档示例原形）**
   Android：`app-android → distribute → modules → uni-oauth → weixin → { "appid": "%微信开放平台申请应用的APPID%" }`
   iOS：`app-ios → distribute → modules → uni-oauth → weixin → { "appid": "...", "universalLink": "%微信开放平台设置的 Universal Links%" }`
   （manifest-android.md / manifest-ios.md 的 `uni-oauth（登录） → 微信登录` 小节；节点位置随版本变：**HBuilderX 4.71+ 用 `app-android`/`app-ios`，4.71 以下用 `app.distribute.modules`**，见 modules 页「手动配置使用的模块」）
   https://doc.dcloud.net.cn/uni-app-x/collocation/manifest-android.html
   https://doc.dcloud.net.cn/uni-app-x/collocation/manifest-ios.html
   同一形状可在 DCloud 官方示例仓库的 manifest.json 交叉验证（`uni-oauth.weixin.appid` / iOS 额外 `universalLink`）：
   https://raw.githubusercontent.com/dcloudio/hello-uni-app-x/master/manifest.json
3. **是否要有 AppSecret 在客户端？** 不需要、也没有配置位。x 版文档只给 `appid`（无 `appsecret` 节点）。官方示例把 secret 放在**服务端** `uni-config-center` 的 config（`config.weixin[appid]`）。
   https://raw.githubusercontent.com/dcloudio/hello-uni-app-x/master/uniCloud-aliyun/cloudfunctions/uni-login-test-co/index.obj.js
4. **是否需要开放平台 AppID**：是（第 0 节三条依据）。`appid` 为空/不匹配 ⇒ 1310500 / 1310501。
5. **基座与打包**：「标准基座已包含 微信登录」「自定义基座需提交云端打包后才能生效」（manifest-modules 页 uni-oauth 注意）；sign-in 页「注意」另写「App平台开发微信登录，无需自定义基座，真机运行可直接开发」。
   ⚠️ 这两句与「标准运行基座使用的是 DCloud 的包名、证书和三方SDK配置」（https://uniapp.dcloud.net.cn/tutorial/run/run-app.html，同页给出 uni-app x 标准基座包名 `io.dcloud.uniappx`）合起来读，得到的**推论**（非文档原话，已标注）：标准基座可跑通「拉起微信 + 回调」的能力面，但**自有 AppID 的包名/签名一致性校验**只能在**自有包名+自有签名的正式包/自定义基座**上成立——微信侧校验依据是开放平台登记的包名+签名。
   https://developers.weixin.qq.com/doc/oplatform/developers/troubleshooting/opensdk.html （「1、应用包名签名信息校验不通过 …AppID 和包名签名信息不一致」）
   iOS 另有硬约束：「自2022年9月14日起iOS真机设备不再支持使用标准真机运行基座…请向苹果申请证书制作自定义基座」（run-app 页）。

## 3. jscode2session 与开放平台 OAuth 的凭证/端点差异（官方口径）

### 3.1 两套端点与两套凭证

| | 小程序（现状所走） | 移动应用 / App（本项目要新增） |
|---|---|---|
| 客户端 API | `wx.login()`（uni-app 侧 `uni.login({provider:'weixin'})` 在 MP-WEIXIN 端） | 微信 Open SDK `SendAuth.Req`，scope **只能填 `snsapi_userinfo`**；uni-app x 侧由 `uni-oauth` 内置 |
| 服务端端点 | `GET https://api.weixin.qq.com/sns/jscode2session?appid=APPID&secret=SECRET&js_code=JS_CODE&grant_type=GRANT_TYPE` | `GET https://api.weixin.qq.com/sns/oauth2/access_token?appid=APPID&secret=SECRET&code=CODE&grant_type=authorization_code` |
| 端点归属 | 小程序（`/sns/jscode2session`，接口适用范围＝小程序） | 开放平台「移动应用」微信登录（网站应用扫码另有 `/sns/oauth2/access_token` 同族端点，见下注） |
| 使用的应用凭证 | **小程序 AppID + 小程序 AppSecret**（公众平台/小程序后台） | **开放平台移动应用 AppID + AppSecret**（注意：不是小程序那一对） |
| code 生命周期 | 小程序 code「详见 jscode2session」，服务端换取；官方明确 code 只在有效期内用一次 | 移动应用 code「超时时间为 10 分钟，且只能使用一次」 |
| 返回的身份标识 | `openid`（+ `session_key`；**若该小程序已绑定开放平台账号**才返回 `unionid`） | `access_token`、`refresh_token`、`openid`、`expires_in`、`scope`、`unionid` |
| 是否还有后续调用 | 无（session_key 用于解密手机号等） | 有：`/sns/userinfo`（拉昵称头像，需 access_token）、`/sns/oauth2/refresh_token`、`/sns/auth`（校验有效性） |
| 失败码 | `40029` code 不可用 / `40226` 风控拦截 / `45011` 频率限制 | 未上架应用的微信登录有 **100 次/天** 限制 ⇒ 触发时错误码 `10060` |

一手来源（逐条对应上表）：

- 小程序端点与参数、返回字段：
  https://developers.weixin.qq.com/doc/minigame/dev/api-backend/login/api_code2session.html
  （同页列 `appid`/`secret`/`js_code`/`grant_type=authorization_code`，返回 `openid`、`session_key`、`unionid`「是用户在开放平台的唯一标识符，若当前小程序已绑定到微信开放平台账号下会返回」，错误码 `40029 无效的code`、`40226`、`45011`）
- 小程序登录流程口径（code → code2Session → openid/unionid/session_key）：
  https://developers.weixin.qq.com/doc/miniprogram/dev/framework/open-ability/login.html
- 移动应用端点、scope 限制、code 一次性/10 分钟、unionid 出现条件、100 次/天：
  https://developers.weixin.qq.com/doc/oplatform/Mobile_App/WeChat_Login/Development_Guide.html
  原话要点：「scope 只能填 snsapi_userinfo」；「code 作为换取 access_token 的票据，每次用户授权带上的 code 将不一样，code 只能使用一次，10 分钟内未被使用则超时」；「当且仅当该移动应用已获得该用户的 userinfo 授权时，才会出现 unionid 字段」；「未上线的应用…每天限制 100 次，超出返回错误码 10060」。
- DCloud 官方示例服务端**实际就是**调开放平台端点（不是 jscode2session）：
  https://raw.githubusercontent.com/dcloudio/hello-uni-app-x/master/uniCloud-aliyun/cloudfunctions/uni-login-test-co/index.obj.js
  要点：`https://api.weixin.qq.com/sns/oauth2/access_token` + `{appid, secret, code, grant_type:'authorization_code'}` → 解析 `access_token/openid/unionid` → 再 `https://api.weixin.qq.com/sns/userinfo?access_token=...&openid=...`；`secret` 来自服务端 `uni-config-center` 的 `config.weixin[appid]`。

> 注：微信开放平台文档另有「网站应用」扫码登录（`/sns/oauth2/access_token` 同形端点 + `redirect_uri`），与「移动应用」是两套应用类型、两套凭证。本项目后端 `WECHAT_OPEN_PLATFORM_APP_ID/SECRET` 的注释自述是「扫码登录」占位——**若要走 App 端登录，需要的是「移动应用」类型的 AppID/AppSecret**，不能复用「网站应用」那对（一手依据：移动应用创建页与 Development_Guide 的前置条件把应用类型写死为「移动应用」）。
> https://developers.weixin.qq.com/doc/oplatform/Mobile_App/guideline/create.html

### 3.2 openid 与 unionid：同一自然人跨端能否认成同一个人

| 问题 | 官方口径 | 一手来源 |
|---|---|---|
| openid 是什么范围唯一 | 「微信用户 + 服务号 AppID = openid」，即**每个应用各有一套 openid**；同一用户在不同应用下 openid 不同 | https://developers.weixin.qq.com/doc/oplatform/developers/doc/service/guide/product/unionid.html （UnionID 机制说明） |
| unionid 是什么范围唯一 | 「微信用户 + 开放平台账号 = unionid」；同一开放平台账号下，同一自然人的 unionid 唯一 | 同上 |
| 小程序与开放平台移动应用拿到的 openid 是否相同 | **不相同**（openid 以 AppID 为粒度）。要跨端认人只能靠 unionid | 同上 + https://developers.weixin.qq.com/doc/miniprogram/dev/framework/open-ability/union-id.html |
| unionid 在小程序侧何时可得 | 小程序**必须绑定到微信开放平台账号**下，code2Session 才返回 unionid；官方另列「绑定开发者账号的小程序」获取途径 | https://developers.weixin.qq.com/doc/miniprogram/dev/framework/open-ability/union-id.html |
| unionid 在移动应用侧何时可得 | 「当且仅当该移动应用已获得该用户的 userinfo 授权（scope=snsapi_userinfo）时，才会出现 unionid 字段」 | https://developers.weixin.qq.com/doc/oplatform/Mobile_App/WeChat_Login/Development_Guide.html |
| 绑定条件/位置 | 移动应用需在同一开放平台账号下创建并通过审核；unionid 与 AppID 无绑定关系而是与开放平台账号绑定 | https://developers.weixin.qq.com/doc/oplatform/developers/doc/service/guide/product/unionid.html |

**结论（对本项目）**：现有 `POST /auth/wx-login` 返回的是**小程序 openid**，与 App 端换取到的**移动应用 openid** 是两个不同字符串，**不能当同人主键**。要让小程序账号与 App 账号落到同一用户，唯一官方路径是两边都拿 **unionid**，其成立条件为：① 小程序已绑定到某个开放平台账号；② App 所属移动应用建在**同一个**开放平台账号下且已通过微信登录能力审核；③ App 端授权 scope 为 `snsapi_userinfo`（移动应用登录官方只允许这一个 scope）。三个条件缺任一 ⇒ 后端无法稳定认人，只能退化为「两端各自独立账户」。

> DCloud uni-id 的数据模型正是按这个语义设计的（可借形，不代表本项目已启用 uniCloud）：字段 `wx_unionid`、`wx_openid.app`、`wx_openid.mp`，并以 `wxPlatform = 'mp' | 'h5' | 'web' | 'app'` 区分渠道。
> https://doc.dcloud.net.cn/uniCloud/uni-id/summary.html （数据模型/三方登录字段；同页注释「App 微信登录所用到的 appid、appsecret 需要在微信开放平台获取，注意：不是公众平台而是开放平台」）

### 3.3 混用是否会被官方「容错」？

一手来源未找到任何「小程序 code 可以拿去 `/sns/oauth2/access_token` 换」或反之的说明；两套端点的参数名虽相似（`appid/secret/code|js_code/grant_type`）但凭证类型不同（小程序 AppSecret vs 开放平台移动应用 AppSecret），文档未提供任何互通或降级路径 ⇒ **按不可混用处理**（本项目现状代码里 `loginByWechat()` 复用 `mpWechatLoginApi(code)` 到 App 端，属于会必然失败的接法，不能保留）。

## 4. 「开放平台未注册」在开发链路上的阻塞程度

### 4.1 拿不到 AppID 之前**根本做不了**的环节

| 环节 | 为什么做不了 | 一手来源 |
|---|---|---|
| manifest 里写 `uni-oauth.weixin.appid` | 唯一合法来源是开放平台移动应用 AppID；占位串会命中 `1310500 未找到微信 APPID`，不一致命中 `1310501 APPID、appIdentifier、bundleId不匹配` | sign-in 页 errCode 表；manifest-android/ios 页配置示例（appid 值本体就是「%微信开放平台申请应用的APPID%」） |
| 微信开放平台侧「应用签名 / 包名（Android）」「Bundle ID / Universal Links（iOS）」登记与校验 | 这些字段本身就是审核材料；未注册即无登记处，SDK 拉起时微信侧必然校验失败 | https://developers.weixin.qq.com/doc/oplatform/Mobile_App/guideline/create.html 、 https://developers.weixin.qq.com/doc/oplatform/developers/troubleshooting/opensdk.html |
| 真实授权回调（拉起微信 → 用户确认 → 带 code 回落 App） | 回调依赖开放平台登记的 AppID + URL Scheme / Universal Links（iOS 缺配置直接 `1310512 / 1310513`）；HarmonyOS 还依赖 `querySchemes:["weixin"]`、`actions` 白名单 | sign-in 页 errCode 表与「注意」小节 |
| 服务端 `/sns/oauth2/access_token` 换取 | 需要 `appid + secret`（移动应用那对）；无凭证无法调用，且返回的 openid/unionid 语义依赖开放平台账号绑定关系 | Development_Guide；hello-uni-app-x 云对象源码 |
| 上线配额（未上架应用 100 次/天） | 需要应用「上架」状态；未注册连「未上架应用」都不是，配额限制是后一阶段问题 | Development_Guide（`10060`） |
| iOS 侧「三方登录必须并列 Apple 登录」 | Apple 审核要求：支持任何三方登录必须同时支持 Apple 登录（x 侧 Apple 登录 HBuilderX 5.21+；文档「注意」小节同样写明） | https://doc.dcloud.net.cn/uni-app-x/api/sign-in.html ；provider 页 apple 说明 https://doc.dcloud.net.cn/uni-app-x/api/provider.html |
| iOS 真机联调走标准基座 | 官方已停：「自2022年9月14日起 iOS 真机设备不再支持使用标准真机运行基座」，需自有证书打自定义基座 | https://uniapp.dcloud.net.cn/tutorial/run/run-app.html |

### 4.2 可以**先行**的环节（不被开放平台阻塞）

| 可先行项 | 依据/边界 |
|---|---|
| 登录页布局、样式、按钮态、次级入口（手机号/邮箱/微信切换条） | 纯前端；uni-app x 的 uvue 样式约束与本仓库既有登录页结构无关微信凭证。真机运行不需自定义基座即可跑样式（sign-in 页「App平台开发微信登录，无需自定义基座，真机运行可直接开发」——同句也说明框架侧不是阻塞点） |
| provider 可用性与「微信是否安装」的运行期探测 | 官方 API：`uni.getProvider({service:'oauth'})` / `uni.getProviderSync`，`UniOAuthWeixinProvider.isWeChatInstalled`；这两者不需要 AppID 就能写并能在真机验证分支（一手：sign-in 页「注意」小节示例 + provider 页） |
| 后端接口骨架与字段契约（路由、入参出参类型、错误码映射） | 端点形状已由官方文档/示例钉死（第 3.1 表）：`POST /auth/app-wx-login { code }`；返回结构可与现有 `WechatLoginResult` 对齐；无 AppID 也能编译、单测 mock 换取层 |
| unionid 作为同人主键的库表/唯一索引预留 | 语义有官方定论（第 3.2），可先落列与约束；注意「小程序必须绑定开放平台」这一步也在外部流程里，列可先建、值先为空 |
| 「无凭证时」的 UI 降级与文案（按钮隐藏/置灰 + 说明） | 官方对 iOS 明确建议「未安装微信时需隐藏/不展示微信登录按钮」（sign-in 页 `isWeChatInstalled` 探测语义 + Development_Guide iOS 建议「未安装微信时应隐藏登录按钮」，Android 建议始终显示） |
| mock / 桩（假 code、假 openid） | 属工程自建，**不是官方能力**（见 4.3） |

### 4.3 官方是否提供 mock / 沙箱路径？

**一手来源未找到** DCloud 或微信开放平台针对「App 端微信登录」的官方 mock/沙箱/测试环境：

- uni-app x sign-in 页无 mock 章节；`uni.getProvider` 只做能力探测，不伪造登录结果。
- 未找到「uni-app x 官方标准基座自带演示 AppID 可直接体验自有账号微信登录」的 x 版一手表述（该说法在 uni-app **vue 版**文档中存在：「标准真机运行基座使用的是 DCloud 申请 HBuilder 应用的 AppID 等信息，仅用于体验微信登录功能」，https://uniapp.dcloud.net.cn/tutorial/app-oauth-weixin.html ），**不能移用到 x 版**。
- 微信侧「测试号/沙箱」类能力在开放平台移动应用登录文档中未出现（小程序有测试号体系，App 登录无对应官方测试凭证可换 unionid）。

⇒ 结论：**不存在可依赖的官方 mock 路径**；需要 mock 只能自建（客户端把「是否具备真链路」判断集中在一个 gate 里，服务端把换取层做成可注入接口以便假实现）。这是工程手段，不是官方能力，文档口径要在评审时讲清楚。

## 5. 结论：「前端样式先行、真链路后接」的最小接缝建议

以下为工程决策建议，事实部分均有上文一手锚点；建议部分是本调研的推论，已按此标注。

1. **入口隔离：不要用编译期条件把微信入口整条抹掉，改成「运行期能力 gate」。**
   - 现状 `pages/login/login.uvue` 用 `#ifdef MP-WEIXIN` 包住微信入口（148-154 行），App 端不可达，样式无法在 App 上预览。
   - 建议：入口常驻在 App 分支里，可见性交给运行期判断——`uni.getProviderSync({service:'oauth'})` 找 `id=='weixin'` 的 provider（官方 API，provider 页/sign-in 页）＋ 一个本地 `appWechatLoginEnabled` 开关（读 `manifest` 是否配了 `uni-oauth.weixin.appid` 不可行于运行期读取，故用 `constant.uts` 或构建期注入的布尔量）。**开关位置唯一、默认关**，真链路接入时只翻这一处。
   - 注意本仓库 ADR-0025 的门判据纪律：不新增 `#ifdef MP-WEIXIN` 指令行——本建议方向与之一致（用 gate 取代新增条件编译）。
2. **按钮可见性/文案口径（区分平台，官方有明确建议）：**
   - iOS：微信未安装时**不展示**微信登录入口（`isWeChatInstalled == false` 即隐藏；一手：sign-in 页 provider 属性 + Development_Guide iOS 建议）。
   - Android：**保持展示**（Development_Guide 对 Android 的建议），点击后失败按 `errCode` 给可读提示；`1310502` ⇒「未检测到微信」，`1310509` ⇒「已取消登录」。
   - 未接入态文案：不要在 UI 写「暂不支持微信登录」这类与官方能力矛盾的静态文案（框架支持，缺的是凭证）；建议隐藏入口或标注为「即将开放」，并由 gate 决定，避免样式与真实行为长期不一致。
   - iOS 上架硬约束：一旦 App 支持微信登录，必须并列提供 Apple 登录（sign-in 页「注意」小节原话）⇒ **Apple 登录入口的样式槽位应现在就预留**，否则后接微信时被审核倒逼补做。
3. **代码接缝形状（最小改动）：**
   - `stores/auth.uts`：保留 `loginByWechat()` 作为唯一入口，内部按平台分流——MP-WEIXIN 走现有 `mpWechatLoginApi(code)`；App 走**新的** `appWechatLoginApi(code)`。**禁止**让 App 的 code 落进 `/auth/wx-login`（第 3.3 结论：必然失败）。
   - `api/auth.uts`：新增 `appWechatLoginApi(code : string)` → `POST /auth/app-wx-login`，返回结构与 `WechatLoginResult` 对齐（`token/refreshToken/userInfo/isNew`），复用同一 `setAuthData(...)` 出口与 `STORAGE_KEY_LOGIN_PROVIDER`（provider 值建议新串，如 `app-weixin`，便于会话审计区分渠道）。
   - 成功回调取 `res.code`（x 版 `LoginSuccess.code` 字段官方兼容性 Android/iOS 5.08；注意其描述文案仍写「小程序用户临时登录凭证」，属文档措辞遗留，语义按平台分流——这点在评审时不要当成「App 端不支持」的证据）。
4. **后端预留形状（不实现）：**
   - 声明 `POST /api/auth/app-wx-login`（入参 `code`），换取层接口化：`WechatAppOAuthVerifier.Exchange(code) → (openid, unionid, err)`；先落**空实现/返回明确 NotImplemented 错误**，等 AppID 到位再填 `https://api.weixin.qq.com/sns/oauth2/access_token` → `/sns/userinfo` 调用链。这与 uni-id-co 的官方做法一致（三方登录留空实现，一手：uni-id 概览页）。
   - 凭证配置位区分语义：`WECHAT_OPEN_PLATFORM_APP_ID/SECRET` 现注释是「扫码登录（网站应用）占位」；App 登录需要**移动应用**类型的另一对 ⇒ 建议加 `WECHAT_APP_ID/WECHAT_APP_SECRET`（或 `OPEN_PLATFORM_MOBILE_*`）而非复用同一对（依据第 3.1 注）。AppSecret 只留服务端，绝不下发客户端（x 版 manifest 无该配置位；第三方插件页亦强调「AppSecret 必须放在服务端」）。
   - 账号同人：`user_auth` 类表预留 `unionid`（唯一索引）+ `platform_openid`（含 `platform` 枚举 `mp|app|web|h5`），照 uni-id 的 `wx_unionid / wx_openid.app / wx_openid.mp` 形状即可，不引入新概念。
5. **前置任务（外部阻塞项，应现在就启动而非等前端做完）：**
   - 微信开放平台开发者账号注册 + 创建「移动应用」（审核 1-7 工作日），需要 Android 包名+签名、iOS Bundle ID（+ Universal Links 域名与 apple-app-site-association 部署）。一手：create 页与 Development_Guide 准备工作。
   - Android 应用签名需正式签名（或明确固定 debug keystore 的 MD5）后才能填写；本仓库若要「样式先跑、签名后补」，应把签名/包名信息采集列为独立 issue 与前端并行。
   - iOS Universal Links 必须有 HTTPS 域名 + `apple-app-site-association` 可访问，这属于域名/部署工作，可先于 SDK 接入完成。
6. **不要在样式阶段做的事（避免后续返工与假结论）：**
   - 不要凭 vue 版文档改 x 版 manifest（`app-plus.distribute.sdkConfigs.oauth` 在 x 版无效；第 1.3 差异表）。
   - 不要在客户端放 AppSecret、不要自造「假 code 走真端点」的联调。
   - 不要把第三方插件当官方能力来决策（路径 A 无需买插件）。
   - 不要以「现在跑不通」为由在文档/注释里写「uni-app x 不支持 App 微信登录」——与一手文档相反。
