# AI 助手首页还原 · 讨论纪要（图一 → 图二）

> **定位**：`/grill-with-docs` 的产出，作为 `/to-spec` 的输入。11 条结论已与维护者逐条对齐（答复序列 `0a 1b 2a 3c 4a 5a 6a` → `7a 8a 9a 10a` → `11a`）。
> **状态**：讨论结束，**代码尚未改动**。规格票已按本纪要生成：[#2781](https://github.com/DriftingLi/FL/issues/2781)（`/to-spec` 的产物，kind=spec，label `ready-for-mobile-agent`）；下一步待手动 `/to-tickets` 拆实施票。
> **关联事实笔记**：`docs/design/20261123-AI助手首页还原-布局事实核查.md`（input 进 scroll-view 的微信端口径、宫格换算、来源清单）。

## 0. 一句话

把 AI 助手首页从「底部大输入面板 + 4 格宫格 + 档位横幅 + `⋯` + `v`」改成图二的「紧凑标题区 + 四格宫格 + 三张薄卡 + 紧跟其后的紧凑输入卡」，**只改布局、间距与可见性；不改接口、消息发送、模型、语音、附件逻辑**。

## 1. 权威性：图二只管视觉

- 图二是**视觉规范**（布局 / 间距 / 尺寸 / 控件形态），不是功能清单。功能集合以**功能注册表**为真值。
- 图二第 2 格「故障代码查询」**不补**：根 ADR-0032 决策 3 已下线该键；`pages/ai-assistant/ai-assistant-constants.uts:14-15` 头注释明写「不要为了补齐 5 格把它接回」；`utils/aiFeatureRegistryParityContract.test.js` 有专门用例断言该键不得复活（剥注释后源码不得出现 `fault_code`/`fault_code_query`/`故障代码查询`）。
- 图二标题写「故障咨询」「维修知识」，注册表 label 是「智能维修诊断」「维保知识」。**以注册表为准**（契约测试第 ② 条锁 `title == label`）。
- 术语依据：根 `CONTEXT.md` 词条 **AI 助手**、**AI 专业版（AI pro）**、**自定义模型**、**选择模型**、**专项**、**随问图片**。其中「`选择模型` 已放开为免费，不属专业版集合」是 D4 的直接依据。

## 2. 决策账（11 条）

### D1 · 四格等宽，不补第 5 格（原 Q0a / Q2a）

- `.function-item` 宽度 `23%` → `25%`，四格填满，图标在格内居中；保留「限免」小签。
- 几何依据：可用宽 702rpx（`.main` / `.func-head` 左右各 24rpx），四格 = 175.5rpx/格，6 汉字标题在 24rpx 下最宽 144rpx ⇒ 放得下。若改成五格 = 140.4rpx/格 < 144rpx ⇒ 必然挤或截。
- 名称保持注册表口径（智能维修诊断 / 图纸识别 / 习题解答 / 维保知识），顺序即 `FUNCTION_ITEMS` 现有顺序。

### D2 · 删档位横幅，专业版入口迁入抽屉（原 Q1b）

- 删 `pages/ai-assistant/ai-assistant.uvue:55-59` 的 `.pro-banner`。
- **前提**：D3 的抽屉迁移必须先落地——横幅当前是基础版用户触达兑换的**唯一**可见入口（基础版右抽屉过滤掉「自定义模型」，模型芯片此前又不渲染，`onModelBarClick` 的 `!proUnlocked → showProSheet` 走不到）。删横幅与删 `⋯` 必须同批，且同批补上抽屉里的「解锁专业版」项，否则基础版**没有任何**专业版入口（ADR-0009 的 2026-09-13 修订记录正是用这条理由否决过"独立专业版页"）。

### D3 · 删 `⋯` 与 `v`，右抽屉四项迁入左抽屉（原 Q3c / Q7a）

- 删 `ai-chat-nav.uvue` `#toolbar` 槽里的 `.chat-menu-glyph`（`⋯`）与页面上的 `:show-toolbar="true"`；右侧菜单抽屉（`AiChatDrawerRight`）随之无入口。
- 删 `ai-assistant.uvue:12-14` 的 `.func-head-handle`（`v` / `^`），宫格恒展开：`functionHeaderCollapsed` 与 `toggleFunctionHeader`（L371-376）一并退役，`.func-head` 的 `v-if` 由 `!isScoped && !functionHeaderCollapsed` 收敛为 `!isScoped`。
- 左抽屉（`components/ai-chat/ai-chat-drawer-left.uvue:7-23`，现为「新对话 + 最近对话」）加一个「设置」分组，承载：对话设置 / 自定义模型（仅专业版，沿用 `rightMenuItems` 的过滤）/ 个人中心 / **解锁专业版**（替代横幅）。两组之间加分组标题，避免被读成"最近对话里混进了设置项"。
- **不需要新图标**：`RIGHT_MENU_ITEMS` 的 `MenuItem` 只有 `{key, label}`，右抽屉本就是纯文字行；左抽屉现有的 `new-chat.png` / `bubble.png` 只服务会话段。
- 处置复用 `onMenuAction`（L674-685）的四个分支，不新写跳转逻辑。

### D4 · 模型芯片常显且可点（原 Q4a）

- `ai-assistant.uvue:121` 的 `:show-model-bar="proUnlocked && !isScoped"` → `"!isScoped"`；`:model-readonly="!proUnlocked"` → `false`。
- `onModelBarClick`（L636-642）语义改为「一律开选择器」，未解锁时点开**只列平台模型**（`allModels` L326-341 已按 `proUnlocked` 过滤自带 key 的用户模型）；「自定义模型 / 管理」行（`onCustomClick` L797-804、`goManageModels` L786-793）**已有** `!proUnlocked → showProSheet` 直门，不依赖"芯片不渲染"间接挡。
- 依据：ADR-0009 L83 + 根 `CONTEXT.md`「`选择模型` 已放开为免费」。即当前"基础版不渲染芯片"是 #1024 之前的残留，本票顺手把 ADR 与代码对齐。
- 同批改 3 处锁字面串的断言：`utils/aiCapabilityGateContract.test.js:57,59`、`utils/aiDiagnosisSourcesContract.test.js:352`、`utils/aiProGateContract.test.js:154-155`；`utils/aiFeatureEntryWiringContract.test.js:445` 锁 `show-image-button` 的那条按 D9 原样保留。

### D5 · 输入卡双态，机制是换 class（原 Q5a）

- 欢迎态（`messages.length == 0` 且非专项）：给 `.main` / `.pro-scroll` 加 class，设 `flex: 0 0 auto` + `height: auto`，主区只占内容高度，输入卡（**仍是兄弟节点**）自然落在三张卡之后，剩余空间留在下方。
- 对话态：去掉该 class，恢复 `flex: 1`，输入卡贴底。
- **不把输入卡移进 `scroll-view`**：`input` 是原生组件、获得焦点时不参与同层渲染（[native-component](https://developers.weixin.qq.com/miniprogram/dev/component/native-component.html)）；且 `components/ai-chat/ai-chat-input.uvue:58-62` 写明学员手打的字**从不进入 `draft`**，`v-if` 重建会丢字。
- **不加任何键盘监听**：`pageHeight` 只在 `onLoad` 取一次 `windowHeight`（`ai-assistant.uvue:2`、`:952`）；移动端 ADR-0073 §⑧ 记过：微信端键盘弹出后可视区已移到键盘上沿，再把 `keyboardheightchange.height` 当作额外的 bottom 偏移会**重复扣除键盘高度、把输入区顶出屏幕**。保持现有兄弟结构 = 键盘行为零回归。

### D6 · 发送即切，专项恒对话态（原 Q8a）

- 判据就是 `messages.length == 0`；发送后立刻回贴底（符合"新会话发出第一条即进入对话"的心智）。
- 专项态（`isScoped`）恒按对话态处理。
- 实现要求：换容器而非"先销毁再挂载"，避免空帧；滚动走既有 `#bottom-anchor` + `scrollIntoViewId`，不新写滚动逻辑。

### D7 · 间距只走 24 / 16 两档（原 Q9a）

单一真值源 `training-app/叉车维修培训学员端跨端应用/docs/ui-spec.md`（§2 `$spacing-md = 24rpx`）；`training-app/叉车维修培训学员端跨端应用/scripts/audit-spacing.mjs` 的 R1/R2/R3 按此查，改前全仓 121 个 `.uvue` 是 `WARN 0`，改后必须仍是 0。

| `.function-item` 宽度 | 23% | 25% |
| 宫格 icon / title | 84rpx / 24rpx | 不变 |
| 宫格 `margin-bottom` | 24rpx | 16rpx |

## 5. 风险与待证

1. **`lines: 1` 在 mp-weixin 的映射未证实**（官方兼容表 Web 列标 `x`、原文标"已废弃"）⇒"6 字标题不换行"不作保证，改完用 D8 的截图核这一项；若确实失效，退路是给 `.function-title` 固定宽度 + 单行高度，不引新机制。
2. **左抽屉语义膨胀**：从"会话抽屉"变成"会话 + 设置"。必须加分组标题，否则误读。
3. **专业版入口单点化**：删横幅后基础版只剩抽屉一处，D10 的守护就是防它被再次删掉的那道闸。
4. **`audit:spacing` 必须仍为 WARN 0**（改后重跑）。
