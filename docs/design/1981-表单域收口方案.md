# 1981 · 表单域收口：批次边界与生效点

> 本文件回答票里卡住的两件事：**批次怎么切**、**「新代码必用」从哪一刻生效**。
> 存量盘点见 [1981-表单域存量盘点](./1981-表单域存量盘点.md)（`node scripts/inventory-form-fields.mjs --md` 生成，不要手改）。

## 一、口径先对齐

票面写 `el-input` 169 / `el-select` 57，本次盘点报 **191 / 58**。差的这 22 是**封装层内部**的 `el-input`（`components/ui/**` 里 `UiInput`、`UiFormField` 自己的实现）—— 旧盘点按「封装层之外」计数，本次把两层都算进来并分开报（`inputBare` 190 / `selectBare` 57）。**迁移面按 190 / 57 算**，封装层不迁（它就是终点）。

## 二、覆盖面缺口（票里问的第 2 件事）

盘点把「`UiInput` / `UiSelect` 够不够用」变成了可核对的清单。**不够**，两处硬缺口：

| 缺口 | 存量 | 影响的批次 |
| --- | --- | --- |
| `UiInput` **没有插槽透传**（`#prefix` / `#suffix` / `#prepend` / `#append`） | `#prefix` 出现 6 个文件（3 个认证页 + `HrwaiUserManage` / `RecruiterManage` / `TutorManage` 的搜索框、`CourseCatalog`） | 管理端 / 认证页 —— 这两批不扩容就迁不动 |
| `UiSelect` **表达不了 `el-option-group`**（它把 `el-option` 写死成 `options` 数组） | 8 处 / 3 文件（`CredentialSwitcher`、`CourseCatalogCourseDrawer`、`QuestionCreate`） | 共享组件 / 讲师端 |
| `UiSelect` 没有 `multiple` / `filterable` / `remote` 透传 | 5 个文件 | 学员端 / 讲师端 |
| `UiInput` 没有 `readonly` | 0 处（暂无人用） | — |

另外三类**不是缺口**、是调用方写法：`ref`（15 文件，多为 `inputRef.focus()`）、`@keyup.enter`（10 文件，搜索框回车）、inline `style="width: …"`（15 文件）—— 这些走 attrs 透传或改一个 prop 就能表达，不需要动组件契约。

## 三、批次边界：按端切，从依赖最少的一端开始

**不按页面族切**。页面族（列表页 / 表单页 / 抽屉）横跨四个端，切出来的每一批都要同时碰 `UiInput`、`UiSelect`、`el-option-group` 三种形态，复杂度不可控；按端切则每批的「特殊用法组合」高度相似（同一端的页面是同一批人写的、同一套习惯）。

| 批次 | 范围 | 处数 | 为什么在这个位置 |
| --- | --- | --- | --- |
| **0** | **组件扩容**：`UiInput` 补 `#prefix` / `#suffix` / `#prepend` / `#append` 插槽透传；`UiSelect` 补 `el-option-group`（`groupedOptions` 或 `#options` 插槽）与 `multiple` / `filterable` 透传 | — | 后面每一批都踩这两处，先做它比在批次里顺手改组件干净 |
| **1** | 讲师端（4 文件） | 8 + 7 | 最小的一批，且带 2 处 `option-group` —— 用它验证批次 0 的扩容是否够用 |
| **2** | AI 助手（2 文件） | 0 + 3 | 纯 `el-select`、无特殊用法 |
| **3** | 招聘端（3 文件） | 10 + 6 | — |
| **4** | 共享组件（17 文件） | 34 + 8 | 含 6 处 `option-group`，依赖批次 0 |
| **5** | 学员端（13 文件） | 28 + 13 | — |
| **6** | 管理端（18 文件） | 79 + 21 | 最大的一批，放在前面几批把坑踩完之后 |

合计 190 + 57 = **247 处 / 60 文件**。

## 四、「新代码必用」的生效点

**生效时刻：批次 1 的 PR 合并那一刻**（不是批次 0 —— 批次 0 只是组件扩容，此时封装件还表达不了所有形态，要求新代码必用会把人逼回裸 `el-input`）。

**执行手段**：`check-ui-intent`（#1982）的「按域分批」现在是**两种模式同一个判定**，需要改成模式敏感 ——

- `--all`（存量）：`el-input` / `el-select` 仍在「按域分批」里，**放行**；
- `--diff`（新增行）：同样两个标签**不放行**，等于「新代码必用封装件」。

落地方式取其一：给 `scripts/lib/guard.mjs` 加一个可选的 `spec.diff.scanSource ?? spec.scanSource`（向后兼容、不动现有三个守卫），或让守卫在 `isDirectRun` 里按 argv 置一个模式位。**本次没实现** —— 它属于批次 1 的 PR（见下「本期范围」）。

**回滚点**：每一批合并即销一次账（该端的 `el-input` / `el-select` 归零）；某一批若卡住，只要不动「按域分批」那一行，守卫口径不会提前收紧。

## 五、每批的判据

1. `node scripts/inventory-form-fields.mjs` 里该端 `el-input` / `el-select` 归零（封装层除外）；
2. `node scripts/check-ui-intent.mjs --all` 绿、`--diff origin/master` 绿；
3. `npm test` 全量绿（表单域改动必然碰挂载用例）；
4. 该端的代表性页面一张截图（`docs/verification/<票号>/`）；
5. 不新增组件、不改 `UiInput` / `UiSelect` 的对外契约（扩容只在批次 0 做）。

踩到的坑值得记：分组里的选项常带 `v-for="c in credentials.filter((x) => ...)"` —— 箭头函数里的 `>` 会让「按 `>` 找标签结尾」的正则提前收尾，生成出 `options: undefined`。批量转换遇到属性里含 `>` 的标签必须显式处理；`vue-tsc` 会把这个错误接住（TS2322），不会漏到运行期。
