## 二、响应式现状（复测）

首版票面的「24 个 / 6 条 media query」是测错的：检索式 `@media \(max-width` 漏掉了 `@media screen and (max-width: …)`。复测：

| 手段 | 数量 | 文件 |
| --- | --- | --- |
| CSS `@media` | **26 条** | 21 个 `.vue`（+1 条在 `valuation-tokens.css`） |
| JS `matchMedia` | 1 处 | `ChatPageShell` |
| Tailwind 断点工具类 | 41 处 | 18 个文件（`sm:` / `md:`，无 `lg:` / `xl:`） |
| **并集** | — | **39 / 172 个组件（22.7%）** |

断点分布：`768px` ×16、`480px` ×4、`767px` ×3、`560px` ×1、`900px` ×1、`1024px` ×1。

## 三、静态布局约束

| 指标 | 实测 | 含义 |
| --- | --- | --- |
| `min-width` 声明 | 20 处（多数 `min-width: 0`） | flex 收缩修正，不是布局约束 |
| 固定像素宽 | 73 处（含 `max-width` 命中，需按类名复核） | 固定宽度写在页面里 |
| `grid-template-columns: repeat(N)` | 5 处（2 列 ×3、4 列 ×2） | **没有成体系的栅格** |
| `overflow-x: auto/scroll` | 5 处 / 5 文件 | **没有成体系的横滚兜底** |
| `el-table` | 197 处 | 宽表在窄屏无统一塌陷口径 |

结论：现状不是"响应式做得差"，而是**没有响应式体系**——断点集中在 768、手段两套并存、宽表靠 Element Plus 自身行为。

票面要求每个页面族给出「最小可用宽度」实测。本机当前**无法完成**：
