## 2. 鉴权与信封

### 2.1 鉴权

| 面 | 中间件 | 行为 |
|---|---|---|
| `/chat`、`/upload-image`、`/diagnosis/*` | `OptionalAuth` | 带 token 就解析填充，**不带/失效也放行**（游客可用）；放行时 `user_id = 0` |
| `sessions` CRUD、`sessions/:id/messages` | `JWTAuth` + `CapabilityRequired(ai_assistant.use)` | 无 token / 失效 → **401「Token无效或已过期，请重新登录」**；能力不足 → **403「权限不足」** |

- token 提取：`Authorization: Bearer <token>`，回退 Cookie（`AccessCookieValue`）。见 `backend/internal/security/session.go:536–541`
- token 由 `POST /api/auth/login` 取得（响应 `{token, refresh_token, user_id, account, username, role}`），`POST /api/auth/refresh` 轮换；access 有效期默认 **2 小时**（`JWT_EXPIRES_HOURS`），refresh 默认 7 天
- ⚠️ **诊断相关的 401 只可能来自 `sessions` 系列**。`/chat` 是 OptionalAuth，**token 过期时不会返回 401，而是静默降级为游客**（回答照出、但**不落库**、`session_id` 无效也不报错）。这条直接影响 T4「登录过期只提示一次并回登录页」的实现方式 —— 见 §8 的 G2

### 2.2 信封

`{code, message, data}`，HTTP 状态码与 `code` 同值。见 `backend/pkg/response/response.go:12–16`。空载荷端点（DELETE / PATCH / POST user-models）`data` 恒为 `null`。

## 3. 逐接口契约

> 示例中 `<…>` 是占位，不是真实值。真实读数来源标注为「联调实测」的来自 runbook，其余是从契约测试桩反推的**形状**（字段名与可空性可信，具体文案以生产实测为准）。

### 3.1 `POST /api/ai-assistant/chat`（SSE）

**请求体**（`StreamChatReq`，`backend/internal/aiassistant/service.go:112–136`）：

```json
{
  "session_id": 1234,
  "feature_key": "fault_diagnosis",
  "messages": [
    {"role": "user", "content": "上一轮问题"},
    {"role": "assistant", "content": "上一轮回答"},
    {"role": "user", "content": "我的中力叉车（液压系统）出现故障现象：举升无力 / 不能起升。补充：E01。请给我排查步骤、根因分析和维修方案。",
     "images": ["https://api.gdyidao.cn/static/uploads/images/ai-assistant/chat_1730952000000.webp"]}
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `feature_key` | 是（诊断） | 诊断固定 `fault_diagnosis`；空 / `ai_assistant` = 通用对话 |
| `messages` | 是 | 非空；**最后一条必须是 `role=user`**，且 `content` 与 `images` **至少一个非空**（允许纯图轮次） |
| `session_id` | 否 | 登录用户传则**持久化**（user + assistant 两行）；游客 / 不传则不落库 |
| `messages[].images` | 否 | **只取最后一条用户消息的图**；历史图不重发（控 token）。元素必须是**本站前缀 URL**，否则不报错、只在正文尾追加 `[部分图片加载失败: <url>]` |
| `brand` / `model` | 否 | **v2 单轨后无消费方**（v2 请求体只有 `content`+`images`），保留字段只为不动前端契约。品牌/型号**必须组句进 content** |

请求校验失败 → **400 信封**（不是 SSE）：「请求数据无效」/「消息不能为空」。

**响应**：`200` + `Content-Type: text/event-stream`，帧形为 `event: <名>\ndata: <json>\n\n`（`backend/internal/aiassistant/handler.go:456–461`）。

| 事件 | data | 何时发 |
|---|---|---|
| `status` | `{"text":"正在检索维修知识库…"}` | 上游首个 delta 之前；可能多条、可能没有（**原样转发上游过程文案**） |
| `message` | `{"content":"<增量>"}` | 逐块；累积即当前正文 |
| `sources` | `{"sources":[{id,text,metadata:{source_url,page_start,page_end}}]}` | **仅当非空**。诊断通道 v2 下**恒不发**（见 §8 G3）；历史列里的老来源仍走 messages 接口回放 |
| `usage` | `{points_cost,total_tokens,balance,prompt_tokens,completion_tokens}` | 计费成功才发。诊断限免（`freePreview`）⇒ **不发** |
| `error` | `{"message":"<中文人话>"}` | 失败；**发完即结束，不会再有 done** |
| `done` | `null` 或 `{"meta":{"badges":[{name,emoji,cls}],"elapsed":11.8}}`，必要时追加 `"content":"<归一后权威全文>"` | 正常结束。`meta` 仅诊断有；`content` **只在「归一后全文 ≠ 已推增量」时出现**（唯一来源是配图白名单改写） |

- 客户端正确形态：**`done.content` 存在则替换累积正文，缺席则保留累积**（#2293 的教训 —— 曾因只归一返回值、没归一用户看到的那份，浏览器真的向第三方主机发了图请求）
- 上游内部事件 `ping` / `user_saved` **不转发**给客户端
- 计费：`fault_diagnosis` 声明 `freePreview: true` ⇒ 预检与扣费都不发生、不发 `usage`（`backend/internal/aiassistant/feature_registry.go:151`、`aiFeatureChatBilled`）

### 3.2 引导五面

**`GET /diagnosis/intents`**（联调实测：2 品牌 4 FAQ）

```json
{"code":200,"message":"success","data":{
  "brands":[
    {"id":"zhongli","name":"中力","tagline":"电动仓储车","icon":"🚜","cls":"cap-brand-zl","picker":"system"},
    {"id":"linde","name":"林德","tagline":"德国进口","icon":"🏭","cls":"cap-brand-ld","picker":"model"}
  ],
  "faq":[{"q":"<高频问题>","a":"<一句话答案>"}]
}}
```

- `brands[].picker` 是**第二层形态的唯一判据**：`"model"` ⇒ 选型号（林德）；其余与 `null` ⇒ 选系统（中力）。**引入第三个值时按系统档处理**（契约未定项）
- `cls` 是对方样式类名，我方按自己的品牌色渲染，**原样保留仅为对齐契约**
- `brands` / `faq` **恒为数组**（空集是 `[]`，不是 `null`）

**`GET /diagnosis/systems?brand=`**（联调实测：中力 14 系统 / 林德 87 型号）

```json
{"code":200,"message":"success","data":{"items":[{"id":"hyd","name":"液压系统","icon":"🔧"}]}}
```

- 缺 `brand` → **400「缺少品牌参数」**（不猜默认品牌）
- `icon` 用 `omitempty`：林德型号**没有**这个键

**`GET /diagnosis/faults?brand=&second=`**

```json
{"code":200,"message":"success","data":{"items":[{"id":"<id>","name":"举升无力 / 不能起升"}]}}
```

- `second` 缺省 = **该品牌的根层列表**（六张诉求卡走这条）；带 `second` 是**另一份列表**（比对照错层会误判，见 runbook §2.2）
- 联调实测根层（`brand=zhongli`）：`仪表报故障码 | 整车无法启动 / 无法上电 | 不行走 / 无法行走 | 举升无力 / 不能起升 | 不能充电 / 充电异常 | 转向失灵 / 无转向`
- ⚠️ 林德型号层的条目在真实响应里**还带 `hint` 字段**（检索关键词），而我方 DTO 只有 `{id,name,icon}`，`encoding/json` 静默丢弃 —— 不报错但信息丢了（§8 G4）

**`GET /diagnosis/code-hint?q=`**

```json
{"code":200,"message":"success","data":{"status":"known","message":"<一行说明>","fix":"","samples":[]}}
```

| `status` | 含义 | 该给什么 |
|---|---|---|
| `known` | 码表命中 | `message` 一行说明（联调实测 `q=E01` ⇒ known） |
| `unknown` | 格式对但未收录 | 安静（不渲染） |
| `format` | 格式不合法 | `samples[]` 给出填法 |
| `none` | 没输入或太短（实测 `q=E`、`q=XYZ` ⇒ none） | 安静 |
| `typo` | 形似字符笔误 | `fix` 给出应改成什么 |

- `samples` **恒为数组**；无缓存（跟着输入框逐字符变）

**`GET /diagnosis/health`** —— **永远 200**

```json
{"code":200,"message":"success","data":{"ok":true,"app_configured":true}}
```

- **有意只投影两个字段**：上游另 18 个字段含 `key_fp8` / `data_dir` / `workflow_id_head` / `memory_mode`，属对方内部拓扑，不得出现在未登录可读端点里（runbook 已实测 `grep -c` = 0）
- 未配置（默认部署态）时 `ok=false` 且 `app_configured=false`，**端点仍 200**
- 前端约定：`health.ok=false` ⇒ **连已拿到的字典一起丢掉**，引导面整块留白

### 3.3 `GET /diagnosis/ossimg/*filepath`

- 响应：**原样字节流 + 上游 `Content-Type`**，`Cache-Control: public, max-age=86400`（不用 `immutable`：文件名是规范名不是内容哈希，同名可换内容）
- 五道闸（`backend/internal/aiassistant/diagnosis_proxy.go:39–90`）：① scheme 必须 https + host 与 `DIAGNOSIS_V2_OSS_BASE` 逐字相同；② path 必须在 `/forklift/repair_img` 之下；③ 剥 `?#`、`PathUnescape` **只解一次**，逐段过 `staticSegmentPattern`（`..` / `%2e%2e` / 空段全落网）；④ 末段必须 `png|jpg|jpeg|webp`（**pdf 故意不放行**）；⑤ 逐段 `PathEscape` 后拼到本站路径
- 失败 → **404 信封**（「图片不存在」/「无效的图片路径」/「诊断配图暂时不可用」）
- 上游取不到时 adapter **不做同步预取**，浏览器 `<img>` 坏图态显示 alt 文字（后端不再多一次出站往返）

### 3.4 `POST /ai-assistant/upload-image`

请求：`multipart/form-data`，字段名 **`file`**（单文件，一图一请求）。

```json
{"code":200,"message":"图片上传成功","data":{"url":"/static/uploads/images/ai-assistant/chat_1730952000000.webp"}}
```

| 项 | 值 | 判据 |
|---|---|---|
| 扩展名白名单 | `png / jpg / jpeg / gif / webp / bmp` | `backend/internal/filestore/file_type_table.go:48–53`；**扩展名校验，无 magic-byte 嗅探** |
| 单文件上限 | **20 MB**（`image` 分档） | `backend/internal/filestore/file_store.go:29–33`（分档表）、`:151–160`(`ValidateImage`) |
| 压缩 | jpeg/png/bmp 经 sidecar 转 **WebP**（gif/webp/svg 不压） | `shouldCompressImage`；sidecar 不可用时**原样保存** |
| 返回 URL | local 驱动 `/static/uploads/images/ai-assistant/…`；R2 驱动 `https://<cdn>/images/ai-assistant/…` | 两种形态都过 `IsSiteAttachmentURL` |
| 失败 | **400 信封** + 可读文案（「不支持的图片格式，允许格式：bmp, gif, jpeg, jpg, png, webp」/「图片大小超出限制，最大允许20MB」） | 同一出口 |
| 鉴权 | OptionalAuth（**游客也能传**） | |

```json
{"code":200,"message":"success","data":[
  {"id":1,"role":"user","content":"<问题>",
   "images":["https://api.gdyidao.cn/static/uploads/images/ai-assistant/chat_xxx.webp"],
   "sources":null,"meta":null,"created_at":"2026-11-05T10:00:00+08:00"},
```

## 4. 图片上传与历史记录：能力说明

### 4.1 图片怎么进、怎么关联

```
客户端选图 → 压缩（降级：不压也行）→ 逐张 POST /upload-image → 拿到站内 URL
  → 随消息放进 messages[].images → 后端读回文件转 base64 dataURL → 送上游
```

- **关联方式**：用户消息行的 `images` 列存 **JSON 字符串数组（站内 URL）**，不存 base64、不存文件引用表（`backend/internal/aiassistant/service.go:606–614`）
- **图片正文只走 dataURL**：base64 只存在于服务端出站请求，**永不下发客户端**（ADR-0091）
- **只读本站前缀**：`Read` 前过 `IsSiteAttachmentURL(u, "images/ai-assistant")` —— 非站内 URL **不报错**，降级成正文尾一行 `[部分图片加载失败: <url>]`（`backend/internal/aiassistant/service.go:675–713`）

### 4.2 两道闸（**注意：都不是「拒绝」，行为不同**）

| 闸 | 值 | 超限行为 | 谁能给可读提示 |
|---|---|---|---|
| 张数 | **3 张/轮** | 上游侧**静默截断**，只在正文尾追加「本次随问附带了 N 张图片，仅前 3 张送达诊断服务。」 | **只有客户端能拦**（后端不会给「超过 3 张」的错误） |
| 单张体积（解码后） | **5 MB** | **整轮失败** → `error` 事件「图片单张不能超过 5MB，请压缩后重试」 | 后端已给可读文案 |

- 5 MB 是**解码后**的字节数，与上传闸门 20 MB 是两个数（`backend/internal/aiassistant/diagnosis_adapter.go:453–457`）
- 压缩后通常是几百 KB，正常不会撞 5 MB；撞上说明压缩没生效

### 4.3 历史能不能还原

- **能**：`images` 列落库 → messages 接口原样回放 → 客户端 `<img>` 直接加载站内 URL（`max-age` 一天）
- ⚠️ **移动端当前未消费**：`api/aiAssistant.uts` 的 `buildSessionMessage` 只映射 `id/role/content/created_at/sources`，**没有映射 `images` 与 `meta`**（`types/ai.uts` 里 `AiSessionMessage.images` 类型已存在但赋值点缺失）⇒ 「重进会话图还在」这条 **AC 要移动端补映射，不是后端缺口**
- ⚠️ **孤儿图片不回收**：悬空 sweep 只覆盖 `forum_image` 与 `contribution` 两个域，`images/ai-assistant/` **不在其中**（`RunOrphanSweep` 的两个注册点见 `forum/image_service.go:77`、`contribution/service.go:329`）⇒ 选了图但没发送的文件会长期驻留（§8 G7）

## 5. 诊断结果字段

| 客户端要的 | 有没有 | 字段 / 来源 |
|---|---|---|
| 最终完整回答 | ✅ | `done.content`（归一后权威全文，**仅在≠已推增量时出现**）；否则用累积 `message` |
| 本轮使用的诊断能力标识 | ✅ | `done.meta.badges[]`，每条三字段 `{name, emoji, cls}`，**原样存对方给的**，不压成逗号串 |
| 诊断耗时 | ✅ | `done.meta.elapsed`（秒，float，上游原始精度） |
| 维修建议 / SOP 正文 | ✅ | 就是 `answer` 本体（markdown）：安全准备 → 步骤 → 验收 |
| 安全提醒 | ✅（以正文形式） | 上游把「前置安全准备」写进 markdown 正文；**没有独立的结构化字段** |
| 知识来源（结构化清单） | ❌ | v2 的 `done` **不带 sources**，`sources` 事件在诊断通道**恒不发**（§8 G3）。历史行的 `sources` 列仍会回放旧数据 |
| 排查轨迹（trace） | ❌（**有意不存**） | 上游 `done.trace` 被 adapter 丢弃：契约自己写「排查用，可不展示」，对方存了也从不回放 |
| 历史回放同源 | ✅ | messages 接口的 `meta`（`badges` + `elapsed`），与当轮 `done.meta` 同形状 |

落库：迁移 `000050_ai_chat_message_meta` 加 `ai_chat_messages.meta TEXT`（与 `sources`/`images` 同形，选 TEXT 不选 JSONB——从不参与过滤聚合）。

## 6. 超时、异常与错误码

### 6.1 超时（**四处独立配置，改一处不会提醒另一处**）

| 层 | 值 | 判据 |
|---|---|---|
| 上游 SSE 总时长 | **300 s** | `backend/internal/aiassistant/transport.go:86` `aiStreamTimeout` |
| 我方 SSE 写超时 | **300 s**（`done` 前逐请求设置） | `writeSSEHeaders` 里 `SetWriteDeadline(now+aiStreamTimeout)`；拿不到底层连接时降级并置响应头 `X-SSE-Deadline: unset`（**`origin/master` 才有，本地树没有**） |
| 引导面单次超时 | **10 s** | `backend/internal/aiassistant/diagnosis_catalog.go:92` |
| 客户端（移动端现网） | **120 s** | `config/env.uts` `AI_REQUEST_TIMEOUT = 120000` |

> ✅ **客户端超时已与服务端同源（#2298 / PR #2324）**：`AI_REQUEST_TIMEOUT = 330000`（300 s + 余量），改前是 `120000` —— 那段日子慢回答会在客户端先被判超时，而服务端仍在跑（还会把结果落库）。见 §8 G5。

### 6.2 错误码

| HTTP | 场景 | message（客户端可直显） |
|---|---|---|
| 400 | 请求体非法 / `messages` 空 / 最后一条不是 user / 文本与图都空 | 「请求数据无效」「消息不能为空」 |
| 400 | 引导面缺 `brand` | 「缺少品牌参数」 |
| 400 | 图片格式/体积不合规（上传端点） | 「不支持的图片格式，允许格式：…」「图片大小超出限制，最大允许20MB」 |
| **不是 HTTP 码** | 图片解码后 > 5 MB（对话端点，走 **SSE `error` 事件**） | 「图片单张不能超过 5MB，请压缩后重试」 |
| 401 | `sessions` 系列：无 token / 失效 | 「Token无效或已过期，请重新登录」 |
| 403 | 能力不足（`ai_assistant.use`） | 「权限不足」 |
| 404 | 会话/模型不存在 | 「会话不存在」「模型不存在」 |
| 404 | 配图代理路径非法或上游无此图 | 「无效的图片路径」「图片不存在」 |
| 429 | 我方 IP 限流（默认 20 rps / burst 40，**仅生产开启**；**响应体是 `{code,message}`，没有 `data` 键**） | 「请求过于频繁，请稍后再试」，带 `Retry-After: 1` |
| 429 | 上游限流（**实测 300 次/分钟**，非契约写的 60） | 「诊断服务请求过于频繁，请稍后再试」，**不带 Retry-After** |
| 502 | 诊断未配置 / 上游 401/403/5xx / 上游超时 / 解析失败 | 「智能维修诊断服务未配置，请联系管理员」或固定文案「诊断服务暂时不可用」 |
| 500 | 我方内部错（如能力判定查询失败） | 「服务器内部错误」 |
| —（SSE `error` 事件） | 上游业务错误 / 图片超限 / 积分不足 | 中文人话；**发完即断，无 `done`** |

**三条对外文案纪律**：① 5xx 一律**不回显上游原文**（`ClientErrorText`：保留前缀、丢尾巴，真实原因只进日志）；② 429 与 502 是两件事（「等会儿再试」vs「服务坏了」），前端按状态码分流；③ 上游 401/403 被翻译成中文人话（Key 失效 / IP 不在白名单），**不暴露对方拓扑**。

### 6.3 失败语义汇总

- `/chat` 出错：**只发 `error` 事件、不发 `done`** ⇒ 移动端等待态必须由 `error` 或请求结束来清，不能只等 `done`
- 上游不可达 vs 未配置：引导面都是 **502**（文案不同）；`health` 都是 **200 + ok=false**
- 登录过期：`/chat` **不会** 401（见 §2.1）；只有 `sessions` 系列才会

## 8. 已具备 / 待确认 / 缺失（逐条给后端确认）

### 8.1 已具备（无需后端新增）
