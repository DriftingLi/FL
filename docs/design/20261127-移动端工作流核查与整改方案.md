## 3 四项决定（2026-11-27 拍板 + 审查回写）

### 3.1 Q1 = D：页面观测进入机器判据 —— 本轮 DEFERRED（不在实施范围）

- **决定**：页面观测进入 `preflight` 判红，**从本轮实施范围移除，标记 `DEFERRED`**。本轮**不修改 `preflight-pr` / `gate-validator` / ruleset，不新增任何阻断条件**，也不为了完成 Q1 顺手改预检或偷偷加其他阻断。
- **保留（不因 defer 受阻）**：页面观测的**采集与只读报告能力照常继续**——A/B/C 三档观测、`audit-spacing` 等只读工具不受影响；preflight 保持现有行为。
- **defer 的理由**：Q1 要让「缺少页面观测」判红，本质是把页面观测加进 preflight 判据 = 改「什么算红」。#2897 Out of Scope 把边界写成「不进 CI 必检 / 不进 pre-commit / 不进 pr-evidence / 不改 ruleset 与门校验器」，比「不新增 GitHub required check」更严：`preflight-pr.ps1` 是日常开 PR 的**强制前置步骤**，动它即踩「不进 preflight」「不改门校验器」两条边界。而 #2897 US#28「要翻案必须另立裁定」锁死顺序：**先立裁定，再谈写代码**。
- **后续如需强制门禁**：先独立提出 supersede 裁定——注意 **supersede 不是整份 #2897 作废**，新 ADR 必须明确指出自己取代的只是「不新增判红门」与「不进 preflight」**这两条具体条款**，其余未被取代的决策仍然有效——获得批准后再实施。
- **存档分析（供后续立裁定时复用，本轮不执行）**：
  - 记录取值四分：PASS / FAIL / BLOCKED / 不适用（后者仅限无 UI 可见面）；FAIL 默认修复重测，不得冒充 BLOCKED。
  - BLOCKED 独立状态：按**目标运行端**判定（其他平台 PASS 不得替代，`dev-loop.md:526`）；须附显式风险接受声明、由人合并；不得记成 PASS；「人接受风险」≠「人工视觉验收通过」。
  - Q1/Q2 交叉（BLOCKED 且命中白名单）：允许明确人工风险接受，记为例外，不得自动通过。
  - 例外解析不得伪装：现有例外通道只认 ②/④（`gate-validator.mjs:446-451`），页面观测 BLOCKED 例外须新增独立语义（独立字段/解析）。
  - 实施形态（届时）：预检输出 `human-merge-required` 机器可读状态 + Agent 纪律（非不可绕过的 GitHub 强制门）；不新增 GitHub 必检。

### 3.2 Q2 = B：视觉关键页白名单 —— 收窄人工验收默认

- **定性修正**：Q2=B 是**取代旧规则**（现状：PR 模板 `PULL_REQUEST_TEMPLATE.md:78` 默认每个 UI PR 都写 `人工验收：待确认`，即「UI 可见面默认停在人工验收待确认」），不是「新增白名单」。收窄后**只有命中白名单页的 PR 才要求人工视觉确认**，其余 UI PR 不排队等人。
- 触发面 = **实际影响**白名单页面的变更；共享组件按其真实影响面判断，**由人维护影响关系，不从 git diff 推导**。
- **生效时机（方案 B）**：白名单尚未建立 ⇒ **Q2 本轮暂缓生效**，随 P1-3 一起落地；白名单正式筛选出来之前，PR 模板仍按现状。

### 3.3 Q3 = B：交付状态段（独立段，默认观测 PASS）

- **页面观测在建 PR 前完成**（`release.md:22-24`「开 PR 时机 = 一件事做完并验完」；移动端 `AGENTS.md` 第 2 步「改完自检含页面观测」）。因此 PR 建出时页面观测已是终态，**默认不该是「待观测」**。
- 四阶段行放**独立 `## 交付状态` 段**，**不塞进 `## 验收证据`**（验收证据段只放门读数行）。
- **默认值纠正**：**「验收=观测 PASS」**——这一默认值本身不依赖白名单，P0 即可落地；「命中白名单再加 `/ 人工待确认`」这个**附加条件**依赖白名单，**随 P1-3 落地后再启用**。`通过 / 退回` 只有人能写。

```
## 交付状态
实现=完成；集成=待合并；验收=观测PASS；工作区=待清理
```

- 取值：实现 完成/未完成；集成 待合并/已合并；工作区 待清理/已清理。
- **验收状态完整枚举（八值）**：`观测PASS` / `观测FAIL` / `观测BLOCKED` / `不适用`（Agent 写）；`人工待确认`（命中白名单，Agent 写）；`人工通过` / `人工退回`（**只有人写**）；`风险已接受（例外）`（**只有人写，与「人工通过」严格区分**——例外放行 ≠ 验收通过）。
- 只作可读、可 grep 的生命周期记录：**不判红、不改 `Closes` 自动关票、不把 `dev-close verdict=ok` 当验收完成**。四阶段各自仍以真实判据为准。

### 3.4 Q4 = A：批次集成窗口

- 派活模板加一行批次纪律；批次组标在**既有 wayfinder map** 上（不强制新建 map）；**不开新 triage label、不加脚本锁**。
- 只约束「最终验证 → 合入」这一段；编码与日常并行不受限。
- **补一条**：批次中任一 PR 合并后，剩余在途 PR 须**重查基线前进**并重新满足 up-to-date + CI 才能继续合并。

## 5 术语：五个词（工程流程词，不落 CONTEXT 词表）

**不落词表**：这五个词都是**工程流程词**，不是领域词汇。移动端 ADR-0043「回写与载体」已裁定「①a / ①b / 能力面 / 发版冒烟是工程流程词，按 0016 ③ 段裁定**不落词表**」（`0043-…md:43`）。按同口径，页面观测 / 人工视觉确认 / 关票 / 收尾同属流程词，**一律不进 `CONTEXT.md`**。流程定义留在现有工作约定，不制造第二套领域词典。

下表只是本方案内部对五词的**口径对齐参考**，不是要写进 CONTEXT 的条目：

| 词 | 含义 | 谁写 | 是否门 | 落点 |
|---|---|---|---|---|
| **页面观测** | 在 A/B/C 某一档真实运行里看到的页面/交互事实 | Agent | **本轮不是门；Q1 DEFERRED** | `dev-loop.md` |

## 7 批次集成窗口（仅并行批启用）

1 列同批在途票 → 2 会让候选运行时面变化的票先合或明确冻结 → 3 目标票同步基线、解冲突 → 4 锁定 head/base 跑正式验证 → 5 验证至合入期间不放行同批其他票推进相同运行时面 → 6 合入后释放（**任一 PR 合入后，剩余 PR 重查基线前进 + up-to-date + CI**）。

作用域：不限制编码与不相干 PR；判断以运行时面定义为准（非文件是否重叠）；**日常单票永不进窗口**。
