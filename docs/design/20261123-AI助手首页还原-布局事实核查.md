## 1. 问题 A：把 `<input>` 放进 `<scroll-view>`

### 1.1 微信端（本票主端）

### 1.4 scroll-view 高度口径（影响方案）

- uni-app x：「scroll-view 组件的内容高度需要**大于** scroll-view 组件的高度，才能滚动。如未给 scroll-view 设置高度，那么其高度**默认与子内容相同**，就会导致无法滚动」；解法「可以指定 scroll-view 的 height，也可以设置 flex:1 来撑满剩余空间」——[uni-app x·scroll-view](https://doc.dcloud.net.cn/uni-app-x/component/scroll-view.html)。

### 2.2 图标 84rpx → 64rpx + `mode="aspectFit"`

官方定义：「scaleToFill 不保持纵横比…使图片的宽高完全拉伸至填满」「**aspectFit 保持纵横比缩放图片，使图片的长边能完全显示出来。也就是说，可以完整地将图片显示出来**」「aspectFill…只保证图片的短边能完全显示出来…另一个方向将会发生截取」——[image](https://doc.dcloud.net.cn/uni-app-x/component/image.html)。

## 3. 对本票的结论

**A 路（把 `AiChatInput` 移进 scroll-view）不建议作为首选**，两个成本都有仓内一手依据：
- 组件会随 `v-if` 重建 ⇒ 内部 `inputText` 丢字。`ai-chat-input.uvue:58-62` 明写「学员手打的字**从不进** `draft`」，而回填只靠 `watch(draftText)`（`:96`）、**同值不触发** ⇒ 重建后 `''→''` 不会回填，欢迎态打的字会消失（除非把输入文字提升到页面 state，属结构改造）。
- 微信端 `focus` 态 input 非同层，且节点树重建会撞「同层渲染失败率（iOS）」（§1.1）。

**B 路（不改 DOM，只改 flex 分配）是本票推荐口径**：`AiChatInput` 保持 `.main` 之后不动，欢迎态给 `.main` 与 `.pro-scroll` 各加一个 class（`.main--flow` / `.pro-scroll--flow`）设为 `flex: 0 0 auto` + `height: auto`。依据：`.main` 不再吃剩余高度 ⇒ 其高度=内容高 ⇒ 输入卡自然紧跟内容（即「随内容流动」）；且无需重建任何组件。必须钉死的边界是**「欢迎态内容高于可视区时怎么办」**——`.ai-page` 定高 `pageHeight`（`:2`、`:952`）且全页无页面滚动，此时既不能滚也不会被 Flex 撑开。粗估欢迎态内容 ≈840rpx（导航 + 把手 88 + 宫格 ≈150 + 3 张卡 ≈360 + 输入卡 ≈150），在 667pt 机型（≈1334rpx）内尚有余量，**但属估算、须真机小屏确认**；要可滚兜底就只剩「给固定高度」（回到贴底）或「整页滚」（要动根容器定高）。

**宫格**：5 列用 `width:20%` + `flex-wrap:wrap` 有全端官方依据且仓内已有 1:1 先例（`dashboard-menu-grid.uvue:44-60`）；但**在 `.func-head` 24rpx 内边距下 6 汉字必然放不下**（差 18rpx）。三条出路择一：① 水平内边距压到**各 ≤15rpx**（内容宽需 ≥720rpx；例如各 12rpx ⇒ 726rpx ⇒ 每格 145.2rpx，仅余 1.2rpx）——代价是与 `.pro-scroll` 的 24rpx 对齐约定脱开（`:1219-1220` 注释）；② 字号降 22rpx（每格余 8.4rpx，字号下限需另行确认）；③ 接受 `lines:1` 截断（真机先确认 `lines` 在 mp 生效）。另注意：第 5 格在**后端注册表里没有对应键**（`ai-assistant-constants.uts:14-15` 明写「不要为了补齐 5 格把它接回」）——5 格的取数前提本身尚未成立。

- 微信端「`confirm-type=send` 在 scroll-view 内不可靠」——官方唯一不确定项是输入法差异。
- 微信端「focus/blur + setData 重渲染导致键盘收起或光标跳动」——输入文档无该条目；相邻官方提醒只有 tip「在 input 聚焦期间，避免使用 css 动画」，以及 `value` 被写成「初始内容」。仓内 `ai-chat-input.uvue` 是 `:value` 单向 + `@input` 回写（`:5`、`:111-115`），属自建受控，**未被任何一手来源覆盖**。
- `lines` / `max-lines` 在 **mp-weixin** 产物的实际行为。
- mp-weixin 上 `box-sizing` 默认值是否有逐项重置清单（只找到「编译器会进行 css 重置」这句综述）。
- 微信端 `adjust-position` 上推的是「页面」还是「scroll-view 内部滚动位置」——无一手表述；本仓只能以 ADR-0073 的「微信端可视区已上移」为实测边界。
