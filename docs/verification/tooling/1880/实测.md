# #1880：欢迎条深色底补齐（学员 / 教师 / 招聘三端）

## 结论

管理端在 #1750 已经把欢迎条从「固定色阶当底色」改成「品牌色浅混面板 token」；**另外三端没跟**。
本次补齐，用的是**同一套比例**（面 8% / 描边 18%），只改 class，不动布局。

| 端 | 修前 | 修后 |
| --- | --- | --- |
| 学员端 | `from-ui-50` + `border-ui-100` | `from-[color-mix(in srgb, var(--color-ui-500) 8%, var(--color-panel))]` + `border-[color-mix(… 18%, var(--color-line-strong))]` |
| 教师端 | 同上 | 同上 |
| 招聘端 | `bg-panel` + `border-line`（不亮，但**没有品牌浅混**，与三端不同款） | 同一层浅混底色（`bg-[color-mix(… 8%, var(--color-panel))]`） |
| 管理端 | — | 不动（#1750 已修，本次作为对照） |

根因与管理端那次相同：`--color-ui-50` = `--color-primary-50` = **#F0FDFA**、`--color-ui-100` = **#CCFBF1**，
这两个色阶在 `design-tokens.css` 的 `[data-theme="dark"]` 段里**没有重定义** ⇒ 深色下仍是亮奶油色；
而 `--color-panel`（=`--color-bg-card`：`#FFFFFF → #1E293B`）与 `--color-line-strong`（=`--color-border`）都会翻。

## 判据：浅/深两主题各取一次**像素**

脚手架把四条欢迎条的 class **从真实 .vue 源码里读出来**（`?raw` + 正则取 `<section class="…">`，不手抄，
所以脚手架不可能飘在源码之外），加上一条「修前」卡复现原缺陷，在真浏览器（Edge headless，1280 宽）里
分别截浅色与深色两版，再按卡片矩形取像素算**相对亮度**：

| 卡 | 浅色采样 | 浅色 L | 深色采样 | 深色 L |
| --- | --- | --- | --- | --- |
| 修前（学员端老 class） | rgb(241,253,250) | 0.9585 | **rgb(216,229,229)** | **0.7629 ← 亮块（缺陷复现）** |
| 学员端 · 修后 | rgb(237,247,246) | 0.9118 | rgb(28,48,64) | **0.0273** |
| 教师端 · 修后 | rgb(237,247,246) | 0.9118 | rgb(28,48,64) | **0.0273** |
| 招聘端 · 修后 | rgb(236,246,245) | 0.9034 | rgb(29,50,65) | **0.0292** |
| 管理端 · 对照 | rgb(246,242,254) | 0.9025 | rgb(39,45,74) | **0.0280** |

判定：**深色下四张欢迎条的底色相对亮度都 < 0.2**（亮块阈值 0.5），而「修前」卡在深色下是 0.76 ——
既证明缺陷可复现，也证明确实修掉了。浅色下四张仍 ≥ 0.90，**浅色观感无回归**（与 0.96 的修前卡只差在
一点点品牌调，肉眼几乎不可分）。

## 边界（只收欢迎条）

`--color-ui-*` 是**固定色阶**，凡是拿它当**大面积底色**（卡片底、区块底、渐变起点）的地方都有同样的
「深色下亮块」风险。本次没有普查全站（那是一次独立的 token 审计），只把欢迎条这一处补齐。
