# #1831：vite 7.3.7 → 8.3.5（构建内核换 rolldown）

## 结论

升了，但**不是改个版本号**：`manualChunks` 在 rolldown 下退化成兼容垫片，直接沿用会让首屏 **+708.5 KB**。
改成 rolldown 原生 `codeSplitting.groups` 后，一切指标**不劣于** 7.3.7：

| 指标 | vite 7.3.7 | vite 8.3.5 | 差值 |
| --- | --- | --- | --- |
| `npm run build` 墙钟 | 47.5 s | **6.0 s** | −87% |
| 首屏静态闭包（JS + CSS） | 2441.0 KB（5 文件） | **2412.4 KB**（9 文件） | **−28.6 KB（−1.2%）** |
| └ JS | 1498.4 KB | 1471.3 KB | −27.1 KB |
| └ CSS | 942.6 KB | 941.0 KB | −1.6 KB |

| `vue-tsc --noEmit` | 0 错 | 0 错 | — |

## 关键发现：`manualChunks` 兼容垫片不能直接用

vite 8 会把 `build.rollupOptions.output.manualChunks` 翻译成 `codeSplitting.groups: [{ name(moduleId) {...} }]`
（见 rolldown 的 `OutputOptions.manualChunks` 文档注释），但**逐模块指派的语义没保住**：

| 现象（同一份源码，只换 vite） | 后果 |
| --- | --- |
| `element-plus` chunk 吸收 `lodash-es` 214 个模块 + vue 运行时（925.7 → 1125.7 KB，+21.6%） | 命名 chunk 语义漂移 |
| `\0vite/preload-helper.js` 被塞进 `markdown-stream`（instrument 过 `manualChunks`：函数**确实**被调用、返回 `'vendor'`，但产物仍在 markdown-stream） | **entry 静态依赖整个 932 KB 的 markdown-stream** ⇒ 首屏 2441.0 → **3149.5 KB（+708.5 KB）** |
| `vendor` 309.3 → 188.3 KB、`vue-vendor` 192.0 → 77.5 KB | 与上一条同源 |

根因是 rolldown 的 `includeDependenciesRecursively`（默认 true）：组捕获到模块时会**递归把它的依赖
一起带进来**——element-plus 组因此拖走了 lodash-es，preload helper 则被并进它最大的消费者。

## 改法：判据仍一处，翻译成原生分组

- `vite.config.ts` 里把原来的 `manualChunks(id)` 函数体原样提成 `chunkNameOf(id)`（判据没有第二份）；
- 用 `CHUNK_GROUPS = CHUNK_NAMES.map(name => ({ name, test: id => chunkNameOf(id) === name }))` 翻译成
  `build.rolldownOptions.output.codeSplitting.groups`，并显式 `includeDependenciesRecursively: false`
  （本仓的「独占依赖闭包」本来就是 `dependencyClosure()` 在构建期现算的，比递归捕获精确）；
- 关掉 `modulePreload`、`chunkSizeWarningLimit: 700` 两条历史约束原样保留。

## 验证

1. **分块完整性**：`dist` 里 176 个 JS / **1070 条 import 边**，逐条查目标文件 → **0 处悬空**（迁移后
   「引用了没产出的 chunk」是典型故障，这条是全量结构判据）。
2. **首屏不回归**：`dist/index.html` 的静态闭包 9 个文件里**没有** katex / mermaid / stream-diffs /
   markdown / markdown-stream —— 按需 peer 仍然只在用到时才下载（这是 `modulePreload:false` +
   分块策略共同保证的性质）。
3. **按需 chunk 真能加载**：在页面上下文里逐个 `import()` —— katex(3 exports) / mermaid(1) /
   stream-diffs(1) / markdown-stream(5) 全部成功解析。
4. **真浏览器（本机 Edge headless）**：构建产物 `vite preview` 起服务，`/` → 落到 `/login`，
   页面渲染出登录卡片（`.auth-page min-h-screen`），body 字体/背景取自设计 token，控制台**只有**
   两条 `/api` 502（本地没有后端，与构建无关），`requestfailed` 为空。截图 `built-app-entry.png`。
5. **A/B 像素比对**：同一份源码分别用 7.3.7 和 8.3.5 构建、同一浏览器同视口截同一页 ——
   **1440000 像素里 0 处不同（最大通道差 0）**，`diff bbox = None`。截图 `ab-vite7.png` / `ab-vite8.png`。
6. `npm run dev` 也验过：`/` 200、`/src/main.ts` 200（vditor 静态拷贝插件、tailwind 插件在新内核下都正常）。

## 复现

```powershell
node ../.scratch/entry-closure.mjs dist   # 首屏静态闭包（脚本是一次性的，逻辑见上）

```

## 回退

一个 commit：`git revert`。注意配置已改用 rolldown 的 `rolldownOptions`，vite 7 不认识这个键，
所以回退要连 `vite.config.ts` 一起退（不能只把 package.json 改回 7）。
