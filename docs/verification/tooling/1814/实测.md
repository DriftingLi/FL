# #1814 Pillow 10.4.0 → 13.0.0：实测

侧车（libreoffice-sidecar）唯一改动的运行时依赖。验证分三层：**宿主机 Python 的编码行为**、
**真镜像的构建**、**真容器上的两条 HTTP 腿**。

## 1. 编码行为：同输入两版逐字节可比

夹具：同一份合成图（640×480 / 800×600 渐变），分别灌进 `image_bytes_to_webp` 与 `png_to_webp_bytes`。

| 用例 | Pillow 10.4.0 输出 | Pillow 13.0.0 输出 | 判定 |
| --- | --- | --- | --- |
| PNG(RGB) → WebP | 5282 B | 5282 B | 等长 |
| JPEG(RGB) → WebP | 5528 B | 5528 B | 等长 |
| PNG(RGBA) → WebP | 5282 B | 5282 B | 等长 |
| WebP(源) → WebP | 5386 B | 5386 B | 等长 |
| `png_to_webp_bytes` | 5282 B | 5282 B | 等长 |
| GIF → | `SKIP`（原样返回） | `SKIP` | 同 |
| 调色板 PNG → | `ORIGINAL`（压缩后变大回退） | `ORIGINAL` | 同 |

两版解回的 WebP 都是 `format=WEBP, mode=RGB`，尺寸不变。⇒ 编码器与三条分支（WEBP / ORIGINAL / SKIP）行为一致。

## 2. 镜像构建

```
docker build -t fl-sidecar-p13:test libreoffice-sidecar   → 成功
in-container: Pillow 13.0.0 / Python 3.12.15
```

关键前提：alpine 镜像里**没有编译器**（只装了 libreoffice / poppler-utils / font-noto-cjk），
所以必须命中 musl wheel。命中的是 `pillow-13.0.0-cp312-cp312-musllinux_1_2_x86_64.whl`（PyPI 元数据可见，
构建日志里 pip 直接落 wheel，没有触发源码编译）。

## 3. 真容器 HTTP 冒烟（`docker run -p 18099:8000`）

| 请求 | 结果 |
| --- | --- |
| `GET /health` | `{"status":"ok"}` |
| `POST /convert-image` PNG(RGB) 640×480 | `200` / `status=WEBP` / 3252 B / 解回 WEBP RGB 640×480 |
| `POST /convert-image` JPEG 640×480 | `200` / `status=WEBP` / 3590 B |
| `POST /convert-image` PNG(RGBA) | `200` / `status=WEBP` / 3252 B |
| `POST /convert-image` GIF | `200` / `status=SKIP` |
| `POST /convert` 2 页 PPTX（`chapter_id=999999`） | `200` / `success=true` / `slide_001.webp` 18708 B、`slide_002.webp` 18964 B，均 1500×1125 可解码 |

`/convert` 这条腿把 LibreOffice → PDF → PNG → **Pillow** → WebP 全串起来跑了一遍，
覆盖的是 `png_to_webp_bytes`（第 1 节里只单测了函数，这里补端到端）。

## 复现命令

```powershell
docker build -t fl-sidecar-p13:test libreoffice-sidecar
docker run -d --name sidecar-p13 -p 18099:8000 fl-sidecar-p13:test
# /health、/convert-image、/convert 见上表
docker rm -f sidecar-p13
```
