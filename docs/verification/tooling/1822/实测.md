# #1822 mermaid 11 → 12 评估实测

结论：**可以升**。渲染三种图 × 两套主题都对，代价是**按需 chunk 变大**（下表），首屏不受影响。

## 渲染验证（真链路）

夹具：本机 dev server 挂**真实**渲染路径 —— `utils/markstreamRuntime` 的 `setupMarkstreamRuntime()`（`enableMermaid(() => import('mermaid'))`）
+ `markstream-vue` 的 `<MarkdownRender mode="chat" html-policy="escape" :mermaid-props="MARKSTREAM_MERMAID_PROPS">`，
正文是三块 ```mermaid：flowchart LR / sequenceDiagram / stateDiagram-v2。浏览器为本机 Edge（puppeteer-core），视口 1100×1400。

| 版本 | 主题 | 结果 |
| --- | --- | --- |
| mermaid 11.17.2（改前） | 浅色 / 深色 | 3 张图都出 SVG，无 pageerror / console.error |
| mermaid 12.2.0（成稿） | 浅色 / 深色 | 同上；`g.node`（flowchart）、`g.stateGroup`（state）、participant 文本（sequence）齐 |

两版截图见 `m11-light.png`（改前）与 `m12-light.png` / `m12-dark.png`（成稿）—— 结构一致，v12 的节点间距与配色略有不同（同一套 `isStrict` 输入）。

## chunk 体积（vite 构建，同一份源码只换 mermaid 版本）

| chunk | mermaid 11.17.2 | mermaid 12.2.0 | 差 |
| --- | --- | --- | --- |
| `mermaid-*.js` | 3,065.75 kB（gzip 830.95） | **4,847.16 kB（gzip 1,368.38）** | **+1.78 MB / +537 kB(gzip)，+58%** |
| `katex-*.js` | 557.73 kB | 295.33 kB | −262 kB（分块归属变化，见下） |
| `markdown-stream-*.js` | 960.37 kB | 960.37 kB | 0 |
| `stream-diffs-*.js` | 10,980.42 kB | 10,980.42 kB | 0 |
| `element-plus-*.js` | 947.89 kB | 947.89 kB | 0 |
| 全站预压总量 | 25,730 KB → 5,823 KB | 27,213 KB → 6,270 KB | +1.48 MB |

判读：

- **首屏零影响**：`mermaid` 仍是 `LAZY_PEERS` 的独立按需 chunk，只有页面真的出现 ```mermaid 才会被拉；
- `katex` 变小是**分块归属变化**（两个 peer 共享的那部分依赖在 12 里被独立成一份，落进了 mermaid chunk），
  不是体积净赚 —— 看总量更准：**+1.48 MB**；
- 增长与「新增图表类型」无关：两版都把 gitGraph/pie/journey/mindmap/sankey… 打进去了（chunk 里都能搜到），
  变大是 core 本身变大（v12 的 `dist/mermaid.core.mjs` 就是对外入口，没有更瘦的官方入口可选）。

## 决策

升。代价只在「真的要看图的页面」上，且 v11 落后一个大版本会让下一次跳跃更贵；若未来有「只注册三种图」的官方入口，再切过去瘦身。
