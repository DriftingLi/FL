# ADR-0062: 第十四波架构深化（幂等键含主体 / 权益读面 / 题库池上 scope / 「查不动≠查得空」/ 错误码翻转 / 装载流归位）

- 状态：已接受（2026-09-21，architecture review 10 candidates → 11 票；本轮按「真 bug 优先」口径扫描，每条候选都经主会话逐行读码复核，38 条原始命中里 27 条为误报、重复或已被 ADR-0060/0061 结清）｜领域：积分簿记 interface / 权益与可见性 / 题库池 / 定时守护 / 会话终止 / 端点错误面 / 装载流编排 / 契约可空性
- 拆票顺序：**A 批（后端止血，票 1-7、9）先合**、**B 批（契约与前端编排，票 2b、8、10、11）后合**。票 1 与票 2 是一对（同一症状的两个独立成因，只修一个仍是死的）。

## 背景

第十三波（ADR-0060）的贯穿形态是「骨架把职责让渡给 caller」，本波扫出来的东西比它更硬：**十条里有七条今天就在扣错钱、漏答案、锁死付费用户，或可以在一次 DB 抖动里删光在线文件**。共同形状只有一个——**interface 少了一维**：幂等键少了主体、回收 provider 少了 error 出口、错误条目少了「解析错误除外」这一位、可见性判据少了共用形态。同一事实被 caller 各抄一遍 ⇒ 漏一处就是漏一条读路径。

决定时点的事实（逐条实测，非估计）：

- `points_entry_idem` 只有 `idem_key` 一列做主键（`migrations/000011:8`），而 `RedeemIdemKey(sku)="redeem:{sku}"` 不含主体 ⇒ 学员 A 兑 `course:5` 后，学员 B 的权益行插入成功、`ApplyTx` 撞占坑 ⇒ 整笔回滚 ⇒ 映射 `ErrAlreadyRedeemed`（`points_service.go:750/756`）。**每个 SKU 全平台只有第一个学员兑得到**，课程/真题卷/商城三胞胎共用这条管线。
- `ai_assistant.go:452` 的 requestID 取自 `X-Request-ID`，`middleware.go:37` 原样采信（缺省才生成 uuid）⇒ 客户端固定一个值，`DeductAI` 预检（`points_service.go:915`）第二次起命中并**返回成功 + 本次应扣的积分数字、零扣费**；跨用户撞键在 `:933` 被当成功咽下。实测 `DeductAI` 生产侧只有 `ai_meter.go:162` 一个调用点，前端与移动端都不发该头 ⇒ 改口零连带。
- `HasEntitlement` 的三个消费点全在真题卷域（`real_exam_service.go:95/109/154`）⇒ **课程兑换写下的权益没有任何读路径**，闸门只剩前端内存里那句 `points_price = null`（`CourseList.vue:462`）：刷新后又被拦「请先兑换」→ 再兑 400「已兑换」→ 付过分的课永久进不去；反面是后端对付费课程零门禁（`course_service.go:581` 原样回传价格、读面不查权益）。词表「积分商城」条写的却是「HasEntitlement 供各域门禁复用」——词表对、代码漏。
- 题库池有一份单点（`question_pool_scope.go:22-38`）但只被三条读路径引用：`GET /api/question-bank/questions` 组级只有 `JWTAuth`（`api/question_bank.go:77-80`）、`status` 不传即全量、出口 `newQuestionDTO(..., true)` 带答案/解析/评分标准（`question_service.go:654-684` + `question_dto.go:55-60`）⇒ 学员 token 整库翻走 draft/pending/源标记真题题的答案。该端点**没有任何学员端消费者**（消费者只有 `admin/QuestionReview`、`tutor/QuestionManage`、`tutor/QuestionTags`），而 by-id 那条**有**（`QuestionDetail.vue:162`，故 #981 的按能力分流必要）——两半不同源正是全部原因。同族漏口另有四处：笔记写读（`note_service.go:111` + `:221-224` 的 `LEFT JOIN question`）、评论（`question_interaction_service.go:46-62` 连题目存在性都不查）、收藏写面（`favorite_service.go:94-99` 只判 published，紧邻注释自陈课程/章节「不在此手拼谓词」）、`POST /chapter/:id/slides/regenerate`（`course_service.go:326` 不做 `CourseVisibleByID`，同函数 GET 半边 `:301` 有）。
- `runOrphanSweep` 对 `list` 失败刻意整轮放弃（`orphan_sweep.go:44-50`，注释「避免误判」），但 `referenced func() map[string]bool` 没有 error 槽 ⇒ 两次 `Pluck(...).Error; err == nil`（`forum_image_service.go:92,104`、`contribution_service.go:230`）任一失败即空引用集 ⇒ **删光所有超 24h 的论坛图片与投稿文件**。同一形状另有四处已核实：`job_posting_service.go:353-356`（查失败 ⇒ 全部职位报「可投递」，点了才 400）、`practice_mode_service.go:467`（签名无 error ⇒ 数据报告页一半 500、一半「0 题」）、`question_interaction.go:190`（error 丢给 `_` 后照样 200）、`training_catalog_service.go:226`（`err == nil` 才排除 ⇒ 真题标签漏过滤）。
- `code_service.go:678` 的验证码重置口令直写 `password`、不吊销；而 `auth_service.go:273-280`（改密）与 `:536-554`（禁用）都走 `RevokeIdentity` ⇒ 被盗号者最典型的场景（用户改密码自救）下，攻击者手上 refresh 仍可静默续登最长 7 天。
- `WithSuccess(ok, 500)` 装的 `errStatusAll` 只有一条 `sentinel: nil` 条目，按 `endpoint.go:218-220` 自陈**必然抢在 `*ParseError` 之前** ⇒ 20 处端点把 400 类输入错误答成 500（`api/contribution.go:205-224` 连自己的 `@Failure 400` 注解都违反）；`errstatus_test.go:130-140` 把该顺序当既有字节行为钉住了。`real_exam.go:103/124/145` 用 `errStatusAll(404)` 把 `ErrInsufficientPoints`/`ErrAlreadyRedeemed` 全答 404，而同仓 `points.go:19-32` 对同一批哨兵回 400（同域同判破了）⇒ 前端只能 `msg.includes('已兑换')` 猜语义（`RealExamPapers.vue:149`，ADR-0024 禁的字符串比对搬到消费侧）并据此弹「已解锁本卷」**成功**提示。`settings.go:147` 的 `errStatusAllPrefix(500,"更新失败: ")` 配 `ai_config_service.go:210` 裸 `gorm.ErrRecordNotFound` ⇒ 界面出现 `更新失败: record not found`。
- 追加式分页（票4 建的机器）无批次令牌：`useAsyncPage.ts:237-244` await 后无条件 append 并回写 `page` ⇒ `ChapterDiscussion.vue:59-69` 在「加载更多」飞行中切帖时，旧帖第 2 批写进新帖已清空的列表；`ChapterView.vue:199` 在 `onMounted` 的并发流里同步读 `chapterStateMap` ⇒ 断点续播位置多半读成 0（词表「学习位置」承诺失效）。`filterDeps`（`useAsyncPage.ts:85`）已是「筛选轴失效刷新」的 seam，但 7 个引用当前证件的文件里只有 2 个真在 `watch` 里重装；`PointsLedger.vue:48` 是全站唯一拿 `handlePageChange()` 处理筛选变化的页面 ⇒ 非首页切筛选就是假空态。
- `contact_authz.go` 的存活判据只有学员侧（`studentAccountAlive`），学员看企业那条走零查询的行级 `GrantsPlaintext()` ⇒ 企业被禁用（`ToggleRecruiterStatus`，正是处置动作、并吊销其全部会话）后，已授权学员仍见其电话/邮箱/微信明文。
- 论坛 `images` 经 `parseImageURLs` 可出 `null`，生成物却承诺 `string[]`（`generated/forum.ts:74/116/152`），今天只靠两处页面手抄 `|| []`/`&&` 存活；AI 域同形已补标 ⇒ 一仓两套口径。

## 决策

1. **幂等键必须含主体，形状照先例**：`redeem:{sku}:{userID}`、`ai_tokens:{userID}:{requestID}`（`checkin:{uid}:{date}` 早就是这个形状）。**不动表结构、不加迁移**——老键失配的兼顾由 redeem 面的权益预检兜住；AI 面登记为有意的语义断点。**否**「主体升为 `points_entry_idem` 主键列」：那要把六个键族逐条重判「这坑是不是 per-user」（回收族 `rollback:{topicID}` 是跨多用户共用一坑，`points_service.go:690` 只给 `i==0` 传键），不是本波的量。
2. **requestID 由服务端铸造，闸门不信任 caller**：计费路径不再采信 `X-Request-ID`（该头可继续只用于日志回显）。口径从「同请求重试/重放只扣一次」改述为「**一次服务端请求只扣一次**」，与「一次请求 = 一次用户可见消费」同源。
3. **权益是独立事实，既不进可见性也不进前端内存**：新增具名合成判据「**学员可读 = 可见性 ∧ 权益**」（权益事实仍住积分域，课程域只作 consumer）；照真题卷两件套——列表/详情下发 `entitled` 槽，内容读面（章节详情 / slides / 进度写）未兑换即 404（越权按不存在，不泄漏存在性）。**不给存量豁免**（与 ADR-0051 不回改历史归属不冲突：那是数据归属，这是门禁）。`RedeemShop` 为 `unlock_real_paper` 写的权益行按同一条读面结清。
4. **可见性判据装进必传 scope 值对象**：题目与课程两域的学员读面必须收一个由入口装配的 `questionReadScope`/`courseReadScope`（能力派生的可见性谓词 + 当前证件分区）⇒ 新读面「忘过池」在类型上过不去（票1b「类型层就是那道锁」同形）。**权益不进 scope**（只对付费内容存在，塞进去会让笔记/评论 caller 背上空槽）。管理专用端点 `/question-bank/questions` 与 `slides/regenerate` 补能力守卫（学员零消费者）。
5. **授权覆盖从文本锁升级为 deny-by-default 行为台账**：拿学员 token 打 swagger 全量路径，凡 2xx 者逐条登记「学员可读面」白名单并写理由。理由：ADR-0047 §1 选文本锁的原始理由（gin 不暴露中间件链）仍然成立，而台账绕开它且断言行为；**否**「重造 20+ 蓝图的路由声明表驱动注册」（量级不是本波的）。
6. **「查不动」不得被读成「查得空」**：`referenced()` 加 error 出口；部分失败（topics 成功、replies 失败）**整轮放弃**（引用集不完整等于不知道谁在引用，删就是赌）；另加与查询成败无关的兜底闸——`stored 非空 ∧ referenced 为空` 即放弃并记 error。同判据覆盖上述四处（`fillApplyStates`/`GetStats`/knowledge 读面/目录标签），要么带 error 要么显式声明有意吞并写原因。
7. **两条口令写面合成「落新口令」，重置口令入尽力而为族**：共享 6-20 位校验 + 哈希 + 落库 + `RevokeIdentity`，失败策略由调用方声明（与注销族「先标记后删」保持有意不同——口令一落库即不可回退，与改密同构）。入口差异（登录态 vs 验证码）留在 handler。
8. **`*ParseError` 恒优先于无条件条目**：翻转 `renderError` 规则序并改 `errstatus_test.go` 的钉法；`WithSuccess` 第二参语义收窄为「成功文案 + 默认错误面」。**不预设「连解析错误也同码」的逃生槽**（一个 adapter = 假想 seam，真出现再加）。同票：`real_exam` 兑换面复用 `pointsErrStatus`（同域同判），前端删掉文案嗅探；`ai_config` 的 `RowsAffected==0` 改回具名哨兵（驱动原文不再进界面）。
9. **授权有效态双向对称**：词表从「双方账号均未注销」升为「**均有效（未注销且未被禁用）**」，两侧共用同一条存活谓词；**授权存在 ≠ 授权可用**——徽章仍按授权事实投影，可用性呈现在明文位置（企业已停用的具名说明）。
10. **装载流归位到 composable**：`run`/`reset` 递增 generation、`loadMore` 发起时捕获落地前比对（不等即丢批且不回写 `page`/`total`/`hasMore`）；新增 facet 声明槽（与列表共享同一批失效时机：筛选变化 / 切证件 / reset）。**否** AbortSignal（要改 loader 签名与 `client.ts` 透传，非本波量）与「页面各自加 request-id 守卫」（正是本波根因形状）。
11. **学习位置由后端下发**：`GET /course/:id/chapter/:id` 加 `resume_position`（按 (user, chapter) join `study_record`，词表「学习位置」的既有事实源）⇒ 前端不再跨两个端点拼位置；`chapterStateMap` 保留喂列表完成态（那部分无先后假设）。**否**「前端串行 await 两条流」（只消时机假设、不消拼装）。
12. **数组契约出口归一空数组**：`images` 无图即 `[]`，删两处页面手抄；加锁「DTO 的切片字段要么出口归一、要么显式标 `x-nullable`，禁止默认 nil」。**否**「只补 `x-nullable`」（把可空性推给每个 caller，且「无图」与「数据缺失」在本域是同一件事）。`null → []` 属跨端字节变，落地前按惯例与移动端对一次判空方式（本波不读那侧）。

## 理由

十二条同为「把 interface 少掉的那一维补回去」。deletion test 逐条过：删掉「caller 记得带 uid」「caller 记得过池」「caller 记得先 await 哪条流」这三处隐含约定后，复杂度**集中**进键构造器、scope 值对象与 generation，而不是散到更多调用点。判据宿主从注释与巧合升级为类型与锁——票4 的 append 档已经证明过一次：判据一旦有了具名入口，前后端批次大小常量耦合那种东西会自动消失。三处「本波不做」的理由都同一把尺：主体入主键要重判六族（范围变更）、路由声明表驱动注册要重造 20+ 蓝图、AbortSignal 要重开 loader 契约——都不是顺手能完的量，硬塞只会让本波的锁写不实。

## 被否备选

幂等主体升为表列（要把六个键族逐条重判是否 per-user，回收族跨多用户共用一坑）；新键与老键共存逐票淘汰（键规则出现两份，与 `points_idem_keys.go` 顶注的「格式单点 + 快照锁」相冲）；已兑换者的 `points_price` 出口抹 null（把判据塞进字段值，语义由巧合承担）；权益并进 `CourseVisibleByID`（该谓词有四个无主体的共用 caller）；只封端点入口 + 静态扫描题目读面（断言源码文本，ADR-0061 §1 已给否理由）；保留错误表现序另加 `Except-Parse` 槽（让默认那一侧继续是错的一侧）；重置口令走强一致族「先吊销后落口令」（Redis 抖动时用户找不回账号，且与同族改密裂成两种失败策略）；页面各自加并发守卫；facet 另立独立小 module（与 `useAsyncPage` 重叠一个「失效时机」概念，两个抽象谁持有需再裁一次）；企业禁用只当「不能登录」不看联系面（处置不延伸到联系面即留空洞）。

## 锁

- 键格式：`points_idem_keys_test.go` 快照改期望值 + 新增「两个学员兑同一 SKU 都成功」「同一固定 `X-Request-ID` 不扣第二次费」两例。
- 可见性：`questionReadScope` 必传即编译期锁；deny-by-default 台账（学员 token 打全量 swagger，2xx 者须在白名单内逐条带理由）；「学员读题目/课程不得手拼池与挂载谓词」的静态扫描作第二道（改名即绕过，故只当补强不当主锁）。
- 守护：`orphan_sweep` 契约测试注入失败 provider ⇒ 断言零删除；「空引用集 + 非空 stored ⇒ 本轮不清理」单独一例。贯穿判据那条：`GetStats`/`fillApplyStates` 等四处各自的「查询失败 ⇒ 错误如实上抛」用例（照 ADR-0061 的教训——只有直接问那个函数才能红）。
- 会话：重置口令后「旧 refresh 轮换即 401」一例，与 ADR-0060 票2 的「吊销标记写失败 ⇒ 账号仍在」并列（两族失败策略不许互相顶替）。
- 错误面：`errstatus_test.go` 改钉「`*ParseError` 恒优先」；新增锁——端点 `ErrStatus` 可能返回的状态码集合不得与自身 `@Failure` 注解矛盾（CI 现在只锁 swagger 新鲜度，两件事没人对账）。
- 前端：generation 令牌用例（append 飞行中 reset ⇒ 旧批不落地、`page` 不被回写）；「筛选项变化不得直调 `handlePageChange`」的机检；facet 声明槽使用后 `pages/` 不得再出现只挂在 `onMounted` 上的证件相关装载流。
- 契约：`entitled` / `resume_position` / `images:[]` 三处走 codegen + 跨端差异清单回写移动端；`images` 出口归一后，`pages/` 与 `components/` 的手写 `|| []` 判空由守卫点名清掉。

## 实施回记（落地时逐条实测；未回记前本段为空，后续会话不要按上文计数行事）

- **票2/票3 的一处前提被实测推翻**：`POST /chapter/:id/slides/regenerate` 的消费者**是学员**
  （`frontend/src/components/student/PptViewer.vue:186` 的刷新按钮），不是管理动作 ⇒ 扫描期
  提的「给它挂能力守卫」会直接打断学员。正解是接上与 GET 半边同一条具名可读性判据
  （`studentCanReadChapter` = 可见性 ∧ 权益）。票3 的题目面守卫仍按原案。
- **票8 的一个实例（落地票9 时撞上）**：`PUT /admin/ai-configs/:id` 的 body 校验失败
  （`binding:"required"`）今天返回 **500**「更新失败: 请求参数错误: Key: 'BaseURL' …」——
  即 `errStatusAllPrefix` 那条 `sentinel: nil` 条目把 `*ParseError` 自带的 400 咽掉了。
  这不是推测：删掉 `base_url` 打这条端点即可复现。票8 翻转规则序后归位。
- **票2 的传播链有一处已知残留**：`GET /course/:id/chapter/:id` 与 slides 两端挂的是
  `WithSuccess(ok, 404)`，所以 `studentCanReadChapter` 如实上抛的 DB 错误也被答成 404
  （而非 500）。判据本身正确，状态码待票8 归位。
