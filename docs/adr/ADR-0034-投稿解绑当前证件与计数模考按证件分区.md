# 投稿目标证件解绑当前证件、计数口径收敛当前证件、模考按证件分区

背景：投稿创建时强制「投稿证件必须等于当前证件」——投稿是供给侧写入，却被浏览侧的全局过滤器绑死，想给别的证件供稿要来回切换当前证件。与此同时，课程目录树与标签列表的计数走全局口径（目录树请求无参数导致拦截器注入被跳过、标签计数无证件参数），与按当前证件过滤的课程列表 / 抽题池对不上；模考抽题完全不分区，且开始考试链路藏三处缺陷（空卷进卷渲染空壳、倒计时因挂载顺序恒不启动、题量时长字段错位被吞）。

决定：投稿写入解绑当前证件——表单加目标证件选择器（默认当前证件），后端放宽为「投稿者须已选定当前证件（资格门槛保留）＋目标证件有效存在」，列表仍按当前证件过滤（投到别的证件需提示切过去可见），配额仍按用户全局计；课程目录树与标签列表计数收敛到与列表 / 抽题一致（按当前证件分区：目录树课程查询加证件过滤、标签 published 计数叠加题库池三元组，请求侧带空参数对象让拦截器注入生效）；模考开始经查询参数透传证件分区抽题，并一并修复空卷不进卷、先切卷面再起倒计时、兼容前端题量时长键三处。

理由与权衡：读侧（列表/抽题/计数）统一按当前证件过滤是既有约定，计数是读侧，应收敛；写侧（投稿创建）绑死当前证件没有域理由，解绑后跨证件供稿一次完成，代价是审核队列出现非当前证件的稿（审核本就跨证件工作，无影响）与词汇表投稿条目改一句。否决项：投稿列表跨证件聚合（破坏全局过滤器心智）；配额按证件拆分（背压对象是用户刷量行为，与证件无关）；真题卷改动（仅随机模考收敛分区）。
