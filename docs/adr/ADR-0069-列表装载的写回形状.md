# ADR-0069: 列表装载的写回形状——loader 只取数，写回由代数校验后调用（修订 ADR-0060 §4）

- 状态：已接受（2026-09-28，真实缺陷评审 grilling 定案；全量迁移 44 个调用点 / 43 文件）
- 领域：前端 —— 列表装载 / 分页状态机（`useAsyncPage`）
- 修订：ADR-0060 §4（append 判据换服务端事实）所在的编排面

## 背景

`useAsyncPage` 的 replace（默认）档要求 loader「自己取数 + 自己写回页面 ref」，而批次代数守卫 `if (gen !== generation) return` 位于 `await load(page)` **之后**——旧轮的数据在守卫看到之前就已落地。于是连点分页 / 快切筛选 / 切当前证件时，后到的旧响应覆盖新状态（页码第 3 页、内容是第 1 页）。仓库自带的代数用例全部是 append 档，replace 档零覆盖。

同一机制还有一处变体：`ChapterDiscussion` 的 `expandedTopic/detailContent` 在 loader 内写回，切帖时出现「面板 B 显示帖子 A 的正文与作者判据，replies 却是 B 的」。

## 决策

1. **loader 只取数**：`useAsyncPage` 新增 `apply` 槽（与 append 档已有的 `pickItems` 对称），页面在 `apply` 里写回自己的 ref；`run()` 在 `gen === generation` 校验通过后才调用它——写回判据从 43 个消费面收回一处。
2. **全量迁移**：44 个调用点 / 43 个文件一次迁完，不留存量名单；append 档的 `pickItems` 不变。
3. **两条锁**：① 行为锁——replace 档三条轴（翻页 / 筛选 / 切证件）各一例，断言旧轮被整体作废；② 结构锁——守卫扫源码，禁止 `useAsyncPage` 的 loader 参数体内出现页面 ref 写回（存量清零后零豁免执法）。
4. **切目标也是代数事件**：`ChapterDiscussion` 的切换走 `reset()`（推进代数），故其写回并入 `apply` 后串帖在机制上不可能；另补一条「展开 A 后立刻展开 B，面板只显示 B」的用例。

## 被否备选

- **只修点名处、不建槽**：机制没变，下一个新页面照抄即复发。
- **逐页自持 gen**：等价改动，但判据仍在 43 个消费面各写一遍——正是本 module 当初要收编的东西。
- **不迁存量、建名单 + 守卫禁新增**：暴露面收敛但不归零；本次选择一次收口。
- **只加行为锁不加结构锁**：写回一旦回到 loader 内，单页层面的行为锁测不到。

## 实施回写（2026-09-28，随 P1 修复批）

- **迁移面（44 个调用点 / 43 个文件）**：38 处的写回直接住在 loader 体内，机械搬进 `apply`（AST 改形，不由正则切语句）；8 处是命名 loader / 表达式体 loader（本就要么只取数、要么手改）。
- **`apply` 的执行时机**：`run` 与 `loadMore` **都**在 `gen === generation` 校验通过之后调用它（append 档同理）——「写回只有一处」这句话才成立；否则 append 档的 loader 仍得住着写回。`apply` 入参就是 loader 的返回值。
- **泛型化 loader 返回类型**：`useAsyncPage<T>`（`apply?: (res: T) => void`），43 处调用点因此不必各自 `as` 断言。副作用一个坑：loader 里读解构出来的 `page`/`pageSize` 时，`T` 的推导与解构类型互为因果，TS 判「自引用」并把 `page` 退化成 `any`（TS7022）——在命中处显式写出 loader 的返回类型即可点破（本次 1 处）。
- **顺序即语义（迁移中最容易错的形态）**：写回搬进 `apply` 后，loader 里对「被写回 ref」的**读**会读到旧值。实测命中并修正两处：`ChapterView` 的 `latestVideoPosition = chapterVideoPosition.value`（学习计时基准）、`ResumeDetail` 的 `loadContact()`/`startApprovedPolling()`（分别读 `data.user_id` 与 `data.contact_state`）——后者的顺序错由既有的 `ResumeDetail.spec.ts` 直接抓红。迁移后另按调用图（loader 调的本页函数体内是否读被写回的 ref）全量体检一遍，其余 0 命中。
- **一处「取数不是写回」的判别**：`MyApplications` 的次级取数流（翻页拉全量已授权联系方式）留在 loader 并随响应回传 `{ res, approved }`，**没有**搬进 `apply` —— 它是取数，搬进去反而绕过代数守卫（旧轮的联系方式会落进新页）。
- **一次装载写两个面的三处**：`ForumPage`（主题 / 我的回复按 Tab 二选一）、`SearchPage`（聚合 / 分页分档）、`ChapterDiscussion`（append 档第 1 批才写面板头部）——loader 回传带标记的载荷（`{ target }` / `{ mode }` / `{ ...res, firstBatch }`），`apply` 按标记分派；`ChapterDiscussion` 用展开保留 `replies`/`pages`/`total`，故 `pickItems` 与分页信封判据不受影响。
- **两条锁的落地**：① 行为锁在 `useAsyncPage.spec.ts`（翻页 / 筛选 / 切证件三条轴各一例，外加「写回留在 loader 里时旧轮照样覆盖」的反例自检）；② 结构锁在 `loadFlowLocks.spec.ts`：**R4** 用编译器 API 判「写页面 ref」（赋值 / 复合赋值 / `x.value[i] =` / 可变方法 `push·splice·sort·set…`），只读用法（`x.value.trim()`、条件里的 `x.value`）不算 —— 文本法会把 `activeType.value === …` 误判成写（实现时踩过），故按 AST 判写目标。存量清零、零豁免。
- **R4c 与三处登记（写回槽的入参来源）**：R4 看不见「loader 只调别人的写状态函数」这个形状，故补一条「loader 必须有带值 return」。存量剩三处，逐条登记理由而非普通豁免：`admin/CourseCatalog.vue`（委托 `useCourseCatalog.fetchCatalog()`，状态与 8 条用例都归该 module）、`student/Dashboard.vue`（三路 helper 中 `loadStudyStats` 归 `useRoleDashboard`）、`admin/ValuationConfigManage.vue`（装载器 `catch` 分支要清四份草稿「错误态与陈旧数据不同屏」，而 `apply` 只在成功路径被调用 ⇒ 需要先有一个错误出口槽）。锁里另带一条「登记表不得留死条目」的反向断言。
- **不在本 ADR 面上的同类**：`useAdminTable` 的 `load`（`await fetch` 之后直接写 `list`/`total`，无批次代数）形状同病，admin 面竞态窗口较窄，另立票。
