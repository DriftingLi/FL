# ADR-0027: 站内信事件构造器全域收编与悬空回收 sweep 合并

- 状态：已接受（2026-09-04，architecture review 6 candidates + grilling 逐一定案；代码待实施）
- 领域：站内信通知域 / 存储悬空回收 / model 组织 / clock 域 / 招聘投递授权 / 前端路由契约

## 背景

本轮架构评审（2026-09-04，热点驱动：contribution / recruiting / points / forum 四域 + 前后端接线层，近三个月 router.go×42 · models.go×38 · deps.go×26 · router/index.ts×55 · navigation.ts×40）产出 6 个 deepening candidates，经 grilling 逐一定案。评审报告为临时件（`.scratch/architecture-review-20260904.html`，不入库）。

## 决策

### C1 站内信事件构造器全域收编（Strong）

ADR-0024 C3 只落地了问答采纳试点；其后新落地的投稿域又手拼 4 处，全仓共 10 处调用点手拼 title/content/link/payload。本轮**10 处全部收编**（论坛 5 + 投稿 4 + contact 1）：

- **形状**：统一为 ForumAcceptEvent 已验证的形状——事件 struct + `New*Event` 构造函数 + 域内写入方法；`ProfileReviewNotification` 的四元组旧形态一并对齐，站内信域只剩一种形状。payload marshal 随事件归位站内信域（`contributionPayload` 从投稿域搬迁）。
- **错误语义两族**：与业务写同事务的强一致用 `Create*Event(tx, …)` 返回 error（失败回滚）；尽力而为用 `TryCreate*Event(…)` 内部吞错记日志（删帖/删回复/举报处理/contact 申请通知）。调用方一行触发，尽力而为的日志口径同时单点化，不再在 4 处重复 `if err != nil { logger.Warn }`。

### C2 悬空文件回收 sweep 合并 + 时间戳归位（Strong）

论坛图片与投稿文件两份 ~100 行同算法复制（sweep 循环 + key 提取 + 文件名时间戳正则）。本轮合并为 service 层单点 sweep module，两个业务域各自只剩「prefix + 引用集 provider + TTL」薄配置。

**时间戳知识归位 storage seam**：`Storage` interface 新增 `ListWithInfo(prefix)` 返回 `{URL, LastModified}`（local 走 ModTime、R2 走 S3 ListObjectsV2 原生 LastModified，两者皆原生能力）；两套文件名时间戳正则（`forumFileTimestamp` / `contributionFileTimestamp`）删除——存储产物文件名内嵌时间戳不再被消费者反向解析。

### C3 model 单体文件按域拆分

models.go（877 行 / 62 struct / 30 个分区注释，编号已漂移）按 CONTEXT.md 领域词汇表拆约 10 个文件（account / training / forum / recruiting / points / contribution / notification+audit / ai / misc 共用件）。同 package 纯文件搬移，零 import 变更、零语义变更。

### C4 自然日边界收编 clock 域

「Asia/Shanghai 自然日」两种消费形态共 13 处手写：`time.Date(y,m,d,0,0,0,0,loc)` 起点 ×9、`Format("2006-01-02")` 日期字符串 ×4。clock 包新增 `DayStart(t) time.Time` 与 `DayKey(t) string` 双函数，13 处全收。

**不做**大而全的 quota module：各限额的窗口列与谓词不同（created_at / check_date / claim_date），one adapter = hypothetical seam，不预造 seam。

### C5 投递侧授权状态迁移收口

`JobApplicationService.Apply` 事务闭包内手写 ContactRequest 三段状态迁移（pending 覆盖 / 新建 approved / revoked 复活）。本轮收口：`ContactService` 新增事务内 `EnsureApproved(tx, recruiterID, studentUserID, message, now)` **单方法收三分支**，投递侧一行声明意图，授权状态机知识收回 contact 域。与 ADR-0025「投递即授权、同一事务」决策兼容——只改实现形状，不改域决策。

### C6 前端 RouteName as const 常量表

路由与导航双写（router/index.ts 55 次变更 × navigation.ts 40 次）靠裸字符串手工同步。新建 routeNames.ts 手写 `as const` 常量表（约 55 个路由名）：routes 的 `name` 与 navigation 的 `routeName` 都引用它，`NavItem.routeName` 类型改为常量值 union。改错名/改漏名立即编译报错，双写被同一事实源收紧。

## 约束

- C1 既有通知的 title/content/link/payload **逐字零漂移**（含 `?tab=contribution` 与 `?tab=contribution&view=mine` 两种 link 变体的现状保留）；强一致/尽力而为的划分按现状语义对号，不趁机改行为。
- C2 sweep 行为口径不变：24h TTL、差集判定、ctx 取消贯穿、存储错误不中断（ADR-0026 的扫描口径约束继续生效）。
- C3 拆分是纯搬移：不趁机重命名字段、不调整 struct 归属。
- C4 行为等价替换：DayStart/DayKey 与既有 13 处手写逐字等价（含 Asia/Shanghai 口径）。
- C5 EnsureApproved 行为零漂移：三分支迁移、ExpiresAt 写法、事务边界均保持现状。
- C6 路由名字符串值不变，仅类型收紧；navigation 结构（分组/图标/activeRouteNames）不动。
- valuation 域本轮继续冻结不触碰（R2）。

## 执行

建议 5 个 PR（按栈与耦合切分）：C3+C4 合一（均为机械搬移/等价替换，先行为 C1/C5 铺路）→ C1（站内信域）→ C2（storage interface + 两域薄化）→ C5（contact 域收口）→ C6（前端）。每个 PR 走分支 + CI 门禁（后端 gofmt / vet / golangci-lint / test；前端 type-check / vitest）。

## 后果

- 站内信通知口径（文案/link/payload 契约）改动单点生效；新业务事件 = 一个 constructor + 调用点一行；前端确定性消费的 payload 契约有单点测试面。
- 悬空回收 bug 修一次两域全好；存储文件名约定变更只动 FileStore 一处，不再泄漏进消费者。
- model 域内变更不再跨域制造合并冲突；AI 导航按文件名直达域。
- 时区口径 bug 修一次 13 处全好。
- 授权状态机演化不再要求读投递域代码。
- 路由改名断链从静默运行时错误变为编译期错误。
