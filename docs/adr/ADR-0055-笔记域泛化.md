# ADR-0055: 笔记域泛化——题目笔记与独立笔记合一

- 状态：已接受（2026-09-17，grilling 定案）
- 领域：题库与练习 —— 学员笔记（note）

## 背景

笔记原先只有「每题一条」一种形态：`question_note` 表 + `GET/PUT/DELETE /api/questions/:id/note`，**没有「列出我的全部笔记」的接口**——学员在题目里记下的东西散落各处、离开练习流就再也看不到。同时完全没有「与题目无关的笔记」这个能力。（证据索引：`docs/plans/学员端四项体验升级-方案.md` §2.4，**本地不入库**，同 ADR-0049 先例。）

关键事实：这两种笔记是**同一概念的两个形态**——都是学员的私有文字，区别只在「有没有挂在一道题上」。另有一条 Postgres 语义让「合一」变得便宜：**唯一索引里 NULL 互不冲突**，因此 `UNIQUE(question_id, user_id)` 一条索引同时表达「每题一条」（非空时）与「独立笔记可多条」（为空时）。

## 决策

### 1. 一张 `note` 表两形态

`question_note` 重命名为 `note`（表 / 主键 / 唯一约束 / 两条外键 / 索引**一并更名**——名字不说谎：更名后表里会躺着 `question_id` 为空的行），`question_id` 放开为可空（NULL = 独立笔记）。`UNIQUE(question_id, user_id)` **保留不动**。新增 `(user_id, updated_at DESC)` 索引服务列表倒序分页。

Go 面同步改名：`model.QuestionNote` → `model.Note`（`QuestionID` 由 `int` 变 `*int`——用指针而非零值哨兵：题目 id 从 1 起，拿 0 表达「不挂题」会把「没挂」和「挂了不存在的题」混成一谈），`QuestionNoteService` → `NoteService`（它同时服务两种笔记，旧名会说谎），并迁到独立文件 `note_service.go`。

### 2. 两条写入路径，契约各自成立

- **题目维度**：`GET/PUT/DELETE /api/questions/:id/note` **请求/响应契约逐字不变**（题目详情 / 题库练习 / 真题练习 / 错题本重做结果区都在消费），它只是换了底表。
- **笔记维度**：新增 `GET /api/notes`（`scope=all|question|standalone` + 分页，按 `updated_at` 倒序）、`POST /api/notes`（新建独立笔记）、`PUT|DELETE /api/notes/:id`（只认本人）。列表用**一次 LEFT JOIN** 带回题干摘要（禁 N+1），供卡片显示「这条笔记挂在哪道题上」与跳题。

### 3. 字段与形态：与题目笔记同构

**不加 `title` 列**——列表用**正文首行当标题** + 摘要 + 更新时间；编辑器与既有 `NoteCard` 同构（纯文本、2000 字节上限、原样换行）。首行即标题是笔记类产品的通行做法，零额外字段，也避免「改了正文但标题没改」的不一致。

### 4. 门禁：两条路径都只要求登录，不挂能力点

笔记是**纯用户私有数据**：读写一律以 `user_id` 收口，越权访问按「不存在」处理（同一哨兵 `ErrNoteNotFound`，不区分「没有」与「不是你的」，不泄漏存在性）。既有 `/api/questions/:id/note` 本就没有能力位；给同一资源的两条路径挂两套门才是真正的不一致。该决定登记在端点授权覆盖锁的豁免清单里（`authz_coverage_lock_test.go` 的 `allow`）——**要么有守卫，要么有一次被 review 看见的豁免决定**。

## 被否选项

- **只把 `question_note.question_id` 放开为可空、保留表名**：迁移最小（一句 `DROP NOT NULL`），但表名从此说谎——里面会躺着大量与题目无关的行。
- **两张表 `question_note` + `user_note`**：职责最清晰，但「我的笔记」的排序 / 分页 / 计数要么做两次、要么在应用层合并，未来加「置顶 / 标签」这类通用能力还要写两遍。
- **独立笔记加可选 `title` 列**：列表更好扫，但同一张表里一半的行不用这个列。
- **笔记升级为 Markdown**：能排版，但两种笔记的编辑器从此分裂，还要把内容渲染的转义 / 白名单口径（ADR-0046）引进笔记域。

## 后果

- `question_note` 的所有外部行为保持：迁移只改表名与列可空性，老端点的请求/响应形状不变（契约测试逐字断言）。
- **回滚会丢弃独立笔记**（`down` 里必须 `DELETE FROM note WHERE question_id IS NULL` 才能把 `NOT NULL` 加回去）——已在迁移注释里写明。
- 正文长度上限**沿用字节口径**（`len(content) > 2000`，中文一字三字节）：这是历史语义，不是本次议题；文案「不能超过2000字」与实现的口径差记在此处，留待单独一拍。
- 新增契约域 `note`（`apitypes/domains.go`）→ 生成 `frontend/src/api/generated/note.ts`；路由总数基线 315 → 319。
- 移动端 `pages/profile/profile.uvue` 的 `notebook` 占位与 `practice-do` 之外的笔记入口另开 issue 交 @zhengcookie（#1082）。
