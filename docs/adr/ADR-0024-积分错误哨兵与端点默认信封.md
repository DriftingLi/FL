# ADR-0024: 架构评审定案——积分错误哨兵 / 端点默认信封 / 站内信事件构造器 / useAsyncPage 收编

- 状态：已接受（2026-08-31，architecture review 4 candidates + grilling 逐一定案；代码分 4 个 PR 待实施）
- 领域：积分域错误契约 / Endpoint 骨架 / 站内信 / 前端列表页状态机

## 背景

本轮架构评审以近期 commit 热点（积分域 #354/#355/#361、学员端重构、论坛招聘链路 #381、答题域深化 #391）划定扫描范围，产出 4 个 deepening candidates，经 grilling 逐一定案。评审报告为临时件（`.scratch/architecture-review-20260831.html`，不入库）。

## 决策

### C1 积分域错误哨兵（Strong）

points_service.go 的 17 处 `errors.New("中文")` 全量收编为域内哨兵，一语义一哨兵：

- `ErrAlreadyClaimed`（终身已领）/ `ErrDailyClaimLimit`（今日已领）——两语义分开，前端提示不丢
- `ErrAlreadyRedeemed`（已兑换，service 内 3 处统一）
- `ErrTaskNotFound` / `ErrCourseNotFound` / `ErrCourseNotRedeemable` / `ErrRealPaperUnavailable` / `ErrShopItemUnavailable` / `ErrUserNotFound` / `ErrInvalidPenalty` 等

文案成为哨兵的属性而非契约本身；handler 侧以 `errors.Is` 一处映射 HTTP 状态码（404/400），彻底移除 `err.Error() == "…"` 字符串比对（points.go 7 处、contact.go 2 处、question_bank.go 1 处同模式一并收编）。既有 `ErrPointsProcessed` / `ErrInsufficientPoints` 保持不动。

### C2 Endpoint 默认信封（重开 ADR-0013 §9）

endpoint.go 骨架支持 Render 省略：`Render == nil` 时走内置默认信封（`ParseError` → 对应 4xx、invoke 错误 → 500、成功 → `Success(c, resp)`）。仅保留有业务错误映射的端点写自定义 Render——C1 落地后即只剩这类。

C1 落地后**一次性清删**退化为纯样板的 Render 闭包（现存量 180 处 / 26 文件），不留新旧两套并存的长期态。parse → invoke → render 三段式守卫链与路由装配形态（Register*Routes + RouterDeps）不变——本条取代 ADR-0013 §9「Render 所有端点均须显式提供」的表述，其余延续。

### C3 站内信 typed event constructors

站内信 interface 从 6 裸参数（Create/CreateWithTx）深化为事件构造器：每个业务事件一个构造函数，title/content/link/payload 口径内聚站内信域，业务方一行触发。**最难路径先行**：问答采纳奖励双事件（forum_service.go 采纳事务内 CreateWithTx + SettleRewardTx 同事务）先验证事务内构造器形状，再迁论坛互动 7 处与 contact / profile_review 各 1 处。

不引入领域事件总线：当前 9 个调用点、3 个域，无第二 adapter，seam 未成真（one adapter = hypothetical seam）。

### C4 useAsyncPage 收编（Speculative）

13 页非冻结域机械收编（admin×8 / recruit×3 / student×4 / onboarding×1），valuation×2 按 R2 冻结排除。无新设计决策，沿用 a86286f tutor 收编的既定路径。

## 约束

- 既有响应 shape 与信封零漂移：默认信封行为与当前纯样板 Render 逐字等价（ServerError / Success）。
- 错误语义冻结：文案与状态码映射不变（已领取 → 400、任务不存在 → 404 等），仅契约载体从字符串换为哨兵。
- 站内信事件构造器首批仅问答采纳双事件，其余 7 处调用点行为与文案不变。
- valuation 域本轮冻结不触碰（R2）。

## 执行

4 个独立 PR：C1 → C2 链式依赖（sentinel 化后 Render 才退化为纯样板），C3 / C4 独立可并行。每个 PR 走分支 + CI 门禁（后端 gofmt / vet / golangci-lint / test；前端 type-check / vitest）。

## 后果

- 积分域文案改动不再漂移 HTTP 语义，「业务错误静默变 500」缺陷模式消失；测试以 errors.Is 断言语义而非字符串快照。
- 纯样板 Render 删除即消失（deletion test = concentrates），复杂度集中到 endpoint.go 单点；新增端点 ~15 行 → ~5 行。
- 站内信通知口径（link/payload 规则）改动单点生效；ForumService 不再因手拼通知继续膨胀。
- 前端列表页三态 bug 修一次 30 处（17 已收编 + 13 新收）全修好。
