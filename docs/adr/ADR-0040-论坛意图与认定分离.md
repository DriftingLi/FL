# 论坛意图与认定分离：备考经验从学员自述类别变为管理端认定

学员论坛的三种模式原以 `forum_topics.category` 单列承载：`discussion`/`question` 是学员发帖时**自述的意图**，而 `experience`（#706/#722）也是学员自述——发布页第三个 tab 一选即成「备考经验」。这在 #742 给经验叠加 +20 终身奖之后变成漏洞：`growth_first_experience` 的达成判定读**当前** `category`，而 `PUT /api/forum/topics/:id`（#811）允许作者随时改类别，于是**任何在线发布的帖子改一下下拉框即可白拿 20 分，正文一字未动**。本次把两义拆开：`category` 收窄回 `discussion` | `question`（学员自述的**意图**），新增 `is_experience` 为管理端**认定**的归类列（与既有 `is_featured` 精选位同轴），并以 CHECK 保证 `is_experience ⇒ is_featured`（经验区是精选的子集，不存在「经验但非精选」）。认定奖励合并为一条 +30（每帖一次，撤精不回滚），删除 `growth_first_experience` 任务（**已领取的 +20 不追回、不补差**）；存量 `category='experience'` 行**一律不被认定**（降 `discussion`、不发分、不追回），经验区由管理端从讨论区重新策展。

判据一句话：**学员只能声明他想干什么（讨论/提问），不能声明他产出了什么（这是考经/这是精选）。自称不产生事实，也不产生奖励。**

## Consequences

- **经验与普通精选同酬**（都是 +30）——经验并不比精选多拿钱，这是「一个认定动作」的直接结果而非缺口。`is_featured` 全类别可用，讨论帖同样可被加精并拿 +30。
- **写入路径分裂**：发帖/编辑的分类归一收窄到两值，`is_experience` 只能由管理端写。既有「已采纳的帖子只能是问答帖」禁令（迁移 000026 + service）继续**独立**成立，两件事不要混为一谈。
- **前端发布页由四 Tab 变三 Tab**（广场/资源/知识问答），经验 Tab 从发布入口变为只读策展流。
- **奖励阶梯变为**：任意帖每日首篇 +10（发帖任务）→ 认定 +30（三模式通用）→ 问答另有采纳 40/5。经验不再有专属分。
- **存量迁移必须先定落位**：`question` 恒 `chapter_id IS NULL`（迁移 000005 的 CHECK），故**挂章节**的存量经验行只能落 `discussion`；不挂章节的同理（凭空赋予问答语义会带出采纳与答主概念）。
- **经验 Tab 会短暂清空**——内容仍在讨论区，可被逐一重新认定。这是「存量未经审核不算经验」的必然代价，不是回归。

## Considered Options

- **保留 `category` 第三值，只把写权限收归管理端**：改动最小（存储/索引/CHECK/API/前端全不动），但 `category` 一列继续同时装「自述」与「授予」，既有纪律「判类别看 category、判区域看 chapter_id」还得再加一条「且其中一个值学员不能写」的例外——而论坛的 WHERE 恰是全仓最容易出错的地方（`scope=general` 与问答帖都吃 `chapter_id IS NULL` 那条教训就是这么来的）。拒绝。
- **单一档位列 `designation`（none < featured < experience）**：蕴含式由类型天然保证，连 CHECK 都不需要。但把刚拆开的「质量位」与「内容归类」又压回一列，将来若要「非精选的考经」（经验区不参与精选推荐流）必须改模型。拒绝。
- **独立 append-only 认定事件表（`is_featured`/`is_experience` 降级为读缓存）**：唯一能顺带解决「违规回收范围过窄」的方案，但本批改动面最大，且要与刚落地的 `is_featured` 列双写过渡。拒绝——认定事件表的价值有限（布尔位无历史语义需求），回收问题按 ADR-0041 在流水层单独解决。
- **存量一律认定为「经验 + 精选」并补发分**：等于承认「自称就能拿钱」，正是本次要堵的洞；且无法区分真诚作者与刷分者。拒绝。
- **存量保留 `is_experience` 但不置 `is_featured`**：产生与 CHECK 冲突的悬挂态，而悬挂态正是本仓在采纳语义上专门防过的东西（迁移 000026 清 orphan_accepted）。拒绝。
