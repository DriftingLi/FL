# ADR-0056: 第十一波架构深化——分页错误模式与信封登记 / 证件分区谓词 / 巡检读面归位 / 扣罚通知回归域内 / 守卫 runner / 迁移对账 / 契约事实 / 前端编排与词表 / 字体并回

- 状态：已接受（2026-09-17，architecture review 12 candidates，经 grilling 逐一定案）
- 领域：分页契约 / 证件分区 / 管理端巡检 / 积分与站内信 / CI 守卫与迁移门 / 契约 codegen / 前端列表编排与状态词表 / 估值 PDF

## 背景

第十波（ADR-0053）后本轮扫描覆盖四面：`backend/`（service 与 api 层、`pkg/`、估值域、基础设施面）、`frontend/src` 全域、部署与 CI/scripts 面，外加契约 codegen 面。12 个候选经 grilling 全部定案。

本轮与前几波不同的地方：**除了「真源已有、派生物散在消费面」这一贯形态，还实测到两处行为缺陷**——① `pkg/paging` 的 `Query*` 把 `Count/Find/Scan` 的错误全部吞掉，DB 故障渲染成 HTTP 200 + 空列表（19 个 importer 继承 fail-open）；② `scripts/check-async-section.mjs --diff` 因实参形态错（`parseAddedLines(base, '*.vue')` vs 真 interface `parseAddedLines(diffText)`）恒返回空 Map、恒 0 违规——本机复现：`node scripts/check-async-section.mjs --diff origin/master` 打印 ✓ 并 exit 0。后者的成因正是第十波收掉的「判据宿主不唯一」在**守卫 runner 骨架**上的残留。

移动端（`training-app/`）不在本仓评审范围，未产生候选。

## 决策

### 1. paging：错误模式 + 信封登记（合成一票）

- **事实**：`paging.Query/QueryWithMax/QueryWithScan` 丢弃 `.Error`（`paging.go:42,47,73,78`），interface 上没有「查询失败」这个错误模式；`Page` 信封类型全仓 0 消费者；26 个域各自声明 page struct，其中 13 个用 `pages`、10 个用 `page_size`、2 个没有分页元数据；另有 14 处手写 count/offset（12 处未 import paging，且每处都判错）；api 层 4 处 `gin.H` 手拼分页信封，`ContactRequestListResult` 是「只服务 swagger 的类型」而运行时出字节的是 map。
- **决策**：① `Query*` 返回值末尾加 `error`，`.Error` 一律上抛；调用方**统一上抛 → 500 信封**（前端既有错误态与 retry 接管）。② `AuditService.List` 补 error 位、`api/audit.go` 改走 `ServerError`；forum 三个无 error 的兄弟读方法补 error。③ 25 处调用点收编到 `paging.Query*`。④ 信封**只登记不改值**：每端点一行声明（键集合 + 键序 + 是 `pages` 还是 `page_size`），装配单点；删死类型 `paging.Page`。
- **顺序约束**：必须先做 ①③ 再做 ④——12 处手写副本比 paging 更正确，先收编等于把对的换成错的。
- **被否备选**：只补错误模式 / 只收信封（两半的失效面不同：一半是行为缺陷、一半是形状漂移，但共享同一个 module 与同一批调用点，拆票会让同一批文件改两遍）；统一两种方言（破坏性契约变更，违反 ADR-0048「只增不破」，另案）；`paging.Page` 作为被嵌入的信封统一 26 处（字段序被 ADR-0009 §2 的字节锁钉死，塞进同一 struct 会破锁）。
- **锁**：paging 失败注入用例（今天无法在单测里造 DB 错误）+ 25 处调用点编译期覆盖 + 「每个含 total 的列表结果类型都在登记表内」的覆盖锁 + 既有 `envelope_dto_shape_test.go` 字节锁保持全绿。

### 2. 证件分区：三族具名谓词 + 变参改显式参数

- **事实**：`CONTEXT.md`「当前证件」与 ADR-0047 §4 / ADR-0051 把它当一等不变式，但仓里没有这个 module——18 处内联谓词分四族。同一个 `*int` 承载两种相反语义：`answering_session.go:187-193` 的 `credentialClause` 把 nil 读成 `credential_id IS NULL`（只取 NULL 桶），而 `practice_mode_service.go:426-428` 把 nil 读成「不过滤、看全部」；两处相距不足 200 行、参数同名。16 个方法把可选位写成 `credentialID ...*int`。前端五条注释仍写「由主 client 拦截器默认注入（#387）」，而 `api/client.ts:203-211` 只挂 Authorization。
- **决策**：在 service 包建**证件分区具名 module**，导出三个谓词：`RecordPartitionOf`（记录冻结分区，nil = 看全部）、`PartitionBucket`（NULL 桶，nil = 只取未选定证件那一桶）、`EntityOwnedBy`（读被检索对象自身的证件列）；18 处内联改调具名谓词；16 个变参可选位改为显式命名参数或 options 结构。客户端半边见**前端伴随票 #1106**：删掉五条失效的「拦截器默认注入（#387）」注释，把「跟随当前证件」与「浏览指定证件」两种意图拆成两个名字。
- **登记一条例外（本轮核实）**：`CredentialScoped` 的服务端兜底分支要求 `roleOf(c) == student`（`middleware/credential_scope.go:42`），而 `/api/search` 挂在**没有 JWT** 的 api 组下、`/api/courses`（`api/courses.go:31`）的 `CredentialScoped` 也挂在**公开访问**的课程 group 上 ⇒ **这两个匿名可访问端点的兜底永不生效**，客户端必须显式下发 `credential_id`（移动端已在 `api/search.uts` 文件头写清，见 #1107；Web 端在 `api/search.ts` / `api/course.ts` 的注释与 `api/__tests__/credentialScopeContract.spec.ts` 的冻结清单里登记，见 #1106）。这与 ADR-0047 §4「客户端不再维护豁免表」的表述冲突——事实上存在一张「必须显式传」的清单（Web 端另有两个**未挂** `CredentialScoped`、由 handler 自读 query 的公开端点 `/api/catalog/tree`、`/api/tags`），只是此前没有落点。本波把它记为**例外**（不改端点鉴权；给这两个端点挂 OptionalAuth 涉及匿名浏览/搜索语义，另案评估）。
- **边界**：**不合并** ADR-0050 §1 否掉的「学员可见性」那一族（题库池 / 课程挂载是另一种不变式）；本条只收证件分区这一族，算 §1 边界内的新增。
- **被否备选**：typed scope 值（`All | Bucket | ID(id)`）统一所有读面（类型最硬，但 16 个方法 + handler + 测试全改签名，过渡期过长）；只修对撞那一处（其余 17 处仍各写各的）。
- **锁**：三谓词的行为断言（含 nil 三态）+ 静态扫描「service 包不得再出现裸 `credential_id = ?` 谓词」（白名单 = 谓词实现处）+ 客户端注释与实现一致性检查（那条 `#387` 注释清零）。

### 3. 巡检读面从 api 层搬回 service

- **事实**：`api/admin_inspection.go:19` 是全仓 api 层**唯一**拿 `*gorm.DB` 的注册点（`grep *gorm.DB backend/internal/api` 只有 deps.go 与它）；三条读路径（`/admin/recruit/views`、`/admin/recruit/requests`、`/admin/inspection/*`）绕过 paging 钳制、DTO 定型与错误传播，`_ = q.Count(...)` 让 DB 故障渲染成 200 + 空列表；出参是裸 model（加一列自动进响应）；连 swaggo 注解都没有（注册在闭包内）。文件第 18 行自陈「积分流水查询归位 service 层（#401）」——同一处四条里只修了一条。
- **决策**：新建 `InspectionService`，三条读路径收进 service：typed 请求 + typed DTO + `paging.Query*` + 错误上抛；`RegisterAdminInspectionRoutes` 签名从 `db *gorm.DB` 改成 service 实例（与其余 20 个 `Register*Routes` 同形），handler 走 `Endpoint` 骨架并补 swagger 注解。**响应字节不变**：typed DTO 按 model 字段序声明（照 ADR-0009 §2 先例）+ 形状锁。
- **被否备选**：借机重命名/收敛字段（破坏性契约变更，且移动端消费面不在本仓）；保持裸 model 出参只搬查询（DB 列名仍是契约）。
- **锁**：三条读路径的形状锁（字节全等）+ 失败用例（内存库注入错误 → 500 信封）+ 「api 层不得出现 `*gorm.DB`」的静态守卫（白名单 = deps.go 的装配字段）。

### 4. 扣罚即通知回归积分域：强一致 + 域表

- **事实**：`api/admin_points.go:45-66` 是全仓唯一一处「积分变动 → 站内信」落在 api 层 Invoke 闭包里的编排：罚分事务已提交、站内信事务外另写且错误被 `_ = ` 吞；文案与 payload 是 api 现场拼的第二个源（ADR-0027 全域收编后的唯一漏网）；该 handler 未挂 `pointsErrStatus`，`ErrUserNotFound`（域表 404）被渲染成 400，与 `/points/claim`、`/points/redeem` 同域不同判。对照：`contribution_service.go:648,758,968`、`forum_service.go:1007,1013`、`profile_review_service.go:247` 全部同事务发信。
- **决策**：新增 `NewAdminPenaltyEvent(userID, delta, reason)` 域构造器；`PointsService.AdminPenalty` 在**同一事务内**经 `CreateWithTx` 发信（**强一致族**：通知写失败则扣罚整体不生效）；handler 退化为一行 `invoke`，Render 挂 `pointsErrStatus`，并给管理员**可见的失败原因**（可重试）。审计仍由中间件承载，不搬进 service。
- **被否备选**：尽力而为（事务后 `TryCreate` + 日志）——扣罚是合规动作，「被扣罚的学员必须被告知」是动作的一部分；保持 api 层编排只补错误处理（文案第二源与事务外写入仍在）。
- **锁**：行为级「通知写失败 → 流水不存在」（今天无法在 service 层断言）+ 文案/payload 构造只在 `notification_events.go`（`api` 包不得出现站内信文案）+ 域表映射用例（404 不再压成 400）。

### 5. 守卫 runner 单点 + `--diff` 入 CI

- **事实**：三个守卫（`check-api-seam` / `check-el-controls` / `check-async-section`）各自重写一遍 runner 骨架；第三份把 `added-lines.mjs` 的 interface 用错（单参 `diffText` 被当成 `(base, pathspec)`），`--diff` 恒 0 违规；CI 只跑 `--all`、自检只测判定函数，假绿两侧无人接住。本机复现：`parseAddedLines('origin/master','*.vue')` → 空 Map；`--diff origin/master` → ✓ + exit 0。
- **决策**：新增 `scripts/lib/guard.mjs`，独占 argv 解析、`--all` 走查、`--diff` 取 diff 并调用 `added-lines`、allowlist 放行、报告与退出码；三个守卫只保留判定面（`GUARDED_*` 常量 + `scanSource`）与各自自检（入口脚本与 CLI 面不变，照 ADR-0053 §9 的形态）；**`--diff` 接进 CI 的 PR 增量门**；runner 自带表驱动自测，含一条「合成 diff 必须报违规」。
- **被否备选**：只修 runner 与 bug、不动 CI 触发面（`--diff` 仍是死路径）；合并成单命令多子命令（文档/CI/checks.md 全改，收益同 §9 否掉的理由）。
- **锁**：runner 的自测（合成 diff 正/负样本）+ CI 两个触发面（`--all` 全量、`--diff` 增量）+ 「新增守卫只需实现 scanSource」的接口文档化。

### 6. 迁移校验真跑 + 单向列对账 + 部署硬失败

- **事实**：`migration-check` 起了 postgres:15-alpine 并注入 `DATABASE_URL`，却只 `find | wc -l` 比 up/down 个数（`ci.yml:300-312`），一行都没连过库；生产 schema 的事实源是 `migrations/*.up.sql`（37 对，从未在 CI 执行），测试 schema 的事实源是 GORM `AutoMigrate`，两者零对账；`deploy-remote.sh:903-912` 把迁移失败降级成 `log_warn` 后继续部署。
- **决策**：① `migration-check` 在现成 Postgres 上真跑 `go run ./cmd/migrate up`（空库重建 baseline）。② **单向列对账**：GORM 模型期望的列集合必须 ⊆ `information_schema` 实际列集合，缺列即红（正好覆盖「模型加字段、忘写迁移」，且不因索引/刻意不映射的列产生假红）。③ 部署链路改**硬失败**，保留一个显式逃生开关给线上事故。
- **被否备选**：双向对账 + 豁免登记表（更彻底但要维护豁免清单、索引会造成持续假红）；只跑迁移不做对账（丢掉本候选的主要价值）；保持降级但把状态写进部署结论（默认静默，与本仓 fail-closed 纪律不一致）。
- **锁**：CI 对账步骤本身（缺列探针验证过）+ 部署脚本的失败分支用例（可 dry-run）+ 逃生开关必须显式声明理由。

### 7. 前端编排侧接回 useAsyncPage（含 15 个存量错误态支结清）

- **事实**：ADR-0053 §6 只落地了渲染侧（`UiAsyncSection` + 守卫）；编排侧入口 `itemsRef` / `filterDeps` / `isEmpty` 的**生产消费为 0**（命中全在 composable 与 spec），32 处手写 `:empty=`（6 处写死 `false`）；`QuestionDetail.vue` 自建三态与 retry，原因是 `loadError` 只有 boolean；`JobPlaza` 与 `Resumes` 各抄一份 append 分页。守卫 ALLOWLIST 的 15 条逐条指向真实文件，15/15 已在用 `UiAsyncSection` 但 **0/15 用 `UiErrorState`**——剩下要迁的是错误态那一支（外加 4 处手写条件）。
- **决策**：① `isEmpty` 成为喂 `UiAsyncSection` 的默认路径（`itemsRef` 或页面显式声明）。② `loadError` 升级为可携带 kind 的判据（404 = 空态、其余 = 错误态），收编详情页。③ 补 `mode: 'append'`。④ **把 15 个存量文件的错误态支一次结清并销号**。⑤ 守卫：新增 `:empty=` 只允许 `isEmpty` 或登记例外。
- **被否备选**：只收 `isEmpty`（辨析仍靠页面自觉）；把 15 个存量文件留到以后（同一批文件会再次成为候选）。
- **锁**：`useAsyncPage.spec.ts` 既有两条判据断言第一次被生产路径穿过 + 新增 `:empty=` 守卫 + ALLOWLIST 销号到 0。

### 8. 状态词表单点（联络授权 / 投递）

- **事实**：`ContactRequestDTO.status` 的 5 个取值在三处各有一份文案判定（MyRequests / ResumePage / Inspection），另有两处模板内联；`ApplicationDTO.status` 的 3 个取值有两份且**已漂移**（`applied`：`投递中` vs `待处理`），contact 侧也已漂移（`pending`：`待同意` vs `待处理`）；同一域的 `tagType` 两处逐字相同；这些文案零测试断言。生成物里 status 一律 `string`（无 enum、无 union）。
- **决策**：给 contact_request 与 application 各建一个 **label/tone descriptor 深 module**（输入 status，输出 `{ label, tone }`），五个消费面只消费它；status 收成前端 union（照 `ContributionStatus` 先例），取值集合用一条小 codegen 或对账锁钉到后端常量表——contact 侧已有 `ContactGrantState` 常量表可用，application 侧需先补一张 Go 常量表（照 contribution 先例）。两处漂移文案以「描述状态事实」为准统一（如 `applied` = 「投递中」）。
- **被否备选**：后端注解补 enum 由现有生成器渲染 union（方向正，但属新的生成器能力，与「内联 object 渲染」合成一片另做）；只做 descriptor、status 保持 string（漏掉的状态值仍在运行时才暴露）。
- **锁**：descriptor 的穷尽 Record（漏一个取值编译报错）+ 取值集合与后端常量表一致性锁 + 「模板不得内联状态文案」静态扫描。

### 9. admin 多列表页的第二档写明归属

- **事实**：同一文件里「三态 + 分页 + 筛选」有两档实现：一档走 `useAdminTable`（含 loadError/retrying/retry/applyFilters），另一档逐字手写且丢掉三态——`Inspection.vue` 的 views/requests/jobs/reports 四段共 5 处 `catch {}`（252/300/310/337/347）静默吞错、无重试入口；`ForumManage` 与 `ContributionManage` 的举报队列各再抄一份。
- **决策**：**分两档并写明归属**——分页列表 → `useAdminTable`；只读/计数 section（巡检计数、汇总卡）→ `useAsyncPage` + `UiAsyncSection`（`deleted-after-accepted` 这类单值计数不硬套列表状态机）；两档都消灭 `catch {}`；每页在文件顶部登记档位。
- **被否备选**：全部迁 `useAdminTable`（计数类要伪造 items）；只把 `catch {}` 改成 toast（同页两档继续存在）。
- **锁**：`grep 'catch {}'` 在 `pages/admin` 清零 + 档位登记（每页顶部注释，守卫可扫）+ `Inspection.spec` 覆盖两档。

### 10. AI 助手：发送编排与流式终态收进 store

- **事实**：`AIAssistantPage` 与 `FeatureChatPage` 逐字写同一段发送编排（trim → streaming 守卫 → 清 inputText → await → 吞错）；「可发送」有四处派生（两页各算 canSend、壳只用它 disabled 按钮、`ChatPageShell.vue:639-643` 的 Enter 直通、store 内的真闸门）；收尾有三份 implementation（onDone / onError / stopStreaming）且复位字段子集各不相同；失败被拼进正文文本（`[生成中断：` / `[生成失败：`），没有可挂重试的状态通道；`lastSources` 导出但零消费者。
- **决策**：store 承载**一轮发送的编排与终态**（`send(text, opts)` + `canSend` / `startDraft` 派生 + 私有 `finalizeTurn(done|error|aborted)` + `lastTurnError` 独立通道）；**输入文本留在页面**（UI 态）；流式进行中的「新对话」给**显式反馈**（禁用或提示）而不是 `if (streaming) return` 静默吞掉；壳的 Enter 与发送按钮读同一判据；删掉零消费者的 `lastSources` 导出面。
- **被否备选**：文本也搬进 store（纯 UI 状态入 store，耦合面变大）；只做终态 module（两页编排与四处 canSend 保留）。
- **锁**：store 层的三种终态用例 + 「`pages/ai-assistant` 不得再出现 `sendMessage` 编排」静态守卫 + 重试路径的页面用例。

### 11. 契约事实收成一份：具名分派表 + 消费面覆盖锁

- **事实**：估值管理端「路径 + 方法 + 响应字段集」有三份手抄——dictcrud 描述符、37 条 `@Success` 内联字段表（`dictcrud_docs.go`）、`apitypes/domains.go:810-846` 的端点清单；那 37 个 `Admin*` 方法**从不注册进路由、全仓零引用**（grep 实测），真路由由 `registerDictCRUDRoutes` 从 `AllDescriptors()` 循环注册匿名闭包；现有锁只做「声明表 vs swagger」单向校验。前端消费面：`api/inspection.ts` 的 8 个端点里 4 个在 swagger 但不在任何域声明表、另 4 个连 swagger 都没有，行类型由调用方 `<T>` 给出（文件头自陈欠条）。
- **决策**：**一次到位**——路由注册改成**具名分派表**（一个描述符对一个具名方法），注解宿主同时成为执行体；`@Success` 的响应字段表由描述符派生而不是手抄；新增**消费面覆盖锁**（形态对齐 `check-api-seam.mjs`：`--all` 报存量、`--diff` 阻断新增）：扫描 `frontend/src/api/**` 的 method+path，逐条要求落在 `apitypes.Domains` 端点集内；给 8 个巡检端点补注解与登记，泛型行类型换成 generated 产物。
- **被否备选**：只加锁、宿主保留（死代码与三份手抄仍在）；只补消费面覆盖锁（注解与描述符的关系继续无锁）。
- **锁**：37 条注解的 path/method/字段集 == `AllDescriptors()` 派生集合 + 8 份既有 per-entity CRUD 契约测试全绿（回归证据面）+ 消费面覆盖锁。

### 12. 估值 PDF 字体并回 pdfutil

- **事实**：`internal/pdfutil` 是按「共享 PDF 能力、消除重复内嵌」抽出来的叶子 module（注释写明「与残值域 pdf.FontSimHei 同名同值，供两个域共用」）；估值域从未迁过去，保留第二份 `//go:embed` 与逐行等价的 `ensureFontLoaded`，两处 `simhei.ttf` 的 md5 实测相同（`4093871a7f48e43b9ce7c38da0c34809`，各 9,745,792 字节）——同一份字体被编译进二进制两次（约 19.5 MB）。
- **决策**：删掉 `internal/valuation/pdf/font.go` 与它下面的 `fonts/`，两处调用点改走 `pdfutil.EnsureFontLoaded` / `pdfutil.FontSimHei*`；顺带删掉被 `//nolint:unused` 压住的 `fontFileName()`。**不**改成运行时从磁盘加载（会引入启动期的新失败模式）。
- **被否备选**：彻底去嵌入（二进制更小，但文件缺失/权限/路径成为新的运行期失败面）；保持两份（零收益）。
- **锁**：二进制/镜像体积可复测（少约 9.7 MB）+ 两个估值 PDF 模板的渲染用例（字体注册路径不变）+ 「`internal/valuation/pdf/fonts` 不存在」的仓库断言。

## 约束

- **行为变更只有三处，且都是有意为之**：候选 1 的查询失败从 200 + 空列表变 500 信封；候选 4 的通知失败从「静默不回滚」变「整体不生效 + 管理员可见」；候选 6 的部署从「迁移失败继续」变「硬失败 + 显式逃生开关」。其余九条为**行为零漂移**的形状收敛。
- **响应 shape 与 HTTP 契约只增不破**（ADR-0048）：候选 1 的信封登记、候选 3 的 DTO 搬迁、候选 11 的字段表派生都必须逐字节保持既有形状；两种分页方言只登记不改名。
- **字节序是契约的一部分**（ADR-0009 §2）：换 struct / 搬 DTO 时字段声明序必须与旧输出一致，靠既有字节锁验证。
- **ADR 边界**：候选 2 只在 ADR-0050 §1 的边界内新增（不合并学员可见性那一族）；候选 11 执行 ADR-0048 片九已写明的收敛方向；候选 4 兑现 ADR-0009:60 的「另立片」欠账。
- 移动端不在本次范围。根仓侧发现的**跨端差异**已开移动端对齐票并 assign @zhengcookie：证件下发口径清单 #1107、投稿状态文案 #1108；根仓自己的客户端半边见 #1106。

## 后果

- **错误模式回到 interface 上**：`paging.Query*` 的 25 个调用点从 fail-open 转 fail-closed；「查询失败」不再是不可区分的谎。
- **证件分区的两种 nil 语义变成两个名字**；新增读路径不可能再选错——这是 ADR-0051 只写了「写入时冻结」而没覆盖的读侧那一半。
- **api 层不再有第二个数据访问面**（巡检归位）与**第二份发信编排**（扣罚回归域内）：`service` 是唯一读写落点，「谁在读库 / 谁在发信」可机械回答。
- **CI 的假绿面收窄**：守卫 `--diff` 有了自测与 CI 触发；迁移门从「数文件」变成「真跑 + 对账」；契约有了**消费面**方向的锁（此前只有声明表→swagger 单向）。
- **前端两条不变式回到编排侧**（空态判据、筛选回第一页），admin 两档档位与状态词表成为可核对声明。
- 二进制少一份 9.7 MB 嵌入字体。
- 未立卡但已登记的相邻观察（18 条）见本轮评审报告；下轮扫描的起点是它们与两处未覆盖区（`internal/api/training_catalog.go` 细读、`auth_service.go` 的会话/配置 seam）。
