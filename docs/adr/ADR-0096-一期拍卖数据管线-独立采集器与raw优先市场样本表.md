# ADR-0096：一期拍卖数据管线落点——独立 Python collector + raw 优先的 market_transactions

- 状态：Accepted（2026-11-19）
- 日期：2026-11-19
- 领域：残值评估 / 数据采集（市场真值）
- 票：#2672（实施 tracer bullet）· 父规格 #2671

## 背景

残值评估的输出是「原价 × 多维系数」的模型估计，但**系数是否可信**此前没有任何市场数据可校准。评估记录是不可变事实（ADR-0004），不能回写；把它们与市场真实成交价对齐需要一条独立的数据管线：从公开拍卖公告采样本 → 原始留底 → 抽取清洗 → 与历史评估匹配 → 得到残值率标签 → 用于系数校准。

一期范围（spec #2671）明确：新建独立 Python **collector** 组件（batch 回补 + daemon 增量两种模式，同一组件两种运行形态），新增独立 `market_transactions` 表，评估记录表与评估路径零改动。#2672 是这条管线的 tracer bullet：只打通「一份 fixture 公告 → 一行 raw 样本」，抽取/清洗/匹配留后续票。

## 决策

**一、采集器是独立 Python 服务，不进 Go 后端。** 生产 compose 增加独立 `collector` 服务，与 backend 共享 PG 网络（`forklift-net`）；实现放在仓库根 `collector/`，用标准库 `html.parser` + `psycopg[binary]`，不引入爬虫/ORM 框架。理由：采集是一个 I/O 密集、与请求-响应后端生命周期不同的关注点，混进 Go 后端会把「每公告一个解析版本」的包和后端编译/发布绑在一起。

**二、新表独立，raw 优先。** `market_transactions`（迁移 `000063`）只要求渠道 / 来源 URL / 原始描述 jsonb 非空，其余字段（原始价格、规格、清洗状态、置信度、抽取版本、匹配层级、溢价异常、残值率标签与引用原价）全部可空或带 raw 默认值。原始描述是**不可变留底**，抽取/清洗结果写各自字段，不覆盖原文。

**三、单一测试 seam：端到端契约测试。** spec 指定唯一 seam = collector batch「fixture HTML 进 → 真 PG 一行出」。测试（Python unittest，与 `deploy/tests` 同 runner）纪律：随机 schema 隔离、`current_schema()` 收窄断言、本机无 `DATABASE_URL` 干净 skip、首跑在 CI 专用 `collector-test` job（自带 postgres service）。LLM 抽取在该 seam 以 stub 形式出现，本票尚未接入故不涉及。

**四、价格口径：管线存原始价，不施加清算折扣 δ。** 残值率 = 成交价 ÷ 匹配原价；清算折扣 δ（基线 0.85，敏感区间 0.75–0.95）是**下游校准阶段**的参数，不进采集/留底层。否则「市场真值」与「已折算值」会在同一列漂移。

**五、匹配不用评估路径的模糊匹配器。** 评估路径取最高价；市场校准若沿用会把样本系统性偏向高价，得到有偏的残值率。匹配器按 7→4→3 字段分层、多命中取中位数，是独立实现（后续票落）。

## 被否备选

- **把采集逻辑塞进 Go 后端 cron**：省一个服务，但把「公告解析版本」和后端发布绑死，且 Go 侧没有轻量 HTML 语义解析生态；spec 明确 collector 为独立组件。
- **复用评估表存市场样本**：字段形似（都有原价/残值率），但评估记录是不可变事实（ADR-0004），写入会污染评估路径；且市场样本需要 raw 留底与清洗状态，评估表没有这些槽。
- **在 raw 阶段就算残值率 / 施加 δ**：能让首票「看起来更有用」，但当时的抽取与匹配都还没做，算出来的标签没有可信原价引用——正是 spec 禁止的「弱标签当真值」。
- **契约测试对接本地 mock DB（sqlite）**：跑得快，但 jsonb / `current_schema()` / 真迁移链都测不到，与后端 PG 契约测试纪律（真 PG + 随机 schema）不一致，首跑必须是真 PG。
- **把 collector 纳入 deploy.py 的完整镜像更新/回滚生命周期**：本票只有一次性 batch 命令、无常驻 daemon，纳入后要同步改 CD 构建图 / 备份回滚等 6+ 处，收益为零且漂移面扩大。改为 compose 里 profile-gated 服务（`profiles: ["collector"]`）；镜像默认值 `COLLECTOR_IMAGE` 仍登记进 topology 声明表并由 drift lock 钉住（非空默认即事实，不登记就会成为漂移盲点），但不在本票参与 deploy.py 的镜像更新/回滚；daemon 化时再一起纳入生命周期。

## 后果

**收益**：①市场真值第一次有独立、不可变的事实留底，后续清洗/匹配/校准各阶段可在同一行上逐版本迭代而不回写原文；②评估路径零改动，ADR-0004 的不变性不被本管线触碰；③单一端到端 seam 让「解析→落库」的正确性在 CI 真 PG 上可断言，本机缺环境时干净 skip 不误判。

**代价**：①多一个 Python 服务与其镜像/依赖维护面（本票只装 psycopg，面很窄）；②`market_transactions` 一期绝大多数字段为空，读方必须按 `clean_status` 过滤，不能把 raw 行当有效标签；③collector 暂未纳入 deploy.py 生命周期，镜像更新需显式 compose 命令，daemon 化票需补齐这部分；④根词汇表残值评估节新增 5 个新词（市场真值 / 弱标签 / 残值率标签 / 清算折扣 / 校准），需随本票同步落库以免出现「代码说一套、词汇表说一套」。

**实施边界（本票不做）**：LLM 抽取、清洗七规则版本化模块、分层匹配器、校准拟合、daemon 增量模式、admin UI——全部在后续票（#2673 起），本票只交付地基与单条 raw 行。
