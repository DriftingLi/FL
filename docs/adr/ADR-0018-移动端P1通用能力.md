# ADR-0018: 移动端 P1 通用能力——论坛互动 / 通用收藏 / 全局搜索 / 学习资料聚合

- 状态：已接受（2026-08-19）
- 领域：论坛 / 收藏 / 搜索 / 学习资料（移动端缺失 API P1 排序 4-5，《移动端缺失API整理.md》2.4/2.6/2.10/2.12）

## 背景

移动端 P0（学习位置，ADR-0017）之后，P1 中无产品决策阻塞的四项：论坛互动（点赞/举报/我的帖子/我的回复）、通用收藏、全局搜索、学习资料。笔记/学习计划/考试目标等 UI 未定，AI 专业能力与学员证书依赖产品决策，均不在本批。

## 决策

- **论坛互动**：新表 `forum_topic_like`（topic_id+user_id 唯一，点赞幂等）与 `forum_report`（topic/reply 二选一，status 0 待处理/1 已处理）；帖子详情返回 `likes_count` + `liked_by_me`；管理端 `/api/admin/forum/reports` 列表 + PUT 处理。帖子收藏不单独造接口，走通用收藏（target_type=topic）。
- **通用收藏**：单表 `favorite`（user_id+target_type+target_id 唯一，幂等），多态覆盖 course/chapter/question/featured/topic；`/api/favorites` CRUD + `/check`；列表按类型分组 batch 回填目标快照（标题/封面，题目标题取题干前 50 字）；收藏时校验目标存在且可见（课程=已发布+挂载不变式、题目=published、精选=已发布）。目标被删后列表跳过该行。
- **全局搜索**：不引入搜索引擎，多表 `LOWER(col) LIKE LOWER(?)`（Postgres/SQLite 双兼容）；`GET /api/search?keyword=&type=` 公开；type 缺省返回各分区 top5+总数，指定类型（course/question/content/topic）分页；可见性与业务口径一致（课程挂载不变式、题目 published、精选已发布、帖子物理删除即消失）。
- **学习资料聚合（低成本路径）**：不建独立资料库表，资料 = 已发布课程下章节挂载的 `chapter_file` 附件视图；`/api/materials`（列表，可按课程过滤）/`/:id`（详情）/`/:id/download`（返回 file_url 静态直链）+ `/api/student/materials` 别名；legacy 无章节附件（chapter_id NULL）不含。

## 明确不做

- 帖子收藏的 forum 专用路由（收藏统一走 `/api/favorites`）。
- 独立资料库（PDF/维修手册新表）、资料上传（沿用讲师章节附件流）。
- 笔记 / 学习计划 / 考试目标 / AI 专业能力 / 学员证书（依赖 UI 确认或产品决策）。

## 后果

- 举报仅入队（pending），内容处置沿用既有管理端删帖/删回复流程，不自动删内容。
- 搜索为顺序 LIKE，数据量大后可再演进 pg_trgm/全文索引（当前量级可接受）。
- 收藏快照不落库（实时回填），目标改名自动跟随；目标删除后条目静默消失。

## 补遗（2026-09-18）：收藏的唯一列表承载面与开放的类型轴

### 背景

`#1089` / `PR #1147` / `#1159` 三票修的是**同一个病**：`favorites.uvue` 与
`personal-activity.uvue` 各自维护了一份收藏落点表，两份都缺 `question` / `featured` 分支、
章节落点都写错键。缺陷不在任何一份表里，而在「**同一份数据有两个列表承载面**」这个结构。

### 决策

- **收藏的唯一列表承载面 = 「我的 → 收藏夹」**（`pages/profile/favorites.uvue`）。学员可见的收藏列表
  只此一处；**个人动态不承载收藏** —— 原「赞/收藏」子 tab 摘除，收成平铺的「赞过」
  （词表口径见 `CONTEXT.md` 的「赞过（liked topics）」）。
- **落点表全仓只此一份**：`target_type` → 目标页的映射只允许存在于 `utils/favoriteLanding.uts` 的
  `favoriteLanding()`。任何页面要展示收藏条目，**复用该承载面**，不得复制落点表。
  （2026-09-21 #1237 把它从 `favorites.uvue` 的 `onItemClick` 搬出：住在 `.uvue` 里的实现只能被
  「取函数体 + `new Function`」那类自搓执行器跑，而 `docs/agents/guards.md` 的分类器只认
  `loadUts(` 这一个执行调用 ⇒ 那一面没有 ③ 承重证据。页面从此只**应用**决策：
  `notice` → `showToast`、`url` → `navigateTo`。）
- **`target_type` 是开放的类型轴**（新增类型不改表结构）：当前收录 course/chapter/question/featured/topic。
  新增一个类型时移动端有**四处收口点**（缺一即产生静默 no-op 或用户可见的裸枚举）：
  ① `favorites.uvue` 的 `typeOptions` 筛选 chips；② 同文件的 `getTypeLabel` / `getTypeColor`；
  ③ `utils/favoriteLanding.uts` 的 `favoriteLanding()`（缺则**点了没反应** —— 本族缺陷的原始形态）；
  ④ `utils/favoritesLandingContract.test.js`（唯一会因缺分支判红的守护；**行为守护**、对 ③ 承重）。

### 明确不做

- 不做 forum 专用收藏路由（重申原决策）；不因「论坛里能收藏帖子」而在论坛侧再开一个收藏列表。
- 不在个人动态恢复第二个收藏列表承载面。
- 不为**表外类型**写渲染分支：今天没有任何输入能产生它（后端只存五类；调用侧预留的
  `notice/job/collection` 在列表里读作**空集**而非错误），写了即**不可验证的死分支**，
  与 `course_id <= 0` 那种「纵深防御、声称不了真机验过」同族，本仓不取。

### 后果与落锁

- `utils/personalActivityContract.test.js`：反向守护「收藏面不得回潮」（页面零 `getFavoritesApi` /
  `FavoriteItem` / `onFavoriteClick` / `favorited` / `likesSub*`；模板剥注释后无「收藏」；`:sub` 只剩一处），
  并钉住摘除的**前提**（唯一承载面已注册、筛选 chips 未掏空）。
- `utils/favoritesLandingContract.test.js`：**行为守护** —— 经 `utils/utsHarness.js` 的 `loadUts` 真跑
  `utils/favoriteLanding.uts`，断言五类落点 + 章节双键 + 缺课程可见提示 + 未知类型静默。
  成对取证（`guards.md` 判据③）：未改动树上 23/23 全绿，4 个「落点表损坏」变异 **4/4 判红**（#1237）。
  它在 #1237 之前跑的是页面函数体的自搓求值 —— 分类器只认接线守护 ⇒ 不构成 ③ 证据，这正是本条补遗的由来。
- `CONTEXT.md`：「收藏（favorite）」词条补「开放类型轴」与两条 `_Avoid_`。
- 未复现声明：`#1159` 原「整行不可点」结论在改判后的树上**未能复现**（注入点击确实触发 handler），
  该现象随承载面摘除而失去对象；如在他处复现，属新的诊断票，勿据旧结论推断。
