# 论坛正文格式由作者声明（纯文本 / Markdown），UGC 走安全渲染单点

论坛正文此前一律纯文本，`CONTEXT.md` 甚至把它写成了领域事实：「**图文分离**——正文保持纯文本，不做 markdown 渲染」。追到出处是 #44，原文为「为论坛增加"图文分离"的图片支持（**不做 markdown 渲染**）」——那是**当期的范围排除**（那个 issue 只做图片），不是安全立场，也不是有理由的架构决定。

而维修交流的结构表达需求是真实的：列排查步骤、贴故障码与报错原文、标出关键动作、给出手册与维修视频链接。现状下这些只能靠感叹号堆叠和换行硬撑，或者退化成堆图片。

本次为 `forum_topics` / `forum_replies` 各加一个 **`content_format`**（`text` | `markdown`，缺省 `text`，存量一律回填 `text`），并新增**全仓唯一的 UGC 内容渲染单点**。

## 为什么是作者可选，而不是一刀切

格式**不能被系统猜**：同一段文字按两种格式渲染结果不同——「1. 检查电瓶」在 markdown 下会变成有序列表，`2*3` 可能被当成强调。若一律按 markdown 渲染，写纯文本的人会发现自己随手写的符号被擅自解释；若一律按纯文本渲染，就等于没做这次改造。所以它是一个**作者自述的声明位**，与 `category`（意图）同类，而不是由服务端推断的派生值。

首次默认**纯文本**、之后记住该用户上次选择：不主动改变任何人的表达，Markdown 完全 opt-in，且不需要每一次都重选。**代价要认**：opt-in 意味着采用率会偏低，因此格式开关的**可发现性**是这个功能的成败关键——实现上不能把它做成一个不起眼的小图标。

## 为什么是 markstream-vue，而不是 marked + 净化库

学员正文是**不可信输入**，而全仓此前没有任何净化设施：现有的 `v-html` 渲染点（章节正文、管理端内容生成）处理的都是讲师/管理员内容，属可信来源。把学员 UGC 接到 `marked` + `v-html` 上会新增一条存储型 XSS 面。

仓库里已经有现成的答案：`markstream-vue`（AI 助手在用），且 AI 域已经立下「**不再有裸 `v-html`**」的收敛约定；该库文档也明确写着不可信 UGC 应当用 `htmlPolicy="escape"`，并内置了 tag 阻断与属性净化。学员 UGC 与 AI 输出同属不可信输入，走同一条路既一致又免新依赖。

`escape` 的语义是**把 raw HTML 渲染为文本**，而不是丢弃——这对内容治理是好事：管理员能看到别人究竟写了 `<script>` 字面量，而不是被静默吞掉。**也正因如此它不是内容过滤器**，违规内容仍靠举报与管理员删帖治理。

## Consequences

- **`breaks` 必须开启**（单换行即换行）：markdown 默认把单个换行折叠成空格，而存量帖子是多行纯文本。不开它，历史内容会被压成一行——肉眼可见的退化。该选项属于 markdown-it 的实例配置（`MarkdownItOptions`）而非 `ParseOptions`，只能经 `customMarkdownIt` 注入。
- **存量不需要迁移，也不需要格式列之外的任何机制**：已实测扫描生产论坛全部 14 条正文，会被 markdown 语法重新解释的 **0 处**；配 `breaks` 后外观与今天一致。`text` 是缺省值，因此不带该字段的客户端与历史数据天然落在纯文本分支。
- **编辑路径不写该字段**：`UpdateTopic` 是**全量替换**语义（四字段都必填都显式写），但 `content_format` 是新增字段，既有客户端（移动端）不带它。若更新路径按「缺省 = text」处理，**移动端编辑一次 markdown 帖就会把格式静默重置成纯文本**。故更新路径不写该字段（保持原值），并有契约测试钉住这条不变式。将来若加 Web 编辑入口，需显式决定「提供则校验并应用、缺省保持原值」。
- **搜索无需改动**：全局搜索走 `LOWER(content) LIKE ?` 子串匹配，markdown 源串里照样能命中正文文字（`**故障码**` 含「故障码」）。
- **列表摘要必须剥成纯文本**：摘要直接渲染源串会露出 `##`、`**`。剥离走**与渲染同一个解析器的 AST 投影**，不写正则——正则与渲染器是两套规则，代码块内的符号、转义、嵌套标记都会与真实渲染不一致。同时也避免在列表里挂十几个渲染实例。
- **移动端本批不改**：移动端论坛正文目前是纯文本直出、不解析 markdown，因此不改它也不会产生跨端不一致（它会照旧显示源串）。补齐行内样式渲染、发帖输入与 `content_format` 消费另立 Issue——它受移动端四门验收约束。
- **外链离开本站需要确认页**：这是唯一一处内容能把用户带离本站的地方，故站外链接经确认页中转、加 `rel=noopener noreferrer nofollow`、并用库的 `isUnsafeHtmlUrl` 拦掉伪协议。链接改写发生在 **AST 层**（`postTransformNodes`），不做 DOM 事后改写；站内链接（以 `/` 或 `#` 开头）直连，不无谓打断。
- **管理端的正文预览不做导航**（`linkPolicy=plain`，链接一律渲染为纯文本）：管理员看的是「学员实际看到什么」而不是要去访问它，因此不需要中转页；顺带去掉一处后台点到外站的入口，也避开了「admin 访问学员工作区路由会被角色守卫弹走」的问题。这是对「站外链接经中转」的**有意收窄**，不是遗漏。
- **子集是真的受限**：表格与脚注不在声明子集内，已在渲染配置里 `disable` 掉（解析器默认带它们）；正文内嵌图片 `![]()` 展开成 alt 文本——图片一律走 `images` 数组。否则「受限子集」只是纸面说法，而移动端并没有对应的块渲染能力。
- **子集补记（#900 / ADR-0046）**：开启公式与 mermaid 图表后，它们**事实上进入了声明子集**——受限子集从「标题/有序无序列表/加粗/行内代码/代码块/引用/链接」扩为**再加 `$$...$$` 块级公式与 ```mermaid 图表**。能力开了，子集描述就得跟着改，否则这份 ADR 与 `CONTEXT.md` 会退化成过时的纸面说法。两点边界：**行内 `$...$` 上游尚不支持**（实测不产生数学节点，见 ADR-0046「已知限制」）；mermaid 固定 `securityLevel: 'strict'`、KaTeX 保持 `trust: false`，raw HTML 仍一律转文本。

## Considered Options

- **一律按 markdown 渲染，不加格式列**：零 schema 变更、零渲染分支。拒绝——实测存量虽然 0 命中，但这条买的是「未来写纯文本的人不会被擅自解释」的表达自由，而不是存量安全；且系统无从区分「他想要列表」与「他随手打了个 1.」。
- **加格式列但由系统区分存量与新帖**（存量 text、新帖 markdown）：语义上等价于「默认 markdown + 一次性迁移」，仍然剥夺了写纯文本的人的选择权。拒绝。
- **`marked` + DOMPurify + `v-html`**：行业常规，改动最小，还能直接复用 `markdown.css` 与既有 `v-html` 写法。拒绝有三条：新增净化依赖与一份要长期维护的白名单（漏一个属性就是一个 XSS）；与仓库「不再有裸 `v-html`」的既有收敛方向相反；移动端走原生组件渲染，Web 走 HTML/CSS，两端渲染语义会分叉。
- **`AST → 自写 Vue 组件`**：结构上免疫（HTML 永不进 DOM），不依赖第三方净化策略，且与移动端 `MarkdownBlock` 模型对称。拒绝——要自己写渲染器、行内样式与全套 CSS 并长期维护，工程量最大，而这些正是 `markstream-vue` 已经提供且已被仓库验证过的。
- **复用 Vditor 作为编辑器**：功能最全、已有组件。拒绝——它是数百 KB 的重依赖，目前只在讲师/管理端包里，拉进学员端会显著增加首包体积；且它的预览走自有 markdown 引擎，会与发布后的渲染结果不一致，直接违反「预览与发布同源」。
