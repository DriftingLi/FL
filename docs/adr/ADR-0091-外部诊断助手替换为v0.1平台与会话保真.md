# ADR-0091: 外部诊断助手替换为 v0.1 平台，会话仍归 FL

- 状态：已接受（2026-11-02）；施工前置未满足——新服务服务账号未取得，`/api/chat` 真实契约（流式与否、溯源形态）无法实测，§决策2 的映射表字段与伪流式策略待实测后钉
- 领域：AI 域 / 外部服务接入（上游交付物换代 + 契约重映射 + 能力退役；承接 ADR-0032 的通道形态，ADR-0029 单 port / ADR-0030 注册表 / ADR-0031 计量闸门不变）

## 背景

ADR-0032 接的是交付包 forklift-assistant（FastAPI + bge-m3 本地向量检索，部署 pve-01 lxc101，`DIAGNOSIS_ASSISTANT_URL=http://172.17.1.23:8000`），端点前缀 `/assistant/*`：`/assistant/api/chat`、`/chat/with-image`（阻塞 JSON，无 SSE）、`/assistant/api/{brands,models,fault-codes}`、`/assistant/static/*`。FL 侧对应实现是第二个 AIModelPort adapter 把阻塞 JSON 按段落切块伪流式，以及四个只读代理。

供应商现交付 v0.1.0「叉车故障诊断与维修助手平台」（公网 `https://forklift-repair-assistant.app.workbuddy.host`，`Server: CloudStudio Gateway`）。**它不是同一套服务的新版本，而是架构级重写**：`/api/health` 返回 `workflow_id_set` / `memory_mode:"official"`，内核是 Agent 工作流平台，不再是本地向量库；路由表整体更名，老端点在新服务上全部 404。2026-11-02 对 openapi.json 实测（11 路由 / 5 schema）：

| 端点 | 匿名 | 实测返回 |
| --- | --- | --- |
| `GET /api/intents` | 可用 | `{brands:[{id,name,tagline,icon,cls,picker}], faq:[{q,a}]}`，`picker ∈ {system,model}` |
| `GET /api/systems?brand=` | 可用 | `{items:[{id,name,icon}]}`（中力 EP：控制器/电池/液压…） |
| `GET /api/faults?brand=&second=` | 可用 | `{items:[{id,name,icon}]}`（林德：插头/驱动/制动…） |
| `GET /api/code_hint?q=` | 可用 | `{status:"known", message:"已识别故障码 E01（… / 电池_BMS系统）", fix, samples}` |
| `GET /api/suggest?q=`、`GET /api/faq` | 可用 | `{items:[...]}` |
| `POST /api/compose {brand,fault,mode?,vin?}` | 可用 | `{sentence:"我的中力 EP叉车（）出现故障现象：…请给我排查步骤、根因分析和维修方案。", mode, brand}`——**纯 prompt 拼装** |
| `POST /api/chat {conv_id,content,image?,images?}` | **401** | 需登录；`conv_id` 为必填整数 |
| `GET|POST /api/conversations`（含 `{id}` PATCH/DELETE、`{id}/messages`） | **401** | 需登录 |
| `POST /api/login`、`/api/register` | — | `Creds{username,password}`，自带账号体系 |

两点决定架构走向：**对话必须登录且按 `conv_id` 有状态**（老服务是无状态、由 FL 转译 chat_history），**且无任何静态资源路由**（老服务的 `/assistant/static/*` 手册图在新服务上不存在）。`/api/compose` 只是把三层点选拼成一句 prompt，不承担生成。

产品口径已定：**替换**老服务（不下线并存），**继续用 FL 账号与 FL 会话**（不引入第二套账号）。

## 决策

1. **上游替换，通道形态不动**：`DIAGNOSIS_ASSISTANT_URL` 改指 v0.1 平台，老 lxc101 服务下线。仍由第二个 AIModelPort adapter 承接（ADR-0029 单 port 语义、routing 按 FeatureKey 分发、计量闸门在最外层单点，三条均不变）。
2. **会话保真：FL 持服务账号 + conv_id 映射表**：后端配置一个新服务**服务账号**，登录换 token 并缓存复用；新增 `assistant_conv_map`（FL session ↔ 新服务 `conv_id`）表，首次对话惰性建 conv。用户侧始终只见 FL JWT，不暴露第二套登录。FL 仍是会话历史的唯一真相源（新服务侧历史仅作为上游上下文，不反向覆盖 FL 消息表）。
3. **不调用 `/api/compose`**：它是无状态的纯字符串拼装（实测毫秒返回、仅回 `sentence`），FL 侧自拼等价且更可控——三层点选 → 拼句 → 走 chat。少一跳网络，也少一处契约耦合。
4. **只读代理重映射**：`/diagnosis/brands` → `/api/intents` 的 `brands[]`（`{id,name}` 映射为 `{value,label}`，并把 `picker` 一并透出，前端据此决定 L2 是「系统」还是「型号」）；`/diagnosis/models` → `/api/systems?brand=`；`/diagnosis/fault-codes` → `/api/code_hint` + `/api/suggest` 组合（**形态变更**，见 §后果）。
5. **手册静态图能力退役**：`/diagnosis/manual/*` 代理与其 SSRF 白名单、adapter 内 `<<IMAGE:>>` 令牌与 `/app/static/`→`/assistant/static/` 路径改写一并退场（新服务无静态路由）。前端对图片来源做兜底，不再假设一定能取到图。
6. **删掉 chat_history 转译与伪流式的历史假设**：老 adapter 的两块核心逻辑（FL 会话轮次转译成助手 `chat_history`；阻塞 JSON 按段落切块伪流式）随契约失效而删除；图片改走 `image` / `images` 字符串字段。

## 备选

- **老新并存、双上游**：拒绝——双份契约维护，且知识库/故障字典会随迭代漂移，同一问题两个答案；用户已明确选替换。
- **为每个 FL 用户在新服务注册账号（账号双轨）**：拒绝——新服务 `conversations` 按登录账号隔离，账号治理、凭据保管与注销链路都要再造一套，且破坏「FL 是唯一账号主体」的既有边界。
- **前端/小程序直连新服务**：拒绝——要过业务域名/服务器域名白名单，且等于在小程序里再嵌一套登录；`.host` 域名的可备案性亦未确认。
- **调用 `/api/compose` 拼 prompt**：拒绝——等价纯函数，多一跳网络与一处契约耦合，收益为零。
- **让供应商加 SSE / 加静态资源端点**：暂不采纳——交付物不在本仓可控范围；先按现契约接入，真需要时另立 ADR。

## 后果

- **施工前置未满足（阻塞）**：新服务服务账号未取得，`/api/chat` 无法发一次真实请求 ⇒ 响应是否流式、溯源资料如何返回、错误码形态全部未知。§决策2 的映射表字段与 adapter 的伪流式策略须实测后钉，**在此之前不写 chat 链路代码**（只读代理与配置项不受阻）。
- **能力损失（须产品认账）**：① 手册图 / 故障配图（移动端 `ai-feature.uvue` 溯源图、Web `assistantImageRender`）失去图源；② 故障码「码表 + 关键词 + 分页」检索降级为「单条识别提示（code_hint）+ 联想（suggest）」，前端 `diag-bar` 的搜索与「加载更多」交互语义要改。
- **新增外部依赖的可用性边界**：新服务在公网 CloudStudio 网关上，可用性不由本项目控制；不可用时前端表现为 SSE error 友好提示（沿用既有外部调用先例，不新增熔断）。
- **配置面扩三处**：URL 改值 + 服务账号 + 密码，需同步 `.env`、`deploy/topology.go`、`deploy/docker-compose.prod.yml`；凭据仍不进 AIConfigResolver（沿用 ADR-0032 口径）。
- **老服务下线是运维动作**：lxc101 容器、`DIAGNOSIS_ASSISTANT_URL` 旧值、nginx 残留挂载的清理不在本 ADR 的代码改动内。
- 若未来新服务补上静态资源或 SSE，只影响 §决策5 与 adapter 内部，端口与消费方不受影响。
