# ADR-0098：市场样本清洗——单模块版本化七规则 + 三段分离 + 身份剥离

- 状态：Accepted（2026-11-19）
- 日期：2026-11-19
- 领域：残值评估 / 数据采集（市场真值）
- 票：#2674（实施）· 父规格 #2671 · 承接 ADR-0097

## 背景

ADR-0097 把标注样本抽出为结构化规格 + 逐字段置信度 + 原始价格，但模型输出里的噪声（批量包价、报废车、占位价、面议/区间报价、车商重发帖、竞价狂热溢价）若直接进校准集，会把「废铁价 / 包价 / 单台虚高价」当成单台使用价值真值，系统性污染残值率标签。wayfinder map #2661 的「标签口径」（#2666）与「采集器运行架构」（#2670）两票已裁定七条硬规则与三段分离；#2674 把这份裁定落成单一版本化清洗模块。

## 决策

**一、采集 / 清洗 / 入库三段分离，清洗是纯函数。** 采集层只 fetch + 原始留底，抽取（ADR-0097）与清洗都是独立的纯函数阶段，入库只做写。清洗吃一条已抽取的 `RawSample` + 可选的已入库样本列表（去重信号），产出清洗后的样本与入队原因列表；不碰网络、不碰 PG、不改入参。因此「重跑清洗不用重爬」：新增 `collector clean reclean` 子命令从 PG 读回已入库行，按当前规则版本重算清洗列与结构字段，抽取版本 / 匹配 / 标签列不动，原文留底（除身份剥离）不重写。

**二、七条硬规则集中在单一模块 `collector/clean/rules.py`，版本化。** `CLEAN_VERSION`（当前 `v1`）与抽取的 `PROMPT_VERSION` 各自独立——两代规则可分离重跑。清洗结果统一盖上 `CLEAN_VERSION` 并落库到 `market_transactions.clean_version`（迁移 000065），使「这行是哪版规则判的」可审计、规则升级后可按版本分离重跑；抽取侧对应 `extraction_version`。规则按优先级串行：① 批量包价剔除（无逐台字段）；② 报废注销 / 无电池车剔除（废铁价 ≠ 使用价值）；③ 占位价量级过滤（吨位 × 量级下限，滤「7 吨挂 8 元」）；④ 面议丢弃；⑤ 区间报价丢弃（单值字段是幌子）；⑥ 车商批量帖去重（图哈希 / 描述相似度 `difflib` / 同公司跨城）；⑦ 溢价 > 评估价 × 1.5 **标记降权而非剔除**。剔除类写 `clean_status='rejected'` + `rejection_reason`（具名常量，如 `bulk_lot_no_per_unit`）；溢价写 `clean_status='cleaned'` + `premium_anomaly=true` + 入队 `premium_anomaly`，实际 0.5 降权系数留给 #2675 校准拟合配置（本票不引权重列）。清洗得率不设硬门槛（#2662 已裁），本模块只如实产出状态。

**三、买受人身份入库剥离，原始留底亦不含身份。** 拍卖确认书的买受人姓名 / 竞买号（及证件号等）从 `structured_specs` 与 `raw_description` 两处剥离后才落库；即便没抽成结构化字段，原文 body 里带标签的行内身份值（`买受人 张三` / `竞买号 A1234`）也以正则替换为占位符脱敏，只保留标签与非身份正文。这是 spec #2671 对 PIPL 匿名化口径的延伸——只留价格 / 日期 / 规格。剥离与清洗在同一纯函数里完成，重跑清洗同样会再剥一遍（幂等）。

**四、去重信号取「抽取字段 + 原文」，不新增迁移列。** `image_hashes` / `seller` / `city` 从 `structured_specs` 读，描述相似度用 `difflib.SequenceMatcher` 比 `raw_description.body`；命中重复写 `reason=duplicate_image_hash` / `duplicate_description_similarity` / `duplicate_same_company_cross_city` 并剔除。同一 `source_url` 不与自身比对。不新增专用去重列——这些字段本就是抽取产物，再落一列是第二份真相。

**五、契约测试用录制 fixture 打桩，纯判定用同 runner。** 单一 seam 仍是「fixture HTML 进 → 真 PG 行出」：注入录制抽取输出（确定性、不测 prompt 质量），断言行上 `clean_status` / `rejection_reason` / `premium_anomaly` / 身份剥离 / 抽检队列原因；重跑清洗用 e2e 直接改一行结构字段后调 `reclean`，断言重判为 rejected 且原文来源不变。七规则 / 去重 / 身份剥离的纯判定用 `python3 -m unittest discover`（与 deploy/tests 同 runner，prior art 见 ADR-0096）。

## 被否备选

- **清洗塞进采集 parse 阶段**：采集层就会做语义判断，重跑清洗必须重爬，违背三段分离；独立纯函数才能「重跑不重爬」。
- **每条规则各建一个模块 / 可插拔插件框架**：七条规则同属一个版本化决策单元，拆散反而让版本与顺序难对齐；单模块 + 具名常量足够。
- **溢价样本直接剔除或剥夺标签资格**：wayfinder #2666 / #2668 裁定是「标记降权而非静默剔除」（竞价狂热反向污染要可审计），剔除会丢失竞价样本的存在证据。
- **买受人身份只从结构化字段剥离、留底原文带身份**：违反 spec 的 PIPL 延伸口径，留底亦需匿名化。
- **去重落独立 image_hash / seller / city 列**：与抽取字段重复，是第二份真相；复用抽取产物即可。
- **清洗得率设通过率门**：#2662 已裁「记录为事实、不设硬门槛」，不立门。

## 后果

**收益**：①噪声样本按七规则自动分流，剔除原因逐行可审计、溢价样本可标记降权，校准集不再被废铁价 / 包价 / 竞价虚高污染；②三段分离 + 纯函数让规则升级后可用同一批留底行重跑，不必重爬；③买受人身份在入库即剥离，满足匿名化口径；④清洗版本与抽取版本各自独立，两代质量可分离。

**代价**：①新增 `collector/clean/` 子包与若干录制 fixture，代码面增大；②描述相似度用 `difflib`（启发式、阈值 0.92 为初版经验值），边界样本可能误判——靠抽检队列兜底，不设硬门槛；③`reclean` 是破坏性重写清洗列（按规则版本重算），执行前应确认下游是否已消费旧结果（本票阶段下游 #2675 尚未落地，无消费方）。

**实施边界（本票不做）**：分层匹配器（7→4→3）、残值率标签计算与实际降权系数拟合、校准拟合管线、抽检队列消费 / 复核 UI、daemon 增量模式——全部在后续票（#2675 起）。批次入库（`run_batch`）只在同批样本间做去重信号比对；跨「已入库语料」的去重由 `reclean` 读回全量样本完成（daemon 增量模式的入库即去重在后续票落地）。三形态去重语义本身由录制 fixture 单测钉住。本票只交付「抽取结果 → 清洗 → 写回 / 入队」这一段；评估记录表与评估路径零改动。
