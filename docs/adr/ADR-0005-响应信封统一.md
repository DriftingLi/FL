# ADR-0005: 响应信封统一（全后端单一契约）

- 状态：已接受（2026-08-05，architecture-review 全量优化）
- 领域：全系统 —— 响应契约

## 背景

同一进程存在两套响应信封：

- 主体系 `pkg/response`：`{code, message, data}`，成功 `code = HTTP 状态码`（200）；
- 估值模块 `handler/common.go`：`{code, message, data}`，成功 `code = 0`，业务失败 HTTP 200 + 40000 系列业务码。

`api/ai_assistant.go`（主体系模块）反向依赖估值模块的响应封装（40 处 `vhandler.*`）——唯一跨模块泄漏。前端要同时兼容两种成功判定（`code===0` 与 `code===200`）。

## 决策

全后端统一到 `pkg/response`（code = HTTP 状态码）：

- 估值全部 handler 迁移到 `pkg/response`；业务失败按语义映射 HTTP 状态（400/404/500），40000 系列业务码删除；
- `ai_assistant.go` 回归主体系信封，移除对估值模块的依赖；
- 估值模块独立信封实现（common.go）删除；
- expand–contract 排序：先迁移全部调用点（双信封并存，CI 保持 green），后删除旧信封；
- 前端成功判定迁移（`code===0` → `code===200`）与三客户端统一合并为一次改动（见 ticket 11）。

## 后果

- 前端与测试只认一种成功判定；
- 跨模块泄漏消除（估值模块不再被主体系依赖）；
- 代价：估值前端成功判定迁移一次（与前端客户端统一同批）。
