# ADR-0017: 学习位置与章节完成状态

- 状态：已接受（2026-08-19）
- 领域：课程学习 —— 学习进度 / 继续学习（移动端缺失 API P0，issue 见《移动端缺失API整理.md》2.2/2.3/3.1/3.2）

## 背景

移动端「继续学习」与「我的课程」需要：按课程查询最后学习位置（章节 + 播放位置 + 时间）；进度上报需要秒级时长、播放位置与显式完成。原 `study_record` 双轨记录（课程级 `chapter_id IS NULL` 承载课程进度、章节级承载时长自动完成）无位置字段；上报 body 仅 `chapter_id + duration(分钟)`。

## 决策

- **不建新表**：复用 `study_record` 双轨模型，迁移 000004 加三列——
  - 章节级：`video_position`（该章节最后播放位置，秒）
  - 课程级：`last_chapter_id` + `last_studied_at`（最后学习章节与时间戳；区别于按天的 `study_date`）
- **章节完成单一事实源 `progress >= 100`**：时长自动完成（累计达 `chapter.duration` 阈值）与上报 `completed: true` 显式完成收敛于此，不新增 completed 列。
- **上报兼容映射**：`POST /api/course/:id/progress` 新增可选 `duration_seconds`（>0 优先，按 ceil 换算分钟累加，秒级精度不落库）、`video_position`、`completed`；旧 body（分钟）不受影响。带章节的上报同步刷新课程级 `last_*`。
- **查询收口**：`loadLearningPosition`（course_service 包级函数）为「课程详情增强」与「单课程学习详情」共享数据源；「我的课程」走 batch 回填（课程级记录一行一课程 + 元信息/章节计数/完成计数/最后章节标题与位置全部批量，无 N+1）。

## 新端点

- `GET /api/student/courses`：我的课程（按 `last_studied_at` 倒序）+ `continue_learning`（最新 top1，合并进响应，不单开路由）。
- `GET /api/student/courses/:course_id`：单课程学习详情（每章 progress/video_position/completed，未学章节零值并入）。
- `GET /api/course/:id` 增强：`is_enrolled`（以存在学习记录代理报名语义）、`completed_chapters`、`last_chapter_id`、`last_position`、`last_studied_at`。

## 明确不做

- `learning-progress` / `learning-history` 新端点（profile + records + study-stats 已覆盖）。
- `continue-learning` 独立路由。
- 移动端对接（另行任务）。

## 后果

- 章节级记录的 `study_date` 仍是「最后上报日」，位置语义统一走课程级 `last_studied_at`（时间戳）。
- 历史数据兼容：存量课程级记录 `last_*` 为 NULL（列表排序排后）；上报一次即回填。
