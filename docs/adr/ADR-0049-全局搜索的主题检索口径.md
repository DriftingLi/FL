# ADR-0049: 全局搜索的主题检索口径——可检索面 / 落点 / 命中片段 / 排序 / 检索事实

- 状态：已接受（2026-09-14，grilling 定案七条口径）
- 领域：搜索（Web 培训域学员工作台 + 后端 `/api/search`）
- 面：本 ADR 只覆盖 Web 与后端；移动端候选已转 issue #979（照根 `AGENTS.md`「架构评审范围」）
- 来源：候选清单 `docs/plans/全局搜索升级候选-方案.md`（本地不入库，S/W 候选与 `文件:行` 证据索引）

## 背景

ADR-0018 引入全局搜索时的形态是「四分区 `LOWER LIKE` 聚合 + 各分区 top5 / 指定类型分页」，同时自认「搜索为顺序 LIKE，数据量大后可再演进 pg_trgm/全文索引」。今天暴露的断点分三类：

- **结果不可用**：题目与内容精选在 Web 无落点，点了没有任何反馈（`SearchPage.vue:191-199`，`Favorites.vue:162-172` 是同款系统性缺口）；排序与相关度无关（course `course_id ASC` / question `id ASC` / content `content_id ASC` / topic `id DESC`）；摘要取正文**开头** 80/50 字（`favorite_service.go:268-274`），命中在中后段时摘要与关键词无关，且论坛 markdown 源串原样露出标记。
- **覆盖不足**：内容面四个（章节正文 / 内容精选 / 论坛正文 / AI 助手回答）里只覆盖两个——章节正文搜不到、论坛**回复**搜不到、课程 `description` 作为摘要展示却不参与匹配。
- **无证据**：全仓零搜索埋点，排序与分区取舍只能靠推断。

另有两处口径缺口（与本次探索相互独立、但会被搜索放大）：关键词里的 `%`/`_` 未转义即拼进 `LIKE '%…%'`（`search_service.go:89`）；题目按 id 直取的读路径不过题库池口径——`GetQuestion` 是 `First(&q, id)` 且 `newQuestionDTO(&q, true)` 回传答案/解析/参考答案/评分标准（`question_service.go:362-370`、`question_dto.go:55-59`），任何登录学员可读 draft 题与源标记真题题。

## 决策

1. **职责 = 主题检索**（词条见 `CONTEXT.md`）。判据是**学员输入时心里有什么**：拿一个术语找「平台上讲了这件事的什么」。因此首要质量是**命中可解释**，不按「最近访问/熟悉度」排序（那是导航），也不把热词/联想/推荐位当必备能力（那是发现面，需另立决策）。
2. **可检索面两条判据缺一不可**：① 内容对**搜索者**可见（过当前证件 / 题库池等既有作用域，不越权益与会话私有）；② 命中后能给**落点**，学员能打开。**「搜到但打不开」不是降级呈现，而是不合格**；`AI 助手回答` 是内容面但**不可检索**（会话私有）。
3. **覆盖面 = 内容面全覆盖（AI 助手回答除外）**：新增**章节**分区（落点 = 章节学习页）；**论坛回复**纳入 topic 区分命中，结果仍指向主题并标注「命中在回复」；补现有分区匹配面（课程 `description`、内容精选正文）。资料侧（`material` / `contribution` / 真题卷名）**不捎带**——它在公开路由与能力门之间有真实冲突（见「明确不做」）。
4. **落点是硬口径，本轮补两处**：① 内容精选在**训练域**新增详情页（后端公开端点 `GET /api/featured-content/:id` 已在，顺带修好收藏页同款死链；不跳官网门户——那是独立仓库、URL 约定在本仓不可验证，且会把学员带出工作区）；② 题目新增承载页（复用练习单题栈），**前置**修掉按 id 直取的可见性口径（draft / 源标记真题题 / 非当前证件一律 404，题干选项答案解析同此）。
5. **结果形态 = 分区并列、区内排序**。**一级键统一为命中位置**（标题命中优先于正文命中）；**二级键按内容性质分派**——常青内容（课程/章节）用编辑信号 `sort_order → is_hot → is_featured → id`；时效内容（论坛帖）用 `last_reply_at`，被采纳 / 帖子精选优先；内容精选用 `published_at`；题目用稳定序 `id DESC`（无可靠热度信号，且不把「被做过多少遍」暴露成排序信号）。**不引入跨类型统一排序**——内容面之间没有可比尺度，混合排序要么人为加权（不可解释）、要么改用热度（那不是相关度）。
6. **命中片段 = 命中窗口 + 命中位置**。后端在**源串**上定位首个命中、取前后各 N 字窗口，回传原文片段与命中位置标记；**markdown → 纯文本的投影与关键词高亮由各端用与自身渲染同源的实现**完成（ADR-0044 的同源原则；Web 用 `utils/markdownText.ts`，移动端现有 `utils/markdown.uts:stripInline` 的正则路径是 ADR-0044 点名的反模式，须在其自己那一侧修）。契约**不承载投影规则，也不承载命中区间下标**——两端的本地搜索历史与投影实现都不该被契约钉住。
7. **检索事实匿名，搜索历史留端上**。服务端只记关键词 + 各分区命中数 + 时间，**不记 user_id / 当前证件 / 设备**（照「属地」的最小化先例：不指向人、不做二次用途、不做画像）；搜索历史是个人意图痕迹，只留在各端本地，不入服务端。

## 明确不做

- **资料侧分区**（学习资料 / 资料投稿 / 真题卷名）：搜索是公开路由而资料需 JWT、真题卷有按套权益门禁。把它们纳入要么改 `OptionalAuth`、要么让分区对未登录降级——ADR-0047 §4 已把「公开路由改可选认证」标为**独立决策**，不被「扩分区」顺手带走。
- **热词 / 联想 / 推荐位**：发现面能力，需要数据与另立决策；本 ADR 只把「检索事实」备好。
- **pg_trgm / 全文索引**：延续 ADR-0018 结论，当前量级可接受；落地时写实测触发条件（P95 或相关表行数阈值），不在本 ADR 拍数。
- **AI 助手回答入搜索**：会话私有，可见性口径与平台公开内容不同。
- **属地入搜索**：`CONTEXT.md`「属地」词条已定「不做任何二次用途（不入搜索 / 筛选 / 排序）」。
- **混合单列排序、后端统一投影**：理由见决策 5 / 6。
- **移动端实施**：转 issue #979。

## 约束

- **题库池是学员端题目的可见性口径，覆盖每一条读路径**（作答抽题、搜索结果、按 id 取详情）；`draft` 与源标记真题题对学员不可见，题干、选项、答案、解析同此。
- **证件作用域**：公开路由保留客户端显式传参（ADR-0047 §4）；移动端搜索漏传 `credential_id` 属实现缺陷（issue #979），不改服务端形态。
- **契约演进**：搜索响应类型已在生成面（ADR-0048 片六），新增字段走 handler 注解 → `cd backend && go run ./cmd/gen-apitypes` → `frontend/src/api/search.ts` 别名同步。
- **排序留在 SQL**：不得先分页再在内存里排（分页正确性）。
- **章节分区的文本可得性边界**：可匹配 `chapter.title/content/description`；PPT / 视频型章节的正文在幻灯片图片与附件里，本期不覆盖（要做需另立「文本提取」决策）。
- **移动端不因本 ADR 改口径**：两端对同一端点各自适配，移动端修自己那一侧。

## 后果

- 「搜到之后不可用」这一类问题在口径上被关闭：无落点者不得进结果，故内容精选与题目必须补落点才能继续留在分区里。
- 新增**章节**分区后，「内容面」与「搜索分区」正式解耦（可检索面是独立划分），后续再加分区（如资料侧）必须过一次两条判据的评审，而不是顺手加一个 `case`。
- 契约保持薄：片段是源串窗口而非成品文本，投影留在端上——代价是两端可能显示不同（同源原则的必然），收益是契约不携带任何渲染规则。
- 排序从「主键序」变为「命中位置 + 内容性质」两级，课程/章节不再被新旧绑架；代价是每分区一条独立排序口径需要各自测试。
- 检索事实表落地后，「零结果词」第一次可见；但它**不可反查人**，因此不能用于任何个性化。

## 落地回写（2026-09-14，票 #980–#984 实施）

实施中与上文措辞不完全逐字对应的落地形态登记于此（口径不变，只写清「实际长成什么样」）：

- **契约只增不破**：`SearchItemDTO` 新增 `snippet`（命中窗口，源串原文）与 `hit_field`（title|body|reply），另加 `parent_id`（章节结果所属课程 ID，其余类型 0——章节落点需要课程与章节两个参数）。**`summary` 保留不动**：移动端老客户端仍读它（ADR-0048「只增不破」），决策 6 的「摘要改成命中窗口」在 Web 端由 `snippet` 承载，`summary` 退化为兼容字段（前端在 `snippet` 为空时回退）。
- **题库池覆盖的读路径实际有两条**（#981）：`GET /question-bank/questions/:id` 按能力分流（`question.author` / `question.review` 走编辑面可读 draft，其余走池口径 404）；`POST /practice-mode/submit` 加池口径守卫——提交即回传答案与解析，属同一族读路径。**`WrongQuestionService.RedoWrongQuestion` 有意不动**：它以「本人错题记录存在」为前置，而错题记录只可能来自池内题目。
- **内容精选公开详情端点登记进 featured 域**（ADR-0048 决策 1）：训练域 Web 成为该公开端点的第二个消费者（门户之外），故把 `GET /featured-content/{id}` 与 `service.FeaturedContentDetailDTO` 登记进声明表并补齐注解 data 指认——生成物因此多出详情类型，供落点页消费。
- **零结果词查询面用 `admin.access` 能力**（运营面读匿名事实）；事实表仍无任何指向人的列，并有结构性测试（字段名含 user/credential/ip/device/session 即红）钉住。
- **排序二级键的实际形态**：课程 `sort_order → is_hot → is_featured → course_id`；章节 `order_num → chapter_id`；题目 `id DESC`；内容精选 `COALESCE(published_at, created_at) DESC`；论坛帖 `is_featured DESC → 已采纳优先 → COALESCE(last_reply_at, created_at) DESC → id DESC`。一级键统一为「标题命中优先」（`CASE WHEN <标题命中> THEN 0 ELSE 1 END`，参数化，用户串不入 SQL 文面）。
- **匹配面**：题目分区仍**只**匹配题干（解析/答案不进匹配面，符合「明确不做」）；课程加 `description`；内容精选加正文；论坛加**回复正文**（`EXISTS` 子查询，命中标 `reply`）。
- **移动端零改动**：本轮全部改动落在 `backend/` 与 `frontend/`；移动端候选仍由 issue #979 承载。
