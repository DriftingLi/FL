# ADR-0063: 外部诊断助手图片令牌归一与静态根放宽

- 状态：已接受（2026-09-22）；修订 ADR-0032 §决策5 的「手册子路径白名单」措辞与实现，其余条目继续有效
- 领域：AI 域 / 外部服务接入（智能维修诊断的图片面；承接 ADR-0029 单 port、ADR-0031 计量闸门、ADR-0032 传输通道、ADR-0033 来源持久化、ADR-0046 渲染口径、ADR-0048 契约 codegen 边界）

## 背景

交付方发布 forklift-assistant `20260921`（旧现网为 `20260904`）。2026-09-22 在 pve-01 lxc101 起 8001 临时容器把两版响应逐项实测（原始样本存 `.scratch/assistant-20260921/`，并已转成本仓测试夹具），结论：

- **接口面零改动**：`main.py` 与旧版字节级相同，7 个端点、参数、`{code,data}` 信封、`/assistant` 前缀全部不变；响应只**增**字段（`data.answer_images` 等，旧版 20 键 → 新版 21 键）。
- **唯一真破坏在图片表达**：正文 `sop_text` 不再有 markdown 图片，改为 `[IMG:image_id]` 裸令牌，URL 全部搬进 `data.answer_images[]`（实测一条回答 5–17 个令牌，中文案例目录 `/assistant/static/fault_images/制动系统/…png`）。我们只解 `sop_text + answer_sources` ⇒ 令牌会原样进 SSE 与落库正文：Web 在 `html-policy="escape"` 下按字面渲染、移动端正文是纯文本，学员会看到 `img_ab12cd34ef56` 且一张图都没有。
- **旧版图片其实本就是坏的**：旧正文内联的是 `/assistant/static/manual/…`，而 ADR-0032 已下线助手公网子域 ⇒ 该路径在学员侧域名下 404（实测确认，非推断）。
- 来源面不变坏：`answer_sources[].text` 的 `<<IMAGE:…>>` 两版都是 `/assistant/static/manual/` 形状（交付方入库代码写的是 `/app/static/`，实测未漂进 sources），但其标记可带 `| 描述:xxx` 后缀；`answer_images[].file_path` 是交付方构建机 Windows 绝对路径（`E:\temp\…`，不得读用）。
- 运维事实：pve-01 当日 10:10 内核升级重启后，lxc101 **因未配 `onboot` 停摆 4 小时**无人察觉（容器自身 `--restart unless-stopped` 只在 LXC 起来后才生效）。已补 `onboot: 1`；存活告警另票。

## 决策

1. **图片表达在 adapter 内归一（不外扩）**：`normalizeDiagnosisImages` 把 `[IMG:id]` / `<<IMAGE:url|描述:c>>` / `![](/app|assistant/static/…)` 三种形状统一成 `![alt](本站代理 URL)`，发生在伪流式切块与来源容器写入**之前** ⇒ SSE、落库正文、历史回放、Web、移动端读到的都是同一份归一结果，三端零改动。**未知 image_id 丢令牌**：宁可少一张图，也不把内部标识露给学员。理由：端口签名与 `DiagnosisSource` 字节锁都不动，且不依赖移动端发版节奏。
2. **静态代理放宽为双根，SSRF 强度只增不减**：`resolveStaticSubpath` 用逐段白名单（`^[\p{L}\p{N}][\p{L}\p{N}_\-.]*$` + 扩展名白名单）替换旧 ASCII 正则，静态根仅 `manual` 与 `fault_images`；**「绝对形状一律拒绝、strip 唯一在前端完成」这条不变式保留**，改的只是「相对子路径可以是带根形状，也可以是无根旧形状（恒归 manual）」。无根分支永久保留 —— ADR-0033 明令不回填，历史行里的旧标记形状不会消失。
3. **本站代理是图片唯一出口**：AI 生成的正文里指向外部主机的图片一律丢弃（外链图 = 学员浏览器被第三方内容驱动，是追踪面）；不重开助手公网子域、不在 nginx 直挂案例图（`/kbimg/` 先例看过但不用：图片须留在 OptionalAuth 之后，且不得混进计量面，ADR-0031）。
4. **契约真值改由线上夹具钉**：`fakeDiagnosisServer` 原先用 Go 类型**回编码**响应 ⇒ 厂商改键名只会「解析成零值」而恒绿。新增 `raw` 通道 + 真实抓包夹具 + `TestDiagnosisWire_KeySetLock`（`data` 与 `answer_images[]` 键集相等断言）；生产解码仍保持宽容（`diagnosisCode`/`diagnosisSourceID` 那套容忍不变）。
5. **来源前缀归一放后端单点**（`/app/static/` → `/assistant/static/`），不在 Web/移动端各加一条规则 —— 一处判定，三端不可能漂移。

## 备选

- **透传 `answer_images`（新 SSE `images` 事件 + 命名类型 + 持久化列 + 三端渲染）**：拒绝——为表达差异铺 5 个面，且 SSE 面按 ADR-0048 决策 6 不在 codegen 内（新事件手写无锁）、历史回放要新列而 ADR-0033 不回填，还硬依赖移动端发版节奏。保真收益（`anchor_type`/`step_no` 排版语义）当前无消费面。
- **只换知识库不换后端**：曾作为应急档评估，实测成立（旧镜像 + 新挂载可读新库，dim 1024、故障码 34→1193），但拿不到案例图且仍无正文图片 ⇒ 对本轮目标不够。
- **要求交付方回退旧形态或支持 SSE**：拒绝——同 ADR-0032 对 SSE 的裁决，交付物形态不由我方契约驱动。

## 后果

- 顺带修好一条存量缺陷：旧版正文内联的内网图片改指本站代理后可显示；`DiagnosisSources.vue` 的 PDF 链接 `#page` 锚点按其自身注释承诺真正保留（此前被正则丢掉）。
- 令牌语法是厂商可控面：改名即夹具红（键集锁），改语义（如把 URL 放回正文）则归一函数需并行扩展 —— 本 ADR 是下一次复核的入口。
- SSRF 面白名单从 ASCII 放宽到 Unicode 字母/数字：仍是**白名单**（`..`、隐藏段、空段、`\ % ? # ; :`、NUL 天然落网），DeepSec 与 `--all` 消费者守护照常跑。
- 图片请求经我们后端流式代理，不计入计量（`DiagnosisProxyService` 从来不在闸门内侧），与 ADR-0031 一致；缓存头仍 1 天。
- 外部服务单点仍不做熔断（ADR-0032 裁决不变），但「无 onboot 导致 4 小时静默停机」登记为运维债：存活告警与交付方镜像绑定 `0.0.0.0` 的问题（两版都只写 `127.0.0.1`，我们靠自研 pve 启动脚本纠正）各自另票。
