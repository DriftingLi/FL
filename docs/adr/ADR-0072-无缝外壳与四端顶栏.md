# ADR-0072: 无缝外壳与四端顶栏

- 状态：Accepted
- 日期：2026-10-10
- 关联：#1619（本决策的实施票）；#1618（管理端权限，导航按其运行时能力集过滤）；#1620（管理端标签栏，挂本外壳的内容列顶部）；ADR-0047 §2（页面描述符是导航与可见性的单一事实源）；`docs/agents/ui-conventions.md`（UI 词汇与 Tailwind 边界）

## 背景

四个工作区（学员 `TrainingLayout` / 讲师 `TutorLayout` / 管理 `AdminLayout` / 招聘 `RecruitLayout`）共用 `layouts/SidebarLayout.vue`，残值域 `ValuationLayout` 是独立布局。改造前的形态与问题：

1. **没有顶栏**：身份区（头像 + 昵称 + 角色徽标 + 退出登录下拉）长在侧栏顶部；明暗切换是一个**固定浮动按钮**（`ThemeToggle fixed`）；移动端靠左上角 44px 的浮动按钮（`.mobile-fab`）唤出侧栏，内容区还为它预留了 `padding-top`。
2. **侧栏恒深**：三个调用方显式传 `sidebar-theme="dark"`、`SidebarLayout` 默认值也是 `dark` —— 侧栏在明暗两种主题下都是石墨青暗底（"2026-08-31 起统一三端恒深石墨青侧栏"），`AppSidebar` 里 19 条、`AppSidebarItem` 里 4 条 `.is-dark` 规则维护它。
3. **接缝明显**：侧栏底色是 `--color-bg-card` + `border-right`，主区是 `--color-bg-page`；深色模式下侧栏（`#0B1120`）比主区（`#0F172A`）还深一档，两块表面之间总有一条可见的缝。

## 决策

**一、四端统一换新外壳（棋盘格）**，估值端不动：

- 顶栏横贯全宽、`fixed`：**左格**（身份：头像 + 昵称，纯展示）宽度与侧栏**同源**（都用 `--sidebar-width` / `--sidebar-collapsed-width`，侧栏收起时左格一并收窄到只剩头像）；**中区**是工作区控件插槽（学员端放 `CredentialSwitcher`）；**右区**是工具位（通知入口 + 单一用户菜单）。
- 侧栏从**顶栏下沿**开始，保持竖向连续；折叠按钮仍留在侧栏底部。
- 顶栏与侧栏都 `fixed`，只有内容区滚动。

**二、无缝外壳**：外壳三块（顶栏 / 侧栏 / 内容区底）统一 `var(--color-bg-page)`，侧栏去掉 `border-right` —— 接缝靠「同色」消失；层次全部由内容区里的卡片（`bg-card`）承担。

> **改判（#1629，线上截图驱动）**：`完全无缝` 被推翻 —— 顶栏与侧栏/内容区**同底**保留（背景仍靠同色融为一体），
> 但边界改由**十字细线**明示：横线在顶栏下沿（`.app-topbar` 的 `border-bottom`），竖线沿侧栏右缘
> **贯通顶栏**（`.topbar-left` 与 `.app-sidebar` 各自的 `border-right`），二者在「顶栏下沿 × 侧栏右缘」交叉。
> 起因有两个可复现的缺陷：① 顶栏中区的证件切换器三行内容溢出 56px 顶栏、且溢出部分**没有底色**，
> 表现为「透明的文字压在内容卡上」；② 三块完全同底时，左上角身份区与侧栏、顶栏与内容区在视觉上分不开。
> 同批修复：证件切换器加 `compact` 变体（顶栏里只留选择器）；顶栏中区 `overflow: hidden` 兜底。
>
> **补漏（#1627，2026-10-10 线上截图驱动）**：只规定「同色 + 去边框」并不足以让接缝消失 ——
> 侧栏导航列一旦溢出，原生滚动条就**紧贴侧栏右缘**，成了整屏最显眼的一条竖线。逐像素实测（1920×1080
> 截图）：该线位于 x=293..299、y=112..904、色值 `#CBD5E1`（= 全局 `--color-border-dark` 的 6px 滑块），
> 而两侧底色其实**完全相同**（`#F8FAFC`）。故本决策追加一条硬约束：**外壳内部不得出现可见的滚动条**
> —— 侧栏导航列隐藏滚动条（滚轮/触控板/键盘/拖拽照常），横向滚动条同理（本仓 `MarkdownToolbar` /
> `UiSegmentTabs` / `AdminTabBar` 已有先例）。

**三、恒深侧栏体系整体退役**：删 `SidebarLayout.sidebarTheme` prop、`AppSidebar` 的 19 条与 `AppSidebarItem` 的 4 条 `.is-dark` 规则、三个调用方的 `sidebar-theme="dark"`、`--color-bg-sidebar` / `-hover` / `-active` 三个 token，以及 `CredentialSwitcher` 的 `theme` prop 与其 6 条 `.is-dark` 规则（它原为「随侧栏配色」而存在）。

**四、交互归属**：身份留在顶栏左格（不可点）；**主题（外观三态）与退出登录收进右上角用户菜单**；角色徽标从常驻改为收进菜单顶部只读行（按角色的四档配色保留）。

**五、移动端**：汉堡进顶栏左格（同一个开关：开/关抽屉），删 `.mobile-fab` 与内容区为它预留的 `padding-top`；遮罩从顶栏下沿开始，抽屉打开时顶栏仍可点。

## 理由

- **为何四端一起改，而不是只改三端**：`SidebarLayout` 是**同一个共用件**。只改三端就得给招聘端留一条旧外观基线，共用件里从此有两套外观同时维护、且只有一套有人天天看；这与 `ui-conventions` 的「变体一律追加覆盖」初衷（避免分叉）相反。
- **为何统一到 `bg-page`（而不是 `bg-card` 或新造 shell token）**：内容区本来就是 `bg-page`，改动只落在侧栏与顶栏两处；卡片仍是 `bg-card`，浅色 `#FFFFFF` on `#F8FAFC`、深色 `#1E293B` on `#0F172A` 都拉开一档，深色下不塌。新造 `--color-bg-shell` 首期值与 `bg-page` 完全相同，只多一层间接。
- **为何退役而不是「保留 prop、默认跟随主题」**：无缝之后 `is-dark` 分支**没有任何调用方，也没有测试覆盖** —— 留着就是无人走的分支，改错了没人发现。需要时从 git 历史取回（本仓既有先例：`RoleRequired` 退役）。
- **为何身份在顶栏、交互在菜单**：一处职责一个入口。身份（我是谁）是**只读展示**，放在左格与侧栏同宽的位置上；交互（换主题 / 退出）是**动作**，收进右区菜单一处 —— 退出是破坏性动作，留在菜单里可避免误点（它原本也在菜单里，只是从侧栏顶部挪到了顶栏右上）。
- **为何「外观」用平铺三项而不是子菜单**：Element Plus 2.14 的 dropdown **不支持嵌套子菜单**（`dropdown/src/dropdown-item.mjs` 无嵌套渲染），平铺三项 + 分组标题表达同一语义（单选、当前项打勾）。
- **为何 `FacetItem` 的 hover 一并改判**：它 hover 到 `--color-bg-sidebar-hover`（深石墨），而它实际渲染在**内容区浅表面**上（`CourseList` / `TutorCourses` / `CourseCatalog`）——深底配深字本就是错位配色；token 退役正好把它改判为「比所在表面深一档」的 `--color-bg-page`。

## 后果

- **有意突破 `ui-conventions` 的 R2**（「改共用件时新特性一律走 prop + 默认值等于现状」）：本次是**基线整体变更**（四端一起换），不是给共用件加可选特性；理由见上，规则本身不变。
- **主题入口位置变化**：四端由顶栏用户菜单承载；`ValuationLayout` / `AuthPageShell` / `ChatPageShell` 保持各自入口（本次不动）。`ui-conventions` 的「主题切换按钮要覆盖所有布局」按新形态改写。
- **术语口径**：「三端」在本仓指 学员 / 导师 / 管理；而 `SidebarLayout` 的实际覆盖面是**四端**（多一个招聘端）。本决策与后续票一律按**四端**表述，避免按字面漏改。
- 侧栏从「自带深色」变成「跟随主题」：深色模式下侧栏与内容区同底，导航项的层次改由 hover/激活态承担。
- 移动端不再有浮动按钮；内容区顶部让位量由固定值（`44px` + padding）改为顶栏高度变量。
- 后续（#1620）：管理端标签栏挂在**内容列顶部、贴顶栏下沿**，随顶栏一起固定 —— 侧栏的竖向连续性不被打断。
