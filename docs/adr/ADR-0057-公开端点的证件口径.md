# ADR-0057: 公开端点的证件口径 —— /api/catalog/tree 与 /api/tags 不挂 CredentialScoped

- 状态：已接受（2026-09-17，第十一波后续票 #1121 定案）
- 领域：证件作用域 / 公开读面 / 跨端契约
- 前置登记：ADR-0056 §2（第十一波把这两类例外记为「不改端点鉴权」的例外，本 ADR 给它落点并给出决策）

## 背景

「当前证件」的分区口径由 `middleware/credential_scope.go` 的 `CredentialScoped` 单点承载，解析序写在它的文档注释里（`:24-28`，实现 `:31-51`）：

1. 显式 query `credential_id` > 0 → 用它（保留「显式浏览其他证件」的既有用法，`:33`）；
2. 否则用**登录学员**的服务端当前证件（`hrwai_users.current_credential_id`）——兜底分支要求 `roleOf(c) == string(authz.RoleStudent)`（`:42`），非学员角色不解析；
3. 都没有 → 不设置上下文值，端点按「不分区」处理（`:28` 第 3 条）。

落到公开读面上，本轮核实存在**两类成因不同的例外**（ADR-0056 §2 的登记只写了结论，这里补上机械事实）：

**类别 A：未挂 `CredentialScoped`，handler 自读 query。**
`/api/catalog/tree`（`api/training_catalog.go:36`）与 `/api/tags`（`:38`）注册在 `/api` 组上、**没有**任何证件中间件；两个 handler 各自用 `queryIDPtr(c, "credential_id")`（`:105`、`:143`；helper 在 `api/helpers.go:37`）**直接读 query**，从不读 `middleware.CredentialIDPtr(c)`（`:72`）。⇒ 这两个端点只有「显式传参」一条分区通道，且**挂上中间件也不改变行为**——本轮实测：给它们挂 `OptionalAuth + CredentialScoped`（学员当前证件=A）后 `/api/catalog/tree` 的响应与匿名逐字节相同；把 handler 改读 `middleware.CredentialIDPtr(c)` 才真正收敛（新锁随即判红，见「锁」）。

**类别 B：挂了 `CredentialScoped`，但所在组没有 JWT 上下文，兜底永不生效。**
`/api/search`（`api/search.go:28`）与 `/api/courses`（`api/courses.go:31` 在本蓝图 group 上挂中间件、`:34` 公开访问）都注册在 `/api` 根组上——根组只挂 `AuditLog`（`api/router.go:89`、注册循环 `:122-123`、蓝图顺序 `api/routes_registry.go:36/107`），没有 `JWTAuth` 也没有 `OptionalAuth` ⇒ `roleOf(c)` 恒为空 ⇒ 分支 2 恒不成立。这两个端点与类别 A 的差别在于：它们的 handler **是**读上下文的（`search.go:57`、`courses.go:72`），所以只要补 `OptionalAuth`，兜底立刻生效（不需要改 handler）。

**客户端侧现状（与本案一致，不是待修的债）**：#1106 已把「必须显式传」的传参点冻进清单（`frontend/src/api/__tests__/credentialScopeContract.spec.ts:13-14` 的例外说明，与同文件传参点表的 `:38` 「`api/training.ts`：/catalog/tree、/tags 不在 CredentialScoped 里，handler 自读；不传 = 不分区」、`:33-34` 「`api/course.ts` / `api/search.ts`：公开端点，服务端兜底不覆盖匿名/非学员，要分区只能显式传」）；移动端同一口径写在 `api/search.uts` 文件头（#1107）。

## 决策

1. `/api/catalog/tree` 与 `/api/tags` **保持现状**：handler 自读 `credential_id` query，未传即不分区；**不挂** `CredentialScoped`，也不挂 `OptionalAuth`。
2. `/api/search` **不挂** `OptionalAuth`（与 §1 同族，但是另一件事：它会把兜底变成「未登录匿名 / 登录学员」两种搜索语义，另案评估）。
3. 「显式传参」是这两个公开端点唯一的分区通道，继续由 #1106 的冻结清单守（新增传参点必须回清单登记，否则 `credentialScopeContract.spec.ts` 判红）。

## 理由

- **收益极窄**：挂上只对「登录学员 **且** 未显式传参」这一个组合生效（显式传参第 1 优先；非学员不解析；未选证件不分区）；对类别 A 还要额外改 handler 读上下文（本次实测），落地是两处改动而不是一处。收益仅是「未来客户端可以少传一个参数」。
- **代价是跨端默认口径的静默改变**：同一句 `GET /api/catalog/tree`，今天是「匿名与登录学员同结果」，挂上后「登录学员未传」变成按他的当前证件收敛。移动端消费面不在本仓（`training-app/` 由 @zhengcookie 负责，ADR-0056 已开对齐票 #1107），本仓**无法同步验证**；未升级的旧客户端不传参就会被静默改变可见面——正是 ADR-0047 §4（`:39` 删除 `client.ts` 的豁免前缀表与拦截器注入）想消灭的那类「默认值替客户端做主」的反向版本。
- **显式传递是更可核的口径**：「传没传、传的哪个证件」在请求上看得见，可被静态清单与契约测试机械核对；默认收敛则把口径藏在「谁登录了 + 他上次选了什么证件」里，排障与回归都要带上用户状态。
- **与 ADR-0047 §4 / ADR-0051 不冲突**：ADR-0047 §4 收的是客户端**隐式注入**，本决策保留的恰是**显式声明**那条通道；ADR-0051 的 `nil` = 不分区语义在本案里原样成立（未传 = nil = 不分区）。

## 被否备选

- **给 `/api/catalog/tree` 与 `/api/tags` 挂 `CredentialScoped`（默认收敛到当前证件）**：收益与代价同上；且单挂中间件对这两个端点**不改变任何行为**（handler 不读上下文），真要落地就必须同时改 handler —— 一笔「跨端口径变化 + 无跨端验证面」的改动，不换任何今天用得上的能力。
- **给 `/api/search` 挂 `OptionalAuth`（让匿名兜底生效）**：它改的是**匿名搜索语义**（同一关键词，未登录看全量、登录学员看当前证件），与「客户端要不要显式传参」是两件事，且移动端搜索消费面同样不在本仓。另案评估。
- **统一改成「服务端兜底优先」并同步全端**：方向与 ADR-0047 §4 一致，但需要全部公开读面一起改 + 移动端同步发版 + 旧版本兼容窗口，本轮不具备验证面。

## 锁

- `backend/internal/api/credential_scope_contract_test.go` 新增 `TestPublicCatalogEndpointsAreNotCredentialScoped`（用既有的训练目录契约装配：`testutil.NewMemoryDB` + `newContractDeps` + `NewRouter` + `catalogRequest`/`unpackData`）：
  - 登录学员（`current_credential_id` = A）**不传** `credential_id` 调 `/api/catalog/tree` ⇒ data 与匿名响应**逐字节一致**（两门证件课程都在 = 不分区），不是按当前证件过滤；
  - `/api/tags` 同族同判：不传时标签题目计数与匿名一致（不按当前证件收敛）；
  - **判别力前置**（同用例内）：显式 `credential_id=A` 必须真的分区（树只剩 A 的课程、标签 B 计数归 0）——否则「两种调用都返回全量」会让用例退化成语义不变式。
- 锁的判别力探针（2026-09-17 本机，改完即还原）：① 只给这两个端点挂 `CredentialScoped` → 用例仍绿（`roleOf(c)` 空，兜底不成立）；② 再挂 `OptionalAuth` → 仍绿（handler 自读 query，中间件形同虚设）；③ 再把 handler 改读 `middleware.CredentialIDPtr(c)` → **判红**（`登录` 响应只剩 A 的课程），即口径一旦真的改变，锁按预期接住。

## 复访条件

- 移动端（#1107 或后续对齐）确认消费口径后，若两端都愿意把「未传」改成「按当前证件」，本决策重开；
- 或出现真实产品需求「未传即按当前证件」（例如新增消费面无法传参），届时按第 1 条的两处改动（中间件 + handler）一并做，并带上跨端验证面。
