# ADR-0022: 问答积分直记与招聘角色隔离

- 状态：已接受（2026-08-30）
- 领域：培训域 / 论坛问答积分、简历与招聘端（关联 #363）

## 背景

学员在论坛的问答行为与找工作需求此前无处安放：提问混在综合讨论区、回答无质量闸门与激励；简历若以"求职帖"留在论坛，则时效性与留存性根本不匹配。本次需同时落地「问答帖成为论坛类别」与「简历常驻 + 招聘端单向查看 + 学员授权交换」，并回答两个反复被质疑的选型：

1. 采纳奖励为何不走既有任务领取制？
2. 招聘方为何要做第四角色 + 独立子域 + cookie 隔离，而非给学员账号加开关？

此外，本次引入的"综合讨论区"定义收窄（`chapter_id IS NULL` 不再等价于综合区），若不落文档，下一个实现者会直接写出 `scope` 与 `category` 叠加漏写的 bug。

## 决策

### 1. 问答奖励走流水直记，不走任务领取制

- **形状**：采纳是"第三人触发、别人受益"的离散事件（楼主点按钮 → 答主受益），与任务模型"我完成 X、我领我的分"不匹配；任务领取受 `points_task_config` 日限与领取幂等约束，一次采纳对应一笔钱的语义会被日限截断。
- **先例**：系统已有四条同形状的流水直记路径（AI 扣费、课程兑换、真题兑换、管理员罚分），采纳奖励属于同一族：`PointsLedger` 自由文本 `reason/ref_type/ref_id`，零 migration。
- **不变式**：每帖只发一次采纳分（幂等键 `reason='accepted_bonus', ref_type='forum_topic', ref_id=topic_id`）；取消/更换采纳只改状态、不产生第二笔钱、也不追回已发分。追回在封底 0 语义下本来就不完全（分被花掉即追不回来），留口子即留套利敞口，故"不追回"是刻意不变式。
- **防刷停在封顶型（乙档）**：自答零分；答主单日计分采纳 3 次、楼主 `accept_action` 日 5 次；同一楼主↔答主配对 1-3 次满分、4-5 次减半、6 次起零分。单人单日问答理论上限 3×40+5×5=145 分，需 ≥3 个独立楼主配合，已将对刷寿命压在个位数。**删帖不回滚**（否则楼主握有威胁答主的权力），仅累加 `deleted_after_accepted` 巡检计数供管理端观察；举报成立删除时按 `rollback` 对冲回收（封底 0，幂等）。
- **一期不做悬赏**：全勤约 60 分/天、一套真题 300 分，让学员为一句提问押两天全勤，结果是零人使用；强制悬赏更会挡住新人提问（提问量本身是教学反馈信号）。

相关代码：`ForumService.AcceptReply/CancelAccept`（`backend/internal/service/forum_service.go:1260`，CAS `WHERE accepted_reply_id IS NULL` + 流水幂等 + 配对衰减）、`PointsLedger`（`model.PointsLedger`）、`ForumService.AdminDeleteTopic/rollbackAcceptedBonusTx`（`#376` 回收）、`SystemSetting` `deleted_after_accepted` 计数。

### 2. 招聘端为第四角色 + 独立子域 + cookie 隔离

- **为何不复用学员账号加开关**：`hrwai_users` 已被三套登录鉴权共用（学员/残值/AI），`GET /api/auth/me` 逐字节契约、`RoleRequired` 守卫语义、账号注销的匿名化（论坛内容重分配给 `__deleted_user`）均按单角色建模；加双角色会击穿三套鉴权共表、`/me` 契约与注销语义。`admin`/`tutor` 已先例独立表，不并入统一用户表，招聘端沿用同一边界：新表 `recruiter_users` + `role=recruiter`。
- **邀约制**：不开放注册，管理员创建时企业信息（`company_name`/`credit_code`/`business_scope`/`contact_name`/`contact_phone`/`contact_email`）全部必填，机构自己控制入口，杜绝"先建号后补资料"。
- **独立子域**：`recruit.<根域>`，沿用"单构建 + 按 hostname 判定工作区"模式（`SubdomainType` 加第 6 值 `recruit`、`roleNavigation.recruiter`、`RecruitLayout`、`getSubdomain()`/`getRoleForSubdomain()`）。部署上落入既有 nginx `catch-all` server block，**主要运维工作是 DNS 记录与证书 SAN 覆盖**（现有子域走同一张 fullchain，确认复用 catch-all，无需新增 server block；若后续需独立 server block 或 SAN 增量，需单独立项）。
- **cookie 必须换名收紧**：现状单一 `hrwai_token` 且 Domain 为父域（HTTPS 后跨子域共享已生效，ADR-0003 已解决）。若招聘方沿用同一父域同名 cookie，已登录学员侧的 cookie 静默恢复路径会拿到一个 recruiter token，导致角色错乱与整站 403。取"cookie 换名 + 收紧为 host-only"（`recruiter_token`，`Domain=""`），不引入父域共享——邀约制企业账号本来就不该和学习端互通；会话仍归 `security.Session` 单例（ADR-0011 关切是"签发与校验同实例"，不是"只能有一个 cookie 名"，`Session.recruiterCookie` 由角色派生）。
- **三层漏斗**：L1 未登录不可见（无公开列表/详情/SEO，全部在 `JWTAuth` + `RoleRequired("recruiter")` 之后）、L2 脱敏卡（岗位/地区/薪资/年限/经历/自评/持证标签可见，姓名打码，无手机/微信/精确现居地/PDF/证书原图，`RecruitService.desensitize` 唯一路径）、L3 交换后明文（`contact_requests` 状态机 `pending/approved/rejected/expired/revoked`，沉默 14 天过期、30 天冷却、企业日限 20、附言 1-200 字、申请阶段不向学员展示企业电话、撤回实时生效、明文不缓存现查 consent、学员注销一并失效）。

相关代码：`RecruiterUser`（`model.RecruiterUser`）、`AuthService.RecruiterLogin/CreateRecruiter/ToggleRecruiterStatus`（`backend/internal/service/auth_service.go:314`）、`security.Session`（`internal/security/session.go`，`hrwai_token` 父域 vs `recruiter_token` host-only）、`RecruitService`（`backend/internal/service/recruit_service.go`，`desensitize` 单路径 + `applyFilters` 需 `CAST(... AS TEXT) LIKE` 兼容 sqlite）、`ContactService`（`service/contact_service.go`，`daemon.Runner` 托管的 14 天过期）、`RecruitResumeView`（`model.RecruitResumeView`，`(resume_user_id, viewed_at)` 索引支撑 7 天聚合）。

## 备选

- **奖励走任务领取制**：拒绝。任务模型为"我完成→我领取"，采纳是"他人触发→我受益"，硬套会破坏幂等语义且受日限约束；已有四条流水直记先例，采纳属于同族。
- **悬赏/预付托管**：拒绝。一期全勤约 60 分，悬赏阈值（300 分/套题）会让提问量归零；强制悬赏更会挡住新人提问（提问量是教学信号）。
- **给学员账号加 `is_recruiter` 开关**：拒绝。会击穿三套鉴权共表、`GET /api/auth/me` 逐字节契约、注销匿名化语义，且企业资质信息无独立归属地。
- **招聘端复用 `hrwai_users` 但加第二套 JWT claim**：拒绝。仍需在 `hrwai_users` 上加企业字段与禁用位，且 `hrwai_token` 父域共享会让学员侧静默恢复拿到 recruiter token。
- **同名 cookie 保持父域共享**：拒绝。父域同名会导致学员侧已登录态静默拿到 recruiter token，整站 403；邀约制企业账号本就不该与学习端互通。
- **简历以求职帖留在论坛**：拒绝。求职信息时效性（常驻最新）与帖子留存性根本不匹配；单表 `job_cards` 常驻实体（`user_id` 主键，无发布/快照/有效期，`visibility` 默认 `hidden`）是唯一收敛。

## 后果

- 问答帖成为论坛 `category` 判别列（`discussion|question`，`CHECK` 兜底 + service 400，存量行 `DEFAULT 'discussion'`），`forum_topics` 加 `accepted_reply_id/solved_at`，`forum_replies` **不加列**（是否被采纳由主题上的 `accepted_reply_id` 推导）；列表 `category` 必须与 `scope` 共存在同一条 WHERE，否则问答帖整片灌进讨论 Tab（已有一条回归断言焊死，管理端同理）。
- 积分侧零 migration（`reason/ref_type/ref_id` 自由文本），发分与状态迁移在同一事务内解耦（CAS 保证并发只发一次分，`reward_issued` 批量回填供二次确认）。
- 招聘端新增 `recruiter_users`、`job_cards`、`recruit_resume_views`、`contact_requests` 四表及 `000006`/`000007`/`000008`/`000009` 四迁移；`hrwai_users` 保持不动；`RecruitService` 脱敏单路径与 `StudentViewStats` 7 天聚合（`DISTINCT recruiter_id` 走索引）为唯一实现。
- 部署上确认复用既有 catch-all + 单张 fullchain，运维工作收敛为 DNS 与 SAN；若后续需独立 server block，需单独立项并更新本 ADR。
- uni-app `training-app` 端契约漂移（ADR-0019）本次未覆盖，继续挂账，不悄悄掩盖。
