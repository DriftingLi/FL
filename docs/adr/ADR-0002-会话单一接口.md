# ADR-0002: 会话（session）单一接口

- 状态：已接受（2026-08-05，refactor/architecture-deepening）
- 领域：账号与认证 —— 会话（session）

## 背景

JWT 签发在三条登录路径（HrwaiLogin / AdminLogin / TutorLogin）各有一份拷贝；黑名单 key 字面量 `jwt:blacklist:` 散落在 middleware、api/auth.go 与估值模块三个文件；Bearer 解析实现三份；logout/黑名单/cookie 路径没有任何测试，注释「与中间件提取逻辑一致」靠人工保证。

## 决策

会话生命周期收敛到 `security.Session`，作为中间件、AuthService 与全部登录路径的唯一接口：

- Issue（签发）/ Verify（校验，拒绝非 HMAC alg）/ Revoke（吊销，黑名单 TTL = token 剩余有效期）/ IsRevoked / ExtractToken（Bearer 优先，Cookie 兜底）/ SetCookie / ClearCookie；
- 黑名单 key 与 Bearer/Cookie 解析只有一份实现；`Claims` 迁入 security，middleware 保留类型别名；
- 黑名单存储可注入（生产 Redis，测试内存），IsRevoked 读异常时放行（Redis 宕机不阻断登录）。

## 约束

- JWT claims 结构、黑名单 key 格式、cookie 属性（父域名 httpOnly、SameSite=Lax）与旧实现完全一致，线上已签发 token 不受影响。

## 后果

- 登出/黑名单/cookie 逻辑终于可单测（`security/session_test.go`），中间件黑名单分支测试在有 Redis 时运行；
- OptionalAuth 同步获得黑名单检查（登出后的 token 在可选认证端点也不再被识别）——这是对旧行为的修正；
- 代价：middleware 与 AuthService 各自持有 Session 实例（由同一 cfg 派生，无状态），不是单例注入。
