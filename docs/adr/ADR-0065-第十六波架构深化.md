# ADR-0065: 第十六波架构深化（表态要有证据，事实要在每个消费点用同一个名字）

- 状态：已接受（2026-09-24，第十五波 ADR-0064 结题账 7 笔 → 逐笔复核实测后开工；本轮不重扫，仍按「能报出 file:line 才算事实」）｜领域：路径参数解析点 / 契约可空性表态 / 同一事实的跨消费点对齐 / 第 3 族「输入不合法」余量 / 同文案双载体 / 可见性 fail-closed 的档位后果
- 拆票顺序：**按违例形状八批**，⑤ 路径解析点 → ③ 第 3 族余量 → ④ `学员不存在` 双载体 → ①′ 给表态锁加第 4 判据 → ①-A 错标改判 → ①-B 真 null 出口加 flag → ⑥ 课程详情面 500 档 → ② **消费点对齐锁（必须最后建）**。
- 与上一波的关系：判据原文不改（ADR-0064 §背景），本波只补它的一条**推论**——

> **一次表态（可空性 / 档位 / 事实归属）若拿不出一条能让它变红的行为证据，它就不是表态，是装饰。**

## 背景

第十五波把「事实塌缩」按域收完了，结题时留了 7 笔账。逐笔复核实测后有 4 笔的**前提被推翻或数不对**，本波按复核后的形状开工：

- **① 的前提是反的**（最大的一笔）。登记写「91 处补 `x-nullable`」。实测抽样 49 个字段：**约 35 处构造点是 `make([]T,0,n)` 或显式 nil→`[]`，永远发不出 `null`**（`course_service.go` 8、`training_catalog_types.go` 7、`student_service.go` 6、`forum_service.go` 6、`faq/points/admin/stats` 14 全是这种），**只有约 14 处真有 null 出口**（`ChapterSlidesDTO.Slides` 在 `slideRenderer==nil`/转图失败时返回 nil；`valuation/repository/dict_coefficients.go:51-54` 四个 `var` 字段；9 个 `model.JSONArray` 字段——它的 `MarshalJSON` 会发出字面量 `null`）。⇒ 按登记口径做，等于给 35 个永不 null 的字段对外宣称可空，还要消费端为它们写无意义的 `?? []`。
- **① 的算术也不对**：99 处 `nullable` 声明里 **5** 处集合字段已带 `extensions:"x-nullable"`（`api/audit.go:21`、`ai_assistant_service.go:61,62`、`content_generate_service.go:32`、`practice_mode_dto.go:24`），另有 3 处在 2xx 响应闭包外 ⇒ 99 − 5 − 3 = 91。ADR-0064:169 写的「8 处」是错的。
- **③ 是 11 条不是 9 条**：`applyCourseTrainingFields`（`course_service.go:907-1005`）里缺席具名的是 **8** 条——证件 `:911/:921`、方向 `:929/:939`、等级 `:947/:957`、**证书模板 `:965/:975`（原登记漏了这一对）**，再加负数学时/排序 `:982/:988/:994`。同一份非法输入在 Create 答 400（`api/admin.go:142` 默认面 400）、在 Update 答 500（`:202-207` 默认面 500 + 只挂 3 条哨兵）⇒ **一件输入错误按 HTTP 动词分家**。
- **③ 里另冒出一处未登记的同文案双载体**：`ErrQuestionCredentialNotFound = "所属证件不存在"`（`question_service.go:31`）与 `course_service.go:921` 的裸串逐字同文案。
- **⑤ 比「负数 id 跨域不同判」严重**：路径整型参数的解析点**不止两枚 helper**。实测 37 处自定义实现散在 11 个文件（36 处裸 `strconv.(Atoi|ParseInt)(c.Param(...))` + 1 处把**路径**参数喂给查询侧守卫 `requiredPositiveID`，`real_exam.go:82`）。其中 `question_interaction.go` 的 7 处写成 `qid, _ := strconv.Atoi(c.Param(...))`——**解析错误整个丢弃**，非数字 id 以 `0` 进 service。这 7 个端点对外怎么答，实测**不是一种而是两种**：6 个经 `renderOutOfPoolQuestion` 答 **404「题目不存在」**（非法输入冒充不存在），`GET /questions/:question_id/knowledge` 因那条路径不过 scope 而答 **200 + 空数组**（把「id 不是数」说成「这题没有考点」）。同时 `pathInt64` 一直是对的（`err != nil || v <= 0`），只有 `pathInt` 缺 `<= 0`。
- **② 今天不可静态表达**：`nullability` tag 只带可空性；`envelope_registry.go` 只有 result type × 端点、没有事实 key；swagger `description` 是散文（ADR-0047 §1 明确不认它作真值）。⇒ 「同一事实在明文位与列表投影必须同 key」这条锁**需要新增一层声明**，不是找现成字段比对。

## 决策

1. **`internal/api` 里路径整型 id 只有两处解析点**（`pathInt` / `pathInt64`，都在 `endpoint.go`）：判定逐字相同（非数字、`0`、负数 ⇒ 400 + **本端点那句文案**），本包 37 处自定义实现全部收进来。`<= 0` 是**解析层**事实，与「这个资源不存在」无关，因此不许留到 service 去答 404。
   **口径限定**：`internal/valuation/handler` 另有 **6 处** `strconv.ParseInt(c.Param("id"), …)`（同样只看 err ⇒ 0/负数继续进 repo）。它们不在本批收：收它需要先有一枚**跨包共享**的解析出口，而「现造一个没有先例可校的形状」正是 ADR-0064 决策 7 否掉的做法 ⇒ 锁里以常量 `valuationPathParseDebt = 6` 记成**只能减的债**（变大红、变小也红，逼着同步改数）。
2. **service 层那 5 处 `id <= 0` guard 保留**（`admin_service.go:182/201/218/233/255`；`:29-30` 是两枚哨兵的定义处，不是 guard）。**可达性实测已归零**：这两枚哨兵的全部引用只有 `api/admin.go` 的 5 处档位映射，五个 service 方法生产侧唯一 caller 就是那五个 handler，而 id 现在都在解析层被挡下 ⇒ 保留的理由只剩「service 契约不假设调用方」这一条，不是「它还管 body 里的 id」（该说法本批复核为**不成立**）。它因此是一处**可达性归零的防御性 guard**：本批不删（删要同时作废第①批的 5 条哨兵映射与其台账行），登记待裁定。
3. **第 3 族 11 条升具名哨兵，并钉住「同一非法输入跨动词同码」**：Create/Update 两条面必须给同一档；哨兵文案各说一件事实，对外句子由端点给（沿用 ADR-0064 决策 1 的呈现层规则）。交换排序一族（`admin_course_service.go:164,167` + `training_catalog_service.go:76` + `catalog_engine.go:144`）把「待交换的项不存在」与「查不动」从同一个 400 拆成 404 / 500。
4. **`学员不存在` 双载体分两步合**：先把裸 handler（`api/contact.go:56-71` 对任何错误都答 `BadRequest`）迁到 Endpoint 缝并**逐字节保形**，再把 `contact_service.go:238` 的裸串升成 `ErrStudentNotFound` + 补一条「查不动」档。顺序不能反——不先保形，第二步的 400→404 归因不了。
5. **可空性表态要有正向证据**：`nullable` 从「一句自我声明」升级为「必须举出一个真会发 `null` 的出口」，与已有 `nonnil` 的反向行为例对称；恒非 null 的错标**改判 `nonnil` + 补 `[]` 行为例**，而不是给它加 flag。债务常量按实测下降（91 → ①-A 后按实测数），且每次下调必须同 PR 更新算式注释。
6. **`x-nullable` 只加在实测有 null 出口的字段上**，且加 flag 与消费端类型修正**同 PR**（`make swagger` → `gen-apitypes` → `vue-tsc` 为门）。移动端 `.uts` 是手写类型、不吃 codegen，其非 null 假设差异在 GitHub 上正式同步，不在本仓改。
7. **⑥ 本波做后端**：`CourseVisibleByID` / `QuestionReadScope.VisibleByID` 停止丢弃 `.Error` ⇒「查不动」答 500，真不可见/未兑换仍 404；档位台账从「据实不声明 500」改成**声明并打得出**。Web 的 `.catch(()=>null)` 同 PR 分辨。移动端 `api/course.uts:449-457` 在任何错误下回填 mock 课程数据 ⇒ 本波只在 GitHub 上提出，代码归 @zhengcookie。
8. **② 引入声明层元数据**：响应字段挂 `fact:"<key>"` tag，事实的载体集合与投影位登记在 `internal/api/consumption_fact_registry.go`（与 `envelope_registry.go` 同处，防两处登记漂移）。锁的第四条断言专治空转：**每个注册 key 必须被遍历到 ≥1 个带 tag 字段，否则 Fatal**。
9. **`所属证件不存在` 这对同文案双载体保持分裂**，各给具名哨兵（课程侧新增 `ErrCourseCredentialRefNotFound`）并把「有意分裂 + 理由」登记下来。合并会把「题库挂载所引用的证件」与「课程写面的证件校验」耦成一次改动，而它们的消费端点与档位都不同。

## 理由

第 1 批（⑤）之所以从「改一个 `<= 0`」长成「收 37 处实现」：只补 helper 会得到一把**有缝的锁**——`path_int_face_contract_test.go` 的表当场红在 `PUT /api/admin/specialty/:id` 上，因为它根本不走 `pathInt`。这与第④批「只认一种漏法的锁等于没有锁」（ADR-0064 决策 10）是同一条判据的复发。

①-⑤ 这几笔的共同形状是**声明与证据脱钩**：`nullable` 是被写出来的、不是被举证的；档位台账「据实不声明」的地方没有反向证据；`company_disabled` 与 `ErrCompanyUnavailable` 说的是同一件事却各起一名。所以本波的护栏都朝一个方向修：**把每条声明配一个能把它打红的观察**。

## 被否备选

- **否「91 处一律补 `x-nullable`」**（原登记口径）：见 背景 首条，多数是错标；那等于让契约朝另一个方向撒谎，并把无意义的空值分支推给每个消费端。
- **否「本波只立锁、不改任何声明」**：债务常量会原地不动，下一波仍按错数估工。
- **否「给 37 处留豁免名单的漂移锁」**：豁免名单会把「只能减」变成「默认合法」，且字面量正则扫不出 `idStr := c.Param(...)` 再转换的三处（`contact.go`/`recruit.go`/`resume_pdf.go`）——正是要抓的形状。⇒ 改用 AST 数据流 + 债务清零 + 夹具自证。
- **否「删掉 service 层的 `id <= 0` guard 以求唯一」**：见 决策 2。今天删它只是在收一处不可达分支，而会连带作废第①批 5 条哨兵映射与台账行；留着则必须承认它是防御性代码——本批选后者并把可达性写实，不留「它还管 body」这种已被推翻的说法。
- **否「⑥ 推到下一波」**（我的初始建议）：跨端 blast radius 由人裁定要现在收；本波按裁定做，但只动本仓代码 + 在 GitHub 上正式提出移动端的按码分辨。
- **否「用 swagger `description` 当事实 key」**：散文不被认作真值（ADR-0047 §1），且锁会退化成字符串比对。

## 锁

1. **`path_parse_point_drift_lock_test.go`**（AST）：`internal/api` 里「把路径参数转成整数却没走 pathInt/pathInt64」即红，覆盖三种形状（直接套 `c.Param`、经同函数内变量中转、路径参数喂给查询侧 helper），且 `strconv` 以**别名**导入时同样抓到；`pathInt*` 名字族必须恰好两枚（加第三枚或改名即 Fatal）；扫描面 < 30 个文件即 Fatal（防空转）；跨包那 6 处按债务常量双向锁。
   **已知盲区（写成断言而不是措辞）**：变量的收集只在单个函数体内，故**跨函数中转**（`raw := rawID(c)` 之后再 `strconv.Atoi(raw)`）不在射程内。`TestPathParseDetectorKnownBlindSpot` 断言的正是「今天抓不到」——检测器哪天变强，这条夹具会红并逼着回来改这里。理由：一条声称比实际更硬的锁，比一个洞更危险。
2. **`path_int_face_contract_test.go`**：helper 判定表（含 `0/-1/空串/带空白`）+ 跨域「与同端点非数字档**同码且同文案**」表（基准取自实测响应，不硬编码文案，故改文案不会误红、被咽成 404 必红）。
3. 随批落地：第 3 族 Create/Update **同码对称测**、④ 的**逐字节保形断言**、①′ 的 **nullable 正向例判据**、② 的 **registry 四断言**。

## 实施回记

- **批⑤（路径解析点）实测比登记大一个形状**：收进来的自定义实现是 **37 处 / 11 个文件**（不是「两枚 helper 之一缺个判断」）——`training_catalog.go` 12、`question_interaction.go` 7、`question_bank.go` 6、`ai_assistant.go` 4（这四处早已手写 `id <= 0`，只是丢弃 err）、`wrong_question.go` 2、`settings.go` 1、`tutor.go` 1（另有一处解析的是 query/form 值，不属路径参数，未动）、`contact.go`/`recruit.go`/`resume_pdf.go` 各 1（`idStr := c.Param` 中转形状），以上 36 处为裸 `strconv`；第 37 处是 `real_exam.go` 把路径参数喂给查询侧 `requiredPositiveID`。⇒ 本包 `pathInt` 现有 **94** 个调用点、`pathInt64` **36** 个，自定义解析点 **0**（口径限 `internal/api`；`valuation/handler` 的 6 处见 决策 1）。
- **那 7 个端点的改判形状，我第一版写错过一次**：初稿写「7 个端点从 200 + 空集合 搬到 400」。双轴评审按实测推翻——只有 `ListKnowledge` 那条路径不过 scope，真是 200 + `[]`；其余 6 条走 `renderOutOfPoolQuestion`，改判前答的是 **404「题目不存在」**。⇒ 症状从「坏输入被演成成功」更正为「坏输入冒充不存在，其中一格冒充成成功空集」。这条误述原本还被我抄进新测试文件的注释里（同一处错传了两遍），一并改掉。病根与第②批 B 段「登记为缺哨兵、实为三种错法」同一条：**按叙述记账，不按逐条实测记账**。
- **跨域同码之后还要同文案**：`hrwai-users`/`tutor` 两域的负数 id 今天已经是 400，但用的是「用户 ID 非法」「讲师 ID 非法」，与同端点非数字档「用户ID无效」不同句 ⇒ 表测试因此按「与基准档响应体逐字相等」断言，而不是只比状态码。
- **双轴评审（`/code-review`，fixed point = `0ef87994`）在本批抓到 5 件我自己写错或写漏的**：①「7 个端点 200 + 空集合」只有 1 个成立（上条已改）；②「`strconv.*(c.Param` 残留 0」口径未限包，`valuation/handler` 还有 6 处（决策 1 已按包限定 + 记债）；③决策 2 举的 guard 行号里 `:29-30` 其实是哨兵定义、第 5 处 `:255` 漏列，且「还管 body 里的 id」经引用清点为不成立；④漂移锁的文件头把「按函数体收集」写成「按文件共享、宁可误红」，方向正好相反（既有假绿风险又虚报严格度），现按实测边界改写并补一条盲区夹具；⑤本批最大的改判（那 7 个端点）当时**没有任何 HTTP 级证据**——新表 8 行不含它们，正撞本波推论「拿不出能让它变红的证据就不是表态」⇒ 表扩到 11 行，并对扩后的表重做还原破坏（11/11 红，命中数 2 处——顺带暴露我的破坏同时改到了 `pathInt64`，两枚 helper 的失败分支文本相同）。
- **`@Failure 400` 文档同步只做到「本批点名的那些」**：`question_interaction.go` 的 7 个端点原本不声明任何失败档，本批补上 `@Failure 400`；另补 `DELETE /admin/course/:course_id`（它的台账行被本批从 404 改成 400，而文档原本只声明 401/404）。`make swagger` 后 `docs.go`/`swagger.json` 各 **+42 行**、`swagger.yaml` **+28 行**（YAML 压掉了每行的引号结构，行数不同是正常的，第一版按 42 一处口径写「+42」不准确），全部是 400 描述、零删除；`gen-apitypes` 输出**零变更**（反向证实 codegen 只读 2xx）。
  **残留缺口（登记，不在本批补）**：其余走 `pathInt` 的端点里有多少个 swagger 没声明 400，本批没有全量核过——「文档说的档位」与「代码打得出的档位」之间**没有锁**（第①批只锁了「路由是否出现在 swagger 里」）。它与 ② 的 registry 同属「声明与消费点对齐」，下一波一起定形。
