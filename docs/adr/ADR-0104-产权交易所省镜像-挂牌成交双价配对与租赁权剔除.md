# ADR-0104：产权交易所省镜像——「挂牌价 / 成交价」双价配对，与租赁权样本的识别剔除

- **状态**：已接受
- **日期**：2026-11-20
- **领域**：拍卖数据管线 / 采集层 / 清洗层
- **票**：#2680（父 spec #2671）

## 背景

#2672–#2679 建成的管线已经能落「成交价 + 评估价（或起拍价）」，但下游校准真正需要的那类样本还缺一种：**同一标的的挂牌价与成交金额同时可得**。有了这一对，才能直接观测「挂牌 → 成交」的折扣关系，用来检验校准里的清算折扣 δ 基线 0.85 是否站得住；只有成交价时，δ 只能靠假设。

#2680 要接的是产权交易所省平台镜像（`hbggzyfwpt.cn`）。它的价值在实测中确认得非常直接：**成交公告页一页之内同时给出「挂牌价格」与「成交金额」**。

但这张票要解决的不止「多一个采集面」（那是 ADR-0103 已经解决的 seam 问题），而是三个**只在这个源上出现**的形态问题：

| 问题 | 形态 | 不处理的后果 |
|---|---|---|
| 双价配对 | 成交页同时有挂牌价与成交金额 | 只有 `raw_price` 一个价位列 ⇒ 配对关系在落库时丢掉，下游再也算不出折扣比 |
| 单位陷阱 | 挂牌详情标签是「挂牌价格（**万元**）」，成交详情是「（**元**）」 | 差 10000 倍，残值率标签全错 |
| 租赁权混入 | 当期 9 条成交公告**全是**「三年承租权」 | 成交金额是三年租金总额、评估价是年租金评估价，量纲与设备残值无关；当设备样本落库会把租金比当成残值率 |

## 决策

**一、挂牌价独立成列 `listing_price`，不改 `raw_price` 的语义。** 迁移 `000068_market_listing_price` 给 `market_transactions` 加一列 `listing_price NUMERIC(14,2)`，列语义恒定：**`listing_price` 永远是挂牌价**，不随 `raw_price_kind` 变。三种落库形态：

```
成交样本：raw_price = 成交金额，listing_price = 挂牌价   ⇒ 两价齐备（判据②）
挂牌样本：raw_price = 挂牌价，  listing_price = 挂牌价   ⇒ 两列同值
其它源  ：raw_price = 原语义，listing_price = NULL       ⇒ 无配对语义
```

**为什么不让 `raw_price` 按 kind 承载两个价、或把挂牌价塞进 `structured_specs`**：前者会让下游每次读价格都要先判 kind 再决定这一列是哪个价，任何一处漏判都错；后者把可计算的数值降级成 JSON 里的字符串，SQL 里再也算不了折扣比、也建不了索引。独立列让「两价齐备」变成一句 `listing_price IS NOT NULL AND raw_price_kind = 'deal'`，并能建部分索引（迁移里已建 `idx_market_transactions_listing_pair`）。

**「其它源留 NULL」是刻意的**：京东/公拍网/rmfysszc 没有配对语义，留 NULL 表示「这个概念不适用」，与「挂牌价是 0」或「挂牌价缺失」区分开。下游按 `listing_price IS NOT NULL` 筛配对样本时不会误收它们。

**二、单位按标签取，不按数值大小猜。** `_to_yuan(value, unit_hint=...)` 的判定顺序是：显式 `unit_hint`（来自标签里的「（万元）」）> 值文本自带的「万元」> 默认按元。**不能靠数值大小反推**——2.43 万元与 2.43 元都是合法价格，按大小猜必然在某类样本上错。实测：挂牌详情 `挂牌价格（万元）: 2.43` ⇒ 24300 元；成交详情 `挂牌价格（元）: 199300` ⇒ 199300 元。

**三、租赁权/承租权样本必须剔除，而且要有剔除审计。** 产权交易所是**通用**产权交易平台，不是设备拍卖平台——当期 9 条成交公告全是房屋/铺位的「三年承租权」。这类样本的「成交金额」是三年租金总额、「评估价格」是年租金评估价，实测成交/评估比 3.86~7.33；若当设备样本落库，这个比值会被当成残值率，直接污染校准。

处理方式是**标记 + 清洗规则剔除**，不是适配器里直接丢弃：

- 适配器按标题线索写 `structured_specs.lease_right = True`；
- 新增清洗规则⑧ `_rule_lease_right`（`REASON_LEASE_RIGHT = "lease_right_not_equipment"`）把它剔成 `rejected`；
- 行**照常落库**（剔除 ≠ 丢弃），得率报告里能看到 `lease_right_not_equipment` 这个原因。

**为什么不直接在适配器里跳过**：丢弃就没有剔除审计，得率报告也看不见「这个源当期 100% 是租赁权」这个事实——而那正是判断「这个源值不值得继续采」的关键读数。

**四、租赁权规则排在占位价规则之前。** 顺序是 ①②报废 → ③**租赁权** → ④占位价 → ⑤面议 → ⑥区间 → 去重 → 溢价。原因：租赁样本的成交价与吨位无关（三年租金 / 吨位 可能低于 1000 元/吨的占位价阈值），排在占位价之后会把原因归成 `placeholder_price`——得率报告读起来像「价格异常」，实际是「这不是设备样本」。有专门回归测试钉这个顺序（`test_lease_rule_runs_before_placeholder_rule`）。

**五、非设备样本剔除（规则⑨），而且判据必须自己看文本、不依赖适配器标记。** 除了租赁权，源里还有房产（「北京市海淀区…房产处置」，实测挂牌 22,860,830 元）与无规格物资包（「一批废旧资产处置」，1000 元）。第一版实现是「看适配器写的 `equipment_relevant` 标记」，**这个设计在真实抓取与既有测试的双重暴露下被否掉**：

- 真实抓取里房产样本以 `cleaned` + `label_eligible=true` 落库——它永远匹配不上叉车原价、永远算不出残值率，只会以 `(NULL,NULL,NULL)` 组堆进 `market_unmatched_queue` 顶部（该视图按 `sample_count DESC` 排序），把人工补原价的注意力引到房产上；
- 反过来，只看标记会**误伤**其它采集面：#2679 的公拍网溢价测试样本没写这个标记，被这条规则判成了非设备（`test_premium_is_flagged_when_deal_far_exceeds_appraisal` 直接红）。

所以规则⑨的判据是**两条同时满足才剔除**：① 没有任何设备身份字段（`brand` / `model` / `tonnage` 全缺）；② 文本（`structured_specs.title` + `raw_description` 的 title/body）里没有任何设备线索（`_EQUIPMENT_MARKERS`：叉车/托盘车/堆高车/搬运车/前移式/牵引车/电动叉车/电动托盘/内燃叉车/平衡重 + 林德/合力/杭叉/永恒力/JUNGHEINRICH）。**对所有采集面一致生效**，适配器标记只作额外快路径。宁可漏判也不误杀：只缺 brand 但有吨位的样本可能是抽漏了品牌，仍有匹配价值；文本提到「叉车」的样本即使没抽到规格也属本领域。

**六、租赁权与「非设备」是两条规则、两个原因。** 租赁权是**量纲不同**（三年租金总额 / 年租金评估价），必须单独剔、单独记原因；非设备是**领域不相关**（房产/物资包/办公设备）。合并成一条会让得率报告看不出「这个源里设备样本占多少」——而那正是判断该源值不值得继续采的关键读数。规则顺序：①②报废 → ③**租赁权** → ④占位价 → ⑤面议 → ⑥区间 → ⑨**非设备**。非设备排在占位价之后：它可能带价格异常，占位价规则先给更具体的剔除原因；都命中不了再归到「不是设备」。

**七、两个入口（挂牌列表 / 成交列表）都是默认发现入口。** `SourceSpec.default_list_urls` 同时给 `jygg`（挂牌）与 `jyjg`（成交）两个列表——一条命令两种列表都抓，不需要运维记住两个 URL。挂牌样本与成交样本是不同 guid，跨页关联靠「项目编号」（`structured_specs.project_no`）；但既然成交页自带两价，配对不依赖跨页。

**八、列表行缺 `</tr>`，解析器不能依赖表格结构完整性。** 实测源站列表 `<td>` 结束直接接下一个 `<tr>`（源码如此，不是抓取损坏）。按 `</tr>` 分块会漏掉后半部分条目——所以 `parse_listing` 用 `HTMLParser` 按 `<a>` 标签取链接与 `title` 属性，不碰表格结构。有回归测试（`test_missing_tr_close_does_not_lose_entries`）。

**九、列表页不给条目发布日期 ⇒ `keep_undated=True`。** 日期在另一个 `<td>` 里、与链接不同层级，按链接配对会串行。所以列表解析留空发布日期，由 `SourceSpec.keep_undated` 放行年份窗口（机制见 ADR-0103 决策八），真正的日期从详情页的「发布时间 / 公告期限」取。

## 被否备选

- **把挂牌价塞进 `structured_specs`**：SQL 里算不了折扣比、建不了索引，可计算的数值被降级成 JSON 字符串。
- **让 `raw_price` 按 kind 承载两个价**：下游每次读价格都要先判 kind，任何一处漏判都错；且「两价齐备」在库里表达不出来。
- **所有源统一加 `listing_price` 并回填**：其它源没有这个语义，回填等于编造数据。
- **租赁权样本在适配器里直接跳过**：没有剔除审计，得率报告看不出「这个源全是租赁权」（见决策三）。
- **租赁权规则排在占位价之后**：原因归错，报告可读性差（见决策四）。
- **非设备样本只标记不剔除**（第一版实现，已被真实抓取否掉）：房产样本以 `label_eligible` 落库污染待审队列（见决策五）。
- **非设备判据依赖适配器写的 `equipment_relevant` 标记**（第一版实现，已被既有测试否掉）：漏写的适配器会静默放行非设备样本，且误伤没写标记的既有采集面（见决策五）。
- **靠数值大小判万元/元**：2.43 万元与 2.43 元都合法，按大小猜必然在某类样本上错（见决策二）。
- **按 `</tr>` 分块解析列表**：源站缺 `</tr>`，会漏一半条目（见决策八）。
- **把租赁权与非设备合并成一条规则**：两个原因要分开记，得率报告才能看出「设备样本占多少」（见决策六）。

## 真实抓取验证（2026-11-20，真网 + 真 PG）

用生产路径（`load_robots_book` → `CrawlClient` 限速 2s → `run_backfill` 全管线）抓两个默认列表：

```
robots 核验：www.hbggzyfwpt.cn 已核验（robots.txt 404 ⇒ fail-closed）
  默认判定：allowed=False disallowed=True     ← 合规默认不可采
  override：allowed=True overridden=True      ← 需显式 --allow-robots-override + 审计
落库 18 行；清洗得率 0.0%（cleaned 0 / 18）
  按剔除原因：lease_right_not_equipment 15（83.3%）
              not_equipment_sample 3（16.7%）
双价齐备的成交样本：9 条（成交 = 挂牌，ratio 全为 1.0000）
```

**读数含义**：①两价配对在真实数据上成立（9 条成交样本全部两价齐备）；②**设备样本 0 条**——当期该源内容是 15 条租赁权 + 2 条北京房产 + 1 条无规格物资包，判据②的叉车配对样本要等源站出现设备类成交公告；③9 条租赁权成交的 ratio 全是 1.0000（成交=挂牌，无竞价），进一步证明这些是租赁权而非设备竞价。

**真实抓取暴露并修掉的缺陷（判据之外但必须记）**：第一版规则⑨只看适配器的 `equipment_relevant` 标记 ⇒ 房产样本以 `cleaned` + `label_eligible=true` 落库（22,860,830 元）；改成「看文本」后同时发现它误伤了 #2679 的公拍网溢价测试（适配器没写标记）。两处都是真实链路才暴露的，单测无法预见。

## 后果**收益**：①「挂牌→成交」折扣比在 SQL 里直接可算（`raw_price / listing_price`），下游校准检验 δ 有了真配对样本；②单位按标签取，万元/元不会混；③租赁权与非设备污染各按具名原因挡住且可审计；④两个入口一条命令全覆盖；⑤与 #2679 的采集面无共享状态（ADR-0103 的自注册 seam 生效，本票只加一个模块文件 + 两条清洗规则 + 一列迁移）。

**代价**：①多一列迁移（`000068`），`store.py` 的 `_COLUMNS` / `_FETCH_COLUMNS` / `fetch_samples` 解包三处必须同步——这是既有设计的手工同步点，本票按既有方式维护；②清洗规则从七条变九条，`CLEAN_REVIEW_REASONS` 同步加两项；③租赁权与非设备的判据都靠标题关键词，平台改文案时需更新——适配器与清洗侧各存一份（刻意重复：适配器漏标时清洗侧兜底，且清洗侧对所有采集面生效）；④`listing_price` 只在产权交易所采集面上有值，其它源 NULL，下游必须按 `IS NOT NULL` 筛而不是当 0 处理；⑤当期该源 9 条成交公告全是租赁权、其余为房产与物资包 ⇒ **真实语料里叉车配对样本仍可能为 0 条**（实测一轮 18 行：15 租赁权 + 3 非设备，设备样本 0），判据②的「两价齐备」在 fixture 上验证，真实得率要等源站出现设备类成交公告；⑥规则⑨对文本关键词敏感，未来若出现「叉车配件」「叉车电池」类样本会被判成设备相关（宁可漏判不误杀的代价）。

**实施边界（本票不做）**：挂牌详情与成交详情的跨页配对（成交页自带两价，不需要）；湖北以外其他省级平台；源站翻页（实测当期列表只有 9 条，翻页参数未探明）；管理端 UI；评估路径改动。

**后续票线索**：①`hbcpre.com`（源网站链接指向的原始站点）可能给出更细的标的字段，未探；②该源列表翻页参数未探明，若条目量增长需要补；③「挂牌→成交」折扣比的消费方（校准拟合管线）尚未建票，是本 spec 的 Out of Scope。
