# ADR-0094：诊断多轮上下文由 FL 折叠——保留 `foldHistoryIntoQuery`

- 状态：Accepted（2026-11-10）；推翻 [#2237](https://github.com/DriftingLi/FL/issues/2237) A.3 末项「删除 `foldHistoryIntoQuery` 与三个折叠预算常量」，#2237 其余各项继续有效
- 日期：2026-11-10
- 领域：AI 域 / 外部服务接入 / 上下文形状（承接 ADR-0029 单 port、ADR-0031 计量闸门、ADR-0032 传输通道、ADR-0093 切流）
- 票：#2393（补 ADR）；要求方 #2295 决策 22 与 §10.2
- 判据物：`backend/internal/aiassistant/diagnosis_adapter.go:465-541`（`buildDiagnosisPayload`）、`:534-536`（折叠调用点）、`:545-550`（三常量）、`:559-601`（`foldHistoryIntoQuery`，注释 :559-568 + 函数体 :569-601）；`backend/internal/aiassistant/service.go:598-625`（服务端按 `req.Messages` 重建 `msgs`）；`frontend/src/utils/diagnosisCompose.ts:1-15`（前端只组本轮句）；`training-app/叉车维修培训学员端跨端应用/pages/ai-assistant/ai-feature.uvue:340-347`（移动端原样上送 `messages`，`:343` 即 `messages: history`；`history` 在 `composables/useAiChat.uts:164-197` 组装）

## 1. 背景

v2 是单轮 RAG QA（契约 FAQ Q5：有意不支持多轮），请求体只有 `content` + `images`，`content` 是唯一文本通道；前端只把本轮「品牌 → 系统/型号 → 现象 → 补充」拼成一句朴素句子（`diagnosisCompose.ts:1-15`），**不碰历史**；历史由调用方按 `req.Messages` 全量上送，`service.go:598-625` 逐条重建成 `msgs`，再由 `buildDiagnosisPayload` 在 `:534-536` 折进本轮 query。#2237 换 v2 单轨时，A.3 末项据此列了「删除 `foldHistoryIntoQuery`(:562-604) 与三个折叠预算常量(:556-560)」（票面行号是 v1 时期的），前提是「票 2241 已把组句放在前端，后端不再做这层折叠」，并自设制动：「若实施时发现前端确实靠它续上文，停下来回到本票改口径，**不要私自留**」。实施时前提被证伪，按制动条款改口径，#2237 进度评论（2026-11-03T19:58:42）记为「`foldHistoryIntoQuery` 保留（前端靠它续上文）」，代码照留——但决策层没有载体：本条落库前 `grep foldHistoryIntoQuery docs/adr/` 只在 ADR-0093 背景段命中一次旁句。

## 2. 决策

保留 `foldHistoryIntoQuery` 与三常量，**不执行** #2237 A.3 末项的删除。

## 3. 理由

1. **折叠是历史进入 v2 的唯一入口**：上游无 `chat_history`、无 `conv_id`（ADR-0093），`[对话上下文]…[本轮问题]…` 折叠文本是历史进入上游的唯一通路。
2. **删掉即「追问失忆」**：「这个故障码刚才说了，然后呢」会掉回无上文的首问，与「支持连续追问」冲突。
3. **折叠有上限、成本可控**：三档预算封顶，长会话不会把 prompt 与检索污染成「什么都沾一点」；折叠同时是检索质量手段——`:559-568` 注释写明检索按整段 query 做向量匹配，历史里的故障码 / 车型关键词能把追问拉回同一主题。

## 4. 被否备选

- **删函数、不折叠**：直接违背 v2 契约形状——上游无历史字段，删掉等于主动放弃多轮。
- **交由前端拼历史（Web 纯函数 + 移动端各一份）**：重复实现两份预算与角色口径；移动端当前并不拼历史（`ai-feature.uvue:340-347` 原样上送 `history`）。
- **把 v2 改成有状态多轮（`conv_id` / 会话映射表）**：需对方改协议并提供有状态会话，与「无 `conv_id`、会话由 FL 的 `session_id` 承担」（规格 §3.4）冲突，跨方改造收益不抵成本。

## 5. 后果

- **正面与代价**：追问能续上文，检索命中率靠历史关键词抬升，成本与污染被预算锁住；代价是折叠文本占用上游 prompt 预算（≤1200 rune + 骨架），旧话题可能轻微稀释对本轮问题的注意力——靠 `[本轮问题]（请结合上文理解本轮追问；勿重复回答历史问题）` 指令与 6 条窗口缓解，不试图消除。
- **预算口径**：`foldMaxTurns=6` 是**6 条消息**（一轮 = user + assistant 两条，按轮核会差一倍），`foldMaxTurnRunes=300` 每条 300 rune，`foldMaxTotalRunes=1200` 合计 1200 rune。`:545` 注释自身还写着「轮次上限」「单轮截断」，措辞是历史遗留，语义以本条为准。6 条是经验值、无实测最优解，若线上反馈「上文明显不够」先量再调，不在本条重开。
- **不做的事**：不加折叠开关（无第二取值）；不为折叠单独打点（成本面已由 ADR-0031 覆盖）；不放宽到全量历史。

## 6. 与票面差异与指路

- 推翻的是 #2237 A.3 **末项**（删除函数与三常量），A.3 其余各项与 #2237 其他条目继续有效；#2237 保持关闭，不重开、不改正文。
- 折叠位置固定在 `buildDiagnosisPayload` 末尾（`:534-536`）：这是「上游协议形状」问题，属适配器职责；不上升到 service 层，不加开关。
- 指路：切流 ADR-0093 背景段、#2237 评论各有一行指向本条；规格 `docs/design/20261105-移动端维修诊断整合规格.md:261`/`:423` 的号位已同步。
