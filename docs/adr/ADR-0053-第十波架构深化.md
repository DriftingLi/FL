# ADR-0053: 第十波架构深化——认证用途声明表 / 联络授权读面 / 简历投影 / 计量口径 / 四段式合成 / api seam / 估值证据面 / codegen 骨架 / 门判据宿主

- 状态：已接受（2026-09-16，architecture review 10 candidates，经 grilling 逐一定案）
- 领域：验证码认证 / 联络授权（联系方式交换）/ 简历卡投影 / AI 计费口径 / 前端列表状态机 / 前端 api 层 / 估值旅程 / 契约 codegen / CI 门判据

## 背景

第九波（ADR-0050）后，第十波扫描覆盖 `backend/internal` 全域、`frontend/src` 全域与 `scripts/` + CI 面，产出 10 个 deepening candidates。其中 **2 个被本轮自行证伪后收窄**（候选 5「两条口径是重复实现」、候选 8「图表重算公式」），**1 个因范围理由收窄**（候选 10 的一半在移动端工具链，见 `AGENTS.md`「架构评审范围」）。

本轮的共同形态与前几波不同：**不变式的「事实真源」已经存在，但派生物散在多个消费面**——用途枚举的六个派生物、授权状态的五处字符串判定、简历卡的三处投影、门判据的两处实现。因此本波的决策多为「把派生物收成一张声明表或一个具名 module」，而不是新建概念。

移动端（`training-app/`）不在本仓评审范围，未产生候选。

## 决策

### 1. 目录 handler 收窄 + 目录域契约补缺

- **只收 api 层**：`Endpoint` 骨架（`endpoint.go:59-72`）已吸收公共守卫链与默认信封（ADR-0024 C2），剩下的样板只有两块——Invoke 里 `result, err := h.svc.X(*in); return &result, err` 的指针舞蹈（全仓 21 处，12 处在 `training_catalog.go`）与 Render 里的成功文案 + 状态码。新增**两个域中立适配器**（`invoke` / `renderMsg`），顺手把 `Parse: func(c){ return bindJSON[T](c) }` 这类多余闭包写成 `Parse: bindJSON[T]`。
- **service 侧 22 个一行转发不动**：它们是 `CatalogEntitySpec[M,I,D]` 的编译期实例化（ADR-0015 的 typed facade），每个还挂着一条领域注释，删掉换取不到收益。
- **handler 函数保留**：swaggo 从函数注释生成端点文档，删函数等于删文档（ADR-0047「收口」既有教训）。
- 同票补目录域契约缺登记：`/admin/specialties`、`/admin/levels` 补 `@Router` 注解 + 新增 `SpecialtyListDTO` 替掉 `gin.H{"specialties": …}` + `internal/apitypes/domains.go` 补两行。
- 被否备选：**目录专用便捷构造**（只服务一个域，其它 20 个域仍各写各的）；**文案进 service spec**（HTTP 文案下沉到 service 包）；**上端点声明表 / codegen**（handler 的依赖解析会从编译错误降级为运行期查找，同 ADR-0047 §6 对 `Deps` 的顾虑）。
- 证据：复用 `training_catalog_contract_test.go` 四个契约测试 + 两个新端点用例 + **把「状态码 + 成功文案」纳入断言**（今天 `unpackData` 读完 `message` 就丢掉，重构能静默改掉用户可见文案）+ 一条负向回潮锁（目录域 handler 内不得再出现手写指针舞蹈 / 多余 Parse 闭包）。

### 2. 验证码用途声明表（service 侧，6 行 × 7 个纯数据槽位）

- **口径修正**：该枚举不是「四份重复的允许集合」，而是**六个消费面**——匿名入口白名单（`api/code_auth_routes.go:49-56`，3 态）、目标占用校验（`code_service.go:505-537`，6 态穷举 + default 报错）、邮件 title/op（`code_service.go:325-336`，5 case + **隐式默认 register**）、短信模板（`sms_tencent.go:75-86`，3 case + **隐式默认 login**）、短信启动自检（`sms_tencent.go:106-118`，硬编码 4 个模板）、配置就绪断言（`config.go:91-100`，硬编码 4 个 `Tpl*`）。
- 决策：建一张 6 行用途声明表，槽位 **RequiresSession / 占用校验规则 / 占用错误文案 / 邮件 title / 邮件 op / 短信模板键 / 短信参数量**——**全是数据，不放闭包**。邮件 body 拼接、短信 API 调用、校验动作等骨架留在各消费面。
- **入口槽位用领域词 `RequiresSession`**（「这个用途的完成动作是否需要已登录会话」），不把 HTTP 词 `anonymous` 写进 service；**api 的 3 态白名单保留为显式清单**——它镜像的是路由注册（`code_auth_routes.go:38-46`），不是属性的投影；另加一条**单向不变式**「白名单 ⊆ 非 RequiresSession 用途」（反向错配报红，新增用途忘改白名单不会自动暴露）。
- 启动自检与配置就绪断言的模板键集合**从表派生**，不再硬编码 4。
- 被否备选：**白名单改为表投影**（匿名面变成 fail-open，漏标一个属性就静默多一个公网发码口）；**只修两处隐式默认**（堵住 fail-open，但「加一个用途改六处」的格局不变）；**全声明化含闭包**（表本身变成新学习面，同 ADR-0050 §2 被否的形态）。
- 锁三条：结构完整性（表覆盖全部 6 个用途且 7 槽位非空）+ 行为级逐字断言（对 6 态真跑 `EmailChannel.Render` 与 `templateFor`，断言产出与表一致——测真调用点）+ 单向不变式。

### 3. 联络授权读面单点化（`contact_authz.go`，internal seam）

- **写侧已由 ADR-0027 C5 收口**（`EnsureApproved` 承载三分支迁移），本轮只补读侧。口径修正：候选原报的「四条读路径」中只有两条是明文门禁，另两条是展示态投影与状态迁移。
- 新建同包文件 `contact_authz.go`，承载：typed 五态授权状态、**单条**（`(企业, 学员)` 授权态，含「学员注销即一并失效」与「最新 `decided_at`」语义）与**批量**（供企业视角徽章，禁 N+1）两形态查询。`GetContact`（企业侧看学员明文）、`toDTO`（学员侧看企业明文）、`fillContactStates`（企业视角徽章 none/pending/approved）三处改为走它。
- **零装配改动、零导出面变化**：三个消费者全在 `service` 包，这是 internal seam（同 ADR-0050 §3 的「同包分文件」先例）。
- 同票收回写侧残留：撤投连带的 revoked 迁移改走联络域具名方法（与 `EnsureApproved` 对称），去掉 `job_application_service.go:249-253` 的内联 SQL——否则构造函数上「contact 收口授权状态机」的声明名不副实。
- 被否备选：**独立导出 `ContactAuthzService`**（三个 caller 全在联络域 → one adapter = hypothetical seam，ADR-0050 §3 判据）；**导出纯函数**（导出面变大，api 层可越层直调）。
- 锁：行为级（三处投影同源）+ 不变式（明文只在 `approved` 透出、注销即失效）+ 字面量清零静态扫描（今天 `"approved"` 在 service 包出现 19 次）。

### 4. 简历卡投影单点化（`resume_projection.go`）

- 口径修正：不是「两份 DTO 不同步」，而是**三处投影 + 三处打码规则**——L2 脱敏卡 `desensitize`（`recruit_service.go:96-146`）、明文卡 `toJobCardDTO`（`job_card_service.go:378-405`）、打码版在线简历 PDF `ResumePDFRenderer`（`resume_pdf.go`）。
- 新建 `resume_projection.go`：**打码规则**（姓名打码 / 证书去图 / 现居地截断到市）与**三处投影的字段清单同文件**，让新增 `model.JobCard` 字段时三处决定相邻可见；**不引入字段级声明表或 DSL**。
- **证书去图从 deny-list 改 allow-list**：今天是 `delete(certs[i], "image_urls")` + `delete(..., "imageUrls")`，而 `resume_certifications` 是 JSONB——将来多一个带图/带隐私的键就会静默泄漏；改为只保留已知安全键。
- **零行为变更**：L2 卡不带现居地、打码 PDF 展示到市，是 `CONTEXT.md`「简历卡」词条已区分的两条有意口径，不动产品行为。
- 被否备选：**字段敏感级声明表**（一张表驱动三个不同形状的投影，接近 ADR-0050 §2 否过的硬声明化）；**只修 deny-list**（规则仍分叉在三处）。
- 锁：allow-list 键集合断言（结构，fail-closed）+ 真实输出不得含哨兵明文（行为级，打真调用点）。

### 5. 「什么算 prompt」口径单点化（实现服从词表）

- **词表与代码的分歧**：`CONTEXT.md`「AI 计费」写「prompt 只算最后一条**用户**消息」，而真正被计费的是声明路径——`ai_assistant_service.go:543-546` 取 `req.Messages` 最后一条的 `Content`，**不滤角色**；回退路径 `aiPromptChars`（`ai_meter.go:116-133`）才滤 `schema.User`。两条口径本来就不同（输入不同：DTO vs 重组后的传输消息），差异只写在注释里。
- 决策：**实现服从词表**——定义包内中立形态（角色 + 文本），声明路径（DTO）与回退路径（端口消息）各写一个 adapter 把输入投影过去，口径函数只写一遍（含「从后往前找第一个 user」与多模态取首个文本 part 的规则）。两个 adapter 是真实存在的两种输入形态，构成该 seam 的判据。
- **这是行为变更**：尾消息为非 `user` 角色时不再按它计费。落地前置证据：核实没有合法流程以非 `user` 消息结尾（有则先补该流程的口径声明，再动）。
- 被否备选：**词表服从实现**（改措辞即可零行为变更，但让声明路径继续偏离产品口径）；**只修测试面**（抽取函数但不统一口径）。
- 锁：测试改为**打真调用点**（删掉 `ai_meter_test.go:375-380` 自建的镜像实现）+「尾消息为 assistant 时按前一条 user 计费」的行为断言。

### 6. 列表四段式合成（`UiAsyncSection` + 扩 `useAsyncPage`）

- **成对做**，因为两个失效面不同：`UiAsyncSection`（props `loading` / `error` / `empty` / `retrying`，slots，`@retry`）收**渲染顺序与互斥**；`useAsyncPage` 增补**空态判据**与**筛选轴变化回第一页**的声明式入口，收**编排**。
- 范围：**全量**——学员/导师端 39 处手写四分支链（`ForumPage.vue` 同一页内写两遍）+ 管理端 10+ 个 el-table 页。
- **表格页的 loading 保留 `el-table` 自带遮罩**，差异提升为组件的一档（`skeleton="table" | "none"`）并写进 `docs/agents/ui-conventions.md`——不是散落特例，也与 ADR-0037「不逐个改表格、默认就对」一致。
- 展示型第 5 态（`ChapterView.vue:168`、`TutorChapterEdit.vue:258` 的 `chapterNotFound`）用 `UiEmptyState` + action 表达，**不自造状态**。
- 被否备选：**只做组件**（编排的 26 处手写不动）；**只扩 composable**（39 份模板不动，同 ADR-0050 §2 否过的「只提共享 helper，格局不变」）；**表格页 loading 也改骨架**（10+ 管理页 loading 观感全变，跨端可见视觉变更）。
- 锁：现有页面 spec + 一条「页面不得手写四分支链」的静态守卫（形态对齐 `check-el-controls.mjs`）。

### 7. 前端 api seam 复原 + position 端点契约

- 先给 `/positions`、`/admin/positions` **补后端注解与 `apitypes` 声明**，让类型来自 `api/generated/`（`api/generated/*.ts` 只导出类型、无可调用函数，且这两个端点今天不在里面）；再补 `api/position.ts` / `api/inspection.ts`，收回 6 个页面 18 个调用点（今天全是 `const res: any`，零类型）；`/credentials` 直接复用既有 `credentialApi.listCredentials`。
- 守卫 `check-api-seam`：页面/组件不得 import `@/api/request`，白名单初始为空；`--all` 报存量、`--diff` 阻断新增（对齐 `check-el-controls.mjs`）。
- 被否备选：**只补前端 module、类型手写**（新增第二份手写类型，与 ADR-0048 按域解冻的方向相反）；**只补高频两点**（`Inspection.vue` 的 9 处进白名单豁免）。
- **本文档是 api seam 约定的落点**——它是架构约定而非模板/样式约定，因此**不进 `ui-conventions.md`**（那份文档的适用面是前端 UI 模板与样式）。

### 8. 估值旅程（两票，先证据后手术）

- 票①：给这个**全站唯一 0 spec 的域**立证据面（不依赖后端的 spec：表单校验/联动/提交、结果卡渲染）。
- 票②：抽 `UiFormField` 容器（label + 必填标记 + 错误态 + 控件 slot），**原生 `<select>` / `<input>` 保留**——`UiSelect` 包的是 `el-select`（下拉浮层），原生 `<select>` 在移动端会调起系统选择器，直接换掉是移动端体验退步；卡片与 scoped CSS 收敛随票②做（纯机械、零风险）。
- **两条自行证伪并撤回**：① `FutureValueChart.vue` 并未重算衰减公式——`computeAnnualDecay()` 的实现体是 `return props.decayAnchor`（纯透传），`base * Math.pow(decay, n)` 正是注释授权的「只做乘法」；② 该文件里的 41 处 `#xxxxxx` 经 `scripts/check-bare-hex.sh --all` 验证**全为 `var(--token, #fallback)` 防御写法**，不是裸 hex 存量。
- 登记（不在本波）：**原生 HTML 控件是第三种写法且无守卫在看**——`ValuationForm.vue` 用了 0 个 `ui/` 组件、11 处原生控件，而 `check-el-controls.mjs` 只守 Element Plus 引用。是否迁 `ui/` 封装需另案 + 真机对比。
- 被否备选：**控件一起换 `UiSelect` / `UiInput`**（移动端体验退步风险，且违反 R2「默认值对齐改造前行为」）；**只收 CSS，不动结构**（字段块重复仍在）。

### 9. codegen 骨架包（`internal/codegen`）

- 5 个生成器（`gen-apitypes` / `gen-authz` / `gen-credscope` / `gen-deploy` / `gen-aifeatures`）各写一遍同骨架——`gen-authz` 与 `gen-credscope` 的 `resolveOut` **逐字相同**（只差文件名字面量），`fatal` 只差程序名前缀。新增 `internal/codegen`：`codegen.Run(codegen.Spec{Name, FileName, Render})` 收 resolveOut / fatal / 落盘 / 打印，Go 侧 in-sync 断言收成 `codegen.AssertInSync(t, spec)`（5 个域测试各一行）。
- **CLI 面不变**：仍是 `go run ./cmd/gen-X`，文档、CI、生成物头部的「再生成」指引零改动。
- 骨架包**必须自带单测**（`resolveOut` 三条路径 + 渲染/写盘失败走 `fatal`）——它是 5 个生成器共享的，一个 bug 同时打中 5 处。
- 被否备选：**只抽 helper**（五个 main 的骨架重复仍在）；**合并成单命令多子命令**（根上消灭重复，但所有文档、CI、生成物头部引用要全改）。
- 澄清：`internal/credentialscope` 的生成物前端 0 importer **不是缺陷**——ADR-0047「收口」已声明「运行期判据不变，变的只是台账位置；覆盖锁扫前端源码比对登记表」，它是人读台账。

### 10. 门判据单点化（根仓范围，Node 单实现）

- **范围修正**：`level-detect.ps1` / `evidence-gen.ps1` / `gate-common.ps1` / `dev-finish.ps1` 全在 `training-app/叉车维修培训学员端跨端应用/scripts/`——**移动端工具链，范围外**，由 @zhengcookie 处置。根仓可动的有四组：① `cd.yml:141-146` 与 `testing-smoke.yml:48-53` 的 ci-summary 聚合 jq 逐字相同；② `check-bare-hex.sh:89-93`（awk）与 `check-el-controls.mjs:166-197`（JS）各自实现一遍 `git diff -U0` 新增行解析；③ `topology_test.go:35-39` 的 env 默认值漂移锁只列 3 个文件，`deploy.sh:183` 的 `DB_USER:-forklift` 在锁外；④ PR 模板手抄了一份运行时面清单（与 `.github/workflows/pr-evidence.yml:54-59` 的权威判据不同源）。
- 决策：**收成 Node 单实现**——新增 `scripts/lib/added-lines.mjs`（一份 diff 新增行解析，含 `core.quotepath` 八进制解码），`check-bare-hex.sh` 与 `check-el-controls.mjs` 都调它；ci-summary 聚合收一份；③④ 随票做（env 锁纳入 `deploy.sh`；PR 模板不再复述判据，改为指向权威实现）。
- 理由：门判据这一族的宿主语言本来就是 Node（`pr-evidence` 校验器及其抽取式单测、`check-el-controls.mjs`、`ci-summary` 的 jq），且 `check-el-controls` / `check-bare-hex` 所在的 **`frontend-check` job 只有 `setup-node`、没有 `setup-go`**（`setup-go` 只在 backend-lint / backend-test / security-scan / migration-check 四个 job）。
- 被否备选：**Go 小工具 `cmd/gatecheck`**（单一实现最硬，但要给前端 job 补一套 Go 环境与模块缓存时间）；**Go 工具 + artifact 跨 job**（前端 job 零新增工具链，代价是多一条 job 间引用）；**只修锁与模板、重复不抽**（三组里两组是逐字重复，抽象成本低于保持两份的成本）。

## 约束

- **行为零漂移**，唯一例外是候选 5（声明路径加角色过滤，属有意口径变更，见该节的落地前置证据）。
- **响应 shape 与 HTTP 契约只增不破**（ADR-0048 口径）：目录域两个新端点与 position 端点是「补登记」，不是改形状。
- **service 侧已收口的写路径不动**：`EnsureApproved`（ADR-0027 C5）与 engine/spec（ADR-0015）本波不改形态，只补读面与派生物。
- **术语零新增**，仅两处词条小补（见「相关」）。
- 移动端不在本次范围。

## 后果

- **「不变式的真源已存在、派生物散在消费面」这类 bug 的实现形态被关闭**：验证码第 7 态不再静默落到登录短信模板；证书去图不再靠删已知键；新增 `JobCard` 字段时三处投影的决定相邻可见。
- **计费口径与产品词表对齐**：prompt 口径从「注释里的两条」变成「一个实现 + 两个 adapter」，且断言打在真调用点上（不再是镜像）。
- 前端列表状态机从「控件收敛、编排各写」变为「控件与编排都单点」；管理端表格页的加载观感**不变**（保留遮罩档）。
- 全站表单控件仍是三种写法（EP 原生 / `ui/` 封装 / 估值域原生 HTML）——第三种仍无守卫，已登记待另案。
- 门判据的根仓半边收到一处；移动端半边（含 `isRuntimeFile` 三处实现已造成 #1037 假红的历史）仍分叉，需移动端侧自行收敛。
- 未来 architecture review 不再重新提议以上 10 项；下次扫描的起点是本次登记项与未覆盖领域（`internal/valuation` 的 handler 面、`pkg/`、`internal/api` 的 16 处 `gin.H` 尾巴）。
