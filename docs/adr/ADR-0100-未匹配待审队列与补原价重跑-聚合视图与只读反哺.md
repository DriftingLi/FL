# ADR-0100：未匹配待审队列与补原价重跑——聚合视图 + 只读反哺

- 状态：Accepted（2026-11-20）
- 日期：2026-11-20
- 领域：残值评估 / 数据采集（市场真值）
- 票：#2676（实施）· 父规格 #2671 · 承接 ADR-0099

## 背景

ADR-0099 给市场样本打上残值率标签，但原价表覆盖有限：拍卖公告常缺门架/配置字段，或型号不在原价表里，样本因此匹配不上、没有标签。spec #2671「原价反哺」已裁定：**不自动写回原价表**；未匹配样本按品牌×型号×吨位聚合成待审队列（一期为聚合视图，无管理端 UI），人工定期审核补原价条目，补入后重跑匹配回收标签。本票把这份裁定落成聚合视图 + 查询入口 + 可验证的回收链路。

## 决策

**一、聚合形态是 SQL VIEW（迁移 000067），不是表。** `market_unmatched_queue` 视图按 `structured_specs ->> 'brand' / 'model' / 'tonnage'` 分组，输出 `sample_count` / `price_min` / `price_max`。选视图而非表：待审集合是**表的派生**，落成实体表就要维护刷新时机与一致性，多一条状态路径；视图永远与 `market_transactions` 同步，任何客户端（collector、DBA、下游）都能直接查，无需走应用层。

**二、待审口径 = 未匹配且未被剔除。** 视图 `WHERE residual_rate_label IS NULL AND clean_status <> 'rejected'`：已匹配样本不需要人工补原价；被剔除样本本身不该进校准集，补原价也无意义。`raw` 行仍进待审——它只是还没跑完管线，不是「无需处理」。

**三、同一口径两处实现共用列名，避免两份真相。** `collector/review.py` 的纯函数 `group_unmatched` 与 SQL VIEW 是同一判定的两种载体（前者供单测与未来内存路径，后者供任意 SQL 客户端）；列名共用 `UNMATCHED_GROUP_COLUMNS`，契约测试断言「视图内样本总数 == 表内待审行数」把两者钉在一起。

**四、反哺只读原价表，无自动写回路径。** `collector rematch` 从 `original_prices` 直读候选后重算匹配，**不插、不改、不删**原价表；契约测试断言 `rematch` 前后原价表的行数与价格总和不变。人工补条目走既有 admin 接口/手工 SQL，管线不提供写回捷径——原价表是评估域的既有事实源，自动反哺会让「人工审核」这道闸门消失。

**五、回收与首次匹配同口径。** `rematch` 复用同一个 `match()` 纯函数与同一份原价候选读取路径，因此回收样本的 `match_level` / `matched_original_range` / `residual_rate_label` / `match_version` 与首次匹配完全一致；契约测试用 fixture 走完整链路（未匹配 → 补条目 → rematch → 有标签）并逐字段断言，同时断言回收后该样本从待审视图消失。

## 被否备选

- **聚合落实体表**：需要刷新时机与一致性维护，且与「零写入路径」有张力；视图足够。
- **物化视图**：需 `REFRESH` 命令，多一条状态路径，一期量级（千条）无需物化。
- **自动写回原价表（反哺自动化）**：spec #2671 明确裁定不自动写回——人工审核是质量闸门，自动反哺会把错配原价固化进评估域。
- **待审队列只含「有价格资格」的样本**：会把价格抽取失败样本也排除；但价格失败样本已在抽检队列（ADR-0097），待审队列关注的是「有价但无原价可匹配」，两个队列职责不同。
- **加管理端 UI**：spec #2671 明确一期无 UI；视图 + CLI 已够运维核查。
- **重跑匹配时只处理未匹配行**：会漏掉「原价表条目被修正、已有标签需重算」的情况；全表重算是幂等纯函数，成本可忽略。

## 后果

**收益**：①未匹配样本可按品牌×型号×吨位聚合查看，人工补原价的优先级（样本多的组）一目了然；②补原价后一条命令回收标签，不重爬公告、不动抽取/清洗列；③反哺路径只读原价表，评估域事实源不被管线改写；④视图与纯函数共用列名，口径不漂移。

**代价**：①多一个迁移与视图（依赖 `structured_specs` 的 jsonb 形状，抽取字段改名会影响分组——已在 ADR-0099 记为已知耦合）；②全表 rematch 在语料增大后是 O(n) 重算，一期量级（千条）可接受，daemon 增量期需再评估；③视图 `tonnage` 用 `NULLIF(...)::numeric` 转换，非数值吨位会让该组行落在 NULL 组（不丢样本，但分组变粗）。

**实施边界（本票不做）**：管理端 UI、自动写回原价表、按待审组批量补条目的工具、daemon 增量模式、校准拟合——全部在后续票或独立工作。本票只交付「聚合视图 + 只读查询 + 补条目后重跑回收」这一段；评估记录表与评估路径零改动。
