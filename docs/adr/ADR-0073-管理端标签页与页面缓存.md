# ADR-0073: 管理端标签页与页面缓存

- 状态：Accepted
- 日期：2026-10-10
- 关联：#1620（本决策的实施票）；#1619 / ADR-0072（外壳：标签栏挂在内容列顶部）；ADR-0047 §2（页面描述符是导航、可见性与缓存的单一事实源）；#1618（管理端导航按运行时能力集过滤）

## 背景

管理端有 20 个页面，日常是在「用户管理 → 投稿审核 → 论坛治理」之间来回跳。改造前每次跳转都**销毁上一页**：列表的筛选条件、翻页位置、滚动位置全部丢失；`SidebarLayout` 还明确写着「不用 keep-alive，避免课程章节页/考试页等带副作用的状态被缓存」——那条判断对学员端（考试、章节）是对的，但对管理端的列表页恰好相反。

## 决策

**一、标签页只在管理端出现**（其余三端不引入标签栏，也不启用缓存），标签栏挂在**内容列顶部、贴顶栏下沿**，随顶栏一起固定（ADR-0072 的棋盘格第二行，不越过侧栏、不并进顶栏）。

**二、固定页 + 会话内记忆**：仪表盘恒在且不可关（保底返回点）；标签列表只活在 pinia 里，**不写 localStorage**。

**三、详情页并入所属标签**：归属判据取描述符既有的 `nav.activeRouteNames`（列表页自己声明「哪些详情页属于我」），不另建「详情页 → 列表页」表。

**四、缓存逐页 opt-in**：`PageDescriptor.keepAlive?: boolean`，**缺省 false**；开启的页面必须把组件名设成自己的路由名（`defineOptions({ name })`），由 `config/__tests__/keepAliveLock.spec.ts` 锁住。名单由 `navigation.keepAliveNames(workspace)` 派生，传给 `SidebarLayout` 作为 `keep-alive` 的 `include`。

**五、缓存页的 key 取路由名**（同页不同查询参数共用一份缓存实例）；未缓存页仍用 `fullPath`（保持既有 180ms 淡入淡出语义）。

## 理由

- **为何只在管理端**：缓存是「保留用户在某页的工作状态」，管理端是长驻的列表/审核工作台，收益最大；学员端的考试页/章节页**恰恰不能**缓存（计时、作答中状态、章节副作用），ADR 里那条既有判断继续有效 —— 名单为空时 `keep-alive` 等价于直通。
- **为何不持久化到 localStorage**：标签是**会话工作集**；刷新后滚动与筛选本来就不保，只还原"一排标签"会让人以为状态还在。这也避免了「登录态过期后标签指向无权页」的额外分支。
- **为何缓存要 opt-in 而不是默认全开**：漏标一个生成/编辑类页面的代价是「切回来状态丢了」（可接受），默认全开的代价是「状态串到别的页面」（不可接受，且难归因）。默认安全的一侧。
- **为何用组件名而不另建映射**：`keep-alive` 的 `include` 只认组件名；把名字对齐到**已有的路由名**，则"清单"仍然只有描述符一处事实源，锁测试只需比对两侧字符串。
- **为何固定仪表盘**：标签栏会把"返回首页"这件事变成一个需要用户自己记得的操作；固定页给了一个恒定的落点，也是详情页归属/关闭全部之后的兜底。

## 后果

- 管理端切换页面时，列表页的筛选/翻页/滚动保留；生成与编辑类页面切走即重置（有意）。
- 新增管理页时：要缓存就写 `keepAlive: true` **并**在页面里加同名 `defineOptions`，否则锁测试判红；不写则默认不缓存。
- `SidebarLayout` 的 `keepAliveNames` 缺省为空数组 —— 另外三端的行为与改造前逐字相同（无缓存）。
- 标签数量随操作增长，但关闭当前/其他/全部三个动作齐备；标签过多时标签栏横向滚动，不换行。
