# ADR-0073: 管理端标签页与页面缓存

- 状态：Accepted
- 日期：2026-10-10
- 关联：#1620（本决策的实施票）；#1619 / ADR-0072（外壳：标签栏挂在内容列顶部）；ADR-0047 §2（页面描述符是导航、可见性与缓存的单一事实源）；#1618（管理端导航按运行时能力集过滤）

## 背景

管理端有 20 个页面，日常是在「用户管理 → 投稿审核 → 论坛治理」之间来回跳。改造前每次跳转都**销毁上一页**：列表的筛选条件、翻页位置、滚动位置全部丢失；`SidebarLayout` 还明确写着「不用 keep-alive，避免课程章节页/考试页等带副作用的状态被缓存」——那条判断对学员端（考试、章节）是对的，但对管理端的列表页恰好相反。

## 决策

**一、标签页只在管理端出现**（其余三端不引入标签栏，也不启用缓存），标签栏挂在**内容列顶部、贴顶栏下沿**，随顶栏一起固定（ADR-0072 的棋盘格第二行，不越过侧栏、不并进顶栏）。

**二、固定页 + 会话内记忆**：仪表盘恒在且不可关（保底返回点）；标签列表只活在 pinia 里，**不写 localStorage**。

**三、详情页并入所属标签**：归属判据取描述符既有的 `nav.activeRouteNames`（列表页自己声明「哪些详情页属于我」），不另建「详情页 → 列表页」表。

**四、缓存逐页 opt-in**：`PageDescriptor.keepAlive?: boolean`，**缺省 false**；开启的页面必须把组件名设成自己的路由名（`defineOptions({ name })`），由 `config/__tests__/keepAliveLock.spec.ts` 锁住。名单由 `navigation.keepAliveNames(workspace)` 派生，传给 `SidebarLayout` 作为 `keep-alive` 的 `include`。

**五、缓存页的 key 取路由名**（同页不同查询参数共用一份缓存实例）；未缓存页仍用 `fullPath`（保持既有 180ms 淡入淡出语义）。

## 理由

- **为何只在管理端**：缓存是「保留用户在某页的工作状态」，管理端是长驻的列表/审核工作台，收益最大；学员端的考试页/章节页**恰恰不能**缓存（计时、作答中状态、章节副作用），ADR 里那条既有判断继续有效 —— 名单为空时 `keep-alive` 等价于直通。
- **为何不持久化到 localStorage**：标签是**会话工作集**；刷新后滚动与筛选本来就不保，只还原"一排标签"会让人以为状态还在。这也避免了「登录态过期后标签指向无权页」的额外分支。
- **为何缓存要 opt-in 而不是默认全开**：漏标一个生成/编辑类页面的代价是「切回来状态丢了」（可接受），默认全开的代价是「状态串到别的页面」（不可接受，且难归因）。默认安全的一侧。
- **为何用组件名而不另建映射**：`keep-alive` 的 `include` 只认组件名；把名字对齐到**已有的路由名**，则"清单"仍然只有描述符一处事实源，锁测试只需比对两侧字符串。
- **为何固定仪表盘**：标签栏会把"返回首页"这件事变成一个需要用户自己记得的操作；固定页给了一个恒定的落点，也是详情页归属/关闭全部之后的兜底。

## 后果

- 管理端切换页面时，列表页的筛选/翻页/滚动保留；生成与编辑类页面切走即重置（有意）。
- 新增管理页时：要缓存就写 `keepAlive: true` **并**在页面里加同名 `defineOptions`，否则锁测试判红；不写则默认不缓存。
- `SidebarLayout` 的 `keepAliveNames` 缺省为空数组 —— 另外三端的行为与改造前逐字相同（无缓存）。
- 标签数量随操作增长，但关闭当前/其他/全部三个动作齐备；标签过多时标签栏横向滚动，不换行。

## 修订（2026-10-10，#1630 / #1631 / #1633）

线上四条反馈里有三条落在这个 ADR 的射程内，逐条订正（**原文条款继续有效**，本节只补被漏掉的前提）：

**一、标签标题的唯一来源是描述符的 `nav.label`**。原文只说「标题取描述符的 `nav.label`，或路由 `meta.title`」，而 `router/index.ts` 的 `routeMeta()` **从来没有注入过 `meta.title`** —— 于是线上标签印的是英文路由名（`仪表盘 | AuditLogs | AdminAccountManage`）。`resolveTab` 现在只收注入的 `titleOf`（= `navigation.pageTitleOf`），不再读 `meta`。**测试的 fixture 当时自己塞了 `meta.title`**，替生产补了一个不存在的输入，缺陷因此在用例里看不见 —— 这条教训一并记在这里：fixture 要与生产同形。

**二、内容列的页面过渡不得用 `mode="out-in"`**。out-in 的放行条件是「离场动画完成」的回调（`BaseTransition` 的 `leavingHooks.afterLeave`），而**根节点不是单个元素**的页面在渲染器里走 Fragment 分支：`deactivate` 是 `move(…, LEAVE)`，Fragment 那支只搬 DOM、不碰过渡钩子，回调永不触发 ⇒ `state.isLeaving` 永久为真、内容列只剩空占位符（线上形态：**从该页切走那一刻起内容区永久空白**，标签栏与侧栏都在，刷新才恢复）。管理端「管理员管理」的根恰好是多分支组件 `UiAsyncSection`（Vue 会警告 `renders non-element root node that cannot be animated`）。改为默认模式 + **离场即时隐藏**（`.inner-fade-leave-active { display: none }`，缓存页的离场本来也没有可播的动画），另页面模板单根时才有进入动画 —— 正确性不再依赖「页面模板恰好单根」这条约定。回归锁：`layouts/__tests__/SidebarLayoutCache.spec.ts`（**必须显式 `stubs: { transition: false }`**，@vue/test-utils 默认把 `<transition>` 换成 stub，stub 掉就等于把被测行为删掉）。

**三、标签栏贴在顶栏下沿**：它此前挂在 `.main-content` 里，而内容区有 `--space-6` 内边距 ⇒ 标签栏离顶栏下沿差 24px（看上去浮在内容中间）。现在由 `SidebarLayout` 的 `.content-header` 承载（内容区**之外**、与页面同列），`position: sticky; top: var(--topbar-height)`，底色仍与内容区同底（不另加第二档底色，也不另加第二条分隔线 —— 十字细线仍只有顶栏那一条横线）。

**四、关签不销毁缓存实例**（语义登记）：标签是「会话工作集」，而 keep-alive 的 `include` 名单是描述符派生的**静态**清单 —— 关闭标签只是把它从标签条上移除，缓存实例仍留在 `include` 里，重进会恢复上次的筛选/翻页（实测：搜索词保留）。这不是遗漏而是本批登记的语义：真要「关签即重置」得按名驱逐（把名字临时挪进 `exclude` 再挪回），而 KeepAlive 的 `pruneCacheEntry` 对**当前页**有 current 守卫、时序微妙；本批不做，另开票。

**五、缓存往返实测（证据）**：`docs/verification/admin-shell/1635/标签页缓存-搜索词保留.png`（输入搜索词 → 切走 → 点标签切回，内容区不空白且搜索词仍在）与 `docs/verification/admin-shell/1635/关闭标签后重进.png`（关签 → 从侧栏重进，不空白）。口径：本机 dev server（真实前端代码 + Playwright 路由 mock），非线上；线上的部署产物核对见 #1635 的合并后评论。
