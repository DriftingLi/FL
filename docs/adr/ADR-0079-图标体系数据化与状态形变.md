# ADR-0079：图标体系数据化（UiIcon 单一入口 + 状态形变）

- 状态：已采纳（2026-10-25）
- 相关：[#1910](https://github.com/DriftingLi/FL/issues/1910)（spec）、实施票 [#1911](https://github.com/DriftingLi/FL/issues/1911) / [#1912](https://github.com/DriftingLi/FL/issues/1912) / [#1913](https://github.com/DriftingLi/FL/issues/1913)
- 交叉：[ADR-0035](ADR-0035-UI控件收敛到ui封装层.md)（UI 封装层）、[ADR-0078](ADR-0078-可交互图标的尺寸分档.md)（图标控件尺寸）、[ui-conventions](../../docs/agents/ui-conventions.md)

## 背景

图标在这之前有**两个事实源**：一处是 `src/icons/index.ts` 的全局注册（36 个 Element Plus 图标，其中 15 个已无人使用），另一处是各页面自己 `import` 的 64 个图标名。同一屏幕上 14 / 16 / 18px 三种尺寸混用：有的走 `:size`，有的靠 `text-sm` 的字号继承。

由此产生的具体问题：

- **无法回答「这个语义的图标在哪」**：加一个要先决定加进注册表还是就地 import，删一个要全仓搜；
- **一致性靠人**：描边粗细、尺寸、可访问名三件事各写各的；
- **换数据源等于全仓改**：名字是组件引用，不是数据；
- **没有状态过渡**：收藏、上传结果、主题切换都是「跳一下」。

规模（探索时实测）：169 个 `.vue`、68 个文件 import 了 EP 图标、64 个不同名字、177 处 `<el-icon>`、19 处 `:is` 动态组件图标。

## 决策

| # | 决策 | 说明 |
| --- | --- | --- |
| 1 | **数据源**：Lucide（ISC），其导出即 `[tag, attrs]` 的 24 网格数据 | 不依赖它的组件包；只取数据。精确版本锁定（`lucide@1.61.0`）—— v1 的图标名仍在演进，浮动能省事也能让编译悄悄变红 |
| 2 | **实心图标**从 `@element-plus/icons-vue`（MIT）一次性抽成仓内数据（保留版权头），**随 #1912 落地** | Lucide 只有描边。抽 8 条路径比引入第二套图标库便宜；业务侧因此可以彻底不再 import EP 图标。本票不登记实心图标，所以渲染层目前没有 fill 分支（不做今天用不上的分支） |
| 3 | **单一入口** `components/ui/UiIcon.vue`：`name / size / strokeWidth / label / morph / spring / reducedMotion` | `class` 与 `aria-*` 透传到根 `<svg>`；有 `label` 才 `role="img"` + `<title>`，否则 `aria-hidden` |
| 4 | **双渲染路径**：默认静态（直接渲染数据，不加载动画模块）；`morph` 才走 morphicons，且该模块**动态 import** | 运行时拆独立 chunk（`morphicons`），入口不引用它 —— 不用动画的页面一个字节都不付 |
| 5 | **尺寸默认 `1em`**，与 `el-icon` 同口径 | 迁移时 `text-sm` / `:size` 原样保留，零视觉位移；数字即 px |
| 6 | **形变只给「形状真的变」的地方**（白名单见下） | 同形状换方向（chevron 旋转）、纯描边↔填充（心形 outline/filled 是同一个 `d`）继续用 CSS 过渡 |
| 7 | **动效参数单点** `src/config/motion.ts`；`reducedMotion` 默认 `user` | CSS 过渡由 `global.css` 的媒体查询压平，rAF 动画由 `UiIcon` 自己压平：两者各管各的动画面 |
| 8 | **名字是类型**：`IconName` 由注册表推断 | 写错名字 `npm run type-check` 红；运行期未知名**降级为警示图标并开发环境告警**（生产静默降级，不刷屏也不白屏） |
| 9 | **配置面字符串化**：导航/能力图标的 `icon` 由组件引用改为图标名 | 字符串才能进注册表、能被守卫扫、能序列化（随 #1912 全量替换） |
| 10 | **守卫** `scripts/check-icons.mjs` + 迁移期基线 `icon-legacy-baseline.json` | 四条判据：不得 import EP 图标、不得写 `<el-icon>`、不得手写 24 网格 svg（跨行同判，渲染器 `UiIcon.vue` 是唯一例外）、`<UiIcon>` 必须带 name。**第四条与基线是实施时补的**：spec 只说三条，但少了「`<el-icon>`」这半条，旧的包裹层写法能从判据缝里漏过去；基线则让规则在迁移期就能进 CI（只减不增，自检断言无过期行） |

### 形变白名单（#1913 执行）

| 位置 | 从 | 到 | 为什么用形变 |
| --- | --- | --- | --- |
| 主题三态（ThemeToggle） | sun | moon / theme-system | 同一位置、三个形状 |
| 侧栏折叠 | panel-left-close | panel-left-open | 同一按钮、两个形状 |
| 收藏 / 举报 / 删除 | outline | filled | 形状本身不同（星形轮廓与实心不是同一路径） |
| 附件上传 | loader-circle | circle-check / circle-x | 结果替换过程本身有语义 |

**不进形变**：心形点赞（同一 `d`，只是填充开关 —— 走 morph 还会拉进距离场代码）、展开箭头旋转（同形状换向）、所有「选中态变色」（那是颜色不是形状）。

### 「跟随系统」的图形

原先是 `ThemeToggle` 里手绘的四段 SVG（两段填色 + 两段描边，描边 1.5）。改为 Lucide 的 `sun-moon`，理由两条，都是硬约束：

1. **形变驱动把整个图标合成一条 `d`**，混合填充/描边的四段图形撑不过那一刻；
2. 三态要**视觉重量一致**（本票验收项）：2px 描边 vs 1.5px 描边同屏会被一眼看出来。

代价是「半日半月」的细节更简；换来的是三态同源、可形变、可换数据源。

### 可见性口径（说清楚，不含糊）

形变的真实宿主是 `ThemeToggle`（登录外壳、AI 助手外壳）。**顶栏用户菜单的三态是三个菜单项**——选中即关闭，形变在用户眼前根本来不及发生，所以那里只保证「同源数据 + 同重量」，不承诺动画。同理，播放/暂停形变没有宿主：视频播放器用的是原生 `controls`。

## 被否备选

| 备选 | 否决理由 |
| --- | --- |
| 同步引入 morphicons（不做动态 import） | 首屏 +10KB 级 gzip，与「不用动画的页面不付费」冲突；实测证明可干净拆出 |
| 只加动效、不换数据源 | 两个事实源还在，过半收益为零（尺寸/可访问名/新增路径都不变） |
| 整体换 Phosphor（实心/描边一套齐） | 等于换全套视觉语言，超出「体系迁移」范围；且 Lucide 的数据形状直接就是 morphicons 的输入 |
| 把 morph 做成全局默认（每个图标都动画） | 形变是信号，不是装饰；144 处静态图标同时开驱动会白付 rAF 与内存 |

## 度量（2026-10-25，本机实测）

基线 = `a59b4bfe`（#1909），在临时 worktree 里用同一份 `node_modules` 构建：

| 项 | 基线 | 本票后 |
| --- | --- | --- |
| 入口 chunk `index-*.js` | 35.6K raw / 10.2K gzip | 35.6K raw / 10.2K gzip（**不变**） |
| `morphicons` chunk | — | 34.7K raw / 14.3K gzip（**懒加载**，只有 `UiIconMorph` 引用；入口不引用） |
| `UiIcon` 共享 chunk | — | 1.7K raw / 0.9K gzip |
| 全量 JS gzip | 4,814.7K | 4,830.3K（+15.6K，其中 14.3K 是懒加载的形变运行时） |

首屏增量 ≈ 0：形变运行时是独立 chunk，`index.html` 无 preload，入口 chunk 的 import 列表里没有它。

## 影响与后续

- **#1912**：其余 60 来个图标名登记进注册表，剩下的 75 个文件迁到 `UiIcon`（`AppTopBar` 已在 #1911 迁完，是第一份样板），导航配置字符串化，退役全局注册，摘掉 EP 图标依赖，清空迁移期基线。
- **#1913**：按白名单接上四处形变，补截图证据与体积报告。
- 本文的「目标映射」即 #1912 的执行单；落地时若有名字对不上，改这张表再迁，不许两边各写一份。
- 实施与 spec 的两处偏差（记录在案，不再回头改字）：① 形变模块预热取 **挂载后立即 import** 而不是 `requestIdleCallback` —— onMounted 本就在首帧之后，再加一层 idle 只会让首次点击更容易赶上「还没加载」；② 顶栏 `AppTopBar` 在 #1911 就迁完（原本计划留给 #1912）：它既然要改主题那几行，重写过的 import 行会被 `--diff` 增量门判成「新增的 EP 图标 import」，不迁完就红。
