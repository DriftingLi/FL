# ADR-0070: 域包形态与「目录即射程」的收口（后端按功能分包）

- 状态：已接受（2026-10-01，后端可维护性专项 P1 定案；迁移面 = `internal/service` + `internal/api` 的 30 个域，faq / notification 先行）
- 领域：后端 —— 目录分层 / 依赖方向 / 守卫射程（`internal/<域>/`、`pkg/httpx`、`internal/layers`）
- 修订：ADR-0065 登记的两笔债（`internal/api` 的 CI 超时、`internal/valuation/handler` 的解析出口）的处置**前提**；ADR-0060 / 0061 / 0064 的判据不动。

## 背景

后端可维护性专项（票 #1445）的四条诉求：① 清晰的 DDD 分层与单向依赖（可引 wire）；② 按功能细分目录、测试与实现同目录；③ 简化代码、抽公用组件；④ 简化注释。评估期实测基线：

- backend 636 个 Go 文件 / 161,682 行（含 `backend/docs/docs.go` 这份 29,727 行生成物）；非测试代码 46,134 行、注释 13,509 行 ⇒ 非测试注释率 22.6%。
- **诉求 ② 的一半已经达成**：345 个 `_test.go` 全部与实现同目录同包。
- **诉求 ① 也已成立但隐式**：导入图 0 个互相导入对，只有 `cmd/server` 导入 `internal/api`（装配根在 api，无人反向依赖它）——只是没有任何东西把这两条钉住。
- **诉求 ③ 证据不足**：非测试代码里「≥3 个文件逐字相同的 6 行窗口」只有 6 组，其中 5 组是 import 块 ⇒ 不做大扫除。
- 真正失衡的是**目录按技术分层切**（评估期实测）：`internal/service` 100 个非测试文件 / 29,377 行，`internal/api` 57 个非测试文件 / 14,964 行 —— 两个目录各自承载了**全部 30 个域**的技术半边；一个功能域的 handler、服务、DTO 分散在三处，`internal/api/deps.go` 243 行、`NewDeps` 141 行，装配根里仍是「先构造、后 setter」的形状（`deps.go:158/161` 的 `SetMailer`、`providers_core.go:71` 的 `SetProfileReviewService`；另有登录 Cookie、`SetFeatured`、`SetBinding`、`SetQuestionTags`、`SetCurrentCredential` 等 `Set*`）。
- **「按功能分包」的前置债**：18 处守卫 / 生成器用非递归 `os.ReadDir(dir)` 或硬编码路径枚举判定面 ⇒ 文件一搬，扫描面**安静变小**（不是报错，是判据自己走掉）。这条债不先还，搬迁是在拆自己的网。

另：ADR-0065 第 296-303 行原就登记「`internal/api` 在 CI（带 PG + `-race`）贴着 `go test` 的 10 分钟超时，下一波二选一：拆包，或显式抬高 `-timeout` 并写明理由」。本 ADR 是那条登记的执行面（拆包），不是另起一摊。

## 决策

1. **分层只显式化，不重造**：不引仓储层、不做聚合改造；把「单向依赖」与「测试同居」写进 `internal/layers` 守卫（判据只吃路径与源码，防空转：import 边 < 500 即 Fatal，实测 1000+），并遵守一条纪律——**只登记今天还不成立、且拆包后仍需成立的规矩**，已有守卫管着的不重复登记。
2. **不引入 google/wire**（被否备选里有完整理由）：替代做法是装配根按域拆 `providers_*.go`：`internal/api/providers_core.go` 出 `coreSingletons` + `provideCore`（构造顺序与原单函数逐字一致），每个域一个 `providers_<域>.go` 暴露 `provideXxx(c *coreSingletons, d *Deps)`，`NewDeps` 只做编排（core → 每域一行 → ADR-0061 的守护登记 → `SetMailer`）。
3. **一个功能域 = 一个包**：`internal/<域>/`，**包名 = 域名，域名取自 `internal/apitypes/domains.go` 的域声明表**（30 个域；那张表同时是 swagger definitions 前缀与前端生成物的域边界，不另立域清单）。包内按**文件名**分层：`handler.go`（HTTP 出口 + `RegisterRoutes`）、`service.go`（应用服务）、`dto.go`、`errors.go`；测试是与实现同目录同包的 `_test.go`。**不用子目录分层**（子目录 = 多包 = 导出面被迫扩大，且会让「目录即射程」的守卫再次失明；按文件名判定的先例是 `scripts/check-catalog-sort.mjs` 的 `GUARDED_PATH_SEGMENT`）。
4. **域包不得依赖装配根**：`RouterDeps` 住在 `internal/api`，不进域包；`RegisterRoutes` 只收它真正需要的依赖，由 `routes_registry.go` 的闭包注入。通用件只有三个出口：① 注入参数；② 升级到 `pkg/httpx`（HTTP 形状与请求解析，先例 `httpx.QueryIntPtr`）；③ 留在 `internal/service` 并导出（域实现共用的助手，P3 随 `internal/core` 收编）。
5. **HTTP 面由文件名定义，不再由目录定义**：`internal/testutil/codescan.go` 的 `HTTPSurface` 是**唯一出处**（`internal/api`、`internal/valuation/handler` 整目录 **或** 文件名前缀 `handler`）；`internal/layers` 通过注入 `isHTTP func(SourceFile) bool` 用同一判据（layers 不 import testutil —— 否则它的包内测试会撞 Go 的 import cycle in test）；`scripts/check-render-error-face.mjs` 用同一约定（`GUARDED_FILE_PREFIXES=['handler']` + `GUARDED_FILE_ROOT='backend/internal/'`）。⇒ P2 逐域迁移**零清单维护**。
6. **gin 只许出现在 HTTP 面与登记的 HTTP 基建里**（新判据）：HTTP 面 = 第 5 条的 `HTTPSurface`；基建白名单 = `internal/middleware`、`internal/logger`、`pkg/httpx`、`pkg/response`（**每条目录必须真有 ≥1 个 gin 宿主**，否则算死条目报红，同 gorm seam 的 `TestGormDBWhitelistIsLive`）。理由：域实现要的是解析好的入参，不是 `*gin.Context`。
7. **响应 DTO 随域搬，swagger definitions 键随包改名**：`service.FaqResult` → `faq.FaqResult`（`$ref` 同步）。**前端 TS 生成物字节级无变化**：`internal/apitypes/codegen.go` 的 `tsName()` 只取最后一个点之后 ⇒ 按功能分包不付前端代价。对外行为零变化（wire 文案 / 状态码 / 字段名逐字不动）。
8. **契约测试留在装配根（`internal/api`）**：它走 `NewRouter` 的全量装配链，而 `internal/api/router_test_helper_test.go:47-52` 已明文反对另起测试装配链（「装配链分叉 = 测试装配与生产装配各测各的」）。域内的单元测试与证据表随域搬 —— 即「测试与测试对象同目录」在契约层让位于「契约测试跟装配根」。
9. **证据表可以住在域包**：`nonnilOutlets*` 的落点按**组装发生在哪一层**选；runner 提成 `internal/testutil/nonnil.go` 的普通 `.go`（`MarshalKey` / `AssertNonNilOutlets`），并给 `internal/apitypes/nullability_lock_test.go` 补**跨包「一条事实一个证据」**：同一把钥匙出现在两个举证地即红（同包内重复仍由运行时的 `AssertNonNilOutlets` 抓）。
10. **「目录即射程」收口为清单制**（P0 已落，P2 只维护清单）：扫描器 `internal/testutil/codescan.go`（`Production` / `ProductionOrSelfTests` / `HTTPSurface`）；`ResponsePackages()` 是响应面清单的唯一出处（**P3-B 起不再手抄：现读域声明表现算域包目录**，只把非域包的静态面登记在 `responseStaticPackages`）；守卫 runner 加 `minChecked` 防空转（判定面文件数低于登记下界即红，文案点名「射程漂了，这不是「无违规」」）；域边界以域声明表为唯一出处。
11. **迁移动四个波次、一波一 PR**：≤3 个域 / diff ≤1500 行；生成链顺序硬性（gofmt/vet → `make swagger` → `go run ./cmd/gen-apitypes` → `go test ./...` → 前端检查）。

## 被否备选

- **引入 google/wire**：仓库已归档、无维护（P0 评估期复核，记录见票 #1445）；且装配面要表达的东西 wire 表达不了 —— 除了构造函数，还有运行时后置装配（`SetMailer` / `SetProfileReviewService`）与 ADR-0061 的守护登记表（「谁在哪一层拿 `*gorm.DB`」的白名单逐条带理由，是**文本级**事实）。
- **按技术分层保留现状、只加注释**：一个功能域的 handler / 服务 / DTO 仍散在三处，诉求 ② 没兑现。
- **子目录分层**（`internal/<域>/handler/`、`/service/`）：见决策 3。
- **域边界另立清单、不复用 `domains.go`**：两处域定义 = 两处漂移；那张表已经是 swagger 前缀与前端生成物的域边界（ADR-0048 决策 7 的顺序）。
- **一次全量重排**（一个 PR 搬 30 域）：diff 不可审，锁清单同步错一处就**静默**漏扫；改为波次。
- **契约测试搬进域包**：要么另造一份装配链（与本仓明文决策冲突），要么让域包反向依赖 `internal/api`（成环）。
- **机械删注释（诉求 ④ 的激进解）**：注释率 22.6% 里大量是「为什么」（ADR 实施回写、守卫理由、踩坑）；改走标准 + 试点 + 抽样评审（P4），硬边界：swagger 注解注释、`//nolint:` / `//go:build` 指令、三处用 `parser.ParseComments` 读注释的锁。
- **只抬 `-timeout` 不拆包**：ADR-0065 登记的二选一之一，但只治标（`internal/api` 实测 63 个非测试文件 + 143 个测试文件，仍是全仓最大的包），且不兑现诉求 ②。
