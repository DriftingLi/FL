# ADR-0108：ReleaseTransaction 统一应用回滚与版本化发布计划

- 状态：已接受
- 日期：2026-11-27
- 领域：部署 / 发布事务 / 回滚

## 背景

自动回滚已经使用 ReleaseTransaction 的反转计划，但手工 `do_rollback` 仍重新选择 tag、写环境文件、重建容器并自证。名为完整发布生命周期的 module 只覆盖了一个入口，两种回滚很容易在迁移预检、服务顺序与部分失败处理上漂移。

## 决策

1. **ReleaseTransaction 只统一应用发布回滚**。数据库恢复继续保持显式、可审计的独立 runbook，不进入应用事务。
2. **持久化版本化发布计划**。计划包含发布标识、previous/target 镜像、迁移边界与拓扑引用；手工回滚从中恢复 transaction，不再重新猜 tag。
3. **自动与手工回滚共享同一实现**，包括 migration preflight、反转顺序、镜像自证与最终 verify。
4. **部分失败继续尝试其余服务**，汇总失败后 verify 最终状态；任何未达目标都使事务整体失败。

## 后果

- 回滚编排只剩一个 implementation，自动与手工入口共享同一测试面。
- 需要增加“前端已回滚但后端失败”等部分失败矩阵，以及发布计划版本兼容测试。
- 数据库恢复仍由运维显式执行，避免把破坏性强、耗时不确定的操作塞进应用发布事务。
