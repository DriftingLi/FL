# 论坛输入区形态：图一的 编写/预览 + 工具栏，图二的粘贴/拖拽区

ADR-0044 定下「正文格式由作者声明」，并把**可发现性**认作这个功能的成败关键（「不能把它做成一个不起眼的小图标」）；ADR-0046 定下「预览与发布同源」，但当时也明确记下编辑端仍是近似（Vditor 在编辑态显示的是 lute 的解释）。

而 ADR-0044 同时拒绝了「复用 Vditor 作为学员端编辑器」：重依赖，且它自带的预览引擎与发布结果不一致。于是学员端的输入区一直停在**裸 textarea + 一个「预览」文字按钮**：声明子集已经有 标题/列表/加粗/代码/引用/链接/公式/mermaid，作者却只能靠记忆写语法；图片入口还是两套形态（回复框一个图标按钮、发帖表单一个虚线小按钮）。

本 ADR 决定学员端论坛输入区的形态，并把它与**声明子集**绑在一起。

## 决策

1. **输入区收敛为一个组件**（`components/student/ForumMarkdownInput.vue`）：发帖表单（`ForumPostForm`）与回复框（`ForumComposer`，含章节讨论）共用同一套形态。发帖侧原来的独立「图片」字段并入输入框——图片与正文是一个整体，不是并列字段。
2. **视图档位用下划线 tab**（新件 `UiUnderlineTabs`）：`数据档位`（会被保存的「纯文本 | Markdown」）继续用 `UiSegmentTabs`，`视图档位`（临时的「编写 | 预览」）用下划线 tab。两者不可互换——同一个卡片里并排两组同款胶囊，用户分不清哪组会永久保存。原 `MarkdownEditor`（Vditor）里手搓的下划线 tab 一并收敛到新件，全站不再有第三处 tab 形态。
3. **工具栏按钮集 = 已声明子集**：三级标题、加粗、斜体、引用、代码、链接、无序列表、有序列表、任务列表。这条绑定是硬约束——按钮承诺的语法必须真能渲染出来（表格仍被 `disable`，所以没有表格按钮；公式与 mermaid 在子集内但不在图一的按钮集里，不做按钮）。任务列表因此**进入声明子集**（见 ADR-0044 子集补记）：能点就得能渲染。
4. **标题只给三级标题一个按钮**，不做 H1–H6 浮层：正文层级由页面标题占用，回复里多一级选择只增加点击成本；要高一级低一级手打 `##` / `####` 更快。图一右上角与 markdown 无关的四类（@提及 / 保存的回复 / 交叉引用 / 撤销重做）不做。
5. **每个按钮有中文悬停提示**（`UiTooltip`，落在按钮下方、300ms 延迟）：文案与图标名的唯一来源是 `utils/markdownToolbar.MARKDOWN_TOOLBAR_ITEMS`，组件里不许另抄一份中文。置灰用 `aria-disabled` 而**不是**原生 `disabled`——原生 disabled 的按钮不派发鼠标事件，预览档下整排气泡会同时消失。
6. **图片入口 = 整块虚线区 + 三入口（点击 / 粘贴 / 拖拽）**：拖拽登记进 `useForumImageUpload` 单点，顺带修掉一个既有毛病——不接管 dragover 时，把图片拖到页面上浏览器会直接导航去打开那张图。粘贴监听从 **document 级**改为**卡片级转发**：原来两处同时挂载时要靠 `stopPropagation` 防止同一张图被上传两遍，改为「卡片内粘贴 → 转发给上传单点」后这个隐患从结构上消失，且只有焦点在正文里粘贴才被接管。
7. **预览仍走 `ForumContent` 这一个 UGC 渲染单点**（预览与发布同源，重申 ADR-0044/0046）；编写/预览是输入框组件自有的视图状态，与持久化的 `content_format` 分开（原来两者混在 `useForumContentFormat` 里）。
8. **纯文本档不出现 tab / 工具栏 / 提示行**：没有可预览的渲染结果，摆一排禁用按钮只会制造误解。这是 ADR-0044「Markdown 完全 opt-in」的直接推论。
9. **一行中文能力与边界提示**（表格不渲染、图片走粘贴区），与 ADR-0045 的属地披露同类，登记为 `docs/agents/ui-conventions.md`「不写说明性 hint」的**明确例外**。理由是 ADR-0046 自己的判据：「判据放在作者看得见的地方（编辑器提示 + 预览里的越界说明）」——内容精选编辑器已经有这么一行。
10. **工具栏插入优先走 `document.execCommand('insertText')`**：直接改 value 会把浏览器原生撤销栈弄坏（打完字点一下加粗，Ctrl+Z 的语义就变了）。不支持或结果对不上时回退到「写回 v-model + 恢复选区」，此时原生撤销栈会丢。

## Consequences

- **任务列表进入声明子集**（ADR-0044 子集补记）：解析器与 `markstream-vue` 本就产出/渲染 `checkbox_input`（实测渲染成 `span.checkbox-node` + 勾选图形，带 `aria-label` 的**只读**标记——勾选状态由源串决定，读者侧不可切换），服务端与渲染配置无需改动。跨端风险与 #900 加公式/mermaid 同类：**移动端是否渲染任务列表尚未验证**（归 #905 / @zhengcookie）。
- **工具栏是「能力清单」的第二处表达**：子集变了必须同步按钮表，否则按钮会承诺渲染不出来的语法。判据单点在 `utils/markdownToolbar.ts`，改动时两个文件（按钮表 + `ForumContent` 的 `md.disable` 列表）必须一起看。
- **`execCommand` 已废弃**，但仍是唯一能保住原生撤销栈的路径；happy-dom 下走的是回退路径，**真实浏览器的撤销语义需人工确认**（已写进 PR 验收证据清单）。
- **首访用户看不到新 UI**：默认纯文本是 ADR-0044 的既定取舍（不主动改变任何人的表达），本批不翻案。可发现性依赖既有的「正文格式」分段控件。
- **`UiInput` 新增 expose**（`focus` / `getTextarea`）：选区编辑必须拿到原生 textarea。纯增量，既有调用方零 diff。
- **移动端输入区仍与 Web 不同**（本批不动）：渲染面的一致性已由 ADR-0046 覆盖，输入面形态差异属已知且可接受。

## 评审补记（PR #1018 的两轴评审）

评审提出 2 条应修 + 10 条可选，逐条处置如下（改法都进了代码与用例）：

- **应修 ①：原生插入路径的选区会被 Element Plus 覆盖**。`document.execCommand('insertText')` 会同步派发 `input`，EP 的 `useCursor` 随即在自己的 `nextTick` 里按「插入段末尾」执行 `setSelectionRange(pos, pos)` —— 它**必然把选区塌陷成 caret**，而它的回调先注册、先执行，于是「选中一段点加粗 → 选区没了」「光标处点加粗 → 接着打字落在星号外面」。改法：成功分支再晚一个 tick 补一次选区。happy-dom 跑到的是回退路径，所以这条**必须人工在浏览器确认**（已进 PR 的人工清单）。
- **应修 ②：拖拽命中面只有虚线区**。粘贴早已是卡片级，拖拽却只挂在虚线区根节点上——把图片拖到正文 / 工具栏 / 卡片留白上，浏览器会执行 drop 默认动作**直接导航去打开那张图**，草稿全丢；而「拖到正文上」恰恰是最自然的动作。改法：拖拽与粘贴一样由卡片接住后转发（`ForumImageUploader` 暴露三个 handler），虚线区不再自己挂监听。
- **可选（已采纳）**：```围栏整块选中再点「代码」会套娃`` → 补去壳；`lineSpan` 在 `start=0` 且正文以换行开头时算错行 → 显式分支；斜体在 `***x***` 上越点越多星 → 只脱一层；整条 `[文字](url)` 选中再点 → 去壳（链接是**半切换**，注释已改准）；`dragleave` 判据收进 composable（调用方不必记得写 `.self`）+ window 级 `dragend`/`drop` 兜底（ESC 取消拖拽时高亮不会卡住）；拖拽判定加 `types` 含 `Files`（框内拖动选中文字不再无端高亮）；`triggerSelect` 在上传中也拦住 + 虚线区补「上传中」态；`UiInput.getTextarea` 只认真正的 textarea（EP 若把 expose 改回 Ref 就退化成 `undefined`，而不是把 Ref 当元素读坏正文）；能力提示补上「公式与图表」（子集里有、按钮集里没有，否则作者无从发现）；工具栏插入受 `maxlength` 约束（回复侧原本只有后端会报错）。
- **可选（有意不采纳）**：`UiUnderlineTabs` 的 ARIA 只有 `role=tablist/tab` + `aria-selected`、没有方向键漫游 —— 与既有的「分段控件」`UiSegmentTabs` **同口径**；要补应当两件一起补，只给一件加会让这一族控件出现两套键盘行为（组件注释已记这条取舍）。

## Considered Options

- **把 Vditor 引到学员端**：拒绝——ADR-0044 已拒，理由未变（重依赖 + 自有预览引擎破坏预览同源）。
- **视图档位复用 `UiSegmentTabs`**：拒绝——见决策 2，同卡片两组胶囊会让人分不清哪组是永久保存的表达格式。代价是要新增一件 UI 组件并写进约定文件（已做）。
- **标题做 H1–H6 浮层菜单**：拒绝——见决策 4；借用 `UiMoreMenu` 更不行，它的边界是「治理动作收纳」。
- **粘贴区只做 点击 + 粘贴**（不做拖拽）：拒绝——图二的语义就是 drop，且不接管 dragover 时拖图会导航走。
- **保留 document 级粘贴监听**：拒绝——多处同时挂载时同一张图会被上传两遍（`ForumComposer` 的历史注释记录过这个坑），卡片转发后天然只有一个落点。
