# ADR-0068: 「本题得分」是判分 module 的唯一出口（修订 ADR-0010）

- 状态：已接受（2026-09-28，真实缺陷评审 grilling 定案；含存量回填）
- 领域：培训 —— 判分（grading）/ 模拟考试（mock exam）
- 修订：ADR-0010 §1 判分收敛的出口语义

## 背景

`gradeQuestion` 对多选题返回 `(false, partial)`（半对给部分分）、对简答题返回 `(nil, 0)`（AI 分另走 `ShortAnswer.Score`）；而 `mock_exam_service.go` 的总分只在 `IsCorrect == true` 时累加 `Earned`。结果 `total_score < Σ details[].score`——同一份交卷响应自相矛盾，学员看到的总分被系统性低估（多选半对等于白答、简答 10 分档等于没分）。实测：10 分多选只选对 1/3 ⇒ 明细 1.7、总分 0。

## 决策

1. **Earned = 本题得分**：`gradeOne` 出口统一——客观题取判分结果（含多选部分分），简答题取 AI 评分（AI 不可用降级为 0）；`IsCorrect` 三态语义不变（客观对错 / 短答 nil / 练习流 AI 及格覆写）。
2. **总分 = Σ Earned**：`total_score` 只有一处累加；`correct_count` 仍只认 `IsCorrect`。判分 module 因此可以写下一条机器判据：`total_score == Σ details[].score`。
3. **明细同源**：`detail.Score` 与总分同一事实（短答不再出现「0/10」与「AI 给 8 分」并排）。
4. **存量回填**：`mock_exam.score` 与 result JSON 的 `total_score` 视为**派生值**（由已落库的逐题事实派生），按逐题 `max(score, ai_score)` 重算一次、幂等。这不是改判——不改对错、不改任何一题的判分事实。

## 被否备选

- **装配层合并两个来源**：判分出口不动，`total = Σ Earned + Σ ShortAnswer.Score`。总分出现两个来源，且 `detail.Score` 仍是 0 ⇒ 那条「total = Σ details[].score」的锁写不出来。
- **短答 AI 分定性为参考值、不入总分**：与 CONTEXT.md「模拟考试 = 自动判分 + AI 评分」冲突，且要在 UI 上区分「得分」与「参考分」。
- **不回填 / 回填但标注旧口径**：前者历史成绩永久偏低；后者要给记录加版本位、前端分支展示，成本高于回填且对学员无用。

## 实施回写（2026-09-28，随 P1 修复批）

- **决策 1 的落地形态**：出口唯一化写在 `gradingEngine.gradeOne` 内（短答分支取到 AI 分即覆盖 `Earned`），装配层零判据。顺带把 `MockExamService` 的短答 adapter 从 Submit 内的临时包装收到构造处（`grader ShortAnswerGrader`，与 `PracticeModeService.grader` 同形）——一处包装、一处注入，测试也因此能喂 fake grader 直接锁 Submit 级总分。
- **决策 2 的机器判据**：锁形状是「Σ details[].score == total_score」，在**交卷响应**与**落库 result JSON** 两处各断言一次（`mock_exam_total_score_test.go`）。
- **期望值更新（非放宽）**：`grading_engine_test.go` 两条短答用例的 `Earned` 由 0 改为 AI 分（8 / 2）——本 ADR 改的正是这条现状，表格锁跟着改口径；降级与 adapter 返回 nil 两条仍为 0。
- **决策 3 的前端落地**：`MockExam.vue` 明细行原本不展示单题得分；现按 `details[].score` 展示一处，短答的 AI 评语单独一行（不再有「0 分」与「AI 给 8 分」并排的形态）。同时把明细卡判色改成三态：`is_correct === null`（简答未判对错）不再画成错题——它现在带着得分，标红就是同一处自相矛盾。
- **决策 4 的落地形态**：`service.BackfillMockExamTotalScores` + `cmd/backfill-mock-exam-scores`。口径 = 本题得分 `max(details[].score, details[].ai_score)`、`total_score = Σ`、**`details[].score` 同写为本**（否则「total == Σ details[].score」这条锁在存量行上不成立）；`is_correct` / `ai_score` / `max_score` / `correct_count` / `accuracy` 一律不动。幂等判据取「第二次运行 updated == 0」，无逐题事实的行（空 result / details 为 null）记 `no_facts` 原样保留 —— 不把「不知道」写成「0 分」。
- **同类未收口（已登记）**：`useAdminTable` 的装载写回形状与 `useAsyncPage` 同病（`await fetch` 之后直接写 `list`/`total`，无批次代数），admin 面竞态窗口较窄、且不在 ADR-0069 的收编面内，另立票处理。
