# ADR-0081：侧栏密度单档与导航图标尺寸回归

- 状态：已采纳（2026-10-26）
- 相关：[ADR-0072](ADR-0072-无缝外壳与四端顶栏.md)（外壳与十字细线）、[ADR-0079](ADR-0079-图标体系数据化与状态形变.md)（图标唯一入口 `UiIcon`）、[ADR-0080](ADR-0080-字号只走-token-阶梯.md)（字号阶梯）、[ui-conventions](../../docs/agents/ui-conventions.md)

## 背景

两条同时暴露的问题，都出在侧栏：

1. **密度分叉**：学员端 / 导师端 / 招聘端传了 `sidebar-density="compact"`，管理端不传。差别不在字号（四端共用 `.nav-item-label { font-size: var(--text-sm) }` = 14px），而在行的纵向内边距 —— `.nav-item` 8px vs compact 6px、分组标题上边距 12px vs 8px。**同样的 14px 字塞进更矮的行**，观感上就成了「学员端的字更小更密」。维护者对照两端后判定管理端这档更顺眼，要求四端统一到它。
2. **图标尺寸回归**：#1912 把图标迁到 `UiIcon` 之后，两处按 Element Plus 写的选择器再也不会命中 —— `UiIcon` 渲染的是裸 `<svg>`，没有 `.el-icon` 类：

   ```css
   .nav-item-icon .el-icon        { font-size: var(--text-lg); }   /* 18px，已失效 */
   .nav-group-icon-only .el-icon  { font-size: var(--text-base); } /* 16px，已失效 */
   ```

   于是图标回落到 `UiIcon` 的默认 `1em`（≈16px），比设计的 18px 小一档。检查脚本 `check-icons` 只扫模板（禁 `<el-icon>` 标签），扫不到 `<style>` 里这类**失效选择器**，所以它静默活在代码里。

## 决策

### 1. 侧栏密度只剩单档

删掉 `AppSidebar.density`、`SidebarLayout.sidebarDensity`、`:class` 里的 `is-compact`、以及两条 `.app-sidebar.is-compact …` 覆盖规则；学员 / 导师 / 招聘三端移除 `sidebar-density="compact"`。**默认那档（= 管理端）成为唯一档。**

为什么不反过来「四端都传 compact」：管理端行数最多、信息密度最高，压紧只会更挤；而且维护者的判据就是「管理端这档顺眼」。

为什么不只是把 `density` 的默认值改成 `compact`：那等于把一个旋钮的默认档当暗档用，调用方看不出差异，下一个人仍会问「为什么这里传了一个和默认一样的值」。

### 2. 图标尺寸回到容器字号

```css
.nav-item-icon       { font-size: var(--text-lg); }    /* 18px */
.nav-group-icon-only { font-size: var(--text-base); }  /* 16px */
```

`UiIcon` 默认 `1em`，容器给字号即图标尺寸 —— 不再依赖任何 `.el-icon` 选择器。这条口径与 ADR-0079「尺寸默认 1em 跟随字号」一致。

### 3. 内容区宽度不动

`content-width="narrow"`（学员 / 导师 / 招聘）保留：那是**内容列**的限宽，与侧栏观感无关，本期不碰。

## 后果

- 四端侧栏的行高、分组标题间距、图标尺寸**完全一致**；学员 / 导师 / 招聘端每行比之前高约 4px（一屏大约少 2–3 行）。
- 导航图标从实际 ≈16px 回到 18px，分组折叠态的图标回到 16px，视觉重量略增。
- 不再存在「两种密度」。将来若真需要密度档，重新引入时必须同时给出四端取值并在本 ADR 追加决策 —— 不允许只给某一端开。

## 被否备选

- **四端都传 `compact`**：见决策 1，管理端更挤且与维护者观感相反。
- **按视口自适应密度（`clamp()` / 容器查询）**：四端视口一致，没有区分依据；只是给同一屏加一层不可预测的抖动。
- **继续用 `.el-icon` 选择器、给 `UiIcon` 补一个 `.el-icon` 类**：把 Element Plus 的类名当自有契约，下一次迁移还会掉；容器字号是零假设的写法。
