# ADR-0091：诊断回答配图的白名单代理与降级 —— 修订 ADR-0063 决策 3

- 状态：Accepted（2026-11-03）；**修订 ADR-0063 决策 3**（「外链图一律丢弃」→「白名单内改写代理、白名单外降级文字」），ADR-0063 其余决策继续有效
- 日期：2026-11-03
- 领域：AI 域 / 外部服务接入（承接 ADR-0029 单 port、ADR-0031 计量闸门、ADR-0032 传输通道、ADR-0063 图片归一与本站代理、ADR-0088 部署面）
- 票：地图 #2236 · 决策 #2239（`wayfinder:grilling`，已 close）
- 判据物：`backend/internal/aiassistant/diagnosis_adapter.go`（改写与降级）、`backend/internal/aiassistant/diagnosis_proxy.go`（白名单解析与上游取字节）、`backend/internal/aiassistant/handler_diagnosis.go`（新路由）、`backend/internal/config/config.go`（配置校验）、`backend/internal/deploy/topology.go`（部署事实源）

## 背景

v2 契约（#2237 / #2242 的迁移目标）把回答正文里的配图换成**交付方自家 OSS 的公网链接**：

```
https://hrwai-guangzhou.oss-cn-beijing.aliyuncs.com/forklift/repair_img/linde/<型号>__<原名>.png
```

2026-11-03 实测一张真图 `HTTP 200 / image/png / 72,321 B`，响应头只有 `ETag` / `Last-Modified` / `x-oss-request-id`，**无 `Cache-Control`、无 `Access-Control-Allow-Origin`**。形状来自对方脚本 `27_图片伴随输出_脚本节点_v9.py:576` 的 `"![%s](%s)" % (cap, _url(name, ctx))`——即 markdown 图，URL 是最终形态（该脚本 :669-680 对已是 `http` 的图原样放行）。

而现行归一链对「不认识的 markdown 图」是**整段删除并静默 `return ""`**（`diagnosis_adapter.go:762-764`）。两者相撞的结果不是「有风险」，是**必然**：v2 一切流，所有配图 100% 消失，且零信号——只能等学员报「图没了」。

三个已核实的前提，它们决定了这个决策的形状（证据来自交付方源码与实测，**都在仓外**：本机参考目录 docs/reference/外部AI助手/ 被 `.gitignore` 的 `docs/*` 忽略、`git ls-files` 为 0，且内含密钥 ⇒ 下文的对方源码行号是**取证记录**，不是仓内可点路径）：

1. **对方 OSS 桶不是它独占的**：`forklift-ecs/backend/config.py:18` 自述「同一批 OSS 资源，本项目独占 create/ 前缀」⇒ 同桶还有别的项目前缀；`/create` 是**上传**基准，与图片基准 `/forklift/repair_img` 不同。
2. **文件名不是内容哈希**：中力是 `images_all/<规范名>.png`，林德是 `linde/<型号>__<原名>.jpg` ⇒ 同名可换内容，这条直接否掉了 `immutable` 缓存。
3. **移动端根本不发图请求**：`utils/aiAnswerBody.uts:29-34` 先 `expandImageMarkers` 把 `![alt](url)` 展开成 alt 文字，`utils/markdown.uts:35-36` 明写论坛档不含 image ⇒ 本决策的受益面**只有 Web**。

## 决策

1. **口径不动，只补第三条通路**。ADR-0063 决策 3 的立场「本站代理是图片唯一出口」继续成立：不重开助手公网子域、不在 nginx 直挂、不承认这次是例外。既有两条通路是「助手内网静态路径」（`/diagnosis/manual/*`）与「`answer_images[]` 令牌」（归一到前者）；本条补的是「对方 OSS 公网 URL」→ 新代理。**白名单内改写、白名单外降级**（票面选项 4 混合）。
2. **白名单五道闸，缺一不可**。对 `![alt](url)` 判定：
   - ① `https://` + host + 路径前缀——host 与前缀由 `DIAGNOSIS_V2_OSS_BASE` 承载，代码里 `forklift/repair_img` 仍作**校验常量**（配置只许换 host / bucket，不许扩前缀）；
   - ② 剥 `?#`（`?x-oss-process=` 之类不属于资源路径），与 `diagnosis_adapter.go:694` 同口径；
   - ③ 逐段复用 `staticSegmentPattern`（`diagnosis_proxy.go:60`，`^[\p{L}\p{N}][\p{L}\p{N}_\-.]*$`）——`images_all` / `linde` **不写死**，品牌目录任意单层均可；
   - ④ 末段用**新常量** `diagnosisImageExtPattern = (?i)\.(png|jpg|jpeg|webp)$`：**故意不复用** `staticExtPattern`（`:63` 含 `pdf`，那是给 manual 发手册用的）。`/ossimg/` 的位置是 `![](…)` 图片语法，放行 pdf 只会是坏图 ⇒ pdf 落到「白名单外」降级为文字；
   - ⑤ 先 `url.PathUnescape` **一次**，再逐段 `url.PathEscape`。这是本决策最容易写错的一处：对方生成 URL 时已对文件名 `quote()`（`27_图片伴随输出_脚本节点_v9.py:553/561/564`），到手已是百分号编码；再 `PathEscape` 一次就是 `%25…` 双重编码，代理侧解不回来 ⇒ **必然 404**。「解一次 → 校验 → 逐段转义」正是 `resolveStaticSubpath`（`diagnosis_proxy.go:83-85` + `:102-104`）的既有性质，照抄即可，不新增不变式。
3. **新路由 `GET /api/ai-assistant/diagnosis/ossimg/*filepath`，与 manual 同构**：同 `group`、同 `middleware.OptionalAuth`、同 handler 形状（`defer body.Close()`、上游 `Content-Type` 非空才设、`io.Copy`、错误走 `response.NotFound`）。**不改既有 manual 链**。上游取字节的能力挂在 `DiagnosisProxyService` 上（加 OSS base 字段，不拆 service——白名单判定与 manual 共用 `staticSegmentPattern`，拆开必然漂移）。
4. **host 走配置 `DIAGNOSIS_V2_OSS_BASE`**：部署侧进 `topology.go` 声明表并同步 compose 与默认值生成物；运行期默认**空**（与 `DiagnosisAssistantURL` 同形，故在 `backend/internal/deploy/topology_test.go` 的重叠子集判据下不算漂移、不必进 `layerDivergences`）。**空值不是合法终态**：配置非空时必须过三条校验（`https://`、path 以 `/forklift/repair_img` 开头、可解析），不合法**即启动失败**，**绝不回退到「不过滤」**——过滤失效比启动失败危险得多。但校验的**挂点**要避一个坑：`DiagnosisAssistantURL` 允许为空是因为「空 = 诊断功能不可用但服务照跑」，若新变量也在 `Validate()` 里无条件要求非空，默认部署会**直接起不来**。故校验挂在「v2 通道开关已翻」（#2242 的通道选择项）之后——开关没翻时它不被读、为空也不报；开关翻了才要求它合法。这处挂点是实施票要落的一行，写在这里是为了不让它被误读成「无条件必填」。
5. **两种失败统一降级成 alt 文字一行**。白名单外（adapter 同步判定）：`![alt](外链)` → `alt` 纯文本，alt 复用 `diagnosisAltSanitizer`（`:629`）清洗，空则用 **`诊断配图`**（与 `diagnosisMarkdownImage` 的 `:772` 同词，不造新词）。白名单内但代理取不到（运行时）：**不做同步 HEAD 预取**——adapter 只管改写，取不到交给浏览器 `<img>` 坏图态显示 alt。代价是「图坏了只看到一个词而不是一句解释」，换来每条回答不多一次出站往返。
6. **缓存头 `public, max-age=86400`**，与 `handler_diagnosis.go:125` 逐字一致。**不用 `immutable`**：文件名是规范名不是内容哈希，同名可换内容，`immutable` 会让更新在客户端卡一年。
7. **降级留一行日志，不打点**：host + 是否在白名单 + URL 前 120 字符，level 取 debug/info。不开计数器、不动 Prometheus、**不进计量面**（ADR-0031 明令图片不混进计量）。理由就是背景里那句「零信号」：对方换域名时，这行日志是本仓唯一的发现手段。
8. **明确不做**：不跟随重定向（`http.Client` 默认跟随；实施时关掉，避免白名单被 302 绕过）；不 HEAD 预取；不改移动端（它不发图请求）；不为「增量归一」改伪流式（见后果）。

## 备选

- **放行（选项 3）**——拒绝。破 ADR-0063 决策 3，且对方换 bucket 我方会瞎；追踪面从「我方可控」变成「第三方内容驱动学员浏览器」。
- **全降级纯文字（选项 2）**——拒绝。最安全但学员一张图都看不到，而诊断场景里「这张图长什么样」正是最要紧的信息；本仓已有「图取得到」这条通路（manual 代理）证明画像可行。
- **复用 `/diagnosis/manual/*` 承载 OSS 图**——拒绝。manual 的 baseURL 是**助手内网主机**，OSS 是**公网第三方**；混进同一个校验函数会让「静态根」同时承担两种语义（内网目录白名单 vs 外网 host 白名单），且 `staticRoots` 那两层目录校验与 OSS 的前缀校验不是一回事。
- **复用 `staticExtPattern`（含 pdf）**——拒绝。见决策 ④，`![](…)` 里放 PDF 只会是坏图。
- **同步 HEAD 预取校验可达性**——拒绝。每条回答多一次出站往返，且取得到与否本就是运行时事实；浏览器坏图态已经给了可接受的降级。
- **`immutable` 长缓存**——拒绝。见决策 6。

## 后果

- **ADR-0063 决策 3 自此分叉成两条通路并存**：内网静态路径照旧，公网 OSS 走新代理。任何后续「要不要开放行」的重议，入口是本 ADR，不是 ADR-0063。
- **多一跳**：学员浏览器的图片请求打到本仓后端，再出站到阿里云 OSS。图片不进计量面（`DiagnosisProxyService` 从不经过闸门，与 ADR-0031 一致）；缓存头 1 天，命中后由浏览器/CDN 承接。
- **白名单是按对方源码推定的，不是按契约文档**：v2 契约 `方案B_v2API接口清单.md` §5.1 只列 `answer / badges / trace / elapsed` 四字段、全文无一处 `![` 示例 ⇒ 回答正文图片的确切 markdown 形状是**文档未闭合项**。联调时必须用真实响应复核一次；若对方换了前缀，改配置不够、要同步改 `forklift/repair_img` 这个校验常量（这正是决策 7 那行日志存在的意义）。
- **另一个未闭合项**：v2 的 `answer` 里是否仍会出现 `answer_images[]` / `[IMG:]` 令牌。若会，归一链的令牌分支继续生效，与本次新通路互不冲突（令牌归一成 manual 代理、OSS 链接归一成 ossimg 代理）。
- **双重编码是这块的常驻坑位**：任何「改 URL 形状」的后续改动都要先问一句「这段是不是已经编码过了」。已写进决策 ⑤，测试应有一条带中文/百分号段名的用例。
- 运维面代价：对方 OSS 域名或前缀变更时，表现为「配图集体变成『诊断配图』四个字」，不会报错、不会 5xx。发现靠决策 7 的日志。
