# ADR-0004: 评估结果事实性（建议与 λ 值在评估时点持久化锁定）

- 状态：已接受（2026-08-05，architecture-review 全量优化）
- 领域：残值评估 —— 评估记录 / 建议（suggestions）

## 背景

评估记录（evaluations 表）持久化了 K 系数、残值与置信区间，但**建议（suggestions）与 λ 值不入库**：
详情/报告每次读取时用**当时**的 `coefficient_configs` 动态重建。管理员修改系数配置后，历史评估记录的建议文字（如"残值率 42%"）会静默变化——创建响应、详情、PDF 可以互相矛盾。

事实核查：`KTimeAdjusted` 与维度分是入库 K 系数的纯函数（不漂移）；唯一跨时间漂移的是建议（百分比从全局系数配置动态读取）。

## 决策

评估记录是不可变事实。建议与本次评估使用的 λ 值在**评估时点**持久化锁定：

- `evaluations.suggestions`（jsonb）——创建时写入，详情/报告直接读取，不再重建；
- `evaluations.lambda_electric` / `lambda_combustion`——创建时使用的 λ，随响应下发给前端（走势图数据驱动）；
- 创建响应返回锁定值，与详情/报告同源；
- 存量记录用**当前**系数配置重算一次并写入（`cmd/backfill-evaluation-suggestions`，幂等：已有建议跳过）。

## 约束

- 历史记录的"当时系数配置"不可考，回填以当前配置为最佳近似；
- 维度分与 KTimeAdjusted 仍为入库系数的纯函数、不持久化（不漂移，读时计算）。

## 后果

- 管理员改系数配置不再改变历史评估结论；
- 报告协调器不再需要"重建建议"（配合报告流程收敛，见候选 2）。
- 代价：一个 jsonb + 两个 float 列、一次回填命令。

## 未来路径

若要精确还原历史时点系数（而非"评估时点锁定"的近似），需要**系数配置版本化**
（每次变更保留版本快照，评估记录引用版本号）——较大工程，需求出现时重新评估。
