# IP 属地：发布那一刻的快照，建立在可信取 IP 口径之上

论坛里「对方大概在什么地域」是真实语境：同样的故障在不同气候与工况下成因不同——北方冬季的启动问题与南方潮湿环境的问题往往不是一回事。主流社区的做法是在署名行带一个属地（「18 小时前 · 上海」），本仓库此前没有这个概念。

但只要开始显示属地，两个问题立刻变成前提：**这个 IP 是谁说的**（可不可信），以及**什么时候取的**（快照还是实时）。本批的四张票分别解决这两件事：取 IP 口径（#888）、落库与采集（#889）、展示与披露（#890）、以及本文件与其余文档收尾（#891）。

## 属地是发布那一刻的快照，不是实时查询

属地**只在首次发布时解析一次并落库**，查询路径不碰它。

若改成查询时实时解析，用户换个网络（手机切 WiFi、开代理、出差）就会让他**所有历史回复的属地整体漂移**——那不是「属地」而是「当前位置」。社区语义要的是「他当时在哪」，而且这个语义必须稳定：一条回复的署名行是内容的一部分，不应该在读者两次刷新之间改变。

由此推出两条硬约束：

- **编辑帖子不写该字段**：编辑改的是正文，不是「发布」这个动作。`UpdateTopic` 是全量替换语义（四字段都必填都显式写），但 `ip_province`/`ip_city` 不在其中——与 `content_format` 同类（ADR-0044），属于「作者没在声明就不动它」的字段。
- **不回填历史数据**：当时没有记录 IP，回填只能瞎猜。存量行由列默认值得到空串，展示侧整段不渲染，老帖看起来与今天毫无差别。

## 粒度：省 / 市两档，不做区县

属地是**纯社区氛围标识**，不承载任何业务功能。粒度收到省市是三个最小化手段之一（另两个是「只在发布时取快照」与「不做二次用途」）。

不做区县的理由不是「数据拿不到」，而是**与定位不符**：区县级会把一个氛围标识变成接近定位的信息，收益（读者获得的语境）几乎不增加，隐私面却显著放大。同理，**属地不参与搜索 / 筛选 / 排序**——一旦进入查询口径，它就从展示决定变成了个人信息处理用途，需要单独的告知与评估。

**境外地址显示州 / 省级地名**（如 `California`）：库给什么就存什么，不额外做国别映射。本批数据只有两列，没有国家级字段，因此不构造「美国」这类别名——多一层映射就多一处会过时的规则。

## 取 IP 口径：可信代理 + 取 IP 单点

属地必须建立在**服务端认定的**客户端 IP 上，否则用户塞一个请求头就能冒充任意省份。这条在本批之前是不成立的：

- gin 默认 `TrustedProxies = 0.0.0.0/0`（**信任所有代理**），`c.ClientIP()` 因此采信 `X-Forwarded-For` 并取**最左**项；
- nginx 用 `$proxy_add_x_forwarded_for` 把真实对端**追加**在末尾，XFF 形如 `<客户端伪造>, <真实IP>`；
- 于是 `X-Forwarded-For: 114.114.114.114` 就改写了服务端认定的客户端 IP——按 IP 限流可被绕过、审计日志写假 IP（这两条与属地无关，是既有问题）。

修法：

1. **可信代理按部署登记**（`TRUSTED_PROXIES`，默认空 = 不信任任何代理）。取值是**部署事实**，不是通用默认值：本部署 frontend 用 host 网络模式，容器看到的 TCP 对端是宿主机在 `forklift-net` 网桥上的地址，而**两台宿主机的网段不同**（production 172.19.0.0/16、testing 192.168.240.0/20），所以只能按实测登记并留环境变量覆盖口。
2. **只登记网关与回环，不写整段私网**：gin 的算法是「从右往左跳过可信代理、取第一个不可信地址」。若把 `172.16.0.0/12` 整段写进可信列表，**真实客户端自己落在私网里时**（局域网用户）会被当成代理而继续往左找，客户端自带的伪造值反而胜出。这条语义有专门的用例钉住。
3. **取 IP 收敛成一个函数**（`middleware.ClientIP`）：限流键、审计日志、访问日志、属地四个消费方共用，口径只有一处。
4. **反代到后端的每个 location 都必须显式设置 `X-Forwarded-For`**：nginx 只在设置时才覆写 / 追加该头，没设置的 location 会把客户端自带的同名头原样透传；后端开始信任本机对端之后，那个伪造值就会被采信。`/static/` 就是复审抓到的漏网那条——它当时只设了 `X-Real-IP`。
5. **启动自检**：声明了可信代理、但本机默认网关不在其中时，启动日志点名实际网关。换宿主机 / 重建 docker 网络会让旧网段失配，症状不是报错，而是**所有请求被算作同一个客户端**（按 IP 限流退化为全局限流）——这条日志把静默退化变成一句话。它也刻意**不自动信任网关**：网关是不是一个会清洗请求头的代理是部署事实，裸机 NAT 场景下自动信任它等于把伪造头直接放行。

## 为什么是 ip2region，而不是 GeoLite2 / 在线 API

- **GeoLite2 的 EULA 限制再分发**：本仓库是 public，数据库不能入库，只能构建期用 Secrets 拉取，等于给部署链引入一个外部账号依赖，构建也不可复现。
- **在线地理 API**：每写一条帖子多一次外网调用（延迟、配额、可能收费、服务不可用时降级），并且**把用户 IP 发给第三方**——与最小化方向正好相反。
- **ip2region**：MIT、可入库、中文省市口径、有 Go 实现。数据文件进仓库，构建可复现、不引外部账号。

**代价要认**：xdb 是数据快照，会过时。新增或调整的 IP 段会解析不出或解析错，缓解方式是「定期人工替换 + 版本留痕」，而不是追求实时——精确到省市的实时免费数据本身不存在。

## 数据：两列、NOT NULL DEFAULT 空串、只在发布时写

`forum_topics` 与 `forum_replies` 各加 `ip_province` / `ip_city` 两列（VARCHAR(64)，NOT NULL DEFAULT ''）。

- **两列而不是拼接串**：展示口径以后若从「市」降级成「省」，两列不必回填；拼接串得解析。与 `content_format` 同一条思路。
- **NOT NULL DEFAULT 空串而不是可空**：可空会把「没有属地」压成 NULL 与空串两个状态，而展示侧只需要一个「空」。存量行由 DEFAULT 天然得到空串，**不做任何回填**。
- **解析失败一律落空**：内网 / 保留地址（库对它们返回 `Reserved|Reserved|Reserved|0|0`）、非法地址、IPv6、库中无该段，全部折成空串，**不报错也不阻断发帖**。

## 展示：市优先退省，为空整段不渲染

- **位置**：回复署名行接在相对时间之后（「18 小时前 · 上海」）、帖子正文作者行与时间同一行。列表卡片**不加**（卡片信息密度已经很高）。
- **只显示一级**：市优先、市为空退到省。署名行是窄的（时间 · 属地 · 楼主 / 已采纳标签），两级叠加会互相挤压；数据仍按两级存，日后想改成「省 · 市」不必回填。
- **为空即整段不渲染**：不显示「未知」、不留占位、不出现悬空的分隔符。历史帖因此看起来与今天完全一样。
- **端与范围**：只做 Web。移动端消费与渲染另立 Issue（受移动端四门验收约束）；章节讨论自动覆盖——批一起 composer 与卡片已是单点组件。

## 披露：`ui-conventions` 的明确例外

发帖与回复输入区各加一行极短提示：「发布内容会显示 IP 属地」。

⚠️ 这与 `docs/agents/ui-conventions.md`「不要写说明性 hint 文本，仅保留必要的功能性提示」**存在张力**，本批认定**披露属于必要的功能性提示**而非装饰：属地在点发布那一刻才产生，事前告知比事后解释便宜。该文件已把这一行登记为**明确例外**——否则下一个按约定办事的人（人或 agent）清掉它时是完全合规的。

## Consequences

- **xdb 版本留痕**：当前数据文件 `backend/internal/geolocation/data/ip2region_v4.xdb`，库自身头部记录的生成时间 **2026-08-28T04:43:01Z**，md5 `c30f0c57e4ba14cab6aa5a15e976ac1c`，来源为 ip2region 仓库的 `data/ip2region_v4.xdb`；Go 绑定 `github.com/lionsoul2014/ip2region/binding/golang v0.0.0-20260901011515-c1a1fc7d5941`（MIT，见 `THIRD_PARTY.md`）。**更新方式**：人工替换 xdb → 同步更新包内 `DataSourceMD5` 常量 → 重新构建部署；指纹不一致时有测试直接变红，版本记录由 `geolocation.DataVersion()` 从库头读出（不手抄日期）。
- **只覆盖 IPv4**：本部署域名没有 AAAA 记录，客户端一律以 IPv4 到达；IPv6 地址落空（不报错）。若日后启用 IPv6，需要另入库并接第二份数据文件。
- **移动端缺口**：移动端目前不消费这两个字段，因此不会出现跨端不一致（它只是没有属地）——补齐另立 Issue。
- **库过时的可见症状**：新 IP 段解析不出 → 那条帖子没有属地（整段不渲染），而不是显示错误地区。这是有意的降级方向。

## Considered Options

- **查询时实时解析**：无需新列，实现最省。拒绝——属地会随用户当前网络漂移，那是「当前位置」不是「属地」（详见上文）。
- **一个拼接串列（「江苏省南京市」）**：一列搞定、展示直接拼。拒绝——展示口径想降级成「只显示省」时要解析字符串，而两列天然支持。
- **只做省级**：隐私面更小。拒绝——省市是主流社区的口径，市级才是读者真正能对上的语境（「南京」比「江苏」有信息量），而区县才有隐私问题。
- **把属地放进 `ForumAuthor`（作者对象）**：前端取用最方便（作者行与署名行都现成）。拒绝——`ForumAuthor` 描述的是**用户**（id / 昵称 / 头像），而属地是**这条内容**在发布那一刻的属性；放进作者对象会诱导后来者把它当成用户资料（缓存、复用、跨帖共享），正好破坏快照语义。它是帖子 / 回复 DTO 上的字段。
- **用在线 IP 地理 API**：零数据入库、永远最新。拒绝——多一次外网调用、配额与可用性风险，且把用户 IP 发给第三方。
- **用 MaxMind GeoLite2**：数据质量最好。拒绝——EULA 限制再分发，public 仓库不能入库（详见上文）。
- **给用户一个属地开关**：主流社区均不提供。拒绝——属地的意义在于「读者知道」，可关掉的属地等于没有；若日后要做，属功能变更而不是配置项。
