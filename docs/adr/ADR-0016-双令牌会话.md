# ADR-0016: 双令牌会话（access 2h + refresh 7 天轮换）

- 状态：已接受（2026-08-18）——扩展 ADR-0002；前置条件（生产 HTTPS）已就绪（PR #254）
- 领域：账号与认证 —— 会话（session）/ JWT 签发与刷新

## 背景

原认证为单 JWT（默认 24h，ADR-0002），无刷新机制。问题：令牌泄露攻击窗口长达 24h；登出仅黑名单当前 access；无法支持「短生命周期 access + 可吊销长周期 refresh」的通行做法（issue #163）。

生产此前为 HTTP（ADR-0003），Secure Cookie 不可用，双令牌 cookie 通道被硬约束阻塞；PR #254 启用 80/443 HTTPS 后约束解除。

## 决策

- **双令牌**：access = 2h（JWT_EXPIRES_HOURS 默认 24→2），refresh = 7 天（新增 JWT_REFRESH_EXPIRES_DAYS，默认 7）。
- **claims 增加 `token_type`**（access/refresh）：`VerifyAccess` 仅中间件用、`ValidateRefresh` 仅刷新端点用，交叉使用即拒绝。每次签发带随机 `jti`，保证轮换后新 token 必然不同于旧 token（避免同秒 iat 重合）。
- **刷新端点** `POST /api/auth/refresh`：请求体带 refresh → 校验类型/黑名单/有效期 → 签发新 access + 新 refresh（轮换），旧 refresh 立即入黑名单（防重放）；失败统一 401（防枚举）。
- **签发路径**：全部登录/注册/改账号（密码三入口、邮箱/手机验证码、默认用户）经 `issueLogin`/session `IssuePair` 双令牌下发；登录响应增加 `refresh_token`（`token` 保留兼容）。
- **黑名单**：key 语义复用 `jwt:blacklist:`，**只管理 refresh**；登出（/logout 请求体带 refresh）撤销 refresh；access 生命周期短、不入黑名单、自然过期。
- **中间件**：`resolveClaims` 用 `VerifyAccess`（仅 access），移除 access 黑名单检查。`/logout` 不依赖 JWTAuth（access 过期时也能撤销 refresh / 登出）。
- **前端**：`storage.ts` 双 key；`client.ts` 401 → 模块级**单飞行**静默刷新 → 重试原请求（并发去重），刷新失败才走既有 401 策略；`stores/auth.ts` 双令牌生命周期。
- **Cookie 通道**：跨子域 cookie 恢复只带 access（不自动续期），既有约束延续，不劣化现状。

## 兼容与迁移

同仓同发直接切换，不做新旧双轨：access 短令牌即时生效，refresh 由前端在首次登录后持有；存量 access 令牌无 token_type 视为非 access 于下个请求自然过期并走刷新。

## 后果

- access 泄露窗口从 24h 缩至 2h；refresh 可轮换/可吊销，登出语义可靠。
- 客户端 2h 内会话不中断（401 静默刷新），考试/评估等长任务不受影响。
- 多设备/多会话列表未纳入（可另立 spec）。
