# ADR-0078：可交互图标的尺寸分档（桌面 28 / 移动 40）

- 状态：已采纳（2026-10-25）
- 相关：[#1893](https://github.com/DriftingLi/FL/issues/1893)（W2 第三项）、[ADR-0035](ADR-0035-UI封装层.md)（封装层）、[ui-conventions](../../docs/agents/ui-conventions.md)

## 背景

无障碍复查里，图标按钮有两个方向的缺口：**可访问名**（已由 #1898 补齐并加 AST 锁）与**点按尺寸**。尺寸这条一直没有成文口径：全站图标控件以 32 / 36px 为主，28px 若干，另有缩略图右上角的 16px 删除键。触屏用户在小控件上点空的概率远高于鼠标用户，而「桌面密集后台」又不允许把按钮统一放大到 44px。

WCAG 2.5.5（AAA）要求 44×44；2.5.8（AA，Target Size Minimum）要求 24×24。本项目桌面端是鼠标为主，取 2.5.8 之上的 28 作为工程下限；移动端是手指为主，取 40。

## 决策

| 断点 | 下限 | 口径 |
| --- | --- | --- |
| 桌面（≥ 768px） | **28×28** | 图标控件的**盒子**尺寸（`h-7/size-7` 及以上）。`h-8`（32）与 `h-9`（36）是现状主流，不动 |
| 移动端（< 768px） | **40×40** | 图标控件的**命中区**。可以是盒子本身（`max-md:h-10 max-md:w-10`），也可以只扩热区（`after:absolute after:-inset-*`），**视觉尺寸可以不放大** |

判定对象是「纯图标、无文字的交互控件」（`button` / `a` / `UiButton`）。以下不算：

- 装饰性图形（章节序号块、时间线圆点）；
- 图片（`<img>`，logo 等）；
- 带文字的控件（其命中区由文字与 padding 决定，不按本条判）。

**允许「视觉尺寸 < 下限、命中区达标」**：在缩略图 / 密集行内，放大盒子会破坏排版，此时用伪元素扩热区（`after:-inset-1.5` = +12px，`after:-inset-3` = +24px）。

## 已落地

- `ForumImageUploader` 缩略图删除键：视觉仍 16px，热区桌面 28 / 移动 40（`after:-inset-1.5` / `max-md:after:-inset-3`）；
- `ChatPageShell` 浮动图标组、`SuggestionArrow`：桌面保持 28-32，移动端盒子抬到 40（`max-md:h-10 max-md:w-10`）。

## 例外与后续

- 新增图标控件默认落在这两档内；确需更小的（例如密集表格行内的「⋯」），在 PR 里登记理由并使用热区扩展；
- 尺寸目前由评审把关，**没有机械守卫**：模板里盒子的最终尺寸可能来自父级、padding 或 `:class` 表达式，静态推断会误报。若将来出现反复回潮，再按「显式 `size-*`/`h-*` 类」做窄口径扫描。
