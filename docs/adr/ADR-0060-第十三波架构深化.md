# ADR-0060: 第十三波架构深化（端点 Render 收窄 / 会话终止两族 / 收藏开关 / append 判据 / 配置漂移锁 / 分页容器归位 / 角色称谓 / 路由描述符 / 侧栏渲染 / 目录排序第二源）

- 状态：已接受（2026-09-20，architecture review 12 candidates → 10 立项、2 降级观察；经 grilling 逐一定案）｜领域：端点骨架 interface / 会话终止 / 多态收藏 / 分页 / 配置默认值 / 契约容器 / 角色词表 / 路由描述符 / 侧栏渲染 / 课程目录
- 拆票顺序：**票1a → 票1b**（先换 74 处纯成功闭包，`RenderFunc` 改签名时只动 helper 定义一处，74 个调用点不跟改）；余九票彼此独立。后端票先合、前端票后合（沿用波次惯例）。

## 背景

第十二波（ADR-0059）后本轮扫 `backend/` + `frontend/` + CI/守卫三面，移动端不在范围（未产生候选）。三处 hot-spot 假设被实测证伪并撤回：`router/index.ts` 的 63 次 churn 是页面描述符（ADR-0047 §2）2026-09-13 落地前的历史信号；`JobPlaza`/`Resumes` 早已迁进 `useAsyncPage` 的 append 档；`model/models.go` 已于 `b1d87726` 拆分。本轮的贯穿形态与前几波不同——不是「派生物散在消费面」，而是**骨架把本该属于 interface 的职责整体让渡给 caller**：`Endpoint` 让 `Render` 全权写响应，于是「记得自己查域表」只能用注释约束（实测 180 处手写闭包、106 处读 `err`、20 处显式查表）；`requiresAuth` 用「缺省 true + meta 继承」表达，于是顶层 13 条记录里 8 条处于「忘写一行即静默公开」；append 档用「本批满一批」推断还有没有下一批，而后端首页主动给置顶条留一格（实测只回 19）。同时抓到一条凭证层缺口：账号硬删除路径不吊销 refresh，而 `RotateRefresh` 不查用户是否存在——已注销身份最长仍有 7 天可用凭证。

## 决策

1. **端点 Render 收窄（两票）**：票1a 把 74 处只写成功面的闭包换成 `renderMsg`/`invoke`（ADR-0053 §1 备好、至今 0 使用的两个适配器）；票1b 把 `err` 从 `RenderFunc` 的 interface 上拿掉——错误渲染归骨架，实测四种定制（固定 500 / 固定 404 / 固定 400 / 查域表）全部表达为域表条目（`errStatusEntry` 加可选固定文案槽）。**不留逃生口**：需要非信封错误形状的面走 raw handler，沿用既有 6 处先例。`endpoint.go:156-163` 那份与事实分两处的手写例外清单随之取消。
2. **会话终止两族（含行为变更）**：`SignOut`（撤销手上这枚 refresh + 清本角色 cookie；token 取自请求体还是 Bearer 头是入口差异，不是第三种语义）与 `RevokeIdentity`（用户级吊销标记，改密·禁用·注销共用）。**注销走「先写吊销标记、标记失败即不执行硬删除」**——与改密「密码已生效故吊销失败只记日志」的尽力而为策略有意不同，因为注销没有任何已生效动作值得牺牲凭证失效。删除 `api/cookie.go` 的 pass-through 与 `security/session.go` 零调用的 `Set/ClearCookieForRole`。
3. **收藏开关**：一个 module 两个具名入口——`useFavorite(key, id)`（自带 check，服务单对象开关）与 `useFavoriteList(key)`（不 check，态由列表行携带，toggle 返回新态供回填与「只看收藏」筛选重载）；「哪种可收藏」的判据唯一来自内容对象表，key 的类型收窄到 `favoritable=true` 那一档（编译期即挡不可收藏类型）。内容对象表管声明槽、本 module 管运行期状态机，二者正交。
4. **append 判据换服务端事实（含行为变更）**：`useAsyncPage` 的 append 档判据从「本批满一批」改为响应里已有的 `page < pages`（`Page/Pages/Total` 早已下发，**零契约变更**），不留旧档——append 模式必须能取到 `pages`，取不到即不合法而非静默退回。`ForumDetail` 的手写窗口（含逐页 for 循环重载）迁入该档，前后端批次大小常量耦合（`ForumReplyMaxPageSize` 与那行注释）自动消失。
5. **配置默认值只扩锁不派生**：`config.go` 纳入 `internal/deploy` 既有漂移锁的文件清单（只比对重叠子集），并删掉 `setDefaults` 与 `Load` 内部各写一遍的两处（`redis_pool_size`、`redis_dial_timeout`）。**不做**「抽中立叶子表让 config 派生」——`EnvVars` 自陈范围是「compose 中带非空默认值的变量」，且 `internal/deploy` 只被生成期引用；把它扩进运行期是范围变更而非收敛。登记为条件项：同一默认值第三次漂移时再升表。
6. **分页容器归位**：`Page<T> = {items, total}` 定义在 `src/api/` 侧，各域列表函数出口即返回它（那里本就知道生成物类型），`useAdminTable` 的 `fetch` 契约改吃 `Page<T>`；11 页 17 处 `{list: res.items||[], total: res.total||0}` 手抄消失。不在 `client.ts` 猜键名、不让 api 层反向 import composable。
7. **角色称谓单点（含行为变更）**：canonical 为「讲师」，词表是仲裁者、现场文案向它收敛（**不**按 caller 视角分档，学员侧与管理侧同名）。套用 ADR-0056 §8 的 label descriptor + 穷尽 Record + 内联扫描形态，把扫描白名单从 status 扩到角色；收敛 23 个前端文件与 2 处后端用户可见串。
8. **路由描述符补严（两小项）**：`requiresAuth` 从「缺省 + 继承」改为必填（13 条顶层记录逐条判定意图，公开集合 = 显式 `false` 的登记清单，新增忘写从静默公开变编译报错）；删 `routeNames.ts` 常量表，`RouteName` 由 `pages.ts` 派生——83 处 name 字面量天然被 union 穷尽检查，35 处路径手拼改走表派生的跳转 helper。
9. **侧栏项级渲染 seam**：只收 `AppSidebar` 内部（三层嵌套 × 外链/router-link 共 7 份 markup、470 行 scoped CSS），并给 `navigation.ts` 四条判定纯函数补 spec（其注释记着两次线上故障却无测试）。`TrainingLayout` 按 `courseStore.chapters` 现算 `NavItem[]` 是合法的运行时 producer，**不动**。
10. **目录排序第二源**：专业方向与课程等级两处排序串改从 `catalog_specs.go` 取（实测与读面逐字同串）；`course.sort_order ASC, course.course_id ASC` 带表别名、与 spec 不同源，登记不动。顺手合并 6 个完全同形的 update 请求 struct 与两份逐字相同的 swap Parse。**不**立目录树读面 module。

## 理由

十条同为「把 caller 必知的事实搬回 interface / 把判据的宿主从注释与巧合升级为类型与锁」。`deletion test` 逐条过：删 106 处错误定制与 17 处容器映射后复杂度**集中**而非搬走；`useFavorite` 两入口、会话终止两族各自对应真实存在的两种调用形与两种失败策略（两个 adapter = 真 seam），而 `useDirtyDraft`（117 行 1 caller）与「给 `Endpoint` 加 `RawRender` 逃生槽」都是单实现，本波不立。行为变更三处且都有意的：票2 注销即吊销（合规口径）、票4 论坛回复从恒判到底变真能翻（缺陷修复性质）、票7 称谓统一（用户可见文案）；余七条零字节漂移。

## 被否备选

`EndSession(scope)` 兼表两族、`useFavorite(key,id,{initial})` 兼表「态已知/待查」——同一参数兼表两义是 ADR-0056 §2 已否过的形态；骨架先查表再把状态码交给 `Render`（复杂度只是搬走，deletion test 不过）；`client.ts` 统一嗅探容器键（把「哪个键算列表」从类型降为运行期约定，新域换键名静默返回空列表）；首页多取一条凑满批次以维持「首批必满」的假设（用实现巧合把一个错的判据焊住，同 ADR-0059 对题库 status 通道的否因）；config 派生自部署声明表（扩大该表自陈范围并给运行期加一条依赖边）；侧栏 producer 归位（只有一个，假想 seam）。

## 锁

后端：`RenderFunc` 签名变更由既有响应字节锁与 37 处论坛契约测试护航，加「Render 闭包内不得出现 `response.ServerError/NotFound/BadRequest`」静态扫描；注销路径的用例（吊销标记写失败 → 账号仍在；旧 refresh 轮换 → 401）。前端：append 档新增「首批短一格仍可翻页」用例（照置顶真实形态）+ 公开页面清单锁 + 禁 `push('/…')` 手拼守卫；内容对象表与 `target_type` 互等锁（扩展 ADR-0059 §2 那条）；称谓穷尽 Record + 内联扫描含角色维度；`pages/` 不得再出现 `{list: res.…}` 手抄映射（`--all` 报存量、`--diff` 阻断新增）。CI：漂移锁文件清单加 `config.go`；目录读面不得出现裸排序串。

## 实施回记（2026-09-20，落地时逐条实测）

开票时的四个计数是估的，实际如下——后续会话按这一节行事，不要按上文计数：

- **票1a**：`internal/api` 共 **179** 个手写 `Render` 闭包，可换 `renderMsg` 适配器的是 **81** 个（非 74）。
  余量分布：41 个错误分支用的是固定文案而非 `err.Error()`、12 个完全不读 `err`（属票1b）、
  其余为真定制载荷。落地时响应字节锁抓到一处载荷实参是现场构造的 map（`featured.go` 的
  `content_id`/`view_count`）——**分类器必须校验成功渲染的第二个实参确实是端点响应变量**，
  否则字段名会漂。
- **票8a**：「顶层 13 条中 8 条未写 `requiresAuth`」不准——顶层 **14** 条记录**全部**已显式写过
  （13 条 `false` + `LinkOut` 一条 `true`）。本票的净收益因此是「类型层必填 + 公开页逐名锁定」，
  没有存量入册工作；需要补值的是 61 条布局子记录。
  ⚠️ 守卫判据是 `matched.some(requiresAuth === true)`，故子记录写显式值零行为漂移；
  但 `getRoutes()` 里布局记录与其同 path 的子记录并存，**不能再拿 `requiresAuth` 当布局的区分判据**
  （`recruitRoutes.spec.ts` 因此需要改用 `!r.name`）。
- **票9**：侧栏行 markup 实测 **9** 份（非 7）；`navigation.ts` 四条判定的 spec **早已存在**
  （第十二波前的 `c591a6ca`，15 例覆盖四条判定含两次线上故障）——本票 (b) 的前提为假，
  改为在其上补 7 例并修掉「零测试」那句过时注释。
- **票10**：逐字相同的 swap `Parse` 是 **3** 份（非 2）；`SwapPositionSort` 那份错误优先级不同，
  不并入。
- **票6**：17 处 / 11 页的计数按实测成立。两处与票面措辞不同：
  ① 锁的形态是 **vitest spec**（`frontend/src/api/__tests__/page.spec.ts`，照
  `statusWordsTemplate.spec.ts` 的先例），不是 `scripts/check-*.mjs` 的 `--all` / `--diff` 一对——
  因此「`--all` 报存量」改为「断言当前命中集合为空」，且判定按**形状**（`list:` 与换成中立键的
  `items:` 都判红）而非按文件；必须走 AST 的原因是页面里 `const { list: items } = useAdminTable(…)`
  的解构改名与手抄在正则下无法区分。
  ② 除 17 处之外，`questionBankApi.getQuestions` 出口收窄还牵出**一处票面未列的页面**
  （`pages/tutor/QuestionManage.vue`，走 `useAsyncPage` 而非 `useAdminTable`，读的是 `res.questions`），
  一并改成 `res.items`。学员端 `forumApi` 的读取面（`listTopics` / `my-*`）**刻意不收窄**：
  它们要带 `pages` 字段喂票4 的 append 判据。
- 契约测试装配根此前**没有可用的黑名单存储**（`NewDeps` 造的是 Redis 版，测试链路无 Redis），
  所以「真实写凭证状态」的端点在测试里一律走不通。本波起 `newContractDeps` 注入内存实现。

- 票8b 登记的「类型循环」**可解，不是障碍**：循环只存在于「`pages: PageDescriptor[]` 且
  `PageDescriptor.name: RouteName` 且 `RouteName` 又由 `pages` 派生」这个写法里。
  改用**先派生、后标注**：`const pagesData = [...] as const` → `export type RouteName = (typeof pagesData)[number]['name']`
  → `export const pages: readonly PageDescriptor[] = pagesData`。
  形状错漏仍被第二行标注接住（穷尽性检查不丢），而 `name` 的字面量类型在 `as const` 阶段就已定型。
  连带效果：`legacyRedirects` / 布局重定向里指向**不在描述符表内**的名字会直接编译报错——
  这正是本票要的（孤儿路由名从「静默断链」变成「写不出来」）。

- **票1b**：接口收成 `RenderFunc[Req,Resp] func(c *gin.Context, req *Req, resp *Resp)`，
  错误面由 `Handle` 无条件走 `ErrStatus.renderError`，**Render 在错误路径上根本不被调用**。
  比预期更强的收获：`err` 不在闭包作用域内 ⇒ 在 Render 里写错误信封**连编译都过不了**，
  类型层就是那道锁，静态守卫（`scripts/check-render-error-face.mjs`，`--all` 存量 0）只是第二道。
  「无条件定制」的表达是 `errStatusEntry{sentinel: nil, status, message}` 且
  **排在 `*ParseError` 规则之前**（这保住了目录域「解析错误与业务错误共用一个状态码」的既有字节），
  单码端点用 `errStatusAll` / `errStatusAllMsg`；`WithSuccess` 签名与票1a 的 81 处调用点一字未改。
  余量清点：179 个闭包里票1a 收 81、本票把剩下一切「读 err 的分支」外提，最终 95 处
  真定制 Render 只写成功面；例外清单注释取消，需要非信封形状的继续走 raw handler（逃生槽仍为零）。
- **票1b 的一处实测更正（第五种错误形态）**：决策段说「实测四种定制全部表达为域表条目」，
  落地后 `/code-review` 复核发现漏了第五种——`response.Xxx(c, "查询失败: "+err.Error())`
  这一族（前缀 + 错误原文）。表里当时只有「固定文案」一格，收编会把前缀静默丢掉，
  即**第 10 个端点级别的未登记行为变更**（courses / notification / profile_review / settings 等 9 处）。
  现补 `errStatusEntry.errPrefix` 与 `errStatusAllPrefix`，并修正两处把
  「一切错误同一个码」收成 `{fallback}` 的写法（那连 *ParseError 的状态码都改了）。
  教训：把「四种」写成事实之前，得先按**文案表达式形态**分类计数，而不是只看状态码种类。

- **票3**：四处单对象复制 + 一处列表复制收成一个 module 两个入口，实测净减 224 行。
  超出票面的收获：`useQuestionPeripherals` 里那条 `FavoritePeripheralAdapter` 注入 seam
  在唯一实现搬走后变成**一个 adapter 的假想 seam**，按本 ADR 自己的判据删掉，
  观察面改挂到 `@/api/favorite` 边界（既有 spec 本就在那里打桩，故其消费者零改动）。
  列表行的槽位命名刻意用 `targetId` 而非 `id`：错题行主键是 `id`、收藏目标是 `question_id`，
  叫 `id` 会让 `toggle(item)` 整行直传也能过类型检查然后收藏错对象。
- **票7**：「23 个前端文件」是**含注释**的文件数；按运行期可见文案实测是前端 8 个文件。
  后端实际收敛 4 个文件（审计资源标签表、AI 评分降级三条、讲师不存在、讲师账号或密码错误）
  加 `internal/api` 的 6 条运行期串，`swag init`（v1.16.4，与 CI 同钉版）再生成 `backend/docs`。
  两处刻意不动并说明：`@Tags 管理端-导师` 与描述性注释不是运行期可见串，改 tag 会牵动生成物
  分组结构；`auth_service.go` 种子账号 `Name:"导师"` 是**数据**（用户可自行改显示名），不是界面称谓。
  全站扫描只禁两个无歧义词（「讲师」与退役别名「导师」）——「学员/企业/管理员」同时是日常名词，
  实测两处正当用法，全站禁裸串会连它们一起判红，与 #1103「通用词只在写错处禁回流」同一取舍。
- **票2 的一处口径偏离**（现行实现如此，未来要改需另立案）：估值模块的登出
  （`valuation/handler/auth.go` 的 `Logout`）仍直接调 `RevokeRefresh`，**没走 `SignOut`**。
  实测该模块 `auth.go` 内没有任何 Cookie 读写——它是纯 Bearer 面，走 `SignOut` 会给一个
  它从不设置的 cookie 加一条清除头，那是本波未登记的第四处行为变更。
  即「同一族、cookie 半边不适用」，与票面「两条入口都经本动作」不完全一致。


- **票4 的两条前提为假，落地时按实测改了**（后续波次不要再引用这两句）：
  1. 「列表响应早已携带 `page`/`pages`/`total` ⇒ 零契约变更」——对**两个现存 append 消费者不成立**：
     `service.JobListResult` 与 `service.RecruitListResult` 只有 `{items, total}`。
     硬性要求 `pages` 会把职位广场与简历库的「加载更多」直接删掉。现判据为
     「`请求页 < pages`，`pages` 缺位时由 `total` 与本批批大小派生」——仍是服务端事实，
     除数是本页自己发出的 page_size；两者皆缺才报契约违例，且不退回旧判据。
  2. 「后端首页主动给置顶条留一格（实测只回 19）」——健康路径上**不成立**：
     `forum_service.go` 留格后又补了一格，首页恒等于 `page_size`，且有后端契约测试钉住。
     19/20 只在被置顶那行取不到时出现（采纳者已注销走 `INNER JOIN`、或
     `accepted_reply_id` 成孤儿）。19-of-20 用例照建（锁的名字就是它），
     但本票真正稳定修掉的是**同一猜测的另一方向**：最后一批恰好满批时留着一个
     点了只会打到空页的死「加载更多」。
  3. 顺带的行为代价（如实登记，非静默）：删回复后阅读位置收回到首 20 条——
     「保持已加载 N 页不缩回第一页」在现有 interface 上表达不出来，未为单一 caller 扩 interface。
  4. 落地时另有三处未登记的界面行为差，一并记账（都属「论坛翻页」这条已登记变更的机器被复用到
     别的入口时暴露出来的旧毛病）：`reset()` 现在返回 promise（写操作后要等重载的 caller 能 await）、
     `loadMore` 飞行中不再把 `hasMore` 清零（旧写法会在请求途中闪出「没有更多回复」，
     且一批失败后重试入口永久消失）、凭证切换改为清空累积条目（旧写法把新一批**追加**到
     上一个证件的列表上，JobPlaza / Resumes 双堆叠）。
  5. **spec 场景 4「在章节讨论里同样能翻完回复」原设计未覆盖**：票面只写了 ForumDetail 手写窗口
     迁入 + 常量耦合消失。落地复核时按场景补做——`ChapterDiscussion` 的回复面改走同一 append 档
     （批大小 20，与详情页一致），原来的「仅显示前 N 条 + 跳详情页」截断提示换成真的翻页入口，
     翻到底才显示「已显示全部 N 条」。这条是场景驱动补的，不在决策段里。
