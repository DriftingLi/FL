# ADR-0047: 第八波架构深化——授权能力声明 / 页面描述符 / 论坛域拆分 / 证件作用域 / 部署拓扑

- 状态：已接受（2026-09-13，architecture review 8 candidates，其中移动端候选因范围外移除、其余 7 项经 grilling 逐一定案）
- 领域：授权与会话 / 前端路由与导航 / 论坛域 / 证件作用域 / 部署与 CI / 装配根 / AI 功能注册表

## 背景

第七波深化（ADR-0015）后，architecture review 扫描最近 ~200 次提交的 hot spots（`frontend/src/pages` 901 次、`backend/internal/service` 696 次、`backend/internal/api` 566 次），产出 8 个 deepening candidates。

其中候选 01（移动端壳层与 9,343 行「契约测试」）以**范围理由**移除：移动端由 @zhengcookie 负责，不在根仓库 architecture review 范围内（范围约定见 `AGENTS.md`「架构评审范围」）。余下 7 项经 `/grilling` 逐一定案，本 ADR 记录定案结论，作为未来架构评审的锚点，避免重新提议已决策事项。

## 决策

### 1. 授权能力声明（backend + codegen 到 frontend）

- 新建 `internal/authz`：能力常量 + 角色→能力表 + 判定函数，被 `security` / `middleware` / `api` / `valuation` **单向依赖**（消除 `security/session.go` 与 `middleware/audit.go` 里硬编码的角色字面量——它们此前硬编码是因为 security 不能 import service）。
- **能力 = 资源域.动作**（如 `forum.moderate`、`valuation.config.write`），端点授权、路由可见性、页面内动作入口**三层共用同一能力位**。
- **数据级不变式不进能力表**：所有权（仅楼主可采纳）、可见作用域（按当前证件分区）、状态前置（经验帖不可被采纳）与能力正交，由拥有该不变式的域以**具名谓词**单点表达（后端为事实源）。词条见 `CONTEXT.md`「能力」「数据级不变式」。
- 「角色 → 能力」以**窄域 codegen** 下发前端（延伸 ADR-0030 的表→codegen 先例；不改变 ADR-0019 推迟全量 codegen 的结论）。前端只声明「页面 → 所需能力」。
- 迁移**先立 adapter、后收敛**：第一批把 `RoleRequired` 改造为 authz 的薄 adapter（签名不变，40 个蓝图零改动）；随后收敛落地时**一批做完**而非按域分多次提交——偏差记录：① 50 处调用点与能力表是 1:1 映射（只有 contact / resume_pdf 两侧共用一个能力会越权，已拆成 `contact.request`/`contact.respond` 与 `resume.pdf`/`recruit.resume_pdf`）；② 30+ 个 api 契约测试逐角色断言 HTTP 可达性，一次全量即可证明零漂移，分域提交不会增加证据强度；③ `RoleRequired` 已删除，守卫只剩 `CapabilityRequired` 一个形态，并有全仓扫描锁钉住它不复活。

### 2. 页面描述符（frontend，与候选 1 的前端半边并表）

- 一张页面描述符（path / name / 工作区 / 所需能力 / 导航归属 / 详情页归属）派生：路由记录、导航树、以及测试断言。
- 消掉 `config/__tests__/navigation.spec.ts` 里手抄的 EXPECTED 映射表——它今天与路由表不同源，是「加一个页面改 4 处」的第 4 处。
- 候选 1 与候选 2 的前端半边**并表落地**：先出候选 1 的 authz 与 codegen（描述符的输入），紧随做描述符本身，避免同一批文件（`router/index.ts`、`navigation.ts`、该测试）改两遍。

### 3. 论坛域拆分（backend）

`forum_service.go`（2,276 行 / 60 个函数 / 7 个概念）拆出两个 module，**分两次落地、各自独立验收**：

- **奖励政策 module（先做）**：interface 约两个方法——`Award(tx, 事实)` / `Rollback(tx, ref, reasons)`；implementation 吸收**发放事实判定**（今日该判据在 1915 / 2042 / 1161 / 2251 四处被独立重写、三种 delta 语义）、防刷策略（配对 3 折半、5 归零；日 3 / 日 5）、幂等占坑、写流水与站内信构造。阈值表与配对衰减作为 internal seam 的纯函数，供无库单测。
- **读面 module（后做）**：`ListTopics` / `GetTopic` / 置顶分页 / 管理端视图收成返回 typed page 的 module；删除逐字重复的 `AdminGetTopic`（handler pass-through）、消灭穿过 seam 的 `map[string]any`，并把 clock 注入补齐（与同装配根的 Contribution / CheckIn 一致，测试不再需要直接改库里的 `created_at` 伪造时间）。

### 4. 证件作用域的事实源移到服务端

- 受作用域端点**在注册时声明自己的作用域**，缺省读请求上下文里的 `current_credential_id`；客户端只在**显式浏览非当前证件**时传参覆盖（显式优先）。
- 解析成本：中间件在 JWT 解析后取用一次并放进请求上下文，底层走按 user 维度的短 TTL 缓存，切换端点写库即失效（不写进 JWT claim——那与「切换立即生效」直接冲突）。
- 删除 `client.ts` 的豁免前缀表与拦截器注入（同一句话今天在四处各说一遍）；`useAsyncPage` 的 `credentialScoped` 开关保留——它管的是「切换后是否重装」，与「按什么过滤」是两件事。

**实现中的两处偏差（已核实理由）**：

1. **不加短 TTL 缓存**：解析代价是一次主键读，与受作用域端点自身的查询相比可忽略；缓存会引入失效逻辑与新的漂移面。留待有实测证据再评估。
2. **公开路由保留客户端显式传参**：课程列表 `/api/courses`、全局搜索 `/api/search`、目录树 `/api/catalog/tree`、标签 `/api/tags` 都是**公开路由**（无 JWTAuth），服务端拿不到登录用户，服务端兜底在这四条上不生效——调用方显式传当前证件（`CourseList`/`Materials`/`SearchPage`/`QuestionBank` 四处）。把它们改成可选认证（`OptionalAuth`）是**过期 token 处理**的行为变更，属独立决策，不在本片顺手做。

### 5. 部署拓扑声明（部署与 CI）

- `internal/deploy` 一张 **Go 源码声明表**（与 `ai_feature_registry.go` 同构）+ `cmd/gen-deploy` 生成器 + `go test` 字节级 in-sync 断言；覆盖 env 名与默认值、端口、域名与子域路由、服务清单。
- `docker-compose.prod.yml` 与 `.github/workflows/cd.yml` 消费生成物；`frontend/nginx-host.conf` **只做一致性校验，不整文件生成**（SSL / location / header 等运维细节留在手写文件里）。
- 本期**不重构** `scripts/deploy-remote.sh` 的 1,337 行内部结构。

### 6. 域装配描述符（backend，分两步）

- 第一步（本期）：每个域导出一份**模型清单**由 `testutil/db.go` 汇总派生；路由注册收进一个**域聚合点**声明。
- `Deps` 的 37 个业务字段**暂留手写**；用 codegen 生成 struct 字段留作有证据后再评估（生成字段会让「handler 拿不到依赖」从编译错误退化为运行期查找）。

### 7. AI 功能注册表派生面扩展

- `ai_feature_registry.go` 增加 **slug** 与 **adapter（transport）** 两列；codegen 输出到前端。
- 前端路由的 slug 正则白名单（`router/index.ts`）、`AISettings.vue` 硬编码的助手键列表、以及 3 处 `key === ...` 能力判断改读**生成表**；专用 UI 组件保留各自实现（差异是真实的，不通用化）。

## 落地顺序

`03 论坛奖励政策` → `02 第一步：authz 包 + RoleRequired 薄 adapter` → `06 页面描述符` → `02 逐域收敛` → `05 证件作用域` → `04 部署拓扑` → `07 域装配描述符` → `08 AI 注册表派生面`。

（03 先做是因为它封闭在论坛域、有现成契约测试作证据面；05 排在 02 之后是因为两者的声明都挂在同一个路由注册点上，02 建好的端点描述符可被 05 复用。）

## 约束

- **响应 shape 与 HTTP 契约零漂移**：能力声明第一批迁移是「行为不变的 adapter 替换」，不改变任何现有可访问性。
- **证件作用域的显式传参优先语义与今天一致**；迁移完成后需回写 `CONTEXT.md`「当前证件」词条：作用域清单按现状逐面确认（词条今天只列了课程/题库/练习/模考/错题/搜索/收藏，未覆盖招聘/积分/打卡/投稿/学习资料五面）。
- **论坛奖励数值口径不变**（配对 3 折半、5 归零；日 3 / 日 5；每帖只发一次；流水即发放事实源，延续 ADR-0041）。
- **部署生成物与现状逐字节等价**，唯一例外是已漂移的 `REDIS_POOL_SIZE`（CD 20 / 部署脚本 10 / compose 20）——迁移前先定值。
- 移动端不在本次范围。

## 后果

- 「谁能看见什么」从后端 84 处角色字面量（49 个文件）+ 前端三套机制，收敛为一张能力表 + 一张页面描述符；页面级 30 处角色 `v-if` 获得同一判据。
- 论坛 2,276 行文件出现两个真 seam：奖励政策（发分前的事实判定单点）与读面（typed page，`map[string]any` 退出契约）。
- 证件作用域从「客户端前缀表 + 页面 opt-out + 22 个手传点 + 后端逐端点 WHERE」四处表述收敛为端点一列声明。
- 部署漂移从「人工 diff 三份文件」变为「CI 断言失败」；nginx 保留手写但被一致性校验守住。
- 未来 architecture review 不再重新提议以上七项；下次扫描的起点是本次未覆盖的领域（`pkg/`、`internal/valuation` 内部、前端估值旅程）。

## 收口（spec #940，2026-09-13）：收尾清单里未登记的尾项

上面「审查发现但按设计保留」一节记的是**有意保留**的偏差；本节记的是**执行没做尽、且当时没登记**的尾项 —— 不登记就会被下一次架构评审当成新候选重新提议。

- **§3 读面 module 只落了一半**（片二已收）：`ListTopics` 当时已收成 `*ForumTopicPageResult`，但 `GetTopic` 仍是 `map[string]any`，且 `AdminGetTopic` 与学员端 handler 是逐字重复的两份装配 —— 而 §3 的决策原文写着「收成返回 typed page 的 module、删除逐字重复的 `AdminGetTopic`、消灭穿过 seam 的 `map[string]any`」。现已：详情收成 `ForumTopicDetailDTO`（字段按 JSON key 字母序声明，保持与旧 map 相同的序列化字节序）、`AdminGetTopic` 收成一行委托（**注解注释保留在函数上** —— swaggo 从函数注释生成端点，删函数等于删文档），并补形状契约测试（key 顺序 / 两端字节全等 / 越界页空数组）。
- **§4 scope codegen 位**：`credentialScoped` 与 12 处 opt-out 按「另一片工作」保留 —— 片六把它改成登记制。
- **§5 `deploy/env.defaults` 暂无消费者**（片四已接线）：ADR 写「接进部署链路需在 CI 可验证后进行」，两条锁测试已在册，条件已满足。落地形态：CD 生成的环境变量文件**先 `source "$DEPLOY_PATH/deploy/env.defaults"`**，随后只补写「secrets / 环境里确实提供了值的变量」（变量清单直接读生成物，workflow 里不再手抄默认值）；生成物随 tar 一起上传，缺失即中止部署（fail fast，而不是静默回退到 compose 默认值）。cd.yml 里声明表内变量的默认值字面量已全部删除；compose 的「有默认值的变量引用」按原决策退居最后兜底，漂移锁继续钉住它与声明表一致。新增 `TestEnvDefaultsIsConsumed` 守住接线本身（source 行 + 打包清单两项），否则一次重构就能把消费者悄悄摘掉。
## 代码审查（第八波收尾）与处置

2026-09-13 用 `/code-review` 对 `origin/master...HEAD`（14 提交 / 95 文件）跑了两轴审查（Standards：对照 AGENTS.md、`docs/agents/*`、CONTEXT.md 词表与 smell baseline；Spec：逐片核对 #927–#934）。结论与处置如下。

### 审查发现并已修（代码问题）

1. **证件作用域未按角色收口**（§4，正确性）：`CredentialScoped` 对任意角色都按 JWT sub 直查 `hrwai_users`，而 admin/tutor/recruiter 的 sub 来自各自的表 → 会命中**同号的陌生学员行**，把控制台请求静默按别人的证件过滤。已修为「仅学员角色解析」，并补 `TestCredentialScopeIgnoresNonStudentRoles`（用「学员当前证件与题目证件不同」的夹具，负向探针验证过可捕获回归——第一版夹具两种路径都得 3，属退化用例，已修正）。
2. **作用域中间件挂错 group**（§4）：`courses.go` 把 `CredentialScoped` 挂在共享的 `/api` group 上，覆盖范围由注册顺序决定，且给其后注册的所有蓝图各加一次证件查询。已改为挂在本蓝图自己的 group。
3. **漂移锁漏检 GitHub 表达式形态**（§5）：原锁只认 `${VAR:-x}`，cd.yml `env:` 段的 24 处 `${{ secrets.X || 'x' }}`（含 `REDIS_POOL_SIZE`）全部漏检，与测试注释宣称不符。已补该形态。
4. **手抄 EXPECTED 映射表未删**（§2）：ADR 明文要求删除，实现保留并自我背书为「零漂移证据」。已删除——一致性由 `pages.spec.ts` 从描述符断言。
5. **后端 adapter 分发仍比较功能键**（§7）：`routingAIModel` 的 `Complete`/`Stream` 判 `featureKey == FeatureFaultDiagnosis`。已改读注册表 `adapter` 列（新增 `aiFeatureAdapterOf`，未注册键回退通用通道）。
6. **死代码/误导性锁**：`authz_coverage_lock_test.go` 新增「每个蓝图必须有守卫或显式豁免」的覆盖锁（补 §1 决策 6 的落地）；`middleware_test` 的变参收敛为单参；过时注释（「由拦截器注入」）一并更新。

### 审查发现但按设计保留（已在本文档记录理由）

- **§1「路由 → 能力」全枚举未做**：gin 不在路由上暴露中间件链，运行期拿不到「这条路由需要什么能力」。落地形态改为**蓝图级覆盖锁**：注册函数内必须出现能力守卫，否则登记进 allowlist 并写明理由（现有 11 项豁免：认证入口、公开端点、以及横跨多端的课程/题库/站内信读面）。新增蓝图漏挂授权会在测试里报红。
- **§3 `Reclaim` 签名比 spec 窄**：spec 写 `Rollback(tx, ref, reasons)`，实现是 `Reclaim(tx, topicID)`——ref 与 reasons 由 module 内部固定（论坛域是唯一调用域，回收范围固定为「该帖全部直记奖励」）。比 spec 更收敛，故不扩。
- **§3 时间注入只做到 module 收 `At`**：调用点仍用 `beijingNow()` 传参（module interface 已可注入）；既有 `forum_reward_factsource_contract_test.go` 仍改流水时间戳作零漂移证据，未改。
- **§4 scope codegen 位未交付**：`credentialScoped` 与 12 处 opt-out 保留——它管「切换后是否重装」，与「按什么过滤」是两件事；把重装判据也 codegen 化属另一片工作。
- **§5 `deploy/env.defaults` 暂无消费者**：cd.yml / deploy-remote.sh 仍自写默认值（生成的默认值文件已就位并由全等契约钉住）。把它接进部署链路需在 CI 可验证后进行；nginx 一致性校验同样留在后续。
- **`docs/agents/issue-tracker.md` 的本机 gh 路径备注**：与七片实现无关，是用户指出「gh 在 bun 里」后顺手记下的环境事实（评审标注为轻微越界，此处留存说明）。
