# ADR-0071: 专属子域的身份由缺席角色先行裁定

- 状态：Accepted
- 日期：2026-09-30
- 关联：#1614（缺陷）；#618 / ADR-0047（守卫决策管线）；#1363 / ADR-0067（refresh 令牌父域 Cookie）；b383f805（父域共享登录 + /auth/me 跨子域恢复）

## 背景

父域 Cookie（access `hrwai_token` 与 refresh 同 `Domain`，后端鉴权无 Bearer 头时回退读 cookie）加上前端 `withCredentials` 的 `/auth/me` 恢复，使**任何子域**都能静默恢复登录态。于是「已登录」不再等价「是本子域的人」：学员（`hrwai_user`）带着登录态访问 `mentor.`（讲师）或 `manage.`（管理后台）时：

1. `/` redirect 无 mentor/manage 分支 → `resolveWorkspaceForRole('hrwai_user')` = `/training`；
2. 守卫 `subdomainBoundaryStep` 发现目标子域 training ≠ 当前 tutor/admin → **整页弹去 training 子域**；
3. 若先落 `/login`：`authPageStep` 的 `workspace-home` 按**子域缺席角色**给 `/training/tutor` 或 `/admin/dashboard`，`roleStep` 角色不符 → `workspaceFallback` 仍弹 `/training` → 同样被边界弹走。

结果：角色与子域不匹配的访客**永远到不了该子域的登录页**，与 `utils/subdomain.ts`「跨子域视为不同站点、需要重新登录」的声明矛盾。子域识别与部署（nginx / 线上 bundle）经查无误，缺陷在路由决策层。

## 决策

在守卫决策管线的 `authRequiredStep` 与 `roleStep` 之间插入 **`subdomainRoleStep`（步骤 4）**：

- **专属子域**（`tutor` / `admin` / `recruit`）上，已登录但角色 ≠ 该子域缺席角色（`getRoleForSubdomain` 口径：`tutor` / `admin` / `recruiter`）→ **`clearAuth` 回本子域 `/login` 并携带 `redirect` 回跳**；
- 清登录态后管线重跑：未登录 → `authRequiredStep` 常规登录引导（同向，无行为冲突）；登录页属 `auth` 工作区不触发本步骤，**无循环**；
- **共号子域**（training / valuation / main）与 **IP 直连**旁路——身份语义仍由既有角色 / 能力校验承担。

配套两处：

1. **`/` redirect 补 mentor/manage 分支**（`router/index.ts`）：专属子域根路径按缺席角色落公开入口路径（`/training/tutor`、`/admin/dashboard`），身份校验交给守卫——与 valuation/recruit 分支对齐，消除「根路径按**实际**角色先弹走」的缺口；
2. **`authPageStep` 注释钉边界**：已登录访问认证页的 `workspace-home` 回跳按缺席角色给落点，到不了的角色由步骤 4 拦回登录页。

## 理由

- **为何插在 roleStep 之前**：`workspaceFallback` 的角色回落（admin→管理台、tutor→导师台、其余→`/training`）是**跨子域目标**的源头；不先拦，回落决策会被 `subdomainBoundaryStep` 升级成整页跳转，登录页永不可达。
- **为何 clearAuth 而非直接展示受限页**：携带不匹配角色的令牌继续留在应用内，所有 API 都将 403；回到登录页是唯一能让用户**换身份**的路径（「不同站点需重新登录」语义）。
- **为何只限三个专属子域**：training/valuation/main 本来就共号（`hrwai_user`），不存在「缺席角色」；valuation 有独立估值登录页语义，已有分支处理。
- **保留 ADR-0067 的免重复登录**：同角色跨子域（学员在 training/valuation 之间、admin 在 manage. 免登录直达）不受影响；只在「身份与子域不匹配」这唯一歧义点改判。

## 后果

- 学员访问 `mentor.` / `manage.`：清登录态 → 停在本子域登录页（登录成功进入本子域工作区）。
- admin 访问 `mentor.`：清登录态回 mentor. 登录页（原为整页弹去 manage.）；tutor 访问 `manage.` 同理。**行为变化**：跨角色子域访问不再自动被送去「正确」子域，而是要求重新登录——换取「每个子域的登录页可达」与登录身份可预期。
- recruiter 在 `recruit.` 的既有角色回落路径不再触发（被步骤 4 接管）；共号子域上的回落行为不变（单测钉死两侧）。
- 管线从五步变六步；步骤顺序仍是行为承诺，单测矩阵（`guard.spec.ts` `subdomainRoleStep` + 顺序与优先级）钉住插入位置与旁路面。
