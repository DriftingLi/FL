# ADR-0010: 答题会话模块与判分收敛（含状态推进语义修正）

- 状态：已接受（2026-08-12，架构深化第三波 spec #148）
- 领域：培训 —— 答题会话（answering session）/ 考试 / 判分

## 背景

CONTEXT.md 声称练习/模拟考试/定级考试/错题重做共享「答题会话」交互形态，但代码中无此 module：会话状态机被复制到三张表（practice_progress / mock_exam.answers / exam_participant.answers_snapshot），「本人+进行中」守卫复制 6 次、ids→qMap 题目顺序重建复制 5 次；bug #142 的根因即「answers_state 同一概念三处初始化只修两处」（显式 JSON null 落库成 SQL NULL）。判题同样双实现（checkAnswer 与 gradeQuestion 仅差部分给分）、分值表三套、AI 简答评分内联块复制 4 次、及格线魔数 0.6 出现 4 次。

另有一处读路径副作用：定级考试场次状态（upcoming→ongoing）在 GET 列表/可用列表上惰性落库（ListSessions / GetAvailableExams 读时写库），学员端展示本已用基于时间的 effStatus 计算，落库只为管理端列表展示，属于纯副作用。

## 决策

### 1. 答题会话 module（service 包，函数形态）

- 守卫（本人+进行中）、题目顺序重建（ids → qMap → 有序列表）、答案快照三态归一（nil/JSON null/缺失 → 空 map）、answers_state 三态初始化（nil/空/显式 null → `{}`，锁定 #142 修复）收敛为单一实现（`answering_session.go`）；
- 三张存量表结构不变，不做 DB 迁移。

### 2. 状态推进语义修正（行为变更）

- **GET 读路径不再写库**：可用列表 / 管理端列表 / 场次详情的展示统一用基于时间的 effStatus 计算（已到开始时间按 ongoing、已过结束时间按 finished）；
- upcoming→ongoing 只在两个写路径发生：学员进入考试（EnterExam，进入即开始）与管理端手动 UpdateSessionStatus；
- 不引入定时器自动推进。

### 3. 判分收敛（题目契约 typed 化）

- typed QuestionDTO 为题目契约唯一锚点（JSON key 与旧 map 逐字一致，shape-lock 测试冻结）；
- gradeQuestion 为判题唯一实现（保留多选部分给分），checkAnswer 删除；
- 分值表按流（定级/模拟）单点定义，模拟考试的差异分值（识图 4 分、简答 10 分）为产品设定、原样保留；
- AI 简答评分统一入口 + 及格线常量（满分 × 0.6）。

## 约束

- 三张会话表结构与既有 JSON 契约（前端零改动）不变；
- 学员端行为冻结：进入考试/交卷/断点续传/自动交卷语义与深化前一致。

## 后果

- 会话语义只实现一次，#142 类「三处初始化只修两处」缺陷无从复现；
- GET 纯读由测试锁定（`TestLevelExamReadPathsDoNotWrite`），未来读者不会误以为推进丢失是 bug 而把副作用改回去；
- 管理端列表对「开始时间已过但无人进入」的场次展示为进行中（effStatus），DB 状态保持 upcoming 直至学员进入或管理员手动开始；
- 代价：管理端按状态筛选（ongoing）不再命中未落库的场次。
