# ADR-0105 公开资格与阻塞原因由 PostgreSQL 视图统一计算

- **状态**：已接受
- **日期**：2026-11-26
- **领域**：Web 公开网校、公开题库、管理员与讲师工作区

## 背景

访客查询在 SQL 中判断内容能否进入公开网校和公开题库，管理员和讲师则读取 Go 投影生成的公开阻塞原因。引入公开开关时，两条路径分别加入开关条件。此后每次修改一级培训分类、证件映射或公开判据，两条路径都可能需要同步调整。

## 决策

由 PostgreSQL 普通视图实时计算课程和题目的全部适用公开阻塞原因，并从原因集合推导公开资格。内容的阻塞原因集合为空时具备公开资格。访客的课程列表、详情、分类选项和题库计数消费同一判定，并继续由数据库完成过滤、分页和聚合。管理员与讲师读取视图产生的全部阻塞原因，沿用现有响应中的原因代码。

一级培训分类及其证件映射仍是分类事实源。题目继续应用题库池的来源标记口径。公开开关只影响访客公开面，发布、审核、登录后的学习面以及旧端点的证件规则沿用各自约定。分类选项和题库计数保留各自的归集口径。

## 取舍

集中维护 Go 原因投影和 SQL 筛选的改动较小，但两份实现要靠跨出口测试保持一致。在应用中共享 SQL 表达式也能统一判定，且规则可随应用版本回滚。采用普通视图后，数据库中的判定有独立、可直接查询的定义，所有现有读路径消费同一结果，调整资格规则需要迁移，并要协调应用与视图的发布和回滚顺序。

## 验收

- 在真实 PostgreSQL 上用同一批数据对照员工端的全部原因与访客的课程列表、详情、分类选项及题库计数。
- 覆盖符合资格、已发布但关闭公开开关、分类停用、分类缺少证件映射、带来源标记，以及多个阻塞原因同时存在的情况。加入有公开题目但无公开课程的分类，分别核对课程分类和题库计数。
- 检查课程分页与题库聚合的查询计划，比较引入视图前后的代价，记录有意义的退化并处理后再交付。

相关裁定见 [ADR-0057](ADR-0057-公开端点的证件口径.md)、[ADR-0058](ADR-0058-课程与章节的可见性覆盖按id读路径.md)和 [ADR-0070](ADR-0070-域包形态与目录即射程的收口.md)。

## 实施

[迁移 000076](../../backend/migrations/000076_public_eligibility.up.sql) 新增分类、课程和题目视图。课程和题目视图各自复用同一组阻塞条件生成原因和资格。资格按条件检查，使 PostgreSQL 可以继续使用状态索引和反连接筛选候选行。

在隔离的 PostgreSQL 18 上，用额外写入的 1 万门课程、5 万道题目进行计划对比，约 10% 为已发布内容。课程分页执行耗时约 2.2 → 2.1 ms，题库聚合约 10.6 → 11.2 ms。两条查询均保留状态索引，题库聚合保留反连接。读数反映本地模拟数据的一次对照。

## 修订（2026-11-27）：员工端公开状态读模型

- 员工端读模型显式返回**公开开关、公开资格、全部阻塞原因与 canonical 分类**；公开开关不再由 `manually_hidden` 反推。
- legacy 分类桶的筛选、计数与分页下沉到后端同一读模型，前端不全量装载后本地重算。
- 内容行存在而公开视图缺行视为读模型违约，显式失败；不静默返回空状态。
- PostgreSQL 视图仍是唯一判定事实源；本次只深化消费 interface，不新增第二份 SQL/Go 判据。
