# ADR-0015: 第七波架构深化——课程目录 descriptor / FileService 拆分 / featured typed 契约 / admin 列表 module / 估值旅程收敛

- 状态：已接受（2026-08-16，architecture review 5 candidates + grilling 逐一定案）
- 领域：培训目录 / 文件存储与 PPT 渲染 / 精选内容 / 前端 admin 列表 / 前端估值旅程

## 背景

第六波深化（ADR-0014）后，architecture review 扫描最近提交 hot spots 与重复代码，产出 5 个 deepening candidates；经 `/grilling` 逐一定案。本 ADR 记录定案结论，作为未来架构评审锚点，避免重新提议已决策事项。

## 决策

### 1. 课程目录 CRUD descriptor engine（backend）

- 专业方向 / 课程等级 / 证书模板 / 题库标签四个目录实体全部纳入 descriptor engine；
- descriptor 使用 typed 回调（mapInput / validate / toDict / onDelete），不引入 generic map；
- 外部保留 typed facade（handler 与前端契约零改动），engine 为 internal seam 不对外暴露；
- 排序 / 撞码 / 删除关联语义按现状原样冻结；
- engine 层写完整行为测试，typed facade 只保留 shape-lock + adapter 测试，逐实体重复用例删除。

### 2. FileService 拆分（backend）

- 拆为 `FileStore`（Save / Delete / DeleteFiles / List / ValidateImage）与 `SlideRenderer`（Render(ppt, chapter) → URLs）两个 module；
- PPT URL 定位与 HTTP 下载保留在课程流侧，`SlideRenderer` 只接收 bytes；
- 图片 WebP 压缩保留在 `FileStore` 内部，作为 Save 的 implementation 细节；
- `SlideRenderer` 内部使用 sidecar / LibreOffice 双 adapter seam，外部 interface 不变；
- `ExtractTimestamp` 从公共 interface 移除，由论坛图片清理 module 自行解析命名契约。

### 3. Featured content typed 契约（backend + frontend）

- wire 主键 key 保持 `content_id`，前端类型改为 `content_id`，不重命名 wire 格式；
- `FeaturedService` 全部 8 个 map 方法改为 typed DTO（列表项 / 详情 / 分页 / 创建 / 更新 / 删除 / 发布），JSON key 与现状逐字一致；
- handler 的 Create / Update 改为直接 bind typed struct，消灭 map 请求体；
- 前端 `FeaturedContent` 类型对齐实际 wire shape，清理 `handleAction(cmd, row: any)`；
- shape-lock test 锁定契约零漂移。

### 4. 前端 admin 列表 module（frontend）

- 新建 `useAdminTable`，不扩展既有 `useCrudTable`（两者解决不同问题）；
- 第一波收编 6 个标准表格页：TutorManage / HrwaiUserManage / FeaturedContentList / QuestionTags / ProfileReview / ExamSessionManage；
- interface：`{ fetch(paging, filters), actions, searchable }`，module 提供通用 confirmDelete，页面注入特殊 action；
- 第一波只收状态/行为，不做 `AdminTablePage` 布局组件；时间格式化统一走 `utils/format.ts` 的 `formatDateTime`，删除页面本地 `formatDate`；
- 新增 `useAdminTable.spec.ts` 测分页重置 / 搜索置 page=1 / loading 时序 / action 分发 / 确认删除。

### 5. 前端估值结果旅程收敛（frontend）

- `valuationEvaluation` 与 `valuationBattery` 两个 store 都收编；
- 统一状态语义：`loading` + `error` + `currentId` + `currentResult`，保留匿名评估语义（submit 成功不强制 fetch detail）；
- journey module 采用泛型 `submit(payload) → result` / `fetch(id) → detail` adapter interface，不关心具体 DTO 类型；
- 以 factory `createValuationJourney(adapters)` 实现，Pinia store 在 setup 中调用并返回其 state/actions，保留单例语义；
- 为 factory 写 `createValuationJourney.spec.ts` 覆盖 submit 在途 / 成功 / 失败 / fetch 恢复 / reset；两个 Pinia wrapper 不重复写 spec。

## 约束

- 全部响应 JSON key 与既有契约逐字一致；前端行为冻结；
- 课程目录 CRUD、文件上传/PPT 转图、精选内容管理、admin 列表、估值旅程的外部调用点均不改变行为；
- 遵循 ADR-0008 / ADR-0009 / ADR-0012 / ADR-0013 既有方向，不重新争论已决策事项。

## 后果

- 课程目录 CRUD 语义实现一次，新增目录实体只需一个 descriptor；
- FileService 的存取与渲染两个 interface 分离，转换 adapter 可独立替换与测试；
- featured 契约从 map 漂移变为编译期 + shape-lock 双门禁；
- admin 列表状态机实现一次，6 个页面退化为 adapter；
- 估值结果旅程状态机实现一次，两个 Pinia store 只声明 adapter。
