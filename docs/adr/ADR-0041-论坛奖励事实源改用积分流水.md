# 论坛奖励的事实源改用不可回退的积分流水

采纳奖励的「配对衰减」原以**当前仍挂着 `accepted_reply_id` 的帖**计数，而 `CancelAccept` 把它置 NULL、`DeleteTopic` 把行硬删，两者都让计数**回退**——互刷对只要每轮走「采纳 → 取消采纳（或让楼主删帖）」，计数就退回 1，配对衰减**永不触发**，唯一剩下的闸门是答主日 3 次 = **120 分/天，无限期**。违规回收同样是残缺的：只声明 `accepted_bonus` 一条 reason（楼主的 +5、帖主的 +30 全不追），且触发条件绑在「曾被采纳」上——而按 ADR-0040，新的主力激励**备考经验帖恰恰不可被采纳**，天然整片落在回收盲区。本次把两处的事实源统一改为**不可回退的积分流水**：配对次数由 `points_ledger` 中同一 `ref_id` 的 `accepted_bonus`（答主）与 `accept_action`（楼主）自连接还原（**零 schema 变动**，历史配对数天然可从既有流水重建、无需回填），阈值改以「已付配对数」为基准（prior ≥ 3 减半、prior ≥ 5 归零，与既有契约测试断言的每对终身 3×40+2×20=160 一致）；违规回收范围扩到 `accepted_bonus`+`accept_action`+`featured_bonus` 三笔，触发条件改为「该 ref 存在任一正向流水」。

`RollbackByRef` 早已支持多 reason 且**已按 `user_id` 分组**（ADR-0023），一次调用即可从答主/楼主/帖主三方各自追回，封底 0 与幂等占坑都是现成的——本次只是把声明方写完整。

**共同根因**：奖励判定读的是「可回退的当前状态」而不是「不可回退的事件/流水」。配对衰减读状态列，首篇经验读当前 `category`（后者已由 ADR-0040 从内容模型侧消除）。

## Consequences

- 配对口径变成「**付过钱的**配对次数」而非「发生过的配对次数」：被日封顶拦下的采纳不计入配对，理论上可让一对多拿一两次满分——但攻击者得先主动浪费当日额度，收益边际。
- **作者自删帖仍不回滚**（删自己的帖是正当权利），仅累加 `deleted_after_accepted` 巡检计数；**管理员违规删除才回收**。
- **撤精不回滚**：撤精的语义是「不够好」而非「违规」，回滚会让管理员不敢加精。
- **删帖是奖励处置的唯一出口；删被采纳的回复只清采纳状态、不回收**（实现阶段定案，推翻了本 ADR 初稿「删回复回收采纳两笔」的写法）。原因是 `RollbackByRef` 的护栏是 **ref 级一次性**：该 ref 只要存在任一条 `rollback` 流水就整体跳过（这条护栏保护占坑表上线前的历史数据，投稿域共用，动不得）。因此「删回复回收两笔」与「删帖回收三笔」**在现有积分域下不可能并存**——先跑的那个会永久占掉该帖的回收机会，帖主的 `featured_bonus` 再也追不回。选「删帖单出口」还顺带**最大化回收能力**：管理员删整帖时答主/楼主/帖主三笔一次全部追回。代价是单删一条违规回答时答主暂时保留 40 分，直到管理员删整帖。
- **`AdminDeleteReply` 必须显式清 `solved_at`**：`accepted_reply_id` 有 `ON DELETE SET NULL` 外键兜底，`solved_at` 没有——漏清会让主题停在「已解决但无采纳回答」的悬挂态。
- 任务中心已领的 `growth_post`/`growth_reply` **不在回收范围**：它们按「日」计量、`ref` 不指向具体帖，按帖回收在语义上不成立，且单笔仅 10 分。

## Considered Options

- **新建 append-only 配对表**（记录配对事件本身，与付不付钱无关）：语义最纯、可审计，还能支撑管理端互刷巡检。代价是新表 + 采纳路径多一次写 + 存量回填 + 多一处幂等，而收益只在那条边际上。拒绝。
- **`forum_topics` 删帖改软删（加 `deleted_at`）**：计数即可读到历史采纳。但会波及全仓**每一处** `forum_topics` 查询（列表/详情/搜索/收藏/通知/管理端/计数回填…），漏一处就是内容泄漏。拒绝。
- **去掉配对衰减、只留日封顶**：承认修不好也不再假装有。但长期上限变成 120 分/天无期限，对「两人长期互刷」彻底没有刹车，而日封顶每天都会重置。拒绝。
- **账号级处罚替代回收**：回收受封底 0 限制、分花掉就追不回（ADR-0023 已承认这点不完全），处罚看似更彻底。但要新建一整套处罚能力，且与既有 rollback 并存会形成两套治理口径。拒绝。
