# ADR-0008: 字典管理面由实体描述符驱动（含 AI client 双栈决议附注）

- 状态：已接受（2026-08-08，architecture review 全量优化）
- 领域：残值评估 —— 系数表（dictionary）

## 背景

估值管理端字典管理面（品牌/车型/车况/规格/级联/系数/原价/区域/车辆类型等）的消费接口宽达 ~70 方法（30+ 只读查询 + 26 个 CRUD 写操作），handler 约 60 个骨架 1014 行。写操作已被 `createNamed`/`createValue`/`deleteOne` 骨架部分统一，证明 26 个 CRUD 形状是机械重复；只读侧每个实体查询形状各异，无法通用化。

## 决策

字典管理面由**实体描述符（dictionary descriptor）驱动**：

- 每种字典用一个声明式描述符定义（字段、唯一约束、排序、级联父、缓存 key 模式）；
- CRUD 写操作塌缩为 generic 核心接口（List/Create/Update/Delete/Invalidate 级小面），handler 骨架由同一描述符注册生成，不再逐实体手写；
- 30+ 只读查询保留为每实体 typed 方法（形状异构，不强行通用化）；
- 描述符先行清点：实现第一步是盘点全部字典实体的字段/约束/级联/缓存差异，清点结果驱动描述符设计（异构处允许声明式差异，不允许 if-branch 堆积）。

## 附注：AI client 双栈决议

go-openai（非流式）与 eino（流式）两个 client 栈**保留为真实 adapter**，只消除重复的配置结构体——两栈消费同一份 resolved config（经 AI 配置模块解析），各自 client 构建路径读取同一配置。不强行统一流式/非流式接口：两者消费方不同（阅卷/内容生成 vs AI 助手会话），单一接口会是 hypothetical seam，且需重写 eino 的 session 流程。
