# ADR-0082: 积分暂不过期

- 状态：Accepted
- 日期：2026-10-26
- 关联：#709（`ExpiresAt` 首版恒 nil）；ADR-0023（积分簿记收敛与幂等占坑）；ADR-0054（任务中心口径收敛）；CONTEXT.md「积分」词条；`docs/design/20261026-原型图全量对照-移动端缺失页面功能调研.md` §8（Q3/Q14 定案）

## 背景

原型积分明细页画了完整的过期机制：「即将过期」tab、「本月暂无过期积分」提示条、「已过期」筛选 chip；积分规则页含过期条款。后端现状：`backend/internal/core/model/points.go:17` 留有 `ExpiresAt` 字段槽但**首版恒 nil**（#709 裁定「先不引入过期」），`GET /points/ledger` 无过期查询参数，移动端 `points-detail.uvue` 只能在客户端筛已加载条目（分页下筛不准，:156 注释）。

2026-10-26 原型 grilling 重提此题：过期机制本期落不落地。

## 决策

**积分暂不过期。** 本期不引入任何过期负债：

1. 原型「即将过期」tab、「本月暂无过期积分」提示条、「已过期」chip **不落地**；积分明细页保持收入/支出两维；
2. `ExpiresAt` **字段槽保留、恒 nil 维持现状**（不删字段——将来引入过期不必改表）；
3. `GET /points/ledger` **不加** `expire_filter` 参数（调研草案 §6-C3 过期部分作废；`direction` 参数实际已支持——`points/handler.go:96`，属 swagger 滞后待补文档，与本决策无关）；
4. 积分规则页（原型缺失页、定案补建）只写获取/消费规则，**不写过期条款**；
5. 「每实付消费 1 元得 1 积分」的返点条款随电商域裁定（维持 ADR-0031 不做）一并**不写**。

## 理由

- **过期的事实源是「时间流逝」，不是用户行为**——引入过期 = 制造一笔负债账：必须先回答「每笔积分何时过期」（按获取批次滚动？统一日历年底？积分重置时旧账怎么办？），每个答案都要求**回填存量流水**的 `expires_at` + 新增过期结算守护；这些成本在原型里看不见，在实现里全要付。
- **出口未建成就先收门票是最伤体验的顺序**：积分供给侧已收敛（ADR-0023 簿记收敛、ADR-0054 任务口径），但消费出口——积分商城页——当前是死按钮（`task-center.uvue:296-298`）。商城页本期补建（Q14 定案）；在用户还没处花分时引入过期，等于资产在可花之前先无声缩水。
- **无运营诉求背书**：目前没有「降积分负债」的运营请求；原型画过期是通用电商积分模板的惯性，不是本系统的诉求。

## 后果

- 积分余额是单调不减的负债（直到兑换消费），无过期守护、无回填、无结算 job；
- 「即将过期」客户端筛不准问题（#709 的 UI 症状）自动消解——不存在「即将过期」集合；
- 移动端积分明细/规则页按无过期口径实现；
- **将来引入过期 = supersede 本 ADR**，届时至少需要：存量收入流水回填 `expires_at`、过期结算守护（ADR-0061 登记表）、ledger 加参数、规则页补条款——四件套一次立项，不做半吊子（只 UI 不结算的「假过期」比不做更糟）。

## 明确不做（本决策范围外）

- 过期、过期提醒、过期积分结算；
- 现金消费返积分（依附电商域，ADR-0031 口径）；
- 积分清零/重置机制（无任何现行方案）。
