# ADR-0106：中文目录名保留——编码面收口四条边界，改名走触发式复评

- 状态：Accepted（2026-11-26）
- 日期：2026-11-26
- 领域：仓级结构 / 路径编码（不属移动端 ADR 体系）
- 票：#2875（前置 #2874；环境默认值 #2873 / #2885）

## 背景
移动端项目位于 `training-app/叉车维修培训学员端跨端应用/`。中文名在 Windows 链路上必过四类编码面（git quotepath、pwsh 码页、JVM file.encoding、adb 判据），#1853 / #2027 / #2139 / #2161 各付过一次代价；「为什么不改名、何时复评」此前只散在 20 余个脚本注释里，两份 AGENTS.md 对编码零字，没有可引用真源。

## 决策
**现在不改名**，把编码知识收口为一处真源：移动端 `docs/agents/path-encoding.md` 四条边界各一条「症状 → 解」；解码唯一真源 = `scripts/lib/level-detect.ps1` 的 `ConvertFrom-GitQuotedPath`，调用点归属由 `utils/ps1GitPathScan.js` + `utils/levelDetectContract.test.js` 的 `GIT_PATH_REGISTRY` 五档对账（#2874）；根与移动端 AGENTS.md 只各加一行触发式指针。不改名不等于没成本，而是成本已被有界封装。

## 被否备选
- **现在改名（一次性）**：2026-11-26 主树实测 654 处相对引用 / 190 文件、485 处 `D:\FL\…` 绝对路径 / 114 文件、7 个在飞 worktree；HBuilderX 按目录名（项目名）解析，改名后已导入项目须逐个重新 `project open`，全仓 `<中文目录名>` 锚点同时失效。代价一次付清，收益只是不再踩四类坑，而四类坑已有确定修法。
- **新旧目录名并存**：脚本按 `<中文目录名>` 剥前缀（`scripts/lib/capability-surface.ps1`）会分叉，比现状更坏。
- **全局 `core.quotepath=false` 替代解码器**：只免非 ASCII 转义、不免引号与反斜杠转义（`scripts/lib/behavior-subset.ps1` 注释实测），且是机器级配置、clone 后不生效（CI 侧另见 #2885）。

## 触发复评
满足任一条即重新评估改名（不新增 label）：① 编码类新票 **≥2 张/季度**——`gh issue list --search '编码 OR 中文路径 OR 乱码'`，把结果按 `createdAt` 落到当季计数；② 出现四条边界装不下的新编码面且无确定修法。

## 后果
编码问题有了单入口：先读 `path-encoding.md`，要改就改解码器；守卫对新增路径输出调用点报红，要求逐点重新分诊（设计意图，不是 flake）。改名代价仍在，只是从「一次性 654 处」变成「三条可复算的触发条件」。
