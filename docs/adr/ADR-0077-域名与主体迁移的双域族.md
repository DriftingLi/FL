# ADR-0077: 域名与主体迁移（双域族、独立 API 入口、反代换 Caddy）

- 状态：已接受（2026-10-22，票 #1756）
- 领域：部署面 —— 域名 / 证书 / 反代 / 会话边界（`frontend/Caddyfile`、`backend/internal/deploy`、`backend/internal/security`）
- 修订：ADR-0003（生产 HTTP 下登录态不共享）、ADR-0022（Cookie 域作用域）在**域族**层面的前提；ADR-0047（部署事实唯一事实源）的产物清单 +1（Caddyfile 的生成区）。ADR-0016 / 0067（双令牌与 refresh 通道）语义不动。

## 背景

运营主体从「和润天下（广州）人工智能科技有限公司」迁到「易道网络科技（广东）有限公司」，承载站点的主域从 `gccsmile.com` 换到 `gdyidao.cn`。两件事不能混着搬：

- **残值评估属于和润**：品牌文案、PDF 报告署名、短信签名与邮件前缀都是和润。塞进易道主域下会导致同一页面出现三个主体。
- **培训 / 讲师 / 管理 / 招聘属于易道**：它们跑在旧域上，证书是外部签发、由 CI 以 Secrets 注入的，换域名必然失效。

三笔技术债同时到期：反代的投递分档规则由 Go 代码生成并带 8 条结构锁、对象存储公开 URL 写死在旧资源域且库里存绝对地址、移动端 API 基址硬编码在两处。

## 决策

1. **双域族、双主体**。和润门户与残值评估在 `hrwai.cn`（备案号见第 9 条）；培训 / 讲师 / 管理 / 招聘在 `gdyidao.cn`。推论：**`hrwai.cn` 与本机服务器再无直接关系**（除 EdgeOne 回源到 `api.gdyidao.cn`），旧反代里「收 `www.hrwai.cn` 作回源 Host / 对它直接 404 防环」那段整体删除，不搬到新反代。

2. **API 入口独立成 `api.<domain>`**。移动端、门户回源、残值 BFF 都打它，页面域名与它解耦 —— 下次换页面域名，这三条链路一行都不用动。裸域与 `www` 一跳 301 到培训入口。

3. **反代换 Caddy，证书自动签发**。生产走 ACME（443 的 TLS-ALPN 为主、80 的 HTTP-01 兜底），不再有「证书到期前记得换」这件事；`SSL_FULLCHAIN` / `SSL_PRIVKEY` 两个 secret 退役。**证书策略由 `TLS_MODE` 分档**而不是 `APP_ENV`：两套环境后端都声明 `APP_ENV=production`，但测试冒烟不该去申请生产域名的证书（`TLS_MODE=internal` → `auto_https off` + `tls internal`）。

4. **旧域硬切，不留 301**。App 与小程序均未发布（已核实：无强更机制、小程序未上线），因此不需要过渡期。代价是 `cdn.gccsmile.com` 一起消失 ⇒ **存量绝对 URL 必须回填**（工具已支持 `-from/-to`，判据是路径前缀、与域名无关，故安全；要求先 dry-run 记账、第二次执行命中 0 行）。

5. **会话按族隔离，用 `aud` 而不是第二套密钥**。令牌族 `web` / `valuation`；`IssuePairFor` / `VerifyAccessFor` 按族签发与校验，一个族签出的令牌另一族入口不认。选择 `aud` 的理由：BFF 形态下浏览器本来就不共享任何凭证，密钥分离换来的隔离增量很小，而多一个要轮换的 secret 是实打实的运维面。**空族按 `web` 处理**，切换前签发的存量令牌不会被这次改动踢下线。

6. **账号级吊销标记不按族分家**（对第 5 条的显式补充）：改密 / 禁用应当**同时终结两族会话**，按族分开反而会让「改密后估值侧还能用」。族隔离解决的是「令牌能不能在这个入口用」，不是「这个人的会话该不该一起死」。

7. **不拆表（L0）**。`evaluations` / `battery_evaluations` 的 `user_id` 是纯 INTEGER、**没有外键**，语义不变；账号表不拆。收益是「学员一键看残值」这条转化路径不被打断；代价是主体边界只在域名 / 会话 / 备案层表达，不在数据层。补一条结构锁：估值域不得读取账号表以外的跨域表（积分 / 论坛 / 投稿）。

8. **品牌与通知归属**。产品品牌保留 HRWAI（= 和润天下人工智能的缩写，与短信签名、邮件前缀自洽）；页脚署易道是**法律主体署名**，两者不冲突。通知通道（短信签名 / 邮件标题前缀 / 发件人）维持和润，含义是易道站的验证码由和润通道代发 —— 这是**显式决策**，不是实现细节。

9. **备案号按站分配，三处不同号是故意的**：易道站 = 主体备案号下的第 3 个站点；和润门户 = 另一套备案号；和润的估值 PDF 与通知沿用和润。**别来「统一」它们**。

10. **残值前端北迁、后端留本仓**（**2026-10 已完成**）。过渡期 `valuation.gdyidao.cn` 由本仓 SPA 服务；现已改为 301 到 Nuxt 版（和润域 `valuation.hrwai.cn/valuation`），本仓的该工作区 SPA 与路由一并删除，只留后端、数据与管理端「残值配置」。BFF 同源代理 `/api`，浏览器不见跨站 Cookie，`CORS_ORIGINS` 不需要加和润域（估值域**零上传**，EdgeOne 的 6 MB 请求体上限不构成限制）。

11. **改写只动外显，不动标识**。站点标题、拓扑文档、AI 助手壳的品牌文案统一到 HRWAI；代码标识（`hrwai_users` / `hrwai_user` / `hrwai_token` / logo 文件名）与历史 ADR / 验收记录**一律不动**（历史记录被改写就不可信）。

## 明确不做

- 不保留旧域的 301 与服务（第 4 条）。
- 不为证书引入 DNS 服务商凭证与自建 Caddy 镜像（第 3 条）—— 逐子域签发即可。
- 不拆账号表、不拆库、不搬后端（第 7 条）。
- 不把通知通道切到易道（第 8 条）。
- 不在本 ADR 里决定残值 Nuxt 的具体实现（第 10 条，单独立项）。

## 影响面

- `frontend/Caddyfile`（新增，含 gen-deploy 生成区）、`frontend/Dockerfile`、`frontend/docker-entrypoint.sh`、`docker-compose.prod.yml`、`scripts/deploy-remote.sh`、`cd.yml` / `ci.yml`。
- `backend/internal/deploy/caddy_delivery_gen.go` + `caddy_topology_test.go`（8 条结构锁按 nginx 时代同一组判据迁移）。
- `backend/internal/security/session.go`（族）+ `session_family_test.go`。
- `deploy/env.defaults`：`SSL_CERT_DIR` 退役。
- `frontend/src/components/layout/SiteFooter.vue`（新增）+ `SidebarLayout` / `AuthPageShell` 的接线。

## 待办（按依赖）

1. 估值族登录端点 + `JWTAuthAllowFamilies` 接线。**过渡期估值组必须同时收两族**（老 SPA 仍用主站令牌），北迁完成后收窄到只认估值族 —— 这条要写成代码注释，否则下一个人会以为「允许两族」是设计意图。
2. 切换日 runbook：回填 dry-run 记账 → 部署 → 验证书与四端可登录 → 门户回源切 `api.` → 删旧域 DNS 与 Caddy 块。
3. README 拓扑章节按新域名重写（本 ADR 只给判据，不复述配置）。
