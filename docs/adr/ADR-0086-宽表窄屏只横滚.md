# ADR-0086: 宽表窄屏只横滚，不降列

- 状态：Proposed（草案，待维护者签字）
- 日期：2026-10-26
- 关联：#1937；ADR-0084（管理端只保桌面）；ADR-0083（意图裁定）

## 背景

`el-table` 197 处，集中在管理端。实测：`≤1024` 出现表体横滚（`.el-scrollbar__wrap--h`），375 下 `/admin/hrwai-users` 表体 **1230 / 319（3.9×）**，右侧固定「操作」列压住内容；1440 下 `/admin/profile-review` 与 `/admin/statistics` 尚不滚。

## 决策

**默认横滚，不降列。**

1. 保留 `el-table` 的表体横滚；固定列**只允许「操作」一列**固定在右；
2. **不为通用表格实现"窄屏降列 / 卡片化"**；
3. 若某页面被判定为**移动必需**（如学员端少量列表），在该页面做局部卡片化，**不回流到通用表格**。

## 理由

- 表格集中在管理端，而管理端已裁定只保桌面（ADR-0084）⇒ 窄屏降列的服务对象基本不存在；
- 197 处表格的降列要逐页定义"降哪几列、详情放哪"，是 23 个页面级决策；横滚是 Element Plus 的既有行为，维护成本为零；
- 降列还会与 ADR-0083 的意图模型纠缠：同一个"查看一行明细"的意图会在表格与卡片之间分叉出第二形态。

## 备选

- **通用降列**：要维护"关键列"清单 + 详情抽屉形态，197 处逐一迁移，且与 ADR-0083 冲突。
- **卡片化替代表格**：信息密度损失大，批量操作无法承载。
- **窄屏隐藏低频列**：隐藏逻辑会分散到各页，等于让每页自己决定降列 —— 正是本条要避免的分散。

## 后果

- 表格的窄屏体验保持现状（横滚 + 右侧固定操作列），不再列为响应式改进项。
- 若未来出现移动端管理诉求：先改 ADR-0084，再议本条。

## 证据边界

同 ADR-0084：浅色、1 行数据；饱满态只会让横滚更宽，不改变结论。
