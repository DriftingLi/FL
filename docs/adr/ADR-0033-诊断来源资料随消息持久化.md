# ADR-0033: 诊断来源资料随消息持久化

- 状态：已接受（2026-09-07）
- 领域：AI 域 / 智能维修诊断（取代 ADR-0032 的「历史不持久化 sources」取舍；承接 ADR-0029 单 port、ADR-0031 计量闸门）

## 背景

ADR-0032 把外部诊断助手的 `answer_sources` 经 SSE `sources` 事件透传到前端内存态，历史回看不显示（与 usage 计费脚注同策）。上线后学员把「刷新后来源消失」报为 bug（#666）：回答正文引用了手册页码与溯源图，回看时依据丢失，回答可信度无法复核。usage 脚注是消费凭证、历史无意义；来源是证据链、历史仍有意义——两者「同策」的前提不成立。

## 决策

1. **来源随助手消息行持久化**：`ai_chat_messages` 新增 `sources` TEXT 列（JSON 数组，随助手消息存；用户消息与非诊断对话存空串）。写入点唯一：在 `StreamChat` 持久化分支内从 ctx 来源容器序列化，失败按无来源落库、不阻断主流程。
2. **历史查询同口径回放**：`GetSessionMessages` 解析 `sources` 列下发（解析失败按无来源处理，不阻断列表）；前端逐消息轮在回答下方折叠展示（默认折叠、图片懒加载）。
3. **当轮内存态保留**：SSE `sources` 事件与 `lastSources` 仍用于流式中的当轮面板；切换会话/新一轮即失效，历史以持久化字段为准。

## 备选

- **维持 ADR-0032 不持久化**：拒绝——用户已明确把消失报为 bug，且证据链与计费脚注的语义不同，不应同策。
- **来源挂会话维度只记最后一轮**：拒绝——多轮追问的每轮依据不同，只记最新一份会张冠李戴；用户确认随消息行存。

## 后果

- ADR-0032「后果」第二条（历史不持久化 sources）被本 ADR 取代；传输契约（SSE `sources` 事件、移动端同步义务）不变。
- 存量消息 `sources` 为 NULL，回放按无来源处理，不补回填。
- 限免/计费口径不变：来源持久化不产生新的计费消费。
