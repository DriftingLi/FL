# ADR-0050: 第九波架构深化——学员可见性谓词单点化 / 搜索分区描述符 / 论坛治理 seam

- 状态：已接受（2026-09-15，architecture review 3 candidates，经 grilling 逐一定案）
- 领域：题库池与课程挂载（学员可见性口径）/ 全局搜索 / 论坛治理

## 背景

第八波深化（ADR-0047）后，第九波扫描产出 3 个 deepening candidates（移动端不在范围，未产生候选）。三个候选的共同形态：**领域不变式已由 ADR / CONTEXT.md 声明为「单点口径」，但其实现形态在多个 module 里各写一遍**——不变式靠纪律维持，不靠结构维持。按 id 直取漏池（ADR-0049 票2，2026-09-14 修复）正是这个 bug 类的实证。

## 决策

### 1. 学员可见性谓词单点化（题库池 + 课程挂载不变式）

- **按域各自导出**，不合并：题库域导出「题库池 scope」、课程域导出「挂载课程 scope」两个具名 module。被否备选：合并为一个「学员可见性」module——两族谓词是不同域的不变式（题库池三元组 vs 课程挂载三元组），合并是跨域 shallow module（deletion test 不过：删掉后复杂度回到各自域，不是消失）。
- **interface 双形态**：gorm 函数谓词（主形态，`poolFilter` 提升导出）+ SQL 片段常量（`excludeSourceTagsSQL` 收编进题库池 scope module）。被否备选：仅函数形态——catalog 标签计数是 raw SQL（`LEFT JOIN` + `FILTER (WHERE ...)`），改写 gorm 链式要绕子查询反而复杂；两个形态同源一个 module，漂移面收敛。
- 落点（四处 inline 拷贝全部替换）：search 题目分区（`search_service.go:341-347`）、catalog 标签池计数（`training_catalog_service.go:249-276` 的 raw SQL 重写已与常量脱钩）、favorite 收藏回填（`favorite_service.go:73`）、search 课程/章节分区（`search_service.go:270,302`）。
- 与 ADR-0049 约束节**对齐而非冲突**：「题库池覆盖每一条读路径」目前是文档纪律，本决策把它变成结构约束。

### 2. 搜索分区半描述符（本轮实施，升格自 Speculative）

- 评审时定级 Speculative（无新分区在途，YAGNI）；grilling 定案**趁 ADR-0049 上下文还热本轮一并做**。
- **半描述符**：引擎 module 收敛同构骨架（count → 命中排序 → scan → 分页），分区声明六个槽位：类型键 / 匹配面（WHERE 形状）/ scope 谓词（正好接决策 1 的具名 scope）/ hit 函数（`hitOf` vs `hitOfTopic`）/ 排序二级键 / DTO 装配函数。被否备选：**全声明化**——匹配面与装配每分区真不同（章节有 description 命中回退、论坛有 EXISTS 回复子查询），硬声明化会发明一门小 DSL，描述符本身变成新的学习面，与深化目标背道而驰；**只提共享 helper**——加分区仍碰 4 处（switch/DTO/方法体/handler），格局不变。
- `SearchAllDTO` 五字段契约不动（只增不破，ADR-0048 口径）；聚合组装循环化但响应形状零漂移。
- 依赖决策 1 先行（scope 槽位是具名谓词）。

### 3. 论坛治理 seam（ForumModerationService）

- **按 caller 切两片**：`ForumService` 保留学员交互 + 个人集合（~25 方法）；治理 module 收编举报处置、意图认定（备考经验/帖子精选）、管理端强制删除与违规回收（~10 方法，含 forumRewardPolicy 收编——「认定即发分」读写同址）。被否备选：按概念切三片——个人集合只有一个 caller（学员端），单独立 module 是 hypothetical seam（one adapter = hypothetical seam）；只拆文件不切 interface——42 方法宽面原样保留，治理测试仍穿宽 interface 装配。
- **同包分文件**：治理 module 与 `ForumService` 同在 service 包，`deleteTopicWithImages` / `fetchTopicDTO` / `enrichRewardIssued` 等私有 helper 保持包内共享。被否备选：独立 package——共享 helper 被迫提升导出，interface 反而变宽。
- **举报按 caller 切**：`CreateReport`（学员发起）留学员交互侧；`HandleReport` / `ListReports`（处置与队列）归治理侧。被否备选：举报全族归治理（概念内聚）——seam 判据是 caller，入口的路由是学员端点。
- **命名 Moderation**：对齐能力表既有 `forum.moderate`（ADR-0047），词汇零新增。被否备选：Governance（与能力表不同源，要维护两个词的对应）；Admin（角色词，与「管理员」账号概念混淆）。
- deps.go 装配：治理 module 与 ForumService 共享依赖（db / fileSvc / notificationSvc / forumCnt / pointsSvc / logger），实例分离；api 层管理端路由换依赖治理 module，学员端 handler 零改动。

## 落地拆票（每票一会话）

| 票 | 内容 | 依赖 |
| --- | --- | --- |
| 票① | 学员可见性谓词单点化（双形态 scope module + 四处落点替换） | 无 |
| 票② | 搜索分区半描述符（引擎骨架 + 六槽位分区声明） | 票① |
| 票③ | 论坛治理 seam（ForumModerationService + 管理端路由换依赖） | 无（与①②可并行） |

顺序 ①→②→③（票② 的 scope 槽位依赖票① 的具名谓词；票③ 封闭在论坛域、有现成契约测试作证据面，参照 ADR-0047 落地顺序的先例排最后独立验收）。

## 约束

- **谓词语义零变化**：票① 是行为不变的重构，池三元组与挂载不变式的判定结果逐字节等价（契约测试锁住）。
- **搜索契约只增不破**：`SearchAllDTO` / `SearchPageDTO` 响应形状不变，分区描述符化是 engine 内部形状。
- **学员端 handler 零改动**：票③ 只动管理端路由依赖与 `Deps` 装配；`ForumService` 收缩方法集不影响学员端调用面。
- **论坛治理数值口径不变**：认定/回收/防刷语义延续 ADR-0040 / ADR-0041 / ADR-0047 §3。
- 移动端不在本次范围。

## 后果

- 「不变式靠纪律」变「不变式靠结构」：新学员读路径组合具名 scope 即过池，漏拼谓词那类 bug（按 id 直取漏池）的实现形态被关闭。
- 加搜索分区从碰 4 处（switch / DTO / 方法体 / handler）变为 1 处声明；ADR-0049 的两条判据评审门保留——描述符只改代码形状，不改评审口径。
- catalog 标签计数与池口径的漂移窗口关闭（raw SQL 引用同源片段）。
- 论坛 83KB 单文件的 git 冲突面收窄（多会话并发，见 docs/agents/multi-agent-git.md）；治理行为不再经学员交互 interface 测试。
- 「论坛治理（forum moderation）」进 `CONTEXT.md` 词表。
