# ADR-0083: UI 形态的裁定单位是意图（三轴），不是控件

- 状态：Accepted
- 日期：2026-10-26
- 关联：#1957（UI 形态审计主票）；#1934 / #1954（同批 a11y 收口）；ADR-0035（UI 控件收敛到封装层）、ADR-0037（el-table 边界）、ADR-0038（剩余控件观感口径）、ADR-0080（字号只走 token 阶梯）；`docs/agents/ui-conventions.md`「UI 词汇」

## 背景

2026-10-26 实测：封装层是齐的 —— 35 个组件、10 类控件已进守卫、业务模板裸用为 0。但**同一作用存在多套形态**：

- **卡片**：`UiCard` 24 处 vs 页面本地 `.xx-card` 29 个类 / 18 个文件；scoped 里 `border-radius` 15 种取值、`box-shadow` 13 种（裸 `8px` 出现 16 次）。抽查 29 个本地类，**只有 2 处可点击**，其余是布局容器。
- **切换**：`UiSegmentTabs` 14 个文件 / `UiUnderlineTabs` / 裸 `el-tabs` 21 处 / 5 个页面。`FaqManage` 的「分类·条目」用胶囊，`ValuationConfigManage` 的「原价表·算法参数」用全宽 tab 条 —— 同一个动作，两种形态。
- **确认**：`el-popconfirm` 5 处（行内，其中两条文案写明「仅解除关联」）vs `useConfirm` 45 处（模态，含**交卷**、**登出**）。
- **弹层**：`UiDialog` 56 处 vs 裸 `el-drawer` 4 处。

既有口径不在这个粒度上。ADR-0035 定的是「业务页面不得直接使用 EP 控件」，准入按「**重复度 × 视觉影响**」排序 —— 那是**按控件**度量；ADR-0038 收的是「剩余控件观感」，同样一类控件一议。于是「同一件事长两副样子」这件事：既不在守卫的判定面里（守卫只认 10 个控件名），也没有任何 ADR 为它负责。

## 决策

**UI 形态的裁定单位是「意图」；控件与视觉形态都是它的实现。**

1. **意图按三轴判定**：① 目标（选一个看下去 / 选一个存下来 / 确认一个动作 / 把一个对象当入口…）；② 后果（是否持久化、是否改变正在操作的对象）；③ 可逆性与影响半径（能否撤销、影响当前一行还是整页）。**三轴全同才是同一意图。**
2. **层级不是轴**：页面级与卡片级不是两个意图。同一意图只有一个视觉语法，层级只派生**尺寸档**（高度 / 字重 / 间距），不派生第二形态。
3. **容器归档位，入口归意图**：卡片这类容器受「视觉档位表」（圆角 / 内边距 / 描边 / 阴影）约束，**不强制收编进 `UiCard`**；可点击的入口类才受「一意图一形态」约束。`UiCard` 的定位改为「默认容器」，不是唯一容器。
4. **形态可以由审计重定**：审计不止盘点，可以对既有语法提出重定。每次重定须凑齐四样 —— 同屏对比、影响面清单（页面数与处数，含深色态）、ADR 草稿、维护者签字；**不限条数**，成本由影响面自证。重定**不在审计票内落地**，一条重定一张迁移票。
5. **守卫改为意图登记制**：每个意图登记一组允许的组件，模板里的交互控件必须落在某个意图的允许集内，**未登记即红**。它取代「控件黑名单」成为目标态，**不设黑名单过渡态**。
6. **新守卫等迁移全部落地再上**：上线当天 `--all` 必须为绿，不接受例外表，也不接受增量门常态化。守卫的诞生日期由最慢那张迁移票决定。**期间现有黑名单守卫照常运行**（它的判定面与新制度无关）。
7. **清单全站一次，迁移按意图开票**：清单必须一次覆盖全站，否则跨页面族的同意图重复看不见；迁移按意图切，「改完那一刻该意图只剩一种形态」才可验收。

## 备选

- **按控件裁定**（每控件一封装、裸用清零）：拒绝。会把本该并存的几种切换硬并成一个 —— 视图档与数据档的差异在「后果」轴上，是真实差异；且控件层已经做到 0 裸用，问题不在那里。
- **按形态裁定**（只收圆角 / 阴影取值）：拒绝。只治症状：29 个卡片类里一半差异是参数，另一半是结构，"结构该不该存在"继续无人判。
- **把层级算作一轴**：拒绝。任何不一致都能用「层级不同」解释掉，审计失去可证伪性。
- **多数票定标准形态**：拒绝。数据档意图的现状是裸 `el-tabs` 21 处 vs 胶囊 14 个文件 —— 多数票等于让「越裸越正确」赢，与 ADR-0035 方向相反。
- **重定设数量上限（≤3）**：拒绝。上限是拍脑袋；用「影响面 + ADR + 签字」做闸门，成本自己调节。
- **守卫先加黑名单再换登记制**：拒绝。过渡态要维护两套判定面，且黑名单对新控件天然失明。
- **守卫先上 `--diff` 增量门、存量慢慢迁**：拒绝。增量门会让同一意图长期并存两种形态 —— 正是本 ADR 要消灭的状态。
- **清单与迁移都按页面族滚动**：拒绝。跨族重复（`FaqManage` 胶囊 vs `ValuationConfigManage` tab 条）按族切永远看不见全貌。

## 后果

- `ui-conventions.md`「UI 词汇」新增「意图」词条（三轴；层级只派生尺寸档）；「视觉基调」不变。
- 审计产出两张表，落点都是 `ui-conventions.md`：**意图 → 允许形态**（新守卫的登记表）与**视觉档位表**（容器卡片用）。
- 立刻可推的结论：21 处 `el-tabs` 并入胶囊语法（页面级用放大档），`UiUnderlineTabs` 继续管视图档；`el-popconfirm` 与 `useConfirm` 按可逆性重新分档；4 处 `el-drawer` 的归属留给审计判。
- `check-el-controls` 的判定面将在迁移收尾后从「控件黑名单」改写为「意图登记表」；在此之前不改。
- 迁移票的完成判据统一为：该意图在全站只剩一种形态，且新的登记制守卫 `--all` 返回绿。
- 登记制只看得见"用了哪个组件"，看不见自绘的 `<div>` 交互 —— 那一层仍靠评审，不指望守卫。
