# ADR-0054: 任务中心口径收敛——每日登录无条件化与成长分组退役

- 状态：已接受（2026-09-17，grilling 定案）
- 领域：积分 —— 任务中心（points task center）
- 取代：ADR-0028 中关于「每日登录事实源」的条款

## 背景

任务中心的两处口径问题在学员端体验 grilling 中被一并定案（证据索引：`docs/plans/学员端四项体验升级-方案.md` §2.1 / §2.2，**本地不入库**，同 ADR-0049 先例）。

**一、每日登录的达成判定挂在一个被动触发的事实源上。** `daily_login` 的 claimable 判据是「当日 `user_daily_login` 行存在」，而落表只发生在**登录签发**与 **`/auth/refresh` 轮换成功**两个入口。双令牌体系下（access 2h + refresh 7d，ADR-0016），是否发生轮换由**客户端**决定：Web 端是「本地 token 未过期就直接用，过期才静默刷新」（`frontend/src/api/client.ts`），移动端是「401 后才被动刷新」。于是存在真实窗口——23:50 刷过 token 的学员次日 00:30 回来，access token 仍在有效期内，当天不落表、任务显示「去完成」且领不了。**客户端实现细节在决定一项每日任务的可用性。**

**二、`group` 是 `total_limit` 的冗余投影。** 三条 `growth_*` 任务的 `(daily_limit, total_limit)` 与三条 `daily_*` **逐字一致**（`daily_limit=1, total_limit=NULL`）；前后端描述文案也自认同口径（「每日达成每日领，当日 0 点重置」）。「成长任务」不是第三种口径，只是 `group` 列上一个贴错的标签。

## 决策

### 1. 每日登录无条件化，事实源退役

`daily_login` 保留为任务，**只去掉行为前置**：`taskProgressFor` 返回 `nil`，走「无行为前置 → 顶层按可领透出」的既有分支。每日限领一次仍由配置 `daily_limit=1` 承担。

`user_daily_login` 表与两条落表路径**一并退役**（它不再有任何消费方）：模型与 AutoMigrate 注册、`PointsService.MarkDailyLogin` / `hasDailyLogin`、`AuthService.RecordDailyLogin` / `dailyLoginMark` / `SetDailyLoginMarker`、`/auth/refresh` 的调用点、装配根注入、以及**注销时的显式清理语句**（最易漏的一处）。表由迁移 `000034` 删除。

### 2. 成长分组退役，收敛到 daily / newbie

迁移把三条 `growth_*` 的 `group` 改判为 `daily`，CHECK 收窄为 `('daily','newbie')`；Web 端 `TaskGroup` 类型、分组标签/描述映射、分组渲染顺序同步收敛。任务中心从三段变两段：**每日任务（6 项）+ 新手任务（4 项）**。

**任务 code 保持 `growth_*` 不变**：code 是 `points_ledger.reason` 与 `points_task_claim.task_code` 的历史标识，改名会割裂已发流水，且属 API 契约面。分组才是这次要修的那一层。

`group` 是 `total_limit` 的投影（非空=终身一次 / 空=每日可再生）这一事实记在此处，**作为将来退役该字段的依据**——本 ADR 不退役字段本身（那要动 `PointsTaskItem.group` 契约与两端渲染）。

## 被否选项

- **保留事实源，改为「当日首次认证请求」落表**：ADR-0028 当初就把「任意认证请求算登录」列为被否（理由「每请求多一次 Redis」）；改成「当日首次」能解成本问题，但仍是给一个不需要前置的任务维持一张事实表，且把判定挪进认证中间件会扩大认证面的职责。
- **退役 `daily_login`，把 5 分并入打卡基础分**：打卡已覆盖「每日到访」（点一次直记 5 分 + 连击阶梯），但会改动每日可得积分口径，且任务中心少一项内容——超出「修领不了」的意图。
- **只合并展示，不动数据层**：后端数据继续留一个语义错误的分组值，下一个人必踩。
- **连 `group` 字段一起退役**：把冗余状态彻底删掉最干净，但要动 API 契约与两端渲染，超出本批。

## 后果

- 「空领不可」的闸门在 `daily_login` 上不再由行为判定承担，而由 `daily_limit` 承担——契约测试相应改为断言「初始即 claimable」+「重复领取 400 今日已领取」；「有行为前置的 daily 型任务未达成报 ErrTaskNotDone」这条覆盖改由 `daily_quiz` 承担。
- 已删的登录到访流水**不可恢复**（回滚迁移只能把表结构建回来，是空表）。
- `daily_login` 的描述从「每日登录或续期会话即达成」改为「每日进入任务中心即可领取」；Web 端分组描述从「当日达成当日领」改为「当日各可领一次」。
- 移动端 `pages/points/task-center.uvue` 的 growth 分组分支成为死代码（`buildGroups` 有 `rest` 兜底，不会崩），另开 issue 交 @zhengcookie（#1080）。
