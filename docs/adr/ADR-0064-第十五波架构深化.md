# ADR-0064: 第十五波架构深化（一个事实只在一处成立，并在它的每个消费点都可分辨）

- 状态：已接受（2026-09-22，第十四波结题账 + 跨端 #1267 回执 → 六族违例；本轮不重扫，逐条以「能报出 file:line 才算事实」的口径复核实测）｜领域：端点错误面 / 不可读语义 / 处置动作后果集 / 联系方式投影 / 题目列表实现 / 口令写面形状 / 契约可空性
- 拆票顺序：**按域四批**，① 身份处置族 → ② 题库/练习/真题/模考 → ③ 课程/内容/精选/讲师 → ④ 投影完整性 + D5/D6 + **表态锁（必须最后建，先建即全场飘红）**。每批自带该域的档位台账。

## 背景

第十四波（ADR-0062）的形状是「interface 少了一维」。本波是它的下一层：**同一件事实在 N 处各成立一次，或只在一处成立却只投到一部分消费点**。前者使「改一处忘九处」成为常态，后者使客户端只能猜——两者都不是 bug 计数问题，而是**事实没有唯一住处**。

判据（本波的贯穿不变式，六族违例都由它派生）：

> **一个事实只在一处成立，并在它的每一个消费点都可分辨。「统一」只允许发生在呈现层，且必须是显式决定，不能是唯一可能。**

「在消费点可分辨」包含两半：响应里能分辨（码/具名说明），以及**同一个事实在所有承载它的端点上都存在**（缺一处就退化成猜）。

决定时点的事实（逐条实测，非估计）：

- service 层裸 `errors.New(…不存在/未找到/找不到…)` 共 **97 处，去重后 49 个文案**；「课程不存在」在 10 个不同函数里各写一遍、「章节不存在」10 遍、「招聘者不存在」4 遍。已有具名哨兵 80 个作对照 ⇒ 同一域内哨兵与字面量并存。

- 「输入不合法」被答成服务端故障：`featured_service.go:171` 的 `errors.New("分类无效")` 经 `featured.go:76` 的 `WithSuccess(…, http.StatusInternalServerError)` 出去 ⇒ **生产答 500**。同类 **40 处**（`参数无效`/`格式无效`/`图片地址无效` 等）。这是 ADR-0062 票8 的**另一半**——票8 只修了 `*ParseError`（binding 层），service 层的具名校验错误至今仍被无条件条目咽掉。

## 决策

1. **「不可读」拆成三件事实，统一只留在呈现层**：`不存在` / `不在平台上`（未发布或未满足挂载不变式）/ `无权益` 各自一个具名哨兵；api 层对学员**仍统一渲染 404 + 同一个文案**（保持 ADR-0062 决策 3 的不泄漏存在性）——但那句文案由**消费端点**给出（课程面「课程不存在」、章节面「章节不存在」），不由哨兵自带：哨兵一旦携带对外句子，「被哪个端点消费」就在决定「它叫什么」，而那是本决策要禁的那一格。与旧形状的区别不是码，而是**分档住进了类型**——「压成同码」从一个端点唯一可能的结果，变成一个可被审计、可被单独打开的显式决定。词表已同步新增「不可读（unreadable）及其成因」。
2. **「不存在」族 97 处全收，每对象一个哨兵**：同一 wire 文案跨域共用（两个「章节不存在」）**列为删除对象**而非命名细节；哨兵是事实的载体，文案是呈现层的事。
3. **「输入不合法」40 处升具名哨兵并改判 400**：补完 ADR-0062 票8 的另一半。这是**跨端可见行为变更**，落地时按 #1265 的先例再走一轮同步（同域已有 51 处 `WithSuccess(…,400)` 先例 ⇒ 不是新政策，是把漏的那半边接上）。**否**「只升类型不改外显」（分档只到类型层、客户端收益为零）。
4. **处置动作的后果集必须齐全，且不追溯改写历史事实**：`ToggleHrwaiUserStatus` 补 `RevokeIdentity("hrwai_user", id)`，与招聘者侧对称；后果**止于会话与联系面明文两项**——权益/学习记录/积分一律不动，解除禁用即恢复原状（依 ADR-0051 写入时冻结、「授权存在≠授权可用」）。同票：`AdminService.ResetHrwaiUserPassword` 停止自行哈希，改调 `SetNewPassword`。
5. **事实要在它的每个消费点都可分辨**：`company_disabled` 回填到简历卡面 DTO，**缺席式、与明文位置同键同措辞**；徽章仍按授权事实投影不变（依词表「授权有效态」的「两者不得互相顶替」）。**否**「禁用时降级 `contact_state`」——那是把可用性并进授权事实，会让「被禁用」与「从没授权」在列表上重新塌回同值。Web 的 `Resumes.vue`/`ResumeDetail.vue` 两处消费**与本票同 PR**。
6. **同一事实一份实现**：`ListQuestions`/`ListPoolQuestions` 收成一份、scope 作参数（D6）；`SetNewPassword` 的双 error 升成具名结果类型，使「口令已成、吊销可选失败」在签名上可读（D5）。
7. **D3 不在本波硬收**：`ListQuestionTags` 的 `credentialID *int` 确实违例，但它缺的是**聚合形态的 scope 设计**（票3 的 scope 是逐行读面，标签计数是聚合），不是意愿。本波只产出该设计并据其定形；**否**「在 PR 里现造一个没有先例可校的形状」。
8. **护栏两件，且表态锁最后建**：① **声明式档位台账**——每个纳入的端点登记其可能档位集合（如 `{400,404,500}`），对每一档逐一验，并反向锁「声明了却测不出该档」；未登记端点不进台账（deny-by-default 登记式，沿用 ADR-0062 票4 形状）。**否**「固定两例」（收完第三族即过期）与「两条台账」（同一条判据两份实现，正是决策 6 要修的病）。② **表态锁**——反射扫响应 DTO，每个切片/映射字段必须显式表态「可为 null」或「出口恒非 null」，漏标即红；它不推断数据流，故不是上一波否决的假绿锁。

9. **5xx 不外发驱动原文**（第②批实施中由台账照出，故编号排在 8 之后）：`errStatusAll` / `WithSuccess` 默认面的文案取 `err.Error()` ⇒ 任何底层错误原文（`record not found`、`no such table`、`SQL logic error`、`pq: …`、`dial tcp …`）都原样进响应 `message`。规则收在渲染层单点：**4xx 照旧回错误原文**（那是给调用方看的领域说明，收掉直接伤可用性），**5xx 一律固定文案 + `c.Error` 记账**；有前缀时保留前缀、丢掉尾巴。要把原因说给用户的 5xx 必须改成抛具名领域错误或显式声明固定文案 —— 即「说什么」是显式决定，不是 `err.Error()` 的默认漏出。**否**「逐端点换成 `errStatusAllMsg`」：那是把一条判据摊成上百次手抄，正是本波要修的病。
10. **锁的断言宽度本身要被复核**：第①批的泄漏断言只查 `"record not found"` 一条字面量，于是同族的 `no such table` 从锁缝里过去 —— 加宽后第①批 7 档立刻红。**一条只认某一种漏法的锁等于没有锁**；写泄漏类断言时先枚举「这一族还能以什么形式出现」。


## 理由

四批按域切而按不变式立论：判据必须全局一致（同一个「不存在」不能这域分档那域不分），交付必须小（137 处一次合会让评审与撞车都失控）。锁放最后是被自己的判据逼出来的——表态锁约束的是**全部** DTO，先建即在未改完的域上飘红，那会把锁变成阻塞而不是护栏。

存量近零（背景末条）是本波敢一次收两族的唯一原因。它同时意味着**这些改动今天不会被生产验证**：付费门禁、企业禁用收回、兑换键都无可观察对象 ⇒ 行为正确性只能靠档位台账与 testing 环境注入，不能靠「上线后没人报错」。

## 被否备选

- **按票逐条列**：三张票会改同一批函数（`Toggle*Status` 同时在身份族与哨兵族），互相踩、回归跑两遍。
- **只做到「能分档」不收敛重复**：新增约 42 个同形异名哨兵（十个都叫「课程不存在」），下一波还得再收一次。
- **单 PR 全收**：违反「一个 PR = 一件做完且已验证的事」，且一次直发 130+ 处变更进生产。
- **静态文案扫描锁**（禁 service 出现裸 `errors.New("…不存在…")`）：即 ADR-0047 §1 的文本锁形状，本仓已判定不信——改措辞触发门禁、扫不到变量拼出的文案。
- **真数据流推断的可空性锁**：上一波已判为做出来即假绿，沿用该结论。
- **只挑身份族 + 跨端族**（约 15 端点）：会让 27 处留在案上，而「未收部分」正是 D3/D5/D6 滞留两波的那类命运。

## 锁

- 声明式档位台账（正向：登记的档必须测得出；反向：登记项拿不到该档即红）；建在每批内、随该域改动同 PR。
- 表态锁：DTO 切片/映射字段必须显式表态可空性；**只在本波最后一批建立**。
- 跨域文案锁：同一个 wire 文案不得由两个不同域的哨兵发出（直接钉住「章节不存在」两域撞车这类）。
- 消费点对齐锁：一个具名说明若同时存在「明文位置」与「列表投影」两类消费点，二者必须声明同一键（防 #1267 那类只投一处复发）。

## 实施回记（落地时逐条实测；未回记前本段为空，后续会话不要按上文计数行事）

- **决策 4 的射程在第①批实施中扩大了一次（维护者 2026-09-22 裁定并入）**：原文只列了学员侧两条
  （`ToggleHrwaiUserStatus` 补吊销、`ResetHrwaiUserPassword` 接进唯一动作）。做完顺着「同一事实」
  往下找，发现**讲师侧是它的另一半而不是另一票**：`ToggleTutorStatus` 与 `ResetTutorPassword`
  同样不吊销，而讲师登录走的是同一条双令牌链（`auth_service.go` 的 `"tutor"` 分支）。
  于是第①批含三侧对等：学员 / 讲师 / 招聘者（后者本就已做）。生产存量：讲师 1 个、未禁用 ⇒ 零真实流量影响。
- **顺带修掉一处「同一个事实的两个住处」**：吊销命名空间的 `"hrwai_user"` 早已有 `HrwaiRole` 常量，
  而 `"tutor"` 只有散在 `auth_service.go:94 / :307` 的字面量、吊销侧一用就得再抄一遍。补
  `const TutorRole = "tutor"` 并让登录分派与吊销共用它。**测试专门钉了这一条耦合**：把
  `tutorPasswordSubject` 的 role 改成无人读的值，讲师两条吊销用例会红 ⇒ 命名空间与 JWT 角色
  claim 不同源时，吊销标记会「写得进去、读不出来」。
- **「落新口令」动作从「学员专属」参数化成按主体**：`applyNewPassword` 收一个 `passwordSubject`
  （`dest` / `key` / `role`），学员与讲师各一个实例。做成 `AuthService` 的方法会逼 `AdminService`
  横向依赖 `AuthService`，而这里要的只是同一条动作。
- **一处本批引入又本批结清的假成功**：`applyNewPassword` 按 id 更新但不判行数 ⇒ 给不存在的账号代重置口令返回**成功**。由 `passwordSubject.notFound` + `RowsAffected == 0` 结清（台账里 `hrwai-users/999999/password` 与 `tutor/999999/password` 两档 404 是它的锁）。副作用如实登记：两条**未登记**的自助入口（登录态改密、验证码重置）现在主体不存在时报 400 而不是成功——它们恒为已登录主体，判据上不可能不命中，故接受这个外显收窄。
- **`/code-review` 双轴复核抓出本批三处自反违规（当场修掉，逐条留在锁里）**：
  1. **负数 id 回归**——我把默认错误面从 400/404 收窄到 500 之后，service 里那句裸 `errors.New("用户 ID 非法")` 被答成 **500**：`PUT /admin/hrwai-users/-5/password` 从 400 退到 500。⇒ 教训：**收窄默认面必须同时清点该端点会经过的所有具名/非具名错误**，这正是决策 3 那一族的内容，我却在本批先动了默认面。现以 `ErrInvalidHrwaiUserID`/`ErrInvalidTutorID` 落 400，台账把「非数字」与「负数」两种成因分开钉（同一状态码多种成因 ⇒ 档位表用切片而非 `map[int]`，按码建表会把第二种挤掉）。
  2. **同事实两哨兵**——新建 `ErrHrwaiUserNotFound` 时没查到 `points_service.go` 早有一个同文案、同对象（`hrwai_users` 行）的 `ErrUserNotFound`。**修波次自己的病却先造了新的那个病**。现合并成单一载体；「生成任务不存在」则与积分域的「任务不存在」是**两类对象**，按决策 2 的跨域文案规则改成可分辨的文案。
  3. **注释与代码互否**——三处端点还留着上一波写的「本批不在改动面 / 无具名哨兵可分档」，紧接的 `ErrStatus` 就登记了新哨兵。过期注释比没注释更坏，删。
- **`GetTaskStatus` 的「非数字」只修了一半**：`fmt.Sscanf("%d", &id)` 接受 `"12abc"` 并静默截成 12。换 `strconv.Atoi` + `id > 0`，台账钉 `"12abc"` 这一档。
- **招聘者口令写面一并接进唯一动作**（复核发现，非扩面）：`ResetRecruiterPassword` 是本动作之外的
  第三份哈希副本，且其中那句 `Count` 的 error **没查** ⇒ 查不动会被读成「招聘者不存在」——
  正是决策 1 要消灭的那一型。加 `recruiterPasswordSubject` 后一并消失。
  同时把吊销命名空间的字面量收干净：`RevokeIdentity` 的 5 个 caller 现在全部用
  `HrwaiRole`/`TutorRole`/`RecruiterRole` 或 `subject.role`，无一处裸字符串（`internal/security`
  的测试除外，那层不能 import service）。
- **第②批 A 段（目录实体）改的是引擎不是端点**：`CatalogEntitySpec.NotFoundMsg` 是一个 **string** ⇒ 引擎只能 `errors.New` 出匿名错误，于是「查不动」与「不存在」在 api 层分不出档，且**一处塌缩同时污染 5 类实体 × Update/Delete**。换成 `NotFound error` 后 10 个端点各挂一次 `WithSentinel` 即分档；6 个哨兵住在 descriptor 旁边（新增实体必须同时立名字，漏了编译不过）。台账 30 档全部不需要播种。
- **第②批 B 段（练习/真题/模考 6 端点）实测到的形状比登记更糟**：登记时只写「裸 `errors.New` 无哨兵可名」，实际是三种不同的错法 ——
  ① 抽题三处 `if err != nil { return errors.New("查询题目失败") }` 是**吞掉真错误再造一条文案**，再被 `errStatusAll(404)` 渲染成 404 ⇒「数据库查不动」对外表现成「题库没有题」；
  ② `请指定题库标签` / `该标签不支持专项练习` 是**输入不合法被说成资源不存在**；
