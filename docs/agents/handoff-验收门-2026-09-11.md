## 四、怎么工作

### pr-evidence workflow

`.github/workflows/pr-evidence.yml`：`pull_request` 触发，只读正文 + 文件清单，不 checkout、不构建、不部署。是本仓「PR 事件不触发 CI/CD」的**唯一豁免**（ADR-0008 写明理由）。校验逻辑内联在 `actions/github-script@v7` 里；抽取式单测 `.github/scripts/pr-evidence-check.test.mjs`（18 例）+ ci.yml `pr-evidence-selftest` job（守护的守护）。**不是 ruleset 必检**（有 admin 通道，裁定不装）；仅红/绿可见，不阻止合并。

gate-②（微信开发者工具门）有条件判定：需命中 MP-WEIXIN 面（manifest.json / platformConfig.json / patch 含 MP-WEIXIN）。其余运行时面门无条件。

### 编译门

`scripts/compile-check.ps1` + `npm run build:compile`：`cli.exe open` → `project open` → `launch app-android --compile true`；**解析 stdout**（退出码恒 0）；超时兜底；日志 `.ci-verify/build.log`（gitignore）。实测 ~4.6 分钟。

**④c（本地整模块 Kotlin 编译，2026-09-11 落锁，#870 T2）**：`npm run build:kotlin-all` → `cli publish app-android --type appResource --project <项目>` 导出 + HBuilderX 自带 kotlinc **整模块**编译（不需要 Android SDK / appkey / 云账号）；**输入只能用 appResource 产物**，`-SkipPublish` 供受限会话只跑 kotlinc 部分；与 `compileReleaseKotlin` **不等价**。守护 `utils/kotlinAllGateContract.test.js`。

### AGENTS.md

移动端 `AGENTS.md`「验收门与合并纪律」：**agent 不得自行合并运行时面 PR**，必须停在「待人工签收」。根 `AGENTS.md` 有指针。

### 触发判据

运行时面 = `*.uvue` / `*.uts` / `training-app/**/manifest.json` / `pages.json` / `platformConfig.json`（`git diff --name-only` 可机检）。不触发：`*.test.js`、`docs/**`、`AGENTS*.md`、`.opencode/**`、`jest.config*.js`。

## 五、已知编码缺口
1. **pr-evidence 的 workflow 由 head 分支提供**：老分支不含时不跑。ruleset strict mode 迫使 merge master → 解决。但 PR 可修改该文件；防线是人工 approve + diff 审查。
2. **校验器只校结构不校真伪**（ADR-0008 明确不做）。真实性靠人工签收。
3. **CLI 退出码恒为 0**（失败也 0），一律解析 stdout。#859 追加实测：`cli publish app-android --type appResource` **缺 `--project` 会失败但退出码仍为 0**；正确写法须带 `--project <项目绝对路径>`。
4. **dev/release 编译差异的机制（#859 已证实，取代原推测）**：`runUVueKotlinDev()` 只把**本次变更的 .kt** 交给 kotlinc，并把上一次的 `class/` 目录放进 classpath（陈旧 class 复用）；release / appResource 路径 `result.kotlinc = false`，**本机不做 Kotlin 编译**，交云端 Gradle 整模块编译。⇒ 差异在编译单元粒度 + 转译模式，不在「dev 不编译 Kotlin」。**新坑位**：dev 缓存不是自洽的编译单元，本地整模块编译必须取 appResource 产物。详见 ADR-0008「④a 的运行前提与 ④b 的判定」。

## 九、并发会话的记录法（2026-09-13）

多会话同时开时，**每样东西都记到它「该被谁读到」的那一层** —— 记错层就是没记。

| 产物形态 | 记在哪 | 为什么 |
| --- | --- | --- |
| **一次性工具**（探针页、临时脚本；跑完即删） | 工作区 + `docs/agents/` 一行（**含来源**：分支名 + 提交号 + 跑完要删什么） | 它不该长期存在，但「它在哪、怎么重来」必须留在冷启动会读到的地方 |
| **本会话结论 / 状态** | **GitHub issue 评论**（本仓 = issue tracker） | 跨会话唯一共享的黑板；也不会因为谁切分支而消失 |
| **决策 / 新坑位** | **回写 ADR 或 `docs/agents/`** | 本仓纪律原文「issue 评论不是冷启动会话的必读面，ADR 才是」 |

**只记状态，不记指令。** 待办要写成「现状 + 来源 + 判据」，不要写成对下一个会话的吩咐 —— 它可能带着不同的上下文来，指令会误导它。先例：本节写的是「探针在 `probe/937-gradient-syntax`（`7900574c`），跑完即删」，而不是「你必须先跑探针」。
