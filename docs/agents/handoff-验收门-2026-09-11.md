四、怎么工作  ### pr-evidence workflow  `.github/workflows/pr-evidence.yml`：`pull_request` 触发，只读正文 + 文件清单，不 checkout、不构建、不部署。是本仓「PR 事件不触发 CI/CD」的**唯一豁免**（ADR-0008 写明理由）。校验逻辑内联在 `actions/github-script@v7` 里；抽取式单测 `.github/scripts/pr-evidence-check.test.mjs`（18 例）+ ci.yml `pr-evidence-selftest` job（守护的守护）。**不是 ruleset 必检**（无 admin 装不上）；仅红/绿可见，不阻止合并。  gate-②（微信开发者工具门）有条件判定：需命中 MP-WEIXIN 面（manifest.json / platformConfig.json / patch 含 MP-WEIXIN）。其余运行时面门无条件。  ### 编译门  `scripts/compile-check.ps1` + `npm run build:compile`：`cli.exe open` → `project open` → `launch app-android --compile true`；**解析 stdout**（退出码恒 0）；超时兜底；日志 `.ci-verify/build.log`（gitignore）。实测 ~4.6 分钟。  ### AGENTS.md  移动端 `AGENTS.md`「验收门与合并纪律」：**agent 不得自行合并运行时面 PR**，必须停在「待人工签收」。根 `AGENTS.md` 有指针。  ### 触发判据  运行时面 = `*.uvue` / `*.uts` / `training-app/**/manifest.json` / `pages.json` / `platformConfig.json`（`git diff --name-only` 可机检）。不触发：`*.test.js`、`docs/**`、`AGENTS*.md`、`.opencode/**`、`jest.config*.js`。  ## 五、已知编码缺口  1. **pr-evidence 的 workflow 由 head 分支提供**：老分支不含时不跑。ruleset strict mode 迫使 merge master → 解决。但 PR 可修改该文件；防线是人工 approve + diff 审查。 2. **校验器只校结构不校真伪**（ADR-0008 明确不做）。真实性靠人工签收。 3. **cli compile 退出码恒为 0**（失败也 0），若未来用它当门必须解析 stdout。 4. **dev/release 编译差异的机制仍未证实**：dev 也调 kotlinc（缓存有 1312 个 .class），推测是 Gradle 与 HBuilderX 编译单元粒度不同。  ##
