# 注释标准

> 读者：要**新增、删除或改写注释**的人。适用面是后端（`backend/**/*.go`）；前端与移动端另有约定（移动端运行时面注释见 `training-app/叉车维修培训学员端跨端应用/AGENTS.md`，本文件不覆盖）。
> 由来：issue #1445 的 P4。**底数与逐包实测**在 [`docs/design/1445-p4-comment-audit.md`](../design/1445-p4-comment-audit.md)（本文件只给判据，不重复那份表；表会随收口变短，判据不会）。

## 1. 三问判据（先问，再动笔）

1. **删掉它，读者会丢一个「代码里读不出来」的事实吗？** 会 ⇒ **保留**（第 2 节）；不会 ⇒ **删除**（第 3 节）。
2. **它是某个工具或生成物的输入吗？** 是 ⇒ **不可动**（第 4 节）。
3. **它记的是历史，还是在指路？** 历史（血账、迁移记账、被否备选）⇒ 不可动；指路 ⇒ 目标已改名/已删/行号已漂的，按第 3 节修或删。

一句话版本：**注释存储的是「代码没有说的事」**——取舍理由、不变量、踩过的坑、真源在哪。复述代码本身的句子不存储任何事实，是负债。

## 2. 保留类（A）

| 子类 | 判据 | 本仓先例 |
| --- | --- | --- |
| 判据与不变量 | 写清「为什么必须这样」，含 issue / ADR 号 | `internal/core/contact_authz.go:1`（「什么算有效授权」的单点）、`internal/core/password_write.go:5-11`（会话吊销两族失败策略不同且不许互相顶替） |
| 血账 | 现象 + 成因 + 复发的后果 | 手册 §11、`internal/core/nonnil_declaration_test.go:23`（本文件用例测不到的边界登记） |
| 跨文件真源 | 指向**符号**（可 grep），不写易漂的行号 | 「真源是 `internal/apitypes/domains.go` 的域声明表」式写法 |
| 公式与推导 | 领域算法（残值系数、RUL） | `internal/valuation/kcondition.go` 的 `Kc = clamp(Kc_raw, 0.30, 1.15)` |
| 词汇引用 | 指向词表而不是复述词义 | `CONTEXT.md` 的「会话（session）」「接口契约」引用 |
| 包文档 | 包级导览（路由树、文件分工） | `internal/valuation/handler.go` 文件头的「路由结构」注释块 |

判断「复述还是解释」的土办法：**把代码改名后这句话还成立吗？** 只在代码原样时成立的，多半是复述。

## 3. 删除类（B）

| 子类 | 判据 | 实测（#1445 P4 时点） |
| --- | --- | --- |
| 复述型 | 把下一行逐字翻译（`// i++`、`// 遍历 items`） | 逐包甄别，无全仓自动判据 |
| 装饰型 | `// =====` 分隔线、纯标题横幅 | 非测试 36 行 / 18 块，落点见报告 §5-B |
| 重复型 | 相邻逐字重复的注释行 | 3 处（报告 §5-C） |
| 失真包文档 | 文件头 `// Package <旧包名>` 与真实 `package` 子句不符 | **42 处**（报告 §5-A；CI 的 golangci-lint 只开 errcheck/gosimple/govet/ineffassign/staticcheck/unused，抓不到） |
| 失效指路 | 指向已删/已改名的文件、符号或行号 | 29 处 `file:line` 指路需人判（报告 §5-D） |
| 空话型 | 「注意」「重要」「小心」而无具体后果 | 逐包甄别 |

**失真包文档怎么修**：句子里还带着真实信息的（如「招聘域：职位（job posting…）」），**改前缀**为真实包名（`// Package job …`）；只剩空壳的（`// Package service 实现业务服务层。`），**整行删**。同一个包里多条重复的包文档只留一条，别把包导览拆成 N 份。

## 4. 不可动类（C）

- **指令性注释**：`//go:build` / `//go:embed` / `//go:generate` / `//nolint` —— 它们是编译与工具输入，删了会坏构建。
- **swagger 注解**（`// @Summary` 等）：生成物（`backend/docs` 与前端生成物）的唯一事实源；动了要按 `docs/agents/checks.md` 的生成链顺序重跑，且会牵动若干注解锁。
- **锁与守卫里的证明性注释**：计数算式、允许名单理由、`parser.ParseComments` 读到的那三处（`internal/apitypes/nullability_lock_test.go`、`internal/api/consumption_fact_lock_test.go` 的档位说明等）。数字与注释必须同批改。
- **迁移记账与历史记录**：`docs/adr/*`、`docs/design/1445-*`（注释审计底数——里面的旧路径与行号**本身就是取证**）、手册 §10.1/§11、「原住 `internal/service/…`，P2 波 4e 搬来」式句子（**69 处**）；丢了就找不到迁移的来龙去脉。⇒ **收口死链只改活约定文档，历史面原样保留**（明文判据见 `docs/adr/ADR-0070-域包形态与目录即射程的收口.md` P3-A 段）。
- **移动端 `.uts` / `.uvue` 里的注释**：`pr-evidence` 的运行时面判据按文件路径与扩展名走，顺手改一处注释就会把 PR 拉进运行时面。
- **生成物头部注释**：前端生成物的「覆盖的 Go 类型」清单由生成器写，手改即漂。

## 5. 棘轮（只减不增）

落地形态：`scripts/check-comment-cleanliness.mjs`（`--all` / `--diff`，runner 走 `scripts/lib/guard.mjs`），**基线 0、allowlist 为空**，即「只减不增」已经减到底；确有例外时逐条登记进 `allowlist` 并写明理由（口袋式棘轮，先例 `utils/uvueFontCarrierContract.test.js` 的 `DEFERRED`）。首刀实测：42 处失真包文档 + 54 行装饰分隔线（36 行生产 + 18 行测试）+ 3 处重复行 = **99 处已收口**（2026-10-03，PR 见 issue #1445）。

只锁**可机检且无歧义**的三类：① 失真包文档；② 装饰分隔线；③ 相邻重复注释行。

明确**不锁**的两类：
- **注释率**（注释行 ÷ 非空行）：会给「新增解释性注释」判红，与第 2 节直接冲突。本仓非测试注释率 23.0% 是**文化特征不是欠账**。
- **「注释掉的代码」语法启发式**：实测 24 处命中全是公式、路由形态、`//go:embed` 指令与文档示例（精度约 0，见报告 §3）——假阳性会被当成噪声绕过去，比不锁更糟。

## 6. 动注释的纪律

- 注释改动也要过 `gofmt`；一次提交只做一件事（删注释与改代码分开，回滚粒度见移动端「一个视觉主题一个 commit」的同理约定）。
- 删注释**不改行为**：删完跑该包测试 + `gofmt -l .` + `go vet ./...`。
- 见到「注释说的是 A、代码做的是 B」不要随手改注释——先确认哪一侧对；改注释把不一致盖住是最坏的一种修改。
