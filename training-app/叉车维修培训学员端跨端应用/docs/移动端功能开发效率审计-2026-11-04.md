# 移动端功能开发效率审计（2026-11-04）

> **性质**：只读审计。**本轮不修改任何业务代码 / 脚本 / npm scripts / CI，不删除文件，不创建 Issue / PR，不改 ADR 或验收规则。**
> 本文是一次性盘点产出的新增文档（先例：`docs/工具链复杂度审计-2026-11-04.md`、`docs/门资产清算-2026-10-28.md`），不触达任何既有资产。
> **口径**：所有数字当场现测，命令记在 §10。跨版本失效的数字不写；无法从历史记录确认的，在 §2 明确标「未知」，**不估算成实测数据**。

---

## 0. 一句话结论

**1～3 小时的开发时长，主因不是"写代码"，是"固定的门禁成本 + 名存实亡的精准测试 + 为源码文本维护的测试与接线"。**

三个可量化的构成：

1. **精准测试没有生效**：11 个真实功能 PR 的改动集回放 `scripts/behavior-suite-deps.mjs`，**11/11 退化为全量 107/107**。行为腿固定 **32.8 min**，与功能大小无关。
2. **测试测的是源码文本**：160 个套件 `readFileSync` 断言源码字面量，**0 个套件渲染 `.uvue`**。任何结构性改动都要同时改源码与其断言 ⇒ 测试成为「改动量的放大器」。实测 47% 的改动行来自 `*.test.js`。
3. **PR 阶段不是瓶颈**：11 个功能 PR 建 PR→合并中位 **6.8 min**，最快 4.4 min。真正的耗时在跑门与内循环。

结论：**不存在"开发者写得慢"，存在"每做一个小功能都要付一遍与它无关的固定成本"。**

## 5. 交付 3：造成耗时的具体文件、命令与流程

### 5.1 根因一：`-Changed` 的「精准」在结构上不可能发生

**实测复现**（把 11 个 PR 的 `git show --name-only` 原文喂给规划器）：

```
PR2132     6     107   100.0%
PR2135     6     107   100.0%
PR2138    17     107   100.0%
PR2140     6     107   100.0%
PR2144    10     107   100.0%
PR2145     8     107   100.0%
PR2151     6     107   100.0%
PR2160    18     107   100.0%
PR2200     4     107   100.0%
PR2224     7     107   100.0%
PR2225    10     107   100.0%

平均子集 107.0/107 = 100.0%
等于全量（无收益）的改动集：11/11
```

**根因锁定到单条边** —— `scripts/behavior-suite-deps.mjs:325-330`：

```js
const suiteFiles = norm.filter((c) => /(^|\/)utils\/[^/]+\.test\.js$/.test(c));
if (suiteFiles.length) {
  reasons.push({
    edge: 'suite-set',
    why: '改动 utils/*.test.js ⇒ 全跑（两腿切分与心跳契约以套件集合为输入）',
```

**任何改动了 `utils/*.test.js` 的功能 PR，行为腿必然全跑。** 11 个 PR 无一例外都改了测试文件。实测构成：**7 个新增测试文件、3 个仅修改**（2140 / 2145 / 2200）——即便是「只给现有套件补几行断言」也判为套件集合变更。

**日志佐证**：`.ci-verify/test-behavior-changed.log`（2026-11-01 23:29）尾行
`TEST_BEHAVIOR_CHANGED_RESULT ... mode=changed planned=103 completed=103 wall=2197s` —— 103 个套件跑了 36.6 分钟。

**附注**：接线腿（`test:unit`）在 changed 档**本来就是全量**，`scripts/dev-finish.ps1:733` 注释明说「接线腿在 changed 档跑的是全量 ⇒ planned 就是发现数，两枚同值」。所以 `test-unit-changed.log` 的 `planned=129 discovered=129` **不是缺陷，是设计**，但它让 `changed` 这个名字失去了意义。

### 5.2 根因二：测试断言源码文本，不测行为

| 读数 | 值 |
| --- | --- |
| 用 `readFileSync`/`readText` 读源码做断言的套件 | **160** |
| `mount()` / 渲染 `.uvue` 的套件 | **0**（全仓无 `@vue/test-utils`） |
| 断言总数 | **9,941** |

后果：改函数名、拆文件、调整导出，**必然**同时改源码和它的断言。测试不是安全网，是改动量的放大器。

### 5.3 根因三：每个功能都要维护两张接线表

| 文件 | 规模 | 为什么必须改 | 11 个 PR 中被改次数 |
| --- | --- | --- | --- |

## 7. 交付 5：需要代码改进的问题

| 问题 | 具体位置 | 如何缩短开发时间 |
| --- | --- | --- |
| 模块登记靠手写大表 | `utils/modules.js`（609 行） | 改为按目录约定自动发现（`utils/*.uts` 即模块），删掉 609 行表与「忘登记就判红」这一类失败。每功能省一次 609 行文件的定位与编辑 + 一次对账返工 |
| 类型全量再导出 | `types/index.uts`（25 行 barrel，22 域） | 让调用方直接 import 域文件或按需导出，删掉「新增类型必改两处」 |
| 160 套件断言源码文本 | `utils/*.test.js` | **不是新增框架**，是把断言从「源码含某字符串」改为「调用函数得到某结果」。凡是函数返回 `undefined` 时仍能通过的断言，一律重写或删除。直接砍掉测试端的结构性噪音 |
| 页面内联业务逻辑 | `pages/`（36,655 行扁平） | 已有 `pages/<模块>/` 分目录，真正的问题是逻辑内联在 `.uvue` 里（2132 单文件 +125/−63、2151 单文件 +92）。**2160 已给出正例**：`practiceModuleDisplay.uts` +28、`wrongQuestionDisplay.uts` +41、`usePracticeOverview.uts` +37，应成为默认写法 |

**架构改进的成本解释（治理原则要求）**：`modules.js` 自动化省的是**每功能一次 609 行文件编辑 + 一次对账失败**；测试断言去源码化省的是**每功能平均 1,611 行测试改动中的结构性噪音部分**。两项都作用在「每次功能都重复发生」的动作上，不是新增抽象层。

## 8. 交付 6：需要工具链改进的问题

1. **`behavior-suite-deps.mjs` 的 `suite-set` 边**（P0，见 §6.1）。改动集中在一个函数 + 11 个套件名单，**不新增门、不改测试框架**。
2. **④a 全量编译在「未触及原生面」时降档**：945 s 里 71.9% 是整模块 kotlinc + dex，与改了哪一页无关。若改动面为纯 `.uvue`/`.uts` 且 ④c 已 fresh，可走热缓存档（257 s）。**注**：ADR-0046 已有三档，需确认执行单是否无条件调用全量档。
3. **② 的 IDE 楔死自愈**：`port-file-dead` 反复出现（env-blocked 占 ② 成本 45%），应在 pre-probe 失败时做一次「结束残留进程 → 重启 IDE → 重试」自动恢复，而不是直接判 `env-blocked` 交给人。**这是修已有异常的恢复路径，不是新增门禁。**
4. **④c 补 `elapsed` 落盘**：`kotlin-all.log` 只有 `errors/classes/files/freshness`，没有耗时 ⇒ 该门至今无可信成本读数。

| **`suite-set` 边替换** | **实测 −28.2 min/PR**（32.8 → 4.6 min） | `node scripts/behavior-suite-deps.mjs --batch <11 个历史改动集>`，期望「等于全量」从 11/11 降到 ≤1/11（2138 因 `page-set` 合法全跑）；再跑真实门，`TEST_BEHAVIOR_CHANGED_RESULT ... planned` 显著下降且 `testsFailed=0` |
| `modules.js` 自动化 | 每功能省一次 609 行编辑 + 对账返工 | 功能 PR 中 `utils/modules.js` 出现次数从 7/11 → 0；对账门仍绿 |
| 测试断言去源码化 | 测试改动行数下降 | 同一批 PR 的 `*.test.js` / `.uts+.uvue` 新增行比从 **0.90** → 目标 **< 0.5** |
| ② 楔死自愈 | 回收 ② 成本 45%（≈60 min / 200 PR） | `MP_WEIXIN_*` 结果行中 `errors=env-blocked` 占比下降；`elapsed` 逐条复算 |
| ④c 落盘 `elapsed` | 让该门成本可测（当前未知） | `kotlin-all.log` 新增 `elapsed=` 字段 |
| ④a 降档 | 945 s → 257 s（潜在 −11.5 min） | `COMPILECHECK_WALL_SEC` 读数下降且 ④c 仍 fresh |

**统一判据（遵循 ADR-0053 总成本尺）**：总开发成本 = 开发 + 验收 + 维护 + 返工。任何优化必须同时报告「减少了多少实际成本」与「新增了多少维护规则」，**单看墙钟不算数**。

### 9.1 一个必须限定的收益项

行为腿里最慢的两个套件 `mpWeixinAuthSkipBehavior.test.js`（**657.8 s**）与 `mpWeixinGateResultLineBehavior.test.js`（**434.2 s**）合计占全量 **55.5%**。但经核查，它们**只由 `gate-script` 边（改 `scripts/` / `.github/`）触发，功能 PR 选不到**。

⇒ **修复它们对「功能开发耗时」零贡献**，只对改工具链的 PR 有价值。此项不应与 §6.1 混算。
