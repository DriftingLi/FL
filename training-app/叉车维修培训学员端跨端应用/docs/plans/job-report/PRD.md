| 字段 | 内容 |
|------|------|
| **产品名称** | 职位广场（Job Board）— 学员端 |
| **变更范围** | 仅前端（后端 API 已全部就绪） |

## 背景与目标

招聘域后端已实现职位列表、详情、举报、投递全套 API，但学员端移动端仅有 mock 数据的列表页（`job-list.uvue`）和已完工的详情页（`job-detail.uvue`）。本次补全**列表页接入真实 API**这一最后环节，使「职位浏览 → 查看详情 → 举报/投递」完整用户链路闭环。

## 用户故事

| # | 角色 | 场景 | 期望 |
|---|------|------|------|
| US-1 | 学员 | 进入职位广场 | 看到按发布时间倒序排列的真实职位列表 |
| US-2 | 学员 | 按专业方向筛选 | 点击筛选标签后列表只显示对应方向的职位 |
| US-3 | 学员 | 滚动到底部 | 自动加载下一页，无更多时提示 |
| US-4 | 学员 | 点击职位卡片 | 跳转到职位详情页，信息一致 |
| US-5 | 学员 | 在详情页举报职位 | 选择预设原因或自定义输入，提交后按钮变为「已举报」 |
| US-6 | 学员 | 在详情页投递 | 点击投递后按钮变为「已投递」 |

## 功能需求

### F1 — 职位列表页（`job-list.uvue`）

- 接入 `GET /api/jobs` 替换 mock 数据
- 筛选标签动态加载（复用 `getCatalogTreeSpecialties()`），首项「全部」（id=0）
- 分页：每页 20 条，`scrolltolower` 触发加载
- 卡片字段：公司名、职位名、薪资、地区、描述截断
- 空状态 / 加载中 / 没有更多了 三态提示

### F2 — 职位详情页（`job-detail.uvue`）— 已完成，无需改动

- 举报弹窗：4 个预设选项（虚假信息/违法内容/骚扰信息/其他）+ 「其他」时展开 textarea
- 投递按钮：点击调用 `POST /api/jobs/:id/apply`

### F3 — 前端 API 层（`api/job.uts`）

- 新增 `getJobListApi(params)` 对接 `GET /api/jobs`
- 新增 `JobListParams`、`JobListResult` 类型

## 验收标准

| # | 条件 | 期望结果 |
|---|------|----------|
| AC-1 | 进入职位广场页 | 列表显示真实职位，按发布时间倒序 |
| AC-2 | 点击筛选标签 | 列表刷新为对应专业方向的职位 |
| AC-3 | 滚动到列表底部 | 自动加载下一页并追加 |
| AC-4 | 所有职位加载完 | 底部显示「没有更多了」 |
| AC-5 | 点击任意职位卡片 | 跳转详情页，职位信息与列表一致 |
| AC-6 | 详情页举报提交成功 | Toast 提示成功，按钮变为「已举报」且不可再点 |
| AC-7 | 详情页投递成功 | Toast 提示成功，按钮变为「已投递」 |
| AC-8 | 无职位数据时 | 显示空状态占位图 |
