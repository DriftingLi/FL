## 手法（零编译的「点击导航」逐页取证）

术前 / 术后两棵树各自部署一次，取证全程**点击导航**（简历总览 →「在线简历」→ 返回 →「附件简历」），
**不用 `cli launch`**（每次都要增量编译 2–5 分钟），因此两轮 6 页取证只有 2 次部署成本。

每页采：`uiautomator dump`（a11y 文本）+ `screencap`，在**滚到顶**后按**定步慢拖**（`input swipe … 600ms`，6 步）取 6 个位置的文本并集，
首屏与末屏各留一张图 ⇒ 术前 / 术后**同程序、同步长、同判据**可比。

## 设备侧两条前提（本轮实测，别再踩）

- **`npm run capture:device -AllowAppStart` 在本机是假绿**：它靠 `am start … -d uniapp://…` 切页，本机切不动（脚本头已记「三条路全堵死」），而它的页身份判据只是「多页截图哈希不同」⇒ **没切页也能 PASS**。可靠切页 = `cli launch --pagePath` 或点击导航。
- **屏幕 10 分钟超时 + 人脸解锁**：编译期间设备睡着后 `uiautomator` 返回空树、`screencap` 是黑图（约 15 KB）；无线调试场景下必须 `stay_on_while_plugged_in=3` 且保持解锁（人脸/PIN 属人的动作，agent 不得代做）。
