## 为什么①a 仍然**判不通过**（不粉饰）

**设备上跑的不是本分支的包。** 判据（`device-facts.txt` 第 4 节，可复跑）：

- 从设备拉回 `www/pages/profile/components/wrong-question-card/classes.dex`（`sha256 e1789424…`，53208 B）后逐字串判定：
  `重做 = 1`，而 `查看答案与解析 = 0`、`收起答案 = 0`、`我上次选的答案 = 0`、`暂无解析 = 0`、`解析：= 0`、
  `最近 = 0`、`record-question-img = 0` ⇒ 这是**改动前**的卡片。
- 与 17:19 抓到的 a11y 树完全一致：三张卡上都**只有** `重做 / 移出`，**没有**「查看答案与解析」，
  也没有「最近 …」「解析：…」「我上次选的答案：…」。
- 对照本工作树 9/17 的**本地编译产物** `unpackage/cache/.app-android/src/pages/profile/components/wrong-question-card.kt`
  （30598 B / 2026-09-17 15:30:02）：「我上次选的答案」「暂无解析」「record-question-img」「最近」**都在**里
  ⇒ **本地树是对的，设备上是旧的**。

**为什么没把新包推上去（阻塞，附原始报错）**：本会话的 HBuilderX CLI 通道不可用，
`cli.exe` 每次调用都返回

```
与主程序的连接已中断，可能已关闭。请运行 cli open 重新启动后再试。
```

并且 `cli open` 本身报 `启动超时`（HBuilderX CLI 失败时退出码恒为 0，故只能读文本）。已排除的几项：

- 不是主程序没起：`Get-Process HBuilderX` = pid 22100 存活（本会话全程未触碰、未 kill）；
- 不是版本错配：主程序与 `cli.exe` 同属 `D:\软件\HBuilderX.5.23.2026080626\HBuilderX\`；
- **是命名管道被拒**：`cli.exe` 走 `QLocalSocket`（其导入表里就是 `RPC::LocalSocketClient` + `QLocalSocket`），
  而本会话直接连主程序的命名管道 `\\.\pipe\hbuilderx_1789695022251_pipe` / `…0223065_pipe`
  均报 **`Access to the path is denied.`** ⇒ 本会话的沙箱**禁止打开命名管道**，
  CLI ↔ 主程序的本地 IPC 在机械上不可能建立（与 ADR-0008「受限会话阻断本地 IPC」同一条坑位）。
- 本会话同时**不能**写工作区之外的路径（实测 `C:\Users\ZHENG\…` 与 `C:\Windows\Temp\…` 均 `Access denied`），
  即文件沙箱仍为 `workspace-write`，未随环境的授权变更而放宽 —— 需要由**具备全访问权限的会话**重跑。
