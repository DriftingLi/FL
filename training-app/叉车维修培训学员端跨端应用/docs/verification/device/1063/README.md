设备（按**本次实测**记录，不沿用旧记录的写法）：serial `b32d8398`、`ro.product.marketname`=**Redmi Note 12 Turbo**、
`ro.product.model`=`23049RAD8C`、Android 15、HBuilderX 5.24 调试基座。
⚠️ 如实标注一处**与旧记录不一致**：#1059（`docs/verification/device/1059/`）把同一 serial 记作 `2510DRK44C`；
本次两种取法（`ro.product.model` / `ro.product.vendor.model`）都读作 `23049RAD8C` ⇒ 本次按实测记录，不改旧文档。

对象：`feat/mobile-ai-1041-feature-key` 收口树（head sha 见 PR）。
手法：按移动端 `docs/adr/0008-移动端验收门与证据.md`「①a 取证手法补遗（2026-09-15 实测）」的**会话式**取证 ——
`adb screencap` 截图 + `uiautomator dump` 取文本（**uvue 的文字在 `content-desc`，不是 `text`**）+ `input tap` 点击，
点击坐标一律取 dump 里的 `bounds` 中心（不按截图目测）。带参数的专项页走不了自动截图模块（它只支持 `--pagePath`），
故本页按补遗第 5 条走会话式，并从**宫格点进**（等价于 `--pageQuery` 那条深链）。

## 结论：分区**两个方向**都成立

| 页面 | 抽屉内容（`content-desc` 原文，逐字） | 结论 |
| --- | --- | --- |
| 专项页（智能维修诊断） | `wt1041-feature-probe`（本次探针）+ `货叉提升缓慢伴随异响原因分析`（既有） | **只列该功能区**；通用区会话（`hello` / `故障咨询` / `如何高效阅读书籍？`）**一条都不在** |
| 通用页（AI 助手） | `hello` + `故障咨询` ×6 + `如何高效阅读书籍？` ×6 | **只列通用区**；`wt1041-feature-probe` **不在**（同一次真机运行内，专项页发完再回看） |

⇒ 专项页建的会话**不混进首页抽屉**，且在专项页**自己的抽屉里可见**（可重开 / 可删除）——
ADR-0013 那条「**带键必有列它的界面**」在真机上为真，而不是只写在注释里。

## 夹具披露与清理（ADR-0008 ①a 第 4 条要求）

- **新建 1 条**：`fault_diagnosis` 区会话 `wt1041-feature-probe`（专项页首轮发送自动创建，1 问 1 答）。
- **已清理**：取证后在该区抽屉里删除 —— `21` 的列表里已不含它（`11` 记录它存在过）。
- **未触碰既有数据**：`hello` / `故障咨询` / `如何高效阅读书籍？` / `货叉提升缓慢伴随异响原因分析` 一律未改动。
- 如实记（**顺带发现**）：`货叉提升缓慢伴随异响原因分析` 是**改动前就落在 `fault_diagnosis` 区**的会话
  （由更早的客户端或 web 端创建 —— 后端按 `feature_key` 落库，与本次改动无关）。改动前移动端**两个抽屉都列不到它**
  （通用页只列 `ai_assistant` 区、专项页当时没有列表），本次改动让这类「孤儿会话」**重新可见**。
  这是 ADR-0013 想要的收益（其「历史回放需要分区承载」），不是本票新建的数据。
