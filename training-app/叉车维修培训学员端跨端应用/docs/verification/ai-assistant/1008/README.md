## 判据（不是靠肉眼看「像不像」，都有量出来的数）

1. **02 与 04 逐像素差异 = 0.00%** —— 一次完整往返（顶部 → 上滑看回答 → 下滑 5 次）
   **精确回到起始视口**，证明两个方向都能滚、且能回到宫格入口处。
2. **03 与 02 逐像素差异 = 33.87%** —— 中间态确实与顶部态不同（内容发生了位移），
   排除「截图拍到的是同一个静止画面」。
3. 修复前基线：内容区反复 swipe，前后截图 **0.00%**（同位置不变），即本票「滚不动」。
4. 全部滑动过程都校验 **App 仍在前台**：避免把 MIUI 手势导航的「上滑回桌面」误判成滚动
   （该误判在本轮诊断中真实发生过一次：一次上滑把 App 切走，产生了 98.75% 的假「滚动」差异）。

  而 `windowHeight=771` ⇒ 容器没被约束、无滚动余量。
