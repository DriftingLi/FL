## 判据（本轮现测确立，可复算）

`uiautomator dump` 的 XML 里，两种形态**在文本上可区分**：

| XML 中的形态 | 含义 |
| --- | --- |
| `&amp;#NNN;`（`&` 被转义） | 屏上是**字面量实体字符串**（8–9 个 ASCII 字符）⇒ **缺陷态** |
| `&#NNN;`（裸 `&` 数字引用） | 屏上是**真实字符** ⇒ 正常形态 |

**对照锚**：同一屏 sheet 右上角关闭 `✕`（模板**静态**文本里的 `&#10005;`，ADR-0015 认定一直被解码）恒为真字符 —— 它是「同屏、同构建、同判定代码」的阳性对照。

> ⚠️ dump 会把**星平面字符**转义成裸数字引用（📎 U+1F4CE 即如此），所以「裸引用 ⇒ 真字符」这条判据必须与 `&amp;#` 形态**成对**读，不能只看有没有 `&#`。

## 字形覆盖（补充判据，回答 ADR-0015 ⑤ 的「待真机确认」）

ADR-0015 ⑤ 明写：`U+2699 (⚙)` 全仓无先例，**Android 侧字体是否覆盖待真机确认；若不覆盖应换码点**。
dump 只能证明「文本是真字符」，**不能**证明「字形被覆盖、不是缺字方框」⇒ 另做**本地像素形态判据**（本机视觉 API 配额已耗尽，故不用视觉模型）：

| 字形 | `width_cv`（逐行墨迹宽度归一化标准差） | `mid_ink`（中段墨迹占比中位数） | `ink_ratio` | 判定 |
| --- | --- | --- | --- | --- |
| 合成「空矩形 .notdef」（自检样本） | **0.0000** | 0.15 | — | tofu 基准 |
| 合成「带齿圆盘」（自检样本） | 0.4644 | 0.6667 | — | 真字形基准 |
| ✦ `U+2726` | 0.9651 | 0.1429 | 0.1098 | glyph-like |
| **⚙ `U+2699`** | **0.5049** | 0.1579 | 0.2237 | **glyph-like（非空矩形）** |
| 📎 `U+1F4CE` | 1.1197 | 0.0482 | 0.0311 | glyph-like |

- 判别器带**注入自检**：先用 PIL 合成「空矩形」与「带齿圆盘」，自检不过则整份结论作废（fail-closed）；本轮自检 PASS，两类基准分离明显（`width_cv` 0.00 vs 0.46）。
- 结论：⚙ 的 `width_cv=0.5049` 远离空矩形的 `0.00`，且 `ink_ratio` 为三者最高 ⇒ **渲染成了实体字形，不是空方框**。
- **边界（如实声明）**：该判据能排除「空矩形 tofu」这一失败形态，**不能**判读字形的具体外观是否美观；外观的最终判读仍属 ① **人工门**（见 `03-icons-magnified.png`，6 倍 NEAREST 放大）。
