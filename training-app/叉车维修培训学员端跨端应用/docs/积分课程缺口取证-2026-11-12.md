# 积分兑换课程入口与课程内容可读性缺口取证（#2435）

> 取证口径：`origin/master` @ `30a38a4c`（#2431 招聘端切包）。全程只读，未触碰主树他人未提交改动。
> 引用路径均相对仓库根；移动端文件前缀省略为 `training-app/叉车维修培训学员端跨端应用/`（下文简称「移动端」）。
> 结论只写仓内可验证的事实；线上库实际数据未取到，单列于末节。

## 结论速览

| # | 可能 | 判定 | 一句话 |
| --- | --- | --- | --- |
| 1 | 前端尚未实现 | **不成立（入口存在且可达）**；但「积分商城里的课程入口」确实不存在，属 ADR-0031 的设计而非遗漏 | 兑换面单点归 `course-detail`，课程商城/课程列表/首页课程区都能走到详情页 CTA |
| 2 | 后端没有接口或数据 | **接口不成立；数据成立** | `/points/shop/course/{id}/redeem` 已注册且实现完整；但 `course.points_price` 全仓无任何写入通道、无 seed 值 |
| 3 | 接口已存在但前后端没对接 | **不成立** | `buildCourseItem` / `buildCourseDetail` 已消化全部字段名差异；仅 `chapter_count` 一处后端不下发、前端兜底成假数据 6 |
| 4 | 业务本身未完成 | **成立（价格侧）；不成立（章节内容侧）** | 6 门 seed 课程 `points_price` 全为 NULL ⇒ CTA 恒「开始学习」、兑换入口永不出现；18 个 seed 章节有真实 Markdown 正文 |

**缺口定位：不在前端入口，也不在接口，而在「课程价格数据 + 价格写入通道」这一层。** 用户看到的两个现象是同一根因的两面：没有 `points_price` ⇒ 没有「N 积分兑换」CTA；而「课程页面没有可阅读内容」在仓内证据下不成立（章节正文有 seed、渲染链路完整），更可能是线上数据/登录态/页面选择问题，见末节。

## 一、四种可能逐条判定

### 1. 前端尚未实现 —— 不成立

**入口存在，且三条路径都能走到兑换面。**

- 兑换 CTA 的唯一实现：`移动端/pages/courses/course-detail.uvue:110` 调 `buildCourseCta(d.points_price ?? null, d.entitled ?? null, balanceReading.value, resumeLabel)`；四态派生在 `移动端/utils/coursePointsCta.uts`（免费/已拥有 → 学习；未拥有 → 「N 积分兑换」；余额不足 → 追加提示行）。
- 点击链路：`course-detail.uvue:357 onCtaClick` → 兑换面 `showModal` 确认 → `course-detail.uvue:332 doRedeemCourse` → `redeemCoursePointsApi`（`移动端/api/points.uts:201`）→ 成功后 `await loadDetail()` 重拉 `entitled`。
- 兑换 API 已接：`api/points.uts:201` 拼 `POST /points/shop/course/{id}/redeem`，四字段 `balance/total_earned/sku/ref_id`。

**「积分商城没有课程入口」是设计，不是缺口。** 移动端 ADR-0031 决策 1 明确「兑换面单点归 `course-detail`」；`移动端/pages/points/points-shop.uvue:126` 只消费 `getShopItemsApi()` 的 SKU 列表，页面内无任何课程条目（全文无「课程」字样）。积分商城的商品来自 `points_shop_item` 表，而课程兑换走的是 `course.points_price`，两者是不同事实源（见 `backend/migrations/000002_points_system.up.sql:109` 表注释「积分商城（真题等，课程兑换走 course.points_price）」）。

**唯一可算「前端未实现」的边角**：`移动端/pages/mall/mall.uvue` 的课程卡片只有整卡点击进详情（`:178 onProductClick`），没有列表内直接兑换按钮——这同样符合 ADR-0031 决策 1（兑换面单点归详情），不算缺口。

### 2. 后端没有接口或数据 —— 接口不成立，数据成立

**接口侧齐全：**

- 路由已注册：`backend/internal/points/handler.go:56` `g.POST("/shop/course/:courseId/redeem", h.RedeemCourse)`，挂在 `/points` group（JWTAuth + `CapabilityRequired(authz.CapPointsUse)`）。
- 实现完整：`backend/internal/points/service.go:860 RedeemCourse` 查课程 → `if course.PointsPrice == nil || *course.PointsPrice <= 0 { return nil, ErrCourseNotRedeemable }`（`:865-866`）→ 走统一 `redeem` 管线（lockKey `shop:course:%d:%d`、sku `entitlement.CourseSKU(courseID)`、refID courseID、reason `redeem_course`）。
- 章节正文接口返回正文：`backend/internal/course/service.go:765 ChapterToDTO` 含 `Content string json:"content"`；`ChapterDetailShared`（`:891` 起）装载 `Files`、上下章、`study_status`、`resume_position`。`GET /course/:course_id/chapter/:chapter_id` 注册于 `backend/internal/course/handler.go:44`。

**数据侧缺：`points_price` 从未被赋值，且没有写入通道。**

- 列存在：`backend/migrations/000002_points_system.up.sql:98` `ADD COLUMN IF NOT EXISTS points_price INT CHECK (...)`，注释「NULL/0=免费直学，>0=需积分兑换」。
- 6 门 seed 课程的 INSERT 列**不含** `points_price`：`backend/migrations/000001_baseline.up.sql:1334-1339`。
- 全仓 `UPDATE course` 只有一条（`:3110`，只写 `credential_id`）；`points_price` 在 `migrations/`、`cmd/` 里只出现在 000002 的 ADD COLUMN 与注释。
- 导入器同样不写：`backend/cmd/import-reference-content/courses.go:240` 的 `INSERT INTO course (...)` 列清单无 `points_price`。
- **管理端 API 也无法设置**：`backend/internal/course/dto.go:8-24 CourseInput` 字段清单里没有 `points_price`；`admin_service.go:54 CreateCourse` / `:104 UpdateCourse` 走 `applyCourseTrainingFields`，均不写该列。管理端写路由见 `backend/internal/course/handler_admin.go:45-52`（POST/PUT `/admin/course`）。
- 结论：今天要把某门课变成付费课，只能直接 SQL `UPDATE course SET points_price = N`。

### 3. 接口已存在但前后端没对接 —— 不成立

`api/course.uts` 头部注释列的字段差异，均已在 build 函数里消化：

| 后端形状 | 前端映射 | 证据 |
| --- | --- | --- |
| 列表 `{courses, pages}` | `COURSE_LIST_KEYS=['courses','items']` | `移动端/api/course.uts:294` 附近 |
| 课程 `name` / `cover_image` | `title` / `cover_url` | `api/course.uts:52 buildCourseItem` |
| 详情 `{course_info, progress}` | `course_id` / `progress_pct` | `api/course.uts:129 buildCourseDetail` |
| `points_price`（`*int`，omitempty） | `toNumberOrNull` → `number|null` | `buildCourseItem` / `buildCourseDetail` |
| `entitled`（`*bool`，仅详情有主体时下发） | 三态保留 `null`，不 `toBool` 兜底 | `buildCourseDetail`；类型见 `移动端/types/course.uts` |

唯一对不上的一处是**后端不下发、前端兜底造假**：`chapter_count` 只在详情路径由 `fillChapterCount` 填（`backend/internal/course/service.go` 的 `CourseDTO.ChapterCount *int64 json:"chapter_count,omitempty"`），列表接口不带；前端 `移动端/pages/courses/courses.uvue:67` 写 `共{{ course.chapter_count > 0 ? course.chapter_count : 6 }}个课时` ⇒ 真实数据下列表恒显示「6 个课时」。这是展示层假数据，不是兑换链路断点。

### 4. 业务本身未完成 —— 价格侧成立，章节内容侧不成立

**价格侧成立（核心缺口）：**

- 6 门 seed 课程 `points_price` 全 NULL（`000001_baseline.up.sql:1334-1339` 未写该列）。
- 无任何迁移/seed/导入器/管理端 API 赋过值（见第 2 条证据链）。
- 后果链：`points_price` NULL → `buildCourseCta` 判免费（`utils/coursePointsCta.uts` 的 `isPaidCourse`）→ 详情页 CTA 恒「开始学习」→ `doRedeemCourse` 永不触发 → 用户在任何页面都看不到「N 积分兑换」。
- 连带症状：课程列表「积分兑换」筛选（`courses.uvue:138-139`，`paid='paid'`）走后端 `points_price > 0`（`backend/internal/course/list.go:58`）⇒ 真实数据下该 tab 恒为空列表。

**章节内容侧不成立：**

- 18 个章节有真实长 Markdown 正文：`backend/migrations/000001_baseline.up.sql:1342` 起（chapter_id 1-18，course 1-6 各 3 章，如「## 第一章 叉车分类与型号」），`content_type` 有值。
- 渲染链路完整：`移动端/pages/courses/chapter-view.uvue:48` `ChapterMarkdown v-if="detail!.content.length > 0"` → `:125 parseMarkdown(detail.content)` → `components/markdown/markdown-blocks.uvue`（章节档声明 heading/paragraph/code/list/quote/divider/image/table 八位）。
- 章节列表不设权限条件：`移动端/pages/courses/components/course-chapter-list.uvue` 全量 `v-for` 渲染，空列表才显示「暂无章节内容」。
- 免费课可读：`backend/internal/course/service.go` 的 `courseEntitled` 对 `pointsPrice == nil || <= 0` 恒 true ⇒ 章节详情正常返回正文。

**反向发现（不是用户报的「读不到」，而是「读太多」）：** `GET /course/{id}` 的详情响应把**全部章节的 `content` 原样下发**——`loadCourseWithChapters`（`backend/internal/course/service.go:232`）对每章调 `ChapterToDTO`（`:765`，含 `Content`），`GetCourseDetail`（`:356`）未按 `entitled` 过滤。这与根仓库 ADR-0062 决策 3「内容读面（章节详情 / slides / 进度写）未兑换即 404」不一致：付费课的正文可绕过章节详情、直接从课程详情响应里读走。属安全缺口，建议单独立票。

## 二、入口可达性路径图（文字）

```
tabBar「课程」(pages/courses/courses)
  └─ 课程列表项点击 onCourseClick
       └─ /pages/courses/course-detail?id=<course_id>
            ├─ 章节列表（course-chapter-list）点击 → /pages/courses/chapter-view?course_id&chapter_id
            │     └─ 正文 / 「该章节需先解锁」/「该章节暂无内容」
            └─ 底部 action-bar 单按钮 onCtaClick
                  ├─ 免费或已拥有 → onStartLearn（chapters 为空则 toast「暂无章节内容」）
                  └─ 未拥有 → showModal 确认 → doRedeemCourse → POST /points/shop/course/{id}/redeem
                        └─ 成功 → 重拉详情（entitled 变 true）→ CTA 回归「学习」

tabBar「首页」(dashboard)
  ├─ 宫格「课程商城」→ /pages/mall/mall（dashboard-menu-grid.uvue:30，available: true）
  │     └─ 课程卡片整卡点击 → course-detail（mall.uvue:178）
  └─ 首页课程区 → course-detail（dashboard.uvue:169/176）

tabBar「我的」(profile)
  └─ 可用积分 → /pages/points/points-detail（profile.uvue:314）
        └─ 「商城」入口 → /pages/points/points-shop（points-detail.uvue:142）
              └─ 只有 SKU 商品（当前仅 ai_pro），**无课程条目**（设计如此，ADR-0031 决策 1）
```

**可达性结论：**

- 课程 → 详情 → 兑换：**代码可达**；真实数据下 CTA 停在「开始学习」，兑换面不可见（因 `points_price` 全 NULL）。
- 积分页 → 积分商城 → 课程：**不可达，且按设计不应可达**。积分商城是 SKU 货架，课程不是 SKU。
- 商城 → 课程：**可达**（整卡点击进详情），但商城自身无兑换按钮，价格行显示「免费」（`mall.uvue:194 coursePriceText` → `renderCoursePrice`）。
- 无 tabBar 藏入口问题：`pages.json` tabBar 为 首页/课程/AI学/交流/我的，课程与首页都在；`mall`、`points-shop` 均为普通页面，分别由首页宫格与积分明细进入。

## 四、移动端可独立完成（不依赖后端新接口）

1. **课程列表「积分兑换」空态说明**：`courses.uvue` 在 `paid='paid'` 且列表为空时，补一句「暂无可兑换课程」而不是空白列表（纯前端文案，`courses.uvue:164` 取数处已有 `loadError` 三态可复用）。
2. **列表课时数假数据修正**：`courses.uvue:67` 的 `: 6` 兜底改为「课时数待更新」或不显示，避免真实数据下恒显示 6（后端列表不下发 `chapter_count` 是事实，前端不应编造）。
3. **商城卡片补「查看/兑换」语义**：`mall.uvue` 价格行已显示「N 积分/免费」，可在卡片上补一个「去兑换」次级按钮跳详情（仍遵守 ADR-0031 决策 1：兑换动作只在详情页发生，列表只做导流）。
4. **积分商城页补「课程兑换」导流区**（可选，需产品确认）：`points-shop.uvue` 可复用 `getCourseListApi(..., paid='paid')` 拉付费课，渲染一个「课程兑换」区块，点击进 `course-detail`。这不新增后端接口，也不违背「兑换面单点归详情」——只是多一个入口。**注意**：真实数据下该区块会为空（`points_price` 全 NULL），需与后端数据补齐同批上线，否则又是一个空态。
5. **章节内容空态/错误态已完备**，无需改动：`chapter-view.uvue:20`（锁定）、`:57`（暂无内容）、重试位均在。

> 移动端**不能**独立完成的事：让兑换 CTA 出现。CTA 由 `points_price` 驱动，前端没有任何合法途径伪造该值（ADR-0031 决策 4 明确禁止内存抹值）。

## 五、需后端配合

1. **给 `points_price` 建写入通道（P0）**：`CourseInput` 增加 `PointsPrice *int json:"points_price"`，`CreateCourse`/`UpdateCourse` 落库；同步管理端课程表单。否则运营永远无法把课程标成付费。
2. **给至少一门课赋 `points_price`（P0）**：新增迁移（如 `UPDATE course SET points_price = N WHERE course_id = X`）或 seed 补列。没有这一步，兑换链路在真实环境无法被验证，移动端所有兑换 UI 都是死代码。
3. **决定课程是否进积分商城 SKU 货架（P1，产品决策）**：若要求「积分商城能看到课程」，需在 `points_shop_item` 建课程行并在 `sku_registry.go` 登记权益读者（否则 `ListShopItems` 会按 deny-by-default 过滤掉）；若不要求，则应在文档/文案上明确「课程兑换在课程详情页」，避免用户继续在积分商城找。
4. **修课程详情正文过度下发（P1，安全）**：`GetCourseDetail` 对未拥有付费课的 `chapters[].content` 置空或不下发，与 ADR-0062 决策 3 的「内容读面未兑换即 404」对齐。
5. **列表下发 `chapter_count`（P2）**：`GetCourses` 补 `fillChapterCount` 或批量 count，消除前端假数据 6。

## 六、未取到

- **线上/生产库实际数据**：`course.points_price` 当前值、`chapter.content` 是否为空、`points_shop_item` 实际行。本次无 DB 访问，只能证明「仓内没有任何写入 `points_price` 的代码路径」，不能证明线上一定全 NULL（可能有人手工 SQL 改过）。
- **生产是否执行过 `000001_baseline` 的章节 seed**：若线上库是空库或章节被清空，则「课程页面没有可阅读内容」成立，但根因在数据运维而非代码。
- **用户报障的具体页面/账号/证件**：issue #2435 正文只有概述，未附截图、账号、课程 id；无法判断用户看到的是「资料课」tab（`courses.uvue` 该 tab 恒显示「内容建设中」）还是课程详情页。
- **未登录态**：`GET /course/{id}` 与章节详情均需 JWT（`course/handler.go:43-44`），未登录时详情页只会显示加载失败；用户是否登录未取到。
