# 微信小程序上传代码检查未通过 —— 一手资料调研（2026-11-07）

调研对象：微信开发者工具「上传」时的代码质量 / 包体积检查面板报出的 4 项未通过（主包 1.5M、JS 压缩、组件按需注入、图片音频 200K），以及 uni-app / uni-app x 在 mp-weixin 侧的落地方式。

取证原则：只记录能拿到原文的官方页面；拿不到的写进「未取到的内容」，不做推测性指控。

---

## 结论速览

- **主包硬上限是 2MB，不是 1.5M**：官方原文「单个分包/主包大小不能超过 2M」，全部分包合计不超过 30M（服务商代开发 20M）。
- **「1.5M」是代码质量扫描的建议阈值**，出自官方《小程序性能优化指南》第 1 条「代码包不包含插件大小超过 1.5 M」，等级标注为【建议】，不是平台硬限制。
- **用户给的链接就是那份指南本身**：`developers.weixin.qq.com/miniprogram/dev/devtools/quality.md` 的「评分规则」一节直接把它列为「可优化项清单以及优化建议」的文档地址。
- **该扫描基于本地代码静态分析**（原文「基于本地的代码进行扫描」），与上传后展示的包体积口径不同 —— 这是社区长期抱怨「扫描说我 1.5M＋、上传只显示 1.39M」的根因，官方文档未解释两者换算关系。
- **组件按需注入 = `app.json` 里加 `"lazyCodeLoading": "requiredComponents"`**，基础库 2.11.1+、工具 1.05.2111300+ 起生效；指南里该条为【必须】。
- **JS 压缩 = `project.config.json` 的 `setting.minified`**（官方字段说明原文「上传代码时是否自动压缩脚本文件」），是开发者工具的编译设置项，不是小程序运行时配置。
- **图片音频 200K 的判定粒度官方没有写死**：原文只说「图片、音频等静态资源体积大小超过200K时，将它们上传到CDN」，未说明是单文件还是合计、也未说明统计范围含不含分包 —— 此项只能按「未取到」处理。
- **uni-app / uni-app x 都把 `lazyCodeLoading` 放在 `manifest.json` 的 `mp-weixin` 节点**（uni-app x 文档原文同句：目前仅支持值 requiredComponents）；分包走 `pages.json` 的 `subPackages`，静态资源「不占主包」还要另外开 `mp-weixin.optimization.subPackages`。

## 逐条取证

### 1. 主包体积上限到底是什么

**结论**：硬限制 2MB（单包）/ 30MB（全部分包合计）。面板上的「1.5M」是《小程序性能优化指南》第 1 条给出的**建议阈值**，属于代码质量扫描的优化建议级别（【建议】），既不是新规、也不是某个类目的额外要求。

**原文引用**

- 《小程序性能优化指南》第 1 条（官方开放社区「知识库」文，前置标注「官方 精选 热门」）：
  > 1. 代码包不包含插件大小超过 1.5 M
  > 【建议】小程序代码包单个包大小限制为2M。因此我们建议开发者在开发时，如果遇到单包体积大于1.5M的情况，可以采取分包的方式，把部分代码拆分到分包去，降低单个包的体积，提升小程序的加载速度。具体可以查看文档《使用分包》。

- 硬限制（「分包加载」页）：
  > 目前小程序分包大小有以下限制：整个小程序所有分包大小不超过 30M（服务商代开发的小程序不超过 20M）；单个分包/主包大小不能超过 2M。

- 扫描口径（「代码质量」页）：
  > 代码质量扫描是一项方便小程序开发者提升代码质量的插件，它会**基于本地的代码**进行扫描，找出代码中的可优化项，以及给出一些优化建议。
  > 可优化项清单以及优化建议，可具体查看文档：[小程序性能优化指南](https://developers.weixin.qq.com/community/develop/doc/00040e5a0846706e893dcc24256009)

- 该指南的编辑状态（页面页脚与元数据）：创建 2021-12-20，`最后一次编辑于 2025-07-24`，浏览 3634146，页脚另有免责：「知识库内容非实时更新，可能已过期、失效或不适用于当前情形，请谨慎参考」。

**来源 URL**

- 指南（用户给的那条，正文见「未取到的内容」说明取法）：<https://developers.weixin.qq.com/community/develop/doc/00040e5a0846706e893dcc24256009>
- 代码质量页：<https://developers.weixin.qq.com/miniprogram/dev/devtools/quality.html>（`.md` 版：<https://developers.weixin.qq.com/miniprogram/dev/devtools/quality.md>）
- 分包上限：<https://developers.weixin.qq.com/miniprogram/dev/framework/subpackages.html>

### 2. 「组件按需注入」

**结论**：官方要求即 `app.json` 加 `"lazyCodeLoading": "requiredComponents"`。开启后只有「当前访问页面 + 该页面 JSON 声明的组件 + app.json 全局声明的组件」会被注入执行，未访问页面与其未声明组件不加载；插件包与扩展库暂不支持按需注入。

**原文引用**

- app.json 配置参考（`lazyCodeLoading` 条目）：
  > 目前仅支持值 `requiredComponents`，代表开启小程序「按需注入」特性。
  > ```json
  > { "lazyCodeLoading": "requiredComponents" }
  > ```
  > 表格行：`lazyCodeLoading | string | 否 | 配置自定义组件代码按需注入 | 2.11.1`

- 《按需注入和用时注入》页：
  > 基础库 2.11.1 及以上版本支持，2.11.1 以下兼容但无优化效果。工具调试请使用 1.05.2111300 及以上版本，基础库选 2.20.1 及以上版本。
  > 启用按需注入后，小程序仅注入当前访问页面所需的自定义组件和页面代码。未访问的页面、当前页面未声明的自定义组件不会被加载和初始化，对应代码文件将不被执行。请开发者修改配置后务必确认小程序的表现正常。
  > 启用按需注入后，页面 JSON 配置中定义的所有组件和 app.json 中 usingComponents 配置的全局自定义组件，都会被视为页面的依赖并进行注入和加载。建议开发者及时移除 JSON 中未使用自定义组件的声明，并尽量避免在全局声明使用率低的自定义组件，否则可能会影响按需注入的效果。
  > 插件包和扩展库目前暂不支持按需注入。如果需要实现插件按需加载，可以考虑将插件置于一个分包，并通过「分包异步化」的形式异步引入。

- 用时注入（进阶，需配占位组件，基础库 2.11.2+）：
  > 每个页面内，第一次渲染该组件前，该组件都不会被注入；第一次渲染该组件时，该组件会被渲染为其对应的占位组件，渲染流程结束后开始注入；注入结束后，占位组件被替换回对应组件。

- 指南第 12 条（本条检查的出处）：
  > 12. 未开启组件懒注入（按需注入）
  > 【必须】在 app.json 中加入 `"lazyCodeLoading": "requiredComponents"` 可以开启小程序组件按需注入特性。

**关于「副作用 / 限制」的准确边界**：官方文档明写的是上三段（未访问页面不注入、JSON 声明即视为依赖、插件与扩展库不支持）与用时注入的占位渲染时序。**没有**官方原文直接讨论 `selectComponent`、动态组件名（`<component is>`）、或「自定义组件只在运行时被引用」时按需注入的行为 —— 这三类只能归到「JSON 声明即视为依赖」这一条规则的推论，不写成官方结论。

**来源 URL**

- <https://developers.weixin.qq.com/miniprogram/dev/framework/ability/lazyload.html>（`.md` 版：<https://developers.weixin.qq.com/miniprogram/dev/framework/ability/lazyload.md>）
- <https://developers.weixin.qq.com/miniprogram/dev/reference/configuration/app.html#lazyCodeLoading>（`.md` 版：<https://developers.weixin.qq.com/miniprogram/dev/reference/configuration/app.md>）

### 3. 「对 JS 文件进行压缩」

**结论**：判定对象是**上传包里的脚本文件是否被压缩/混淆**，开关在开发者工具侧（`project.config.json` 的 `setting.minified`，对应「详情 - 本地设置」里的「上传代码时自动压缩脚本文件」）。同组还有 `minifyWXSS` / `minifyWXML`（样式、WXML 压缩），`es6`（ES6 转 ES5）与 `enhance`（增强编译）是另外的编译选项，工具 1.05.2106091 之后二者合并为「将 JS 代码编译成 ES5」。

**原文引用**

- 指南第 8 条（本条检查的出处）：
  > 8. 未开启JS压缩
  > 【必须】在工具「详情」-「本地设置」中开启「上传代码时自动压缩脚本文件」的设置
  （第 9、10 条同理：WXML、WXSS 压缩；第 3 条与本条并列。）

- `project.config.json` 字段说明：
  > `minified | Boolean | 否 | 上传代码时是否自动压缩脚本文件`
  > `minifyWXSS | Boolean | 否 | 上传代码时是否自动压缩样式文件`
  > `minifyWXML | Boolean | 否 | 上传代码时是否自动压缩 WXML 文件`
  > `es6 | Boolean | 否 | 是否启用 es6 转 es5`
  > `enhance | Boolean | 否 | 是否打开增强编译`
  > `uglifyFileName | Boolean | 否 | 上传时进行代码保护`
  > `ignoreUploadUnusedFiles | Boolean | 否 | 上传时是否过滤无依赖文件`

- 「代码编译」页「压缩代码」节：
  > 开启此选项，开发者工具在上传代码时候将会帮助开发者压缩和混淆 javascript 代码，减小代码包体积。
  > 同页「将 JS 代码编译成 ES5」：工具 1.05.2106091 之后，原「ES6 转 ES5」与「增强编译」合并为该选项，逻辑与原「增强编译」一致。

- 「代码保护」的已知不适用情形（与压缩同页，影响「压缩后是否还报错」的判断）：

### 4. 「图片和音频资源大小应不超过 200K」

**结论**：官方只有一句建议 —— 超过 200K 的图片/音频等静态资源上传 CDN 用 URL 引入。**判定粒度（单个文件 vs 合计）与统计范围（主包/分包/插件）官方文档均未写明**，见「未取到的内容」。同文档另有一条易混的「引用插件大小超过 200 K」（插件体积计入 2M 限制），两者数字相同但对象不同。

**原文引用**

- 指南第 3 条（本条检查的出处）：
  > 3. 图片和音频资源大小超过 200 K
  > 【建议】小程序代码包里可以存放一些必要的静态资源（如tabbar的icon等）；但其他非必要的静态资源体积过大会影响小程序代码包加载速度。因此我们建议图片、音频等静态资源体积大小超过200K时，将它们上传到CDN，用URL引入会是个更好的选择。

- 指南第 2 条（易混项，对象是插件不是静态资源）：
  > 2. 引用插件大小超过 200 K
  > 【知会】小程序插件的大小是会算进小程序代码包2M体积限制中的。因此当我们发现开发者引用的插件体积大于200K时，会对开发者予以提示…

- 官方优化指引第 3 条（处理方式的权威表述）：
  > 控制代码包内的资源文件 —— 小程序代码包在下载时会使用 ZSTD 算法进行压缩，图片、音频、视频、字体等资源文件会占用较多代码包体积，并且通常难以进一步被压缩…建议开发者在代码包内的图片一般应只包含一些体积较小的图标…这类文件应尽可能部署到 CDN，并使用 URL 引入。

**来源 URL**

- <https://developers.weixin.qq.com/community/develop/doc/00040e5a0846706e893dcc24256009>（第 2、3 条）
- <https://developers.weixin.qq.com/miniprogram/dev/framework/performance/tips/start_optimizeA.html>（「控制代码包内的资源文件」节）

### 5. uni-app / uni-app x 在 mp-weixin 侧怎么落地

#### 5.1 分包 `subPackages` 与分包预下载 `preloadRule`

**uni-app（`uniapp.dcloud.net.cn`）**
- `pages.json` 配置项表：`subPackages | Object Array | 否 | 分包加载配置`、`preloadRule | Object | 否 | 分包预下载规则 | 微信小程序、QQ 小程序、抖音小程序、支付宝小程序、京东小程序`。
- `subPackages` 子项字段：`root`（子包根目录）、`pages`（参数同 pages）、`plugins`。原文注意事项：
  > subPackages 里的 pages 的路径是 root 下的相对路径，不是全路径。
  > 微信小程序每个分包的大小是 2M，总体积一共不能超过 20M。
  （**注意**：这句「总体积 20M」是 uni-app 文档的旧口径，微信官方现行是 30M / 服务商 20M，以微信页面为准。）
- `preloadRule` 官方示例（字段即 `network` 与 `packages`）：
  > `"preloadRule": { "pagesA/list/list": { "network": "all", "packages": ["__APP__"] }, "pagesB/detail/detail": { "network": "all", "packages": ["pagesA"] } }`

**分包优化的真正开关在 manifest，不在 pages.json**（`manifest.json` → `mp-weixin.optimization.subPackages`）：
  > 在对应平台的配置下添加 `"optimization":{"subPackages":true}` 开启分包优化
  > 目前只支持 mp-weixin、mp-qq、mp-baidu、mp-toutiao、mp-kuaishou 的分包优化
  > 分包优化具体逻辑：静态文件：分包下支持 static 等静态资源拷贝，即分包目录内放置的静态资源不会被打包到主包中，也不可在主包中使用；js文件：当某个 js 仅被一个分包引用时，该 js 会被打包到该分包内，否则仍打到主包（即被主包引用，或被超过 1 个分包引用）；自定义组件：若某个自定义组件仅被一个分包引用时，且未放入到分包内，编译时会输出提示信息。

**uni-app x（`doc.dcloud.net.cn/uni-app-x/`）**
- 编译目标前提：「HBuilder 4.41 + 支持编译到微信小程序」（同页另有 HBuilder 5.31+ 支持支付宝小程序）。
- `pages.json` 配置项表同样包含：`subPackages | Array<PagesSubPackages> | 否 | 分包加载配置`、`preloadRule | preloadRule 配置项列表 | 否 | 声明分包预下载的规则`。
- `subPackages` 子项字段为 `root`（子包的根目录）、`independent`（是否声明对应分包为独立分包）、`pages`（`Array<SubPackagePagesOptionsPage>`）—— 与 uni-app 经典版相比**没有 `plugins`，多了 `independent`**。
- 独立分包页：「uni-app x 和 uni-app vue3 项目从 5.21 支持小程序独立分包功能…uni-app x 和 uni-app vue3 项目会自动识别 pages.json 中的分包配置」，平台兼容表里 uni-app x 在「微信小程序」列标 √；vue2 项目则需在 `manifest.json` 的 `mp-weixin` 里加 `"independent": true`。
- 独立分包**当前限制**（原文）：
  > 暂不支持自动复制或重写 root 外的业务依赖，包括 JS、TS、Vue 文件、原生小程序组件、静态资源和样式资源。
  > 暂不复用主包 main.* 中的业务初始化逻辑，包括 app.use()、globalProperties、provide、store、i18n、全局 mixin 等。
  > 暂不复用 App.vue 的应用级样式，也不模拟主包 App 生命周期。
  > 独立分包引用 root 外业务文件、组件、静态资源或样式时会受到限制并给出错误提示，现阶段需要开发者主动将相关依赖放入独立分包 root 内。
  > 不支持通过 hx 在独立分包根目录创建 uni-modules… uni-stat 统计暂不支持独立分包
- 补充：uni-app x 的 `subPackages` 静态资源「不占主包」是否也走 `optimization.subPackages`，**uni-app x manifest 文档里检索「分包」为 0 处命中**，即该优化开关在 uni-app x 侧未文档化 → 见「未取到的内容」。

#### 5.2 `lazyCodeLoading` 的注入方式

**结论**：写 `manifest.json` → `mp-weixin` 节点，不手改 `app.json`，不用条件编译。

- uni-app manifest 文档（`mp-weixin` 节点属性表）原文：
  > `lazyCodeLoading | String | 目前仅支持值 requiredComponents，代表开启小程序 按需注入 特性，详见`
  > 同表相邻项：`independent | Boolean | vue2 微信小程序是否开启独立分包`；`nativeTags | Array | 微信小程序平台的原生组件 (4.81+)`；`slotMultipleInstance`、`mergeVirtualHostAttributes`、`embeddedAppIdList`、`requiredPrivateInfos`。
- uni-app x manifest 文档（`mp-weixin` 节点）原文：
  > `lazyCodeLoading | string | 目前仅支持值 requiredComponents，代表开启小程序按需注入特性，详见 https://developers.weixin.qq.com/miniprogram/dev/reference/configuration/app.html#lazyCodeLoading`
  （uni-app x 侧另有 `enableVirtualHost | boolean`「是否为组件启用 virtualHost，默认启用」、`darkmode`。）
- 若确需直接改微信项目配置，uni-app 另给了「自定义小程序项目配置」通道（不覆盖 `lazyCodeLoading`，但覆盖 `project.config.json`）：
