## 3. 死资产：真实的"可删面"

**结论：没有真死脚本。** 59 个脚本里引用次数最少的是 1 次（`behavior-subset.ps1` 被 `dev-finish.ps1` dot-source）。唯一可选归档的是 3 个**只被历史证据文档引用**的一次性取证工具：

| 文件 | 行数 | 唯一引用面 |
| --- | --- | --- |
| `scripts/cert-fix-evidence.mjs` | 519 | `docs/verification/mp-weixin/1671,/1692` 的 README |
| `scripts/png-lum-profile.mjs` | 127 | 同上（1671） |
| `scripts/png-crop.mjs` | 101 | 同上（1671） |
| **合计** | **747** | — |

→ 处置建议：**移入 `docs/verification/_tools/` 或标注 `# 历史一次性工具`**，不删（证据可复算性还在）。占脚本总量 **3.4%**。

> **方法上的自我纠错（留作反例）**：我第一遍只扫了 `package.json` / `.github` / `AGENTS.md` / `docs/agents` / `docs/adr` 五个面，判出 **6 个"零引用"脚本**。复核后 **3 个被推翻**：`behavior-subset.ps1`（1 处）、`gate-stages.ps1`（3 处）、`evidence-gen.ps1`（11 处）都在脚本之间 dot-source，只是不在我扫的那五个面里。**这就是本仓门链最大的系统性风险的一个缩影：判据面选窄了，会稳定地给出"干净"的错答案。**
>
> **第二处纠错（同一类病）**：首版统计把 `wc -l` 末尾的 `total` 行又当作一条记录加了一遍 ⇒ 测试行数被读成 **119,132**（真值 **59,566**）、比例被夸成 **10.9 : 1**（真值 **6.3 : 1**）。已按 §7 的复算命令更正。**两次错都不是算错，是"判据面"错 —— 与 §4 那条已死规则同源。**

## 4. 唯一一条"已退役但仍在生产"的判据（本文件最有价值的一条）

**现象**：ADR-0039/0040 的窗口机制已于 2026-10-23 整体退役（0043 决策 1），但它的**判据分支还活着**，且由 9 条测试守着不许删：

| 落点 | 内容 |
| --- | --- |
| `.github/scripts/lib/gate-validator.mjs:133-140` | 描述符：`prefix: ^\s*SKIP\b` + `requireAll: ["待批收口"]`，note 自称"窗口机制已被 ADR-0043 退役，仅过渡期认" |
| `.github/scripts/lib/gate-validator.mjs:526-535` | 分支逻辑 + 结构化 `skipped` 字段路径（"退场判据 = 本判据与 #1858 都合入后…"） |
| `.github/scripts/pr-evidence-check.test.mjs` | **9 处**断言（含 `:1434` 的静态断言 `requireAll.includes('待批收口')`） |
| `.github/workflows/mobile-gates.yml:247` | 渲染分支（"跳过"与"已取证/还没有"三态区分） |

**这就是"每次修完冒更多缺陷"的机制本体**：一条规则退役后，它的判据与守护测试不会自己消失；而下一轮改动碰到的就是这套还在跑的旧判据，于是又产生一处新的不一致、又要一条新守护。**修门的一部分工作量是在维护已死的规则。**

**退场判据已满足（2026-10-28 现测）**：校验器自写的退场条件原文是"本判据与 #1858 都合入后"。实测 `#1858`（ADR-0043 落地 + 五处文档回写）**已于 2026-10-24 CLOSED**、`#1859`（校验器认 0043 新口径）**也已 CLOSED** ⇒ **两条都已满足，代码仍原样在跑。**

**处置**（一条，不需要新机制）：按它自己写的退场判据清场 —— 删描述符（`gate-validator.mjs:133-140`）+ 分支（`:526-535`）+ 9 条测试 + 渲染分支（`mobile-gates.yml:247`）。**这是全清算里唯一"净减代码且不降覆盖率"的动作，且前置已清、无需再等票。**

## 5. 三条准入条件（只管"以后别再加"，不改现行门）

1. **纯函数优先**：能在 ubuntu CI 上跑的判据才准进 ③（每 PR）。依赖 HBuilderX / 开发者工具 / 真机的，只允许"发版前一次"或"人签"，**永不进每 PR**。
2. **配额制**：新增一条门，必须同时退役一条；门类提交设月预算（现 34 天 78 条门提交、56 条降级/退役、69 条修/补 —— 修与减大致打平，说明还在拉锯）。
3. **无实测不入文**：任何"约 X 分钟""低风险"必须先有一次带票号读数。已退役的三条（②门 9–26min / 锁 10min / ④a 4.8–8min）就是反例清单。
