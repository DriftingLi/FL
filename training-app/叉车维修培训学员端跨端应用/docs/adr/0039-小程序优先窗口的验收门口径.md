# 0039 - 小程序优先窗口的验收门口径

- **日期**：2026-10-13
- **关联**：#1679（本票）· #1674（② 门「执行人：agent 执行」已合并先例）· #1671 / #1678（`docs/verification/mp-weixin/` 入仓产物先例）· UI 改造线（map #1591，批 1–4 已并入 master）
- **承接**：`0016` 裁定 5（①a「一次分支收口」节奏）与 ③「不跨 PR 共用一次真机取证」——**窗口期内**按本 ADR 调整（就地标记已回写 0016 / 0008 / 两侧 AGENTS.md）；与 `0038` 无编号冲突，仅顺延。
- **状态**：已裁定（窗口开关 = 人签；本 ADR 是窗口口径，不是开关本身）· **2026-10-15 收紧见 `0040`**（真机零跑 / 小程序门每 PR 必跑 / 能力面 PR 排队到退出后；与本 ADR 决策 4 冲突处以 0040 为准）· **2026-10-24 退役注：窗口机制已被 `0043-真机门降级常态化与发版冒烟（2026-10-23 裁定）.md` 决策 1 整体退役**（不再有「窗口退出」事件，退出被首次发版吸收；② 升为常态主门见其决策 3）。原文保留作历史。
  > **部分被取代**（2026-10-29，#2101 / #2103）：② 覆盖判据改为「改动页全跑 + 空清单冒烟两页 + `coverage=` 三值」，①b 人签整体退役。执行以 `AGENTS.md` 执行单为准；本文件只作来路。

## 背景

- 近期复盘（2026-10-13，/retro）：UI 改造线批 1–4 的每 PR 收口都压在 ① 真机取证上，② 小程序门只是半自动副门。用户裁定转向**小程序优先**：交付的主要判定改到小程序侧，真机取证延后到批收口。
- 现行条文没有「窗口」概念：0016 把 ①a 钉死为「一次分支收口跑一次、不跨 PR 共用」；而 ② 的执行人口径，文档仍写「由人给出原文（agent 可代录、不得自拟）」（0008 2026-09-12 修订），但 #1674 实践已写「执行人：agent 执行」并合并成功 —— **文档落后于实践，据实追认**。
- 机检事实（现读 `.github/workflows/pr-evidence.yml:294`）：入仓产物判据 `docs/verification/<模块>/<PR号>/<页名>.<ext>` 的 `<PR号>` 段**只要求数字、不要求等于本 PR** ⇒ 窗口内后续 PR 的 ① 行引用收口批入仓截图**当下结构可过**，本 ADR 生效无需机检改动前置。

## 决策

1. **窗口定义与开关**。自本 ADR **合并时点**起，UI 改造线进入「小程序优先窗口」（生效时点与追溯口径同 0016 约束段：按合并时点判定、已合并不追溯）。窗口内每个 PR 的**主验收门 = ②**（mp-weixin 构建 + 微信开发者工具取证）；①a 降档为**按批收口跑一次**（批收口 = N03/N01 类收口 PR，如 #1670 / #1678 的角色）。窗口退出 = UI 改造线进入发版/能力面冲刺，或人裁定点名结束；**退出时按分支补跑 ①a**（一次分支收口，回到 0016 原口径）方可发版。
2. **② 的 agent 执行口径追认**。窗口内 ② 由 agent 跑 `scripts/mp-weixin-check.ps1`，「执行人」栏允许写「agent 执行」，证据**必须**由 `-PostToPr` 的 sha 绑定评论承载（先例 #1674：`MP_WEIXIN_RESULT appid=wx38c3e31b16a7ced0 … errorsTotal=0 navigation SKIP reason=navigation-api-unsupported`）。门的语义不变（入口页 + 被改页无 console error / exception；navigation SKIP 不算通过也不算失败、须照实写明）。**不加人工复核**。
3. **① 行窗口内的语义收紧与跨批引用口径**。批未收口期间：① 行只能写 `SKIP·待批收口（ADR-0039 窗口口径）`，**不得携带任何真机结论**（「未验证禁写已通过」总纪律不变）；收口批跑完后：后续 PR ① 行照实写收口读数、行内引用收口批入仓产物路径。① 的证据承载形态**不变**——仍是入仓截图、不引入评论承载（0016 裁定 4）。引用失实 = 伪证，走例外通道条款处置。
4. **窗口不动能力面与 ①b**。四类能力面触发（指纹 / 运行时权限弹窗 / 真机上传 / 厂商 ROM 交互）、①b 的**人签原文**、③④ 门判据（含临时三条件）、`pr-evidence` 校验逻辑——全部**不变**。窗口内任一 PR 触及能力面，①b 照当期触发、**不随批延后**。
5. **拆分步骤（本票合并后排期，本会话不开工）**：
   1. 机检加强票：`pr-evidence.yml` 入仓判据的 `<PR号>` 段放宽为「须等于 master 已收录的 PR 号」——**防静默假引用**（当前数字段口径下引用一个不存在的批号也能过结构校验），是窗口纪律的机检化，非本 ADR 前置。
   2. 取证工具票：`mp-weixin-check.ps1` 增加「任意页直达探针」（用 0038 决策 1 已证唯一可靠的 `pages.json` 首项临时换页 + plain launch 机制），把 ② 的取证面从「入口页」扩到「被改页逐页」——窗口主门的取证强度靠它补齐。**排期裁定（2026-10-13 /grill 人裁）：本票已立 #1682，排在批 5（N04 起）之前。配套澄清（同场裁定）：批收口 ①a 的射程本就是「该批全部改动页」（0016 验收标准 3），不是全仓逐页；全仓逐页只出现在发版前置条款（0008「发版前全量逐页冒烟」），不因此票与本窗口而放宽。**
   3. 链路票：`dev:mp-weixin` npm 脚本 + build-then-verify，堵「改完没重建、拿旧产物跑 ②」的陈旧产物黑洞。
   4. **#1655**（② 门 env-blocked 三分，OPEN）建议随窗口早期落地：② 升为主门后，环境性失败的读数频率放大，一等结果行的收益同步放大。
   5. 批 5（N04 起）按本口径试点；试点中发现的口径裂缝按「写实更正」条款就地回写本 ADR。

## 后果

- **正**：每 PR 主取证转移到全自动 ②（≈4.5 分钟/次、无人值守），①a 每 PR 一次真机的串行瓶颈放开；验收节奏与用户实际观片面（小程序）对齐。
- **负 / 代价**：真机回归滞后到批收口——窗口内若引入真机独有问题，要到收口才暴露，窗口批需预留返工缓冲；HBuilderX 单实例，② 与 ④ 门互斥 ⇒ 窗口内两者在 CI/本地串行排队。
- **接受的风险**：跨批引用的「产物-页面错配」当下无机检兜底（yml:294 只认数字段），靠文案纪律 + 拆分步骤 1 补位；收口批跑 ①a 若照出真机问题，该窗口各 PR 证据段照实改写、按例外通道处理。
- **可逆性**：窗口退出即回 0016 原节奏，无代码回滚成本；本 ADR 的回写全部是文档就地标记（0016 / 0008 / 两侧 AGENTS.md），恢复口径只需一条新修订。
