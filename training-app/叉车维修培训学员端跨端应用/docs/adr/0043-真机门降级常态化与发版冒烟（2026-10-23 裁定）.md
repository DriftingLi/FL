# 0043 - 真机门降级常态化与发版冒烟（2026-10-23 裁定）

- **日期**：2026-10-23
- **关联**：调研文档 `docs/design/20261023-省略真机验证影响与同类实践调研.md`（论据源，本文吸收其 §3.1/§3.4 并收回其 §6.2）· #1608 / #1609（32 页欠账登记票面）· map #1591（UI 改造线）

## 背景

- 实证底数：①a 的每 PR / 每批节奏已被证伪空转——近 20 个触及运行时面的合并 PR 里 5 个声明真机门、**0 个留可核验产物**（0008:72 同账），1494 实测步骤 6 的 420 秒超时零截图。病根是「全量人看不可能时，名义人看退化成没人看」。
- 0039 / 0040 设计为「临时窗口」，退出即复活每分支收口、欠账重新累积。2026-10-23 审讯会话裁定取**常态形态**：①a 永久降级为「发版前一次」，窗口机制整体退役，而不是给窗口打补丁。
- 发版冒烟不是新造义务：发布前置条款已在 0008 存在三处（正式发版前必跑云打包 + 装机自测、补一次全量逐页冒烟，一次性门），且 0039:22 已裁定「全仓逐页只出现在发版前置条款」。但它**从未执行过**（0008:519 测试期裁定，项目至今未发版）。本 ADR 把它从纸面条款变成可机检的执行设计，并让它成为 ①a 降级后的唯一落点。

## 决策

1. **①a 真机逐页取证永久降级 = 发版前一次**。每 PR / 每批的逐页真机取证取消；0039 / 0040 的窗口机制整体退役（不再有「窗口退出」事件，退出被首次发版吸收）。32 页欠账（批 4 N01 19 页 + 批 5 N05 7 页 + 批 6 N06 6 页，票面 #1608 / #1609）并入首次发版冒烟，不再是独立的退出前置。**0040 决策 5 改写**：触及能力面的 PR 合并前完成 ①b 人签即可走，不再排队等「退出」。
2. **发版冒烟绑既有发布前置条款，不建第二个触发点**。发版那一刻 = 跑云打包那一刻；「装机自测」展开为 `device-capture.ps1` 全仓逐页 + D1-D9 断言 + 分级人看（决策 5），与 ④b 同批执行。
3. **② 微信开发者工具门 = 每个运行时面 PR 必跑，从窗口口径（0040 决策 2）升为常态主门**。执行人允许「agent 执行」（先例 #1674，证据由 sha 绑定判据评论承载）。两条如实登记：① 触发判据只认三份 json 与 MP-WEIXIN 条件编译，**纯 `.uvue` / `.uts` 改动无 ② 机检兜底、靠纪律**——该脆弱性随本条永久化；② **② ≠ ①**：四类真机独有失败（`content://` 上传、生物识别、SDK 回调、性能 / ANR，0008:189）仍测不出，只能靠 ①b + 发版冒烟兜底，不得用 ② 冒充 App 端覆盖。
4. **生效顺序：本 ADR 即刻生效；冒烟脚本的机检加固是首次发版的硬前置**。加固范围：逐页重试上限 / 熔断、断点续跑、产物入库、设备状态归一（电量 / 亮度 / 通知栏；状态栏读数已有 `-IgnoreTopRows`）。依据：①a 在窗口内已零跑，ADR 先行不改变任何当下行为；加固在欠账未清、无发版触发点时没有合法的全量试跑时机，「先跑通再生效」会死锁。首次发版前若有人喊发版，必须先完成加固再发。加固属工具链改动，拆独立 PR。
5. **分级人看（替代 0040 决策 4 的「全量人看完」字面）**。人看范围 = ① 自上次冒烟基线入库以来**运行时面改动过的页**（断言过了也看——样式丑不是 logcat 报得出的）② 断言 FAIL / WARN 页 ③ 仅首次：32 页欠账全看。其余页与上次基线做像素比对放行。**比对阈值不许直接移植**：0.5% 是**同帧**标定（0008:17，#1027），跨天基线实测能把零改动树读出 0.919%（dev-loop.md:352 三条腿协议的血账）——跨发版比对的阈值待**第二次发版起用实测标定**，标定前未改页从宽转人看（保守侧错）。首次发版同时建立全仓基线截图库。人看量随改动面增长而非应用规模增长，这是 3-5 人团队看得完的形态。
6. **失败语义：FAIL 阻断发版；WARN 转人看；INCOMPLETE 同样阻断但处置指向工具**。① 断言 FAIL（页面报错 / 白屏 / 关键元素缺失）= 阻断，修复后断点续跑重测受影响页；② 像素超阈类 WARN = 转人看，看完人裁「差异可解释」放行或升级 FAIL；③ 「没测上」（脚本超时 / 设备掉线）记 **INCOMPLETE**——既不是 FAIL 也不是 PASS，阻断发版，但处置是修工具 / 修环境后续跑，不是修产品。零产物不得冒充绿（0/20 空转的病根就在这条上）。例外通道保留且只能由人开（沿用 0008「已接受未验证风险」语义 + 事后验证计划登记）。
7. **发版票制**。每次发版开一张专用 Issue：**由人开**（它是人的发版决策载体，agent 只代录），三重角色 = 发版决策记录（版本号 / 范围 / 例外放行）+ 产物归档主键 `docs/verification/device/<发版票号>/`（沿用数字段惯例，校验器现口径零改动）+ 人签汇总容器（①b 能力面签 + 分级人看结论贴这张票，机检行走 `-PostToIssue`）。首次发版票可现在立，兼当 32 页欠账的执行容器。
8. **PR 侧证据形态换措辞，低风险分层整体退役**。运行时面 PR 的 ①a 行固定写 `免（①a 降级发版前一次，ADR-0043）`（保留显式声明的审计痕迹，替代 0040 决策 1 的 `SKIP·待批收口`——那五个字从此指向不存在的未来）；能力面 PR 额外写 ①b 人签行（口径不变：白名单 `scripts/lib/capability-surface.ps1` + PR 自报，0016）。0008:116-120 的「低风险运行时面免 ①②」退役：① 半被普遍豁免吞掉，② 半被决策 3 宽触发覆盖，留着只会两处口径并存漂移。
9. **uni-automator / E2E 不碰——调研文档 §6.2 收回**。0020 的锁维持有效（不重开 E2E 通道裁决、不激活 uni-automator、不新增 E2E 门），且 0008 探针已判元素级 / 导航级断言在本机组合不可用（`mp.reLaunch` 恒 `Uncaught [object Object]`、`page.$('view')` 与不存在 class 同样超时）；物理前提未变（标准基座 47 个 .so 全 arm64-v8a vs 本机 AVD x86）。本机「省人眼」的上限就是 device-capture 的像素比对 + logcat 断言 + a11y dump，加固只补强度不补新能力。要重开 E2E 须另立 ADR 先 supersede 0020 并满足其重开前置。
10. **云真机：不做，登记候选**。重开配方：触发 = 本机设备长期不可用或发版频率显著上升；前置 = 账号登录态与费用裁定（0041 证伪的是 CI 门场景，不自动覆盖发版前人触发的用法，但逐页业务断言在云平台要重写、投入在发版频率未知下无法回收）；如实标注生物识别 / 指纹类在云机上仍测不出（机械键）。不建评估票、不占排期。
11. **①b 命中频率：不建汇总机制**。调研文档 §7 的「无记录」修正为「机检行存在但未汇总」——`dev-finish.ps1` 每次跑输出 `CAPABILITY_SURFACE touched=…` 并随判据贴 commit 评论；要数据时 gh 检索历史判据评论即可。不建台账文件：多 worktree 并发下往共享文件追加是反模式（AGENTS.md 多 Agent 纪律），且 ①b 保留的论据是机械键无替代、不依赖频率。

## 后果

- **正**：真机串行瓶颈（10-20 分钟/次 + 单实例设备）永久解除；人看变成有限、可看完的量；欠账从「窗口退出事件」变成一张具体的发版票；② 宽触发保住了每个运行时面 PR 的唯一运行时反馈通道。
- **负 / 代价**：① 首次发版前，仓内不存在任何逐页真机执行——明知而接受，不是遗漏；② ② 宽触发后连纯 `.uts` 逻辑改动也要跑开发者工具门（比旧「低风险免」多一次取证，决策 3 的对称代价）；③ INCOMPLETE 语义下设备 / 工具故障会卡发版——把「冒烟可信」排在「发版顺畅」前面的自觉选择；④ ①b 人签依赖设备在场：`23049RAD8C`（自 2026-10-14 离线）从「窗口不需要」变成**能力面 PR 合并的硬前置**，设备拉回是能力面线与首次发版的共同先决条件。
- **接受的风险**：纯 `.uvue` / `.uts` 的 ② 靠纪律不靠机检（决策 3 永久化）；App 端视觉回归在 PR 粒度无人验（发版冒烟的分级人看是其唯一落点）。
- **可逆性**：若首次发版冒烟被证明不可信，可另立 ADR 恢复 ①a 的批节奏；本 ADR 不产生不可回滚的机制。
