# 0028 - 招聘者工作区向学员端设计语言收敛：底部常驻五 tab、首页与职位管理面

**状态**：已接受（2026-09-28；来源：`/prototype` 会话对 `pages/recruiter/*` 现状「自绘壳、与学员端不共用组件」的实测 + grilling 收敛。
本 ADR **推翻** [0021](0021-移动端招聘者工作区形态.md) ② ③ 与 [0022](0022-招聘者工作区落地口径与角色化鉴权.md) ② ⑥ 的四项裁定，
**保留**其身份模型、鉴权通道与平台面。落地拆三票：T1（本文，纯 `*.md`）、T2（骨架与首页）、T3（职位管理面））

> **一句话**：招聘端页面族此前自成一套壳（顶部页内分段件 + 手写 `#2979ff` nav-bar + 右上角藏「我的」），
> 与学员端（底部原生 tabBar、`#239EDD` 主色）视觉上不同源。本 ADR 把「长得像」的东西（配色、底栏、卡片、间距）
> 向学员端设计语言收敛：**骨架结构从「顶部三段」改为「底部常驻五 tab」（首页 / 职位 / 简历库 / 交换 / 我的），
> 「我的」升为 tab**，并**新增首页**（照 web `recruit/Dashboard` 的零统计静态入口卡）与**职位管理面**（推翻 0021 ③「不做发布/编辑/上下架」）。
> 路由与契约锁按新形态重写；身份互斥、401 定向、平台面仅 Android/iOS、`#ifndef` 隔离、禁 N+1 **一条不动**。

## ① 目标与范围

把 `pages/recruiter/*` 的**视觉语言**与**导航骨架**向学员端收敛，并把功能面从「响应侧四页」扩为「响应侧 + 首页 + 职位管理面」。
**骨架不动的边界**：只改「长得像」的东西（配色 / 底栏形态 / 卡片 / 间距），不改后端、不改数据契约的字段语义、不改鉴权模型。

现状锚点（现测，2026-09-28）：
- `pages/recruiter/components/recruiter-tab-bar.uvue` 是**顶部页内三段件**（职位 / 简历库 / 交换），选中态 `border-bottom-color: #2979ff` + 字色 `#2979ff`；
- 「我的」`pages/recruiter/me.uvue` 是**二级面**（`navigateTo` 推入），挂在各一级面导航栏右上角（`uni.navigateTo({ url: '/pages/recruiter/me' })`）；
- 招聘端**没有**首页——登录成功后 `reLaunch` 直接落到职位段（`pages/recruiter/jobs`，见 `recruitWorkspaceContract` H 段）；
- 全仓主色：学员端 tabBar `selectedColor: #239EDD`（`pages.json`），招聘端自绘件用 `#2979ff` —— 两套蓝，视觉不同源。

**为什么是「现在」**：0021/0022 于 **2026-09-20** 裁定，本文于 **2026-09-28** 推翻，间隔**八天**。
这八天里 P1/P2/P3 三票已把「顶部三段 + 响应侧封闭」落成真码并过了真机门（#1194/#1195/#1196）。
推翻不是「当初判错」，而是**维护者见到成品后的新判断**：三段顶部件与右上角「我的」在实际使用中读出来「就是不像学员端」，
且缺首页让招聘端与学员端的入口结构不对称。理由写在这里，别让未来读者猜（见 ② 逐条）。

## ② 选型 + 一句理由（推翻项与被推翻裁定逐条对齐）

### 推翻项

- **导航骨架：顶部页内三段 → 底部常驻五 tab（推翻 0021 ②「独立页面栈、无 tabBar」+ 0022 ②「页内常驻分段、首页即职位段」）**
  —— 学员端 5 tab（首页/课程/AI学/交流/我的）已成事实标准形态；招聘端要「同构」，就得同样数 5 个、同样落底部、同样把「我的」做成 tab 而非右上角二级入口。
  **形态 = 自绘底栏组件常驻底部**（`recruiter-tab-bar.uvue` 从顶部三段件**改写**为底部五 tab 件，白底 / `#239EDD` / 图标 + 文字 / 交换徽标）——
  **不是**开系统 `pages.json` 原生 tabBar：学员端已占满微信小程序 5 tab 上限（0021 ② 的原约束仍在），且 0022 ③「不做 `tabBar.custom`」仍成立。
  底栏是**全仓唯一一份**共享件（0022 ②「唯一一份」纪律不变），五面（首页/职位/简历库/交换/我的）各挂一次，面间 `redirectTo` 换面不堆栈。
  **旧顶部分段件直接删除**，不「退休并存」——并存会制造两份长得不一样的栏，正是 ADR-0009 的病根。

- **职位面：只读 → 完整生命周期（推翻 0021 ③「不做职位发布 / 编辑 / 上下架」+「移动端看到的职位全部来自 web」）**
  —— 与维护者「功能参考前端」的诉求直接冲突：web `recruit/JobManage.vue` 就是发布 + 编辑 + 上下架，招聘端若只读，首页「职位管理 / 发布位」快捷入口就没有落点（会变成 0021 ⑥ 判的「看起来能用、用了必失败」的空壳）。
  T3 落职位列表卡内联动作（编辑 / 上下架，`forced_offline` 隐藏「上架」）+ 全屏 `job-edit.uvue`（8 字段，职位名 + 岗位必填，描述上限 5000）。
  **依赖后端已存在的写端点**（`POST /recruit/jobs`、`PUT`、`toggle-status`），本票**不动后端**、不改 DTO；契约锁 E 段「零发布/编辑入口」随本推翻**改写**为「存在发布/编辑入口，但字段与措辞与 web 同源」。

- **「我的」：二级推入页 → 一级 tab（推翻 0022 ②「『我的』= 导航栏右上角常驻入口 → 推入页」）**
  —— 「我的」升 tab 是「像学员端」的第二实测点（学员端「我的」就是第 5 个 tab）。
  **但 0022 ② 那条「不给『切换到学员登录』入口」保留**：互斥的价值是「不可能同时是两个身份」，tab 化的「我的」只是把退出 / 账号信息挪到底栏，不新增身份切换开关。

- **首屏请求账本：2 → 首页首屏 1 批量请求（改写 0022 ⑥「招聘者态首屏批量请求 = 2」）**
  —— 新增首页首屏只打 **1 个批量请求**（`GET /recruit/contact-requests`）喂紧迫行 + 快捷入口徽标；欢迎卡与账号信息用本地登录态（`stores/auth`）投影，**零统计**（照 web `Dashboard.vue`，它本就零 api）。
  **职位列表由职位 tab 自己拉**（`redirectTo` 换面本来就要重进页面，不存在「首屏替职位段预取」的浪费）。
  **禁 N+1 条款原样保留**（0021 ② / 0022 ⑥）：不逐职位拉 `unread_count`，不新增 `/recruit/summary`。

### 保留项（明确不动，逐条给锚点）

- **身份互斥**：`auth_active_role`（`student|recruiter`）、登入任一方清空另一方（含 `auth_secure_credentials`）—— 0021 ② / 0022 ② 原样。
- **401 定向**：`handleUnauthorized()` 仍是**唯一** reLaunch 出口，出口内按角色选目标 —— 0022 ②「出口对称性」补充约束原样，招聘者登录页的 `clearIdentityForSwitch()` 早于 `reLaunch` 顺序不变。
- **平台面**：仅 Android/iOS 发布，小程序端不发布但仍会打包招聘页（源码级 `#ifndef MP-WEIXIN` 守卫）—— 0021 ② / 0022 ② 原样。
- **不开创 `pages.json` 条件编译先例** —— 0022 ② 原样。
- **禁 N+1**（`fillApplyStates` 单次批量 join 先例）—— 见上「首屏账本」，条款本身不动，只是消费它的面从「职位段」挪到「首页 + 职位段各自」。
- **`pages.json` / `manifest.json` / `platformConfig.json` 不自行提交** —— 0022 ⑤ 纪律不变；T2 新增首页注册由**人**提交。

### 视觉收敛口径

- **主色**：招聘端自绘件的 `#2979ff` → **`#239EDD`**（学员端 `pages.json` tabBar `selectedColor`），逐文件替换样式块。
- **底栏视觉**：白底、选中 `#239EDD`、图标 + 文字（对齐学员端原生 tab 的读感）；交换未过期 pending 徽标保留。
- **卡片 / 间距**：向学员端 dashboard 的卡片圆角与外边距靠拢；**骨架结构（scroll-view 承载、`navigationStyle: custom`、`useStatusBarHeight`）不动**。

## ③ 明确不做的事

- 不改后端（零新增端点、零 DTO 字段变更）；不改 `pr-evidence.yml` 判据。
- 不开系统 `pages.json` 原生 tabBar、不做 `tabBar.custom`（底栏 = 页内自绘常驻件）。
- 不保留旧顶部三段件（删除，不并存）。
- 不给招聘者「切换到学员登录」入口（互斥语义不动）；不复活 `components/app-tabs` / `app-nav-bar` 死件。
- 首页不做任何统计聚合（照 web Dashboard 的零统计静态卡）；紧迫行只吃 `contact-requests`。
- 不引入条件编译到 `pages.json`；不做分包（分包另见 ⑤）。

## ④ 拆分步骤（三票，各自 PR）

1. **T1 · 决策文档（本票）** —— 新增 ADR-0028；0021/0022 状态行加指向注记；`CONTEXT.md`「招聘者工作区（移动端）」词条从「只做响应侧、不含职位发布」改为「响应侧 + 首页 + 职位管理面」。**免四门（纯 `*.md`），可立即合并。**
2. **T2 · 骨架与首页** —— `recruiter-tab-bar.uvue` 顶部三段件**改写**为底部五 tab 件（唯一一份、五面挂载、学员端视觉）+ 职位/简历库/交换三面改挂底栏 + `me.uvue` 升 tab + 新增首页 `home.uvue`（欢迎卡 + 紧迫行 + 快捷入口，首屏 1 请求）+ 删除旧顶部件 + `recruitWorkspaceContract.test.js` 判据重写（挂载面 3→5、分段件不存在、首屏 2→1、登录落点 `jobs`→`home`）。命中运行时面（`*.uvue`/`*.uts`）：**①a 逐页截图 + ② + ③ + ④**。
3. **T3 · 职位管理面** —— 职位列表卡动作升级（编辑 / 上下架内联，`forced_offline` 隐藏上架）+ 全屏 `job-edit.uvue`（8 字段、职位名 + 岗位必填、描述 5000）+ `api/recruit.uts` create/update/toggle + 首页发布位入口点亮。依赖 T2。命中运行时面同 T2；**不命中能力面**（无上传 / 指纹 / 运行时权限弹窗）。

依赖：T2/T3 都依赖 T1 先落（契约锁重写的依据）；T3 依赖 T2（发布位入口挂在 T2 首页上）。

## ⑤ 约束与已知代价

- **主包体积**：T2/T3 新增 `home.uvue` / `job-edit.uvue` + 底栏件，且小程序端仍打包招聘页（不发布但仍进产物）。
  **接受扩面，但把「量」写进验收** —— T2 落地后跑一次微信小程序构建实测主包体积并留证据；**若逼近上限，另立票做分包**。
  分包前提引 0021 ⑤：「若日后要做分包，须先现测 uni-app-x 在 App 端的分包支持度」——本 ADR 不开分包，只留话头。
- **契约锁改写方向**：`recruitWorkspaceContract` 的挂载面集合（`FIRST_LEVEL`）由 `{jobs, resumes, contacts}` 扩为 `{home, jobs, resumes, contacts, me}`；
  二级面（`SECOND_LEVEL`）收窄（`me` 升一级，仅 `applications` 留二级）；B 段首屏请求由 2 改 1（禁 N+1 断言原样保留）；
  H 段登录落点由 `/pages/recruiter/jobs` 改 `/pages/recruiter/home`。**改写不是删锁**：每条都要落到新形态的可机械核验判据。
- 招聘端 `#2979ff` → `#239EDD` 是**视觉值**替换，不进任何状态词表 / 不触契约 F 组同源对账。
- 移动端 ADR 独立编号（本仓 `0001` 起）；本文不引用、不修改根仓库 ADR 编号体系。

## ⑥ 验收标准（断言行为，不断言源码文本）

- 五个一级面（首页 / 职位 / 简历库 / 交换 / 我的）渲染**同一个**底栏件；全仓**仅此一份**；旧顶部三段件不存在。
- 首页首屏批量请求 = **1**（`/recruit/contact-requests`）；**不逐职位拉 `unread_count`**（禁 N+1 原样）。
- 移动端**存在**职位发布 / 编辑 / 上下架入口（推翻 0021 ⑥ 的「不存在发布入口」），字段与必填口径与 web `JobManage` 同源。
- 招聘端主色为 `#239EDD`（不再出现 `#2979ff`）。
- 身份互斥、401 定向、过期 pending 无操作入口 —— 0022 ⑥ 对应各条**保持不变**。
- T2 微信小程序构建主包体积实测已留证据（数值，非「应该没超」）。
- `pr-evidence.yml` 的改动量 = 0。
