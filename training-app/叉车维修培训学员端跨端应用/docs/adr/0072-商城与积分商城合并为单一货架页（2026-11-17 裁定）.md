# 0072 - 商城与积分商城合并为单一货架页（2026-11-17 裁定）

> 状态：已采纳（2026-11-17，#2617 实施同批写入）｜来源：spec #2608（反转 #2518 Q8「两路由不合并」）｜**职责边界**：只定页面与路由形态，不改后端读模型、不动鉴权与积分结算。

## ① 目标与范围
`pages/mall/mall`（课程货架）与 `pages/points/points-shop`（积分商城）是两个入口做同一件事：找可兑换的东西。合并为单页四态左栏，入口收敛到 `tab` 查询参数。

## ② 选型 + 一句理由
- **单路由保留 `/pages/mall/mall`**，`points-shop` 从路由表删除、不做兼容重定向——两条路由各带一份筛选与三态，合并的收益就是删掉这份重复。
- **左栏四态 MECE**（热门 / 课程 / 图书系列 / 积分兑换）**按商品类型切、不按数据源表切**；热门 = 课程前 6 + 积分商品前 6 + 两条「查看全部」。
- **课程分区放全部课程**、不按积分价过滤：积分价可能为 NULL（迁移 #2447 只给 course_id = 5 赋 100，真实定价由管理端表单逐课设置），按价过滤会把没定价的课整段藏掉。
- **客户端两源拼装**：课程分区用课程列表动词、积分商品分区用商品列表动词，热门与积分兑换在客户端拼装——比新增一条后端 union 读模型的维护面小得多。
- **排序栏退役**：四档排序无后端参数支撑，排序是假象；搜索能力移到悬浮按钮。

## ③ 明确不做的事
不改积分结算与兑换接口（服务端裁定、不预扣）；不动 `AI_PRO_SKU` 落点判定；旧路由不做重定向与灰度；筛选只留「积分范围」三档（另设「不限」复位档：控件只在这两个含积分商品的分区可见，没有它选完区间就没有回头路），形态是一排常驻胶囊、不是下拉面板——无展开态、无蒙层，切分区高度天然不跳。

## ④ 拆分步骤
T1 #2617 预重构（行为不变：状态下沉 useMall + 六件拆出）→ T2 #2618 四态骨架 + tab 深链 → T3 #2619 积分商品分区 + 单筛选 + 排序退役 → T4 #2620 入口收敛 + 文案统一 → T5 #2621 旧路由下线 + 契约迁移。

## ⑤ 约束
页面壳层零自持状态（`ref`/`reactive`/`computed` 落 composables 并进显式结果类型）；单文件 ≤600 行、目录 ≤2 层（`utils/modules.js` 声明面执法）；余额卡常驻全分区。

## ⑥ 验收标准与实测
每票过 ③ 两腿 + ④ 全门；T5 收口后路由表无 `pages/points/points-shop`、唯一商城入口为 `tab=points`。**部署库课程积分价的真实分布未测**（本机无可连环境，见 #2617 正文）⇒ 本篇以「价可能为空」为设计前提，不据此断言货架是否全免费。
