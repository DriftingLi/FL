# 0037 - 分页信封归一：api 层响应解码的单一出口

> 状态：已接受 ｜ 2026-10-12 立 ｜ 来源：#1659（architecture review K3 → Design It Twice 三方案对比 → 本 ADR 收口）
> **一句话**：移动端 `api/*.uts` 有 81 处各写一遍「信封解码」（数组键名 `items`/`records`/`materials`/`courses` 各域不一、
> 分页字段 `pages`/`page_size` 混读、`api/forum.uts:343` 与 `api/forumDto.uts:202` 已把 `pages` 读进 `page_size` 槽位）。
> 本 ADR 裁定收成单点模块 `api/envelope.uts`（**方案 A3**），键名知识留在各域文件里声明，解码算法只写一遍。

**① 目标与范围**：归一 **分页列表信封**与**纯数组信封**的解码出口：`Page<T> = { items: T[], total: number, hasMore: boolean }` +
`getPaged<T>(url, page, pageSize, toItem, query?, keys?)` + `decodePage<T>` / `decodeList<T>`。替代面 = 81 处手解码
（24 处分页、25 处纯数组、其余为键名回退链）。**键名不进模块**：keys 由调用方逐域声明（默认 `['items','list']`，
`list` 是 `api/request.uts` 对裸数组的既有包装）；分页字段**只认 `total`**，`pages` / `page_size` 一律不读——
`pages→page_size` 误读家族因此**在结构上不可表达**，而不是逐处修。

**② 选型 + 一句理由**：三方案对比（Design It Twice，全文见 #1659）——**A1 中央键名表**（模块持 ~30 行 url→keys 表，
跨端与根仓库 ADR-0056 对账）：键名集中一处，但成为多会话并发改同一文件的冲突面，否；**A2 八槽描述符 + 解释器**：
表达力最强，但现网异形只有键名一维，描述符是超前设计，降级为重开条件（见 ③）；**A3 调用方声明键名**：把「键名差异」
留在领域文件（每域本来就最清楚自己的键），模块只收编「解码算法」，深度与局部性双优，**取 A3**。`hasMore` 单一三级算法：
`total` 存在 ⇒ `page*pageSize < total`；否则 `items.length == pageSize`；空批次 ⇒ 假。`total` 缺失 ⇒ 回落 `items.length`
（与 `api/note.uts:37` 同）并打 `[envelope] no-total <url>`；keys 全落空 ⇒ 打 `[envelope] no-hit <url>`（console.warn，
**不 reject**——见 ③）。泛型可编译性由 ④ 门证（先例 ADR-0027 PR1 的 `PagedBatch<T>`）。

**③ 明确不做的事**：不做中央键名表（A1 已否，理由见 ②）；不上描述符解释器（A2 仅当出现键名/分页字段之外的**第三维异形**时重开）；
不建新错误协议、**不 fail-loud reject**（信封形状不符只 warn）——现网 `.catch → 空页` 吞错面（`api/forum.uts:361/378/395`、
`api/mockExam.uts:259-268`、`api/aiAssistant.uts:163-165`）会把新错误静默吞掉，这些吞错点随本 ADR 迁移**同批删除**；
不改 `api/request.uts` 的信封裁定（`{code,message,data}` 双校验、`data:null → {}`、裸数组 → `{list:[...]}`、`403:`/`404:`
message 前缀协议原样透传）；不动 `usePagedList` 的 `{items,hasMore}` 契约（ADR-0027 已锁）；不合并 `Page` 与 `PagedBatch`
（6 个页面要 `total`）；不设豁免 allowlist（ADR-0023 决策⑧）。

**④ 拆分步骤**（批次顺序，子票挂父票 #1659）：
1. **PR-A**：`api/envelope.uts` 本体 + 行为守护 `utils/envelopeBehavior.test.js`（成对取证：必不红对照 + 必红变异含
   forum 误读复现）+ 棘轮 `utils/envelopeAdoptionContract.test.js`（api/*.uts 内 `['total']|['page_size']|['pages']`
   索引读计数只减不增，双向精确对账，无 allowlist，定义文件排除；基线 = 现测值）+ 登记 `utils/modules.js`
   `INFRA.files` + **forum 缺陷位首刀**（`api/forum.uts` 误读站点迁移，同批删 `:361/378/395` 吞错点）——
   首迁站点同 PR（⑤ 约束）；modules.js 改动 ⇒ **失低风险豁免 ⇒ ①a + ② 必跑**（ADR-0027 PR1 同因），
   同 PR 的 .uts 迁移不额外加门。
2. **PR-B**：机械迁移——键名直读 `items` 的 14 处分页站点（course 打头，同批删 `api/course.uts:449-457` 错误回填
   mock 数据，兑现根 ADR-0065⑥）+ 25 处 `decodeList` 纯数组站点（计数以现测为准）。
3. **PR-C**：具名键站点（`materials`/`records`/`courses` 4 处，keys 显式声明；`api/forumDto.uts:202` 的
   `pages→page_size` 误读在此消亡——`decodePage` 只读 `total`，该误写在结构上不可再表达）。
4. **PR-D**：兜底链 + 四类异形——`??` 回退链站点（favorite/questionInteraction/mockExam 等）收敛为单一 keys
   声明；search 五分区、侧计数器 `unread_count`/`job_title`、嵌套父列表 `api/forumDto.uts:214-274`、不回显分页
   字段的端点 `api/recruit.uts:635-651`：装得进的迁，确实装不进三出口的保留手解码——只要不索引读
   `total`/`page_size`/`pages` 就不入棘轮计数（**无白名单**，见 ③）；`api/mockExam.uts:259-268` 吞错点同批删。
   已执行（#1664，15 处载体迁出、棘轮 27→12、吞错点删除）：**两个坑位留给后续批次**——① 棘轮 `CARRIER_RE`
   对 `api/*.uts` **全文计数含注释**，迁移注释里写出被计数键的字面量会被算成载体（改述为「响应回显的每页大小」）；
   ② 出口闭包要给 `decodePage` 传 `url` 时**提 `const url` 复用**，勿在 `getMapped<…>(…)` 后再写一处同字面量——
   `credentialScopeContract` 钉的是内联首参、`examContract` 幻影路由锁按字面量计数，重复即红。
5. **PR-E**：裸 `get/post/put/del/patch` 出口收口至 mapper 家族（checkin/questionInteraction/recruit/aiAssistant
   等；父票记 29 处，现测为准；`uploadFile` 与无载荷 void 出口不拆信封、不收口）；`api/aiAssistant.uts:163-165`
   吞错点同批删。
   已执行（#1665，28 处载荷出口收口：recruit×12 / aiAssistant×8 / questionInteraction×5 / checkin×2 / note×1；
   `.catch(() => [])` 吞错点删除，页面侧 try/catch 兜底现测在位；棘轮 12 不动——本批全为纯 DTO 出口，无载体迁出）：
   ① PUT/PATCH **不加便捷面**，经 `requestMapped` + `opts.method` 同通路（先例 `credential.uts`/`auth.uts`，
   本批新增 `note.uts`/`questionInteraction.uts`/`recruit.uts`/`aiAssistant.uts` 四处）；checkin 两出口的
   `.catch(errMsg 重抛)` 非吞错点，原样保留挂在 mapped 出口上。② **一个坑位留给后续批次**——收口 `get(url, null, opts)`
   时 `opts` 必须经 `getMapped` 的**第 4 参**原样透传：`silent` 是「403 预期分支不弹 toast」的唯一载体，漏传静默改变
   错误通道行为；只钉 `const opts` 声明行的接线守护是盲位（首轮迁移漏传第 4 参仍绿，`recruiterResumeBehavior` B2
   已升级为行为断言：替身记录第 4 参 + `options?.silent` 必真）。
6. **PR-F**：清尾——`types/*.uts` 12 处 `page/page_size/pages` 声明删除、2 处页面侧重命名
   （`pages/profile/records.uvue:189-194` `result.records`、`pages/resources/materials.uvue:95-101` `data.materials`）、
   吞错点复核清零、棘轮基线下调至 **0**。可并行的只有 B/C/E 内部各站点；A→B→C→D→E→F 串行（棘轮基线逐批下调）。
   已执行（#1666，棘轮 12→0）：① 声明面按现测清空——16 个 DTO 删 `page`/`page_size`/`pages` 三字段，3 个 DTO
   （`PointsLedgerResult`/`WrongQuestionListResult`/`RecruitContactRequestListResult`）整型删除（无消费方/
   改为 `Page<T>` 出口）；`ForumTopicDetail` 与 `SearchPagedResult` 的 `page`+`pages` 换成 `hasMore : boolean`
   （`decodePage` 依 `total` 推导，替代面 `hasMoreReplies` 由 `replyPages` 数值比较改布尔）。② 两处页面侧重命名落地：
   `records`/`materials` 两类出口改走 `getPaged`（keys 仍逐域声明 `['records']`/`['materials']`），页面读 `.items`
   ——键名知识留在 api 域文件，页面**不再感知后端数组键名**。③ 吞错点复核：`api/student.uts` 的
   `getMockRecords()` 失败回填假数据（日志 `using mock data`）删除，改 `throw`（与 ADR-0065⑥ 同一条纪律）。
   ④ **终态判据必须改口径**（见 ⑥）——原「`total` 索引读为 0」**不可达**：`api/*.uts` 内还剩 5 处读的是
   **非信封的 `total`**（打卡天数、积分任务目标值、练习统计总数、错题总数），后端这 4 个端点**没有同值备选键**
   （逐端点核过 `backend/internal/{checkin,points,practicemode,wrongquestion}/*.go` 的 DTO + swagger），
   `practice-mode/progress` 虽有 `pool_total` 但语义是「实时池总数」而非「上次会话长度」；请求侧另有 2 处
   `page_size` **写位**（`buildFilterParams`）。放宽为一个能过正则的形态（把索引写改写成对象字面量）属钻空子，
   不取。⑤ 与 #1664 诊断给的「已定口径①」**字面相反**、按实测执行并在此留痕：`api/practice.uts` 的
   `total_practiced` 原三级回退是「幻影 `total_practiced` → **真实 `total`** → 他端点 `total_count`」——
   该端点（`GET /practice-mode/stats`）后端 DTO 只有 `total`/`correct`/`wrong`/`accuracy`/`by_type`，
   `total_practiced` 在 `backend/**/*.go` 零命中、`total_count` 属另一端点（`/practice-mode/practice-stats`）。
   故收敛为**直读 `total`**（不是「保留 `total_count` 回退」：那会读一个本端点永远不回的键）。
   ⑥ `practice-mode/progress` 的 `total` 改读 `pool_total`（#1666 裁定：该值唯一消费方是模块题量显示，
   实时池总数比「上次会话数组长度」更贴用途），`buildPracticeProgress` 因此不再索引读 `total`。

**⑤ 约束**：形态同 ADR-0027——显式类型声明、函数成员箭头包裹（`utils/utsAndroidCompile.test.js` 在守）、花括号 import
（`utils/utsHarness.js` fail-closed）；**不 import composables**（依赖方向 api ← composables）；解码器**无 try/catch**、
mapper rethrow 原样上抛（`utils/requestOutletContract.test.js` 在守）；`403:`/`404:` 前缀协议与手动映射（ADR-0003）不动；
导出面用 ④ 门机检：`fun <T> getPaged` / `open class Page<T>` 真出现在导出清单（**先问覆盖**：无消费方时 Kotlin 全程序包
读不到本模块——首迁站点必须同 PR，重演 ADR-0027 PR1「绿了但没覆盖」教训）；`getPaged` 只收编 GET（POST 分页现网 0 站点，
出现时走 `postMapped` + `decodePage`，不加 `postPaged`）。

**⑥ 验收标准**：③ 门——行为守护**真执行**模块（`utsHarness.loadUts`）且成对取证，棘轮双向精确、无 allowlist（判据同
ADR-0027 ⑥：接线守护不构成 ③ 证据；新增守护答 `docs/agents/guards.md` 末节三问）；④ 门——`build:kotlin-all`
`errors=0` 且导出面含 `getPaged` / `Page<T>`；①②——PR-A 常规运行时面照跑，页面迁移批（PR-B 起）随页面改动照四门。

**终态判据（PR-F #1666 修订，取代原「三键索引读全 0」）**——原判据把两类**非信封**载体也算进了分页棘轮，且它们
在后端没有同值备选键，`0` 在「一手交真值、一手不钻正则空子」的前提下不可达。改判据为**三个方向同时锁**，
均在同一份 `utils/envelopeAdoptionContract.test.js` 内两向对账（读多了红、读少了也红）：

1. **分页字段索引读 = 0**：`['page_size']` 与 `['pages']` 的索引**读**在 `api/*.uts` 内必须为 **0**（`api/envelope.uts`
   为判据定义处，排除；`decodePage` 只读 `total`，故 `pages`/`page_size` 的读位没有任何合法形态）。
2. **`total` 读按「函数级域统计」逐处登记**：`['total']` 的索引读只允许出现在登记表内的函数里（每条带一句
   「为什么这是域统计而非信封」），现测 5 条：`buildCheckInResult`、`buildCheckInCalendarResult`、
   `buildPointsTaskItem`、`buildPracticeStats`、`buildWrongQuestionStats`。**登记按 `文件#函数.键` 比对，不按行号**
   （行号随编辑漂移），且**不设文件级豁免**——登记的是函数而不是文件，是为了让同一个文件里新增的 `total` 读仍然变红。
   判据自检：`total` 参与分页 `hasMore` 推导的形态只允许存在于 `api/envelope.uts`（定义处）——一旦有人把
   `page*pageSize < total` 抄回 `api/*.uts`，第 2 条会以「未登记读位」红。
3. **写位按「请求参数」登记**：`['page_size']` / `['pages']` 的**写**（`=` 左侧）另立登记表（现测 1 条：
   `buildFilterParams.page_size`）。**禁止**把索引写改写成对象字面量来绕判据——那是把写位藏起来，
   审查时反而看不见（写位白名单比隐藏更诚实）。

补充判据：`forum` 误读家族（`pages` 读进 `page_size` 槽位）零命中——`decodePage` 只读 `total`，该误写在结构上
不可表达，故只需断言 `api/forum*.uts` 不含 `pages` 索引读（并入第 1 条）。验收证据段按 PR 各自改动集如实填写。
