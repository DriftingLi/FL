# 0070 - 讲师端并入学员端应用与移动录课形态（2026-11-13 裁定）

> 状态：**暂定**（2026-11-13，#2490 立、#2502 改判载体为小程序端；实施未启动、⑥ 四条待实测未过，验证通过后再转「已采纳」）｜来源：地图 #2485 / 规格 `docs/design/20261113-导师移动录课上传-文件库-章节审核规格.md` / 调研 `docs/design/20261113-导师移动端录制能力调研.md`｜**职责边界**：只裁移动端载体、录制形态与上传时机；身份鉴权沿 `0021`/`0022`，分片契约归 #2487，先审后发归 #2488。术语 canonical 是**讲师**（根 `CONTEXT.md`），「导师」为历史别名。

## ① 目标与范围
讲师用手机录课并上传课程视频：录 → 选片 → 分片上传入库 → 挂接章节。只回答两件事：落在哪个壳里、录制能力边界在哪。

## ② 选型 + 一句理由
- **载体 = 并入学员端小程序作第三登录身份（讲师）**：独立登录页 + 独立页面栈、不进 tabBar（5/5 已满），入口 = 学员登录页底部（镜像 0021/0022）。理由：讲师 <20 人、每人每周 1–3 次，亏不起第二套基座/上架/验收门；小程序打开即用，讲师不必装 App。
- **录制 = 系统相机录，小程序只选相册视频**（`chooseMedia` sourceType=album）：系统相机无时长限制、画质与防抖最好、零开发；小程序内 `camera` 录制被否——`startRecord.timeout` 社区实测上限约 5 分钟、切后台 5 s 即断，出不了 10–15 分钟段。
- **产物 = 一段一文件、一节多段**：客户端无合并 API，成片合并归服务端转码（未开票）。
- **体积 = 选片后 `uni.compressVideo(bitrate≈2500, resolution≈0.75)`**，单文件 ≤2 GB 兜底；小程序端压缩能力待实测，不可用则跳过压缩只做 ≤2 GB 检查。
- **上传 = 前台分片**（`getFileSystemManager.read` + `uni.request` 传 `ArrayBuffer`）：队列 + 防息屏 + 断点续传 + 回前台恢复；不做后台上传（无官方能力）。
- **第一阶段范围**：选片/压/传 + 文件库列表·改名·删除·挂接章节；章节 Markdown 编辑留在 Web 讲师端。

## ③ 明确不做的事
不做独立讲师 App、Web 响应式录制、H5 讲师端；**不做小程序内 `camera` 录制**（5 分钟硬顶 + 切后台即断）；**不开第二个小程序**（平台允许一主体多号，但等于第二套上架/审核/域名白名单/发版/验收门）；不做段内剪辑/段合并/后台上传；不重启 ② 门（#2320 已退役）。

## ④ 拆分步骤
1. ADR + 调研笔记入仓（#2490/#2502）。2. 讲师身份接线：角色常量、登录页、`loginPathForActiveRole` 第三分支、页面守卫（镜像招聘端，C2「唯一 reLaunch 出口」不动）。3. 选片页：相册选视频 + 段列表草稿。4. 压缩 + 分片上传队列。5. 文件库与挂接章节。6. 页面落 `pages/tutor` 分包（同 `0066`）。

## ⑤ 约束
主包实测仅余 26,364 B（1,546,500 / 1,572,864 B 预算线）⇒ `pages/tutor` 必须切普通分包；`pages.json` 零条件编译先例（`0022`）不开创；小程序切后台 5 s 断传、30 分钟销毁，上传必须前台 + 断点续传；`uploadFile` 单次有体积上限，必须走分片；2 GB 硬线下 1080p30 8 Mbps × 30 分钟 ≈1.76 GB。

## ⑥ 验收标准与实测
待实测（实施前置，不得写成已验证）：① 小程序端 `compressVideo` 是否可用及产物编码；② `chooseMedia` 选相册视频的体积/时长上限；③ 切后台/锁屏上传是否中断；④ `<video>` 能否播 >100 MB 文件。验收：讲师登录 → 选 10 分钟视频 → 压缩 → 分片上传入库 → 挂接章节 → Web 文件库可见；上传产物 `main` ≤1,572,864 B。
