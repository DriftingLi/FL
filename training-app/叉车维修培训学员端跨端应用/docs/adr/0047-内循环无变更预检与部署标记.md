# 0047 - 内循环无变更预检与部署标记

**状态**：已接受（2026-10-27，来源：#2027 内循环时间账调研；证据 = `.ci-verify` 累积的 12 轮 `HX_RUN` 机检行 + 双轴 `/code-review` 两轮 + 一条先红后绿的行为断言）

> **一句话**：`hx-run.ps1` 在**取锁之前**用 git 判一次「有没有活」——上一轮部署成功且 HEAD 与跟踪文件都没变 ⇒ 秒级 `exit 2` 并打印放行理由，取代实测吃掉总墙钟过半的那类白等；判据文件只编码 `headSha`，**不含设备身份**，这条边界写进代码与本 ADR，不靠脚本猜。

## ① 目标与范围

**目标**：消除一条被实测确认的浪费 —— 「代码没变又跑了一遍」时，`www` 目录 mtime 不前进 ⇒ 部署判据说「未部署」⇒ 白等满 `-TimeoutSeconds`。逐轮数字、占比与归因的**唯一真源**是 `docs/agents/dev-loop.md`「时间账与三样慢」，本 ADR 不复述（见 ⑤）。

**范围**：`scripts/hx-run.ps1` 的日常内循环路径 + 新增 `scripts/lib/hx-noop.ps1`（纯判定 + 写标记）+ 两条守护（接线 `utils/hxNoopContract` / 行为 `utils/hxNoopBehavior`）。

**不含**：门语义与触发面（ADR-0008）、④a 全量的选档（ADR-0046）、编译本身的墙钟、设备身份的判定、`-Clean` 与任何门的默认值。

## ② 选型 + 一句理由

| 决策 | 一句话理由 |
| --- | --- |
| **判据只用 git（`HEAD` + 被跟踪文件的改动），不探设备侧事实** | 取锁前探设备要调 adb；而 `www` mtime **正是这次误判的来源** —— 拿一个"没前进"的量去证明"不需要跑"，是循环论证 |
| **预检排在 `Wait-HxFree` 之前** | 无活时连锁都不取，不占用单实例串行资源；契约测试 C7 只约束「派发 cli 必须在忙检测之后」，本预检不派发任何 cli |
| **结论仍走 `exit=env` + 机检行，不新增第四种出口** | C5 只认 ok / fail / env 三个出口，加第四个会外溢到所有消费方。**代价如实记**：跳过会抬高 `exit=env` 的分母 ⇒ 判读看**时长**不看条数（`dev-loop.md` 同名段） |
| **拿不准一律放行（`Noop=$false`）**：标记缺失 / 读不出 / 缺 `headSha` / git 不可用 / HEAD 取不到 / **`git status` 自身失败** | 失效模式不对称：错判"有活"最多白跑一轮；错判"没活"会**静默跳过一次真需要的部署**。git 的退出码在这里可信，与 C6「HBuilderX cli 退出码恒 0」不是同一件事，注释已写明防回改 |
| **与 ADR-0046 第 5 条不矛盾** | 0046 拒绝的是把**选档**交给脚本 —— 选错不留痕。本预检每次跳过都留三处痕（机检行 `exit=env`、日志 `[noop] <Reason>`、`Reason` 里写明依据哪个 HEAD），且 `-Force` 与"删标记文件"两条退路都是即时的。**留痕 + 可即时绕过**才是 0046 那条原则的实质，不是"能不能进脚本" |
| **文档落点：数字只写一处**（`dev-loop.md`），`AGENTS.md` 与脚本注释只留指针 | 复审实测：同一份测量被抄进 4 个文件并**已经漂移**（`45–161` vs `45–287`）。这正是根 `AGENTS.md` 记的那类「抄写→漂移」 |

## ③ 明确不做的事

- **不做** TTL / 陈旧判定。标记里的 `ts` 只作取证与人工排查用，**没有读者**；一旦让它参与判定，就引入"多久没跑算过期"这个没人能负责的第二判据。
- **不探**设备身份（序列号、App 是否还在）。见 ⑤ 的已知边界 —— 用 `-Force` 承接，不用第二个自动判据去补。
- **不新建**只读源码文本、却声称在守行为的守护。编码 pin（三处 `-Encoding utf8`）因此**故意不设守护**：本仓 CI 跑 pwsh 7，`Get-Content` 已默认 UTF-8，任何这类守护都是无判别力的永绿。理由写在代码注释里，而不是伪装成测试。
- **不改** `compile-check.ps1` 的 `-Clean` 默认值（门必须干净重建才可复现）。
- **不把**「无变更不裸跑」写进 `AGENTS.md` 三层节奏表：该层有硬预算（`utils/agentsLayeringContract.test.js` L1，上限 16000，**量的是 `String.length` 不是字节**），现值余量个位数；判据既然已落进代码，就不该为一句措辞去挤预算。`AGENTS.md` 已有的指针指向 `dev-loop.md`，够用。

## ④ 拆分步骤（★ 可并行）

1. ★ 纯判定与写标记落 `scripts/lib/hx-noop.ps1`（不内联，才能被运行期断言）。
2. ★ `hx-run.ps1` 接预检：排在 `Wait-HxFree` 之前、成功路径之后写标记；加 `-Force`。
3. ★ 日志表头从「截断」挪到预检之后 —— 否则每次跳过都把上一轮完整日志抹成表头 + 一行 `[noop]`。
4. 行为守护 `utils/hxNoopBehavior.test.js`：`spawnSync` 真跑 `.ps1`，含成对断言（干净 ⇒ 跳过 / `git status` 失败 ⇒ 放行），并断言 `Reason` 以区分两种不同的提前返回。
5. 接线守护 `utils/hxNoopContract.test.js`：N1–N10 + 负控；**N10 机器化「点名行为守护」**（文件须存在、须真有 `child_process`+`spawnSync`、须真跑该函数）。
6. 文档：数字收进 `dev-loop.md` 单点，其余改指针；本 ADR 回写（收口纪律要求 ADR 先于关票）。

## ⑤ 约束

- **不得**触碰：C1–C14（`utils/hxRunContract.test.js`）—— 尤其 C2 绝不强杀、C6 不看 cli 退出码、C7 派发顺序、C11/C14 部署基线判据与最短观察窗。
- **不得**把 `-CompileOnly` 的绿当成"跑成功"：编译判据与部署判据两条独立出口（ADR-0012）。
- **不得**在 `hx-run.ps1` 正文出现 `$LASTEXITCODE` / `ExitCode`（C6 只扫该文件；退出码判定留在 lib 内并注明为何 git 可信）。
- **已知边界（写实）**：标记只含 `headSha` ⇒ `pm clear`、重装基座、换设备之后 `headSha` 仍相等 ⇒ 仍判跳过，而被清空的 `www` 不会被发现。那种场景用 `-Force`，或删 `.ci-verify/last-deploy.json`。
- **已知边界 2**：预检在设备解析**之后**，无 adb / 无在线设备时脚本已先 `exit 2` ⇒ 「秒级跳过」以**能解析到设备**为前提。刻意如此（真跑本来就要设备），注释不得声称相反。
- **套件数不写死**（继承 ADR-0046 ③）：一律以 `node scripts/classify-guards.mjs` 现测为准（日期 + 当次数值）。

## ⑥ 验收标准（怎么算完成）

- 带标记 + HEAD 与跟踪文件都没变 ⇒ 秒级 `exit 2`，机检行 `exit=env`，且**不出现**取锁与 launch。
- 四条放行各自可复现：标记缺失 / 标记损坏 / HEAD 已变 / 工作树脏；外加第五条 **`git status` 失败 ⇒ 放行且 `Reason` 含「git status 失败」**。
- `-Force` 绕过预检；`-CompileOnly` 与 `-DryRun` 路径不写标记、不触发预检。
- 跳过**不抹掉**上一轮日志。
- 守护落锁：接线腿 `utils/hxNoopContract.test.js`（N1–N10，含 N10 的两条负控）；行为腿 `utils/hxNoopBehavior.test.js`（真跑 PowerShell，6 条，其中「`git status` 失败 ⇒ 放行」是先红后绿得来的）。
- ③ 门两腿全量绿（本仓 `npm test` = 接线腿 + 行为腿；CI 为最终判据）。
- **本 ADR 先于关票提交**；指针落**按需层** `docs/agents/dev-loop.md`（先例：ADR-0046 的指针也在那一节，而 `AGENTS.md` 常驻层有 L1 硬预算，见 ③ 最后一条 —— **不往 `AGENTS.md` 加行**）。
