# 0026 - 授权事实与可用性两格：缺席式可选键的落点、不进词表、不互顶

**状态**：已接受（2026-09-23，来源：#1267 前半的实现期裁决（根 `ADR-0062` 第十四波把 `company_disabled` 放上交换申请 DTO，第十五波第④批 `ADR-0064` 决策 5 回填到简历卡）；落地：**#1267 前半 PR**）

> **一句话**：「授权**在不在**」与「明文**能不能用**」是两格事实，移动端此前只有第一格有落点。
> 本 ADR 记下第二格的落点选择（读取层归一 + 行级附加说明），以及三条**否决**：不新增状态词、
> 不在客户端重推 `status`、不改徽章轴。

## ① 目标与范围

后端用 `company_disabled`（`contact_service.go:80`，`json:"…,omitempty"` = **缺席式可选键**，
出现即恒 `true`）表达「该企业账号已被禁用或已注销 ⇒ 授权记录还在，但联系方式明文已收回」。
唯一赋值点是 `approved && !contactPairUsable`（`:212-219`）。

范围：招聘域的**读取层**（`api/recruit.uts`）、**展示判定单点**（`utils/recruitDisplay.uts`）、
**交换段列表**（`pages/recruiter/contacts.uvue`）。不动后端，不动 Web 侧词表。

**票面的一处误判已就地纠正**（写进 `api/recruit.uts` 的注释，不在代码里留假前提）：
`GET /recruit/resumes/:id/contact` **不**带这个键 —— 它的 200 体是 `ContactPlainDTO`
（`contact_service.go:96-107`，无此字段），失败时是三态 403（`backend/internal/api/contact.go:98-140`）。
⇒ 移动端**目前**唯一能读到它的端点是 `GET /recruit/contact-requests`。

## ② 选型 + 一句理由

| 决策点 | 取值 | 理由 |
| --- | --- | --- |
| 归一层 | **读取层**收成 `boolean`（`(obj['company_disabled'] as boolean) ?? false`），消费面只判真值 | 缺席是**常态**不是「未知」；归一一次胜过每个消费面各写一遍。先例形状 = `forced_offline`（同文件 `:422`） |
| 呈现形态 | **行级附加说明**（交换段列表行下多一行文本），不是徽章、不是第六种状态 | 徽章那一格挂的是 `ContactGrantState` 五态之一；把「可用性」塞进状态轴 = 让「已同意」与「企业已停用」抢同一个槽 |
| 判定条件 | **只认 `company_disabled` 的真值**，不再叠 `status == 'approved'` | 后端赋值点已是 `approved && !usable`；客户端重推一遍就是把服务端事实换成客户端推断（两个事实来源），且后端哪天放宽赋值点，这层推断会**静默吃掉**新事实 |
| 与有效期的关系 | **两格不互顶**：`剩 N 天` 说时间，收回说明说可用性，同时成立时两行都在 | 用「已过期」盖「已收回」或反之，都是把一格的事实挪去填另一格 |

## ③ 明确不做的事

- **不给状态词表加第 6 行**，也不改任何 `label`。三把「两端同源」锁（取值集合 == 后端 Go 常量表、
  label 逐字 == Web `contactRequestStatus.ts`、消费面 `.tag-<status>` 齐全）只覆盖**状态轴**；
  加行会同时踩破前两把，而那两把是 ADR-0018 的承重件。
- **不给收回态任何操作入口**（沿用 #705：看起来能用、用了必失败的入口比没有入口更贵）。
- **不改徽章配色**：配色仍由各消费面的静态 class 承担，说明行走自己的 `.row-notice`。
- **本轮不动 `pages/recruiter/resumes.uvue` 的卡面角标**。卡面要的是「这张简历对应的企业已停用」，
  该事实要等第十五波第④批把同一个键回填到简历卡 DTO；**不**拿「我发起的 pending 列表」做旁路判据
  —— 那是用另一格的数据猜这一格。

## ④ 拆分步骤

1. 读取层承载 + 展示判定单点 + 交换段行级说明（#1267 前半，一个 PR）。
2. 守护：行为面 `recruiterResumeBehavior.test.js` D3/D4 + `recruitDisplayBehavior.test.js` 两条；
   接线面 `recruitWorkspaceContract.test.js` C 段一条（含「页面不得抄第二份文案」「class 必须真有样式」）。
3. 第十五波第④批：Web 侧文案对齐 + 简历卡回填后，再评估卡面角标（另票）。

## ⑤ 约束与代价

- **措辞目前由移动端单点定**（「企业已停用，联系方式已收回」在 `utils/recruitDisplay.uts`）。
  第⑤条那把同源锁**不覆盖它** ⇒ Web 落地同一维时必须对齐，否则同一个事实在两端出现两种词——
  这正是 ADR-0018 定义的漂移，只是发生在锁的射程之外，靠票面记账兜。
- **今天是潜伏态**：后端在 #1265 给的现测是「生产 3 条 approved 全指存活企业」⇒ 这一行真机上
  暂时不会出现。因此 ①a 取证**必然**要用夹具（本地临时强制该键为 `true` 后编译，产物不入仓、
  代码不提交），并按 ADR-0008 的手法补遗第 4 条**披露夹具**。
- **窗口语义**：该键只在吊销生效窗口内（根 `ADR-0060`）与「禁用后仍存活的授权」这一交叉里有意义，
  别把它当审计面或历史面来读。
- 缺席式键的代价：契约测试里 `company_disabled: false` 那条断言守的是「后端**从不**发 false，
  但万一发了也不得折成 true」—— 它不是对现状的描述，是对映射层方向的约束。

## ⑥ 验收标准

- [ ] 键缺席 / 为 `false` ⇒ 页面零附加说明（不给装饰性提示）
- [ ] 键为 `true` ⇒ 出现该行，且 `status` 取任何值都不改变它
- [ ] 三把同源锁保持绿（状态词表 5 行未变、label 未变）
- [ ] 真机：正常态无回归；夹具态该行可见，文本可被 `uiautomator` 的 `content-desc` 逐字核到
