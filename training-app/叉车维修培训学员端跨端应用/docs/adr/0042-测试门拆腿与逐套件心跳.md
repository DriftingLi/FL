# 0042 - 测试门拆腿与逐套件心跳

> 状态：已生效 ｜ 2026-10-18 立 ｜ 来源：#1702（承接 #1656 的 agent 判读纪律、#1410 的 `-i` 取舍）
> **职责边界**：裁定 ③ 门（单元测试门）**怎么被切成两腿、怎么让人在跑的过程中看得见、入口第一行说什么**。
> 不动门判据（`0008-移动端验收门与证据.md`）、不动 `-i` 串行语义（`#1410`，`jest.config.unit.js` 文件头）、不动 E2E 裁决（`0020`）、不动 `pr-evidence` 的运行时面触发与校验口径。

**① 目标与范围**

起因是同一件事被误判了**至少三次**：全量 ③ 门串行一跑 880 秒、**中途零输出**、`jest.setTimeout` 在 `utils/*.test.js` 里有 9 处取 120–600 秒，于是「跑着」被读成「卡死」，处置是 kill 掉、然后绕开这道门（#1410 / #1656 盘点 / 2026-10 那次会话）。

第二次追问才看见结构性根源：**`test:unit` 名义是单测，实际过半是行为套件**——它们直接起 `pwsh` 脚本、adb / 仿真机桩、真链路探针，最长单套静默到十分钟级。名字与体积不符，读者就无法用名字预判「该等多久」。

范围：命令入口与判据的可读形态（拆腿、心跳、预期时长）、CI 矩阵、机检行 token、承接文档同步。**不在范围**：改测试内容、改门判据、把行为套件并行化。

**② 选型 + 一句理由**

**决策 1（拆腿，轴 = 既有的守护分类）**：`test:unit` 只留**接线腿**（纯逻辑 / 接线套件），新开 `test:behavior` 跑**行为腿**（直接执行被测面的套件）。拆腿轴**不是**新写的清单，而是 `node scripts/classify-guards.mjs` 已有的分类：`behavior ⇒ 行为腿`、`wiring ⇒ 接线腿`，两腿的 `testMatch` 由 `scripts/lib/guard-split.js` 从**同一份分类**现算。理由是 `docs/agents/dev-loop.md`「不新建第三份被测面清单」——双真源漂移在本仓有血账（`#974`）。同时保留 `jest.config.all.js`（拆腿前那条 `utils/**/*.test.[jt]s?(x)` 全量 glob）作 `--testPathPattern` 收窄跑法的底盘：收窄成任一腿，都会让另一半「静默不存在」。

**决策 2（行为腿挂逐套件心跳，接线腿不挂）**：新增 `scripts/jest-reporter-suite-progress.js`，在 `-i` 串行下每套件收尾打一行

```
JEST_SUITE_PLAN total=70 started=18:36:07 note=…
JEST_SUITE i=12/70 status=FAIL secs=41.8 elapsed=628.5 tests=9 failed=1 file=utils/emulatorSmokeTierBehavior.test.js
JEST_SUITE_DONE total=70 passed=67 failed=3 elapsed=1123.6
```

理由：串行本身就是天然的进度节拍，只是此前没人把它打出来。**不挂接线腿**是刻意的——它 40 秒跑完，多一份行只会变成噪音。

**决策 3（入口第一行 = 预期时长）**：`npm run test:unit:gate` 的第一行就写「本次预期 ≈ 20 分钟：先接线腿 ≈ 1 分钟，再行为腿 ≈ 19 分钟，其中 `mpWeixinGateResultLineBehavior` 一套就约 8 分钟；单套件内静默数分钟属设计内」。判据放在读者看得见的地方（根 `ADR-0046` 同构），而不是事后写在文档里让人先读。

**决策 4（流式捕获，否则心跳等于没有）**：`& npm run test:behavior 2>&1 | Out-String` 会把整段输出**攒到命令结束**才吐（2026-10-18 探针：逐行 `| Tee-Object -Variable legLines | Out-Host` 4 秒时已见前几行，`Out-String` 版同一时刻**完全空白**）。改成 `Invoke-GateLegCommand`：边跑边 `Out-Host`、同时收进变量供落盘。这条是票面「880 秒零输出」的**残余形态**——不改它，心跳只存在日志里，跑的人还是看不见。

**决策 5（两腿都跑完再退出，先红者胜）**：与 CI 的 `fail-fast: false` 同口径；本地快路径 `-UnitLocal` 同步两腿（日常环只跑接线腿，会把行为腿的回归推迟到全量门）。

**③ 明确不做的事**

- **不改 `-i`**：`#1410` 的取舍不变（挡的是同机 CPU 争抢下的超时抖动，不是共享面）。拆腿**不**换来并行。
- **不删改任何行为套件的被测内容**，也不把「直接执行被测面」改成桩——那是在降低门的判别力。
- **不新建第三份被测面清单**（决策 1 的理由）。
- **不改门判据、不改 `pr-evidence` 的运行时面触发面**：`pr-evidence.yml` 只改了 ③ 那行的**标签文本**（`matchGate` 只认行首 key，判据不变）。
- **不做 E2E**（`0020` 裁决不动）。
- **不动 `new-worktree.ps1` / `wt-bootstrap.ps1` 的工程探测**：它们以「项目下有 `jest.config.unit.js`」认工程，那是**树可信判据**（`#1144`）而不是套件清单，两腿任一都在。

**④ 落地步骤与载体**

1. `jest.config.unit.js`（接线腿）/ `jest.config.behavior.js`（行为腿，`reporters: ['default', '<rootDir>/scripts/jest-reporter-suite-progress.js']`）/ `jest.config.all.js`（全量底盘），`testMatch` 由 `scripts/lib/guard-split.js` 现算。
2. `scripts/jest-reporter-suite-progress.js`（决策 2）。
3. `package.json`：`test` = 两腿顺序跑，`test:unit` / `test:behavior` / `...:local` 四条各指自己那份 config。
4. `scripts/dev-finish.ps1`：`-Leg unit|behavior` ⇒ 首 token `TEST_<LEG>_RESULT` / `TEST_<LEG>_LOCAL_RESULT`（默认腿逐字节仍是 `TEST_UNIT_RESULT`）；`-UnitGate` / `-UnitLocal` 两腿、`Invoke-GateLegCommand` 流式、入口第一行预期时长、`-PostToPr` 评论两腿并载。
5. `.github/workflows/ci.yml` 的 `mobile-test`：`matrix leg × shard = 8` 个子 job，腿→config 的映射只在 `include:` 一处。（**2026-10-24 #1890 起 unit 腿 ×2、behavior 腿 ×4 = 6 个子 job**；片数调整的裁定与理由见 `0041` 决策 2 的修订注。）
6. 守护：`utils/jestSplitContract.test.js` P1–P7（集合关系 + 真起 `--listTests` + 心跳行格式 + 四条 npm 入口字面量）、`devFinishContract` U15（腿进首 token）/ U8（两腿接线 + 第一行预期时长）/ L3（快路径两腿）、`guardClassification` H2 下界抬到 70 / 190。
7. 文档：移动端 `AGENTS.md`、`docs/agents/guards.md`、`docs/agents/dev-loop.md`、根 `.github/PULL_REQUEST_TEMPLATE.md`、`.github/workflows/pr-evidence.yml`。

**⑤ 约束**

- 两腿 `testEnvironment`（`node`）与 `moduleFileExtensions` 必须一致，否则同一套件换腿会换行为。
- **任何一个套件都不许不在两腿里**：`jestSplitContract` P1（集合完备 + 不相交 + 非空）与 P5（真起 jest `--listTests`，两腿并集 = 全量、无重复）fail-closed 守住，这是拆腿之后唯一的**新假绿形态**。
- **选错腿的 `--config` ⇒ 那个套件「不存在」（0 套件，长得像绿）**。跑单套件前先问 `node scripts/classify-guards.mjs`，收尾时用 `Test Suites:` 或 `JEST_SUITE` 心跳核对数量。
- 新增守护必须能被分类器判进某一腿，否则它自己不会被执行。

**⑥ 验收标准**（票面六条）

1. 两腿各有独立 `testMatch` 与结论行 token，`TEST_UNIT_RESULT` / `TEST_BEHAVIOR_RESULT` 机检可区分。
2. 行为腿逐套件心跳行贯穿整跑（`JEST_SUITE i=k/N`），跑的人**实时**看得见。
3. ③ 门入口第一行打出预期时长。
4. `guards.md` / `dev-loop.md` / `ci.yml` / `pr-evidence.yml` / `AGENTS.md` / PR 模板同步，无指向旧入口的残留口径。
5. 两腿各物理跑一次、全绿，wall 基线落进本 ADR。
6. 不触及 `*.uvue` / `*.uts` ⇒ 按 `ADR-0008` 的运行时面判定不必换流程。

**实测回填（2026-10-18，本机 12 核，head `632a30e0` + 本票工作树）**

- 分类读数：**190 套件 = 接线腿 120 + 行为腿 70**（`node scripts/classify-guards.mjs --json`）。
- 接线腿：`suites=120 tests=2667`，jest `Time: 39.1 s`、入口 wall **42 s**。
- 行为腿：`JEST_SUITE_DONE total=70 passed=67 failed=3 elapsed=1123.6`，入口 wall **1129 s**；最慢单套 `utils/mpWeixinGateResultLineBehavior.test.js` **496 s**，其后 `kotlinAllProcessCaptureBehavior` 76 s、`mpWeixinGateRetryBehavior` 73.5 s。
- 两腿合计 **1172 s**（拆腿前全量一次 880 s / 178 套件，套件涨了 12 个且行为套件变重）。
- 3 条红全部**不是**拆腿引入：`emulatorSmokeTierBehavior`（仿真机桩在整跑里超时，单跑 36 s 绿，`#1410` 同型的墙钟红）、`wtBootstrapBehavior` W7 与 `guardClassification` H3（前者改用 `jest.config.all.js` 列清单、后者由新守护读 `package.json` 满足「必须引用仓内载体」）。

**验收跑（2026-10-18 19:15 起，同一工作树，提交后复跑；两腿都绿）**

- 接线腿：`TEST_UNIT_RESULT exit=0 suites=120 suitesFailed=0 tests=2667 testsFailed=0 time=27.902s wall=33s`。
- 行为腿：`TEST_BEHAVIOR_RESULT exit=0 … wall=1497s`，reporter 心跳 `JEST_SUITE_DONE total=70 passed=70 failed=0 elapsed=1161.3`
  （运行中逐套件行 `JEST_SUITE i=k/70 …` 可在终端连续看到，最慢单套仍是 `mpWeixinGateResultLineBehavior` 483.5 s）。
- ⚠️ **这次 wall(1497 s) 比 reporter 的 elapsed(1161 s) 多出约 340 s，且机检行缺 `suites/tests/time`**：
  实测原因是无线调试 / 快照桩（`fake-adb.bat`）在套件结束后**没退出**（两个孤儿 `cmd.exe` 存活到 19:40），
  jest 收完 70 套后**等这些子进程的管道 EOF 才退出**，而 jest 自己的汇总行因此从来没打出来。
  这是**行为套件自带的桩清理问题**（拆腿前也在，只是被「整跑一笔账」掩盖），本票不扩大范围修；
  判读口径：**以心跳行 `JEST_SUITE_DONE` 与机检行的 `exit=` 为准**，`missing=suites|tests|time` 不等于是坏跑
  （`docs/agents/dev-loop.md` 的判读纪律节已同步这条）。
- 两次墙钟差异（1129 s vs 1497 s）就是上面那段桩等待的抖动 ⇒ **引基线时同时写清 reporter elapsed 与入口 wall**。

**实施回记（坑位，2026-10-27，#2013）——「逐套件驱动形态」只污染本地门读数的两类红**

`dev-finish` 逐套件驱动行为腿（#1994 看门狗）时，每个套件是**自己一个 jest 进程**，且经
`cmd /d /s /c "npm run test:behavior -- --runTestsByPath …"` 起、stdout/stderr **落文件**、`CreateNoWindow`
（驱动入口：`pwsh scripts/dev-finish.ps1 -UnitGate`；逐套件行 `JEST_SUITE i=k/N …`）。这个形态与「直跑
`npm test`」有两处可观测差异，各自造出一条只在本机门里长的红（CI ③ 不注入那两个 env ⇒ 第 1 条在 CI 不可能出现；
第 2 条 CI 为何不复现**未查清**，本票不据「CI 也是重定向」作因果）：

1. **驱动 env 与合成场景串扰（确定性）**：驱动侧注入 `FL_BEHAVIOR_SUITE_OFFSET/TOTAL`（本仓内部契约）。
   `jestSplitContract` 的 P6 用**合成事件**（`numTotalTestSuites=2`）断言行格式，在驱动腿里必然继承那对 env，
   reporter **正确地**优先用全局数 ⇒ 行里是全局套件数（本机现测 81，票面那次 78）、断言要 `total=2`。
   判据归属：env 优先级语义没错（由 `behaviorLegWatchdogBehavior` 的 W6 守着），错的是**测试没隔离场景**
   ⇒ 隔离点放测试侧，且 env 的存/清/恢复收进 `utils/behaviorSuiteEnv.js` 一件（P6 与 W6 共用同一份词汇，
   两处不再各写一遍）；reporter **不加**「测试模式」分支。
2. **无控制台形态下子 pwsh 的输出码页（上下文级）**：`[Console]::OutputEncoding` 在 stdout 被重定向 /
   无控制台时退回本机 ANSI 码页（本机 gb2312）⇒ `evidenceGenContract` 的 #1920 两条拿到 GBK 字节、
   Node 按 utf8 解成 `## ����֤��`。修法与 `dev-finish.ps1` 顶部同款：**子进程自己钉 UTF-8**（非控制台环境
   赋值可能抛 ⇒ `try/catch` 兜住）；不把断言降级成 ASCII token —— 那会毁掉 #1920 要的「中文描述符两侧同源」。
3. **styleLoop E3 的 180 s 超时：本次未复现，成因未定位，故不写「已修」**。同形态真驱动跑了一次
   （本工作树 = `feat/2013`，head `6b2d532a` + 本票改动，**不是 master 基线**；n=1）：
   接线腿 `TEST_UNIT_RESULT exit=0 suites=121 tests=2695`；行为腿
   `TEST_BEHAVIOR_RESULT exit=0 suites=81 tests=984 time=2662.8 s wall=2664 s stalls=0`；
   `styleLoopBehavior`（本跑第 80/81 个套件，票面那次是第 3/78——**位次不同**）`PASS secs=26.9`，
   其中 E3 **2967 ms**（票面的 180.057 s 正是 `runEntry` 的超时出口，不是根因）。
   取证与再现 playbook 的细节以票 #2013 为准，本节只留判据：若再现，按顺序看三处 ——
   ① `.ci-verify/style-loop.log` 最后一行机检行有没有写出来（没写 ⇒ 卡在链体内，不是判据）；
   ② `Get-AdbOutput` 的 15 s 预算有没有被吃满（`env-check.log`）；③ 同时刻是否还有假 adb 桩 /
   `mpWeixin*` 重套件在跑（本机行为腿最慢三套 831 / 664 / 350 s，见上面那条「桩未退出 ⇒ jest 等管道 EOF」——
   争用形态下「慢」与「卡」在读数上同形）。在拿到这三处之一之前，**不改 `runEntry` 的 180 s**：
   那是症状出口，调小只会把「卡」变成「更快地误报」。
