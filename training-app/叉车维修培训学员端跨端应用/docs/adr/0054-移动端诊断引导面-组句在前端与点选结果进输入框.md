# 移动端诊断引导面：组句在前端、点选结果进输入框而非直发

- 状态：已采纳（2026-11-05，#2296 实施同批写入）

## 背景

智能维修诊断的 v2 单轨（根仓库 ADR-0091 / #2236 地图）之后，移动端专项页只剩一个纯文字输入框：
品牌 / 系统-型号 / 故障现象的周边只读面随 v1 通道一起退役（#2237 硬删、#2262 摘面板）。
Web 侧已按对方信息架构补齐并上线（#2276 / #2280），移动端是半成品。

本票把引导面补回移动端：空态品牌快选 + 半屏四步面板（品牌 → 系统/型号 → 现象 → 确认）。

## 决定

1. **组句在移动端重写一份纯函数，但由跨栈守护锁一致**。v2 契约里没有 compose 端点，
   `content` 是唯一文本通道 ⇒ 品牌与型号只能进正文。两端各写一份必然漂移，
   故 `utils/diagnosisCompose.uts` 与 `frontend/src/utils/diagnosisCompose.ts` 的
   **模板骨架序列**逐位比对（`utils/diagnosisComposeParityContract.test.js`）。
2. **点选结果进输入框、不自动发送**（与 Web 的有意差异）。Web 是点完即发；
   移动端票面判据写的是「输入框出现拼装好的问题句，可编辑后再发送」——
   补一句故障码 / 出现时机是学员唯一能补回命中率的手段，替人发出去等于废掉它。
3. **留白只有一个判据**：`health.ok !== true` 或 `intents` 取数失败 ⇒ 引导区整块不渲染、
   已拿到的字典一起丢掉。理由同 Web #2244 决策①：留着品牌卡就是「点得动、点了就 502」的死入口。
   进页拉一次，不轮询。
4. **不新增页面**：引导面是绝对定位的半屏面板（形态同 `ai-chat-pro-sheet.uvue`），
   不碰 `pages.json` ⇒ 不触发打包面门，也不给 ADR-0013「带键必有列它的界面」增加分区。

## 后果

- 两端问法一致这件事从此**有机检**；改任一端模板都会红在跨栈守护上。
- 移动端比 Web 多一次「确认」动作（Web 点完直接发）。学员多一步，换来可编辑。
- 引导面在流式对话期间仍可见（面板不因 `thinking` 关闭），但发送本身由既有守卫拦。

## 不采用的备选

- **直连对方 compose**：契约里没有这个端点，且对方返回里带语料特征词，我方拿不到词表 ⇒ 无法等价。
- **照 Web 一样点完直发**：与票面判据冲突，且废掉补充说明这一唯一提命中率手段。
- **把引导面做成新页面**：触发打包面门，且要多一个按功能键分区的界面面（ADR-0013）。
