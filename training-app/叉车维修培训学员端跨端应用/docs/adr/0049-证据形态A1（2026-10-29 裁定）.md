# 0049 - 证据形态 A1：验收证据降到「正文一行 + sha7」

**状态**：已采纳（2026-10-29，来源：地图 #2098 的决议票 #2100；落库：本 ADR 与同批工具改动）

## ① 目标与范围

把移动端验收证据的**主键**从「sha 绑定门评论 + 三候选集」降到「PR 正文一行 `跑于 <sha7>` + 门自带的机读读数行」。

范围到**证据形态与判据面**为止：不动 ADR-0043 的发版冒烟节奏，不动 ② 的覆盖判据（#2101 在管），不动 ①② 之外的门是否存在（那是下一层的裁定）。

## ② 选型 + 一句理由

**A1（正文一行）**，而不是「保留评论 + 转灰」或「彻底退役 pr-evidence」。

理由不是「简单」，而是 **#2099 的实读把前提推翻了**：`pr-evidence` 与 `mobile-gates` **都不在 ruleset 必检**（必检只有 `ci-summary` + `ensure-testing-smoke`）⇒ 整套评论取证是**荣誉制**：红了不拦合并，绿了不证明任何事；而 gate-validator 里还留着一条例外通道，正文写「已接受未验证风险」即清空全部 errors。

它买的是「多个陌生 agent 并发推同一仓、必须互相取证」这个前提下的东西。单账号串行开发的形态不持有这个前提，却一直在付它的账（#2107 实测 85–110 分钟/PR，其中相当一部分是取证与返工）。

## ③ 明确不做的事

- **不放弃机检**。行内两样东西是硬判据：`跑于 <sha7>`（绑定）与门自带的读数行 token（`MP_WEIXIN_RESULT` / `KOTLIN_ALL_RESULT` / `COMPILE_RESULT`）**且 token 后必须跟着门真打出来的 `key=value`** —— 只写 token 或写 `...` / `<读数行原样>` 判「没有实际读数」。缺任一项判红。
  ⚠️ **「硬」不是绝对的，别读成绝对**：例外通道仍能把这行错误清掉。但 2026-10-29 review 收窄后，**必须点名门号**（`- 例外：已接受未验证风险 ④`），且只清被点名门的缺项；写一句含糊的「已接受未验证风险」现在什么都清不掉。收窄之前它比这里写的更糟：判据对全文做 `/已接受未验证风险/`，连「本 PR **不适用**『已接受未验证风险』」这种**否认句**都能清空全部 errors。
- **不校真伪**（与 0008 一致）：不校验那次门是否真的按该 sha 跑过，只校「行在不在、sha 绑不绑得上」。真伪归维护者，图和日志是附证。
- **不把图当判据**（#2108）：截图附在行尾供人看，校验器不读图、不校验链接可达。
- **不动发版冒烟**：①a 仍是发版前一次（0043），能力面 ①b 已整体退役（#2103）⇒ PR 粒度**零人签**。

## ⑤ 约束（改这块前必须知道的五条）

1. **判据模块必须自包含**：`pr-evidence.yml` 用 `repos.getContent` 取**单个文件**文本 + `new Function` 求值。往 `gate-validator.mjs` 里加 `import` 会在 CI 当场炸，而本地 `node --test` 照样绿 —— 两边的加载路径不同。
2. **占位句里不许写读数行的 token**：判据原先只看 token 在不在那行，写了它就等于「读数已贴」—— 2026-10-29 review 实测：模板预置 `MP_WEIXIN_RESULT ...` 时，只把 `<sha7>` 换成真 sha 就**判绿**，而一个门都没跑。现已把判据升级为「token 后必须跟 `key=value`」，占位写法（裸 token / `...` / `<读数行原样>`）一律判红；但**占位句仍然不许抄 token** —— 这是两道防线，别只留一道。同族的坑本仓踩过（占位句里写 `actions/runs/<id>` 会满足旧 ③ 的产物判据）。
3. **sha 绑定用前缀比较，不是全等**：正文只写 7 位，compare 回来 40 位。旧实现的 `mergeBase !== commit` 是**潜在永假**（祖先口径永远不成立），A1 之前没人撞上是因为评论里能塞全 sha。
4. **compare 取数必须并 `previous_filename`**：`a.uvue` → `a.ts`（把逻辑抽进 `.ts` 是常见动作）时 compare 只报 `filename: a.ts`；只 map `filename` 就会判「其间运行时面没动」⇒ **改名可绕过祖先判定**。另有同族形态：diff 过大时 compare 可能**不回** `files`（而不是回 300 条），`length >= 300` 判不出来 ⇒ 拿不到数组也按截断处理（`identical` 除外）。
5. **例外通道要按门豁免，不能按段落豁免**：声明必须点名门号、只清被点门；否则「写一句话清空全部 errors」，连否认句都命中。

## ⑥ 验收标准（可机检）

- `node --test .github/scripts/pr-evidence-check.test.mjs` 绿，且含「反回流」用例：判据里出现 `gateComments` / `gate-evidence:` / `issueNumbersInBody` / `exemptions` 任一即红；workflow 里出现 `listComments` / `issues: read` 即红。
- 模拟 CI 求值路径（剥 `export` + `new Function`）能跑通 —— 这是唯一与 CI 同构的验证方式。**这条 2026-10-29 review 指出原先只写在 ADR 里、没落成用例，现已落成测试**（只写不测等于没有）。
- **模板原样（只换 sha7）必须判红**，红因是「没有实际读数」—— 防「照抄模板即绿」。同时保留反向断言「模板必须给出可照抄的形状」，否则人不知道要写什么。
- **例外通道**：不点名门号不放行；点名 ② 救不了 ④ 的缺项；否认句不算声明；写在段外不算声明；点名了但该门无缺项只记 note。
- 真跑生成器 → 真喂校验器：有读数判绿、无读数判红且红因是「缺读数」而不是「缺该行」。

## ⑧ 已知遗留（不假装已解决）

**A. 本 PR 刻意没做的清理**（review 认定为 Spec 缺失，但不在本 PR 补 —— 各自独立票）

- 五个门脚本的 `-PostToIssue` **帮助文案**还写着「贴评论」，行为已不投递（`Send-GateComment` 降为只打印块，恒返回 `retired`）；调用方里消费 `CommitUnavailable` / `EvidenceUrl` 的分支是死代码。清理是独立小票——本次刻意把改动面收在库内，不让日常 `dev:finish` 承担重写风险。
- `kotlin-all-check.ps1` / `compile-check.ps1` 仍调 `Publish-GateComment`，`mp-weixin-check.ps1` 仍调 `Publish-ScreenshotArchive`：**调用在、投递已死**（前两个）；截图入库（把 png 提交进 git）在 A1 下应改为 GitHub 附件，但删它动真机取证链路 ⇒ 独立票。
- F3/F4（② 噪音白名单 / `close` 有界收流）**夹带在本 PR 里**（同一个分支、已实测：`oldReadMs=15287 → newReadMs=5008`）。属于「同一个 PR = 一个回滚单位」的代价，回归时按 commit 定位。

**B. 覆盖面空洞（A1 之后仍然没有门的地方，如实列出）**

2026-10-29 review 实测清点（纠正我先前的一处误判）：`components/` 下**全是 `.uvue`**（无 `.vue`）、`composables/`(12) / `api/`(29) / `stores/`(2) 全是 `.uts` ⇒ 这些**仍命中运行时面**，④ 照旧触发。所以「改 components 就绿」不成立。

真正空的是：

| 面 | A1 前 | A1 后 |
|---|---|---|
| `static/**` | 无门 | 无门 |
| `uni_modules/*/index.vue`（`.vue` 不在 `isRuntimeFile` 里） | 无门 | 无门 |
| `scripts/*.ps1`（**门脚本自己**，48 个） | 无门 | 无门（只有 jest 行为腿覆盖一部分） |
| `utils/*.js` 的测试文件（220 个） | 无门 | 无门 —— 删断言永远绿，没有「测试被削弱」判据 |
| **④b 打包面**（`.aar` / `libs/*.jar` / `utssdk/app-android/**` / 三份 json） | 必填一行（执行人 / 日期 / 结论） | **只有 notes**（`gate-validator.mjs` 的 `needs4b`）⇒ 实际无人 |
| ① 的免行痕迹 | 必须写一行 | 无（0043 已实质取消，A1 删掉最后那行审计痕迹） |
| ③ 两腿 | 必填 run 链接 | 无 —— **但这条安全**：`ci.yml` 的 `ci-summary.needs` 含 `mobile-test`，两腿是真门 |

其中**只有 ④b 是 A1 自己新增的空洞**（其余 A1 之前就空）。要不要把 ④b 提回「不判红但必须留痕」的结构位，是半个决定、不是代码问题。

**C. ② 的覆盖洞（#2101 管，本 ADR 不碰）**

`-Pages auto` 的改动页清单只认 `pages/**/*.uvue`：改 `components/*.uvue` 或 `utils/*.uts` 时清单为空 ⇒ 只跑入口页一张，门照样亮绿。这是**② 的覆盖为零**，不是「整个 PR 没门」（④ 仍会触发编译）。

**D. 仍是未知**

「正文那一行由谁在什么时机写进 PR」未定：A1 不要求它先于 PR 存在（不贴评论了），预检是唯一强制点。
