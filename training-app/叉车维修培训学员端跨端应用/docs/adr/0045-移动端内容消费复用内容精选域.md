# 0045 - 移动端内容消费复用内容精选域

**状态**：已接受（2026-10-26，来源：原型图对照调研（`/research`，报告在根仓库 `docs/design/20261026-原型图全量对照-移动端缺失页面功能调研.md`）+ 四轮 `/grill-with-docs`（Q6'/Q16/Q18，全部采纳推荐）；本 ADR 把裁定落到移动端仓库面）

> **一句话**：移动端三处内容消费点（首页新闻板块、考情资讯页、招聘公告 tab）**一律接现成的「内容精选」（featured-content）域**，类别字典加「考情」「公告」两值；**不在移动端建第二套内容系统**，报名入口/成绩查询不建报考实体，外链改由**正文 Markdown 链接**承载（`source` 是来源名称、非 URL；2026-10-28 修订，见文末「修订」）。

## ① 目标与范围

**要回答的是消费口径问题**：原型（70 张小程序设计稿）给移动端画了一整个「资讯域」——首页新闻板块、独立「考情资讯」页（新闻资讯/考试动态/报名入口/成绩查询四 tab）、招聘页「公告」tab。调研初判「后端零 news 接口」，系搜词错误（只搜了 news/article/announcement/notice，未命中 `featured`）：后端**已有完整内容发布系统**——公开面 `/featured-contents`（分页）+ `/featured-content/{id}` + `/{id}/view` 阅读计数，管理面全 CRUD+发布+定时发布（根 ADR-0076）+传图，正文 Markdown（根 ADR-0046 渲染口径），现四类别（公司动态/行业新闻/产品资讯/政策法规）由官网门户与 `/news` 归档页消费。真决策因此是：**三处消费点复用内容精选，还是新建「资讯」实体**。

**范围**：移动端消费口径裁定 + 类别扩展裁定 + 报考外链处置。

**不含**：内容精选后端系统本身（现成，只加类别值）；官网门户行为（归档页按现行类别字典自动枚举，新类别随之可见，已接受）；电商域（维持 `0031-课程兑换面状态机与购物车族清退.md`，本会话 Q1 重申不做）。

## ② 选型 + 一句理由

| 决策 | 一句话理由 |
| --- | --- |
| **移动端不建第二套内容系统，三处消费点一律接 `/featured-contents`** | 内容精选字段形状（title/summary/cover/正文 Markdown/source/sort_order）已覆盖原型资讯卡与详情页全部要素；新建 = 把已有能力用不同名字再写一遍（两套管理端发布页、两套发布/定时/计数逻辑、搜索域两个并列内容类型），没换来任何新信息 |
| **类别字典四态 → 六态（加「考情」「公告」）** | 类别是数据字典值不是代码分支，扩两枚举成本≈0 |
| **首页新闻板块消费 = 考情 + 行业新闻 + 政策法规**（Q18=A） | 公司动态/产品资讯是官网营销内容，进 app 首页是噪音；公告不重复进首页（招聘 tab 已有）；映射写死在本决策，改映射=改决策 |
| **考情资讯页（`exam-info.uvue:74-85` 现纯 mock）去 mock 消费「考情」类；招聘公告 tab（`job-list.uvue:31` 空态）消费「公告」类** | 两处现状注释自证无数据源；接现成分页接口即活 |
| **报名入口/成绩查询 = 「考情」类内容条目的正文 Markdown 链接承载外链；不做站内报考流程、不建独立报考信息实体**（Q16；原文写 `source` 外链，2026-10-28 修订为正文链接，见文末「修订」） | 外链已覆盖用户动作；报考事务信息（民族/户籍/政治面貌/应届）另有「不入简历卡」裁决（根 CONTEXT.md「简历卡」，就业歧视合规理由）；真出现站内报考业务属新域立项 |
| **置顶走 `sort_order`、阅读计数走 `/view`** | 不另发明机制 |
| **「资讯」只作类别语用、不升格为并列概念；canonical 称谓仍是「内容精选（featured content）」** | 根 CONTEXT.md 已裁决裸用「精选」撞名（帖子精选 vs 内容精选）；再造第三个并列概念是术语事故 |

## ③ 明确不做的事

- **不建**移动端独立的「资讯」实体/表/接口族（报告 §6-A news 域草案作废、§6-D1 公告新接口作废）。
- **不做**站内报考流程、报考信息表实体（外链承载）。
- **不做**按类别的差异化权限与发布管线（沿用现单管线）。
- **不做**类别→消费点映射的配置化。

## ④ 拆分步骤

1. **本 ADR + 根报告 §8 定案段 + 根 CONTEXT.md「内容精选」六态词条，同批收进**（决策与被决策的记录同批可复核；先例 0044——调研文档留根仓库、本线 ADR 指过去）。
2. （可并行）后端：类别枚举扩展（字典登记/CHECK）——根仓库票，零新接口。
3. （可并行）移动端三张接线票（竖切片）：首页板块数据源替换、考情页去 mock、公告 tab 接线——触及运行时面（`*.uvue`），走 `scripts/new-worktree.ps1` 闸门与四门纪律。
4. Web 官网：无需改动（归档页按现行类别字典枚举）。

## ⑤ 约束（不能动的）

- 内容精选后端系统与发布管线本体不在本 ADR 射程（只加类别值）。
- 渲染口径沿用根 ADR-0046（同一份 Markdown、门户与移动端各自渲染）。
- 三处接线属运行时面：② 门（微信开发者工具门）为常态主门（`0043-真机门降级常态化与发版冒烟（2026-10-23 裁定）.md`）。
- 术语：_Avoid_ 裸用「精选」、不得立「资讯」为并列概念（根 CONTEXT.md「内容精选」「内容对象」词条）。

## 修订（2026-10-28，#1940 裁定）

> **触发**：#1940 调查发现票面（本 ADR 行文、根 CONTEXT.md、原型对照报告 §8.2 Q6'）共同写着的「报名入口/成绩查询走 `source` 外链」前提**在数据模型里不成立**；#1939 升级同一问题后由维护者裁定「都按推荐」，本段把裁定落到记录面。

- **外链承载：`source` → 正文 Markdown 链接（选项 C）**。`source` 是**来源名称**，三处一手来源一致：`backend/migrations/000001_baseline.up.sql`（`COMMENT ON COLUMN featured_content.source IS '来源（如：公司官网、新华网）'`，`VARCHAR(100)`）、管理端 `frontend/src/pages/admin/FeaturedContentEdit.vue`（占位「请输入来源（如：和润天下、行业媒体等）」）、`API.md` 精选示例 `"source": "官网"`。故「跳 `source` 外链」在现模型下**跳不出去**。改由作者在正文里写 Markdown 链接承载——与根 ADR-0046 决定 3（内容精选正文子集**含链接**）一致，零后端改动。**明确不做**：新增 `source_url` 字段（要动迁移 + 管理端 + Web/门户，跨仓跨队）、`source` 双用途（名称与 URL 混义，存量媒体名会被误当 URL）。**移动端需补**「内容精选正文链接可点」：`pages/featured/featured-detail.uvue` 现只渲染 `block.text`，正文 `[文字](url)` 被剥成纯文本。
- **考情资讯页 tab 收敛为原型四 tab**（新闻资讯 / 考试动态 / 报名入口 / 成绩查询）：删去现存的「招聘信息 / 相关问题 / 岗位表」——「招聘信息」与招聘页「公告」tab（#1941）重复，后两者无原型依据、无数据源，留着即假入口。
- **「报名入口」「成绩查询」同走 `exam` 类别，接受两 tab 同列表**：运营用 `sort_order` 置顶入口类内容，两 tab 各置一行说明文案。**不合并 tab**（会偏离原型四 tab）、**不把 `exam` 再拆类别**（返工 #2063 刚落的字典边界不划算）。
- **chips 只在「新闻资讯」tab 保留**：最新资讯=`sort=latest`、热点关注=`sort=hot`、政策法规=`category=news`、全部=无筛选；其余 tab 隐藏（tab 自身已是类别，「政策法规」在其下必然空结果）。`api/featured.uts` 需补 `sort` 透传——后端早已支持（`backend/internal/featured/handler.go:57-64`、`service.go:64-67`）。
- **多类别取数口径单点复用**：「按 `category` 各发一次 → 去重 → 按 `published_at` 倒序」的合并助手（`utils/dashboardNews.uts`）由首页板块（#1939）与考情资讯页（#1940）共用，不落两套实现；#1939 先落，本票后接。
- **本段只记口径，验收逐票进行**（#1939 首页板块与详情页正文链接、#1940 考情资讯页），不由本 ADR 声称已完成。
