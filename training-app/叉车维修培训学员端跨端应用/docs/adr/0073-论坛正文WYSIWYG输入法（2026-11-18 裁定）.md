# 0073 - 论坛正文 WYSIWYG 是输入法而非内容格式（2026-11-18 裁定）

> 状态：已采纳（2026-11-18，#2639 同批写入）｜来源：规格 #2631｜**职责边界**：只定移动端论坛正文的**输入形态**；不改 `content_format` 契约、不改存量帖渲染、不动 Web。
> **修订关系（旧 ADR 只加指针、不重写正文）**：本端 `training-app/叉车维修培训学员端跨端应用/docs/adr/0025-论坛正文格式与输入区形态.md` 的 ⑥-5 与 ⑩ 已标「已修订」并指回本篇；根 `docs/adr/ADR-0044-论坛正文格式由作者声明.md` 的「正文格式由作者声明」在移动端退化为「由输入形态确定」（`content_format` 契约、escape 策略、编辑不变式三项原样保留，`text` 档只服务存量与无 editor 端）。

## ① 目标与范围
移动端论坛输入区从「textarea + Markdown 记号工具栏 + 编写/预览两态」换成 WYSIWYG：作者按所见即所得排版，**提交前序列化回论坛档子集 Markdown**。范围 = 发帖表单与回复浮层两个载体（共用同一输入组件）；**不含**后端契约、存量帖渲染、列表摘要投影、Web 富文本。

## ② 选型 + 一句理由
- **WYSIWYG 是输入法、不是新内容格式**：`content_format` 仍只有 `text|markdown` ⇒ 存量帖 / Web / 渲染面零改动，编辑器只是「样式树 → Markdown 字符串」的转换层。
- **三层分离，不许糊成一个词**：编辑模型 = 编辑器内部样式树（Quill 内核，只活在输入期）／存储格式 = 论坛档子集 Markdown（落 `content_format=markdown`）／渲染模型 = 现有块 + 行内 runs（锁死在 Markdown 子集）。
- **序列化载体建在 delta 上、不建在 html 上**：html 会把空格写成 `&nbsp;`、把字号颜色写成 inline style、把编辑器不支持的块静默拉平；delta 保普通空格 + 语义 attributes。
- **格式边界由三处共守**：自家按钮集 + 序列化器 + 发布前保真检查；`enable-formats` **不成边界**（实测收窄到 `['bold','italic']` 后 `format('header',null)` 照样生效，它只约束工具栏，不约束任何可达的 format 调用）。

## ③ 明确不做的事
不做正文内嵌图片（**R3**：丢弃 image op + 持续可见提示，图片只走下方「＋」入口）；不做第三种输入形态、不做同端双形态；编辑器支持而论坛档渲染不出的构造（下划线 / 对齐 / 字号 / 颜色 / 上下标）不进按钮集、一律降级纯文本；不改根 ADR-0044 的 escape 策略本身（raw HTML 仍渲染为文本 —— 那是服务端与 Web 的兜底，不是移动端内容的过滤器）。

## ④ 拆分步骤
T1 #2638 序列化地基（`utils/forumDeltaMarkdown.uts`，已合并）→ T2 #2640 输入组件 → T3 #2641 发帖载体 → T4 #2642 回复载体 → T5 #2643 清退格式偏好与 spike 资产 → T6 #2639 本篇 ADR → T7 #2644 真机四项（不阻塞实施）。

## ⑤ 约束
**R1 容量余量 = 0**（常驻 3 枚 = 粗体 / 斜体 / 删除线，其余进二级面板，不再增加常驻位）；**R2 触摸目标 ≥88rpx**（不得为塞按钮而缩小）；能力端（App / mp-weixin / Web）唯一形态是 WYSIWYG，支付宝 / 百度 / 头条小程序保留现有记号工具栏作为**按端例外**；撤掉「编写|预览」两态、**边界提示行保留**且仍与成员声明表对账；**编辑不变式不动**（旧帖按原 `content_format` 回填，`PUT` 不带该字段）。

## ⑥ 验收标准
新发帖 / 回复一律以 `content_format=markdown` 提交序列化产物、作者格式偏好（纯文本|Markdown）从输入路径退出；产物**不含** `<`、`&nbsp;`、`![…](…)`，quote / code / 行内代码 / 链接经论坛档解析出对应块与 run（URL 原样）；粘贴越界构造只留子集内格式，图片被丢弃并**持续可见**提示；空 / 纯空白正文禁用提交，发布前保真检查列出被丢弃 / 降级的项。

## ⑦ 修订（2026-11-19，#2658）

⑥ 的「粘贴越界构造只留子集内格式」**已被取代**：粘进来的富文本**整段降级为纯文本**，不保留任何格式（维护者在 #2658 triage 明确拒绝了「保留子集格式」这条 B 路径，标准改成「不静默失败 + 内容以纯文本落地 + 持续可见保真提示」）。同时补两条此前没写下来的边界：

- **粘贴走「粘贴」按钮、不走原生手势**：uni-app x 的 `editor` 没有 paste 钩子，Android 原生层把 `text/html` 的 clipdata 整段丢弃（0 字、无 `@input`、无 `statuschange`）⇒ 原生长按粘贴 = 静默丢失。故由 `utils/forumPaste.uts` 把剪贴板原文归一为纯文本，经 `editorContext.insertText` 写入 —— 与打字同一条 content-change 路径，一定发 `@input`、一定进序列化。
- **失焦只读态必须自己放开**：`readOnly` 本来只为「点格式按钮不丢选区」而存在，但它同时挡住了「点编辑器重新聚焦」。一次被丢弃的粘贴会让编辑器失焦，只读若一直挂着，作者就再也点不进去（只能退出重进）—— 故失焦后 `READONLY_HOLD_MS` 到点自动恢复可编辑。
- **产物红线扩张到粘贴输入**：归一化层负责去掉 HTML 标签、`&nbsp;` 等各种实体、Markdown 图片语法，并把 U+00A0 换成普通空格；序列化器另在 delta 侧把 U+00A0 归一，两条入口都不让不换行空格进正文。

## ⑧ 回复浮层的微信键盘定位（2026-11-19 修正）

微信端原生 `editor` 弹出键盘后，可视区已经移动到键盘上沿；回复浮层不能再把 `keyboardheightchange.height` 作为额外的 bottom 偏移，否则会重复扣除键盘高度，把输入区顶出屏幕。`forum-detail` 在 `MP-WEIXIN` 下因此保持面板 bottom 为 0；其他端仍按键盘高度补偿。对应的截图几何回归判据在 `utils/replyPanelLayoutBehavior.test.js`。
