# 0032 - 开屏页吞掉认证入口 ⇒ 登录页降级为「次级落点」而非退役；两端能力分叉走运行期探测而非编译期 `#ifdef`

## ① 目标与范围

两件事在同一次改动里耦住，必须一起裁：

1. 启动页（`pages/index/index`）从「品牌开屏 → 自动跳登录页」改成**未登录着陆页**（小程序端直出「微信一键登录」、App 端直出「其他登录方式」）之后，**独立登录页 `pages/login/login` 留还是删**。
2. 「微信登录」这条能力**截至本篇写作（2026-10）小程序端可达、App 端不可达**（缺微信开放平台「移动应用」凭证，见 #1482 与 `docs/design/1482-app-wechat-login.md`），这个分叉该落在**编译期**（`#ifdef MP-WEIXIN`）还是**运行期**（provider 能力探测）。⏳ **后半句那个端别事实是会过期的，不是本决定赖以成立的永久属性**：它由 #1482 的开放平台前置决定；App 端一旦接入，本节与根词表「微信一键登录」「微信小程序登录（wx-login）」两条词条里的"仅小程序端可达"表述**都要改写**。本 ADR 的裁定不随它作废——理由恰恰是"走运行期探测"：凭证到位那天入口自己亮起来，不必再改一次分叉机制。

**不裁的**：App 端微信登录的排期（#1482 给的是可行性 + 接缝，不是日程）；后端凭证与端点形状（本轮零后端改动，`/auth/wx-login` 未被 App 端触碰）；着陆页视觉与文案措辞（属产品面与 ① 门真机读数）。

## ② 选型 + 一句理由

- **登录页不退役，降级为次级落点。** 一句理由：**删页的代价全部落在 ③ 门的冻结锁、两个 ADR 的宿主与 `pages.json` 的人工提交面上，而收益只是"看起来少一张页"。**
- **两端分叉走运行期探测，不走编译期 `#ifdef`。** 一句理由：**运行期探测能达到同等效果（该端不显示不可用的入口），而 `#ifdef` 指令行的增删数可以是 0 ⇒ ② 门免。**

探测件的形状：`composables/useLoginProviders.uts` 返回**可用性判断**（`uni.getProviderSync({ service: 'oauth' })` 里找 `id == 'weixin'` + `UniOAuthWeixinProvider.isWeChatInstalled`），**不是**"要不要渲染"的布尔——后者会被各页各自抄成不一样的前端猜测。跨模块共享：#1484 的 `disabled` 复用同一件。

## Considered Options

三条都日后一定被人重新提出，写下来是为了挡住。代价数字为本票复核值，复核命令：`git grep -l "pages/login/login" -- ":!docs"` 与 `git grep -n "pages/login/login" -- "utils/*.test.js" "utils/modules.js"`（工作目录 `training-app/叉车维修培训学员端跨端应用`，树 = BASE `30cc8f1a`）。

### 1. 彻底删掉登录页 —— 被否

- **引用面 29 个文件**（非 `docs/`）：生产与配置面 **14** + ③ 门套件 **9** + `scripts/` 取证与巡检脚本 **6**。triage 记的是 25，差在 `scripts/` 的计入口径，本票按可复算口径写。
- **③ 门：8 个契约/行为套件、约 17 处断言与源码锚**（测试文件内 19 处命中，扣 2 处纯注释行 = 17；「8 个套件」= 9 个 `.test.js` 去掉 `utsAndroidCompile.test.js` 那把编译门锁）。其中三处是硬锁：
  - `utils/loginContract.test.js:43` —— `PAGE = 'pages/login/login.uvue'`，锁的是**模板整块 + `<style>` 整块两把 sha256 冻结锁**（`sha()` 于 `:67`，块级值取自 `origin/master` 逐字节）；
  - `utils/concurrent401RefreshBehavior.test.js` —— 单文件 7 处，含 `body.indexOf("uni.reLaunch({ url: '/pages/login/login' })")` 这类**字面量源码锚**（改文案格式即红，不是改行为才红）；
  - `utils/modules.js:351` —— ③ 门 harness 的**模块声明清单**收了这一页，漏登记即 `contractHarness.infraFacts().unregistered` 必红。
- **11 处生产路由出口**（分布在 10 个文件）：`uni.reLaunch` **6**（`stores/auth.uts:346`、`pages/guide/choose-cert.uvue:63`、`pages/ai-assistant/ai-assistant.uvue:623`、`pages/ai-assistant/ai-feature.uvue:376`、`pages/profile/composables/personal-info-flows.uts:362`、`pages/recruiter/login.uvue:99`）+ `uni.redirectTo` **3**（`useForgotPasswordForm.uts:242/278`、`useRegisterForm.uts:340`）+ `uni.navigateTo` **1**（着陆页入口 `pages/index/index.uvue:87`）+ **1 处路径常量**（`api/request.uts:162`，**401 学员态唯一出口**）。triage 记的 6 = 只数了 `reLaunch` 那一档。⚠️ 这些出口任何一条失去落点，语义都是「401 之后无处可去」，不是"少一个跳转"。
- **两个 ADR 的宿主同迁**：移动端 `ADR-0022`（招聘者入口「只保留学员登录页底部那一个」——宿主 = `login.uvue` 的 `.recruiter-entry`，且 `pages/recruiter/login.uvue:99` 的回学员端出口也落在这张页）与移动端 `ADR-0004`（生物识别门控回填；`pages/login/composables/useBiometricGate.uts` 注释自述"逐字搬自 `login.uvue` 的 `<script setup>`，函数体一行未改"）。删页要改的是**这两篇 ADR 的本文**，不是代码注释。
- **`pages.json:10` 属人工提交面**（页面注册条目按仓内约定由人 `git add`，agent 不得代提）⇒ 删页等于在一件"纯代码"的票里永久嵌一个人工闸口。

### 2. 开屏与登录合并成一张统一认证页 —— 被否

上面 1 的代价**全集**，再加新页与 `pages.json` 的**双向增删**（删旧条目 + 加新条目，仍是人工提交面），实际等于**重构整个移动端认证面**；而收益与 1 同为"看起来更干净"。两条判据里只有成本是真的。

### 3. 用 `#ifdef MP-WEIXIN` 做两端分叉 —— 被否

② 门（微信开发者工具无报错）的触发判据是：「**运行时面文件**（`*.uvue` / `*.uts` / 三份 json）的 diff 里增删了一条真 `#ifdef` / `#ifndef` / `#if` 指令行，且条件表达式含 `MP-WEIXIN`——**删除指令行同样算，那也改变了交付形态**」（真源：`training-app/叉车维修培训学员端跨端应用/docs/adr/0008-移动端验收门与证据.md` 的「② 触发判据的可机检口径」）。
所以走 `#ifdef` 分叉必然点亮 ② 门（要么新增指令行，要么拆掉 `pages/login/login.uvue:150-152` 那条既有的）；而运行期探测达成同等效果且**指令行增删数 = 0 ⇒ ② 门免**。#1478 两轮都是这么过的：控制器实测「抽取 `.github/workflows/pr-evidence.yml` 内联校验器跑整分支 diff + 同一正则独立扫增删行，双路一致 `needs2=false`」，且没有去拆登录页那条既有 `#ifdef`。
附带收益：探测件可被跨模块复用（#1484），`#ifdef` 分叉不可复用——它只存在于被编译进去的那一个文件里。

## Consequences

- **登录页长期存在但没有主入口地位**：它是 401 顶出、登出、找回密码回跳、注册完成、AI 助手门禁的**落点**，不再是用户主动去的地方。以后看到"这张页在 `pages.json` 里排第二却几乎没人导航到它"，那是本决定的形状，**不是残留**。
- 🔴 **模板 sha 锁的射程盲区（结构性代价，诚实披露）**：协议勾选行从 `pages/login/login.uvue:111-118` 抽成共享件 `components/login-agreement/login-agreement.uvue`（两页同源同文案）之后，`login.uvue` 的**模板整块 sha256 锁对「渲染在登录页上的这一行的文案 / 入口变化」失去感知**——那一行不再是登录页模板的字节。兜底改放在**共享件自己的契约锁**上（`utils/landingLoginContract.test.js` 的 `registerLinkCount = 1` / `registerLinkGated = false` + 两条判别力用例：`gatedByChannel` ⇒ `registerLinkGated == true` 必红、`removed` ⇒ `registerLinkCount == 0` 必红，把"按通道收回入口"和"直接删除入口"两种走偏都钉住）。⇒ 从此**「只改协议行」的 diff 在 `login.uvue` 那把锁上是绿的，这是预期行为，不是漏测**；要审的是共享件那两把。
- 协议行文案与「立即注册」入口从此**一处改两端**：不会再出现"着陆页有注册入口、登录页没有"，代价是登录页的形状审计面变小。
- 微信入口的可见性由**可用性判断**决定，不由"要不要渲染"的布尔决定（口径来自 #1482 第 5 节建议 1/2）。未接入态**不得**在 UI 写「暂不支持微信登录」这类与框架能力相反的静态文案——框架支持（uni-app x 自 HBuilderX 5.08 起 App 端可微信登录），缺的是开放平台凭证。
- iOS 侧一条硬约束留在案上：一旦 App 支持微信登录，**必须并列提供 Apple 登录**（#1482 附录一手来源第 1 条），故 Apple 登录的样式槽位应在样式阶段就预留，否则后接时被审核倒逼。
- 本 ADR **不改代码**，且**代码与文档分在两张票**：代码 = PR #1487（#1478），文档 = 本票（#1488）。这本身是一处流程代价——#1478 的票面「文档交付」段在派单时漏抄，导致文档比代码晚一轮。修法已记在 #1488 正文：**文档交付单列一张票，不再搭车。**
