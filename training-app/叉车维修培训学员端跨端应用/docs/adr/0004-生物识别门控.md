# Biometric-Gated Remember Password

登录页"记住密码"功能采用生物识别门控回填策略：用户勾选记住密码并成功登录后，凭据被持久化存储，但**不在下次启动时自动回填**。取而代之的是展示一个"指纹/面容解锁填充"入口，用户点击后触发设备生物识别（或降级方案），验证通过才将账号密码回填到输入框。此设计在便捷性与安全性之间取得平衡——设备被盗时，攻击者无法直接获得凭据。

**凭据存储**：当前 demo 阶段使用明文存储（`secureStorage.uts`），生产环境采用自研 UTS 原生插件（见 ADR-0005-自研安全存储），直接调用 iOS Keychain + Android Keystore，零成本且无外部依赖。

**平台降级策略**：Android/iOS/微信小程序走真实 SOTER 生物认证；H5 用弹窗模拟（`confirm()`）；支付宝等不支持 SOTER 的平台降级为"仅记住账号"（不保存密码，每次手动输入）。

**凭据生命周期**：凭据永不清除，除非用户主动取消勾选"记住密码"后重新登录。登出操作不清除凭据——这是有意设计，记住密码的核心价值就是跨会话保持。修改密码时后端使旧 token 失效，间接实现凭据失效。

**Considered Options**：
- 直接回填（无验证）：体验最好，但设备被盗即可用，安全风险过高
- 服务端下发加密密钥 + 本地 AES：增加服务端复杂度，且密钥分发本身有安全风险
- OS Keychain 原生封装：自研 UTS 插件直接调用 Keychain/Keystore（见 ADR-0005-自研安全存储），零成本且代码可控

**Consequences**：
- `secureStorage.uts` 作为抽象层，生产加密方案可透明替换，无需改动调用方
- H5 的 `confirm()` 模拟仅用于开发调试，生产 H5 环境需额外评估 WebAuthn 方案
- 账号降级（仅记住账号）意味着不支持密码的平台用户体验有所退化
