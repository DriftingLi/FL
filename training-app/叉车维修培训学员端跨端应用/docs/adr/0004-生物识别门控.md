# Biometric-Gated Remember Password

登录页"记住密码"功能采用生物识别门控回填策略：用户勾选记住密码并成功登录后，凭据被持久化存储，但**不在下次启动时自动回填**。取而代之的是展示一个"指纹/面容解锁填充"入口，用户点击后触发设备生物识别（或降级方案），验证通过才将账号密码回填到输入框。此设计在便捷性与安全性之间取得平衡——设备被盗时，攻击者无法直接获得凭据。

**凭据存储**：当前 demo 阶段使用明文存储（`secureStorage.uts`），生产环境采用自研 UTS 原生插件（见 ADR-0005-自研安全存储），直接调用 iOS Keychain + Android Keystore，零成本且无外部依赖。

**平台降级策略**：Android/iOS/微信小程序走真实 SOTER 生物认证；H5 用弹窗模拟（`confirm()`）；生物识别不可用（平台不支持 SOTER，或设备未启用任何生物识别方式）时降级为"仅记住账号"（不保存密码，每次手动输入）。

**孤儿凭据自愈**：保存凭据后设备侧生物识别被移除（用户删除指纹/面容、硬件失效）时，已存密码密文永远无法解锁。登录页在获得确定性的"设备不支持"结果（`checkIsSupportSoterAuthentication` success 回调且 `supportMode` 为空）后，将完整凭据降级为仅记住账号。API 调用失败（fail 回调）不代表设备失去生物识别，**不触发自愈**——瞬时错误不可逆地清除用户数据代价比残留密文更高。

**快捷登录（refresh_token 凭证化）**：生物验证通过后不回填表单，而是用本地加密保存的 refresh_token 调 `/auth/refresh` 静默续登直接进入应用。凭证选型取 refresh_token 而非密码密文：refresh 因轮换与 7 天滑动过期自我失效（泄露窗口有限），密码密文即凭证则是无限重放的自动登录凭证。密码密文继续保留作为兜底——refresh 失效（超 7 天未用、多设备互踢、后续改密吊销策略生效）时降级为既有"回填表单+手动登录"流程。入口为单入口双轨：文案按 `supportMode` 动态生成（面容/指纹/生物识别），快捷登录失败降级时提示用户。refresh_token 轮换后新令牌由 auth store 既有 `setAuthData` 路径持久化，滑动续期成立。

**凭据生命周期**：凭据永不清除，除非用户主动取消勾选"记住密码"后重新登录。登出操作不清除凭据——这是有意设计，记住密码的核心价值就是跨会话保持。修改密码后，已存凭据不自动失效，而是依赖服务端密码校验自然拒绝（自愈式覆盖），详见 ADR-0006 的相关缺口记录。

**Considered Options**：
- 直接回填（无验证）：体验最好，但设备被盗即可用，安全风险过高
- 服务端下发加密密钥 + 本地 AES：增加服务端复杂度，且密钥分发本身有安全风险
- OS Keychain 原生封装：自研 UTS 插件直接调用 Keychain/Keystore（见 ADR-0005-自研安全存储），零成本且代码可控
- 快捷登录凭证取密码密文：无 7 天失效坑，但密码成为无限重放的本地自动登录凭证，设备被 root 提取后永久沦陷；refresh_token 方案泄露窗口以 7 天为上限

**Consequences**：
- `secureStorage.uts` 作为抽象层，生产加密方案可透明替换，无需改动调用方
- H5 的 `confirm()` 模拟仅用于开发调试，生产 H5 环境需额外评估 WebAuthn 方案
- 账号降级（仅记住账号）意味着不支持密码的平台用户体验有所退化
