# 0046 - 本地不重复持续集成：编译载体三档与行为腿子集

**状态**：已接受（2026-10-27，来源：#1986 wayfinder 地图收口后的 `/grill-with-docs` 裁定会话；证据 #1987 / #1989 / #1997 / #2013，落地票 #2015）

> **一句话**：`#1997` 的选档规则**只进文档、不进脚本**，四档砍成三档（D4「引用上次结果」仅允许人手动）；本地行为腿由「全量约 30 分钟」改为「受影响子集直跑 jest，全量交 CI」，映射覆盖率 <90% 则整个方案不做。

## ① 目标与范围

按「**耗时 × 频率**」重排本地验证，而不是按「单段最大」。#1986 的地图只算了单段墙钟，于是把 ④a 全量编译（945 s）排在了最前面；但 ④a 只在 dev 专属面才跑，而本地行为腿**每次收口都跑**（约 30 min，含离群可到 42 min+）。乘上频率之后，后者是更大的池子，也是本 ADR 的主目标。

**范围**：本地「跑什么、用哪个载体」——④a 的三个载体档位 + 本地行为腿的形态。

**不含**：门语义与判据、④ 门的触发面、CI 片数与权重、被测代码本身。

## ② 选型 + 一句理由

| 决策 | 一句话理由 |
| --- | --- |
| **D1 必须清缓存全量（945 s）**：命中 `manifest.json` / `pages.json` / `platformConfig.json`、新增 `.uvue` 页、或打包面（`uni_modules/**/utssdk/app-android/**`、`*.aar`、`libs/*.jar`） | 页面图与原生面变了 ⇒ kotlinc 的**输入集**变了，`class/` 缓存不可信（#1997 反例 1：只改 `pages.json` 一行却走 D2，新页没进产物而显示「编译成功」） |
| **D2 不清缓存（257 s）**：只改既有 `.uvue` 的模板/样式，或**同签名内**的 `.uts` 实现改动 | 全量 72% 花在整模块 kotlinc（445.9 s）+ dex 化（229.0 s），与「改了哪一页」无关（#1997 归因表）；257 s 是 **2026-09-14 读数、未复测** |
| **D3 只跑 ④c（214 s）**：只有 `.uts` 逻辑层改动 | ④c 的整模块语义比 ④a 的增量语义**更强**，不是放宽（ADR-0008：dev 编译缓存不是自洽的编译单元） |
| **D4 不进自动档**：「引用上次结果」只允许人**手动显式**引用 | 它建立在「祖先链上没有运行时面改动」这个看不见的事实上，错的时候不留痕 |
| **规则只落本 ADR 与 `docs/agents/dev-loop.md`，不进任何脚本、不改默认值** | 失效模式是**静默假绿**且无痕：脚本判错一次，会在很久以后才发现；人选错至少会被 CI 或发版冒烟撞见 |
| **本地行为腿：受影响子集 `jest --config jest.config.behavior.js --runTestsByPath <子集>` 直跑，全量交 CI 4 片** | 同一批测试 CI 9 分钟、本地 30 分钟，差的是并行度不是测试本身；直跑绕开 #2013 的驱动三处缺陷（env 注入 / 码页 / 套件顺序），不被三张 bug 票抵押 |

## ③ 明确不做的事

- **不做**自动选档脚本、不动 `-Clean` 默认值（理由见 ② 第 5 条）。
- **不改** ④ 门触发面（ADR-0008）、**不改** `-i` 串行与腿内并行禁令（ADR-0042）。
- **不在任何文档写死套件数**——四天内出现过 70 / 72 / 75 / 76 / 78 五个值 ⇒ 一律写「以 `node scripts/classify-guards.mjs` 现测为准（日期 + 当次数值）」。
- 其余继承 #1986 的 Out of scope（不做 E2E、不做多树并行换编排、不用 `miniprogram-ci` 替 ② 门、④c 不改差量），此处只指向、不重复展开。

## ④ 拆分步骤

1. 本 ADR + `docs/agents/dev-loop.md` 三小块（套件数改现测口径、补 257 s 与「④a 不含打包段」、④a 归因表入根 `docs/design/`）——同批收，见 #2015。
2. **覆盖率研究票**（可并行）：产出全量行为套件的「改动路径 → 套件」映射表与覆盖率数字。两条兜底边必须写进去：
   - **门脚本 / workflow 改动 ⇒ 全跑**（约 55% 的行为套件是起子进程真跑 `.ps1`/CLI 的 d 类，耗时不由被测代码决定）；
   - **`readText` 后字符串替换注入缺陷的套件 ⇒ 全跑**（隐性 b 类：等价重构也会红）。
3. 覆盖率 **≥90%** ⇒ 实施票（子集直跑 + 两条兜底边）；**<90%** ⇒ 关票，并给本 ADR 标 `superseded`。
4. #2013（`dev-finish` 驱动形态三处红）独立修，**不阻塞第 3 步**——子集直跑不走该驱动器。

## ⑤ 约束（不能动的）

- 门语义、④ 触发面、`-i` 串行、ADR-0042 的腿内并行禁令一字不动；本 ADR 只改「本地用哪个载体」，不改「门判什么」。
- HBuilderX 是**单实例串行资源**：子集直跑不碰 HBuilderX，但不得与 `hx-run` / 编译门抢锁，也不得 kill 主程序。
- 引用本目录 ADR 须**写全路径**（根仓库另有同号 ADR，两套编号体系互不相关）。
- `dev-loop.md` 是**唯一**的权威时间账；其余落点只指向它，不复制数字表。

## ⑥ 验收标准

1. 本 ADR 落 `docs/adr/`，编号无冲突（现最大 0045），六段体齐。
2. `dev-loop.md` 三小块可 grep 到；旧数字保留并标「已退役」；权威时间账仍只有一份。
3. 覆盖率报告存在且给出具体百分比；**未达标不得进入实施**。
4. 实施后首次真实验收：一个纯 `.uts` 改动的 PR 走 D3、一个纯样式 PR 走 D2，各自贴出实际墙钟。
