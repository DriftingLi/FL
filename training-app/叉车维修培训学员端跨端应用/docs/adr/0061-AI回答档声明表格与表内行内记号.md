# AI 回答：表格入档 + 表内行内记号

- 状态：已采纳（2026-11-10，#2398 实施同批写入；修订 ADR-0056 决定 1 的档位成员表）

## 背景

ADR-0056 的 AI 回答档有意不声明 `table`，注释原话「窄气泡里按行退回原始文本」。诊断回答大量出现「首位节点码 / 所属系统」这类对照表，学员在微信小程序里读到的是 `| 首位节点码 | 所属系统 |` 竖线原文（#2396 / #2398）。共享块渲染件（`components/markdown/markdown-blocks.uvue`）本来就有表格分支，章节正文一直在用 —— 缺的只是「AI 档声明它」与「气泡能力位传它」这两处。

## 决定

1. `SUBSET_MEMBERS_AI_ANSWER` 增 `MEMBER_TABLE`；`AI_ANSWER_CAPS` 同批增 `'table'`。两处缺一处，表格块在气泡里静默消失且日志无异常（本票 AC① 钉的就是这个失败模式）。
2. 表格单元格改走 runs（`runsOf(cell)` + `tableRunClasses`）：声明 `inline` 的档里单元格存的是行内源串，直出会把 `**粗**` / 行内码原样吐出来（AC④）。
3. 表内字号**另立** `.md-sz-table`（26rpx / 40rpx），不取所在块的 tier：`markdownTypography` 把 table 归正文档（body 30rpx），照 tier 走会把表内文字顶大一档，等于顺手改了表格刻度。表头另叠 `.md-run-table-head`（加粗 + 深色），因为父 `.md-table-cell-text-head` 带不到子 `<text>`（ADR-0025 C1）。
4. 不新增横滑容器 / 折叠 / 列宽自适应（AC⑥）：四列以上挤压换行是已接受的代价。

## 后果

- 章节档与 AI 档**都**出表格块；论坛 / 精选两档仍不声明，退回逐行段落（兜底边口径不破）。
- 契约镜像（`markdownContract.test.js` 的 `SUBSET_MEMBERS_AI_ANSWER` 与 caps 断言）、`markdownSubsetBehavior` 的「AI 档不声明 table」与「章节档是唯一出表格块的档」两条断言、`aiAnswerBodyBehavior` 的「表格保持论坛档降级」断言与「档位拿错」变异用例同批改；变异目标从章节档换成论坛档（章节档现在也声明 table，不再能区分）。
- 真机可见性（表头行与正文行有可见区分）在 PR 粒度无法取证（② 已于 #2320 退役、①a 降级为发版冒烟）⇒ 落点改为发版冒烟，见 #2392。

## 不采用的备选

- 让表格块在 AI 档走独立渲染分支：与「一套刻度四面共用」冲突，且章节面已有的表格分支会分叉成两份。
- 表内文字跟随正文档 30rpx：改动更小，但等于把表格刻度改掉，超出本票「只让记号生效」的范围。
- 单元格直出 + 渲染层再剥一次记号：等于在渲染层重建第二套记号规则，与分词器两表必漂移。
