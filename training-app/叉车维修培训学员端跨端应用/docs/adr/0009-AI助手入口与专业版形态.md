# 0009 - AI 助手入口与专业版形态

**状态**：定稿（grilling + 原型三分支判定，2026-09-12）；**2026-09-13 修订**：版本由「退场」改为**保留为页内能力态 + 入口横幅**（见文末「修订记录」）—— 来源 issue #911；**2026-09-15 修订**：专业版**重定位**（「选模型」放开为免费）+ 入口形态改为**通用页 + 参数化专项页**（见文末「修订记录」）；**2026-09-15 再修订（#1024）**：**能力面**（配置 / 使用 / 管理入口）一并入门 + 「自带 key 的选用」裁定归 pro（见文末「修订记录」）
**职责边界**：裁定移动端 AI 助手的**入口形态**与**专业版（AI pro）的表达**；不动计费口径（根仓库 `ADR-0031` 计量闸门 / 限免声明）、不动验收门（本目录 `0008`）

## 背景与目标

移动端 AI 助手现有三页：网关页 `version-select`（原生「AI学」tab 的落点）、会话页 `ai-basic` 与 `ai-assistant`。网关页在 `onLoad` 按本地版本标记 `reLaunch` 跳走 —— **一跳就离开 tab 页，系统原生底部栏随之消失**，于是两个会话页各自手画了一个 `TabBar` 顶上（`git grep 'tab-bar/tab-bar'` 全项目仅此两页）。

手画栏要求页面自己把「贴底 + 安全区」都算对 —— 而这两件事系统原生栏本来就不需要页面操心。2026-09-12 一晚连出两个真机回归，全部落在这个面上：

- 页面根 view 用 `height: windowHeight`（该值在两次页面实例化之间取值不同）⇒ 栏**悬空约 247px**
- 组件用 `getSystemInfoSync().safeAreaInsets` 补底部内边距（取不到时**静默跳过**）⇒ 栏**偏下约 43px**（设备 `dumpsys` 实测 `navigationBars` inset = 48px）

目标：**去掉这个易碎的面**，并把「专业版」从「入口处选一个版本」改成「用功能时解锁」。

## 决策清单（六段）

① **目标与范围**：AI 助手改为**单页**；入口不再选版本；专业版改为**积分商城可兑换的权益**。只动移动端 AI 模块的入口与页面结构。（**2026-09-15 修订**：页面形态改为「**通用页 + 参数化专项页**」—— 「单页」在**页面数**上被修订，见文末「修订记录」。）

② **选型 + 一句理由**：
- **入口 = 原生「AI学」tab 直接落会话页**（保留 `ai-assistant`，删 `ai-basic` 与 `version-select`）—— 一跳即 tab 页，原生栏永不消失。
- **专业版 = 积分商城 SKU 的「已拥有」**（复用 redeem 单管线与 `HasEntitlement` 判定）—— 本地 mock 付费（`aiPay.uts` 全套：`ai_version` / `ai_pro_paid` / `mockPay` / `PRO_PRICE_*`）**全部删除**。（2026-09-13 修订：页内保留**能力态** `proUnlocked`，它由「已拥有」派生，**不再是可切换的页面或网关**。）
- **被锁能力的表达 = 欢迎区档位横幅**（原型三分支判定胜出，见下「被否备选」）—— 保住兑换的主曝光位，同时输入区不留锁标、会话界面保持干净。

③ **明确不做**：不碰计费口径（tokens 计量、限免声明位不动）；不改后端 AI 功能注册表键；**不引入「普通/专家」双绑定**（web 端 `ai_assistant_normal/expert` 那套 —— 移动端仍直接挑 admin 模型）；不动 `ai-settings` / `custom-models` 两个推入页。

④ **拆分步骤**（两票，**先结构后门**）：**结构票**（单页 + 删手画栏 + 删 mock 付费，见 #911）→ **门票**（后端列可兑换项接口 + 建 AI pro SKU + 移动端兑换界面 + 横幅 + 门）。

⑤ **约束**：uni-app-x（uvue）—— 只 class 选择器、不支持 `gap` / CSS 变量 / tag 选择器；改 `pages.json` ⇒ 命中 `0008` 的「打包面」而**触发 ④b release 云打包门**；删页须清干净所有 `reLaunch` 引用。

⑥ **验收标准**：AI 页在**任意路径下底部都是系统原生栏**（切页后也不变）；无**页面级**版本态残留（不再有「选版本」网关与两个版本页；页内 `proUnlocked` 能力态属预期）；`version-select` / `ai-basic` / `utils/aiPay.uts` / `components/tab-bar/` 与 mock 付费代码**零引用残留**；默认按基础版能力渲染（模型芯片只读、无附件按钮）；「解锁专业版」横幅可见且点击只给提示（**兑换未上线，不做任何付费动作**）；④a + ④c 编译门通过；真机逐页截图（①，人工门）。

## 被否备选

- ~~**版本作可切换的态**（保留「基础版 ↔ 专业版」切换）~~ —— **2026-09-13 修订：此条被采纳**（见「修订记录」）。当时否决的理由（「解锁后切回基础版没有语义」）在「兑换未上线、界面需要一个可见入口」的现实下不成立。
- ~~**把选择时机后置但保留版本叙事**~~ —— **2026-09-13 修订：方向被采纳**（默认基础版 + 用功能时提示），但**不持久化「上次选择」**（能力态由「已拥有」派生）。
- **原型变体 A · 就地能力锁**：被锁能力留在原位带锁标 —— 可发现性好，但输入区常驻锁标，与「会话页干净」冲突。
- **原型变体 C · 隐身 + 单一出口**：会话页零痕迹、入口只在我的/设置 —— 被维护者否，理由是**积分兑换会失去主曝光位**。
- **原型变体 C′ · 独立专业版页**（C 的修正版：抽屉里有实打实入口 + 独立推入页）—— 结构上可行，但把「专业版」推到一个二级页，兑换曝光仍弱于首屏横幅。

## 修订记录（2026-09-13）

**改了什么**：版本概念**不退场**，改为「**页内能力态 + 欢迎区入口横幅**」；默认基础版，专业版经积分兑换解锁。

**为什么改**：实施（#923）面对两个现实 —— ① **积分兑换尚未实现**，若按原裁定「版本叙事退场、只留能力门」，专业版在界面上**完全没有可见入口**，用户不知道有这个档位（这正是当初否决原型变体 C 的理由：兑换失去主曝光位）；② 维护者需要「现在主要是基础版，专业版走积分兑换」这个叙事留在界面上。

**与原裁定的关系**：原裁定反对的是「版本作为**可切换的页面 / 网关**态」（两页 + reLaunch ⇒ 原生栏消失），这一点**不变** —— 仍是单页、仍走原生栏、仍无网关页。改的只是：页内保留一个能力态 `proUnlocked`，并给它一个横幅入口。

**实施现状（#923）**：`proUnlocked` 恒 `false` ⇒ 所有用户按基础版能力渲染；横幅点击 → toast「积分兑换即将开放」；mock 付费已全部删除，本改动不含任何支付动作。#920 上线时把 `proUnlocked` 改读后端「已拥有」判定、横幅 CTA 换成真兑换。

**同步**：根 `CONTEXT.md`「AI 专业版」词条随之改写（去掉「不是页面级的版本态」这类与新决定冲突的表述）。

## 修订记录（2026-09-13 · #920 实施）

**改了什么**：把「专业版 = 积分商城 SKU 的已拥有」这条裁定**按移动端范围落地**（后端不在本票内），并补三条实施口径。

**落地面（#920）**：`composables/useAiPro.uts`（门的事实源 + 兑换，单点适配器）+ 欢迎区档位横幅两态 + 能力清单/兑换半屏 sheet（`components/ai-chat/ai-chat-pro-sheet.uvue`）+ 兑换成功原地刷新门状态。档位：SKU `ai_pro`、1000 积分、**永久**（`user_entitlement` 无过期列，期限语义无处承载）。

**三条实施口径（本票新定，后续会话不得各立一套）**：

1. **门的事实源本轮用支出流水推导**：后端未提供「列可兑换项 / 暴露权益」的接口、`user_entitlement` 无读面 ⇒ 已拥有 ⇔ 支出流水里存在 `reason='redeem_ai_pro'` 且 `ref_type='shop'` 且 `ref_id='ai_pro'`（三字段全等，防子串假命中）。有界扫描（100 条/页 × 10 页），超限置 `degraded`（结论不可靠），此时 CTA 保持可点，以服务端「已兑换」应答**自愈**——不把已付费的老用户锁在门外。**代价如实声明**：事实源在历史面而非权益面；`AI_PRO_PRICE = 1000` 是移动端常量（后端未暴露价格），改额度须两处同步。**后端接口就绪后只改这一个文件**（换读 `GET /points/shop` 的 `owned`/`price`），页面与组件零改动。
2. **图片门只锁通用助手通道**（`feature_key` 为空或非注册功能键）：web 的三个识图功能（`drawing` / `exercise` / `fault_diagnosis`）走专项功能键，属「功能注册表已声明」的能力，不在「用户自选」这条门内。统一原则：**门锁「用户自选」，不锁「注册表已声明」** —— 这条使「锁自定义模型/选模型」零 web 回归成为可能。
3. **web 端不在本票范围**（维护者 2026-09-13 改判：「无关 web 端」）：原文 D 裁定「同步 web」**撤销**；web 若要同步（含撤掉 `stores/aiAssistant.ts:242` 的 legacy `config_id`）须另立票。

**未满足项（如实记录，不得以「已完成」口径收口）**：

- **验收标准第 3 条**（未解锁时服务端拒绝被锁能力）**未满足**：本票不含后端改动，`/api/ai-assistant/chat` 仍为 OptionalAuth，绕过客户端即可用被锁能力。后端门落地时须同步改移动端 `buildBody`（基础版改送 `mode='normal'` 并去掉 legacy `config_id`；**前置条件**是管理端已绑定 `ai_assistant_normal`，否则基础版对话会报「该模式未绑定模型」）。
- **SKU 未上架**：`points_shop_item` 无 `ai_pro` 行（本票不含迁移）⇒ 真机兑换会得到 400「商品不存在或已下架」（客户端按可读提示呈现，不静默）；**已解锁态因此暂无法在真机观察**，① 真机门本轮只能验未解锁态。

## 修订记录（2026-09-15 · 入口与专业版口径定稿）

**改了什么**（两条）：

① **专业版重定位**：**「选择模型」放开为免费**；专业版只卖真能力 —— **自定义模型**（自带 key），**图片能力落地后再并入**。能力清单里**不再出现**「选择模型」（已免费）与「发送图片」（**功能根本不存在**：`onImageClick` 只 toast「图片发送开发中」）。（连带：输入区模型芯片的 `proUnlocked` 门随之去掉；右抽屉「自定义模型」菜单项**仍**由门过滤。）

② **入口形态**：由「单页（`ai-assistant`）+ 宫格」改为「**通用页 + 参数化专项页**」—— **1 个页面 + `featureKey` 参数**，照 web 一条参数化路由的形态（`frontend/src/config/pages.ts:194` → 同一个 `FeatureChatPage.vue`），**不是 4 个页面文件**。入口清单**收敛到功能注册表的 4 项**（`maintenance_knowledge` / `drawing_recognition` / `exercise_solving` / `fault_diagnosis`）；**「故障代码查询」下线** —— 它在注册表里**没有键**（根仓库 `ADR-0032` 决策 3 已下线 `fault_code_query`），留着就是个「点了走通用对话」的伪入口。⇒ **`#971` 原口径（只接故障代码查询 → `fault_diagnosis`）作废**，该票需重写或关闭。

**同批定稿的配套口径**（均属移动端实现面，故不另立 ADR）：专项页第一版 = **文字 + 品牌/车型/故障码检索**，**不含用户上传图片**；品牌/车型**拼进消息文本**（web 诊断页 `buildContent` 对诊断直接 `return text` ⇒ 客户端一处改动即让筛选真生效，**零后端改动**）；清单与文案移动端**继续手写 + 契约测试锁一致性**（键集合 / 展示名 / 限免位 == 注册表）；**专项页会话按功能键真分区**（另立本目录 `0013`）；专业版**可购买**（`points_shop_item` 插 `ai_pro` 行，独立后端票）；横幅只写「**解锁专业版**」+「查看权益」，**去掉副标题与能力清单**。

**为什么改**：

- 现状锁的三件事**一件比一件站不住**：`选择模型` 只从管理员已配置的模型里挑一个（用户感知弱）；`发送图片` **功能不存在**（专业版锁了一个空壳按钮）；只有 `自定义模型` 站得住。继续挂一个**买不到、又锁着空壳**的档位不诚实。
- 单页**无专项分区** ⇒ 专项会话混进首页抽屉，且根仓库 `ADR-0033` 的「历史回放（含来源）」在专项语境下**没有承载面**（学员看到的就是「刷新后来源消失」形态）。

**与原裁定的关系**：原裁定反对的是「版本作为**可切换的页面 / 网关**态」（网关页 + `reLaunch` ⇒ 原生栏消失），这一点**不变**：仍无版本网关、仍不手画栏、仍落原生「AI学」tab。本次修订的是**页面数**（「单页」→「通用页 + 参数化专项页」，专项页是**推入页**）与**专业版卖什么**。被否备选里的「原型变体 C′ · 独立专业版页」仍**不被采纳** —— 那说的是**专业版**的页，不是**专项功能**的页。

**同步**：根 `CONTEXT.md`「AI 专业版（AI pro）」词条随之改写（去掉与新定位冲突的表述）。

**未满足项（如实记录，不得以「已完成」口径收口）**：

- **SKU 仍未上架**：`points_shop_item` 无 `ai_pro` 行（本次复核 `backend/migrations/*.sql` grep `ai_pro` **零命中**）⇒ 真机兑换仍会 400「商品不存在或已下架」，**已解锁态仍无法在真机观察**（① 真机门仍只能验未解锁态）。
- **权益读面接口仍缺**：`backend/internal/api/points.go` 只有 redeem 端点；`useAiPro` 仍靠**支出流水**推导（三条实施口径见上一节）。
- **后端仍不真的拦**：`/api/ai-assistant/chat` 仍为 OptionalAuth，绕过客户端即可用被锁能力。

## 修订记录（2026-09-15 · 能力面收口 #1024）

**改了什么**（一条裁定 + 三处落点）：

① **「选用已保存的自定义模型」的裁定（维护者 2026-09-15，本票拍板）**：在对话设置页的「已保存模型」里**选用**一个自带 key 的模型，**算专业版能力（归 pro）**。与上一条「『选择模型』放开为免费」的边界由此说清：**免费的是「从管理员已配的平台模型里挑一个」**（`model_source == 'admin'`），**收费的是「自带 key 的模型」** —— 它的**配置面**（填 Base URL / Model / API Key）与**使用面**（选用已保存的模型 / 临时自定义）两面都归 pro。原「选模型放开为免费」的语境是**用户感知弱**的一步（只从管理员已配的模型里挑），不含自带 key 这一层。

② 门的**事实源**收成单点：对话设置页不再自持页面级 `proUnlocked` 常量，改与 AI 助手页读同一个 `composables/useAiPro.uts`。页面级常量是 #936 为避开与 #942 撞车而刻意为之，该前提已随 #942 合入消失。

③ 门的**落点**补齐（口径 A 关的是「页面入口」，**不是能力本身** —— 本票补的正是能力面）：
- **对话设置页**：配置表单（`model_source == 'custom'`）与已保存模型列表（`user` / `custom` 两来源共用）在门内；**未解锁时来源选择器只剩「平台模型」一项** —— 不留「选中了来源、下方却一片空白」的死行。
- **模型选择器**（三条同能力路径，此前都靠「芯片本身不渲染」间接挡住）：③「管理自定义模型」未解锁 ⇒ 走本页档位 sheet（与模型芯片点击同一入口），不跳 `custom-models`；④「自定义 API Key」同样过门；⑤ 已保存的自定义模型**不进选择器列表**。

④ **存量回收**：自带 key 的来源是**本地持久态**，而 `buildBody` 正是按它送 `user_model_id` / 明文 `custom_api_key` ⇒ 只关入口会漏掉「存量已选仍在生效」。**未解锁时两页都把来源回收为「平台模型」并落盘**。

**为什么改**：口径 A 当时只把「进 `custom-models` 页」这一步收进了门，「进页面之外的配置 / 使用 / 管理」三条路径都不过门 —— 与本节上一条「专业版只卖真能力：自定义模型（自带 key）」的定义直接冲突；且「选模型放开为免费」一旦落地（芯片常显），选择器那三条路径会**立刻**变成不过门的直通路径。

**与原裁定的关系**：不推翻 2026-09-15 已定稿的两条；**口径 A 不变** —— `custom-models` 目标页仍未动、不把「对话设置」整项从抽屉里藏掉，门仍落在入口与能力面上。③「明确不做」段那句「不动 `ai-settings` / `custom-models` 两个推入页」指的是**口径 A 的门落点**（不在该页做页面级改造，如「整页只读」）；该句本身的回写属 #939，本票不改它，以免与该票的文档改动撞车。
