# 0040 - 小程序优先窗口的验收门槛口径（2026-10-15 裁定）

- **日期**：2026-10-15
- **关联**：#1608 / #1609（现状登记段是本裁定的准据，写本 ADR 时以这两处为准）· #1661（口径回写先例）· map #1591 · #1694（本 ADR 的落库票）
- **承接**：`0039`（小程序优先窗口，2026-10-13 合并起）——本 ADR 把 2026-10-15 收口会话的裁定成文，**收紧** 0039 的两条口径，其余不变
- **状态**：已裁定（窗口开关仍 = 人裁；本 ADR 是窗口口径，不是开关本身）
- **编号说明**：本文件属**移动端** ADR 编号体系；根仓库另有同号 `docs/adr/ADR-0040-论坛意图与认定分离.md`，两者无关。移动端代码里 22 处裸引「ADR-0040」（`api/forum.uts` 等）指的是**根仓库**那份论坛契约，引用时必须写全路径区分。

## 背景

- 0039 合并后窗口实际运行两天，2026-10-15 收口会话把口径进一步收紧。裁定当时只落在票面：#1608「现状登记（2026-10-15 05:40）」与 #1609「现状登记（2026-10-15）」，两处均注明「ADR-0040 尚未落库，回写时以这两处为准」。本 ADR 即该成文载体。
- 现实压力：真机设备 `23049RAD8C` 自 2026-10-14 22:05 离线（无线调试租约过期，需人手机重新配对，agent 代不了）；样式批次只剩批 6 六页，窗口边际收益趋零而真机欠账在累积。
- 冲突点：0039 决策 4 写「能力面签收不随窗口延后」（意思是窗口内照跑、照签），而 2026-10-15 裁定是「窗口内触及能力面的 PR 一律不合并、排队到退出后」——两者必须择一，本 ADR 择后者。

## 决策

1. **窗口内真机逐页取证 = 完全不跑**（不是 0039 的「按批收口跑一次」）。PR 里真机那一行如实写 `SKIP·待批收口（ADR-0039 窗口口径）`，**不携带任何真机结论**（「未验证禁写已通过」总纪律不变）。收口批的触发也改为**批触发改**：批收口跑不跑真机，由当批是否触及硬判据另行裁定，不再固定为每批必跑。
2. **小程序门 = 每个运行时面 PR 必跑**（0039 里已是主门，此处升为纪律层的无条件项）。门本身行为不变。脆弱性如实登记：`.github/workflows/pr-evidence.yml` 的小程序门触发判据只认 manifest / platformConfig 三份 json 与 MP-WEIXIN 条件编译 ⇒ **纯 `.uvue` 改动的小程序门无机检兜底**，靠纪律执行，不假装有闸。
3. **视觉回归在窗口期内明确记为「无人验」**。不装兜底、不用小程序截图冒充：`scripts/mp-weixin-check.ps1:28` 自述本门只做 page 级导航 + console/exception 判定 + 整页截图，**不得**加元素级断言，它兜不住视觉回归。
4. **欠账登记 = 32 页，退出时逐页真机 + 人看完**：批 4（N01 19 页）+ 批 5（N05 7 页）+ 批 6（N06 6 页）。必须是**人**的理由：`docs/verification/device/1075/README.md:50`「本会话没有人目视核对过图内容」、`docs/verification/device/1080/README.md:36`「本机无本地 OCR 引擎」——0016 允许的「真机逐页取证执行人 = agent 执行」只在有行号/日志/机检行可依的批次上成立，样式像素判断不在其内。
5. **能力面冲突裁定（覆盖 0039 决策 4 的运行方式）**：窗口内触及能力面（指纹 / 运行时权限弹窗 / 真机上传 / 厂商 ROM 交互）的 PR **一律不合并、排队到窗口退出后**再走原流程（含真机人工签收）。注意这不是「把签收延后做完」，而是**把整个 PR 推到退出后**——窗口内既不降档也不代签。
6. **退出条件不变、退出前置新增**：退出 = 进发版 / 能力面冲刺，或人点名（同 0039）。新增前置：**欠账 32 页逐页真机 + 人看完成，才发版**；排队的能力面 PR 在退出后按 0008 / 0016 原口径收口。

## 后果

- **正**：窗口内每个运行时面 PR 只剩小程序门 + CI，真机串行瓶颈（10–20 分钟/次 + 单实例设备）全开；欠账从隐性变成 32 页的显式清单，退出时有唯一待办。
- **负 / 代价**：窗口内真机问题（真机独有交互、样式像素）不暴露，全部推迟到退出后集中爆发，退出批需预留返工缓冲；能力面 PR 在窗口内堆积不进。
- **接受的风险**：纯 `.uvue` 改动的小程序门靠纪律不靠机检（决策 2 的脆弱性）；视觉回归窗口内无人验（决策 3）——两条都是**明知不兜底而接受**，不是遗漏。
- **可逆性**：窗口退出即回 0008 / 0016 / 0039 原口径，无代码回滚成本；欠账清零是退出的文档性前置，不产生新机制。
