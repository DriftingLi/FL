# 职位列表证件筛选组只列当前职位实际要求的证件

- 状态：已采纳（2026-11-11，#2422 实施同批写入）

## 背景

`#1945`（spec `#1935` 草稿 19）把移动端职位列表的证件筛选组定成**全量证件字典**（`getAllCredentialsApi` 分组拍平）：字典里没有任何在招职位要求的证件也照样占位，列表顶部出现一长串与当前内容无关的标签；用户判定不符合预期（#2422）。此前筛选组与职位数据完全解耦，也没有任何函数能从职位聚合出证件。

## 决定

1. 数据源改为**当前职位列表**：`utils/jobCredentialDisplay.uts` 新增 `collectRequiredCredentials(jobs)`，按职位顺序 + 职位内顺序拍平、按 `credential_id` 去重、剔除 `<= 0` 与空名条目。
2. 页面在会话内累积已见证件（`knownCredentials`），翻页 / 切换筛选不缩水；选项仍由 `buildCredentialFilterOptions` 构造（首项「全部证件」）。
3. 删除页面对 `getAllCredentialsApi` 的调用；重建筛选组后按 `credential_id` 把选中项对回去，不按旧索引硬指。
4. 行为腿新增聚合用例与「不去重必红」成对取证；接线腿钉「页面不再拉全量字典」与「选项经聚合函数 → `buildCredentialFilterOptions`」。

## 后果

- 筛选组 = 列表实际要求；无任何职位要求时整行不渲染（沿用 `length > 1` 守卫）。
- 首屏只显示第一页涉及的证件，随翻页增长；累积不缩水是刻意取舍（否则切换筛选后选中项消失、无法切回）。
- 证件字典接口在本页不再被调用；其他页面自己的字典使用不受影响。

## 不采用的备选

- 收进抽屉 / 整组删掉（用户否决：要筛选，但要贴合列表现状）；只按当前页裁剪且不累积（选中项会消失、无法切回）。
