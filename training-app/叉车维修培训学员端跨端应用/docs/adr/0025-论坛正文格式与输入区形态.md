# 0025 - 论坛正文格式与输入区形态：声明子集第三档 + 渲染接入 + 输入区

**状态**：已接受（2026-09-21，来源：grilling 逐条定案（仅移动端范围，参照根仓库 ADR-0052 的**目标**而非结论）；落地：**#1240 单票三段** —— P1 逻辑面 / P2 渲染接入 / P3 输入区形态，**三段均已落地**；Web 侧口径债归 **#1241**）

> **一句话**：移动端论坛**从来没有格式轴** —— `content_format` 在移动端 0 命中、`forum-topic-body.uvue` 对 Web 发来的 Markdown 帖**直出源串**（读者看到 `**故障码**` 的星号）；本 ADR 记下「为什么先补渲染欠账、为什么移动端子集与 Web 不同、为什么本期不做行内渲染」，并把子集收成一份**可执法的声明**。

## ① 目标与范围

要治的是**移动端论坛正文的格式轴缺失**：渲染端不认 `content_format`（把 Markdown 源串当纯文本显示），输入端没有形态（单行 `input` / `textarea` + 独立图片区，无工具栏、无编写预览）。范围 = **渲染接入**（消费 `content_format`，判定走哪一档子集）+ **输入区形态**（编写/预览、工具栏、图片单入口、能力提示行）。

**不含**：行内渲染（粗体/斜体/链接/行内代码）、表格、mermaid 渲染、Web 侧口径债（见 ③）。

三处可复核的事实（全部实测，带路径）：

1. **`content_format` 在移动端 0 命中**：`git grep` 全树无；`createForumTopicApi(title, content, images, category)` 的契约里没有格式字段；`forum-topic-body.uvue` 只有一句 `<text class="content-text">{{ content }}</text>` 加图片墙。
2. **移动端的块模型装不下行内格式**：`MarkdownBlock = { type, level, text, items }`（`types/common.uts:26-31`），行内标记在 `stripInlinePlain`（`utils/markdown.uts:50-65`）里被抹成纯文本。
3. **移动端已有两档具名子集与一个契约套件**：`SUBSET_CHAPTER`（可信面全集，含表格）/ `SUBSET_FEATURED`（三端交集，表格与公式降级为源码），消费面只有章节与内容精选两处（`pages/courses/chapter-view.uvue` / `pages/featured/featured-detail.uvue`），论坛不在其中。

## ② 选型 + 一句理由

| 决策 | 一句话理由 |
| --- | --- |
| **① 先补渲染欠账，再做输入区形态** | 移动端显示源串是**内容读不出来的降级**（根 `CONTEXT.md` 把「会让内容读不出来的降级必须在每一端补齐」定成硬口径）⇒ 它是欠账而不是新功能 |
| **② 加 `content_format` 消费，后端契约零变更** | 字段与缺省语义早就有了（根 ADR-0044），移动端只缺消费 —— 它正是 ADR-0044 所说的「旧客户端」 |
| **③ 新增第三档 `SUBSET_FORUM`，不追求与 Web 同子集** | 各端子集可以不同；移动端已有具名档先例，论坛只是第三档，不必发明新机制 |
| **④ 本期不做行内渲染** | `MarkdownBlock` 是章节 / 内容精选 / 论坛三个内容面共用件，为论坛改它把风险摊到另两个已上线面，而现状「抹成纯文本」不产生**新的**不可读 |
| **⑤ 声明与解析同住 `utils/markdown.uts`，不新起第二份声明文件** | 子集成员表与 `parseMarkdown` 必须同源（分家即两处事实）；契约套件按**行为**对账（执行被测物看产出的块类型） |
| **⑥ 工具栏 = 一排可横滑图标 + 长按中文提示** | 手机没有 hover，长按是最接近的既有手势且不占版面（注意 `white-space` 只在 `<text>` / `<button>` 上合法，须登记） |
| **⑦ 图片 = 拍照 + 相册双入口**（**2026-09-22 被 ⑨ 取代**） | 维修场景要拍故障码 / 铭牌，相对 Web 的「点击 / 粘贴 / 拖拽」是**改进**而不是少一个入口（uvue 侧粘贴/拖拽不可靠）。**取代理由见 ⑨** |
| **⑧ 编辑路径不得写 `content_format`** | 照搬根 ADR-0044：全量替换语义下按「缺省 = text」处理会把 Markdown 帖静默重置成纯文本 |
| **⑨ 图片 = 单一入口 + 系统选择器**（2026-09-22 **取代 ⑦**） | 两个常驻方块的形态**过重**（维护者裁定，属**偏好**而非技术约束）；一个 `＋` 方块弹系统选择器即可，相册 / 相机由系统给 —— 这条同时把 ①「目标与范围」与「附·参照口径」里**原本就写的「图片单入口」**恢复成与实现一致 |

## ③ 明确不做的事

- **不做行内渲染**（粗体 / 斜体 / 链接 / 行内代码）：另立一票，去留取决于「贴故障码要等宽、给手册要能点」是否算核心表达需求。本期如实登记为差异。
- **不做表格**：与内容精选档同处理（退回逐行文本）。
- **不做 mermaid 渲染 —— 但要具名登记**：Web 渲染 mermaid 而移动端显示围栏源码（`graph TD; A-->B;` 这串代码），这是本次唯一的**真降级**（触碰 ① 引的那条硬口径的下限），故必须在登记里具名，不得默认沉默；补渲染另立一票。
- **不做粘贴 / 拖拽入口**：uvue 侧不可靠，用系统选择器（相册 / 相机二选一由系统给）替代并写明理由（同 **⑨**；⑨ 于 2026-09-22 取代 ⑦ 的双入口）。
- **不动 `MarkdownBlock` 的形状**（血账：给扁平块加自定义类型数组字段会让 UTS 编译期改写类型名，整模块 kotlinc `unresolved reference`，④c 门实测）。
- **不改根仓库四份文档**（`CONTEXT.md` 论坛词条 / `FORUM_MARKDOWN_HINT` / 根 ADR-0044 子集补记 / 根 ADR-0052）：论坛子集按端分档后那四处「一份子集」的叙述都不准，但那是跨内容面的口径债 ⇒ 另开 Web 侧票。
- **不动 Web 侧 `content_format` 契约与后端子集配置**：本 ADR 只做移动端消费侧。

## ④ 拆分步骤

**单票三段，每段一个 PR、各自的门判据不同**（合票的理由：设计一次定完，语义不因分票漂移）：

| 段 | 内容 | 门 |
| --- | --- | --- |
| **P1 逻辑面** | `SUBSET_FORUM` 成档 + 成员声明 + 契约套件（档位用例 + 行为对账 + 成对取证）；`types/forum.uts` 补格式字段；`content_format` 消费与**编辑不变式**（编辑不带格式字段 ⇒ 原值不变） | 改动集 = `.uts` / `test.js` / `.md` ⇒ **免 ①②**（低风险运行时面，先例 #908），③④ 必过 |
| **P2 渲染接入** | 档位**决策点在 `utils/forumBody.uts`**（`markdown` ⇒ `parseMarkdown(…, SUBSET_FORUM)`、其余 ⇒ 直出原串）；`forum-topic-body.uvue` / `forum-reply-list.uvue` 接线 + 块渲染组件 `forum-markdown-blocks.uvue`；`forum-detail.uvue` 的正文与回复卡接线 | 含 `.uvue` ⇒ **①②④ 必过**；①b 免（不命中能力面） |
| **P3 输入区形态** | 编写/预览两档 + 工具栏（横滑图标 + 长按提示，文案取自 P1 声明）+ 图片**单入口**（⑨，原 ⑦ 的双入口已于 2026-09-22 回退）+ 数据档位分段控件 + 能力提示行（只讲边界） | 含 `.uvue` ⇒ **①②④ 必过**；**①b 必过**（命中能力面：真机上传 + 权限弹窗 —— 白名单命中 `useReplyComposer.uts` / `forum-create.uvue`，与入口数无关） |

**依赖**：P2 / P3 依赖 P1（都消费它的声明与档位）；P2 与 P3 **可并行**（互不改同一批文件）。**P1 必须先合**：在声明落地前做按钮，做出来的就是一排没有守护的按钮。

> **交付形态（#1240）**：以上三段是**一张票的三段进度**，不是三张票 —— 合票让设计一次定完、语义不因分票漂移；但**PR 仍按三段拆**，因为低风险运行时面的豁免是**逐文件**判的（P1 的改动集全在白名单内 ⇒ 免 ①②；P2 / P3 含 `.uvue` ⇒ ①②④ 必过）。三段各自的进度按 `docs/agents/issue-dispatch.md` §4/§5 如实回填。

## ⑤ 约束（不能动的）

- **`MarkdownBlock` 形状不变**；`SUBSET_CHAPTER` / `SUBSET_FEATURED` 的既有行为**零回归**（章节能渲染表格、内容精选走交集）。
- **后端契约零变更**：`content_format` 的缺省、存量语义、编辑路径的「不写该字段」全部照根 ADR-0044；移动端只消费。
- **编辑不变式必须有用例钉住**：编辑不带格式字段 ⇒ 格式原值不变（本仓 `forumContract` 是字段级断言的既有落点）。
- **读取层归一**：契约套件一律用 `utils/utsHarness.js#readText`（根 ADR-0019 / 移动端 0019），不得自建 `read()` / `normalizeEol`。
- **不新增模块声明负担**：`utils/` 整目录已登记为基础设施（`utils/modules.js` 的 `INFRA.dirs`）⇒ 新增文件**不需要**同步登记；**不得**因为「顺手」去改 `utils/modules.js`（那会把整单降级为常规运行时面）。
- **不新引入 `#ifdef MP-WEIXIN` 指令行**（除非真要做小程序专属分支）：`pr-evidence` 的 ② 门判据是「运行时面 diff 里增删了真正的 MP-WEIXIN 条件编译指令行」，凭空加一条会无端点亮该门。
- **uvue 约束照旧**：无 `gap`、选择器只用 class、`white-space` 只在 `<text>` / `<button>`（须在 `uvueWhiteSpaceContract.test.js` 的 `LEGAL_CARRIER_SITES` 登记）。
- **四门纪律**：①a 按「一次分支收口」跑；④a/② 须全访问权限；HBuilderX 单实例串行 ⇒ 真机阶段按批集中到一个会话。
- **不重开已决**：行内渲染、表格、mermaid、粘贴/拖拽四项本期不做，已在上表具名；重开须另立 ADR。

## ⑥ 验收标准

1. **格式被消费**：Web 发的 Markdown 帖在移动端**不再显示源串** —— 标题 / 列表 / 引用 / 代码块成块，`**粗**` 与 `[文字](url)` 被剥离而非原样显示（P1 到「解析产物正确」，肉眼可见面归 P2）。
2. **子集可枚举且被守护**：`SUBSET_FORUM` 成档；**声明里给某语法加一行而 `parseMarkdown` 不产对应块 ⇒ 用例必红**（成对取证：必不红 / 必红各一条）。
3. **编辑不变式成立**：带 `content_format` 的帖被移动端编辑后格式**不变**（契约测试）。
4. **零回归**：`npm run test:unit` 全绿（含既有 `markdownContract.test.js` 全部用例）；章节能渲染表格、内容精选走交集这两条不受影响。
5. **形态落地**（P3）：编写/预览可切；工具栏可横滑；长按出中文提示；图片走**单一入口**（一个 `＋` 方块 → 系统选择器，相册 / 相机由系统给；**⑨ 于 2026-09-22 取代 ⑦**）；纯文本档**不出现** tab / 工具栏 / 能力提示行（照根 ADR-0052 决策 8）；能力提示行只讲边界、不讲能力清单。
6. **登记在位**：跨端差异（行内格式 / 任务列表 / mermaid / 表格）四处逐条登记，**mermaid 那条具名**（它是唯一真降级）。

## 实施回记（#1240 · P1 逻辑面已落地，2026-09-21）

**机制落地**：子集从「一个 `isFeatured` 布尔」升级为**可枚举的成员声明表** —— `SUBSET_MEMBERS_CHAPTER` / `SUBSET_MEMBERS_FEATURED` / `SUBSET_MEMBERS_FORUM` 三张表（成员名常量 `MEMBER_*`）+ `subsetMembers()` / `subsetHasMember()` 两个取值口。解析器的**七个可开关块产生点**（标题 / 列表 / 引用 / 代码块 / 分隔线 / 图片 / 表格）全部经 `hasMember()` 闸门 ⇒ **声明即行为**：给某档声明表加一行而解析器产不出对应块，行为对账用例判红（⑥-2 的判据由此可执行，不再靠人读注释）。

**新决策（ADR 六段未覆盖，本回记补）：段落是「不可关闭的地板」，不进成员声明表。** 未被本档声明的语法只能**退回可见的段落文本**（论坛档的表格退回逐行原始文本、mermaid 退回围栏源码都是这个地板在承重），**不允许**「声明里没有 ⇒ 内容消失」。理由：根 `CONTEXT.md` 的「会让内容读不出来的降级必须在每一端补齐」是硬口径 —— 若把段落也做成可关，声明改一行就会静默丢正文。降级可读因此有守护（见下条的反向对账组）。

**论坛档的成员清单（P1 定版）**：`heading` / `list` / `quote` / `code` / `divider` —— **不含 table**（与内容精选同处理：退回逐行原始文本），**也不含 image**。后一条是本回记对票面初版清单的**执行细化**：论坛是图文分离，正文内嵌 `![alt](url)` 与 Web 同口径**展开成 alt 文本**（根 ADR-0044「图片一律走 `images` 数组」），故论坛档比内容精选档**少一个 image**，`![]()` 与表格一样回落段落地板、仍可见 —— 这是「按端分档」下最直接的一处档位差异，也已由行为守护钉住。

**与 Web 侧的机制分道（按端分档的延伸）**：Web 侧的子集今天仍是**黑名单**（`md.disable`，口径债见 #1241、实现票 #1253）；移动端这一档**本来就是白名单**（声明表）。⇒ 「按端分档」不只指子集内容可以不同，也**允许机制不同** —— 两端各自成文，互不要求同形。

**守护落锁（③ 门承重）**：
- 新增 `utils/markdownSubsetBehavior.test.js`（**行为**守护，`loadUts` 真执行 `parseMarkdown`）：三档声明表可枚举 / 正向对账（声明了必须真出块）/ 反向对账 + 降级可读（未声明不得出块、但内容仍可见）/ 零回归（chapter·featured 行为不变）/ **成对取证**（拆闸门、声明多一行两种坏实现必红）。
- 新增 `utils/forumContentFormatBehavior.test.js`（**行为**守护）：DTO 归一（缺省与脏值 → `text`）+ **编辑不变式**（PUT 载荷键集合不含 `content_format`）+ 成对取证（注入该键后判据必红）。
- `utils/markdownContract.test.js` 的镜像同步锚点随机制更新（闸门从 `!isFeatured` 改为声明表判断），并把镜像**范围写实**为「chapter / featured 两档的解析语义」—— 全量「声明 ↔ 行为」对账跑真模块，见上面第一个套件。

**本批的边界（P1 只做逻辑面）**：`content_format` 只**消费**（类型 + DTO 归一）；**创建路径不声明格式**（载荷不带 ⇒ 后端缺省 `text` 落库，这是「移动端发帖默认纯文本」，数据档位控件属 P3）；**编辑路径不写该字段**（全量替换语义下带上会把 Markdown 帖静默重置成纯文本）。**未含**：P2 渲染接入（落地后走 `utils/forumBody.uts` 的格式轴，见下节「复核回写」修正②）、P3 输入区形态 —— 两段含 `.uvue` ⇒ ①②④ 必过，P3 另命中 ①b 人工门。

## 实施回记（#1240 · P2 渲染接入已落地）

**机制落地（承载面 = 3 个页面/组件 + 1 个新组件 + 1 个新逻辑模块）**：
- `utils/forumBody.uts`（新）—— **格式轴**：`FORMAT_MARKDOWN` / `isMarkdownFormat(format)` / `forumContentBlocks(content, format)`。Markdown 档 ⇒ `parseMarkdown(content, SUBSET_FORUM)`；其余一切取值 ⇒ **空数组**（壳层直出原串）。
- `pages/forum/components/forum-markdown-blocks.uvue`（新）—— 论坛档的**块渲染**（heading / paragraph / code / list / quote / divider 六条分支；**不持** table 与 image，见下条 ③）。
- 接线：`forum-topic-body.uvue`（新增 `format` prop，纯文本档走原 `.content-text`、Markdown 档走块组件）、`forum-reply-list.uvue`（回复卡同口径，本地薄包装 `isMarkdownReply` / `replyBlocks`）、`forum-detail.uvue`（壳层扁平下发 `topicFormat` 与 `contentFormat`）、`utils/forumDetailDisplay.uts`（`ForumReplyDisplay` 补 `contentFormat`）。

**本段产生的新决策（六段与 P1 回记未覆盖，故在此补）**：
1. **格式 → 档位的「决策」从模板收进 `utils/forumBody.uts`**。理由：留在 `.uvue` 里就只能靠读源码文本的接线守护去守，而 `docs/agents/guards.md` 明说接线守护**不构成 ③ 门证据**（算法被改坏而字面量还在时不红）；抽到 `utils/` 后可被 `loadUts` 真执行，判据落在**产出物**上（先例：`markdownSubsetBehavior`）。页面只接这一条口，**不得**自查 `content_format`、**不得**直引 `SUBSET_*`。
2. **块渲染抽成组件，而不是在正文与回复卡各抄一份**：课程面 T08（#646）已有同形先例（`chapter-markdown.uvue`）。**纯文本档仍留在各自文件里直出**（`.content-text` / `.reply-content` 一行未动）⇒ 常见路径（存量全是 `text` 档）**视觉零 diff**，新样式只作用于新出现的 Markdown 档。
3. **`forum-markdown-blocks` 不持 table / image 两条分支**（与 `featured-detail` 不持 table 分支同例）：论坛档的声明表里没有这两位（表格退回逐行原始文本、正文内嵌 `![alt](url)` 展开成 alt 文本），渲染层跟着不写 —— 多写一条就是**永远不可达**的分支，且会掩盖「档位被换错」。
4. **空数组是「不解析」的哨兵，不是「正文为空」**：渲染层的二选一闸门是 `isMarkdownFormat`（看格式声明），**不看块数组长度** —— 否则一个只有空行的 Markdown 帖会被渲染成「没有正文」。
5. **①a 取证坑位（本轮实测，值得记）**：`uiautomator dump --compressed` 会把这条**长** `content-desc`（正文整段的源串）丢成空串，看着像「正文没渲染」；换**未压缩** `uiautomator dump` 才拿到原文。本轮的 before/after 文本判据全部建立在这条上（机型 `b32d8398` / Android 15）。

**①a 真机取证（本轮实测，同源话题「测试markdown渲染」）**：改前正文节点 `content-desc` = `## 测试 Markdown 渲染…- 无序列表…---…```python…```…---`（**源串直出**，正是本票要治的降级）；改后同一话题按块渲染（星号 / `##` / 围栏 / `---` 均不再出现），纯文本档话题（标题「1」）正文逐字不变 —— 两条判据都是**机检文本**（`docs/verification/forum/<PR>/` 内 `*-ui-desc.txt`），不依赖人眼看图。

**守护落锁（③ 承重）**：新增 `utils/forumBodyBehavior.test.js`（**行为**守护，`loadUts` 真执行，注入的解析器取自真执行的 `utils/markdown.uts`）：档位闸门取值表 / 正反向对账（命中 ⇒ 出块、不命中 ⇒ 空数组）/ 源串剥离（`**` `[]()` 反引号都不再显示）/ 未声明语法降级可读（表格与内嵌图片不丢内容）/ mermaid 具名降级（围栏源码可见）/ **成对取证两组**（拆掉闸门 ⇒ 文本档也被解析；换错档位 ⇒ 表格出块）。分类器：behavior 20 → 22（只升不降）。
接线面（不构成 ③ 证据，只防接线被拆）钉在 `utils/markdownContract.test.js` ⑤ 组新增的三条：页面不自己判档、块组件不持 table/image 分支、格式由壳层扁平下发。

**本批的边界（P2 只做渲染接入，如实登记两处未覆盖）**：① **列表卡片正文预览**（`forum-topic-card` 与 `my-forum` 走的 `getContentPreview`）与「我的动态」里的回复原文仍是**直出原串** —— 它们是**截断 80 字 + 去换行**的预览（不是正文承载面，票面 P2 只点名正文 / 回复卡）；要收口得把格式**下发到列表 DTO 与卡片 props**，属另一批改动（预览的降级口径与正文不同：截断 + 去换行）。⚠️ **该句对「我的动态」里的回复原文不成立** —— 见下节「复核回写」修正①（那里渲的是完整 `content`，属正文承载面）。② P3 输入区形态未动工（工具栏 / 编写预览 / 拍照相册 / 能力提示行）。

## 实施回记（#1240 · P3 输入区形态已落地，2026-09-21）

**机制落地**：输入区收敛为**一个共享组件** `pages/forum/components/forum-markdown-input.uvue`（发帖表单与回复栏只接线，**形态只有一份** —— 同根 ADR-0052 决策① 的目标）。三条档位轴互不混用：**数据档位**（胶囊分段控件，会永久保存）/ **视图档位**（下划线 tab，临时）/ **图片**（拍照 + 相册两个直达入口）。

**新决策（ADR 六段与 P1/P2 回记未覆盖，本回记补）**：

1. **工具栏按钮集 = 本档声明 ∩ 按钮模板，且两个方向都对账**。`utils/markdownToolbar.uts` 持 5 枚按钮（`###` / `-` / `>` / ` ``` ` / `---`），每枚的成员必须在本档声明表里，声明表里每个成员也必须有按钮（或登记进 `DECLARED_WITHOUT_BUTTON`，今天为空）。**行内格式没有按钮**：⑥-6 把「行内格式」登记为跨端差异，而 ③ 明确不做行内渲染（`**粗**` 被剥成「粗」、**不出加粗样式**）—— 放一枚加粗按钮就是承诺一个渲染不出来的效果。判据是可执行的 **round-trip**：每枚按钮插入后的正文，交**真执行的解析器**跑一遍，必须产出该按钮承诺的块类型。
2. **按钮字形用语法记号本身**（`###` / `-` / `>` / ` ``` ` / `---`）：自解释，且避开 `utils/iconGlyphContract.test.js` 守的那族「图标位降级成单个 ASCII 字母」（该守护按**函数名含 `Icon`** 有意收窄，本模块的函数因此叫 `toolbarSyntax` —— 返回的是语法记号、不是 emoji 图标位）。
3. **工具栏插入的落点是纯函数，组件接线只喂「正文末尾」**。`applyToolbarInsert(content, start, end, member)` 完整支持选区（行前缀类逐行加前缀、空行跳过；代码块整块包裹；分隔线独占一行且**不丢选区内容**）；组件这一侧只喂 `content.length`，**插入后的光标落位不做控制** —— 全仓对 `<textarea :cursor>` 与 `selectionStart` 都是 **0 先例**，uvue 侧的光标控制无法在不真机的情况下判定，而 ADR-0025 只要求「工具栏可横滑 + 长按出中文提示」，**未要求选区语义**（选区语义是根 ADR-0052 决策⑩ 的 **Web** 机制）。⇒ **本段如实登记的偏差**：接线到真实选区只需把喂进去的两个下标换成平台上报的选区，属一次独立改动。
4. **记忆位与「首次默认纯文本」合成一条读判据**：`utils/forumFormatPreference.uts`（键 `forum_author_content_format`）——「首次默认纯文本」不是页面里的一个初值，而是**读不到就是纯文本**这条判据本身；发帖与回复**共用一个键**；读与写两个方向都归一，契约外的取值既不进存储也不漏出来。
5. **编辑态不给档位控件，按帖子原格式呈现**：编辑态的 PUT 载荷按编辑不变式不带 `content_format`（P1 已落锁）⇒ 在那里摆一个档位开关就是承诺一件做不到的事（与工具栏同一条纪律）。编辑态回填时读一次详情 DTO 的 `content_format`（**只读**），据此决定给不给编写/预览与工具栏。**资源投稿态同理恒纯文本** —— 它走投稿接口，根本没有格式契约。
6. **回复栏也接同一套形态（票面 ④ 未点名，本回记补记）**：④ 只写「输入区形态」，没点名回复框；但 P2 已经让回复卡按 `content_format` 渲染、后端 `forum_replies` 也有该字段与契约测试 ⇒ 若回复不能声明 Markdown，移动端就成了**「能渲染别人写的 Markdown 回复、自己写不出来」**的单向畸形。回复栏的形态是**原地展开**（不新开浮层/页面）：数据档位常驻一行（它是「Markdown 完全 opt-in」下**唯一**的入口，可发现性靠它 —— ⑥-5 只把 tab / 工具栏 / 提示行排除出纯文本档，数据档位不在排除名单里），tab / 工具栏 / 边界提示行只在 Markdown 档长出。回复没有编辑入口，故不存在上面第 5 条那条约束。

6. **「拍照」只验到入口侧（评审修复后重跑新增；⚠️ 本条对应的是已被 **⑨** 取代的双入口形态 ⇒ 随 2026-09-22 的回退，本节的 ①a 证据整体作废、按「第二次分支收口」重跑）**：点击「拍照」**直达系统相机**（`mCurrentFocus=…com.android.camera/com.android.camera.OneShotCamera`）且**应用内无权限弹窗**（`manifest.json` 本就没有权限声明，走的是系统相机 app）—— 这证明抽成共享 picker 之后**接线仍在**。**按下快门 → 回应用 → 上传成功**这一段是写操作（照片会上传到生产后端），**归 ①b**。回退后这条判据本身也不再成立（没有「拍照」这个常驻入口），新形态的 ①a 改为「点 `＋` → 系统选择器出现」。

8. **回退后的 ①a 已按「第二次分支收口」重跑（2026-09-22，绑 `2f4f74e1`）**：本批判据见 `docs/verification/forum/1261/README.md`（7 份状态 + logcat 实数）。**本轮之后 ①b 需要人眼的只剩「长按出中文名」一条** —— 入口侧（点 `＋` 弹**含两个来源的选择器**）、相册入口、以及**选图 → 回应用 → 上传成功**（经维护者授权由 agent 执行写路径）都已机检；回复栏 / 「我的动态」仍未取证（见上条 5）。**两条新坑位**（已写进该 README）：① **改 composable 的返回类型签名后，内循环增量编译不重编调用方** ⇒ 该页 `NoSuchMethodError: getOnAddImage()…Function1` + 白屏，必须 `cli launch app-android --cleanCache true`（= GUI「干净缓存重建」）后才能验，否则会把「缓存陈旧」误判成「代码坏了」；② **深链 `cli launch --pagePath` 本轮不可靠**（app 停在空白 `UniAppActivity`），**且中途 kill 会把设备上的 `www` 推成半截 ⇒ 整个 app 白屏**（重跑一次 `hx:run` 才恢复）⇒ 取证改走**真实 UI 导航**，深链的编译段**绝不 kill**。

**①a 取证坑位（本轮实测，已记进 `docs/verification/forum/1261/README.md`）**：

1. **软键盘会盖住工具栏** —— 在正文里敲完字后直接按 bounds 找 `###` 会**查不到节点**（a11y 树里没有，因为它被键盘挡住）；先 `adb shell input keyevent 111` 收键盘再 `uiautomator dump`。
2. **深链 `cli.exe launch --pagePath` 会触发一次增量编译（本轮实测约 2 分钟）** —— 早 dump 只会拿到上一页，所以要「轮询 a11y 直到文本集合变化」判到位，不要用固定 sleep。
3. **无线调试会话会掉**（手机息屏 / 闲置后 `adb devices` 与 `adb mdns services` **同时**变空）：`adb kill-server` 再 `adb start-server`、等几秒即重新发现，**不必重新配对**（2026-09-22 实测）。

## 形态回退（2026-09-22 · 第二次分支收口）—— ⑨ 取代 ⑦

**触发**：维护者在 PR #1261 收口前裁定「两个常驻方块（`拍照` / `相册`）**过重**，回退成 P3 之前的一个 `＋` 方块」。这是**偏好**裁定、不是技术约束 —— 记在这里，免得下一位读者把它读成「双入口做错了」。

**改了什么**（改动面 = 1 组件 + 1 picker + 1 composable + 1 宿主注释 + 2 守护 + 本 ADR）：

1. `pages/forum/components/forum-markdown-input.uvue`：两个 `image-add` 方块 ⇒ **一个**（`＋` + `n/9` 计数；上传中显示 `…` / `上传中`）；`emit('add-image')` 不再带来源，事件类型同步。**回复侧沿用回退前的旧形态**：方块上只有 `＋`、不出计数（`variant != 'reply'` 闸门 —— 该 prop 本来就是为「两处形态差异」而设）。
2. `composables/useForumImagePicker.uts`：`onAddImage(source)` ⇒ `onAddImage()`；`sourceType` 由「单来源直达」⇒ `['album', 'camera']`（系统选择器）。**流水线一字未动**（`count = 剩余额度` / `sizeType: ['compressed']` / 限额 toast / `uploading` 闸门 / 失败计数）。
3. `composables/useReplyComposer.uts`：`onAddReplyImage` 去掉入参（只接线）。
4. **`:key` 一并落地**：图片缩略图行由下标作 key ⇒ 用图片 URL 作 key（见上「复核回写」的据实更正①）。
5. **守护翻面（不是删除）**：`forumImagePickerBehavior` 的「来源直达」组改写为「两个来源都在」组；旧的**必红对**（把「退化成系统选择器」当坏实现）随决策反转，替换为新的一组真坏实现 —— ① 来源数组被砍成一个来源；② `count` 写死不按剩余额度；③ 上传循环里的限额闸门被拆；**必不红对照**保留 ⇒ 成对取证（③ 判据③）仍成立。`forumMarkdownInputContract` 的 ④ 组同步反转（一个入口 + 计数 + 「旧的双入口写法已退场」）。
6. **①a 证据整体作废、按「第二次分支收口」重跑**：旧证据里判据 6（「图片双入口」）与判据 8（「点『拍照』直达系统相机」）判的是**已被取代的形态** ⇒ 随回退刷新（新形态的入口侧判据改为「点 `＋` → 系统选择器出现」）；③ / ④c 同批重跑。

**坑位（本轮实测，值得记）**：**回退说明里不要写出被回退掉的那个字面量**。`forumMarkdownInputContract` 是**按文本判**的接线守护（`.uvue` 模板与注释进不了 `loadUts` 的行为缝），picker 的注释里带上「单来源直达」的写法**本身**就会让该守护替代码判红 —— 与 #1030 同族（文本判据分不清代码与散文）。正解是**把注释改述**（已改述），不是放宽判据。

**能力面与 ①b 不受影响**：①b 的触发面是**路径白名单**（`composables/useReplyComposer.uts` / `pages/forum/forum-create.uvue` ⇒「运行时权限弹窗」类）+ 真机上传，与入口数无关 ⇒ 本回退**不改变** ①b 的必要性；变的只是 ①b 要看的东西（点 `＋` → 系统选择器 → 选图 / 拍照 → 回应用 → **上传成功**）。
