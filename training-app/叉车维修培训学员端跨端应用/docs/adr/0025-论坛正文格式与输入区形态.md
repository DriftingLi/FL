# 0025 - 论坛正文格式与输入区形态：声明子集第三档 + 渲染接入 + 输入区

**状态**：已接受（2026-09-21，来源：grilling 逐条定案（仅移动端范围，参照根仓库 ADR-0052 的**目标**而非结论）；落地：**#1240 单票三段** —— P1 逻辑面 / P2 渲染接入 / P3 输入区形态；Web 侧口径债归 **#1241**）

> **一句话**：移动端论坛**从来没有格式轴** —— `content_format` 在移动端 0 命中、`forum-topic-body.uvue` 对 Web 发来的 Markdown 帖**直出源串**（读者看到 `**故障码**` 的星号）；本 ADR 记下「为什么先补渲染欠账、为什么移动端子集与 Web 不同、为什么本期不做行内渲染」，并把子集收成一份**可执法的声明**。

## ① 目标与范围

要治的是**移动端论坛正文的格式轴缺失**：渲染端不认 `content_format`（把 Markdown 源串当纯文本显示），输入端没有形态（单行 `input` / `textarea` + 独立图片区，无工具栏、无编写预览）。范围 = **渲染接入**（消费 `content_format`，判定走哪一档子集）+ **输入区形态**（编写/预览、工具栏、图片单入口、能力提示行）。

**不含**：行内渲染（粗体/斜体/链接/行内代码）、表格、mermaid 渲染、Web 侧口径债（见 ③）。

三处可复核的事实（全部实测，带路径）：

1. **`content_format` 在移动端 0 命中**：`git grep` 全树无；`createForumTopicApi(title, content, images, category)` 的契约里没有格式字段；`forum-topic-body.uvue` 只有一句 `<text class="content-text">{{ content }}</text>` 加图片墙。
2. **移动端的块模型装不下行内格式**：`MarkdownBlock = { type, level, text, items }`（`types/common.uts:26-31`），行内标记在 `stripInlinePlain`（`utils/markdown.uts:50-65`）里被抹成纯文本。
3. **移动端已有两档具名子集与一个契约套件**：`SUBSET_CHAPTER`（可信面全集，含表格）/ `SUBSET_FEATURED`（三端交集，表格与公式降级为源码），消费面只有章节与内容精选两处（`pages/courses/chapter-view.uvue` / `pages/featured/featured-detail.uvue`），论坛不在其中。

## ② 选型 + 一句理由

| 决策 | 一句话理由 |
| --- | --- |
| **① 先补渲染欠账，再做输入区形态** | 移动端显示源串是**内容读不出来的降级**（根 `CONTEXT.md` 把「会让内容读不出来的降级必须在每一端补齐」定成硬口径）⇒ 它是欠账而不是新功能 |
| **② 加 `content_format` 消费，后端契约零变更** | 字段与缺省语义早就有了（根 ADR-0044），移动端只缺消费 —— 它正是 ADR-0044 所说的「旧客户端」 |
| **③ 新增第三档 `SUBSET_FORUM`，不追求与 Web 同子集** | 各端子集可以不同；移动端已有具名档先例，论坛只是第三档，不必发明新机制 |
| **④ 本期不做行内渲染** | `MarkdownBlock` 是章节 / 内容精选 / 论坛三个内容面共用件，为论坛改它把风险摊到另两个已上线面，而现状「抹成纯文本」不产生**新的**不可读 |
| **⑤ 声明与解析同住 `utils/markdown.uts`，不新起第二份声明文件** | 子集成员表与 `parseMarkdown` 必须同源（分家即两处事实）；契约套件按**行为**对账（执行被测物看产出的块类型） |
| **⑥ 工具栏 = 一排可横滑图标 + 长按中文提示** | 手机没有 hover，长按是最接近的既有手势且不占版面（注意 `white-space` 只在 `<text>` / `<button>` 上合法，须登记） |
| **⑦ 图片 = 拍照 + 相册双入口** | 维修场景要拍故障码 / 铭牌，相对 Web 的「点击 / 粘贴 / 拖拽」是**改进**而不是少一个入口（uvue 侧粘贴/拖拽不可靠） |
| **⑧ 编辑路径不得写 `content_format`** | 照搬根 ADR-0044：全量替换语义下按「缺省 = text」处理会把 Markdown 帖静默重置成纯文本 |

## ③ 明确不做的事

- **不做行内渲染**（粗体 / 斜体 / 链接 / 行内代码）：另立一票，去留取决于「贴故障码要等宽、给手册要能点」是否算核心表达需求。本期如实登记为差异。
- **不做表格**：与内容精选档同处理（退回逐行文本）。
- **不做 mermaid 渲染 —— 但要具名登记**：Web 渲染 mermaid 而移动端显示围栏源码（`graph TD; A-->B;` 这串代码），这是本次唯一的**真降级**（触碰 ① 引的那条硬口径的下限），故必须在登记里具名，不得默认沉默；补渲染另立一票。
- **不做粘贴 / 拖拽入口**：uvue 侧不可靠，用拍照 / 相册替代并写明理由（同 ⑦）。
- **不动 `MarkdownBlock` 的形状**（血账：给扁平块加自定义类型数组字段会让 UTS 编译期改写类型名，整模块 kotlinc `unresolved reference`，④c 门实测）。
- **不改根仓库四份文档**（`CONTEXT.md` 论坛词条 / `FORUM_MARKDOWN_HINT` / 根 ADR-0044 子集补记 / 根 ADR-0052）：论坛子集按端分档后那四处「一份子集」的叙述都不准，但那是跨内容面的口径债 ⇒ 另开 Web 侧票。
- **不动 Web 侧 `content_format` 契约与后端子集配置**：本 ADR 只做移动端消费侧。

## ④ 拆分步骤

**单票三段，每段一个 PR、各自的门判据不同**（合票的理由：设计一次定完，语义不因分票漂移）：

| 段 | 内容 | 门 |
| --- | --- | --- |
| **P1 逻辑面** | `SUBSET_FORUM` 成档 + 成员声明 + 契约套件（档位用例 + 行为对账 + 成对取证）；`types/forum.uts` 补格式字段；`content_format` 消费与**编辑不变式**（编辑不带格式字段 ⇒ 原值不变） | 改动集 = `.uts` / `test.js` / `.md` ⇒ **免 ①②**（低风险运行时面，先例 #908），③④ 必过 |
| **P2 渲染接入** | `forum-topic-body.uvue` 走 `parseMarkdown(…, SUBSET_FORUM)`；`forum-detail.uvue` 的正文与回复卡接线；块渲染样式 | 含 `.uvue` ⇒ **①②④ 必过**；①b 免（不命中能力面） |
| **P3 输入区形态** | 编写/预览两档 + 工具栏（横滑图标 + 长按提示，文案取自 P1 声明）+ 图片拍照/相册双入口 + 数据档位分段控件 + 能力提示行（只讲边界） | 含 `.uvue` ⇒ **①②④ 必过**；**①b 必过**（命中能力面：真机上传 + 相机权限） |

**依赖**：P2 / P3 依赖 P1（都消费它的声明与档位）；P2 与 P3 **可并行**（互不改同一批文件）。**P1 必须先合**：在声明落地前做按钮，做出来的就是一排没有守护的按钮。

> **交付形态（#1240）**：以上三段是**一张票的三段进度**，不是三张票 —— 合票让设计一次定完、语义不因分票漂移；但**PR 仍按三段拆**，因为低风险运行时面的豁免是**逐文件**判的（P1 的改动集全在白名单内 ⇒ 免 ①②；P2 / P3 含 `.uvue` ⇒ ①②④ 必过）。三段各自的进度按 `docs/agents/issue-dispatch.md` §4/§5 如实回填。

## ⑤ 约束（不能动的）

- **`MarkdownBlock` 形状不变**；`SUBSET_CHAPTER` / `SUBSET_FEATURED` 的既有行为**零回归**（章节能渲染表格、内容精选走交集）。
- **后端契约零变更**：`content_format` 的缺省、存量语义、编辑路径的「不写该字段」全部照根 ADR-0044；移动端只消费。
- **编辑不变式必须有用例钉住**：编辑不带格式字段 ⇒ 格式原值不变（本仓 `forumContract` 是字段级断言的既有落点）。
- **读取层归一**：契约套件一律用 `utils/utsHarness.js#readText`（根 ADR-0019 / 移动端 0019），不得自建 `read()` / `normalizeEol`。
- **不新增模块声明负担**：`utils/` 整目录已登记为基础设施（`utils/modules.js` 的 `INFRA.dirs`）⇒ 新增文件**不需要**同步登记；**不得**因为「顺手」去改 `utils/modules.js`（那会把整单降级为常规运行时面）。
- **不新引入 `#ifdef MP-WEIXIN` 指令行**（除非真要做小程序专属分支）：`pr-evidence` 的 ② 门判据是「运行时面 diff 里增删了真正的 MP-WEIXIN 条件编译指令行」，凭空加一条会无端点亮该门。
- **uvue 约束照旧**：无 `gap`、选择器只用 class、`white-space` 只在 `<text>` / `<button>`（须在 `uvueWhiteSpaceContract.test.js` 的 `LEGAL_CARRIER_SITES` 登记）。
- **四门纪律**：①a 按「一次分支收口」跑；④a/② 须全访问权限；HBuilderX 单实例串行 ⇒ 真机阶段按批集中到一个会话。
- **不重开已决**：行内渲染、表格、mermaid、粘贴/拖拽四项本期不做，已在上表具名；重开须另立 ADR。

## ⑥ 验收标准

1. **格式被消费**：Web 发的 Markdown 帖在移动端**不再显示源串** —— 标题 / 列表 / 引用 / 代码块成块，`**粗**` 与 `[文字](url)` 被剥离而非原样显示（P1 到「解析产物正确」，肉眼可见面归 P2）。
2. **子集可枚举且被守护**：`SUBSET_FORUM` 成档；**声明里给某语法加一行而 `parseMarkdown` 不产对应块 ⇒ 用例必红**（成对取证：必不红 / 必红各一条）。
3. **编辑不变式成立**：带 `content_format` 的帖被移动端编辑后格式**不变**（契约测试）。
4. **零回归**：`npm run test:unit` 全绿（含既有 `markdownContract.test.js` 全部用例）；章节能渲染表格、内容精选走交集这两条不受影响。
5. **形态落地**（P3）：编写/预览可切；工具栏可横滑；长按出中文提示；图片有拍照与相册两个入口；纯文本档**不出现** tab / 工具栏 / 能力提示行（照根 ADR-0052 决策 8）；能力提示行只讲边界、不讲能力清单。
6. **登记在位**：跨端差异（行内格式 / 任务列表 / mermaid / 表格）四处逐条登记，**mermaid 那条具名**（它是唯一真降级）。
