# 0022 - 招聘者工作区落地口径与角色化鉴权

> 状态：已裁定（2026-09-20，原型翻转 + grilling 收敛）｜来源：ADR-0021 ④ 线 4 的**落地口径**补裁
> **职责边界**：只补 ADR-0021 未覆盖的四件落地事（分段骨架的单一来源、身份与凭据的角色化落点、
> 401 按角色定向、平台面隔离落法）；**不改 0021 的十项裁定**、**不动后端**、**不动 0021 的编号体系**。
> **落地状态：本 ADR 已落文档；线 4 拆成的三张票均未开工。**

**① 目标与范围**

ADR-0021 定了"并入学员端 App、身份互斥、无 tabBar、零后端改动"，但没定**顺序侧形态怎么落**。
本 ADR 补四件事，使 ④ 线 4 达到冷启动可实现的粒度：**导航骨架**、**身份与凭据的角色化落点**、
**401 按角色定向**、**平台面隔离**。形态来源：原型 `.scratch/prototype/recruiter-workspace.html` 的
**变体 D**（B 的分段骨架 + C 的紧迫条），维护者于 2026-09-20 翻过 A/B/C 后裁定。

**② 选型 + 一句理由**

- **导航骨架 = 页内常驻分段**（"职位 / 简历库 / 交换"），**首页即职位段**；面间 `redirectTo`（不堆栈）；二级面（投递列表、我的）**不带分段**（否则段切换与返回栈语义打架）。—— 分段要跨**三个页面**复用，故必须是**唯一一份**：模块内共享件 `pages/recruit/components/recruiter-tab-bar.uvue`；先例形状是 `activity-tab-bar` 被 3 页挂载并被契约测试 `toHaveLength(3)` 锁住。ADR-0009 的病根是**两份手画的栏**，不是"面多"。
- **首页待办线索 = 只收徽标给不了的那一半**：分段徽标给交换申请的**数量**（常驻、三段可见），职位段顶部一行给**最近过期天数**（时间维度），点它直达交换段；「被强制下架」不重复（职位段列表自带该标签）。—— 徽标与紧迫行**共用同一份** `GET /recruit/contact-requests` ⇒ 首屏仍是 **2 个批量请求**，不因合体涨价。
- **身份落点 = 复用既有 `auth_token` 槽 + 新增显式角色标记 `auth_active_role`（`student|recruiter`）**；招聘者登入时清空学员三键（`auth_token`/`auth_refresh_token`/`auth_user`）**并清空学员安全凭据槽** `auth_secure_credentials`，且这一步走**身份切换专用函数**，不改 `clearAuthData()` 的既有语义。—— ADR-0021 ② 否掉的是**并存**身份，"复用单槽"意味着该槽不能同时留着另一方的凭据；而"登出不清凭据"（ADR-0004）讲的是**同一身份的退出**，不是身份切换。
- **401 = 单一出口不变**：`handleUnauthorized()` 仍是**唯一** reLaunch 者，出口**内部**按当前角色选目标（`/pages/login/login` 或 `/pages/recruiter/login`）；招聘者态**禁用刷新链**（无 refresh token，`/auth/refresh` 不得被调用）；顺手把硬编码 `'auth_user'` 换成 `STORAGE_KEY_USER` 常量。—— `concurrent401RefreshContract.test.js` 的 `C2` 钉着"跳转只有一个出口"、`I2/I3/I4` 钉着学员路径行为 ⇒ 只能是**出口内部分支**，不能新增出口。
- **平台面隔离 = 不排页面注册，靠源码级 `#ifndef MP-WEIXIN` 守卫 + 小程序端不发布**；"开创 `pages.json` 条件编译"留作另一条路（本仓 `pages.json` **零条件编译先例**，开创成本与不确定性高于本线收益）。—— 代价写进 ⑤：小程序端仍会多打包招聘者页。
- **「我的」= 导航栏右上角常驻入口 → 推入页**（账号信息 / 凭据策略 / 退出登录）；**不给"切换到学员登录"入口**。—— 互斥的价值是"不可能同时是两个身份"，配切换按钮等于把互斥做成开关；学员侧入口只保留登录页底部那一个（纯文字链接，复用既有 link 样式，不加任何说明性文案）。
- **简历库 = 抽屉式筛选，对齐后端已支持的 8 个维度**（地区 / 岗位 / 证书 / 薪资区间 / 经验 / 用工性质 / 到岗时间），分页"加载更多"（`page_size=20`）。—— "检索"是 ADR-0021 ① 已写的范围，砍维度需要理由；后端有而 web 未用的两个维度（`experience_years` 精确匹配、`experience_max`）**本轮也不用**。
- **事实过期的 pending = 列表显示「已过期」纯事实、不给任何操作**；徽标与紧迫行**只统计未过期的 pending**。—— 见 ⑤ 已知缺口：过期在服务端不落状态，给入口就是 #705 判据禁的"看起来能用、用了必失败"。

**③ 明确不做的事**

- 不做 `tabBar.custom`；不做并存身份 / 双槽凭据；不做页内三态单页（分段只在三个独立页面间 `redirectTo`）。
- 不改 `clearAuthData()` 的"登出不清安全凭据"语义；不把身份切换的清槽并进它。
- 不给过期交换申请任何操作；不做"重新发起"入口（需后端先修，见 ⑤）。
- 不复活 `components/app-tabs` / `components/app-nav-bar` 两个死件；不把分段件提升为全局共享件。
- 不动后端；不做小程序端 / 支付宝小程序端；不开创 `pages.json` 条件编译。
- 移动端不做职位发布/编辑/上下架，不渲染任何"功能开发中"式占位。

**④ 拆分步骤（三票，各自 PR）**

1. **P1 身份面（唯一命中能力面）· #1194** —— 独立招聘者登录页（仅账号密码，`/auth/recruiter-login`）+ `auth_active_role` + 互斥清槽（含 `auth_secure_credentials`）+ 401 出口内角色分支 + 摘掉 `pages/login/login.uvue:114-122` 死桩 + 学员登录页底部纯文字入口。
2. **P2 骨架与三面 · #1195** —— `recruiter-tab-bar`（唯一一份，三页复用）+ 职位段（含紧迫行、强制下架标签）+ 投递列表（`unread_count`、标记不合适、不可逆确认）+ 交换段（数量徽标、剩余天数、已过期态）。
3. **P3 简历库与简历详情 · #1196** —— 抽屉筛选（8 维）+ 列表 + 详情（按 `resume_projection.go` 清单原生渲染脱敏卡）+ 打码 PDF 下载（次要出口）+ 发起交换 + 授权后 6 键明文渲染。

依赖：**P2 / P3 都依赖 P1**（身份与鉴权是它们的入口）；P2 与 P3 相互独立，可并行。

**⑤ 约束**

- `handleUnauthorized()` 仍是唯一 reLaunch 出口（`C2`）；学员路径行为（`I2/I3/I4`：一次跳转、清 access 侧、保留 `auth_refresh_token`、内存登录态归零）**必须保持不变**。
- 招聘者态不得调用 `/auth/refresh`；无 refresh token 是结构前提，不得为它补一条刷新链。
- `backend/internal/service/resume_projection.go`（ADR-0053 §4 / #1051）是打码规则与**三处投影字段清单**的唯一真源；移动端渲染不得自行增删字段。明文（真实姓名 / 电话 / 微信 / 上传 PDF / 工作照 / 证件原图）**只在 approved** 后经 `GET /recruit/resumes/{id}/contact` 获取；打码 PDF 端点 `/recruit/resumes/{id}/pdf` **不要求授权**。
- 导航用 `navigationStyle: "custom"` + `useStatusBarHeight`（与 46/48 页既有做法一致）；平台面仅 Android/iOS。
- `pages.json` / `manifest.json` / `platformConfig.json` 即使只改一行也不自行提交（`docs/agents/multi-agent-git.md`）。
- 已知代价（本 ADR 接受）：小程序端仍会把招聘者页面打进产物（仅源码级守卫 + 不发布）。

**⑤ 补充约束：出口对称性（2026-09-20，#1194 收口；PR #1206）**

**现象**：会话失效后被守卫送进招聘者登录页的用户，**退不出去**。维护者现场见到的形态是「一开 App 就是招聘者登录，且出不来」；真机日志里 `进入页面: pages/recruiter/contacts` → `进入页面: /pages/recruiter/login` **反复出现**（2026-09-20 19:59 连续三次）。

**事实**：

- 进本页的**两条路径都清空页面栈**：`utils/recruitGuard.uts:32` 的 `uni.reLaunch({ url: '/pages/recruiter/login' })`（P2 分支 `feat/mobile-1195-recruiter-workspace`），与 `api/request.uts:126-128` 的 401 角色化出口（本 ADR ② 那条「出口内部分支」—— 该处只有一个 `route != 'pages/login/login'` 判断，**不含**招聘者登录页自身的白名单，故在招聘者登录页上再吃 401 会 `uni.reLaunch` 回它自己）。`reLaunch` 之后**栈里没有可返回的页**。
- 而该页原本**只有** `navigateBack()` 与登录成功后的 `reLaunch → 学员首页`，**没有任何回学员端的出口** ⇒ 上面两条路径送进来的用户 `navigateBack` 无效，**困在本页**。这不是「不好用」，是死胡同。
- 更紧的一层：`auth_active_role` **只有 `loginAsRecruiter()` 会写**，学员侧任何登录路径（`stores/auth.uts` 的 `login()` / `loginByCode()` / `loginByWechat()`）都**不把它写回 `student`**；`clearIdentityForSwitch()` 也只在学员侧路径跑 ⇒ 即便侥幸回到学员登录页，下一次 401 仍按角色分支把人**再送回本页**（来回弹）。这正是本 ADR ② 那条「复用既有身份切换专用函数」要解决的事，而**出口缺失让它无法被触发**。

**结论（约束）**：

1. **但凡「以 `reLaunch` 为唯一入径」的页面，必须自带一条不依赖返回栈的出口** —— 判据是「出口自身用 `reLaunch`，且不以 `navigateBack` 为前提」。入径清空页面栈时，`navigateBack()` 不是出口。
2. **对称性**：学员登录页底部有招聘者入口（`pages/login/login.uvue` 的 `.recruiter-entry`），招聘者登录页底部就必须有**回学员端的镜像出口**（`pages/recruiter/login.uvue` 的 `.student-exit` / `.student-exit-link`，纯文字、复用既有 link 样式、不加说明性文案）。单向可进不可出即违反本条。
3. **出口必须先清角色标记、再跳转**：`clearIdentityForSwitch()` 的调用**必须早于** `uni.reLaunch`。顺序反了就留下「新页 + 旧角色」，下一次 401 仍按角色分支把人送回本页 —— 出口只做对一半不算数。
4. **整页不得留第二条件路径**：页内**所有**出路（左上「返回」、「身份互斥」模态的取消分支）都收敛到同一个出口函数；不得再有 `function goBack` 之类的独立返回实现。

**落锁**：`utils/concurrent401RefreshBehavior.test.js` 的 `describe('#1194 收口：招聘者登录页的回学员端出口')` —— **R6**（出口存在 / 不含 `navigateBack` / 目标是 `/pages/login/login` / `clearIdentityForSwitch` 的位置**早于** `uni.reLaunch` / 整页不得出现 `uni.navigateBack()` / 出口引用计数 ≥3 即「定义 1 + 模板 1 + 取消分支 1」，防止有人留第二条路径）；**R5** 用**真的** `api/request.uts` 把「清槽 → 后续 401 落回学员登录页、不再弹回招聘者登录页」整条链路走一遍；**R7** 是这条判断的**判别力对照**（不清槽 ⇒ 必红），不是为了凑绿。

**已知缺口（不在本 ADR 修复，已另立票 #1197）**

`contact-request-expire` 守护**未被装配**（`backend/cmd/server/main.go` 只装配了 `forum-image-cleanup` 与
`contribution-file-cleanup`），且**全仓无任何可外部触发过期的端点** ⇒ 超期的 `pending` 记录永久停在 `pending`；
又因"同企业同学生 pending 唯一"按 `status='pending'` 判，该组合的**重新发起被永久堵死**；
另外 `approved` 行过期后明文仍透出（门禁不看 `expires_at`）。ADR-0021 ① 的紧迫性论证
（"pending 14 天过期，晚回一天就是损失"）建立在一条**没有运行**的机制上，本 ADR 只如实反映，不掩盖。

**⑥ 验收标准（断言行为，不断言源码文本）**

- 三个一级面渲染**同一个**分段件（契约测试锁"全仓仅此一份 + 三页各挂一次"）；二级面无分段。
- 招聘者态首屏批量请求 = **2**（`/recruit/jobs` + `/recruit/contact-requests`）；**不逐职位拉 `unread_count`**（契约测试锁 N+1 禁令）。
- 招聘者登入后：学员三键为空、`auth_secure_credentials` 为空、`auth_active_role = recruiter`；学员登入后招聘者态不可恢复。
- 401：学员态 → `/pages/login/login`；招聘者态 → `/pages/recruiter/login`；两者都只 reLaunch **一次**；招聘者态不调 `/auth/refresh`。
- 过期 pending 显示「已过期」且**无任何操作入口**；徽标不把它计入。
- 移动端不存在职位发布入口，也不存在任何"功能开发中"式占位。
- `pr-evidence.yml` 的改动量 = 0。
