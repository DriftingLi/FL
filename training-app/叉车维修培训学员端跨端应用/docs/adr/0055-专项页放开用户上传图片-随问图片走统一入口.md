# 专项页放开用户上传图片：随问图片走统一入口、客户端先拦

- 状态：已采纳（2026-11-06，#2299 实施同批写入；放宽 ADR-0009 修订 ②）

## 背景

ADR-0009 修订 ② 把「发送图片」排除在专业版能力清单外，理由是「图片能力根本不存在」，并写明「图片能力落地后再并入」。
v2 单轨后链路已就绪：`/ai-assistant/upload-image` 唯一入站、站内 URL 随消息进对话、后端 3 张 / 5MB 闸门与纯图补话术均已联调（#2295 §5 决策 11–14）——属该条设定的「落地后」。

## 决定

1. 解除「专项页不含用户上传图片」：诊断页开附件入口（📎），选图**只经** `useAiImagePicker` 统一入口。
2. 单轮 3 张、单张 5MB 与后端 `diagnosisMaxImages` 同值；**客户端先拦**并给可读文案，跨栈守护 `aiImageLimitParityContract` 逐字比对两侧。
3. 允许「有图无字」发送：`canSend` 单一判据（有字 ∨ 有图），后端补默认话术。
4. 守护断言同批由否定改肯定（`aiFeatureEntryWiringContract` ⑦）：入口开、托盘在、页面不直调平台选图；压缩不可用（uni-app x 类型面无 `uni.compressImage`，本票现测）即原样上传，不因此挡发送。

## 后果

- 学员可拍照随问；服务端 20MB / 3 张 / 5MB 三道闸兜底。
- 手机端仍不渲染手册配图（属 #2300 二期池，本 ADR 不含）。
- 后来者新增任何图片入口，都必须先过 `useAiImagePicker`，否则守护判红。

## 不采用的备选

- 页面直调 `uni.chooseImage`（第二条上传路径）；自建上传端点 / base64 直传（与 ADR-0091 的「站内 URL + 白名单代理」边界冲突）。
