# 0035 - 移动端顶部安全区与页面骨架收口：单一页头件、胶囊让位与 token 化前置

**状态**：**决策定稿，落地暂停待重新思考**（2026-10-10；来源：一次 `/grill-with-docs` 形状的会话（**非 `/wayfinder`**，判据见文末节）对「小程序右上角胶囊遮挡 + App 端 UI 升级」的实测盘点 + 十八问收敛）。
**①–⑤ 一节的决策一条都未被推翻，可继续引用。② 但落地拆票已全部撤回**：曾拆 #1586 → #1590 五票（原生 `blocked_by` 链），**同日全部 `close --reason "not planned"`** —— 维护者判定**拆票的出发点要重新思考**：主流程是 `grill-with-docs → /to-spec → /to-tickets → /implement`，本轮**跳过 `/to-spec`**（ADR 顶了它的产物），于是五票只答「怎么做对」、无一张答「做成什么样」，**T4「形态收口」缺判据**。**本 ADR 不改写、不删；重新思考后应重新切票，而不是改写旧票**（票的 AC 若因前提改变而重写，它记下的就不是任何人的真实收敛过程）。详见 #1586 关闭评论。
**职责边界**：只裁**顶部安全区 + 视觉 token 可用性**两件事；页面信息架构、底部安全区、深色模式、列表/空/加载态共享协议**均不裁**（各见 ③），留给专项轮次。
**范围界定**：本 ADR **解** 0022 ③ / 0028 ③ 对 `components/app-nav-bar` 的禁令（该禁令字面覆盖页头件，但其原文限定「不把**分段件**提升为全局共享件**」**，`app-tabs` 仍在禁令内）；**修正** `docs/ui-spec.md` 的 4 处漂移（`$border-color` 色值、`$radius-lg` 值与缺失的 `$radius-xl`、§6.2 模板里的 `$bg-page`、§6.1/§6.2 模板的裸 `<style>` 与自带 `.status-bar`）——**该修正已随旧 #1586 落盘在本工作树（未入库）**。
**来源**：`/grill-with-docs` 形状的会话（先用 grep 把现状做成**事实**——58 页 custom 导航 / 57 处 `.status-bar` / `getMenuButtonBoundingClientRect` 全仓 0 命中 / `manifest.json` 无 `app-plus` 段——再 grilling 十八问收敛）。判据是「能不能一手握住」：本任务能一手握住，**故不建 wayfinder map，本 ADR 即本仓的规范面**（同文末节）。曾拆五票 `#1586 → #1590`（已全部关闭，见状态行）。

> **一句话**：微信小程序右上角胶囊遮挡**不是个别页的缺陷，是全站缺统一约定**——58/60 页设 `navigationStyle: "custom"`（避让责任 100% 在项目代码），
> 但 `getMenuButtonBoundingClientRect` 全仓 0 命中，57 页各抄一份 `<view class="status-bar">` 占位，另有 21 个文件各自手写 nav-bar，
> 且三个该收口的页头件全是零引用死件。更底一层：**131 个 `.uvue` 只有 22 个声明 `<style lang="scss">`**，
> 47/60 个页面连 `$primary-color` 都用不了，只能写裸 hex（2184 处）——**token 化在这 47 页上物理上不可能**。
> 本 ADR 的核心动作是**先让 token 可用，再让顶部安全区只有一个真源**；不新建设计语言，不做深色模式，不动信息架构。
>
> **与 `docs/ui-spec.md` 的关系**：那份是**规范**（应当怎样），本 ADR 是**收口决策**（现在先做哪一步）；
> 两份不改写对方的定义，只在 T1 里把那份的 4 处漂移改对。

## ① 目标与范围

**目标**：① 顶部安全区与胶囊让位**只有一个真源**；② 视觉 token **在全部页面可用**；③ App 端状态栏由壳层配置兜底，不再全靠页面自绘。

**在范围内**：token 化前置（`lang="scss"`）、`useSafeArea()` 测量层、共享页头件复活、五个 tabBar 页 + AI 线改造收口、`manifest.json` 新增 `app-plus` 段、契约测试。

**不在范围内**：深色模式/主题（`.uvue` 不支持 `var(--x)`，架构上无落点，单独一轮）、信息架构重做（tabBar/页面层级/底部操作条重排）、底部安全区（home indicator，见 ③）、列表态/空态/加载态共享协议（ADR-0027 ③ 明记 K6 未做，另开一轮）、非头部区域的色彩与卡片重构（T5 之后）。

## ② 选型 + 一句理由（十八问收敛，逐条给出「一句话理由」）

1. **终点形状 = 可交接 spec**（ADR + 切票），不原地改完：60 页 × 双端必须拆成可独立验证的 PR。
2. **不建 wayfinder map**，按仓库约定 ADR 即 map：多一层 map 会成为第三份事实源（`issue-dispatch.md` §0 的判断是「重复票的成因之一是决定里不做的那半被即时开成票」），而 60 页 UI 改造正是「很容易多做半」的活。
3. **技术路线 = 测量层 + 共享页头件**：只加顶部占位（保留手写）已复发一次——`platform-nav-bar.uvue` 就是那份「只加占位」的产物，0 引用；退回系统导航栏会打散 58 页视觉统一性，与「UI 升级」目标相反。
4. **App 端范围 = 视觉现代化 + 一致性收敛，头部/安全区层为唯一架构改动面**：深色模式在 uvue 上无落点（不支持 CSS 变量），信息架构重做验证成本过高会拖到收不了口。
5. **两端同源一套设计语言**，小程序端只做平台补偿（胶囊/安全区/下拉刷新/H5 兜底）：两端本就同源（ADR-0028 在做收敛），分两套会让每页验证面翻倍，而每页验证都要走真机与小程序门。
6. **验收按批次（先 5 个 tabBar 页走完整四门），收口判据是关键页取证**：形态未确认就铺 60 页，返工量最贵；ADR-0016 已定「①a 按一次分支收口跑，不跨 PR 共用」。
7. **解 `app-nav-bar` 禁令、`app-tabs` 继续禁**：0022/0028 的原文限定「不把**分段件**提升为全局共享件」，`app-tabs` 确属分段件；`app-nav-bar` 是仓内**唯一已实现且 uvue 合规**的页头骨架（`height: 88rpx`、`$spacing-md`、`$font-size-xl` 全是现成 token），废弃它另起炉灶等于在一个已通四门的骨架上再交一次学费。
8. **状态栏底色三派不做独立票**：共享页头件统一后 `.status-bar` 变成页头件的内部实现，「收三派底色」被「删 57 行 + 换 1 个组件标签」自然消解。
9. **`pages.json` / `manifest.json` 提交纪律分层**（0022 ⑤ / 0028 纪律不变）：允许改 `manifest.json` 的 `app-plus` 段（**新增段，不动 `appid` 等既有键**），`pages.json` 仍禁改——给 `globalStyle` 加 `navigationStyle` 兜底会让 `register` / `forgot-password` 两页**行为静默改变**（框架开始画导航栏），属真行为变更，必须走人工门。
10. **机检采用「反向 + 渐进」**：只断言**共享页头件自身**满足胶囊让位，不强制 57 页逐页替换；新页必须走共享件，旧页在各自票里换掉时逐个转绿。正向全量断言会让 T3 一开始就大面积红，阻塞批次策略。
11. **底部安全区单独一轮**：`safeAreaInsets` 已实测栽过一次，且截图门顶部噪声问题说明真机验证链本身还不稳；底部触及 5 个 tabBar 页底栏 + 底部操作条，验证面比顶部大。
12. **与 0028 的衔接 = 只碰状态栏与页头色彩**：页面主体色彩留给 0028；状态栏/页头正是 0028 声明「骨架不动」里的头部区，本轮动的就是这一区。
13. **先全量补 `lang="scss"`（不改任何样式值）**：47 页用不了 token 是**视觉现代化的总开关**，不先解决则后续 token 收敛全是空转；而这项本身可验证——补完后变量名写错会立刻表现为样式静默丢弃，等于一份免费的机检面。按批次补会让「这页补没补」永远模糊，收口时给不出整体判据。
14. **主色收敛先只改 `uni.scss` 一个值**，不逐文件替换 302 处：改一个值是最便宜的杠杆，且天然可验证——若全站视觉一致地跟着变说明都在用 token，若只有一部分变就定量出裸 hex 面；302 处替换 diff 不可评审，应独立成票、在 token 化之后做。
15. **只解 1 件死件，不解 4 件**：`app-nav-bar` 有**被 57 页证实的需求**（需求真实存在）；`app-card`/`app-button`/`app-list-item`/`app-badge` 0 引用 + 未验证，而 ADR-0014:32 对 `app-list-item` 有**实质否决理由**（只有 label/value 两段式，承载不了三行结果行）。先解需求已证实的，比同时解四个需求未证实的更稳。
16. **列表态/空态/加载态本轮不补**：0027 ③ 的「重构与 UI 分时」不构成本轮反例，但扩充共享件品类会显著拉长本轮，且其语义依赖 0027 已给的 `failed=true` 保留 items 口径，属「有据可依但不紧急」。
17. **全仓仅此一份页头件，差异用 prop 表达，`fork` 即违规**：ADR-0022:41「**ADR-0009 的病根是『两份手画的栏』，不是『面多』**」是全仓最重的导航经验；现状是 `AiChatNav` + 手写 `app-nav-bar` + 21 个页面各自手写 = **三套页头并存**，正是那条经验所说的复发形态。`AiChatNav` 必须改为 `app-nav-bar` 的一个配置而非兄弟件——AI 线恰是胶囊问题最隐蔽处（沉浸式 + 侧滑抽屉 + 键盘）。
18. **死件的生死判据 = 有没有 `<style lang="scss">`**：8 件里唯二活着的 `app-chip` / `app-empty-state` 恰好是 22 个共享件里唯二声明了 `lang="scss"` 的；反过来那 4 件死件引用的 4 个变量名在 uni.scss 里根本不存在。⇒ 复活任何死件的第一步都是补 `lang="scss"` + 清不存在变量名。

## ③ 明确不做的事

- **不做深色模式/主题**：`.uvue` 不支持 `var(--x)`（`docs/agents/uvue-css.md:41`），唯一载体是编译期写死的 SCSS 变量，不存在运行时切换 ⇒ 架构上无落点。
- **不改 `pages.json`**：不给 `globalStyle` 加 `navigationStyle` 缺省兜底（会让 2 页行为静默改变），`register` / `forgot-password` 的顶部让位问题留人工门。
- **不改 `manifest.json` 的既有键**（`appid`、三份 `icons`）；只新增 `app-plus` 段。`config/agents/` 下 `HBuilderX` 会回写置空 `appid` 的既有坑照旧，跑完任何 HBuilderX 门后照旧 `git status` 查脏。
- **不做底部安全区**（home indicator）：另开一轮，见 ②-11。
- **不复活 `app-tabs` / `app-card` / `app-button` / `app-list-item` / `app-badge`**（T5 只做评估，不预判结论）；**不复活 `page-container.uvue` / `platform-nav-bar.uvue`**（二者逻辑被 T3 的 `useSafeArea()` + `app-nav-bar` 吸收后即冗余，直接删除而非并存——并存就是两份长得不一样的栏）。
- **不开创 `pages.json` 条件编译**；不做分包（0022 ⑤ 纪律）。
- **不逐文件替换 302 处 `#2979ff`**：T1 只改 `uni.scss` 一个值，替换另开票。
- **不做 E2E**：PR #1136 已裁决本仓无 E2E 入口（ADR-0020），验证走 ①a 截图 + `vision_dominant_colors` 逐区取色（ADR-0014:85-86 的手法）。
- **不把「已存在但未被 pages.json 引用」当缺陷外溢**：60 页与 108 个 `.uvue` 一一对应，无孤儿页，本轮不清理 `pages/*/components/` 下的 48 件页面私有组件。

## ⑤ 约束

- **`.uvue` CSS 四条铁律不变**：`<style>` 必须 `lang="scss"`；选择器只认 `.class`；文字样式只落文字类元素；**不支持 `gap`/`calc()`/`env()`/`vh`/`vw`/`grid`/`var()`/`currentColor`/`transition`/`animation`**（`docs/agents/uvue-css.md`）。⇒ **安全区只能 JS 动态取**，`env(safe-area-inset-*)` 与 `var(--plus-safe-area-inset-*)` 两条 CSS 路在本仓都不成立。
- **渐变语法不变**：ADR-0010（只接受 8 个 `to` 关键字、禁 `deg`、恰好 2 色、禁百分比停靠位、兜底 `background-color` 写在简写**之后**），守护 `utils/gradientSyntaxContract.test.js`。
- **一个视觉主题一个 commit**：T2 的补声明（无视觉变化）与 T4 的视觉改造不得混在同一 commit。
- **机检只断言行为、不断言源码文本**（ADR-0008 先例）；`pr-evidence.yml` 的改动量 = 0。
- **截图门必须带 `-IgnoreTopRows`**（顶部 0–120px 有 MIUI 实时网速噪声，否则恒红）；跨天基线会让「改坏」与「没改」分不开，T2 走同帧 `‑UpdateBaseline` 三腿协议（ADR-0034）。
- **改动落 `training-app/**` 一律不在宿主树做**，走 `pwsh training-app/叉车维修培训学员端跨端应用/scripts/new-worktree.ps1 -Task <票号>`（ADR-0029）。该 ADR 判据 A 记着**宿主树里 ③ 恒假绿**（`--listTests` 0 套件却 exit 0），所以这不是风格偏好，是「假绿」防线。
- **本仓的 `docs/refactor-decisions.md:42` 冻结清单含 `manifest.json` / `App.uvue` / `config/`** ⇒ T3 改 `manifest.json` 与该冻结冲突。本 ADR 判定：`App.uvue` 与 `config/` 仍冻结（T3 不碰），**`manifest.json` 解冻但只允许新增 `app-plus` 段**；这条解冻已在上文 `docs/refactor-decisions.md` 加了交叉引用，但**冻结清单本体留给那一票所在会话的人签**（改冻结清单本身属纪律变更，不该由本票顺手带走）。
- **每票一会话**（AGENTS.md「一件票一个会话」），票间 `/clear`。
