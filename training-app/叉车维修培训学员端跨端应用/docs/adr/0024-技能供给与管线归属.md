# 0024 - 技能供给与管线归属：清退仓内死副本 + 立四条约定

**状态**：已接受（2026-09-21，来源：#1230「技能供给与管线归属收口」（只读取证 + triage 分流 + 维护者裁决）；落地：PR #1231 / 本 PR / 票 3、票 4）

> **一句话**：移动端树里躺着 **103 个从不被加载的技能副本文件**（`.agents/skills` 100 + `.opencode/skills` 3）与一条**机器生成的技能目录块**，而已跟踪文件里对它们的引用数为 **0** —— 本 ADR 记下「为什么不生效」「为什么入库是错的」，并立四条约定把这类东西挡在版本库外。

## ① 目标与范围

要治的是**「副本入库却不生效」**与**「生成物入库」**两件事，不是技能集合本身的取舍（用哪些技能、用哪个版本，归插件与 `skills-lock.json`）。

三处可复核的事实（实测见「附」）：

1. **生效面由 harness 的扫描根决定，而它止于 git 根**：`dsh-skill-filesystem` 的 `findProjectRoot` 从 cwd 向上找最近的 `.git`，扫描根依次为 `projectRoot/.dsh/skills`(rank 100) → `projectRoot/.agents/skills`(200) → 自定义(300) → `~/.dsh/skills`(400) → `~/.agents/skills`(500) → bundled(600)。cwd = `D:\FL` ⇒ projectRoot = `D:\FL`，**只扫 `D:\FL\.dsh\skills` 与 `D:\FL\.agents\skills`（两者都不存在）** ⇒ 移动端子树下的两份副本**从不被加载**，实际生效的是插件自带副本（rank 600）。
2. **它们是惰性的**：`git grep` 检索 `.agents/skills` / `.opencode/skills` / `skills-lock` 在**已跟踪文件里命中 0** —— 没有脚本、测试、CI 或文档指向它们。
3. **入库是有意的，但没有独立评审面**：落地提交 `9305dd0d`（PR #534，168 文件）的提交正文写着「Install 37 engineering skills from mattpocock/skills」，与 `docs/agents/` / `docs/adr/` 同批；被压进一个大 docs PR 里，事后无人复核时效性。同类第二例：移动端 `AGENTS.md` 里 `<available_skills>` 的 65 行**机器生成块**（2026-09-02 落库），由 PR #1231 清退。

**范围**：移动端 `training-app/叉车维修培训学员端跨端应用/` 的技能供给面（`.agents/skills/**`、`.opencode/skills/**`、`AGENTS.md` 的生成物块、`skills-lock.json` 的定位）与承载四条约定的 `docs/agents/skills.md`。

**不含**：不改四门（移动端 `docs/adr/0008`）、不动读取层（`0019`）、不动守护分类（`docs/agents/guards.md`）、不评估技能集合本身的取舍。

## ② 选型 + 一句理由

| 决策 | 一句话理由 |
| --- | --- |
| **① 删除两份死副本，不保留「以备参考」** | 0 引用、0 加载，活的副本在插件里 —— 留着只会制造「改错了那一份」的误操作面 |
| **② 第三方技能内容不入库，仓库只记来源与版本** | 分发归 plugin / 包管理器；`skills-lock.json` 已有 37 个键的 `source` / `skillPath` / `computedHash`，仓库要的是**可追溯**而不是内容副本 |
| **③ 生成物不入库** | harness 注入的技能目录/上下文块是**必然过期**的产物，没人会维护它，且会把死路径固化进版本库（#1231 实测块内 3 条 `E:\FL` 死路径，而 `E:` 盘已不存在） |
| **④ 技能改动独立成 PR** | 入库技能文件里的 `.yaml` / `.sh` / `.cjs` **不在** `pr-evidence` 的低风险白名单（`*.uts` / `*test.js` / `*.md` / `jest.config*.js`）⇒ 与 `.uvue` / `.uts` 混在同一 PR 会把整单降级为**常规运行时面**，① 真机与 ② 微信开发者工具双双变必过 |
| **⑤ 引用技能文档引小节名，不引行号** | 行号随上游版本漂移（实测两份快照的 `grilling` 已不同：A 版 29 行 / B 版 23 行），小节名不漂 |
| **⑥ 四条约定落在移动端 `docs/agents/skills.md`，写明「仅移动端线」** | 四条病根全部发生在移动端树内；照 `issue-dispatch.md` 先例标明作用域，前后端会话不读、不受约束 |
| **⑦ 清退动作与决策同批可复核** | 约定入库而东西还在，就会出现「写了约定、仓库照旧」的空转 ⇒ 清退清单作为票面交付物逐条结清（票 3 / 票 4） |

## ③ 明确不做的事

- **不在根 `D:\FL\.dsh\skills\` 落技能**（2026-09-21 裁定）：它是 rank 100 的扫描根，**压过用户级(500)与插件(600)** ⇒ 一旦放入就改变**所有会话**（含前后端）的生效版本，收益不抵这个面。
- **不新建根 `docs/agents/skills.md`、也不在根 `AGENTS.md` 加指针**（同日裁定）：会让这四条进入所有会话的常驻上下文，收益未证明。
- **不把插件目录里的技能内容复制回仓库**，也不为仓内副本补 LICENSE / README / VERSION —— 内容归上游（MIT © 2026 Matt Pocock，版本 v1.2.3）。
- **不改根 `docs/agents/issue-tracker.md` 的 wayfinder 结论**：其表述澄清归 #1234（只澄清表述、不改结论）。
- **不动历史记录行里的 `E:\FL`**：`docs/agents/multi-agent-git.md` 明写「本文件与 `handoff-验收门-2026-09-11.md` 里其余写死 `E:\FL` 的行，绝大多数是历史/现测事实，**不要跟着改，改了就是篡改记录**」⇒ 票 4 只清**导航句**。
- **不动 `.opencode/.gitignore` 与 `skills-lock.json`**：前者仍是有用的忽略规则，后者是唯一的来源记录。

## ⑤ 约束（不能动的）

- **生效面不迁**：仓内**不得**出现会改变全局会话技能版本的东西（尤其根 `.dsh/skills`）；四条约定不授权任何「把技能放进仓里让它生效」的做法。
- **`skills-lock.json` 保持现状**：它记的是**上游路径**（`skills/engineering/*/SKILL.md`）与 `computedHash`，**不指本仓路径** —— 这是它作为「来源记录」的正确形态，不要为了「看起来完整」改成指向仓内副本。
- **`.opencode/.gitignore` 不动**：它忽略自身与 lock 的行为与本次清退无关。
- **`docs/agents/**` 只增不删**：过时用「取代」表达（`docs/agents/domain.md` 的分层纪律）。
- **改动集不得命中运行时面**：命中即须按移动端 `docs/adr/0008` 走四门，本 ADR 的验收口径随之作废。
- **不重开已决**：根 `.dsh/skills` 落点与根 `docs/agents/skills.md` 两项已于 2026-09-21 裁定不做，不因「顺手」重新开张。

## ⑥ 验收标准

1. **约定可读**：移动端 `docs/agents/skills.md` 入库、四条约定逐条成文，并写明「仅移动端线，前后端会话不读」；本 ADR 中文文件名 + 六段齐全。
2. **指针在位**：移动端 `AGENTS.md` 的 Agent skills 段指向 `docs/agents/skills.md` —— 否则约定无人读，而本票治的正是「文档没人读」。
3. **仓内不再有从不被加载的技能副本**：`git ls-files` 在 `.agents/skills` 与 `.opencode/skills` 上命中 **0**（票 3 收口时校验）。
4. **零回归**：`npm run test:unit` 全绿（本 PR 实测 suites / tests 数见「实施记录」）。
5. **不命中运行时面**：改动集只有 `.md` ⇒ PR 正文写「免（未命中运行时面）」（先例 #908）。
