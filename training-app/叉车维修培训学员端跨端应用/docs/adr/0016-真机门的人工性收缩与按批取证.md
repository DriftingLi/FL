# 0016 - 真机门的人工性收缩与按批取证

> 状态：已裁定（grilling 收敛，2026-09-16）｜来源：本会话对 ① 门「触发面 × 签收 × 取证节奏」的三项裁定
> **落地状态：文档口径已落，机制改动未做**（拆票见 ④）。生效前 ① 仍按 `0008` 的现行口径执行。
> **职责边界**：只改 ① 真机门的**触发面**、**签收语义**与**取证节奏**；不动 ②③④ 的触发与证据口径，不动 `pr-evidence` 的真伪口径（仍只校结构），不动移动端源码。

**① 目标与范围**

① 的触发条件一直是「改动碰了什么文件（运行时面）」，于是「改一行 `.uvue` 文案」与「改指纹门控」付**同样的**代价：真机 10–20 分钟 + 人签整条 ①。而真机真正能抓到、agent 抓不到的东西只有四类（指纹按压 / 运行时权限弹窗 / 真机上传路径 / 厂商 ROM 交互）。本 ADR 把 ①b 的触发从「碰了什么文件」换成「**这次改动改变了什么只有人能观测的东西**」。

实测锚点（现测，非叙述）：#1028（纯样式 PR）走了 ① 真机、7 张入库截图；同一份 diff 的 `level-detect.ps1` 判 🟢 且理由文案是「纯样式/文案改动，**未命中运行时面**」—— 同一份改动，本地报免、门报必过。

**② 选型 + 一句理由（六条裁定）**

- **①b 只由「能力面」触发**（指纹 / 运行时权限弹窗 / 真机上传 / 厂商 ROM 交互）—— 这是 agent **机械上无法覆盖**的唯一集合：`adb shell input` 既不触发指纹传感器、也在 `device-capture.ps1` 的只读红线内被禁（0008 已论证）。
- **能力面的可机检口径 = 路径白名单 + PR 模板自报勾选**；**自报是声明，不是判据**（与「已接受未验证风险」同族：允许例外、禁止静默），漏报属违规 —— 因为基于 diff 文本/字符串的触发判据已被 #1030 否掉（误报 + 反向激励；ADR-0008 原话「判的是『改动文本里出现过这个字符串』」）。
- **① 行的「执行人」栏允许写「agent 执行」**（该行只覆盖 ①a 时）；含 ①b 时仍由**人给出原文**、agent 可代录（2026-09-15 根 `AGENTS.md` 口径）—— 校验器**分不出人/agent**（单账号），所以这条只能落在 `AGENTS.md` 的行为约束上，与 ④ 门「填执行会话所用账号并注明『agent 执行』」的先例一致。
- **不为 ① 引入评论承载**（不扩 `gateComment`）—— ④/② 需要 sha 绑定评论，是因为它们的产物在 `.ci-verify/`（**本地产物**，push 一次就作废）；① 的产物是**入仓截图**（`docs/verification/<模块>/<PR号>/`），与 commit 同生共死。照抄别人的解只会多一个漂移面。
- **①a 按「一次分支收口」跑**（不是 PR 内的每次微调，也不跨 PR 共用）—— 一次真机运行**只反映一棵树**；跨 PR 共用必须把证据绑定判据从「祖先 + 其间运行时面未变」放宽成「包含 + 页级投影」，而放宽方向与 2026-09-12 那次收紧相反，且指向 #898（五张 after 图同哈希）那类假绿。
- **④ 维持每 PR**，冷态只做可见事实、不做降级条款 —— 缓存冷热**没有**现成机检（`hx-busy.ps1` 只做锁 + 忙探测 + 上限），写成条款即退化成「我觉得今天慢」；且「④ 已推迟」在现有校验器下必然判红（④ 的结论字段要求命中 `build.log|kotlin-all.log`），唯一的绿路是例外通道 ⇒ **由人执行合并**，与本次把人工挡在合并路径之外的方向相反。

**③ 明确不做的事**

- **不删 ①**，不改 `pr-evidence` 的真伪口径（仍只校结构、不校真伪）。
- **不引入基于 diff 文本 / API 字符串**的触发判据（#1030 的教训）；原生能力调用点扫描**只做提示、不判红**。
- **不按 mtime 判缓存冷热**，不设「冷态降级 ④」条款（判错冷就把编译期错误漏到真机，是 `AGENTS.md` 反模式第一条的血账）。
- **不跨 PR 共用一次真机取证**（堆叠 PR / 集成分支的「包含 + 页级投影」绑定不做）。
- **不用评论承载 ①**；不追溯已合并 PR。
- 本次术语（①a / ①b / 能力面 / 收口批）是**工程流程词**，home 在本 ADR 与 `0008`，**不进 `CONTEXT.md`**（那是产品领域词汇表）。

**④ 拆分步骤（后续票，均未做）**

1. **能力面白名单与 0016 同批落地**（否则生效当天判不出「能力面」）：白名单 + PR 模板自报字段；收口脚本（`dev:finish`）打印「本批触及能力面：是 / 否」并扫一遍原生能力调用点（**提示行，不判红、不进 `pr-evidence`**）。
2. 口径同步：`0008` 就地修订标记（本次已做）→ 移动端 `AGENTS.md`「验收门与合并纪律」+ 根 `AGENTS.md` 验收门段 → `docs/agents/release.md` L24（删「与是否命中运行时面无关」这句过严话、修漂移锚点）→ `docs/refactor-decisions.md` 四门口径 → `.github/PULL_REQUEST_TEMPLATE.md`（L29 的「agent 不得代填」+ 新增自报字段）。
3. 三个写实 bug 同批修：`level-detect.ps1` 的 quick 理由文案（对既有 `.uvue` 说「未命中运行时面」）、`dev-finish.ps1` 结尾那句会让 PR 判红的建议句（「免（低风险运行时面：仅 .uvue 样式/文案改动）」——「低风险运行时面」在 `0008` 里恰是「**无 .uvue**」）、`pr-evidence.yml` 与 `release.md` 的锚点/口径漂移。
4. 守护：能力面白名单与自报字段的契约测试（**断言行为，不断言源码文本** —— 先例：0008「门脚本守护从『断言源码文本』改为『断言行为』」）。

**⑤ 约束**

- 「运行时面」（`*.uvue` / `*.uts` / 三份 json，文件清单判据）**仍是 ③④ 的触发判据，本次不动它**；「能力面」是**新增的一层**，只决定 ①b 要不要人签。
- 自报与白名单**都不进 `pr-evidence` 的判红路径**：漏报靠 ①a 的 logcat、评审与「闭环条款」（人工门当场抓到的问题必须回写为守护规则或注入自检）兜。
- 单账号残余风险照旧：agent 会话与 `zhengcookie` 同账号，GitHub 侧分不出人/agent（`0008`「为何不装『必检 + approve』」段），阻塞仍落在行为约束上。
- **生效时点：按合并时点判定**（与 `0008`「生效时点与追溯」的先例一致）——0016 与白名单合并后新合并的 PR 按新口径；已合并的不追溯。现测 `gh pr list --state open` = 0，故「正在进行的 PR」无需过渡条款。
- 例外通道（「已接受未验证风险」）语义不变，仍由人执行合并。

**⑥ 验收标准**

- 一个**只改 `.uvue` 文案/色值**的 PR：① 行由 agent 出证（入仓截图 + 机检行），**无 ①b、无人签**，证据段填齐即可合并。
- 一个**改指纹门控 / 权限弹窗 / 真机上传**的 PR：白名单命中或自报为「是」⇒ **①b 必做且由人给出原文**；自报漏报 ⇒ 合并前发现即补做、合并后发现走事后验证回执。
- 一次**收口批**：一次 ①a 覆盖该分支全部改动页并绑定该分支 head；其后仅文档/脚本 push 不需重跑（沿用 `0008` 的「祖先 + 运行时面未变」），收口后再改运行时面 ⇒ 相关页必须重跑。
- **`pr-evidence.yml` 的改动量 = 0**（本次不新增任何校验判据）。
