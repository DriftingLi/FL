# AI 回答正文配图渲染：单独一档、只认站内代理出口

- 状态：已采纳（2026-11-07，#2362 决策收口；实施随后同批提交）

## 背景

一期把手机端配图定为**有意的能力扣减**（#2295 决策 20）：回答正文走论坛档、该档不声明 `image` ⇒ `![alt](url)` 退化成 alt 文字。二期要让配图可见，而票面「三件」漏了承重件 —— #1279 的 `expandImageMarkers` 位于**解析之前**，把 `![alt](url)` 改写成 alt、URL 当场丢弃 ⇒ 只给档位加成员仍出不了 `image` 块。

## 决定

1. 新增第 4 档 `SUBSET_AI_ANSWER` = `heading/list/quote/code/divider/image`：声明 `image`，**不声明** `inline`，不含 `table`（沿用「按行退回原始文本」的段落地板）。论坛档、精选档声明表不动。
2. `expandImageMarkers` 原语义保留；新增 `expandLegacyImageMarkers`（只展开 `<<IMAGE:…>>` 历史标记），AI 壳层换用它；两条入口共用**同一条扫描循环**（各写一条 = 两条展开口径会漂移，套件有判据）。markdown 图原样进解析器：**独行**图出 `image` 块，**句内**图由 `stripInlinePlain` 退化 alt（两形实测均无 URL 泄漏）。
3. 客户端站内闸：`image` 块先经 `resolveFileUrl` 归一（**相对 / 绝对站内两形同源**），只放行 `/api/ai-assistant/diagnosis/ossimg/` 前缀；其余退化成 alt 段落，alt 也为空则整块丢弃（无可读内容时不留空壳）—— 后端回归时手机上先兜住，不让 AI 正文驱动请求任意主机（ADR-0063 决策 3 的原始动机）。该前缀与后端 `diagnosisImageRoute` 由跨栈判据逐字比对。
4. URL 拼接唯一点 = `utils/format.resolveFileUrl`（真拼接那份）；壳层解析成绝对后供模板 `:src` 与 `previewImages` 共用。`utils/forumDisplay.uts` 的恒等桩维持现状，论坛面本轮零改动。多图预览按消息收集绝对 URL 走既有 `forumDetailDisplay.previewImages(urls, index)`，同消息左右翻。

## 后果

- 图宽受气泡约束（`mode="widthFix"` + `width:100%`，章节/精选两面先例）；回答不再渲染行内记号（`**粗体**` 由外露记号变抹平纯文本 —— 修既有外露，不是新缺口）。
- 论坛面块数组逐字不变，「论坛档不声明 `image`」的判据保留；新增第 4 档要同批扩 `markdownSubsetBehavior.test.js` 的 `SUBSETS`/差集断言，并改 `aiAnswerBodyBehavior.test.js` 成对变异的锚点串。
- 句内图升块、气泡改走 runs 属后续（另票）。

## 不采用的备选

- 复用 `SUBSET_FEATURED`（已含 `image`，零新增声明）：把「三端交集」的理由与本面绑定，精选面一改就摆动回答气泡。
- 复用 `SUBSET_CHAPTER`（含 `table`）：窄气泡里表格不可读，且要多写一条渲染分支。声明 `inline` + 气泡改走 runs：范围超出本票，且不改 runs 时句内图 URL 直接外露。
