# ADR 0010 · uvue 渐变语法约束

- 状态：已采纳（2026-09-13，#937）
- 范围：本应用所有 `.uvue` 的 `<style>` 块

## ① 目标与范围

钉死 uvue 原生端 `linear-gradient` 的可接受写法，消除「写了渐变、真机上静默不画」这类**不报错、不警告**的失败。

## ② 选型 + 理由

| 项 | 取值 | 一句话理由 |
| --- | --- | --- |
| 方向写法 | 角度（`135deg`）与关键字（`to bottom`）**都可用**，**保留原样** | 真机探针 A4 用 `135deg` 画得出来 ⇒ 方向不是病因，别为改而改 |
| 颜色值个数 | **恰好 2 个** | 探针 B3（关键字 + 4 值、无百分比）同样被丢弃 ⇒ >2 个值本身不被接受 |
| 百分比停靠位 | **禁止** | 探针 A1 / B2 带 `%` 一律整条丢弃 |
| 声明形态 | 统一简写 `background`，兜底 `background-color` 写在**之后** | CSS 简写会重置未列出的 `background-color` ⇒ 兜底写在前面等于没有 |

## ③ 明确不做的事

- 不再断言「不得出现 `deg`」——角度合法，早期结论已被真机探针证伪。
- 不切图、不把渐变一律改成实色。
- 不回改已按实色落地且外观正常的模块（`pro-banner`、`ai-chat-pro-sheet`）——只订正其注释里的错误归因。

## ④ 拆分步骤

1. 全项目 22 处收敛为「2 值 + 无 `%`」并补实色兜底（按模块分提交）。
2. 落地守护 `utils/gradientSyntaxContract.test.js`（注入自检 + 真实文件零命中）。
3. 订正被证伪的归因：3 处源码注释 + `docs/对齐成果-AI助手底栏与专业版形态.md` + 两个既有契约测试。

## ⑤ 约束

- 守护**只扫 `<style>` 块并剥离注释** —— 注释里写着 `linear-gradient` 不算实现（避免假阳性）。
- 参数切分必须按**顶层**逗号做：`rgba()` 内含逗号，用 `[^)]*` 抓参数会误判。
- `.uvue` **不支持 CSS 变量** ⇒ 渐变无法收成一个 token，只能逐处写字面值（这正是「同一写法重复 22 处」无法消除的原因）。
- 「兜底是否真能兜住」**未单独实测**：探针里兜底写在简写之前，与「整条被丢弃」不可分辨 ⇒ 本 ADR 不宣称兜底一定生效，只规定其书写顺序。

## ⑥ 验收标准

- [ ] `utils/gradientSyntaxContract.test.js` 全绿，且其「注入自检」样本在检测器被削弱时会红。
- [ ] 全项目 `.uvue` 渐变声明：颜色值恰好 2 个、无 `%`、无 `background-image` 长写、兜底在简写之后。
- [ ] 真机逐页截图证明被改处不再是纯白或透明（① 人工门）。
