# 0051 - 收藏「题目」按题库类别下钻（字典驱动）

**状态**：已采纳（2026-10-30，#1947；维护者两问裁定「二级 chip 行 / 字典 + 当前证件」；本 ADR 与实现同批）

## ① 目标与范围
收藏页「题目」类型内部加**一层**题库类别下钻（spec #1935 Q25：不推翻内容类型 tab）。后端 #2067 已提供 `GET /favorites?tag_id=`（仅 `target_type=question` 生效，其它类型 400）。仅移动端。

## ② 选型 + 一句理由
- **二级 chip 行 + `?tag_id=` 过滤**：分组标题要全量拉完才稳定，分页会把同类目拆开重排；`tag_id` 是后端白给的过滤参数，只有下钻用得上它。
- **类别清单取 `getTagsApi` + `getCurrentCredentialApi`**：从已加载条目派生会让类别随翻页增长，第 21 条之后才出现的类别第一屏看不见。
- **`tag_id` 判据放 `api/favorite.uts`**：页面漏判也发不出那个必然 400 的请求；一处判据两层都安全。
- **不重排、不读条目 `tags[]`**：`/tags` 已按 sort_order 下发，再排一次是第二份排序知识；字典驱动下 `tags[]` 没有读者。

## ③ 明确不做的事
不建「收藏内类别聚合」接口；不让「题目以外」渲染这一层；不给空类别特判（点进去是空态，字典驱动的已知代价）；不引入「题目归属唯一类别」的新裁定（一题多标签即出现在多个类别下）。

## ④ 落库面（单票，不拆）
`utils/favoriteTagDrill.uts`（决策唯一实现）· `api/favorite.uts`（第四参 `tagId`）· `pages/profile/favorites.uvue`（chip 行 + `tagId` 状态）· `utils/modules.js`（profile 消费 courses / dashboard）· `utils/favoritesTagDrillContract.test.js`（行为守护）。

## ⑤ 约束（不能动的）
六个内容类型 tab 与 `VALID_TYPES` 不动；`GET /favorites` 既有参数与 `favorites` 数组键不动；既有五类收藏行为一字不动。

## ⑥ 验收标准
非 question 永不带 `tag_id`；题目下出现「全部 + 各类别」且顺序=字典顺序；非题目与空字典整行不渲染；②③④ 门过。
