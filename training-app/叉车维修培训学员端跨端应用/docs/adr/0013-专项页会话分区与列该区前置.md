# 0013 - 专项页会话分区与「列该区」前置

**状态**：定稿（grilling 口径定稿，2026-09-15）；**本条改掉一条既有守护**（见 ② 与文末「放宽声明」）—— 来源：AI 助手页面改版立项 grilling 的 10 条决策之一
**职责边界**：裁定移动端 AI 助手**会话与功能键的归属关系**；不动计费口径（根仓库 `ADR-0031` 计量闸门 / 限免声明位）、**不重复**来源资料落库的裁定（根仓库 `ADR-0033`）、不动验收门（本目录 `0008`）

## 背景与目标

`#921` 接线后，宫格点「智能维修诊断」会把 `feature_key='fault_diagnosis'` 带进 `POST /ai-assistant/chat`，但**建会话与列会话都不带该键**（`api/aiAssistant.uts` 的 `createAiSessionApi(title, modelName)` / `getAiSessionsApi()`）。这不是疏漏，是**当时的正确选择**：后端按功能键**分区**查询（`backend/internal/api/ai_assistant.go:241` 读 `query.feature_key`；`:271`–`:277` 建会话接受并落 `feature_key`），若会话带了专项键而**没有任何界面列该区**，该会话在「最近对话」里**永久不可见**——`#921` 首版就是这个回归（探针原文见该文件 ④ 组注释）。

目标：页面改版引入**参数化专项页**后（见 `0009` 的 2026-09-15 修订），把「专项会话」正式分区，让专项通道的历史可回放（`ADR-0033` 的来源面板才有承载面），并**把守护从「一律禁止」改成「有界面才允许」**——让规则跟着产品形态走，而不是反过来把功能钉死。

## 决策清单（六段）

① **目标与范围**：专项页按功能键**真分区** —— 专项页只列「该功能区」会话、通用页只列通用会话；建会话在专项页**带键**、在通用页**不带**。只动移动端会话归属与守护，**后端零改动**。

② **选型 + 一句理由**：
- **专项页 = 带键（list + create）** —— 后端早已支持（`:241` / `:271`），客户端一处改动即生效；收益是专项会话**不再混进首页抽屉**。
- **通用页 = 不带键** —— 缺参落遗留 `ai_assistant` 分区，行为与从前**完全一致**（零回归）。
- **④ 组守护改为条件式「带键建会话 ⇔ 存在列该区的界面」** —— `#921` 的回归**不是「带了键」，而是「带了键却没有任何界面列它」**；该钉死的是这条不变式，不是「永不带键」这个手段。

③ **明确不做**：不改后端接口（分区能力已存在）；不做「跨区全量会话」的合并视图；不做用户上传图片（改版 Q4 已排除，见 `0009` 修订）；**不静默改守护**（见 ⑤）。

④ **拆分步骤**（一票）：`api/aiAssistant.uts` 的 list/create 增 `featureKey` 形参 → 专项页调用处带键、通用页保持不带 → ④ 组改写为条件式并**新增两条断言** → 真机取证（专项页会话列表 + 通用页不混入）。

⑤ **约束**：uni-app-x（UTS 无可选参数默认值机制 ⇒ 形参须显式透传，参 `sendInput` 的既有先例）；**本 ADR 是本次改版唯一放宽的硬约束** ⇒ 《④ 组守护改写**必须在实现 PR 正文显式声明**》；契约测试是落锁面（`utils/aiFeatureEntryWiringContract.test.js`）。

⑥ **验收标准**：专项页只列该区会话、通用页只列通用会话（① 真机逐页截图）；④ 组为**条件式**且新增两条断言（**专项页必须带键调 list/create**；**通用页必须不带**）全绿；`npm run test:unit` 全绿；「带键必有列它的界面」在代码里可判。

## 被否备选

- **维持「永不带键」**：专项会话继续混进首页抽屉 ⇒ `ADR-0033` 的历史回放 / 来源面板失去承载面，学员看到的仍是「刷新后来源消失」那一类形态。**它在 `#921` 当时是合理选择，但专项页存在之后它变成了错误选择**——这正是本 ADR 要改写守护的理由。
- **带键建会话但不改守护**：会把 ④ 组从「守护」变成「谎言」——测试说不能带、代码却带，下一个会话只能二选一（删测试或删功能）。
- **专项页只带 create 键、list 不带**：会话写进了专区的键却列不出来，**正好复现 `#921` 的回归形态** ⇒ 这就是「⇔」必须**两向都成立**的理由。
- **给通用页也做分区（列全部区）**：需要后端新接口（跨区查询），与「后端零改动」冲突；收益仅是首页抽屉能看全 —— 未选，留待有真实需求时另立。

## 放宽声明（本次改版唯一一处）

`utils/aiFeatureEntryWiringContract.test.js` 的 **④ 组**现锁「建会话不得带 `feature_key`（带了就永久不可见）」。本 ADR **改写它**（理由即 ② 第三条）⇒ 守护改为**条件式**，并新增两条断言：**专项页必须带键调 list/create**、**通用页必须不带**。**不得静默改**：实现 PR 正文必须写出这一处，`code-review` 复核时要专门看「有没有把它改歪」。
