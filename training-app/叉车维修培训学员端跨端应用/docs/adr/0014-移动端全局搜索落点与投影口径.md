# 0014 - 移动端全局搜索的落点与投影口径

**状态**：定稿（#979 实施会话收口，2026-09-15）
**职责边界**：裁定**移动端**如何消费共享端点 `GET /api/search`（落点 / 投影 / 高亮 / 历史 / 证件传参）；**不改后端契约**（`SearchItemDTO` 字段沿用，元信息缺口见 ③）、**不动验收门**（本目录 `0008`）
**来源**：根仓库 `docs/adr/ADR-0049`（搜索主题检索口径，明写「移动端候选转 issue #979」「移动端不因本 ADR 改口径」）——本条是它点名的那一侧落地面

## 背景与目标

根仓库 #980–#984（PR #986）把搜索升级落在 Web 与后端：新增**章节分区**、`snippet` / `hit_field` / `parent_id` 三个字段、命中窗口与区内排序。移动端 `pages/search/search.uvue` 是 P2 未改造页，结果**只消费了 `summary` 与 `title`**，且三条口径直接错着：

1. **落点缺两条**（内容精选与题目只有「开发中」toast）——ADR-0049 决策 2 判「搜到但打不开」为不合格；
2. **章节分区被静默丢掉**——移动端 `SearchResult` 类型里根本没有 `chapters` 键，聚合响应里的整个分区无人消费；
3. **证件不分区**——`/api/search` 挂在 `api` 组下，该组**没有** `JWTAuth` / `OptionalAuth`（`backend/internal/api/router.go:89-91`），而 `CredentialScoped` 的服务端兜底要求 `roleOf(c) == student`（`backend/internal/middleware/credential_scope.go:42`）⇒ **兜底永不生效**，不显式传 `credential_id` 就是「全证件不分区」（不是「按当前证件」）。

目标：把移动端补齐到与 Web 同一口径（分区、落点、投影、高亮、证件），且**不引入第二批渲染规则**。

## 决策清单（六段）

① **目标与范围**：五分区（课程/章节/题目/精选/帖子）全部消费 + 每条有落点；片段投影与高亮在端上做；搜索历史与 Web 同口径；证件显式传参。只动 `training-app/**`，后端与 Web 零改动。

② **选型 + 一句理由**：
- **题目落点 = 复用练习单题栈**（`practice-do.uvue` 加 `question_id` ⇒ `mode='single'`）——与 Web #983 的「题目承载页复用 `usePracticeSession` single 变体」同构；`practice-do` 已具备选项/判分/AI 解析/评论/考点/笔记整条链路，**不新增页面也就不动 `pages.json`**（不触发 ④a）。
- **章节落点 = `chapter-view?course_id&chapter_id`**——后端 `parent_id` 就是课程 ID，页面参数早已存在，零新代码。
- **片段投影走 `parseMarkdown`**（`utils/searchDisplay.projectSnippet`）——ADR-0044 同源原则：渲染层怎么理解这段 markdown，投影就怎么理解它；直接对原文跑行内正则是被点名的反模式。
- **高亮在投影后的纯文本上重新定位关键词**（大小写无关、多次命中全切）——与 Web `SearchResultRow.split` 同式，纯函数落 `utils/searchDisplay.uts`。
- **证件显式传参**——ADR-0047 §4「公开路由保留客户端显式传参」；移动端此前漏传属实现缺陷（见背景 3）。
- **历史沿用字符串数组**（上限 10 / 去重前置 / 单条删除 / 清空）——Web `searchHistory.ts` 的公开行为就是这个集合，且其文件头自述「与移动端口径一致」。

③ **明确不做**：
- **结果元信息（作者 / 时间 / 回复数）**：`SearchItemDTO` 只有 8 个字段，**契约里没有这些列**，且跨类型语义不一致（精选有 `published_at`、帖子有 `last_reply_at`、课程什么都没有）⇒ 属**契约缺口**，需根仓库 ADR 面另立；移动端不伪造。
- **搜索历史带时间**：Web 亦无；改存储格式（字符串数组 → 对象数组 + 旧格式迁移）是独立决策。
- **`app-list-item` 复用**：`#979` M3 把它列为应复用组件，但它只有 `label`/`value` 两段式（`components/app-list-item/app-list-item.uvue`），承载不了「标题 + 片段 + 命中标注」三行结果行 ⇒ 结果行保留页面内结构，只复用 `app-chip`（类型筛选）与 `app-empty-state`（空态）。
- **后端改动**：契约只增不破，扩字段须先过根仓库口径。

④ **拆分步骤**（一票）：`types/search.uts` + `api/search.uts` 补 `snippet`/`hit_field`/`parent_id`/`chapters` 与 `credentialId` 形参 → `utils/searchDisplay.uts`（落点表 / 高亮 / 投影 / 命中标注）→ `pages/search/search.uvue`（五分区、六个 tab、请求序号、成功才推进页码、历史单删、token 化、两个组件）→ `api/practice.uts` + `usePracticeSession.uts` + `practice-do.uvue` 加单题模式 → `dashboard.uvue` 补入口 → 守护（新增 `searchDisplay.test.js` / `searchContract.test.js`）。

⑤ **约束与语义坑位**（本轮实测，写给下一个会话）：
- **`.uvue` 的 `<style>` 必须声明 `lang="scss"`**，否则 SCSS 变量不预处理、声明被静默丢弃（本目录 `AGENTS.md` 早有此条，`app-chip` / `app-empty-state` 两个组件当时没遵守）。
- **SCSS 变量名必须真实存在于 `uni.scss`**：`docs/ui-spec-implementation-plan.md` §4.1 的映射表点名了 `$text-secondary` / `$text-placeholder` / `$text-disabled` / `$bg-page` 四个**不存在**的名字（实际是 `$text-color-secondary` / `$text-color-placeholder` / …），照着表写会静默失效。守护 `utils/searchContract.test.js` 已把「引用的 `$变量` 必须在 `uni.scss` 里定义」做成机检。
- **`credentialScoped` 的兜底靠 JWT 解析**：任何挂在**无 `OptionalAuth`** 的组下的公开端点，客户端都必须显式传 `credential_id`；「服务端会兜底」是错的。
- **`practice-do` 的单题模式不落练习进度、不算交卷**：`practice_type` 记 `free`（与 Web 同一记账口径），`saveProgress` 只对 `sequential`/`tag` 生效。
- **UTS 无函数提升**：`<script setup>` 顶层函数的调用不得早于定义（守护 `utils/utsAndroidCompile.test.js` A 组机检）。

⑥ **验收标准**：五分区在「全部」tab 各有条目且可打开（无 toast 死链）；`credential_id` 随 `/search` 两个出口下发；旧响应不覆盖新结果、失败不丢页；片段高亮与「命中在回复」标注可见；历史可单删；`npm run test:unit` 全绿（含新增两组守护）；④ 本地编译门零 ERROR；① 真机逐页截图（本目录 `0008`）。

## 守护变更声明（不得静默改）

本轮**动了三处既有守护**，逐条写出：

1. `utils/practiceContract.test.js` **DTO 出口正则放宽**：URL 形参允许「字面量 + id 变量拼接」（by-id 端点只能这么写）；同时把 `getQuestionByIdApi` **加进** DTO 清单 ⇒ 覆盖面扩大不是缩小。
2. `utils/practiceContract.test.js` **幻影路由锁学会拼接连形态**（`'/question-bank/questions/' + <id>` → `/question-bank/questions/:question_id`，先例 `examContract` 的 `:mock_exam_id`）⇒ 仍对未注册路径判红。
3. `utils/dashboardPage.test.js` **顶部导航图标数 2 → 3**，并把三个字形逐个钉死（`🔍` / `🔔` / `🛒`）——因为 #979 M2 就是「补一个入口」，原断言的意图是「图标不能是空文本」而非「只能是 2 个」。

## 落地回写（2026-09-15 实施，PR #1026）

- **①a 真机取证的判据源写实**：uni-app x 的文案**在 `content-desc` 里，不在 `text` 里**（同一棵 12 节点树：`text` 全空、`desc` 有 10 条）——按 `text` 取会得到空列表。另：`adb exec-out uiautomator dump --compressed /dev/tty` 是**概率性成功**（实测约 4/10，失败时输出长度 9），必须**重试**；`adb shell uiautomator dump` 只回一行「UI hierchary dumped to:...」，不能用。本目录 `0008`「①a 取证手法补遗」记的四条其余仍成立。
- **① 真机实测走通了什么**：搜索页初始态（历史 + 单条删除）、全部态六 tab + 章节分区被消费 + 命中片段、章节 tab、题目 tab、点题目结果进单题承载模式（`单选题｜…｜提交答案`，无答题卡/无交卷）、内容精选详情页可达、dashboard 顶部栏三图标。`logcat fatal=0 anr=0`。
- **① 真机未走通的一项**：**内容精选分区的「点击穿透」**——`adb shell input text` 只支持 ASCII，而 16 个 ASCII 关键词无一命中 `contents` 分区（该分区内容是纯中文正文）。该落点由「详情页真机可达」+「`searchItemPath` 契约测试锁映射」两项承载，**不宣称已点击穿透**。
- **片段里偶见孤立 `**`**：源串命中窗口从加粗段中间切入时，窗口内只剩一个定界符，投影补不回来（投影本身生效：同批片段里 markdown 换行已变成空格）。**不做**「猜着补定界符」——那会让投影与渲染的理解分叉，违反本条的选型理由。
- **发现但不在本票修的缺陷**：`dev:finish` 步骤 6「自动截图」在本机恒报 `找不到 adb.exe`（`scripts/lib/auto-screenshot.ps1:258-272` 内联了第二份 adb 解析，缺 `D:\android-sdk` 兜底；步骤 2/5 走的 `env-check.ps1:21-33` 有该兜底）⇒ 步骤 7–9 永远跑不到，而 4/5 的副作用已经发生。已另立 issue **#1027**。

## 视觉改造（2026-09-15 二轮：维护者反馈「整体白色太单调」）

第一版把搜索页做成了「白 header + 白筛选条 + 白卡片 + 近白画布」——功能齐了，但**整页没有色彩落点**。二轮按**全app既有语言**改（不是自创风格）：

① **头部改主色区**：状态栏 + 搜索栏 = `$primary-color`，输入为白色胶囊 —— 与 `course-detail` / `chapter-view` / `featured-list` / `forum-detail` / `mock-exam` 等**非 tabBar 页的既有写法一致**（这些页面早就这么做，搜索页此前是例外）；取消按钮白字。
② **画布换淡蓝**：新增 `$bg-tint`（`#f1f6ff`）作列表/结果页画布，白卡浮在其上 ⇒ 整页不再是纯白/纯灰。
③ **每个分区给一个色彩锚点**：标题行改 `$primary-tint`（新增 token）浅底带 + 主色小竖条 + 主色「查看全部」；条数用 placeholder 灰。
④ **色彩只落在当前档位**：`app-chip` 选中态从「浅底 + 主色描边」改为**主色实底 + 反白文字**，未选中改浅灰底（原两态在白筛选条上几乎看不出差别）。该组件全仓唯一消费方就是本页。
⑤ **历史 chip**：主色浅底胶囊 + 主色文字，单条删除命中区做到 88rpx（44px）。
⑥ **空态**启用 emoji 图标（此前被我用 `icon=""` 显式抑制）。

同批修掉三个**上一版自己写坏的**观感/规范问题（都不是审美偏好）：

- **题目行渲染两遍题干**：后端对题目令 `title == summary == 题干截断`，而 `snippet` 是同一段题干的命中窗口 ⇒ 两行是同一句话的两种截断。修法 = `itemPrimaryText`（题目主行改用**命中窗口**，既去重又保住「为什么命中」）+ `shouldShowSnippet`（其余分区在片段与标题属同一段文本时也不重复渲染）；纯函数落 `utils/searchDisplay.uts`。
- **片段被染成标题色**：原先所有非命中段共用 `.item-plain`，把片段的灰字覆盖成主字色，层级消失。修法 = 标题/片段各一套 plain 类。
- **uvue 没有 `:last-child`**：末行分隔线由模板显式加 `.result-item--last` 去掉。

新增 token（`uni.scss`，additive）：`$bg-tint` / `$primary-tint` / `$text-disabled`；`docs/ui-spec.md` 登记三个新 token，并**对齐该表漂移的变量名**（`$text-secondary` / `$text-placeholder` / `$text-inverse` / `$bg-page` 在 `uni.scss` 里都不存在 —— 与 §4.1 那次是同一类缺陷），同时订正其主按钮示例里违反 ADR-0010 的 `135deg`。

**明确不做**：不动练习页与 dashboard 的既有视觉；不上渐变（ADR-0010 只允许「2 值 + `to` 关键字」，收益低于风险）；不给结果行加图标/标签等额外元素。

**守护增量**：`utils/searchContract.test.js` 追加「样式块零裸 hex」「主色 header + `$bg-tint` 画布」「分区锚点（浅底带 + 主色竖条）」「触摸区 88rpx」「末行显式类」「app-chip 实底反白」六条；`utils/searchDisplay.test.js` 追加去重口径的镜像与 `.uts` 同步断言。

**手法回写（下一会话可直接用）：视觉结论可以「量」出来，不必靠肉眼。** 本轮会话的模型**不接受图片输入**，于是把「好看/不好看」换成**逐区像素取色**（`vision_dominant_colors`，本机计算、不消耗视觉模型额度）：对截图的指定矩形区域提取主色聚类，再与 token 值逐像素对照 —— 例如本轮实测 header 区 `63.2% #2879FF` + `22.2% #FFFFFF`（白胶囊）、左侧画布竖条 `97.9% #F1F6FF`、选中 chip 区 `23.6% #2979FF`、分区标题带 `80% #EBF5FF`。**这条同时是「SCSS token 是否真的生效」的判据**（变量名写错/漏 `lang="scss"` 时，取色会直接暴露成默认色）。
**注意 `vision_glance` 一类走远端视觉模型的工具在本机不可用**（返回「未充值账号仅可试用 10 次」），别把结论压在它上面；`vision_dominant_colors` 是本机像素统计，不受此限。

**二轮门证据（2026-09-15，PR #1028）**：**③** CI run `34973155752`（`mobile-test` = `npm run test:unit`，**70 suites / 1148 tests** 全绿）；**④c** `KOTLIN_ALL_RESULT errors=0 classes=1281 files=97`（日志 `.ci-verify/kotlin-all.log`）；**①** 真机 7 张（`docs/verification/search/1028/`，`HX_RUN_DEPLOY deployed=true`、`LOGCAT fatal=0 anr=0`）+ 上面那组逐区取色；**②** 免（未命中 MP-WEIXIN 面）、**④b** 免（未触及打包面）。
