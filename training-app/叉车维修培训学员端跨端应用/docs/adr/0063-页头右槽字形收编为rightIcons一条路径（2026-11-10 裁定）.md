# 页头右槽字形收编为 rightIcons 一条路径

- 状态：已采纳（2026-11-10，#2412 实施同批写入）

## 背景

`#1649`（2026-10-11）删掉 `app-nav-bar` 的 `rightIcon` 单图标渲染分支，却留下 prop 与默认值 `:72`。`ai-chat-nav` 仍传 `:right-icon="rightIcon"`（默认 `'⋯'`）⇒ AI 助手页右上「⋯」自 2026-10-11 起不可见。更隐蔽的是 `v-else` 的空 `#right` 插槽：MP-WEIXIN 端它有宽度且挂着 `@click`（看不见、点得动），App/H5 端 `rightSlotWidth` 为 0（`utils/system.uts` 只在 `#ifdef MP-WEIXIN` 赋值）⇒ 入口彻底消失。`aiChatDrawerContract.test.js:98-110` 的 ④ 只钉插槽分支，全仓零断言覆盖 `rightIcon`，三条漂移同时无人察觉。

## 决定

1. 删除 `app-nav-bar` 的 `rightIcon` prop 与默认值；全仓零命中（调用方仅 `ai-chat-nav`）。
2. `ai-chat-nav` 自带 `const rightIcons : string[] = ['⋯']` 直接绑 `:right-icons`，不再多一层同义 prop。
3. 右槽只允许两条渲染路径：组件画字形（`rightIcons`，n = 1 也走数组）/ 页面注入 `#right` 插槽。出现第三条同义 prop 即视为漂移。
4. 契约测试新增 `rightEntryVisible(nav, navBar, page)`，与 `leftEntryVisible` 对称钉三件：字形真的传到页头件、`@right-click` → `onMenuClick` → 页面 `@menu-click="toggleSidebarRight"`、页面渲染 `<AiChatDrawerRight>`；并注入违规样本自证必红。
5. 页面 `ai-assistant.uvue` 与 `AiChatDrawerRight` 零改动。

## 后果

- 右上「⋯」恢复可见可点；App/H5 端不再依赖 `rightSlotWidth` 的微信专属赋值。
- 删的是导出符号：仓内无调用方残留（`resume` / `dashboard` 一直走 `:right-icons`），但外部 fork 若还传 `rightIcon` 会静默无效 —— 这是有意为之，死 prop 正是本次事故的根因。
- 守护从「插槽分支在」升级为「字形 + 接线 + 抽屉三件」，单拆任一环即红。

## 不采用的备选

- 恢复 `rightIcon` / `rightIcons` / `#right` 三段链（维护者已否决：三份实现必再漂移）；保留死 prop 只改调用方（骗下一个调用方）；右槽统一改成插槽直传（调用方要自带字形与点击语义，页头件失去默认样式）。
