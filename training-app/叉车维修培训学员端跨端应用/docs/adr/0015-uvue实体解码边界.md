# ADR 0015 · uvue 实体解码边界

- 状态：已采纳（2026-09-15，#957）
- 范围：本应用所有 `.uvue` 的 `<script>` 块（模板静态文本不受本约束）

## ① 目标与范围

钉死 uvue 里 HTML 数字实体的**可用边界**，消除「数据里写实体、真机上把实体原样显示出来」这类**不报错、不警告**的失败。

触发事故（#957）：专业版半屏 sheet 的能力清单图标列，屏上显示的是 `&#10022;` / `&#9881;` / `&#128206;` 这 8–9 个 ASCII 字符，而不是图形。

## ② 选型 + 理由

| 项 | 取值 | 一句话理由 |
| --- | --- | --- |
| 模板**静态文本**里的实体 | **允许**（如 `<text>&#10005;</text>`） | 模板编译器会解码 —— 同一份 Android 产物里 `sheet-close` 的 `&#10005;` 落成字面字符 `"✕"`，本仓 11 处一直渲染正常 |
| `<script>` **字符串**里的实体 | **禁止**，直接写真实码点字符 | `<script>` 的字符串字面量**不经过任何解码路径** —— 同一份产物里数据值 `&#10022;` 落成字面字符串 `"&#10022;"`，原样下发到渲染层 |
| 汉字/中文文案 | 不涉及 | 中文不经实体编码，不是本条的对象 |
| 运行时解码函数 | **不做** | 见 ③ |

**判据是正反一对、同文件同产物**（不需要真机即可复核）：

```
模板静态  <text class="sheet-close">&#10005;</text>   →  产物  _cE("text", …, "✕")
script 数据  { icon: '&#10022;' }                      →  产物  ProCapability(icon = "&#10022;", …)
```

## ③ 明确不做的事

- **不引入运行时实体解码函数**（`decodeHtml` 之类）—— 本仓无此先例，且它会把「字面量写错」从静态可见变成静默，正是本次要杜绝的。
- **不回改那 11 处模板静态实体**（`ai-chat-input` / `ai-chat-nav` / `ai-chat-drawer-*` / `ai-assistant` / 本 sheet 的闭合 ✕）—— 它们是合法写法。
- 不为此引入图标字体或图片（除非 ⑤ 的字形覆盖被真机证伪）。
- 不动代码里其他与实体无关的写法。

## ④ 拆分步骤

1. 把能力清单三项图标的**数据值**改成真实码点字符（#957 的可见修复）。
2. 落守护 `utils/uvueEntityLiteralContract.test.js`（注入自检 + 模板静态样本判绿 + 真实文件零命中）。
3. 真机 before / after 取证（#957 的 ① 门）。

## ⑤ 约束

- **守护的范围必须切准**：只扫 `<script>` 块，**模板静态文本里的实体不得判违规**；切错会把 11 处正常写法一起判红。
- 剥离注释时必须**尊重字符串字面量** —— 字符串里的 `//`（如 URL）不是注释起点。
- 行号按**换行计数**换算成文件绝对行号：剥离注释会移走字符但保留换行，拿剥离后的字符偏移去索引原文会偏 2–3 行（实测）。
- **已知未验证项（不宣称已覆盖）**：`U+2726`(✦) 与 `U+1F4CE`(📎) 在本应用的静态模板里长期使用、有真机先例；`U+2699`(⚙) 全仓**无先例**，Android 侧字体是否覆盖**待真机确认** —— 若不覆盖，换成长度/形态相近且已验证的码点，不静默留缺字方框。
