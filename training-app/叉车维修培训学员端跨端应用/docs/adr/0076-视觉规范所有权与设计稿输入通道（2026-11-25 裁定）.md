# 0076 - 视觉规范所有权与设计稿输入通道（2026-11-25 裁定）

> 状态：已采纳（2026-11-25，#2841 同批写入）｜**职责边界**：只裁「视觉意图归谁、实现值归谁、冲突听谁」，不改页面代码、不改 `uni.scss` 取值、不新增判红门，也不把设计稿导出物纳入仓库。

## ① 目标与范围
此前本仓「无外部设计稿」，视觉数值只能由工程侧自行判断；设计侧首次提供 Figma 只读原型后，两侧都可能单方面改视觉结果而没有任何判据。本决策就是给这条边界定一条长期口径。范围**仅移动端小程序**（`training-app/叉车维修培训学员端跨端应用`）；Web 侧继续遵循其独立规范 [`docs/agents/ui-conventions.md`](../../../../docs/agents/ui-conventions.md)，**两套规范不合并**。

## ② 选型 + 一句理由
- **双轨：Figma 作变更提议源，`docs/ui-spec.md` + `uni.scss` 作现行真源**——设计稿能表达意图但不可检索、不可机检，而现行守护已把 token 钉在这两份文本之间，真源上移等于让全部 UI 守护失去判据。
- 设计稿只以**离线结构快照**接入（可 diff、可做频次统计），不做逐图层单位换算、不重导全量切图。

## ③ 明确不做的事
- 不把 Figma 样式/变量当取值来源：当前只读权限无法通过 API 获取 Figma 样式与变量数据，且不假设权限会变。
- 不允许任一侧单方面改视觉结果：设计不得直接指定 rpx 值，工程不得未经设计确认改视觉结果。
- 不新增判红门；不提交设计稿导出物（PNG / 原始 JSON），证据面留在判据笔记与导出目录本地。

## ④ 拆分步骤
1. 本文件与 `docs/ui-spec.md` §0 三处（ADR 登记行、上次同步设计稿 version 记录、顶部输入来源改写）同批写入。 2. `utils/uiDocDocMapContract.test.js` 的 `REQUIRED_DOCS` 加入本文件路径，让「新增 UI 文档必须先登记」对 ADR 自身生效。 3. 地图票补协作规则与交接包、导出元数据契约、历史原型证据三节。

## ⑤ 约束
- **所有权四栏**：设计拥有视觉意图与期望效果；工程拥有命名、单位换算（750/390≈1.923 只是换算参考、非逐图层乘算）、实现值映射、组件架构与机检；新增或改视觉数值须「**设计确认视觉结果、工程确认技术实现**」，不得未经设计确认单方面改 rpx；**新组件双方共同拥有**，缺任一方的状态图不进正式实现与验收。
- **仲裁顺序**：`docs/ui-spec.md` + `uni.scss` 是现行真源，Figma 是变更提议源。冲突走提案制——新值先立裁定条目（**值 + 频次 + 屏号**），同批改实现与文档、让守护判绿才生效；只改一边视为未生效。
