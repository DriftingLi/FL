# 0011 - 一键完成（dev:finish）的并发与失败语义

> 状态：已生效 ｜ 2026-09-14 ｜ 来源：PR #978/#989 暴露的假绿 + 用户裁定的 Q-2/A-3/Q3
> **职责边界**：裁定 `dev:finish` 工具链在**并发会话**下的锁纪律与**失败语义**；不动验收门本身（见 `0008-移动端验收门与证据.md`），不动 UI。

**① 目标与范围**：把「编译 → 部署 → 截图 → 证据」的判定做成**不可能假绿**；并让多会话并发只**排队**、不互相破坏。

**② 选型 + 一句理由**

- **quick 拆成 Q-A / Q-B 两档（2026-09-14 修正，原「quick = 编译诊断」的前提被实测推翻）**：**默认 Q-A 静态守护**（契约测试；**秒级、不取锁、不占设备**），要编译诊断须**显式 `-Compile`** ⇒ Q-B（`hx-run -CompileOnly`）—— 实测 Q-B 在冷/失效缓存下 **>901 秒**，**比真运行（4–5 分钟）还慢**，把编译塞进默认 quick 等于谎称「快速」；Q-A 必须**明说「未做编译诊断」**（不是静默跳过，这正是旧口径被废止的原因）。
- **部署判定复用 `hx-run.ps1`**（解析其 `HX_RUN` / `HX_RUN_DEPLOY` 机检行）—— 真运行路径已实测，**重复实现正是第一版假绿的来源**。
- **A-3 一个临界区覆盖步骤 4–6** —— 部署与截图共享设备状态，分次持锁会被别的会话插进来换页（截到别人的页面）。
- **锁交接**（`$env:HX_LOCK_OWNER` + PID 比对）—— 锁按 PID 判定且**不可重入**，父持锁再调子脚本会**自死锁**；交接是唯一不必改写共享库语义就能连跑的办法。
- **截图只截改动页**（git diff 推导 + `-Pages`，`-MaxPages` 兜底）—— 每页一次 launch 都要过一遍 HBuilderX，50 页全量不可接受。

**③ 明确不做的事**：不改 `hx-busy` 的锁语义（仍 30 分钟陈旧可抢占）；不动 `0008` 的四门与证据格式；不做 GUI 热刷新的自动化（秒级那条路仍在人手）；不做多设备并行（真机自动化本质受 HBuilderX 单实例约束）。

**④ 拆分步骤**（可并行项已标）：`hx-busy` 加交接（H10/H11）→ 之后的五项**互不依赖彼此产出**、仅共享 `hx-busy`：`build-deploy` 改调 hx-run（B4–B14）｜ `test-compile` 的 Q-A/Q-B 分档（T3/T8/T10-T12）｜ `auto-screenshot` 限范围（S8–S12）｜ `dev-finish` 包临界区（F6–F11）｜ `env-check` 加 Q-A 轻量检查（E9）。

**⑤ 约束**：HBuilderX **单实例串行，绝不 kill/绝不抢占**；锁超时一律 `exit 2`；**只有真需要 HBuilderX 的路径才取锁**（Q-A 取了锁就白等，秒级定位即失效）；结论字段（`$deployed` 等）**默认 false**，只有拿到证据才置真；契约测试断言的是**源码文本**，故被守护的字面量**不得出现在注释里**（本仓已多次踩中「注释命中断言」）；`hx-run` 自身默认 `-TimeoutSeconds 900` 对**冷缓存编译偏短**（实测 901 秒仍在编译，48 页工程）⇒ 调用方**必须显式透传**（默认 1800）。

**⑥ 验收标准**：9 套件 **82** 用例全绿；锁交接有**行为验证**（带 env ⇒ `result=inherited`；无 env ⇒ `result=timeout` + `exit 2`）；**Q-A 路径不取锁、不要求设备与主程序**（守护 E9 / F10）；无改动页时 `TargetPages=0` 且**不回退全量**；真实并发表现为**排队**（`HX_BUSY wait=…`）而非假失败；`dev:finish` 任一失败路径都经 `finally` 释放锁并清 env。
