# 0012 - 真运行路径的错误行判据作用域（不得拿编译诊断判据扫设备运行日志）

> 状态：已生效 ｜ 2026-09-14 ｜ 来源：§5.2 🟡 端到端首跑的第三个失败原因（本仓 agent 会话）
> **职责边界**：只裁定 `hx-run.ps1` 真运行路径**错误行判据的作用域**；不动部署观察窗（见 `0011`）、不动验收门（见 `0008`）。

**① 目标与范围**：让真运行路径的成败判据**既能拦住编译期诊断，又不把设备侧运行日志当失败**；并保证「到底有没有到设备」的证据行（`HX_RUN_DEPLOY`）**任何情况下都拿得到**。

**② 选型 + 一句理由**

- **错误行扫描**限定在「非设备日志行」（判据：行首 `HH:mm:ss.mmm`）—— 编译期诊断无时间戳、设备 console 日志必带；这是**唯一可靠**的区分面（本轮实测：HBuilderX 把 App 运行日志与编译输出**混在同一条 stdout**）。
- **真运行路径不再 `exit 1`**，设备日志里的 error 一律**降级为警告**；成败由已有部署判据（设备侧事实是否前进）定 —— 否则「App 报了一条业务 error」会把一次**成功部署**判成失败，方向是假失败，且会**吃掉 `HX_RUN_DEPLOY` 行**。
- 仅编译路径（`-CompileOnly`）**判据不变**：它不接设备、输出全是编译诊断，仍是 `exit 1`。

**③ 明确不做的事**：不改 `-CompileOnly` 的判据与退出码；不改部署观察窗默认值（那是 `0011` 的面，见下方遗留）；不解析设备日志语义（不猜「这条 error 重不重要」）；不做「App 无 error 才算运行成功」——那等于让设备上的业务状态决定 CI 结论。

**④ 拆分步骤**：`Get-HxErrorLines` 内部加设备日志行排除（1 处，不改调用点数量 ⇒ 契约 C13 的「调用点 ≥2 且都包 `@()`」不受影响）→ 真运行分支的错误行改为警告语 → 头注释与「退出码」段同步（1 处）→ 新增运行期守护（2 处：真实日志行不判失败 / 编译诊断仍判失败）。

**⑤ 约束**：编译期诊断**必须仍被判失败**（含 `unresolved reference` 等）；真运行路径的**退出码语义变化要写进头注释**（原来 1 = 输出含 error 行）；被守护的字面量不得进注释（`hxRunContract` C 系是源码文本断言）。

**⑥ 验收标准**：新的运行期守护覆盖：① 本轮**真实捕获**的 4 行设备日志 ⇒ **不判失败**；② 典型编译期诊断（`unresolved reference`、`Cannot infer type`）⇒ **仍判失败**；③ 二者混在一份输出里 ⇒ 只报编译诊断行。文本断言（C13）保持全绿。

**遗留（本 ADR 不覆盖，需另裁）**：本轮实测资源落盘耗时 **约 270 秒**，而 `0011` 的最短观察窗默认 **60 秒**、其依据写的是 7–21 秒；`hx-run.ps1` 头注释 L95 自述落盘 **15 秒–9 分钟** ⇒ **窗口窄于脚本自己记录的上界**。窗口默认值要不要按 9 分钟上界上调，属 `0011` 的面，本 ADR 不动。

## 实施回记（#2045，2026-10-27）：这条纪律推广到 ④ 的两处判据

本 ADR 原来的射程只有一句话：`hx-run.ps1` 真运行路径的错误行判据。#2045 把同一条形状纪律（**纯判定必须能 dot-source 真执行**）搬到 ④ 本地编译门的两处内联判据上，产生三条本 ADR 未覆盖的新决策与三条新坑位，按「新决策回写纪律」记在此处（判据落点：`scripts/lib/gate-error-lines.ps1`；题库：`utils/gateErrorLinesBehavior.test.js`；接线：`utils/gateErrorLinesWiringContract.test.js`）。

1. **被守护 pin 住的判据怎么搬**（原 `lib/gate-common.ps1` 的准入门槛 G2 写着「未被守护作为字面量锚点 pin 住的代码才允许搬」，而 ④c 那份恰恰被 `kotlinAllGateContract` C3 pin 住）：裁定 = **同批改写锚点，不是放宽锚点**。C3 从「脚本内声明 `$ErrorLinePattern` 字面量」改写成「脚本 dot-source 判据库 + 两处调用点在真路径」，判据**内容**这一侧改由题库真执行举证；并加反向断言（C3b / W4）「脚本内不得再留判据字面量」，防第二真源长回来。落锁情况：C3 的 4 条新变异样本 + W4 的 2 条，全部在守护的自检里被检出。
2. **归腿以现测为准，不以票面预想为准**：票面写「判定 fixture 与接线契约都进接线腿」，同一段同时规定「按 `classify-guards.mjs` 现测归腿、不手判」。现测结果：题库起 `pwsh` 子进程 ⇒ **行为腿**；接线契约纯读文本 ⇒ 接线腿。取现测。
3. **搬家与改判据分两笔、措辞只在首跑现形后动**：搬家那一笔一字未改，验证 = 18 份合成样本搬前/搬后输出全等（不等=0）；题库首跑 11 条用例中恰有 2 条红（血账 #4 的 `Could not resolve` 原文，命中 0），修复那一笔才加这一枚 token，并附 ledger `:18` 与 `docs/verification/recruiter-workspace/1207/README.md` 对照表行号。#4 由此从 open 转 fixed，状态改动由机检读出。

**新坑位三条（下次照着做，别再撞）**：

- 探针读数**缺失不许降级成 0**：`read()` 读不到 `COUNT=` 行时必须抛。把「没读到」当「判据没命中」，恒 0 与恒真一样是假绿 —— 本票第一版就栽在这里（10 条用例假绿通过，实际 stdout 从未被解析）。
- 顺序类接线断言的锚点要选**机检行里的数字**（`errors=$($errorLines.Count)`），不能选裸 `COMPILE_RESULT` / `KOTLIN_ALL_RESULT` 字样：环境早退分支的 `errors=env` 出现在判据调用**之前**，拿字样排序会把真接线判成违规。
- 判据函数与调用点**两层都包 `@()`**：StrictMode 下无命中的裸管道退化成 `$null`，`$null.Count` 抛（本 ADR ⑤ 段那条约束在 ④ 侧同样成立）。

**本票明确不做的**（留 ledger #25 与合一候选）：第三形态 `lib/hx-errors.ps1` 的 `Get-HxErrorLines` 仍缺 `Could not resolve` 族 —— 它服务 `hx-run` 日常路径，按票面「只加样品、不搬家」，本次只把血账 #917 的收口行补成反向题（E8）；④c 对「时间戳+error:」「⛔error:」两形未复现，作为已知边界写进 `lib/gate-error-lines.ps1` 头注，不改措辞。
