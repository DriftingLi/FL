# 0019 - 契约测试换行符盲区与「读取层归一」

**状态**：已接受（2026-09-19，来源 #1137 / #1138 的收尾 triage；不改变 ADR-0008 的 ③ 门语义）

## ① 目标与范围

移动端 ③ 门（`npm run test:unit`）跑在 **ubuntu** 上，而它守护的一批**接线守护**是**读被守护文件的源文本、用字面量多行锚点做匹配**的。这类守卫对换行符敏感：锚点里含 `\n`，而 Windows 上 `core.autocrlf=true` 会把源文件检出成 CRLF ⇒ 锚点失配。后果有两个，**后者更糟**：① 本机假红（看得见）；② 锚点永不命中 ⇒ **守护静默失效**（以为在守，其实没守）。而 CI 的 `mobile-test` 跑在 `ubuntu-latest`、`core.autocrlf` 默认关 ⇒ **这一整类问题在 CI 里结构性不可见**。「CI 绿 + 本机红」是它的标准形状；**#1137 与 #1138 就是这样漏出来的两个实例**。

**范围只有「源码文本的读取约定」这一件事**：不动 ①②④ 门的触发与证据口径，不动 `pr-evidence` 校验器，不动 `.uts`/`.uvue` 的编译链。

## ② 选型 + 一句理由

| 决策 | 一句话理由 |
| --- | --- |
| **① 接受「Windows-only 破坏」为已知风险**，不为它加 Windows runner | 全仓零 Windows 基建，加一条 `windows-latest` matrix 腿换来**只是换行符这一类**（④ 门已明文把 HBuilderX 排除在 CI 之外），代价与收益不成比例 |
| **② 但不接受「什么都不做」**：补一道**与平台无关**的读取层归一 + 自检 | 「接受」不该等于「什么都不做」；且静默失效是**有欺骗性**的失败——CI 绿、本机也绿，靠本机兜底对它**不成立** |
| **③ 解法取「读取层无条件归一」，不取「继续补钉扩展名」** | 归一后**扩展名钉没钉完全不重要** ⇒ 对 `.txt`/`.yaml`/`.xml`/`.py`/`.cjs`/无扩展名/**未来的新格式**一律免疫。枚举式补钉永远追不上新格式，而漏掉的那一种正是静默失效的来源——**#1137 就是这个形状** |
| **④ 自检走「结构增量门 + 行为断言」两道，且都不计入 ③ 证据** | 结构半防**新写的**裸读、行为半防**归一本身被改坏**；两者都真断言。但结构半按本仓定义属**接线守护**，而 ADR-0008 已明文裁定「接线守护**不构成 ③ 证据**」⇒ 列为独立守卫，不混进 ③ 判据 |
| **⑤ 存量不一把梭**：自检走**增量门**先落，存量归一另摊一张票 | 抄本仓现成先例：`frontend-check` 的「守卫增量门」注释写明「*只查相对默认分支的新增行：存量由专项批次清理，不阻塞日常 PR*」⇒ 政策立刻生效，不阻塞在一个大 PR 上 |
| **⑥ 不加「自报在本机跑过」的 PR 模板要求** | 自报不是判据（0008：「无产物、只有勾选 = 缺证据」）；且勾选项会给人「尽责了」的错觉，而本风险的**本质特征是静默**。改为让自检报错**可行动** |
| **⑦ 不再新增「为契约测试而钉」的 `.gitattributes` 条目** | 读取层归一已结构性消掉该风险；继续补钉属重复防护，且会把「枚举式」的坏习惯延续下去 |

## ③ 明确不做的事

- **不给 CI 加 Windows runner**；不改 `mobile-test` 的 `runs-on` 或触发面。三种做法的对比见「附：为什么不是「加 runner」或「补钉扩展名」」。
- **不把 HBuilderX 搬进 CI**；②/④ 门的载体与触发不动（沿用 0008 的「明确不做」）。
- **不改 ③ 门的语义与证据口径**；不改 `pr-evidence` 校验器（改动量 = 0）。
- **不把本自检计入 ③ 证据**（它是接线守护，见 ②④）。
- **不动 `.uts`/`.uvue` 的编译链**；不追（也不宣称）④ 门在 Windows 上的行为。
- **不新增「自报」类要求**（PR 模板 / AGENTS.md 门纪律都不加）。
- **不重开 #1137 / #1138 已关的结论**；不重开 #1138 的上游缺陷票（第三方库，权限与可达性问题，非能力问题）。
- **不为本议题伪造 repro 去套诊断流程**：两个实例都已填，当前**没有**可复现的红。

## ④ 拆分步骤

**票 A — 行为断言（读取层归一）**
把 `contributionStatusContract.test.js` 里那条**合成 CRLF** 断言推广为**共享读者**的守护：共享读者落点 `utils/utsHarness.js`（已是共享测试源码；`jest.config.unit.js` 的 `testMatch` 只认 `utils/**/*.test.[jt]s?(x)`，故它**不会**被当测试收集）；断言吃**合成 CRLF 文本**后不含 `\r`（**不**读工作树真源——那是平台相关的）。**判别力实测**：把归一那一层拆掉 ⇒ 该断言必须红。

**票 B — 结构增量门**
新增 `scripts/check-contract-read.mjs`，支持 `--all` 与 `--diff <base>`：判据 = `utils/*.test.js` 里**不得出现未归一的源码裸读**；在 `mobile-test` job 里加一步，抄 `frontend-check` 的增量门写法（显式 `git fetch` 默认分支并写目标 ref，理由见那段注释：裸 `git fetch origin <branch>` 在浅克隆下不建 `origin/<branch>`）；**免 allowlist**（读临时/运行期产物天然落在规则外）；**报错文案必须可行动**，直接写明「此读取点要改用 `readText`；理由 = Windows 检出 CRLF 会让多行锚点失配，见 ADR-0019」。**判别力实测**：故意把某个契约测试改成裸读 ⇒ 增量门必须红。

**票 C — 存量收敛**
按「给每个文件的读取帮手补一层归一」收敛（规模见「附：测量」）；**判据是票 B 的 `--all` 通过**，不是那个数（它是静态下限）。**成对取证**：逐批在 Windows 本机跑一次 `npm run test:unit`（本仓唯一能看见该面红了的地方），留下产物。

**票 D — 注释随改**
根 `.gitattributes` 里 `*.uts` / `*.uvue` 两条的注释现把**契约测试锚点失配**写成钉 LF 的**唯一理由**；读取层归一落地后该表述过时且会误导（后人会以为「钉了 LF 就安全了」）。改为「**纵深防御**」口径，并注明主防线已是读取层归一。

**依赖**：票 A 无依赖 → 票 B 依赖 A 的读者落点 → 票 C 依赖 B 的 `--all` → 票 D 随 B/C 落地。

## ⑤ 约束（不能动的）

- 本自检的价值 = **把风险从「依赖 `.gitattributes` 钉对了」转移到「读取层无条件归一」**：从**枚举式防护**变成**构造式防护**。任何方案不得把主防线退回枚举式。
- `.gitattributes` 现有的 15 条 `eol=lf` **不因此废掉**：它们对 `gofmt`、Docker、`^M: bad interpreter` 等**另有工具链理由**（注释里已写明）。两层并存，属性层降级为纵深防御。
- 自检**不得依赖平台**：断言必须用**合成** CRLF 源，**不得**读工作树真源（那会让它在 ubuntu 上恒绿、只在 Windows 上才暴露——正是 #1143 的成因）。
- 本自检**不是 ③ 门的证据**；③ 的判据与覆盖范围不变。
- 存量 83 个文件**不阻塞**日常 PR（增量门语义）；但**也不得**把 `--all` 长期留在红态而不收敛。
- **不得**为了本议题伪造 repro 去套诊断流程（当前没有可复现的红）。

## ⑥ 验收标准

1. **判别力（结构半）**：故意把某个契约测试改成裸读 ⇒ 增量门**红**。
2. **判别力（行为半）**：拆掉归一那一层 ⇒ 合成 CRLF 断言**红**。
3. **平台无关**：两道自检在 ubuntu 与 Windows 上结论**相同**（不得出现「只在 Windows 上才红」的判据）。
4. **零回归**：`npm run test:unit` 在收敛后全绿；`ci-summary` 的 `mobile-test` 仍被断言。
5. **报错可行动**：自检失败的输出含「改用 `readText`」与 `ADR-0019` 指引。
6. **③ 语义未变**：`pr-evidence` 校验器与 0008 的 ③ 条款**改动量 = 0**。

## 附：为什么不是「加 runner」或「补钉扩展名」

| 做法 | 对**未知 / 未钉扩展名**（`.txt`/`.yaml`/`.xml`/`.py`/`.cjs`/无扩展名/未来的新格式）的效果 |
| --- | --- |
| 补钉扩展名（枚举式） | **永远追不上**；漏掉的那一种正是静默失效来源 |
| 加 Windows runner | 也不解决未钉面，只是**让失败当场可见**（更响，但仍靠人记住去补钉） |
| **读取层归一（本决策）** | **对扩展名完全不敏感** ⇒ 这一类风险被**结构性消掉** |
