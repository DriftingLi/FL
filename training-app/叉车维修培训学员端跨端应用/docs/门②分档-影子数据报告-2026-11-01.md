## 0. 结论（先看这三行）

1. **实时影子窗口零样本**：波 2 合并（2026-10-31T15:38Z）后共 5 次 `pr-evidence` run，命中运行时面的 **0 个** ⇒ 分档器在真实 PR 上一次都没算过档。原计划"读影子日志出报告"卡在**数据源**，不在判据。
2. **回放口径（200 个已合并 PR）**：命中运行时面 27 个，**27 个全是全门档**；106 个运行时文件里 105 个全门、**1 个模板档**。模板档 PR = 0。
3. **若现在翻 `exemptionActive=true`**：少跑一次**必过** ② 的 PR 数 = 0，少跑任意 ② 的 PR 数 = 0 ⇒ **收益恒为 0，而判据从未被真实样本行使过**。建议波 3b **不转正**，并把杠杆移到 ② 的执行成本上（§6、§8）。

## 1. 口径：两种窗口不能混说

| 窗口 | 定义 | 本次样本 |
| --- | --- | --- |
| **实时影子** | 波 2 合并后 CI 真算出来的分档（`SHADOW-0052` 注记） | 5 次 run，**0 个命中运行时面** |
| **历史回放** | 同一份判据对历史已合并 PR 的事后计算 | 200 个 PR，27 个命中运行时面 |

回放**不是**影子实测：当时的 PR 没有分档结论、也没有 `- 档位：` 声明，回放只能回答"若这套判据那时就在，会怎么分"。它能给分布与适配面，不能给"判据上线后被实证过"这一条。

名单快照：`.github/scripts/lib/mobile-gate-core-list.json` version 1（2026-10-31），`exemptionActive=false`、`logicLiteTierOpen=false`——本报告全程只读，未改任何开关。

## 4. 为什么模板档在本仓不可达（这是本报告最重要的一条）

模板档的门槛是"**非核心页 `.uvue` 且只改文本行与非布局样式值**"。而本仓的真实 PR 形态是**页面 + 逻辑 + 公共依赖的捆绑**：

- 16 / 27 个运行时面 PR 带公共目录改动（`composables` / `utils` / `stores` / `components`）；
- 12 / 27 带新增或删除文件（新页面、新组件、组件改名）——状态即全门；
- 页面里改一行文案往往同时改 `:.class=` 绑定或加一段 `script`，命中阶梯 3。

反事实证明这不是"某条规则太严"：把**公共目录**这一条从触发里摘掉再算，11 个 PR 里仍然**没有一个**降到模板档——多数仍因核心页、新增文件、绑定而全门。⇒ 页面改动本身带着逻辑，模板档在当前开发形态下几乎没有落点。

这条对 3b 的含义很直接：**转正的收益不是"小"，而是"结构性为零"**。

## 5. 误分类与核身：这一波没有样本

- 正文档位声明：**27 / 27 未声明**。影子期没人写 `- 档位：全门|模板减配|逻辑减配`——这不怪执行人：A1 证据只要求 `跑于 <sha7>` + 门读数行，档位声明属 3b 之后的事。⇒ **核身面（声明 vs 事实）本轮无样本可评**，只能评事实侧。
- 异常注记：**0 条**（名单形状合法、开关未被翻，与波 2 的"Shadow 期间不可能被提前打开"一致）。
- planned 双证：**27 / 27 `absent`**。A1 下 ③ 两腿读数不入正文，changed 行自然为 0；`#2180` 之后新 PR 若贴 `TEST_*_CHANGED_RESULT` 行才会出现。⇒ 决策 6 的双证链在影子期**天然没有样本**，与前置 #2180 的产出不矛盾。

## 6. ② 设备门命中账（副产品，比转正更值钱）

| 指标 | 数 | 明细 |
| --- | --- | --- |
| ② 实际触发面（`needs2`：三份 json 改动，或 diff 含 `#ifdef MP-WEIXIN` 指令行） | **2 / 27** | #1903、#2046 |
| 正文带**真** ② 读数行 | **19 / 27** | 见下 |
| └ `errorsTotal=0` | 16 | — |
| └ `errors=env-blocked` | 3 | #2144、#2145（`ide-port-unreachable`）、#1800（`page-stack-empty`） |
| ② 必过却无读数行 | **0** | 两个必过项都有真读数（均 `errorsTotal=0`） |
| 有运行时面、无 ② 读数行 | 8 | #1844 #1866 #1872 #1878 #2092 #2096 #2132 #1916（都不是必过项） |

读法：

1. **② 的必过面很窄**（2/27），绝大多数 ② 运行是 ADR-0043 决策 3 的**纪律自选**——所以"给模板档豁免 ②"这件事，连省纪律成本都省不到，因为纪律面本来就不是干跑。
2. **真正的痛点是不确定性**：19 次真读数里 **3 次是"环境不可用"**（env-blocked，16%）。#2144/#2145 正文写明 ② 未命中触发面、读数只是留档；#1800 是自动化会话 `pageStack` 为空、三次重跑同一读数。这类失败与改动无关，却要占掉一次排查——比"该不该跑"更贵。
3. 读数识别规则：只认「token 后紧跟 `key=value`」的行；正文里**提到** `MP_WEIXIN_RESULT` 的散文不算（#1916 就踩过，naive grep 会多算一条）。

## 7. 潜在漏检估计

- **结构性漏检 = 0**：转正后会被降档的 PR 数是 0，自然没有"降档后漏掉的问题"。
- **但 0 ≠ 安全**：模板档判据从未在真实 PR 上被行使过，它面对未来形态（大量纯文案/样式页改动）会不会判错，本窗口**无法回答** ⇒ 风险是**未知**，不是**已证为零**。
- 唯一近似样本 `resume.uvue`（#2135，纯文本行）：该 PR 的 ② 读数 `errorsTotal=0`，与"文本行改动无运行时风险"的假设一致——**n=1，不足以支撑任何结论**。
- 换向检验：若未来形态变成"纯文案页 PR 为主"，同一命令重跑即可重估分布，判据不需要改（§8-D）。

## 9. 限制（写实）

- **窗口短**：200 个 PR 只覆盖 10 天；本仓合并频率高，形态可能不代表更早或更晚的时期。
- **核身面缺样本**：27/27 未声明档位 ⇒ 只能评"事实侧"，评不了"声明 vs 事实"。
- **patch 缺失会判全门**：GitHub files API 对超大 diff 不给 `patch`；本窗口 0 个运行时文件缺 patch（已核），更大窗口可能出现——方向保守（升档而非降档）。
- **回放依赖同一天的名单**：若名单本身要改（加/减核心页），分布会变；改名单前后应各回放一次再比较。
- **② 读数行识别**按「token + `key=value`」，正文提到 token 的散文不算；不同人写的行可能有形态差异，报告数字以脚本口径为准。
