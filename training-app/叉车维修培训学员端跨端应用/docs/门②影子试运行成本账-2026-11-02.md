# 门②影子试运行成本账（#2198，2026-11-02）

> 尺子 = **ADR-0053 决策 3 的总成本尺**：`开发 + 验收 + 维护 + 返工`，验收口径含**人工等待、排查失败、重复执行、维护规则时间**。
> 本文件回答 ADR-0053 的两问（验收成本消耗在哪 / 新机制减少多少实际成本），并给出影子试运行（ADR-0052 波 1→波 2→波 3a→P0）的实付账。
> 每条读数标**来源**与**测法**；未计时的一律写「未计时」，不估数。所有 `gh` 命令的取数方式见 §6。

## 1. 口径

- **时间单位**：墙钟秒/分钟。不含模型推理成本（那部分不在本仓可测范围内，见 §5「未核」）。
- **分母**：`200 个已合并 PR`（3a 回放口径，与 #2193 同一分母）与 `影子落地后的实时窗口`（2026-10-31T15:38:07Z 起）。
- **「命中」** = PR 改动了运行时面（`*.uvue` / `*.uts` / training-app 三份 json），即影子分档的输入。
- **「可兑现收益」** = 会被判成模板档（从而免 ②）的 PR 数 × ADR-0052 写的 8–12 分钟/PR。不把「没在跑的门」算成节省。

### 2.2 运行时（每个 pr-evidence run 的增量）

- 影子挂在校验器里：**每 run 恒定取一次名单**（`.github/workflows/pr-evidence.yml:61-69`，不分命中与否），取不到就 `coreList=null` 并 fail-closed 记全门——这条本身不产生任何判红路径。
- 增量 = **1 次 API 往返** + 一次 `JSON.parse`(46 行) + 纯函数分类（无 IO、无网络）。量级：**毫秒级**。
- 现测窗口内 21 个 pr-evidence run 的 job 时长（`updated_at − run_started_at`）：min **6 s** / 中位 **9 s** / max **10 s**（21 个样本：6,7×5,8,9×7,10×5）。
- ⚠️ **与 #2193 的口径差**：#2193 量得 p50 4 s / p95 6 s（n=25，2026-11-02 02:0x），本次同法量得中位 9 s。差值 ~3 s 更大可能是「queued 段是否计入」的口径差（`run_started_at` vs `created_at`），**未核**。两条都说明：影子那一次 getContent 落在噪声里，**不可分辨**。
- 折算全量：22.4 run/天 × ~9 s ≈ **3.4 分钟/天**——**这是整道 pr-evidence 的钱，不是影子的钱**；影子的份额严格小于一次 API 往返 × 22.4/天。

## 3. 对照组：② 门的成本结构（200 PR 窗口）

| 项 | 读数 | 来源 |
| --- | --- | --- |
| 命中运行时面的 PR | **27 / 200（13.5%）** | 3a §3 |
| 其中 ② 实际**触发面**（`needs2`） | **2 / 27** | 3a §6 |
| 正文带**真** ② 读数 | **19 / 27** | 3a §6 |
| ② 单次执行（同树） | 126–327 s，**中位 ≈ 240 s** | `docs/agents/dev-loop.md`「② 门失败后不带 -SkipBuild 重试」段（#1987 实测） |
| ② 整轮（冷树） | **519 s**（publish 215 / 245 s + 会话段 + 冒烟两页） | 同上，#2163 实测 |
| env-blocked | **3 / 19 = 16%** | 3a §6（#2144、#2145、#1800） |

### 3.1 把这 132 分钟拆开

- **21 次 ② 执行** = 18 次其它 PR（各一次）× 240 s ≈ **72 分钟** + #1800 的 **3 次** × ≥1,201 s ≈ **60 分钟**（`direct-total pages=9 accepted=4 elapsed=1201s`，PR #1800 正文原文，2026-10-23）。
- 合计 **≈ 132 分钟 / 200 PR**，摊到每个 PR ≈ **0.66 分钟**；摊到每次真实读数 ≈ **6.3 分钟**。
- **env-blocked 的重复执行占 45%**（60 / 132）——而这 60 分钟里 **94% 由 #1800 一个 PR 的三次重跑贡献**。
- 但注意 **16% 这个比率不等于「16% 的重跑」**：3 例里 **2 例是廉价早退**——#2144 / #2145 的 `reason=ide-port-unreachable` 在 `scripts/mp-weixin-check.ps1` 的**端口预探**阶段就早退（publish 之前），实付 = 一次端口探针 + 写一行证据，**分钟级**。#1800 的 `reason=page-stack-empty` 是**跑完才失败**，那才是贵的形态（≥20 分钟/次）。

### 3.2 人工等待

- **单会话**：`HX_BUSY wait=0 result=free` 是常态（`docs/verification/device/1027`、`1042` 现测），影子窗口内的 5 个 PR 正文都没有排队读数 ⇒ 每 PR 的人工等待实测 **≈ 0**。
- **多会话并发**：锁只保证串行、不保证不阻塞；实测出现过 `HX_BUSY wait=120 result=timeout`（ADR-0007:485），② 的默认预算是 900 s。⇒ 等待是**并发时的一次性上限**，不该摊进「每 PR 成本」。
- 结论：**人工等待不是这张账的主要项**；主要项是「② 的执行时长」与「失败后的重复执行」。

## 4. 对照 ADR-0052 的口径收益

| 项 | ADR-0052 口径 | 本账实测 | 差 |
| --- | --- | --- | --- |
| 模板档免 ② 的单 PR 收益 | 8–12 分钟 | ② 单次中位 **4 分钟**（240 s）；冷树整轮 **8.7 分钟**（519 s） | 口径偏向「②+④c 串跑」的 PR 面整体（AGENTS 常态 12 / 17 分钟），**对单道 ② 高估 2–3 倍** |
| 可兑现的 PR 数 | 未写 | **0 / 200**（回放）、**0 / 2**（实时命中） | 基数不存在，「8–12 分钟 × N」在 N=0 时是 0 |
| 回本期 | 未写 | 不存在（不是「还没到」） | 收益结构性为 0，见 3a §4：拆掉公共目录规则后仍 11/11 全门 |

**为什么基数会是 0（3a §4 已证，此处只引一句）**：本仓真实 PR 形态是「页面 + 逻辑 + 公共依赖捆绑」——16/27 带公共目录改动、12/27 带增删文件，模板档门槛（非核心页 + 只改文本行/非布局样式值）几乎无落点。

## 5. 结论与给下游的输入

1. **影子试运行的成本已经付清、可清点**：1,009 行、5 个 PR、63 小时墙钟；运行增量不可分辨；维护面 46 行名单 + 6 类守护；自身返工为 0。
2. **收益的基数是 0**：200 PR 回放 0 个模板档 PR；影子落地后实时 21 run 命中 2 次，**两次都是 `档=full`**（同一分支 `feat/1951` 的两次推送，run `41385943714` / `41385489783`），判据出处都是 `api/course.uts`（公共目录）+ `pages/courses/courses.uvue`（绑定）。⇒ **3b 复评三条件里的「可验证的实际收益」当前读数 = 0，不构成转正依据。**
3. **顺带纠正 #2193 的一个快照结论**：#2193 在 34.6 h 窗口量到「13 run / 0 命中」，据此说「瓶颈是样本流」；本账在 63 h 窗口量到 **21 run / 2 命中（9.5%）**，与回放的 13.5% 同量级 ⇒ **样本流回来了**，而模板档仍是 0/2。瓶颈不是样本流，是**形态**。
4. **给 P2 的输入**：成本真正的大头在「② 的执行与可用性」（132 分钟里 45% 是环境受阻后的重复执行；单次 4 分钟、冷树 8.7 分钟）。治理对象建议写「② 的成本」，而不是「把分档转正」——后者在本仓没有落点。
5. **给 3b 的输入**：除非命中形态变化（出现真正的模板档 PR），否则 3b 无重评依据；影子可继续零成本跑（它不判红、只记录）。

## 7. 未核与缺口（明写，不据以裁票）

- **纯开发工时未计时**：仓内没有可复算的计时源；本账用「PR 开→合窗钟」作下界替代。
- **29 个 run 的时长口径差未核**：#2193 的 p50 4 s 与本账中位 9 s 差 ~3 s，怀疑是 `run_started_at` 与 `created_at` 之差（排队段），未逐 run 核对。
- **② 的 21 次执行未逐条计时**：#1800 的 1,201 s 是 `direct-total` 段读数（不含 publish），其余 18 次用 #1987 的中位 240 s 代；**个别 PR 的 ② 会长很多**（#1800 就是），所以 132 分钟是**下界量级**，不是精确和。
- **模型推理成本**不在本仓可测范围；若要把 agent 会话成本也折进去，需要另建计时源（本账不估）。
