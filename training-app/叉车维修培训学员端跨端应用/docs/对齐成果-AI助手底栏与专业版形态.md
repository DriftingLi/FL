## ⑦ 判断失误复盘（这一节最值钱）

**同一个底栏问题，我连着判错三次方向**：

| 轮 | 我的判断 | 修法 | 结果 |
|---|---|---|---|
| 1 | 悬空 247px = `windowHeight` 在两次实例化间取值不同 | 根 view 回 `flex:1` + 实色底 | ✅ 真修好了（且顺带纠正了「flex:1 不绘制背景」的旧错判 —— 那结论是被**渐变不绘制**混淆的） |
| 2 | 偏下 43px = `safeAreaInsets` 取不到时静默跳过 | 三段兜底 + 读数设上限 | ❌ **方向错** —— 文字位置从头到尾都对（2480-2491 = 原生），异常不在底部内边距 |
| 3 | 首帧 `<image>` 取默认尺寸撑高 | 图标套定尺盒子 | ⚠️ **半对** —— 修好了「首次创建」，但把「切页重建」那条弄坏了（两态对调） |
| 4 | 钉死栏高 | `height: 96rpx` → 裁掉文字 ✗；改 `128rpx` → 仍裁 ✗ |  **撤回** —— 那条路径栏真有 296px，任何更小的钉死值都会裁 |

**根因不在技术，在方法** ✓✓：

1. **先猜机制，再找验证** —— 应该反过来：先做**能区分假设的测量**，再动手。第三次之后我改用「左边缘颜色剖面 + x=2 屏幕最边缘找通宽白条」，**一次就看清了**（内容在上、多出的空白在下），而前三次都是盲改。
2. **被同构形状骗了两次** —— AI 页的**功能宫格也是 5 列均匀排布**，和 tab 栏签名一模一样 ⇒ 我拿「5 列墨迹带」当 tab 栏量，量的是页面内容 ✗。教训：**签名式判据要先排除同构干扰**（这次靠「通宽白条」这种内容无法伪造的特征 ✓）。
3. **把「两个页面」当成「两种状态」** —— 最贵的一个错：`ai-basic` 与 `ai-assistant` 各截一张图，我当成「首次 vs 切回」，于是推出「状态相关」的错误结论，还据此改了三轮。**先确认两张图是不是同一个对象** ✓。
4. **用错了迭代速度** —— 仓库 AGENTS.md 明写三层节奏（模板/样式改走热刷新 秒级 ✓、script 改走 `hx:run` 1-2 分钟 ✓、全量编译是门的活 ✓）。我一直用 `cli launch` 全量路径（实测 87s–10min ✗），把「验证」变成瓶颈，于是更不愿多试、更倾向猜。**慢的验证会逼出坏的判断。**
5. **补丁思维 vs 去掉这个面** —— 前四轮都在给手画栏打补丁；真正的答案是**根本没有手画栏**（#911/ADR 0009）。是维护者一句「为什么要手画栏，不应该是跟其他页面一样吗」把方向掰回来的 ✓ —— **当同一个组件连续冒出四个现象，怀疑对象应该是这个组件本身。**

**另一处同类：渐变不绘制（2026-09-13 追加，实测定案）**

「本机型不绘制 `linear-gradient`」这条，我在同一晚**怀疑过自己** ✗：起因是 `courses` 页量到一块平的 `#F5F5F5` ✓ —— 那**恰好是该页渐变声明的末色标** ✓，于是「渐变被降级成末色标」这个解释看起来成立 ✓。但它同样能被「那只是页面默认底色」解释 ✗ —— **两种解释各有反例**，我当时既没定案、也没停下来 ✗。

**定案用的方法值得记** ✓：**挑一个「两个候选假设预测彼此远离」的对象** ✓ —— `profile` 页的渐变末色标是 `#0CA2EF`（**强蓝** ✓）：

```
若「降级成末色标」成立  ⇒ 整页强蓝 rgb(12,162,239)
若「完全不绘制」成立    ⇒ 整页白   rgb(255,255,255)
                        两者相差 240 个单位 ⇒ 任何噪声都盖不住 ✓
```

实测（`x=8` / `x=1148` 两侧非内容区，`screencap -p` 无损 PNG）：y=15% / 35% / 55% / 75% / 92% **全部 rgb(255,255,255)** ⇒ **完全不绘制** ✓✓。

⇒ **判据设计的原则**：当两个假设都能解释手头的观测时，**不要去找更多同类观测，而要去找一个两者预测相距最远的观测** ✓。这与上面「先做能区分假设的测量，再动手」是同一条原则的两种用法 ✓。

**影响面**：全项目 **22 处 / 18 个文件**（`Select-String linear-gradient` 全量清点 ✓）—— 整页底色 7 处（`profile` 的强蓝底现在**是纯白** ✗，最显眼）、主色按钮/卡片 6 处、语义色卡片 2 处、强调色卡片 5 处、浅色卡底 2 处。口径与拆分见 **#937** ✓。

**另外两次工具性失误（值得记，避免重犯）**：

- PowerShell 里把 `+` 当字符串拼接**写在参数位** ⇒ 参数错位、**把源文件改坏了** ✗（靠 `git checkout --` 还原 ✓）。规则：拼接放赋值里，不进参数列表。
- PowerShell 双引号串里的 markdown 反引号被当转义符（`` `u `` → unicode 转义报错）✗；以及 GBK 控制台打不出 `✓` ✗。规则：**含 markdown 的字符串一律单引号**；**给控制台输出的脚本别放非 ASCII 符号**。
