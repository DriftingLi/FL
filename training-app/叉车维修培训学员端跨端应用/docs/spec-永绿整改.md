# [Spec] 移动端「永远绿」三层整改 + E2E 通道裁决

> 2026-09-18 · 来源：E2E 通道裁决会话（PR #1136 裁决落地 + #1139 第一票落地）。
> 节次固定六段（本仓口径：spec 与票**不只依赖结论，还依赖被否决的分支与否决理由**）。
> 与页面手术那份 `docs/refactor-decisions.md`（#638）**并列**，不改写它：那是「页面结构」的 spec，这是「验证层」的 spec。

## ① 目标与范围

把本仓三个**「永远绿」**（改坏被测对象也不会红）逐个修成真的，并把「什么才算一层验证上线」写成可复用的判据。

三个先例（均已取证）：

1. `utils/*.test.js` 78 个里 **77 个**改坏被测算法**不会红**（手抄复印件 / 源码文本断言）；
2. `dev:finish` **步骤 7**「截图对比」空转（只比 MD5、基线永远空、有变化只打黄字 ⇒ 永不 fail）；
3. `dev:finish` **步骤 8** 证据生成，编译结果为空时**硬编码** `COMPILE_RESULT errors=0`。

**范围**：移动端工具链的**判据与守护**（`scripts/`、`utils/*.test.js`、相关 ADR）。**不含**：页面结构手术（#638 那份）、后端/前端（根仓库）侧的测试改造、移动端业务代码行为。

**统一判据（每一层上线前必须能回答，答不上就不上线）**：

- ① 「我故意弄坏它，它会不会红？」（判别力）
- ② 「它测的是该测的那一支吗？」（条件编译教出来的第二条 —— 变异自检也骗得过）
- ③ 「只跑通过的那一次，不算验收。」（成对取证）

## ② 选型 + 一句理由

- **判据层用「行为守护 + 契约守护」双轨**：行为守护真跑被测物（证明判据有牙齿），契约守护钉调用点（证明接线没断）——缺前者是永绿，缺后者是空跑。
- **新判据一律先写「成对断言」**（必不红 / 必红各一条），单方向不算 —— 只测一个方向时，恒绿与恒红都骗得过。
- **像素差用纯 Node 零依赖**（`scripts/lib/png-diff.mjs`）：CI 跑 ubuntu，`System.Drawing` 仅 Windows 可用、`magick/ffmpeg` 不保证存在。
- **判定抽成可被真跑的纯函数**（`scripts/lib/screenshot-gate.ps1` 的 `Get-PngDiffVerdict`）：判定散在 I/O 里 ⇒ 没人能真跑它，文本断言抓不到「永不 fail」。
- **E2E 通道裁决结论（PR #1136）**：微信小程序通道**只能做 page 级断言**，不能做「点击 → 跳转 → 断言」的流程验证 ⇒ **Q5「把开发期验证迁到脱真机通道」撤销**；Android 通道只在 ①a 收口时顺带跑。别再重开这个问题。

| 不把「判不了」当「无变化」 | `unsupported` 一律回退 MD5 并如实记 `Mode`；零截图 ⇒ 判红，不是判绿 |

## ⑤ 约束

- **真机类动作攒批**：`dev:finish` 步骤 4–6 会抢 `hx-agent.lock`（上限 1800s），**HBuilderX 是单实例串行资源** ⇒ 攒批一次上机，**绝不 kill HBuilderX**。
- **判据必须协议级**：不可用「端口在不在」「某个文件在不在」当代理判据（血账：用 `project.private.config.json` 判 IDE 是否打开 ⇒ 误报；必须用 `Tool.getInfo` 回包）。同族：**「触发条件永假」的判据等于没有判据**（见 §④ 更正 3）。
- **#1138 不阻塞 #1157（② 门截图）**：`#1138` 坏的是 `automator.launch()`；② 门走「外部调 `cli.bat auto` 再 `connect()`」，`connect()` 实测正常（`Tool.getInfo` 回 `SDKVersion=3.17.2`）—— 证据在 #1138 自己的证据段。**别把这两件事混成一件**。
- **密码学级的措辞纪律**：没有真跑过就不写「已通过」；「未命中运行时面 ⇒ 免四门」不等于「不需要验证」——工具链改动的验收判据是「**它要达成的那个行为在真实链路上成立**」。
- **并发 git 纪律**：一会话一 worktree 一分支；**绝不 `git add -A`**（主树有别的会话在飞改动）。见 `docs/agents/multi-agent-git.md`。
- 既有红 `utils/contributionStatusContract.test.js:231`（Windows CRLF / `.gitattributes` 未钉 `*.uts`）归 **#1137**，不与本 spec 混改。

## ⑥ 验收标准

**每一层（S1–S6）都按同一组判据验收**：

- **代码层**：`npm run test:unit` 除 #1137 那条外全绿；新增守护含**成对**断言（同内容必不红 / 超阈值必红）——只测一个方向不算。
- **判别力（本 spec 的核心）**：把**已知坏实现**塞回去 ⇒ 该守护必须红，且**红在预期的那条用例上**（记进票或 ADR；`pr-evidence` 的「运行时面」校验与本 spec 无关，但 PR 正文照旧写证据段）。
- **真链路（S1 专属，AGENTS.md：改截图判据须跑一次真机并留产物）**：两轮 `dev:finish`（🟡）**成对** —— ① 不动任何文件 ⇒ 全绿、退出 0；② 只改一行 `.uvue` 样式 ⇒ 报出变化且**退出码非 0**。**只跑第 1 条不算验收**。
- **不变量**：既有守护（`screenshotDiffContract` D1–D9、`screenshotDiffSingleFileBehavior` C1–C4、`devFinishContract` F1–F11）必须继续绿。
