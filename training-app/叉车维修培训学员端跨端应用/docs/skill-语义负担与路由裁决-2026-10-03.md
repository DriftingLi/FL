## ① 一句话结论

**三个症状里，「夹带复杂语义」的主因不是 Matt Pocock 的 skill，而是本仓自己那份常驻注入的移动端 `AGENTS.md`（实测 29,535 字符，是同环境全部 38 个可自主调用 skill 的常驻描述总和 5,503 字符的 5.4 倍）；「复杂提问」确实是 Matt skill 的设计（`grilling` 明写「一轮问完整条 frontier 然后等你回」），且与 superpowers 的「一次只问一个」正面冲突、也与你在 2026-09-23 定下的「最多留一件要人拍板的事」冲突；「不知道如何执行」的机制根因是 25 个 Matt skill 里 14 个带 `disable-model-invocation: true`——它们对模型零上下文成本、但把「谁存在、何时用」全部压回你脑子（上游自己称这笔为 cognitive load），而唯一的目录式路由 `ask-matt` 恰好也带这个 flag，所以它永远不会自动出场。**

### 一手口径：哪部分常驻、哪部分按需（Anthropic 官方）

- 「Progressive disclosure is the core design principle that makes Agent Skills flexible and scalable.」
- 「**At startup, the agent pre-loads the name and description of every installed skill into its system prompt.**」
- 「If Claude thinks the skill is relevant to the current task, it will load the skill by reading its full SKILL.md into context.」
- 三级：Level 1 metadata（always loaded）／Level 2 instructions（loaded when triggered）／Level 3 resources & code（loaded as needed）。
- 容量红线：name ≤64 字符、**description ≤1,024 字符**、SKILL.md 正文建议 **<5k tokens**、未触发时元数据 **~100 tokens / skill**，官方明说「you can install many Skills without context penalty」。

### S3「有时候不知道如何执行」

**根因 A：路由器自己也是「只可人唤」的。** `ask-matt/SKILL.md` 的存在理由写在自己的 `:9`（「You don't remember every skill, so ask.」），上游 `SKILL-MECHANICS.md:22` 更把这写成 doctrine：「When user-invoked skills multiply past what you can remember, that piled-up cognitive load is cured by a **router skill** … **It can only hint, never fire them**」。而 `ask-matt/SKILL.md:4` 自带 `disable-model-invocation: true` ⇒ 它的 description 不进常驻清单，模型永远不会自己想到去查它。**每多一个 DMI skill，就多一份「你得记得它存在」的负担；14 个 DMI = 14 份认知负担，0 份上下文成本**（`SKILL-MECHANICS.md:10` 原话：「Zero context load, but it spends cognitive load: you are the index that must remember it exists.」）。

**根因 B：两个 skill 集在同一意图上直接抢，且抢的判据不对称。** superpowers 的注入文本 `using-superpowers/SKILL.md` 实测三条：`:11`「If you think there is even a **1% chance** a skill might apply to what you are doing, you **ABSOLUTELY MUST** invoke the skill.」、`:13`「IF A SKILL APPLIES TO YOUR TASK, YOU DO NOT HAVE A CHOICE.」、`:20`「Invoke relevant or requested skills **BEFORE any response or action** — including clarifying questions」。并且 `:30-31` 直接点名派活：「"Let's build X" → superpowers:**brainstorming** first」「"Fix this bug" → superpowers:**systematic-debugging** first」，`:28` 称这俩是「最常用流程技能」。

对照 Matt 侧同意图入口的触发条件（各 skill description 原文）：`diagnosing-bugs`「Use when the user says "diagnose"/"debug this", or reports something broken/throwing/failing/slow」——**必须有这类措辞才触发**；`grilling`「…or uses any 'grill' trigger phrases」——同理。**判据一边是「1% 就要调」，一边是「得听见关键词」⇒ 自动路径上 superpowers 恒赢，Matt 的 11 个可调用 skill 实际上退化成「人点名才动」。** 这就是「不知道如何执行」的核心机制：不是你选不出，而是模型替你选了一个你没打算用的。
