## 1. 结论先行

测试通过率与运行质量不匹配，不是「测试不够多」，而是**执行面错位**：

1. **233 个自动化套件里，0 个渲染 `.uvue`**。有 120 个测试文件「提及」`.uvue`，全部是读源码文本的接线/契约断言。61 个页面的模板、状态、生命周期，在自动化层面**没有任何执行覆盖**。
2. 页面层的唯一运行门是 ② 微信开发者工具门，但它**只覆盖改动页、只冷启动、只滚动截图**，且改动页以外退固定两页冒烟。回放 200 个已合并 PR，命中运行时面 13.5%（27/200），其中 ② 是「必过面」的只有 **2/27**。
3. **测试自身会成为缺陷的一部分**：#1713 修复前，`utils/forumContract.test.js` 明确断言了错误的存储键与错误函数名——测试把 bug 钉成了「正确行为」；#1677-A 的复现则来自取证脚本把 `wx.request` 全 mock 成空信封。
4. ④c「Kotlin 整模块编译」在脚本里已写明非等价于云打包/Gradle（`scripts/kotlin-all-check.ps1` 头注「非等价声明」），它证明不了 App 运行；WARNING 不进任何门的判据。

## 5. 自动化测试的实际覆盖边界

### 5.1 规模与构成（本机实测，2026-11-02）

| 项 | 数值 | 说明 |
| --- | --- | --- |
| ③ 接线腿（`jest.config.unit.js`） | 129 套件 | 读源码文本断言调用点/常量 |
| ③ 行为腿（`jest.config.behavior.js`） | 104 套件 | `utils/utsHarness.js` 的 `loadUts` 把 `.uts` 去类型后当 JS 真执行，依赖由测试注入 |

| 提及 `.uvue` 的套件 | 120 | 全部为源码文本断言，不执行模板 |
| CI 注释里的腿数 | 120 / 72 | **已漂移**（实际 129 / 104），`.github/workflows/ci.yml:517-518` 待校正 |

行为腿的能力边界写在测试自己的头注里（`utils/apiBatchAOutletBehavior.test.js`）：「渲染层（`.uvue` 模板）node 里跑不了，那是 ①a 真机门的事」。而 ①a 自 ADR-0043 起已降级为**发版前一次**。

### 5.2 覆盖率不能回答的问题

- 页面 `onLoad/onShow/reLaunch` 时序：无任何用例执行；
- 点击 → 状态变化 → 请求参数变化：无任何用例执行（#2196/#1677 正落此处）；
- 平台 CSS 差异（`fixed`/原生 tabBar 遮挡/safe-area）：Node 里没有布局引擎，不可能测；
- 带 query 的页面：② 门的换页机制不支持（#2110），③ 不渲染。

### 5.3 changed-only 的影响评估（结论：不是漏覆盖源）

- 本地 `test:unit:changed` / `test:behavior:changed` 走 `scripts/behavior-suite-deps.mjs`，算法**故意过覆盖**（按 basename 反查、import 反向闭包、门脚本与 text-coupled 名单强制全跑）；
- CI 两腿是**全量**跑（`.github/workflows/ci.yml` 分片执行）；
- ⇒ changed-only 只会多跑，不会漏；真正漏的是「运行时不执行」这一层，与 changed 无关。

## 7. 必须真实设备验证的高风险场景（按风险排序）

1. **原生/WebView 叠加层**：`position:fixed` 遮罩、半屏面板、原生 tabBar 遮挡（#1671 实证）。devtools 截图不可靠，必须真机像素判读或裁图比对。
2. **App(Android) 端 uvue 渲染**：非 mp-weixin 的布局/溢出/图片资产（#1467 吉祥物散架）。④c 编译通过完全无关。
3. **权限与凭据**：生物识别、安全存储、剪贴板、相册（`composables/useBiometric*`、`secureStorage`）。手抄镜像模块 7 个（`guards.md`），Node 侧只能测镜像。
4. **跨端登录态链路**：401 → 刷新 → 重发（#1704）；上传与 SSE 分属不同出口，端到端只能真机跑。
5. **长列表尾部与折叠区**：② 门逐屏截图可覆盖一部分，但懒加载、下拉刷新、上拉分页只在真机有真实时序。
6. **带 query 的直达页**：分享链接/通知跳转（#2110），② 门结构上做不到。

## 9. 最小改造方案（每条对应真实缺陷，不做全量真机、不做全量替换）

**M1（对应 P1/P3）页面状态下沉为可执行纯函数**
- 把「筛选态 → 请求参数」「早退 → 置 loading=false」抽成 `.uts` 纯函数（如 `coursesFilterParams(filter)`），行为腿用 `loadUts` 真执行断言参数逐字与状态复位。
- 成本：2 个函数 + 2 个行为用例；不新增门。挡住 #2196/#2097 同类。

**M2（对应 P2）关键业务链路的「点击 → 可见事实」冒烟，不做像素统计**
- 复用 #1919 已放行的能力面（`page.$` + `element.text()`，不新增白名单）：每条链路 = 一次点击 + 一次文本/参数断言。
- 建议 5 条链路（与 5 个 tab 对齐）：① 登录 → 选证件 → 首页切换（#1677）② 课程筛选 → 详情（#2196）③ 练习答题 → 提交 → 报告 ④ 论坛发帖 → 详情 → 点赞（#1713 回归）⑤ AI 对话 → 模型切换。
- 触发面：只在改动落在该链路所属页面目录时跑 1 条，**不做每 PR 全链路**；断言是业务事实（文本/下发参数），不是截图数量。

**M3（对应 P4）② 门读数强制 + env-blocked 自愈**
- 读数行必须带 `coverage=` 与 `errorsTotal`；`env-blocked` 自动重试 1 次 + 端口预探（影子报告已给建议，无需新门）。

**M4（对应 P5）④ 证据文案分家 + WARNING 可见**
- 证据行区分「④c 编译通过」与「App 运行验收（未做）」；把 `warn=N` 写进读数行（不判红，只可见），对「WARNING 可能对应不生效样式」保留抽样复核而非门化。

**M5（对应 P3）测试三问闸门落地为 lint**
- 行为/接线测试禁止断言存储键、私有函数名等实现细节，只断言对外可见契约；一次性扫描历史断言（#1713 已反转，回扫其余 6 个手抄镜像模块）。

## 10. 预期收益

- **覆盖结构**：页面状态的执行覆盖从 0 → 关键链路 5 条 + 状态函数 N 个；#2196/#2097/#1677/#1713 四类缺陷进入可回归面。
- **成本**：本地基线 12min（同树）/17min（新树）；M2 每条链路 <1min 且按目录触发，增量可控；M3 减少 env-blocked 空转（16% 的 ② 执行失败）。
- **门读数质量**：从 19/27 有读数提升到覆盖运行时面即必带读数，消除「8 个有面没读数」的不可见区。
- **不新增的**：不新增全量真机、不把全量测试改 changed-only、不扩白名单、不用截图数量代替验收。

## 11. 需要维护者裁定的事项

1. **M2 的 5 条链路清单**是否符合业务优先级（尤其「AI 对话 → 模型切换」是否纳入 P0）。
2. **② 门点击能力的允许范围**：#1919 已放行 `page.$` + `element.text()`，是否允许再放行「点击」一步（仍在 C3 禁区内？需要明确边界，否则会踩 15s 挂起）。
3. **#2196 的落地方向**：维护者已裁定「删 chips」并加 guard（PR #2213 open）；确认是否按此合并，还是改为「接上参数」。
4. **WARNING 的处置口径**：只做可见（`warn=N`）还是需要抽样人工复核排期。
5. **①a 发版冒烟的清单**是否纳入「原生叠加层 + App 端渲染」两项高风险（否则 #1671/#1467 类仍只能靠运气）。
