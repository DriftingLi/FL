## 第 1 节：口径与方法

| 项 | 口径 |
| --- | --- |
| 扫描面 | `pages/**/*.uvue` + `components/**/*.uvue` + `App.uvue`，排除 `node_modules` / `uni_modules` / `unpackage` / `.ci-verify` / 点目录 |
| 分层 | `pages/<页>/<页>.uvue` = entry；`pages/<页>/components/**` = private；`components/**` = shared；`App.uvue` = app |
| hex 正则 | `/#(?:[0-9a-fA-F]{8}|[0-9a-fA-F]{6}|[0-9a-fA-F]{3})(?![0-9a-fA-F])/g` —— **只认 3 / 6 / 8 位**，且后一位不得是 hex 字符 |
| 注释处理 | 两套读数：`raw`（含注释）与 `clean`（剥 `//`、`/* */`、`<!-- -->`）。**下文一律用 clean**，raw 仅作对照 |
| token 引用 | `/\$[A-Za-z][\w-]*/g`，在 clean 文本上统计 |
| token 定义 | 解析 `uni.scss` 的 `^\s*\$([\w-]+)\s*:\s*([^;]+);`，按值形态分类 |

### 为什么正则只认 3/6/8 位——一条必须写下来的坑

仓内注释大量使用 `#2520`、`#2761` 这类**票号引用**，而票号全是数字、数字全是合法 hex 字符。用宽松正则 `#[0-9a-fA-F]{3,8}` 会把票号当成颜色。

实测：宽松正则得 **1795** 处，严格正则得 **1028** 处，差 **767** 处。其中 4 位数字形态（`#\d{4}`）实测 **631** 处，抽样 top：`#2520`×25、`#2518`×19、`#2761`×16、`#1024`×15、`#2691`×14 —— **全部是票号，不是颜色**。

> **结论：此前流传的「三层裸 hex 920 / 527 / 348，合计 1795」是宽松正则的产物，被票号污染，不可作为基线。真实基线是 1028。**

## 第 11 节：结论与建议

1. **基线必须换**：1795 → **1028**。旧数被 631 处票号引用污染，任何基于 1795 的进度百分比都是错的。
2. **62.4% 可映射，但不能批量 sed**：`#ffffff` 一个值对 6 个语义 token，机械替换会抹平语义。正确做法是**按使用位置分流**，这是判断类工作。
3. **37.6% 是真缺口，且缺口高度聚集**：7 个「页面底灰」近邻值（65 处）+ 3 个「浅蓝底」近邻值（30 处）合计 95 处，收敛成 2 个 token 就能吃掉缺口的 1/4。
4. **语义色是 token 表最薄的一段**：绿色 100%、红色 79% 落缺口，且 Material / Element / Tailwind 三套色板并存 —— 这是「抄来的组件」的化石，不是设计选择。
5. **B0 换血漏了两组渐变**：`$header-grad-*` 与 `$primary-grad-pressed-*` 定义了 0 引用，页头与按下态仍是硬编码。
6. **白名单与 token 表口径未对齐**：71 条全部活跃（无死条），但其中 `#f5f5f5` 本可映射到 `$bg-color`。
7. **私有子件层引用率最低**（37% vs entry 66%），是 token 收敛的最大存量面。
