## 8. 新页准入判据（T8）

**结论**：新页准入 = **四张既有红牌 + 一张只读报告**。「无需人工判定」只在**合规判定**这一侧成立；N×G 是**分类登记**，与红绿无关。

### 8.1 五步 × 接住它的判据（已生效，全部在 ③ 两腿内）

| 步 | 动作 | 判据 | 红时怎么说 |
| --- | --- | --- | --- |
| ① 路由 | `pages.json` 加 `path` | `utils/nxgLedgerContract.test.js` 组 A：台账路径集合 ↔ 路由集合双向相等 | 点名「台账少一行」或「页面不存在」 |
| ② 入口件 | `pages/<族>/<页>.uvue` | `utils/batch6UiContract.test.js`：五硬指标 + 入口件枚举计数钉 | 逐文件点名 |
| ③ 模块声明 | `utils/modules.js` 登记 | `utils/modulesDeclarationContract.test.js` A2/A3/E2 | 报错给出该加的那一行 |
| ④ 台账行 | 台账加一行 + ui-spec §7.1/§7.2 成员数 | `nxgLedgerContract` 组 B/C | 点名哪一套对不上 |
| ⑤ 跳转接通 | 指向该页的 `navigateTo` query 键 | `utils/navQueryKeyContract.test.js` | 点名键与两个页面 |

**形态裁定**：准入清单 = **既有套件的并集**，spec 只写「哪一步由谁接住」+ 指针，**不新写断言**。新起准入套件会与上四件重复覆盖、造第二处漂移面，且不补任何当前盲区（当前盲区是 T4/T7 的**实施**，不是缺断言）。

### 8.2 两栏：已生效 / 随实施票生效

- **已生效**（今天就红）：8.1 的 ①–⑤。
- **随实施票生效**（现在**无覆盖**，不得显示为通过）：
  - 私有子件 `pages/<族>/components/`：同族封闭 + 值面棘轮，新文件基线缺省 0 ⇒「新增即合规」（T4 §9；`utils/privateComponentUiBaseline.json` **未落盘**）。
  - 共享件：新件「新增即合规」（T3 §X.7）；**引用率不判**（T3 §X.3）——不要把「必须用 `app-card`」写进准入（`utils/sharedComponentUiBaseline.json` **未落盘**）。
  - 判断面观察：G 套选择合理性、页头下沉疑似、间距等只读报告（T7；`scripts/audit-ui.mjs` **未落盘**）。

### 8.3 N×G 与准入的关系

- **N = 描述**，可由源码推导（§5）；**G = 内容区成员组合，不可机械重判**。两者都**不参与红绿**——守护对分类的唯一要求是「枚举合法 + 逐套计数一致」。
- **新页落不进 G1–G9 时**：开「立 G10」票，同批改 ui-spec §7.2 + 守护白名单 + 台账，**不静默造套**；也不允许 `G?` 占位（会让计数断言失效）。
- **新页不得进 N06 白名单**：N06 是存量自绘页面的封闭名单；新页声称 N06 = 给自己开豁免，准入判据直接判这不成立。

### 8.4 失败处理

- **红**：8.1 的既有套件（③ 两腿内）。红是「既有断言对新文件的自动接纳」，**不是新增判红门**：不加脚本、不加 CI job、不进 ruleset / pr-evidence。
- **只报告**：`audit:ui`（只读、`--strict` 默认关）。
- **计数钉刻意保留**：`batch6UiContract` 的入口件计数与新页台账行都要人改一格——这是**显式登记点**，属记账不属判定。

### 8.5 反例检验（已走一遍）

4 个最近新增页（`points-rules` N03/G4、`real-exam-papers` N03/G3、`points-exchange-records` N03/G3、`points-goods-detail` N03/G4）**全绿**。但 `real-exam-papers` 的 4 个私有子件（`practice-banner-card` / `practice-feature-grid` / `practice-module-list` / `practice-stats-bar`）今天**没有任何套件在看**——这就是 8.2 第二栏的盲区实证。另：#2827 的 9 处线宽**无判据接得住**（`utils/dashboardPage.test.js:195-197` 只钉 `section-underline` 存在 + `background-color`，不钉 `width`），属判断面。

## 9. 边界声明

1. **只管小程序端**：本 spec 与 ui-spec 同口径——`.uvue` 两端共用，App 端样式随改随走，**不设 App 端验证门**，验证留给 App 轮（ui-spec §12）。
2. **不新增判红门**：`audit:ui` 是只读报告面；三层判据全部落在**既有 ③ 两腿**内（接线套件 + 棘轮基线），不加 CI job、不进 ruleset / pr-evidence、不改 `gate-validator.mjs`。依据 `docs/design/20261120-间距机检不立裁定.md`（#2715）与 `docs/agents/CODING_STANDARDS.md`「判断类不接确定性检查」。
3. **与 ui-spec 的关系**：ui-spec 是**规范面真源**（值、形态、N×G 定义）；本 spec 是**治理索引与批次口径**，不定义新规范值。冲突时以 ui-spec + `uni.scss` 为准，并同批修本 spec。
4. **与 ADR 0076 的关系**：Figma 只读原型是**变更提议源**，不是规范真源；本 spec 不改变该所有权裁定。
5. **不复制原则**：本文对 ui-spec 与 design 笔记只留指针。任何「把表抄过来」的改动都是新增漂移面——§5 的台账、§6 的旧编号对照、§3 的 10 项表都遵循这条。
