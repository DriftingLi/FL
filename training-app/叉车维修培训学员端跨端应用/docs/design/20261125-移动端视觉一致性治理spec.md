## 2. 三层定义

### 2.1 为什么是「层」而不是「页」

第一性原理：**层是文件属性**（路径可 grep、件数可枚举、值面可机检），**页是集合**（会随增删漂移）。按页切批次必然让一页同时背 token 色值、共享件接入、私有子件样式、布局结构四类债——旧批 4/5/6 的 32 页欠账就是这么产生的（代码合并了，验收没人接）。所以判据与批次都按层切。

### 2.2 三层（判据面）

**层与批次的映射**（批次是工作单元，层是判据面，两者不是同一维度）：

- L3 私有子件 + 页面族结构 → **P3 私有子件与结构层**

### 2.3 每层「不判什么」（边界同样重要）

- **L1 不判**：某个值该不该成为 token（判断类）；可映射值怎么分流（`#ffffff` 对应 6 个语义 token，必须按位置分流，见 §4）。
- **L2 不判**：引用率（唯一例外页头件 `app-nav-bar`）；「该用共享件却手写」（只在 `audit:ui` 留不判红观察项）。
- **L3 不判**：间距（`audit-spacing` 只读、#2715 不立门）；字号/字重/圆角/图标尺寸档位（T1 §4 已裁判断类）；「该不该用 `app-card`」（结构改造票）。

## 4. token 缺口清单（T2）

**读数**：裸 hex 1028 处 / 131 个 distinct 值（全 6 位）。其中**可映射 641 处 / 15 值**（62.4%），**真缺口 387 处 / 116 值**（37.6%）。

**「可映射 ≠ 可批量 sed」**：`#ffffff` 对应 6 个语义 token（`$card-bg` / `$bg-header` / `$tabbar-bg` / `$text-color-inverse` …），必须按位置分流——这是判断类，不是脚本活。任何「一把 sed 换完」的方案都会把语义压平。

**四条结构性特征（比数字更重要）**：

1. **页面底灰有 7 个近邻值**：`#f5f7fa` / `#f7f8fa` / `#f5f6fa` / `#f8f9fa` / `#f5f6f8` / `#f0f1f5` / `#fafbfc`，合计 **65 处**——同一语义写了 7 遍，收敛成 1 个 token 是纯收益。
2. **浅蓝底有 3 个近邻值**：`#e3f2fd` / `#e8f0fe` / `#e8f3ff`，合计 **30 处**。
3. **三套色板并存**：Material（`#4caf50` / `#f44336` / `#ff9800`）、Element（`#909399`）、Tailwind/Radix（`#16a34a` / `#e5484d`）——组件从不同来源抄来的化石证据，不是设计选择。
4. **语义色是 token 表最薄的一段**：绿色 44 处**全部**落缺口（token 表无任何绿色值），红色 58 处里 46 处落缺口。

**高频缺口 top**：`#eeeeee` 30、`#4caf50` 24、`#f44336` 22、`#e0e0e0` 21、`#f5f7fa` 12、`#f7f8fa` 12、`#e3f2fd` 11、`#e8f0fe` 11。**116 值全表**见 T2 §6。

**50 个 0 引用 token 分两类，不能一起删**：34 个 `$uni-*` 框架标准变量**保留**（换主题兼容面）；16 个业务死件是真死件。最值得注意的 4 个：`$header-grad-start/end`、`$primary-grad-pressed-start/end`——**页头渐变与主按钮按下态是硬编码 hex 的**，token 换血 B0（#2516）漏了这两组。

**白名单口径未对齐**：71 条白名单 dead 0，但 `#f5f5f5`（53 处）在 token 表有同值 `$bg-color`——白名单替一个可映射值背了书。P1 收敛时必须先解这条冲突，否则「裸 hex 归零」永远差 53 处。

**细节**：`docs/design/20261125-token值面缺口实测.md` §5（可映射）、§6（缺口）、§7（死件）、§9（白名单交叉）。

### 4.1 语义色收敛结论（#2861 落地，2026-11-26）

**canon 定稿（不改名、不新造）**：成功 `$success-color #14AE50`（#2509 R2 冲突 2 改值，原型决定清单 §2-2 已把 `#00A443` 并入此值）· 危险 `$danger-color #ff3b30` · 警告 `$warning-color #ff9900` · 链接 `$color-link #1b6f9c`（对比度 3.00 < AA 的例外不推翻，#2516）。命名沿用存量两种写法（`$success-color/$danger-color/$warning-color` 后缀式、`$color-link/$color-price` 前缀式），本票不重命名——重命名会连带 §1.7 的 27 条原型换血表与 `utils/uiDocDocMapContract.test.js` 的双向对账。

**分流判据（判断类，四条，可复用到后续值面票）**：

1. **位置语义优先于值近似**：该处是否承担「成功 / 危险 / 警告」语义，由所在选择器与文案决定，不由 ΔE 决定。ΔE 只用来判「是不是同一族的近似值」，不能单独决定换 token——同值可以承载两种语义（`#4CAF50` 既是「通过」也是头像占位底；`#F44336` 既是「错误」也是点赞强调），一把 sed 会把语义压平。
2. **成套色组不拆件**：插画（forgot-password 扳手 9 值）、渐变对（页头/用户卡/分类卡）、倒计时成对色（`#FF6B6B` + `#FFF3A0`）整组保留；要么整组换、要么整组留。本票唯一例外是用户裁定：`exam-result-summary` 的通过/未通过渐变**压成单色实底**（`$success-color` / `$danger-color`），因为渐变本身是这次要收敛的化石。
3. **装饰/品牌色不入语义 token**：头像占位底、资源卡装饰底、微信品牌绿（`#22C55E`）、已解锁按钮绿（`#2E9E5B`）、金币金、强调橙（`#FF6B35` / `#E2622C`）——白名单保留，理由行写明「#2861 裁：非语义位」。
4. **SCSS token 到不了 JS / UTS 字面**：`confirmColor`、内联 `style` 字符串、`uni.showToast` 参数位不在此 token 射程，登记为缺口，不假装已收敛。

**落地读数（feat/2861）**：替换 **69 处**——绿 → `$success-color` 26、绿浅底 → `$success-tint` 2、红 → `$danger-color` 25、红浅底 → `$danger-tint` 11、价格红 → `$color-price` 1、橙 → `$warning-color` 4 / `$warning-tint` 2。白名单：**删 6 条**（`#EE0A24` `#FA3534` `#FADCD9` `#FFF0F0` `#FFF1F0` `#D93025` 已无承载）、**改理由 10 条**（保留值逐条写「#2861 裁」+ 为何留）。私有子件棘轮基线 `utils/privateComponentUiBaseline.json` 由 18 文件/40 处降为 **16 文件/36 处**（`dashboard-course-section`、`exam-result-summary` 清零，由 `scripts/gen-private-component-ui-baseline.mjs` 重出，非手抄）。

**本节对 T2 的两处订正**：① §6.2「token 表无任何绿色值」不成立——`uni.scss` 早有 `$success-color`，缺口是「值不等」而不是「无绿值」，故本票走值收敛而非新造 token；② 红 58 处的口径含 `l > 0.97` 的极浅底（`#FFF1F0` 一类），按「危险色」计只有 46 处，分流时两者分别归 `$danger-color` 与 `$danger-tint`。
