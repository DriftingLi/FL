## 4. 票面三条数字的订正

1. **「裸 hex 348」作废**——348 是宽松正则 `#([0-9a-fA-F]{3,8})` 扫**全文件**的产物（template 58 + script 104 + style 210）。严格口径下 style 块字面量 **141**，其中 **31 处真违规**。script 块另有 10 处，真色值只有 `components/app-card/app-card.uvue` 的 `bgColor: '#ffffff'` 与 `components/login-agreement/login-agreement.uvue` 的 `accent: '#239EDD'` + `return 'background-color:#ffffff;border-color:#C8CDD8'`，其余 7 处是注释里的票号。
2. **「app-nav-bar 53」应为 55 页**——漏了 easycom 全局注册与 `components/ai-chat/ai-chat-nav.uvue` 间接链。**「app-chip 0 引用」应为 1 页**（`pages/search/search.uvue:52` `<AppChip :text="tab.label" ...>`，import 在 :137）。
3. **零引用件是 3 件**（`app-level-badge` 有 1 处引用，不是死件）：`app-card`、`app-badge`、`app-list-item`。三件都是「参数化容器」且极薄——`app-card` 26 行（props padding/margin/radius/bgColor + 默认 slot，style 只有一行 `flex-direction: column`）、`app-badge` 45 行（count/dot）、`app-list-item` 87 行（label/value/avatar/showArrow/danger）。

## 5. Q1 零引用件怎么处置：**留资产，但撤销「规范答案」地位**

三个选项的实测后果：

| 选项 | 对「第 63 页自然一致」的影响 | 代价 |
| --- | --- | --- |
| A 留资产 | **零**——它不减少任何一处手搓 | 无 |
| B 标待淘汰 | 零，且多一条要维护的 deprecated 状态 | 要动基线 + 新页禁引判据 |
| C 直接删 | **零**——删件不减任何一处手搓 | 要同批改 `utils/modules.js:71-81` 的 INFRA 登记与 `utils/globalComponentsContract.test.js` 的 A/B 断言 |

**裁定 A**，理由是第一性的：**app-card 只包 padding/margin/radius + slot，页面照旧要自己写卡内的字号/间距/圆角——它不含任何「视觉一致性」信息。** 真要让第 63 页的卡片一致，靠的是 §9 判据对**页面自己**的裸 hex / 间距的断言，不是这三件存在。所以：

- 判据里明写「共享件层的断言范围 = 全部 27 件**自身合规**，**不含引用率**」；
- 明写「零引用件**不得**被当作『该用它』的判据来源」；
- 删件的动作（B/C）都要越出「本轮只出 spec 不改代码」的边界，且**收益为零** ⇒ 另开清理票，与本判据解耦。

## 6. Q2 自身合规判据形式：**新起接线契约套件（unit 腿）+ 逐文件基线 JSON**

不选「扩 batch6」，不选「只在 audit:ui 出报告」，理由与 T4 同源：

1. `utils/batch6UiContract.test.js` 的扫描面 = `PAGE_ENTRY_RE = /^pages\/[^/]+\/[^/]+\.uvue$/`（深度 2，天然排除 `components/`），其文件头原文把共享件层写成「**明确延后项、不是漏测**」，价值就在「扫描面变化在机检层可见」。扩面会毁掉这条纪律。
2. 「只在 `audit:ui` 出报告不判红」= 只报不管，与 Q3 裁的「先断言自身合规」相反；`audit:ui` 定位是只读聚合、不改判红口径。
3. 新套件与既有 19 个视觉契约套件同构（接线守护、unit 腿、跑在既有 ③ 两腿内）——**不是新增门类型**：不动 ruleset、不加 CI 步骤、不改两腿划分。

**承接 §9 指标 1（裸 hex，走棘轮）+ 2（`lang="scss"` 100%）+ 5（主色字面 `#239EDD` = 0），不承接指标 3、4**：

- 指标 3（`.status-bar` + 页头件引用）是**页面骨架职责**，`components/` 下没有「页面」这个概念；
- 指标 4（`app-*` 引用 100%）**不可机检**，且 Q1 已裁「不判引用率」⇒ 属结构改造票。

31 处进 `utils/sharedComponentUiBaseline.json` 逐文件基线、两向棘轮；新件基线缺省 0 ⇒ 新增即合规。属**接线守护，不构成 ③ 门承重证据**（`docs/agents/guards.md:37`）。

## 7. Q3「该用共享件却手写」怎么判：**不判语义，只补一条不判红的观察项**

事实基础（149 个 `.uvue` 模板 class 正则实测）：

| 手搓形态 | 命中文件 | 对应共享件实际覆盖 |
| --- | --- | --- |
| 空态类名（empty-tip/empty-text/empty-state/empty-box/empty-wrap） | **29 件**（入口 22 + 私有 7） | app-empty-state 4 页 |
| 卡片类名 | **55 件**（入口 27 + 私有 28） | app-card **0** 页 |
| badge 类名 | **15 件**（入口 7 + 私有 8） | app-badge **0** 页 |
| tab 行（tab-row/tabs-row/tab-bar/tab-list） | 10 件（入口 5 + 私有 5） | app-tabs 2 页 |
| 筛选 chip（filter-tag/filter-chip/chip-item/tag-item） | 10 件（入口 7 + 私有 3） | app-chip 1 页 |
| 重试按钮（retry-btn/retry-button/retry-text） | 9 件（入口 8 + 私有 1） | 无对应件 |

- **手搓量远超共享件覆盖量，且私有子件层手搓不比入口层少**（卡片 28 vs 27、badge 8 vs 7）。这才是「8 件 `app-*` 只 3 件活着」的真因——**不是接入成本（easycom 已开、#2436 已裁定），是没人往那儿写**。
- **N06 五页豁免的实测面**：手写页头的**精确就是 N06 五页**（`index` / `login` / `search` / `register` / `forgot-password`），一页不多一页不少；60 个私有子件里精确 `class="status-bar"` = **0**。

**裁定**：

- **不把 N06 沿用到私有子件层**。N06 是**页面级**豁免（那五页自己写了完整页头、不需要 nav-bar）；把页面级豁免搬到子件层会推出「index 页的子件也允许手写 status-bar」这种无依据的结论。
- `status-bar` 判据的扫描面**保持 `pages/<族>/<页>.uvue` 深度 2 的入口件**（batch6 现状），私有子件层不承接（与 T4 已关闭裁定一致）。
- **补一条不判红的观察项**进 `audit:ui` 报告：私有子件里出现精确 `class="status-bar"` 就单列一行「疑似页头下沉」。判红会错误搬运页面级豁免，完全不看则洞真开时无人发现——观察项是这两者之间的唯一位置。
- **「该用共享件却手写」整体不判**：它需要的判据是「这个场景有没有唯一正确答案」，而空态文案 / 卡片内距 / 按钮组合**按场景变**（见 Q4），语义匹配就是 #2715 说的「把判断挪进脚本、造第二份口径」。

## 8. Q4 共享件与页面族：**杠杆按件计，不按层计**

事实：**只有 7 件跨族**（nav-bar 17 族 / icon-button 5 / markdown-blocks 4 / empty-state 4 / tabs·cert-selector·login-agreement 各 2）；其余 20 件只服务单一族内的单页（`ai-chat-*` 11 件全给 ai-assistant、`forum-wysiwyg-*` 3 件全给 forum-detail）。**44 页只用 1 个共享件。**

⇒ 「改组件即改所有使用页」这条 L2 陈述在今天的真实分布里**只对 app-nav-bar 成立**；44 页的「共同理解」是**共用 nav-bar**，不是「共用一个组件库」。

**裁定**：

- **app-nav-bar = 唯一硬约束**（页头必须用它；N06 五页豁免）。依据：页头有**唯一正确答案**（顶部安全区 + 标题 + 返回，全站一致）。
- **其余 26 件一律「按需复用」**：判据只要求**自身合规**（第 6 节），**不要求任何页面必须用它**。依据：卡片 / 按钮 / 空态**没有唯一正确答案**（空态文案、卡片内距、按钮组合按场景变），所以它们是**资产**不是**标准**。
- **这条理由同时解释了 Q1**：三件零引用件之所以零引用，正是因为它们属于后一类——**不是被漏掉的，是被正确判断为「用不上」**。
- **spec 里必须改写 L2 那句**：改成「共享件层的一致性杠杆**按件计、不按层计**——nav-bar 覆盖 17/22 族，其余 26 件逐个登记可达族数、不承诺」。否则 spec 会继续暗示「所有共享件都有 L2 杠杆」，而实测 20/27 件连第二页都没有。

## 9. 为什么这是判断类、而非必检门（对齐 #2715）

本层判据里只有**值面**（裸 hex ∈ token ∪ 白名单、`lang="scss"`、主色字面 = 0）是确定性的；**「该不该用某件共享件」「零引用件留不留」都是判断类**——它们要回答「这个场景有没有唯一正确答案」，而机检只能回答「这个值在不在白名单」。把后者硬做成判红门，就是把判断挪进脚本、造第二份口径（#2715 理由②）。

因此：

- 本层落地的**只有**「自身合规」（值面 3 条）+ 逐文件棘轮基线，作为**接线守护**跑在 ③ 两腿内；
- **不挂 CI 必检、不改 ruleset、不改 `.github/scripts/lib/gate-validator.mjs`**（#2715 现行裁定，翻案须另立新裁定）；
- 「引用率 / 该不该用」只进 `audit:ui` 只读报告（Q4 裁定），**必须「已扫描 / 未扫描」分栏、未实测项不得显示为通过**。

## 10. 可粘贴进 spec 的条文

> **§X 共享件层（`components/`）**
>
> **X.1 层定义**：`components/**/*.uvue`，27 件。它是**资产库**，不是「全站标准件」。
>
> **X.2 断言范围**：全部 27 件**自身合规**，**不含引用率**。三条值面判据：① style 块裸 hex ∈ token 值 ∪ §1.6 白名单；② 有 style 块则 100% `lang="scss"`；③ 主色字面 `#239EDD` = 0。形式 = 接线契约套件（unit 腿）+ `utils/sharedComponentUiBaseline.json` 逐文件基线，两向棘轮（存量 9 件 31 处，只减不增；新件基线缺省 0）。跑在 ③ 两腿内，**不新增门**。
>
> **X.3 引用率不判**：判据**不**断言任何页面必须用某件共享件，**唯一例外**是页头件 `app-nav-bar`（§9 指标 3 现状，N06 五页豁免）。零引用件（`app-card` / `app-badge` / `app-list-item`）**留资产**，但**不得**被当作「该用它」的判据来源。清理另开票、与本判据解耦。
>
> **X.4 杠杆按件计，不按层计**：`app-nav-bar` 覆盖 17/22 族，是唯一全域件；其余 26 件按可达族数逐个登记、不承诺「改一处即改所有使用页」。20/27 件只服务单一族内的单页。
>
> **X.5 手搓不判语义**：判据**不**判「该用共享件却手写」——空态 / 卡片 / 按钮按场景变、无唯一正确答案。仅在 `audit:ui` 报告里给一条**不判红**的观察项：私有子件出现精确 `class="status-bar"` ⇒ 「疑似页头下沉」。
>
> **X.6 为什么是判断类**：值面 3 条确定性、可断言；「该不该用」「留不留」判断类、不进判红门（#2715）。引用率只进 `audit:ui` 只读报告。
>
> **X.7 新共享件准入**：新增即合规——不在基线 ⇒ 按 0 算 ⇒ 任何一处值面违规即红。
