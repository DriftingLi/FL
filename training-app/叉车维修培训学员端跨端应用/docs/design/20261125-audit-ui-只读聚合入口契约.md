## 3. 数据来源（两条子进程，零侵入）

| 来源 | 调用 | 取出什么 |
| --- | --- | --- |
| jest | `npx jest --config jest.config.unit.js -i --silent --json --runTestsByPath <items.json 里声明的套件>` | `numTotalTests` / `numFailedTests` / 逐套件 `assertionResults.length` |
| audit-spacing | `node scripts/audit-spacing.mjs --json` | `scanned` / `warn` / `info` / `skip` |

**为什么是子进程而不是 import/导出**（实测支撑）：

- `scripts/audit-spacing.mjs` **无任何 export**（只有 `main()` 与 CLI 守卫），`import` 不成立。
- 25 个视觉套件 **0 个导出报告函数**（`module.exports` 命中的都是断言里的字符串字面量）。要它们导出就得改 25 个纯 jest 文件，且每个文件多一份导出面。
- jest `--json` 在**断言失败时仍吐合法 JSON**（实测：故意 `expect(1).toBe(2)` → exit 1、JSON 完整、`success:false`、`numFailedTests:1`），所以「红」不会丢读数。
- `--json` 在**零套件匹配时 stdout 为空且 exit 1**（实测 `--runTestsByPath utils/__nope__.test.js` → STDOUT 0 字节），必须按第 8 节 fail-closed，**不能**把空 stdout 当「零失败」。

代价要认：判据名 `fullName` 是自由字符串（中文 + 全角标点，如 `pages/exam-info/exam-info.uvue（ui-spec §9 机检 · #1605 批2） H1 样式块声明位裸 hex ∈ token 值 ∪ §1.6 白名单`），会随改稿漂移。**因此本工具不解析 `fullName`**——只数条数与失败数，判据名的语义靠第 5 节的显式映射表（`scripts/audit-ui-items.json`），不做关键词匹配。

字段硬约束：

| 字段 | 约束 |
| --- | --- |
| `id` | 语义 slug，见第 6 节枚举；**是唯一查找键**，不随排序变 |
| `seq` | 1–10，仅用于终端 `#` 列展示；**禁止**当查找键（它随重排漂） |
| `status` | `scanned` \| `not-scanned`，两值，无第三态 |
| `coverage` | `full` \| `narrow` \| `point` \| `none`，四值，直接抄 T1 §1 的覆盖度判定 |
| `note` | 已扫描行的注记码，当前唯一合法值 `ruled-no-gate`；未扫描行必须 `null` |
| `reasonCode` | 未扫描行必填（见第 6 节）；已扫描行必须 `null` |
| `reason` | 未扫描行必填且**非空**，必须带可核指针（`T1 §2.x` / `文件:行`）；已扫描行 `null` |
| `evidence.suites` | 相对 `$APP` 的正斜杠路径；已扫描行为实际贡献读数的套件，未扫描行为「持有点状断言」的指针套件（可为空） |
| `evidence.assertions` / `failed` | `status === "scanned"` 时必须是数字；`not-scanned` 时必须是 `null`（**不许填 0**——0 会被读成「扫了且全绿」） |
| `readings` | 非 jest 来源的读数数组，可空；当前只有 `source: "audit-spacing"` 一种 |

不可复现内容**一律禁止进 JSON**：`generatedAt`、任何耗时字段、绝对路径（`D:\\…`）、jest 的 `startTime/endTime/duration`、主机名。判据是**同一棵工作树两次跑必须逐字节相同**——只有这样才能进 golden 比对（第 9 节自测钉这条）。耗时只出现在终端表格末行。`items` 按 `seq` 升序；`suites` 按字典序；`readings` 按 `source` 字典序。

## 6. 两栏判定与 `reasonCode` 闭合枚举

### 6.1 判定规则（纯函数，可单测）

```
coverage ∈ {full, narrow}  → status = scanned
coverage ∈ {point, none}   → status = not-scanned
```

`point` 归「未扫描」是刻意的：**点状 ≠ 扫描**。项 2/4/7 合计约十几处断言分散在 6 个套件里，代表不了全仓。把它们放进第一栏，正是地图 Q4 点名要禁止的「未实测显示为通过」。代价是读者可能误以为「一点没查」——所以这三行的 `reason` 必须写成「已有 N 处点状断言，见 T1 §2.x」这种可核指针，不许写空话。

最终分栏 = **已扫描 5 行（项 1/3/5/8/9）+ 未扫描 5 行（项 2/4/6/7/10）**。

### 6.2 `coverage` 与 `status` 正交

项 1 扫了 121 个 `.uvue` 却只是 `narrow`（只 `pages/`、只三条规则、SKIP 204）；项 6 是 `none` 却……也是 `not-scanned`。把两者压成一个布尔量，就会丢掉「#2715 裁过不立门」这个事实。故两字段分开、不得互相推导。

### 6.3 `reasonCode` 五值（闭合，新增值必须改本节 + 自测）

| code | 含义 | 当前用在 |
| --- | --- | --- |
| `no-criteria` | 仓内零判据载体 | 项 6、项 10 |
| `point-only` | 只有点状断言，无全仓扫描 | 项 2、4、7 |
| `run-failed` | 来源崩 / 超时 / 零套件匹配 / exit 2（**运行时才出现**，不在 `items.json` 里预置） | 任意项 |
| `out-of-face` | 判据存在于扫描面外（如 `components/` 27 件不在 audit-spacing 面内） | 预留，当前 0 项 |
| `ruled-no-gate` | 有工具但 #2715 已裁不立门 | **不用于未扫描**，只作已扫描行的 `note` |

**`ruled-no-gate` 不是未扫描的原因码**。这是本契约最容易被半年后的读者搞错的一处：项 1 明明跑了 121 件，为什么不是门？把「跑了」和「不立门」分成两个字段（`status: scanned` + `note: ruled-no-gate`）才说得清。自测必须断言：未扫描行的 `reasonCode` ∈ `{no-criteria, point-only, run-failed, out-of-face}`，且 `note` 为 `null`；已扫描行的 `note` ∈ `{null, ruled-no-gate}`，且 `reasonCode` 为 `null`。任一违反即判红。

## 8. 失败语义与退出码

三种失败分开处理，**不许合并成一档**：

| # | 情形 | 该项 status | 整体退出码 |
| --- | --- | --- | --- |
| ① | 套件跑完，但有断言失败 | `scanned`，`failed > 0`，读数写 `29 断言 / 2 失败` | 默认 0；`--strict` 下 **1** |
| ② | jest 崩 / 超时（>120 s）/ stdout 非法 JSON / 零套件匹配 | `not-scanned` + `run-failed` | **2** |
| ③ | `audit-spacing` 退出码 2（目录或白名单读失败）/ 输出非法 JSON | 依赖它的项 `not-scanned` + `run-failed` | **2** |

- ① **不改 status**：套件红了但我们确实拿到了读数，把它挪进「未扫描」等于用撒谎换整齐。红就是红，读数照打。
- `--strict` **只抬 ①**，不抬 ②③——②③ 本来就是 fail-closed（exit 2），再抬没有增量语义。
- ②③ 的 exit 2 与 `audit-spacing` 的既有语义一致（`scripts/audit-spacing.mjs:25`：0 完成 / 1 strict 有 WARN / 2 读失败），**同一套退出码词汇表，不发明第二套**。
