# 移动端页面族布局结构问题清单 · 条目详述 A（页头 / 层级 / 间距）

> 主文档见 [移动端页面族布局结构问题清单](20261127-移动端页面族布局结构问题清单.md)。本册为 H / L / S 三类共 11 条的逐条现象、证据行、后果与建议归属；T / A / G / F 四类见[条目详述 B](20261127-移动端页面族布局结构问题清单-条目详述B.md)。
> **只报告、不建机检、不进门。** 不含主观审美评分；圆角与字号不在 #2911 范围（归 #2910）。涉「看起来如何」的条目已标「未真机复核」。
> 章节号沿用主文档编号（H=1 / L=2 / S=3），B 册从 T=4 接续。

## 1. 页头行为（H）

### H1 [P1] register / forgot-password 双标题 + 无 status-bar 占位

- **现象**：61 条路由中**只有这 2 条**没设 `navigationStyle: custom`（`pages.json` 两处 `style` 只有 `navigationBarTitleText`），于是原生导航栏仍在；而页内又画了一套品牌区 + 标题。
- **证据**：`pages.json` → `pages/register/register`（`navigationBarTitleText:"注册"`）、`pages/forgot-password/forgot-password`（`"找回密码"`）；`pages/register/register.uvue:3-10`（`<view class="header">` + `<text class="page-title">注册账号</text>`）、`pages/forgot-password/forgot-password.uvue:2-10`（同构，`page-title` 为「找回密码」）；`.header` 在 `register.uvue:188-191` 与 `forgot-password.uvue:127` 为 `padding: 60rpx 0 48rpx 0`（60rpx 是给状态栏让位的经验值，**不是**读了安全区的）。
- **对照**：`login.uvue:3`、`index.uvue:12`、`search.uvue:3` 三页都手写了 `class="status-bar"` 占位；其余 55 页由 `app-nav-bar` 经 `useSafeArea` 自测。
- **后果**：① 同屏出现两个标题（原生栏「找回密码」+ 页内「找回密码」，register 则是「注册」/「注册账号」**文案还不一致**）；② 60rpx 是硬编码常量，换设备/换导航栏高度会错位（**未真机复核**，本条只报结构）。
- **建议归属**：页头骨架票（与 H3 同批，一次把 N06 五页收成一种骨架）。

### H2 [P1] ai-assistant 的页头形态读不到

- **现象**：唯一一页不用 `app-nav-bar` 直连，而是经 `components/ai-chat/ai-chat-nav.uvue` 包装。该件 `withDefaults` 里 `transparent: true`，`pages/ai-assistant/ai-assistant.uvue:4` **不传任何页头形态参数** ⇒ 页面上看不出这页是透明页头，只有翻进 wrapper 才知道。
- **证据**：`ai-assistant.uvue:4` `<AiChatNav :drawer-open="sidebarLeft" @left-click="toggleSidebarLeft" />`；`components/ai-chat/ai-chat-nav.uvue:8-24`（转调 `AppNavBar`，`:transparent="transparent"`）、`:39-51`（`transparent: true` 默认值、`leftIcon: '☰'` 保留只为上抛 click）。
- **结论修正**：台账把此页记为 N05（透明页头）**是对的**，但「实现里没有 transparent」这个早期读数是误判——语义在 wrapper 默认值里。**这也是本条要报的问题**：形态判定不能从页面源码读出。
- **建议归属**：页头唯一真源票（把 `transparent/variant/divider` 显式写在页上，或把 ai-chat 的特化收进 `app-nav-bar` 的插槽）。

### H3 [P2] N06 五页三种页头骨架

- **现象**：N06 白名单五页（`index` / `login` / `register` / `forgot-password` / `search`）都不用页头件，但骨架分三种：手写 `status-bar`（index/login/search）、无任何占位靠 `.header` 的 60rpx padding（register/forgot-password）、以及脱离原生栏后的页面自滚动。
- **证据**：`index.uvue:12`、`login.uvue:3`、`search.uvue:3`；对照 H1 的两页。
- **建议归属**：同 H1。

### H4 [P2] 返回键：载体与尺寸都没有定论

- **现象**：`app-nav-bar` 的返回键是**字形 `‹`**（`font-size: 44rpx`），反色态用 `/static/icons/profile/chevron-left-inverse.png`、非反色态用 `/static/icons/ai-chat/chevron-model.png`——即同一个动作用了「字形 + 两张位图」三种载体。44rpx ≈ 22px，小于 44×44 常规触摸目标，命中区由外层 88rpx 方块补齐。
- **证据**：`components/app-nav-bar/app-nav-bar.uvue:8`（两态图片路径）、`:279-287`（`.nav-bar-left--back` `position:absolute; left:24rpx; width/height:88rpx`）、`:393`（`.nav-bar-icon { font-size: 44rpx }`）、`:252-259`（`.nav-bar-body { height:88rpx; padding: 0 $spacing-md }`）。
- **未合并工作**：`fix/mobile-arrow-touch-targets`（1e267270）已把字形改到 48rpx 并加了 `.nav-bar-back-hit` 88rpx 与按压反馈（`composables/useTouchPress.uts`）。**该分支同时改了 `check-in.uvue` 的月切换箭头，那部分已过时**（master 现在用 `<app-icon-button>`，见 `check-in.uvue:43-48`）。
- **建议归属**：箭头资源统一票；动手前先决定 `wt-mobile-arrow-touch-targets` 是合并、重做还是关闭。

### H5 [P2] 同一 N 套内参数组合不齐

- **现象**：台账 N05（透明页头）7 页的标签写法有 **4 种组合**，且「有没有标题」「能不能返回」靠 `@left-click` 在不在来暗示：

| 页 | 标签写法（原文节选） | 缺少的东西 |
| --- | --- | --- |
| `courses/courses` | `<app-nav-bar transparent :left-icon="''" title="课程" />` | `@left-click`（无返回） |
| `profile/profile` | `<app-nav-bar transparent :left-icon="''" title="我的" />` | 同上 |
| `forum/forum` | `<app-nav-bar transparent :left-icon="''" title="学员论坛">` | 同上（右槽另起） |
| `dashboard/dashboard` | `<AppNavBar variant="plain" transparent :left-icon="''">` | 同上 + 多一个 `variant` |
| `recruiter/login` | `<app-nav-bar transparent @left-click="leaveRecruiterLogin" />` | **无 title** |
| `resume/resume` | `<app-nav-bar transparent @left-click="onBack" :show-toolbar="true">` | **无 title** |
| `ai-assistant/ai-assistant` | `<AiChatNav … />`（形态在 wrapper 默认值里） | 页上完全看不出 |

- **证据**：上表逐行原文；`dashboard.uvue:4`、`mall.uvue:5`（后者属 N03）。
- **写法面另有一处**：N03（20 页）里 19 页写裸 `divider` 布尔（如 `profile/settings.uvue:3`、`points/task-center.uvue:3`），只有 `mall.uvue:5` 写 `:divider="true"` —— 等价但两种写法。
- **建议归属**：页头参数收口票（与 H2 同批）：把「有无返回 / 有无标题 / 有无工具栏」定成显式 props，别靠 `left-icon` 与 `@left-click` 的有无来推。

## 2. 层级（L）

### L1 [P1] `z-index` 没有刻度

- **现象**：全仓 `z-index` 共 **17 处声明、10 个不同取值**（10 / 90 / 91 / 100 / 101 / 200 / 201 / 300 / 301 / 999），散在 **12 个文件**。规律是「成对」：每层用 `X` 作面板、`X+1` 作遮罩（100/101、200/201、300/301、90/91）。但**没有一处注释或 token 说明这些档位的含义**，于是同一语义落到不同值：
  - 「全屏遮罩」用了 **200**（`dashboard` 的 `filter-mask`、`ai-assistant` 的 `model-mask`、`ai-chat-custom-form` 的遮罩）**和 999**（`forum-report-dialog`、`job-detail` 的 `report-modal-mask`、`info-dialog`）两种；
  - 「底部面板基座」用了 **100**（`ai-chat-drawer-left`）、**200**（`ai-chat-custom-form`，同一层既当遮罩又当基座）、**300**（`ai-chat-diagnosis-guide` / `ai-chat-pro-sheet`）三种；
  - **页头件 `app-nav-bar` 完全没写 `z-index`** ⇒ 页头与浮层的上下关系靠 DOM 顺序与父级 `overflow`，不靠层级。
- **证据**（逐行）：`pages/guide/choose-cert.uvue:212`（10）；`pages/forum/components/forum-more-menu.uvue:103`（90）、`:112`（91）；`components/ai-chat/ai-chat-drawer-left.uvue:121`（100）、`:131`（101）；`pages/ai-assistant/ai-assistant.uvue:1142`（200）、`pages/dashboard/dashboard.uvue:311`（200）、`components/ai-chat/ai-chat-custom-form.uvue:99`（200 / 201 见 `:110`）；`components/ai-chat/ai-chat-model-picker.uvue:66`（201）；`components/ai-chat/ai-chat-diagnosis-guide.uvue:271`（300）、`:283`（301）；`components/ai-chat/ai-chat-pro-sheet.uvue:137`（300）、`:150`（301）；`pages/forum/components/forum-report-dialog.uvue:60`（999）、`pages/jobs/job-detail.uvue:483`（999）、`pages/profile/components/info-dialog.uvue:64`（999）。
- **后果**：新增一个弹层时要靠「扫全仓找最大值」决定写 300 还是 999，写错就是被压住或者压不住；而**「谁压谁」这件事没有任何一处可读的真值**。
- **建议归属**：层级刻度票——先定 4–5 档（页头 / 吸底操作区 / 浮层 / 遮罩 / 弹层），再按档改值；**不要**先改值后定档。
### L2 [P2] `position: fixed` 浮层 11 处散落 9 文件

- **现象**：11 处 `fixed` 分布在 `forum`（fab 按钮、更多菜单、举报弹窗、回复面板）、`jobs`（详情页吸底、信息弹窗）、`mall`（浮动动作组）、`recruiter`（筛选抽屉）、`practice`（答题页两个浮层）。它们与他页的页头、`scroll-view`、`windowHeight` 骨架**没有共同约定**：有的按 `bottom: X` 贴底，有的按 `env(safe-area-inset-bottom)`（本项目不支持 `env()`，见 `docs/agents/uvue-css.md` ⇒ 实际靠写死值）。
- **证据**：`forum.uvue:363`（`.fab-btn`）、`forum-more-menu.uvue:98/110`、`forum-report-dialog.uvue:52`、`forum-reply-panel.uvue:170`、`job-detail.uvue:475`、`info-dialog.uvue:56`、`mall-float-actions.uvue:22`、`recruiter-filter-drawer.uvue:250`、`practice-do.uvue:349/370`。
- **建议归属**：浮层约定票（与 L1 同批，先定档再改）。

### L3 [P3] forum 页内菜单层级最低

- **现象**：`forum-more-menu` 用 90/91，低于全站任一遮罩（100–999）⇒ 打开菜单后再触发别的弹层必然压住它（**可能是预期**，但没写下来）；`forum.uvue:363` 的 `.fab-btn` 完全没写 `z-index`，与菜单的上下关系靠 DOM 顺序。
- **建议归属**：并入 L1 的刻度票，不单开。

## 3. 间距（S）

### S1 [P1] 同一页内水平内距出现 4–7 个不同值

- **现象**：9 个页面**自己一个文件里**就声明了 4–7 个不同的水平内距值（含页面级容器、分节容器、卡内、小控件）。这不是「族间不齐」而是「同页不齐」——同一屏上下滚动时，容器边界不落在同一条竖线上。
- **证据**（逐页实测，值为该页 `<style>` 中所有 `padding` 的水平值去重升序，原始读数见[逐族证据册](20261127-移动端页面族布局结构问题清单-逐族证据册.md)）：
  - `points/points-detail.uvue`：24 / 28 / 32 / 40（4 档）
  - `practice/practice-do.uvue`：16 / 20 / 24 / 28 / 32（5 档）
  - `courses/courses.uvue`：12 / 16 / 24 / 28 / 32 / 38 / 40（7 档）
  - `profile/notebook.uvue`：8 / 12 / 24 / 28 / 32 / 40 / 44（7 档）
  - `resume/resume-edit.uvue`：8 / 12 / 16 / 20 / 24（5 档）
  - `forum/forum-detail.uvue`：16 / 24 / 28 / 32（4 档）
  - `featured/featured-detail.uvue`：8 / 14 / 32（3 档 + 非整档 14）
  - `search/search.uvue`：4 / 8 / 16 / 24（4 档）
  - `ai-assistant/ai-settings.uvue`：8 / 12 / 24 / 40（4 档）
- **口径限定**：上述值**含卡内距与小控件内距**，「哪几档是页面级边距」要逐条看类名（本票只给读数，不做断言）。这也是它不能做机检的原因——脚本分不清「页面级」与「卡内级」。
- **为何 `audit:spacing` 报 0**：该入口判的是「卡内距 = 页面边距」这类**逐节点可判**的规则，它不判「同一页内是否多档」——那要跨节点聚类、且「几档算多」是判断类。故本条与「WARN 0 / INFO 0 / SKIP 203」不矛盾；「间距不做机检」的既有裁定见仓库根 `docs/design/20261120-间距机检不立裁定.md`，本条同属判断类。
- **建议归属**：页面级内距收口票（P3 第一批里最容易量化收益的一条）。

### S2 [P2] 族间页面级内距 4 档

- **现象**：页面级水平内距按族分 4 档：**24rpx**（主流，多数 G3/G4 列表详情页）、**32rpx**（`forum` 详情、`check-in`、`points` 族）、**48–56rpx**（`login` / `register` / `forgot-password` / `recruiter/login` 认证类）、**8–20rpx**（`featured-detail` / `featured-list` / `search` / `mall` / `resume-edit` / `custom-models`）。
- **证据**：见 S1 逐页值与各页根容器 padding；对照台账 G 族归属（G3 列表 23 页 / G4 详情 10 页 / G5 表单 10 页 / G6 认证 5 页）。
- **建议归属**：与 S1 同票；先定「族级基线」，再收页内多档。

### S3 [P2] profile 族内双档

- **现象**：`profile` 族 11 页里，`profile.uvue` 的 `section-card` 内距 16，其余同族页 24。
- **证据**：`pages/profile/profile.uvue`（`section-card` 16）对照 `profile/settings.uvue`、`profile/records.uvue` 等（24）。
- **建议归属**：与 S2 同票。
