## 4. 票面三条数字的订正

1. **「527 处裸 hex」作废**——宽松正则把注释里的票号算成颜色（T2 实测全域 4 位数字 631 处）。严格口径下：本层**全量字面量 394**，其中 255 = token 值、100 = 白名单、**39 = 真违规**。T2 账本记 396（clean）/ 439（raw），与本次差 2 处，原因是注释剥离边界（T2 另剥 HTML 注释并留 raw/clean 两套），**无实质分歧**；但这条差异正说明：**基线必须由套件自己的扫描器生成，禁止手抄**。
2. **「3 份缺 lang=scss」应为 2 份**——第 3 份 `pages/forum/components/forum-markdown-blocks.uvue` **根本没有 style 块**。判据必须写成「**有 style 块则 100% `lang="scss"`**」，否则这份会永久误报。
3. **「唯一完全没有机检覆盖的层」只对 §9 五硬指标成立**——`scripts/audit-spacing.mjs` 的 walk(pages) 实测扫 121 件 = 61 入口 + **60 私有子件**，私有层早就在**只读**间距审计面内（#2715 已裁不立门）。准确说法：**五硬指标零覆盖，间距只读已覆盖**。

## 5. Q1 层怎么定义

- **事实**：60 件全部只被同族文件 import，**0 件跨族**。族内复用有 5 件（最多的是 `recruiter-tab-bar` 被 5 个入口件用）。
- **行为面不「纯展示」**：54 件有 props、44 件有 emits，但 3 件直接调 uni 导航、1 件用 Pinia store、31 件引 `../composables/` 的页面级逻辑。所以「私有件 = 哑组件」在本仓不成立，判据不能这么写（否则一次性判红 35 件）。
- **结论**：这层今天的身份是「**页面族实现细节**」——但「实现细节」指**所有权与变更半径**，不指「无状态」。判据化后：
  - 定义 = **路径 + import 图**：位于 `pages/<族>/components/` **且** 静态 import 方全部落在同一 `pages/<族>/`；
  - 出现**跨族 import** ⇒ 它已不是私有件，是**未晋升共享件** ⇒ 判红，要求迁 `components/` 或就地晋升；
  - 同一件被**同族多个入口**复用 ⇒ **不改层**（族内共享仍是族私有）。

## 6. Q2 判据形式

推荐：**新起一份接线契约套件（unit 腿）+ 逐文件基线 JSON**；不扩 batch6 扫描面，不只在 `audit:ui` 出报告。三条理由：

1. batch6 的「全站 = 入口件」是**写进文件头的有意口径**（`utils/batch6UiContract.test.js:8-14`：「两处都是**明确延后项**、不是漏测」），其价值就在「谁把扫描面扩了/缩了在机检层可见」。把子件塞进去，等于用同一条 61 断言同时代表两种职责，任一面漂都看不清。
2. 「只在 `audit:ui` 出报告不判红」= 只报不管，与 Q3 裁的「**先断言自身合规**」相反；`audit:ui` 的定位（Q4 裁定）是**只读聚合、不改判红口径**，不该成为唯一执行点。
3. 新套件与既有 19 个视觉契约套件**同构**（接线守护、unit 腿、跑在既有 ③ 两腿里）——**不是新增门类型**：不动 ruleset、不加 CI 步骤、不改两腿划分。spec 必须写明这一句，否则会被读成翻 #2715 的案。

附带约束（`docs/agents/guards.md` 新增守护四问）：它是**接线守护**，只读源码文本，**不构成 ③ 门承重证据**，文件头要自限（先例：视觉套件全是这一类）。

## 7. Q3 缺 `lang="scss"` 的两份

推荐：**在「判据落地」那个 PR 里同批修**，不单开票、不挂基线。

- 两份（`pages/exam/components/exam-result-summary.uvue`、`pages/forum/components/forum-topic-body.uvue`）的 style 块**零 token 引用**（实测各 0 处），是纯 CSS 字面量 ⇒ 补 `lang="scss"` 是**零渲染变化**的一行属性（纯 CSS 是合法 SCSS 子集）。
- §9 指标2 原文「**无豁免**」；给这两份挂基线等于在指标2 上开第一个口，而修它是一行 ×2、风险 0 ⇒ 挂比修更贵。
- 这不是「本轮改页面」：本票只出判据，修复落在实施票的第一步。

## 9. Q5 新页私有件准入（T8 的输入）

「**新增即合规**」是棘轮的天然性质，不需要任何人工登记：

- 基线只收录存量 18 件；**新文件不在基线 ⇒ 基线按 0 算 ⇒ 任何一处违规即红**；
- 新件必须落在同族内（跨族 import 判红 ⇒ 想复用就晋升到 `components/`）；
- 基线条目**只减不增**（两向棘轮），所以「先挂账后清」这条后门对新件不存在。

## 10. 转绿机制：棘轮 vs 白名单（必须分清）

| 机制 | 管什么 | 性质 | 能否回答「不一次性判红」 |
| --- | --- | --- | --- |
| `utils/uiHexWhitelist.js` | **值**：没有对应 token 的颜色是否可接受 | **永久豁免**，逐值一行理由 | 否——用它兜存量会造出 18 条永不收敛的理由行，且与 §1.6「白名单值必须是真实存量」的自检语义冲突 |
| 逐文件基线棘轮 | **体积**：一个文件还欠多少 | **有期债务**，条目只许下调 | **是** |

棘轮形态照抄先例 `utils/legacyPrimaryColorRatchetContract.test.js` + `utils/legacyPrimaryColorBaseline.json`（现测基线已是空对象）：逐文件相等、**两向判红**（实测 > 基线 = 新写入；基线 > 实测 = 清了没改账）、新文件缺省 0、基线由扫描器生成并排序（先例 `:306-313` 的数据卫生断言）。

## 11. 实现坑（写 spec 时必须带上）

1. **hex 正则必须钉 3/6/8**：batch6 用宽口径（`utils/batch6UiContract.test.js:72` 的 `#[0-9a-fA-F]{3,8}` 加词边界），T2 用严格口径。本层现测两口径**同值（39/18）**，但宽口径在注释剥离有缝时会把 4 位票号算成颜色（历史 631 处事故）。新套件用 T2 口径并在文件头写明理由。
2. **白名单死条自检是手维护并集**：`utils/batch4UiContract.test.js:262` 已手挂 3 个私有件（`pages/forum/components/forum-topic-header.uvue`、`pages/forum/components/forum-topic-actions.uvue`、`pages/forum/components/forum-more-menu.uvue`）；实测 `#FF8F00` **只由私有件承载**。私有层纳入后这类值只会更多 ⇒ 新套件应**另做一条全层死条自检**（71 值在全层真实出现），而不是继续往六份旧套件的并集里手加（ADR-0038 记载的既有漂移面）。
3. **接线守护不构成 ③ 门承重证据**（`docs/agents/guards.md:37`）。
4. **基线 JSON 必须扫描产出**，手抄会带进口径差（T2 的 396 vs 本次 394 就是现成例子）。
