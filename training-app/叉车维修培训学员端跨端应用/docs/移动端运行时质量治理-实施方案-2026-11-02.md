## 4. 影响分析

**会变的**
- 仓库新增 `scripts/poc/link-poc.mjs`（独立 PoC，不被门脚本引用，不参与 ③ 腿分类；确认无脚本清单型守护）。
- 新增 4 份文档（方案、链路规范、WARNING 方案、发版冒烟清单）。
- ④ 读数侧建议新增 `warn=N`（**可见不判红**）——待确认。

**不会变的**
- `scripts/mp-weixin-check.ps1` 与平台噪音白名单：**一字不改**（#2211 正在改同一判定逻辑，禁止并行）。
- ③ 两腿的 config / testMatch / changed 子集算法：不改。
- #2213 的业务方案：#2196 维持「删 chips + guard」。
- ①a 的触发面：仍是发版前一次，不进普通 PR。
- 全量/ changed-only 的关系：CI 仍全量，本地仍 changed。

**成本**
- 新链路验证按目录触发，单条 <1min；不做每 PR 全链路。
- ② env-blocked 的 16% 空转是当前最大隐性成本，PoC 会顺带记录会话建立耗时（`auto 返回 ≠ 会话可用`，#883 血账）。

## 6. 风险与回滚

| 风险 | 触发条件 | 处置 |
| --- | --- | --- |
| PoC 被误当门用 | 有人把它接进 CI | 脚本头注已写「不是门、不得被 check 引用」；接入需维护者确认 |
| 点击能力扩散 | 有人往白名单加任意选择器 | 配置校验只收类选择器 + 步数上限 + 末步必断言；`--self-test` 反向锁 |
| 会话不稳定 | `auto` 返回后端口延迟/关闭 | 同命令内建会话→探针→收会话；失败记 `env` 而非 `fail` |
| 环境不可用导致「假绿」 | 设备离线、IDE 未登录 | 一律 `result=env` + exit 2，不产出 pass |
| WARNING 方案被读成放宽 | 有人删 warn 统计 | 方案写明「三档」，高风险进抽样，不放任 |
