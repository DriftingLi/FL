## 二、流水线阶段（A 方案）

编排器（/root/kb\_orchestrator.sh）管理以下 6 阶段状态机，幂等、自动续跑。

### 阶段 1：parsing — PDF 解析

| 项  | 值                                            |
| -- | -------------------------------------------- |
| 工具 | MinerU 3.4.5（pipeline 后端，CUDA 12.6）          |
| 脚本 | /root/run\_mineru.sh                         |
| 输入 | /root/mineru\_todo.txt（1588 本唯一 PDF）         |
| 输出 | /root/mineru-out/{书名}/auto/{书名}.md + images/ |
| 单本 | timeout 2400s，GPU 内存约 1.1GB                  |
| 状态 | 1553 DONE + 35 FAIL（0.8% 边缘文件，exit=0 无 md）   |
| 速率 | 约 10.8 本/小时（大手册 5-12 分钟）                     |
| 显存 | MinerU fast\_api 常驻 5.1GB RAM + 1.1GB VRAM   |

### 阶段 2：converting — 转换 + 图片上传 S3

- 工具：mineru2kb.py（--no-caption 模式）

- 图片 SHA256 去重，上传至 Ceph RGW forklift-files bucket

- md 内图片链接改写为 `https://dify.gccsmile.com/kbimg/{bucket}/{hash_prefix}/{hash}.jpg`

- 幂等：已产出 md 的书自动跳过

### 阶段 3：embedding — 切块 + 向量嵌入

| 项    | 值                                                    |
| ---- | ---------------------------------------------------- |
| 切块   | 500 字/块，50 字重叠，安全边界检查（防 URL 截断）                      |
| 嵌入模型 | bge-m3（566M, Q4\_K\_M, 1024 维）                       |
| 索引   | FAISS IndexFlatIP（余弦相似度）                             |
| 产出   | 134,315 chunks，525MB faiss.index + 72MB metadata.pkl |
| 速率   | 约 3-4 chunks/s（与 ollama 共享 GPU）                      |

### 阶段 4：captioning — 图片图注（后台，数周级）

- 工具：/root/caption\_runner.py

- 模型：qwen3-vl:2b（部署于 ollama）

- 输入：45 万张已上传 S3 图片

- 缓存：/root/.caption\_cache.json（SHA256 去重，已标注的图不重复跑）

- 产出：图注描述文本，补充进 md 后重新嵌入

### 阶段 5-6：reconverting + reingesting — 带图注重灌

- 全量重跑 mineru2kb.py（--force 模式，图注缓存命中直接复用）

- 清空 FAISS 索引全量重灌（旧索引持续服务，零停机切换）

## 五、Nginx 图片代理配置

图片 URL 结构：

```
https://dify.gccsmile.com/kbimg/kb2/{hash_prefix}/{hash}.jpg
```

Nginx 配置（forklift-frontend-prod 容器）：

```nginx
location /kbimg/ {
    limit_except GET HEAD { deny all; }
    rewrite ^/kbimg/(.*)$ /forklift-files/$1 break;
    proxy_pass http://172.17.1.42:8088;
    proxy_set_header Host $host;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_buffering off;
    add_header X-Cache-Status $upstream_cache_status;
    expires 30d;
    add_header Cache-Control "public, immutable";
}
```

**关键坑**：proxy\_pass 末尾不能带 `/`
（否则会剥离 /kbimg/ 前缀，导致 RGW 按路径第一段认 bucket 名，返回 NoSuchBucket）。

## 六、GPU 显存分配策略

### 当前配置（解析完成后）

| 进程                    | 显存            | 说明             |
| --------------------- | ------------- | -------------- |
| qwen3-kb（4B Q4\_K\_M） | 2.97 GB       | Dify 推理        |
| bge-m3（566M Q4\_K\_M） | 0.13 GB       | 嵌入模型常驻         |
| 合计                    | 3.1 GB / 4 GB | 剩余 \~0.9 GB 空闲 |

### 解析阶段共存

解析期间 mineru 占用 1.1 GB，ollama 以 OLLAMA\_GPU\_OVERHEAD=1536 限制（预留 1.5 GB 给 MinerU），qwen3-kb 部分层被 offload 到 CPU，推理速度降至 7.89 tokens/s。

### 配置变更记录

| 阶段  | GPU\_OVERHEAD | 效果                         |
| --- | ------------- | -------------------------- |
| 解析中 | 1536          | MinerU 独占 1.5 GB，ollama 受限 |
| 解析后 | 256           | qwen3-kb 全速（\~30 tokens/s） |

## 八、切块策略（URL 安全）

### 修复前的问题

固定 50 字符重叠，可能从 markdown 图片链接中间切断，导致下一块以孤儿片段 `xxx.jpg)` 开头。模型检索到残片后按文件名"脑补"错误路径，输出后 404。

### 修复方案

1. **重叠起点安全化**：回退 50 字符后向前推进到换行/表格行边界；若起点落在 `![..](..)` 内部则跳到链接闭合之后
2. **防御性清理**：块首孤儿 `xxx.jpg)`、块尾未闭合的 `![..](https://...` 一律剥离
3. **应用文件**：/root/dify-external-kb/data/ingest\_direct.py（函数 chunk\_text\_v2）
