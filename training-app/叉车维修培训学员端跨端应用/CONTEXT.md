# 叉车维修培训学员端 - 领域词汇表

面向叉车维修人员的在线培训与考核平台，学员端支持 Android/iOS/H5/微信小程序四端访问。

## 认证与安全

**生物识别认证（Biometric Authentication）**：
利用设备硬件能力（指纹、面容）验证用户身份的认证方式。Android/iOS/微信小程序走 SOTER 协议，H5 用浏览器弹窗模拟。

_Avoid_: 指纹认证、面容认证、人脸认证（这些是生物识别的子集，不是完整概念）

**SOTER**：
微信主导的生物认证协议，覆盖 Android/iOS/微信小程序，提供标准化的指纹/面容认证能力。

**凭据门控回填（Credential-Gated Autofill）**：
记住密码的核心策略——凭据持久化存储后，不在启动时自动回填，而是要求用户通过生物识别验证后才回填。区别于传统的"自动填充"模式。

_Avoid_: 自动填充、自动回填（暗示无验证，安全模型不同）

**快捷登录（Quick Login）**：
生物识别验证通过后，不回填表单，而是解密本地安全凭据、以其走一次正常凭据登录换取新会话、直接进入应用（机制经 #1391 改写，原「用本地加密保存的 refresh_token 静默续登」作废——登出吊销与留凭据换会话不可同时成立，见 ADR-0004 2026-09-29 修订）。与凭据门控回填共享"生物验证通过才解锁本地数据"的门控模型，区别在于解锁的是登录凭据而非表单内容；验证对象是机主本人（本地生物识别），服务端不做生物特征比对。成功信号是**会话建立**（access token 落地），refresh_token 只是会话的附带回执（收到即回写包络，缺席不影响已登录的事实，#1398 裁定）。

**凭据降级（Credential Degradation）**：
当生物识别不可用时（平台不支持 SOTER，或设备未启用任何生物识别方式），回退到较低安全级别的存储策略。当前实现：降级为"仅记住账号"（不保存密码）。

**孤儿凭据（Orphaned Credentials）**：
已保存的完整凭据（含密码密文）因生物识别在保存之后变得不可用（用户在系统设置中删除指纹/面容、硬件失效）而永远无法解锁的数据。属于应自愈清理的残留状态。

**secureStorage**：
凭据存储抽象层（`utils/secureStorage.uts`），封装 `hasStoredCredentials`、`saveSecureCredentials`、`loadSecureCredentials`、`clearSecureCredentials` 等接口。App 端经 uni-secure-storage 插件加密落盘（Android Keystore / iOS Keychain），非 App 端明文存储（H5 生产策略另行评估）。

**useBiometric**：
生物识别封装 composable（`composables/useBiometric.uts`），提供 `checkSupport()`（检测设备支持的生物识别方式）与 `authenticate()`（触发一次生物验证）方法，内部处理平台检测、SOTER 调用、降级逻辑。

**未登录着陆页（signed-out landing page）**：
启动页（`pages/index/index`）的**现行职责**——**只服务未登录用户**：呈现品牌与登录入口。入口有**两处**、两端都在位：主 CTA「微信一键登录」与次级入口「其他登录方式」（后者不受任何探测门禁）。主 CTA 的**入口可见性**与**链路可达性**是**两件独立的事**，由**两个**判断分别决定（真源 `composables/useLoginProviders.uts`）：**展示面** `wechatAvailable` = 端别（App **或**小程序）⇒ 两端一律直出；**接通面** `wechatLoginReady` = 端别（**仅**小程序）⇒ App 端点击只给单点提示「微信登录暂未开通」、**不发请求**。这**取代**了本条此前的「按端别直出『微信一键登录』（小程序端）或『其他登录方式』（App 端）」——现行是「两端都直出该入口，App 端是样式位」，改动依据见 [ADR-0032](docs/adr/0032-开屏吞掉认证入口后登录页降级为次级落点与运行期能力探测.md) 的 2026-10-03 修订。上面两个面里**只有端别那半**是会过期的事实，真源在根词条「微信一键登录」，#1482 落地后随它改写。已登录用户**无条件**落 dashboard，而那条 `reLaunch` 是**全应用唯一的已登录冷启动落地路由**（`App.uvue` 的 `onLaunch` 不做任何路由，只异步校验 token）。它因此是一个**停得下来、带入口**的状态页，不是自动前进的过渡画面；独立登录页 `pages/login/login` 是它的**次级落点**、不是并列入口（[ADR-0032](docs/adr/0032-开屏吞掉认证入口后登录页降级为次级落点与运行期能力探测.md)）。本条只裁这张页面的职责；两条登录通道（「微信一键登录」「验证码登录」）的叫法仲裁归**根词表**辖。

_Avoid_: 叫它「开屏页 / 欢迎页 / splash」并据此认为它应当每次显示、可加倒计时或跳过按钮（该方向已在 #1467 / #1478 判为**不予采纳**——「开屏」的语义是展示后自动前进，与它现在承担的入口职责直接冲突）

## 培训体系

**课程中心**：
提供叉车维修相关的在线课程，包含章节学习、学习进度上报、资料下载。

**考试系统**：
模拟考试与等级考试，支持成绩查询和错题本功能。

**练习题库**：
标签练习、随机练习、答题卡、数据报告。

## 资源与投稿（移动端映射）

域定义见根仓库 CONTEXT.md「资料投稿（contribution）」词条族；本节只记移动端映射（#710）。

**资源 tab（forum-resource-panel）**：
论坛页资源分区的 2x2 入口：课程商城 / 我的已购 / 我的上传 / 上传资源。「上传资源」格子与资源区的创建入口（header「发帖」/搜索栏）一律跳 `forum-create?scope=resource`——统一发布页（#760），资源 tab 承载投稿表单，独立页 upload-resource 已退役。

**统一发布页（forum-create）**：
分类行三 tab（ADR-0040 后）：广场/资源/知识问答——**「备考经验」不再是发布选项**（学员不能自称考经，它是管理端认定）。资源=投稿表单（文件方式三行〔微信聊天文档/本地文件上传/选择压缩文件，白名单 pdf/doc/docx/ppt/pptx/xls/xlsx/zip/mp4、单 ≤20MB、合计 ≤50MB、≤5 个前置校验〕+ 标题 ≤120 + 简介 + 目标证件取当前证件〔无证件阻断〕；链路先传后交：逐个 POST `/contributions/upload-file` 暂存 → POST `/contributions` 建稿，API 封装 `api/contribution.uts`）；其余三 tab=发帖表单（标题 ≤100 + 正文 + 图片 ≤9，`createForumTopicApi`，category 即 tab scope）。resource 永不发进发帖接口（isResourceMode 分流 + 编辑回填 normalizeCategory 双守卫）。

**我的已购（my-purchases）**：
已购课程 = GET `/student/courses`（我的课程，根仓库 ADR-0017）口径——后端**无购买概念**（课程全开放，`points_price` 积分兑换无已兑清单 endpoint），真「已购清单」如需支持另立后端票；不要再用 profile.course_progress 假充已购（契约测试已钉）。

## 用户体系

**学员**：
平台的主要用户角色，通过登录注册后使用培训、考试、求职等功能。

**学员端**：
面向学员的跨端应用（Android/iOS/H5/微信小程序），即本项目。

**企业招聘者（recruiter）**：
第四个账号角色（根仓库 CONTEXT.md 词条族），账号在 `recruiter_users` 独立表、与学员的 `hrwai_users` **无关联、无共享 ID 空间**。移动端以**独立登录入口**进入（仅账号密码），与学员身份**互斥**——同一时刻设备上只有一个身份。

_Avoid_：招聘者（裸用，与「招聘」这个动作面混淆）、企业用户

## 招聘（移动端映射）

域定义见根仓库 CONTEXT.md「企业招聘者（recruiter）」「职位（job posting）」「投递（application）」「联系方式交换（contact exchange）」词条族；本节只记移动端映射。

**就业在线**：
学员侧招聘面的唯一入口（`pages/profile/profile.uvue` → `/pages/jobs/job-list`）：公告 / 职位双 tab，头像挂在 tab 行最右端直入「我的」（`pages/resume/resume`，简历总览）。
**术语沿革（防漂移）**：论坛页历史上有一个纯 mock 的「招聘」tab，已于 #705 退场、简历入口即重挂于此。「招聘 tab」一词**只指那个已退役的 mock 面**，不得用来指代现行入口。

**招聘者工作区（移动端）**：
企业招聘者在移动端的形态，导航为**底部常驻五 tab**（首页 / 职位 / 简历库 / 交换 / 我的，与学员端同构），覆盖**响应侧 + 首页 + 职位管理面**：投递处置（按职位查看、详情、标记不合适）、联系方式交换（发起与状态）、简历库检索，加**职位发布 / 编辑 / 上下架**（`job-edit`）。
首页 = 欢迎卡 + 交换紧迫行 + 快捷入口（首屏 1 个批量请求 `contact-requests`）。
**（原「只做响应侧、不含职位发布与编辑」的口径已由 [ADR-0028](docs/adr/0028-招聘端向学员端设计语言收敛.md) 于 2026-09-28 推翻；身份与学员互斥、仅 Bearer、平台面仅 Android/iOS 不变。）**

_Avoid_：招聘模块（该说法在本仓历史上指学员侧招聘面，两面混用必然串线）

## 架构守护

**模块声明（module declaration）**：
本仓「一个模块**是什么**」的唯一事实源——它拥有哪些文件、预算是多少、目录能有多深、承认哪些组件接口、豁免归属哪一侧，一处声明。
与「模块契约」的区别是**事实**与**守护**的区别：声明是数据，契约是消费这份数据并断言不变量的守护。**模块边界因此是显式决定**——在模块目录里新增文件即须同步声明，否则对账判红。

_Avoid_：模块清单（泛称，会把「声明」与「测试里手抄的文件列表」混为一谈）；把声明当目录树的副本（它的价值在于**边界由人决定**，不是自动镜像）

**契约 harness（contract harness）**：
消费模块声明、把结构不变量（行数预算 / 目录深度 / 拆出物接线零孤儿 / 声明与目录双向对账）实现一次的机制，供各模块契约复用。
它**只出事实、不做断言**：断言留在各模块自己的契约里，失败信息才说得出「哪个模块破了哪条不变量」。按 [守护分类](docs/agents/guards.md) 属**接线守护**，不构成 ③ 门证据。

_Avoid_：测试工具（会把「模块边界的唯一事实源」降格为实现细节）；框架（本仓没有可被扩展的通用框架，只有一份声明加一个读者）

**分页列表（paged list）**：
列表页装载协议的**单点实现**（`composables/usePagedList.uts`，移动端 ADR-0027）。它持有条目数组、
加载态、失败态、空态与「还有下一页」，内置**代际守卫**（旧代响应不写任何状态）与**空批次兜底**
（批次为空 ⇒ `hasMore` 强制为假）。页面只提供「怎么取一页」——归一化批次 `{ items, hasMore }`，
**不吃后端信封**——并把 `onLoadMore` 绑到自己的滚动容器上。

边界：生命周期（`onLoad` / `onShow` / 重入策略）与滚动容器留页面壳层；`pageSize` 不进接口；
本地增删与就地改动不回算终止条件。

_Avoid_：异步列表（Web 侧 `useAsyncPage` 的语感，那边的信封形状与这边不同）；分页组件（它不是视图组件，
空态/失败态的渲染仍归页面）；无限滚动（那是触发方式，不是这个概念）

**手写载体（hand-rolled carrier）**：
仍在自己实现分页装载协议的页面或 composable 文件——判据是「页码游标 `…page = ref` **且** 取数函数
`function load|fetch|reloadXxx`」，与协议的具体形态无关。它是**棘轮**的计量单位
（`utils/pagedListAdoptionContract.test.js`，只减不增、无豁免），不是缺陷标签：迁移一页就是把一处计数划掉。

_Avoid_：违规页（它只管「还没迁」，不评价对错）；存量页（说不出计量口径）

**行为守护（behavior guard）**：
真跑被测物的守护——文件里有**代码级的执行调用**（`child_process` / `execFileSync` / `spawnSync` / `utsHarness` / 动态 `import()`）**且**引用了至少一个仓内载体（`.uts` / `.uvue` / `.ps1` / `.mjs` / `.json`）。它是**唯一能满足 ③ 门（`npm run test:unit`）判据**的一类：回答得了「我故意弄坏它，会不会红」。与「接线守护」的界限是**证据力**，不是文件名（叫 `*Behavior.test.js` 却只 `expect(src).toContain(...)` 的仍是接线守护）。
_Avoid_：把「行为守护」当「跑了就行」（还须**成对**：必不红 / 必红各一条，只测一个方向恒绿与恒红都骗得过）；把行为守护的数量现值抄进本表（**真源是 `scripts/classify-guards.mjs` 分类器**，快照见 `docs/agents/guards.md`，数字随 master 前进过期）

**接线守护（wiring guard）**：
只读源码文本断言调用点 / 常量 / 命名 / 顺序的守护，**不真跑被测物**。它防的是**接线被拆**（端点被删、调用点漂移、命名回潮），**不构成 ③ 门证据**——算法被改坏而字面量还在时它不会红。它和行为守护是**互补而非替代**：每条接线要有一个兜底它的行为守护，缺前者会漂、缺后者会假绿。
_Avoid_：把接线守护的「全绿」当「已验证」（这是本仓「永远绿」三先例的共同成因）；把它当可删的冗余（它守的是行为守护看不见的接线面，删除须先确认没有别的接线锁接管）
