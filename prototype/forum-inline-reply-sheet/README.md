## 三份证据各自的射程（别混用）

- **原型（本目录）** 只证明**格式表达的逻辑** —— 记号 → run → 摘要 → 降级落点。
- **一手文档**（`md-inline-render-facts.md`）证明**双端允许什么** —— 它已答掉 ADR 原先划为「只能真机判」的四格中的两格。
- **真机 ①a** 才证明**画没画出来** —— 剩两格：app-android 等宽字体可得性、嵌套子 `<text>` 的实际出图与点击命中。

本仓口径原文：「H5 端未验。本票判据的对象是 uvue 原生渲染器」（`docs/verification/uvue-font-carrier/1269/README.md:121`）。⇒ **三者互补、不可互替**。

## 本目录自己踩到的坑（对票一有价值，故留档不删）

1. **`font:inherit` 简写会重置 `font-weight` / `font-style` / `font-family`** —— 原型里「加粗」挂了 `.r-b` 类却实测 `font-weight: 400`，样式从来没显示出来。**类名挂上 ≠ 样式生效**，判据必须读计算后的样式。
2. **渲染分支可以不消费 runs** —— 引用块走文本转义直出 `**粗体**`，而「按 runs 判」的机检完全看不见。⇒ ⑥-1 要两条判据：逐 run **+** 按元素切段的渲染面。
3. **跨 run 拼接判据会误报** —— 代码内容里的 `**` 与远处一个裸 `**` 会被成对正则连成一击。
4. **只编译抽取片段的自查会漏掉整页语法错误** —— 一处 `'])` 误写成 `'))` 让整页白屏，而当时切片自查 41 条全绿。故 `_verify-forum-inline.js` 的第一条断言是 **INV-0：整段内联脚本必须能编译**。
