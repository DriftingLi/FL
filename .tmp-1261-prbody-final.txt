## 改了什么 / 为什么改

ADR-0025 单票三段的最后一段（P1 = #1254 / P2 = #1257 已合入 master）。关联 **#1240**。

本段补**输入端形态**，并把 P2 留下的两处欠账同批收口：

- **输入区收敛为一个共享组件** `pages/forum/components/forum-markdown-input.uvue`（发帖表单与回复栏只接线，**形态只有一份** —— 同根 ADR-0052 决策① 的目标）。三条档位轴互不混用：数据档位（胶囊，会永久保存）/ 视图档位（下划线 tab，临时）/ 图片（**单一入口**：一个 `＋` 方块 → 系统选择器 —— 原「拍照 + 相册两个直达入口」已于 2026-09-22 按维护者裁定回退，见下节与 ADR-0025 **⑨ 取代 ⑦**）。
- **工具栏**（`utils/markdownToolbar.uts`）：按钮集 = 本档成员声明集（`###` / `-` / `>` / 代码围栏 / `---` **恰好五枚**），两个方向都对账；**行内格式不放按钮**（本档不做行内渲染，⑥-6 已登记）。「按钮承诺必须真能渲染」做成可执行的 **round-trip** 判据（插入 → 真执行解析器 → 必须产出该块类型）。
- **格式记忆位**（`utils/forumFormatPreference.uts`）：发帖与回复共用一个键；「首次默认纯文本」= **读不到就是纯文本**（根 ADR-0044）。
- **创建 / 回复载荷带上作者的声明**；**编辑路径仍不带**（P1 的编辑不变式不动），故编辑态**不给档位控件**、按帖子原格式呈现；资源投稿态恒纯文本。
- 同批收口 P2 的两处欠账：**「我的动态」的回复原文**接上格式轴（P2 复核回写认定的**真实缺口**；`buildReply` 早已带回 `content_format`，不动 DTO）；**`forum-markdown-blocks.uvue` 补 `lang="scss"`**（P2 登记为「与 P3 同批」的那条）。

完整变更、**新决策 10 条**与**已知偏差 5 条**见移动端 `docs/adr/0025-论坛正文格式与输入区形态.md` 的「实施回记（#1240 · P3 输入区形态已落地）」。

## 形态回退（2026-09-22 · 维护者裁定，ADR-0025 ⑨ 取代 ⑦）

维护者在收口前裁定：图片入口的**两个常驻方块（拍照 / 相册）过重**，回退成 P3 之前的一个 `＋` 方块。这是**偏好**裁定、不是技术约束 —— 记在此处，免得被读成「双入口做错了」。

- **形态**：共享组件的两个 `image-add` 方块 ⇒ **一个**（`＋` + `n/9` 计数；上传中显示 `…` / 「上传中」）；`emit('add-image')` 不再带来源；**回复侧沿用回退前的旧形态**（方块上只有 `＋`、不出计数，走既有 `variant` 闸门）。
- **流水线一字未动**：`count = 剩余额度` / `sizeType: ['compressed']` / 限额 toast / `uploading` 闸门 / 失败计数都留原样；变的只是入口数与来源数组（改回系统选择器，相册 + 相机两个来源由系统给）。
- **守护翻面（不是删除）**：`forumImagePickerBehavior` 的「来源直达」组 ⇒「两个来源都在」组，旧的必红对随决策反转、替换为新的一组真坏实现（来源数组被砍成一个来源 / `count` 写死不按剩余额度 / 上传循环限额闸门被拆），**必不红对照保留**；`forumMarkdownInputContract` ④ 组同步反转（一个入口 + `＋`/计数 + 「旧的双入口写法已退场」）。
- **①a 证据作废、按「第二次分支收口」重跑**（见下「验收证据」①）；**①b 的必要性不变** —— 触发面是**路径白名单**（`useReplyComposer.uts` / `forum-create.uvue`）+ 真机上传，与入口数无关。
- **顺带落地与更正**：图片缩略图行 `:key="idx"` ⇒ 用图片 URL 作 key（原「复核回写」声称已落，实测**未落**）；回写的三处表述据实更正（见下节）。
